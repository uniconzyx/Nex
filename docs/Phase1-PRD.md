## 1. 产品概述

### 1.1 命名说明

**APP 名称：CppMind**

- 候选对比：CppMaster 偏"炫技"，CodePath C/C++ 偏"路径"但少了核心卖点；CppMind 直接对位核心价值——**思维导图驱动的 C/C++ 学习**，且域名/包名可用性高（`cppmind.app` / `com.cppmind.app`）。
- Slogan：**「一张导图，从 C 到深度学习部署」**

### 1.2 产品定位

一款**移动优先、跨平台**的 C/C++ 系统化学习 APP，以"思维导图 + 学习路径"为骨架，串联**在线编译、题库刷题、AI 辅导、项目实战、深度学习部署、面试复习**六大能力，完整覆盖 20 章学习框架（第 0–19 章）。

一句话：**把一份 C++ 学习思维导图，变成一个能写代码、能刷题、能问 AI、能做项目、能备面试的完整学习系统。**

### 1.3 与竞品的差异

| 竞品 | 缺什么 | CppMind 补什么 |
|---|---|---|
| LeetCode / 牛客 APP | 无知识体系，纯刷题 | 章节→题目映射，刷题有路径 |
| LearnCpp / cppreference | 纯文档，不能练 | 概念 + 在线运行 + 练习闭环 |
| B 站/慕课视频课 | 被动观看，无反馈 | AI 苏格拉底式追问 + 错题本 |
| 各类"面试八股"APP | 零散、无深度学习方向 | 20 章全覆盖 + DL 部署方向（ONNX/TensorRT/LibTorch/llama.cpp） |

## 2. 目标用户画像

### P1 · 考研/在校学生（主力，约 50%）

- 特征：计算机相关专业，备考 408 或学 C++ 课程，有整块自习时间碎片化的矛盾。
- 痛点：教材枯燥、知识点散、代码没地方跑、不知道学到什么程度算够。
- 核心诉求：**路径感 + 每日任务 + 错题本**。
- 付费意愿：低→中（学生价订阅）。

### P2 · 求职者/面试冲刺（约 30%）

- 特征：校招/社招，目标 C++ 后端、基础架构、自动驾驶/AI 基础设施岗。
- 痛点：八股零散、项目没亮点、手撕代码紧张。
- 核心诉求：**面试题库（按章分类）+ 项目实战模板 + AI 模拟面试**。
- 付费意愿：中→高。

### P3 · 转型/AI 方向工程师（约 20%）

- 特征：Python/算法背景，要把模型落地到 C++ 端侧或服务端。
- 痛点：C++ 基础薄弱但时间少；ONNX Runtime/TensorRT/LibTorch 文档碎片化。
- 核心诉求：**第 12–14 章深度学习分支 + 6 个 DL 部署项目 + 直接可跑的推理示例**。
- 付费意愿：高。

## 3. 核心价值主张（七大支柱）

1. **思维导图**：20 章知识树，节点即知识点，可标记掌握度（未学/学过/掌握/精通）。
2. **学习路径**：第 18 章推荐节奏落地为每日任务 + 周计划，支持 3 种预设路径（零基础 6 个月 / 求职冲刺 3 个月 / DL 方向 4 个月）。
3. **在线编译**：Judge0 CE 沙箱，支持 C11/C17、C++11/14/17/20/23，测试用例即时反馈。
4. **题库**：自建题（每章 ≥5 练习 + ≥3 面试题）+ LeetCode/牛客映射题，支持章节/难度/标签筛选与错题本。
5. **AI 辅导**：苏格拉底式教学、编译错误诊断、代码审查、模拟面试、学习计划生成，上下文注入（当前章节 + 当前代码 + 错题 + 进度）。
6. **项目实战**：5 个基础项目 + 4 个系统项目 + ≥6 个深度学习部署项目，每个含需求/架构/步骤/模板/测试/部署/面试问法七件套。
7. **资源整合**：GitHub 仓库按章分类、LeetCode/牛客题目映射、cppreference/LearnCpp/Compiler Explorer 引用，含同步机制。

## 5. MVP 范围（阶段定义）

### 5.1 MVP 包含（P0 全集）

- 注册登录 + 3 种方向选择
- 20 章思维导图 + 章节内容页（每章 7 类内容齐备）
- 在线编译（Judge0 CE）+ 代码示例运行 + 每章 ≥5 练习题判题
- 题库（自建 + LeetCode 映射）+ 错题本
- AI 助手（苏格拉底教学 + 编译诊断，上下文注入）
- 项目实战列表与任务打卡（15 个项目文档齐备，模板可运行）
- C 语言单独模块（7 单元）
- GitHub 资源清单 + 同步脚本 + LeetCode 映射表
- DL 模块：第 12–14 章内容 + ≥6 个部署项目
- 暗色主题、Docker Compose 一键启动、API 文档

### 5.2 MVP 明确不做（防蔓延）

- 移动端离线编译（只做内容离线缓存）
- 模拟面试多轮对话（P2）
- 支付订阅（P2）
- 社区/排行榜/证书（P2）
- 牛客实时 API 深度集成（MVP 用映射跳转 + 离线 JSON，P1 再接 MCP Server）

### 5.3 MVP 验收口径

第 2 节用户 P1 → P3 任选其一走通"注册 → 选方向 → 导图学习 → 跑代码 → 做题 → 错题复习 → 问 AI → 开项目"全链路无阻断。

## 8. 用户流程图

### 流程 A：新用户冷启动

注册/登录 → 选方向（考研 / 求职 / DL）→ AI 生成初始学习计划 → 进入首页今日任务 → 开始第一章。

### 流程 B：核心学习闭环（MVP 主链路）

章节内容页（学目标 + 概念）→ 遇到示例代码 → 一键运行（沙箱）→ 做本章练习题 → 判题 → 答错自动入错题本 → 唤起 AI 苏格拉底式引导 → 标记知识点掌握度 → 导图节点变色 → 解锁下一节点。

### 流程 C：面试冲刺流

选"求职"方向 → 学习计划切 3 个月冲刺 → 面试题库按章刷 → 错题复习 → 项目实战补亮点 → （V2.0）AI 模拟面试出报告。

### 流程 D：DL 部署流

DL 分支入口 → 第 12 章数学与模型 → 第 13 章 C++ DL 生态（LibTorch/ONNX/TensorRT 示例）→ 第 14 章路径校准 → 选 DL 项目（如 ONNX Runtime MNIST 推理）→ 模板导入沙箱/本地部署向导 → AI 部署指导。

### 流程 E：编译判题流

提交代码 → 后端入队 → Judge0 沙箱执行（无网/限额/超时 kill）→ 测试用例逐条比对 → 返回 AC/用例失败详情 + 耗时内存 → stderr 非空且非 AC → 触发中文错误诊断 → 可选 AI 解释。

核心学习闭环的可视化流程图已在对话中以图形呈现。

## 9. 内容覆盖矩阵（验收对照）

20 章每章必须齐备 7 类内容（P0，缺一不可）：

| 内容类型 | 数量下限 | 存储实体 |
|---|---|---|
| 学习目标 | 每章 1 组 | Chapter.goals |
| 核心概念讲解（图文 + 代码） | 每章 ≥3 个知识点 | KnowledgePoint / Lesson |
| 常见错误与避坑指南 | 每章 ≥3 条 | Lesson（type=pitfall） |
| 练习题（选择/改错/输出/编程混合） | 每章 ≥5 题 | Exercise / TestCase |
| 可运行代码示例 | 每章 ≥10 个 | CodeExample（复用 Lesson 代码块） |
| 面试题（含解析） | 每章 ≥3 题 | InterviewQuestion |
| 项目任务/实战练习 | 每章 ≥1 个 | Project / ProjectTask |

章节清单（0–19）与 C 语言单独模块（指针/内存/结构体/文件/预处理/Makefile/多文件编译）按此矩阵在阶段 7 逐章填充，由内容校验脚本自动检查"7 类内容完整性"，不满足则 CI 报错。

## 10. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 导图渲染 500 节点 ≥50fps；编译请求 P95 < 15s（含队列）；API P95 < 300ms |
| 沙箱安全 | 无网络、只读根文件系统、CPU/内存/进程数/输出大小限制、超时 kill、按用户限速 |
| 移动端体验 | 首屏 < 2s；暗色主题；章节内容离线缓存；编辑器支持代码键盘扩展 |

| 安全 | API Key 仅存后端；JWT 刷新机制；判题结果防作弊（禁止直接输出用例答案检测可后置） |
| 合规 | 外部资源标注来源/许可证；牛客/LeetCode 内容只存元数据与链接，不整站爬取正文 |

## 12. 风险与开放问题

| 风险 | 等级 | 对策 |
|---|---|---|
| 沙箱被滥用（挖矿/攻击） | 高 | Judge0 + 限速 + 免费层每日额度；异常行为封禁 |
| AI 成本失控 | 高 | 规则库优先诊断、上下文裁剪、免费层对话限额 |
| 20 章 × 7 类内容量巨大 | 高 | 阶段 7 用模板化生产 + 校验脚本；优先 P1/P2/P3 用户画像高频章节 |
| 牛客无公开 API，爬取有合规风险 | 中 | MVP 只做链接映射 + 官方途径（MCP Server）探索；不存正文 |
| 移动端编辑器体验难做好 | 中 | MVP 先保证"可写可跑"，P1 再做键盘工具条/手势优化 |
| TensorRT 等依赖 GPU 环境，沙箱无法运行 | 中 | DL 部署项目用"云端演示 + 本地向导"双模式，不强求沙箱内跑 |

决策记录（2026-09-19 随 UI/UX 增补确认）：
1. 移动端：**Flutter 3 + Dart**（设计要求已按 Flutter ThemeData / lottie 包给出，React Native 方案弃用）。
2. AI 底座：**双通道可切换**，默认 OpenAI，Claude 备用，由后端 provider 抽象层控制（见阶段 2）。
3. 首发平台：**iOS + Android 同步**（Flutter 跨端成本一致，无需取舍）。

## 14. UI/UX 设计系统（蓝白猫咪版）· 2026-09-19 增补

### 14.1 设计基调

关键词：清爽、现代、科技感、亲和力、学习陪伴感、蓝白治愈系。
风格参考：**Duolingo 的亲和力 + Notion 的简洁 + GitHub 的代码感 + 蓝白科技风**。

### 14.2 色彩系统（Design Tokens）

| Token | 色值 | 用途 |
|---|---|---|
| 主蓝 | `#3B82F6` | 主按钮、强调、导图"已掌握"节点 |
| 浅蓝 | `#60A5FA` | 次级强调、导图"学习中"节点 |
| 冰蓝 | `#DBEAFE` | 浅底区块、悬停态 |
| 背景白 | `#F8FAFC` | 亮色页面背景 |
| 卡片白 | `#FFFFFF` | 亮色卡片 |
| 深色背景 | `#0F172A` | 暗色页面背景 |
| 深色卡片 | `#1E293B` | 暗色卡片 |
| 主文字 | `#0F172A` | 亮色正文 |
| 次文字 | `#64748B` | 辅助说明 |
| 暗色文字 | `#E2E8F0` | 暗色正文 |
| 强调青 | `#22D3EE` | 高亮、链接态 |
| 成功绿 | `#22C55E` | AC、难度"简单" |
| 警告黄 | `#F59E0B` | 难度"中等"、提醒 |
| 错误红 | `#EF4444` | 判题失败、难度"困难" |
| 渐变 | 蓝白渐变 / 浅蓝→白 / 深蓝→冰蓝 | 首页头部、AI 气泡 |

导图节点四态色：已掌握 = 主蓝，学习中 = 浅蓝，未学习 = 灰色，薄弱 = 橙色。

### 14.3 形状与质感

圆角：卡片 16–20px / 按钮 12–16px / 输入框 12px。阴影柔和低透明度、带蓝色微光。毛玻璃用于导航栏、弹窗、AI 对话气泡。充足留白，呼吸感强。

### 14.4 字体与图标

中文：苹方 / 思源黑体；英文：Inter / SF Pro；代码：JetBrains Mono / Fira Code。图标：线性圆润风格，蓝白为主，统一 2px 描边。

### 14.5 AI 助手猫咪形象

- **名字：CppCat（小蓝猫）** —— 蓝白配色小猫，圆脸、大眼睛、短耳朵、尾巴可动。
- **性格**：温柔、耐心、鼓励，偶尔卖萌；**不直接给答案**（与苏格拉底式教学模式一致）。
- **表情 8 态**：开心 / 思考 / 疑惑 / 加油 / 庆祝 / 安慰 / 睡觉 / 加载中。
- **动作**：眨眼、摇尾巴、点头、跳跃、打勾、敲代码。
- **对话气泡**：圆角、蓝白渐变、带小尾巴。
- **状态联动**：编译中 = 猫咪思考；AC = 猫咪庆祝；失败 = 疑惑表情 + 安慰话术；成就解锁 = 庆祝动画；加载 = 猫咪跑动 / 尾巴摆动 / 敲键盘。
- **出现场景**：首页问候、AI 对话页、代码运行结果页、错题本、成就页、加载页。
- **实现**：SVG + Lottie；Flutter 用 `lottie` 包，Web 用 `lottie-web`。

### 14.6 页面美化要点（与第 7 节页面清单对应）

- **首页**：蓝白渐变头部 + 猫咪问候卡 + 学习进度环 + 每日一题卡 + 继续学习卡。
- **学习地图/思维导图**：节点四态色（14.2），点击节点有猫咪提示。
- **课程详情**：卡片式布局、代码块高亮、重点内容蓝色高亮、猫咪角落提示。
- **代码编辑器**：亮色白底蓝字；暗色深蓝黑底、蓝白高亮；猫咪提示编译状态。
- **题库**：难度标签（简单绿/中等黄/困难红）、蓝白卡片、答题反馈动画。
- **AI 对话**：聊天界面、猫咪头像、蓝白气泡、代码块可复制。
- **个人中心**：成就徽章、猫咪陪伴、学习数据可视化。

### 14.7 动效

页面转场淡入淡出 + 轻微上滑；按钮按压缩放 + 涟漪；进度环形动画 + 打勾动画；猫咪常驻微动效（眨眼/摇尾）。**提供"减少动效"开关**（可访问性硬性要求）。

### 14.8 双主题

亮色：蓝白为主，清爽治愈；暗色：深蓝黑背景 + 蓝色强调，猫咪形象两套通用。两套模式对比度与可读性均须达 WCAG AA。

### 14.9 可访问性

对比度达标、字号可调、减少动效、按钮触控区域 ≥ 44×44pt。

### 14.10 设计交付物（阶段 5 前置产出）

同一份 Design Tokens 三端生成：**Flutter ThemeData / Tailwind 配置 / CSS 变量**；CppCat 的 SVG/Lottie 资源包建议；组件库（按钮、卡片、输入框、标签、弹窗、导航栏、代码块、聊天气泡）；设计规范文档。
