# 阶段 16 · 考研题库（四层讲解 + 分类总结）

## 1. 这一版要解决什么

题库不是「一堆带答案的题」。每道题必须按同一个顺序讲，缺一层就算不合格：

| 层 | 字段 | 回答的问题 | 校验阈值 |
| --- | --- | --- | --- |
| 解题框架 | `walkthrough.framework` | 这类题按什么动作做（跨题复用） | `steps ≥ 3` 步，且必须有 `trap` |
| 解决思路 | `walkthrough.approach` | 这道题具体从哪一步下手 | `≥ 20` 字 |
| 知识点 | `walkthrough.points[]` | 用到哪个知识点、它的核心结论、本题易错 | 每条要有 `title` + `core`，id 必须能在 `knowledge/` 找到 |
| 详细解法 | `walkthrough.solution` | 完整推导与结论 | 客观题 `≥ 60` 字，主观题 `≥ 80` 字 |

顺序在数据里就是键的插入顺序（`framework → approach → points → solution`），
`validate_exam.py` 会比对 `Object.keys` 顺序，前端按顺序渲染即可，不需要另写排序。

题目另外按专题归口。每个有题的专题必须有一份分类总结：

```
recognize（怎么认出这类题）→ framework（固定步骤）→ skills（技巧）→ traps（陷阱）
questionIds 必须与该专题的实际题目集合完全一致（漏统计、多统计都报错）
```

## 2. 目录与文件

```
content/_exam/
  _meta.json               考试与科目的唯一定义（校验、样张都读它）
  frameworks/{subj}.json    题型框架：topics → patterns → {title, ask, steps, traps}
  knowledge/{exam}-{subj}.json 知识点：topic/chapter + [{id,title,core,patterns,tip}]
  questions/{exam}-{subj}.json 题库：每题的 answer + explain + walkthrough
  summaries/{exam}-{subj}.json 分类总结：每个专题一组
  papers/{subj}-mock-NN.json   模拟卷：选择题存 id，主观题存整段快照
  papers/408-mock-01.json      408 整卷（四科混排 + 7 道综合应用题）
  reading/english-e1|e2.json   阅读精读：段落主旨 / 词伙 / 长难句 / 读后复盘
```

`frameworks/408-{subj}.json` 是 408 四科的框架，其余科目用 `{subj}.json`。
`_meta.json` 里加了 `discrete`（dm）与 `algorithm`（algo）两个考试，
所以校验、总结、组卷、样张会自动把它们算进去，不需要再逐处硬编码。

## 5. 一条命令构建

```bash
python server/scripts/build_exam.py
```

顺序不可随意调换：

```
题型框架 → 知识点表 → 各科题库 → 知识点层回填 → 组卷 → 副本同步 → 分类总结 → 校验 → 样张
```

- **知识点层回填（`enrich_exam_points.py`）必须早于组卷**：套卷里主观题存的是整段快照，
  先组卷后回填会让卷子里的知识点层永远停在旧版本。回填脚本对 `papers/` 也做一次兜底。
- **408 整卷的设计题只存在于卷子里**，题库中没有对应 id，回填用全局知识点索引匹配，避免跨科引用漏掉。
- `sync_paper_copies.py` 是最后一道保险：按 id 把快照与题库对齐，只更新快照本来带的字段。

## 6. 校验规则（`validate_exam.py`）

1. 四层齐全，且键顺序必须是 `framework → approach → points → solution`。
2. `framework.trap` 必须写出来（≥ 6 字），这是「动笔前的提醒」，不能空。
3. `points[].title` / `core` 必须存在，`id` 必须能在知识点表里查到（防手写错 id）。
4. `solution` 按题型分档：客观题 60 字、主观题 80 字。
5. 分类总结必须覆盖「有题但没总结」的专题；`questionIds` 与实际题目集合必须相等。
6. 套卷 `kind=mock`、必须有 `disclaimer`、`totalScore` 必须等于各节分值之和。


## 7. 样张（肉眼验收）

```bash
python server/scripts/render_exam_preview.py   # 写出 docs/exam-preview.html
```

样张直接读题库数据，不手写题面，因此**内容与校验结果永远一致**。
它用来确认三件事：四层顺序是否一遍读得下来、陷阱是否醒目、分类总结是否真的按专题收口。

设计上按「试卷」的直觉走：米灰底、衬线题干、左侧题号列，蓝色只出现在层名与陷阱上。
`design-taste-frontend` 的 lint 为 0 FAIL / 0 WARN；inspect 只剩「无图片 / 无视频 / 无首屏按钮」三项，
这是文档型页面的合理取舍——题库的「实物」是文字与数字，塞装饰图反而失真。

## 8. 自查：这一版仍存在的问题

1. **前端还没接**。后端读接口已补齐（`/api/v1/exams/*`，契约见 `docs/API-Exam.md`，
   10 条契约测试），但 `frontend/src` 里仍没有消费它的 ExamPage。四层顺序现在由
   数据键序 + `validate_exam.py` + API 出口测试三层守住，缺的只剩「看得见的页面」。
2. **408 四科只有选择题**，综合应用题只出现在整卷 `408-mock-01` 里（7 道，非题库 id）。
   想要「按科刷大题」，得把设计题补进 `questions/408-*.json` 并给它们分配 id。
3. **套卷内嵌快照有冗余**。选择题存 id，主观题存整段，改题后必须重跑组卷或同步脚本，
   否则卷子里是旧版本。已用 `sync_paper_copies.py` 兜底，但这是设计债，不是零成本。
4. **分类总结的粒度按专题，不按难度**。同一专题里 easy 与 hard 共用一份总结，
   目前靠 `questionIds` 全量覆盖来保证不漏，但没有「先做哪几道」的路径建议。
5. **英语阅读的读后复盘只覆盖 16 篇 passage**（e1/e2 各 8），
   新增 passage 需要同步补 `reading_extras.py` 里的 takeaway / falseFriends / synonyms，否则复盘区为空。
6. **数学一靠 m2 派生 + 追加级数/概率/统计**，与「数一独有考点」并非一一对应，
   遇到线代与概率的交叉题容易重复归类。

## 9. 下一步优先级

1. 前端加 ExamPage：题干 → 四层逐层展开，默认只展开框架；数据走 `docs/API-Exam.md` 的读接口。
2. 给 `questions/408-*.json` 补设计题（目标每科 4 题），把 408 整卷也变成题库驱动。
3. 分类总结加「建议做题顺序」字段（由易到难，且相邻两题考点不重复）。
4. 英语 passage 增补时把复盘数据做成生成器的一部分，而不是手工表。
