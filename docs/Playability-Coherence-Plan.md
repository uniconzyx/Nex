# 凯喵 Code 试炼录 · 可玩性与连贯性方案

> 版本：v1（2026-10-28）
> 范围：`frontend/`（React UI）+ `content/`（玩法数据）+ 可选的 `server/`（判题历史）
> 前提：沿用现有视觉体系（`kaimao.css` 令牌）与项目既有铁律——**不做假数据**。

---

## 0. 一句话结论

这个项目**不缺内容，缺的是把内容连起来的那几根线**：

- 图鉴里躺着 **260 条**真实八股，UI 一条都没读；
- 题库有 **979 道**题，判题结果只活在会话内，刷新即失；
- 项目池有 **110 个**真实仓库，与 141 章之间**没有任何依赖边**；
- 进度模型只有 6 个字段，其中学习数据只有两个布尔集合。

所以「可玩性」不是加动画，而是**把已经存在的数据变成可见的因果**；「连贯性」不是加导航，而是**让每一步都改变下一步**。

## 1. 现状盘点（全部实测）

### 1.1 内容资产

| 资产 | 规模 | 位置 | 当前被谁消费 |
|---|---|---|---|
| 章节 | 141 章（规划覆盖 141/141，三视角 519/519） | `content/<subj>/<ch>/` | 知识试炼区、题库筛选 |
| 图鉴条目 | **260 条**（15 学科，3~6 类/学科） | `content/<subj>/_bagua.json` | **无人消费** |
| 练习题 | **979 道** | `content/<subj>/<ch>/exercises.json` → `bundle.ts` | 试炼实验室（判题需后端） |
| 项目 | **110 个**（T1~T4，含真实 star） | `content/_projects/career*/` | BOSS 项目实战 |
| 章节先修 | 每章 `prerequisites` | `content/<subj>/_manifest.json` | 仅用于展示 |

### 1.2 进度模型（`frontend/src/lib/progress.ts`）

```ts
interface ProgressState {
  theme: Theme;
  outfit: string;
  doneProjects: string[];   // 只有"通了/没通"
  doneChapters: string[];   // 只有"掌握/没掌握"
  checkins: string[];
  coins: number;            // 初始 1280，只增不减
}
```

EXP 的算法是纯线性的：

```
exp = doneChapters×20 + doneProjects×30 + checkins×50
level = 1 + floor(exp/300)
```

### 1.3 模块连通情况

| 模块 | 数据来源 | 玩家看到的 | 闭环 |
|---|---|---|---|
| 主城首页 | 上述 6 字段 | EXP/等级/下一站/今日目标 | 半（只增，不反馈原因） |
| 知识试炼区 | BUNDLE + doneChapters | `0/20 章`、每章「展开」 | 半（布尔，无过程） |
| BOSS 项目实战 | BUNDLE.projects + doneProjects | T1~T4 + 通关勾 | 半（无解锁条件） |
| 试炼实验室 | 979 题 | 筛选 + 判题 | **断**（结果不落库） |
| 怪物图鉴 | 无 | 空态（自述"尚未落库"） | **断** |
| 剧情日志 | 6 字段推导 | 5 个里程碑 | 半（静态） |
| 签到祭坛 | checkins | 连续天数 | 闭环（但产出无差异） |
| 每日试炼 | 硬编码 | 固定推荐 GoogleTest | **断**（不随进度变） |

## 2. 五个断层（按修复价值排序）

**F1 结果不落库** —— 判题失败后什么都没留下，玩家无法「看见自己的错误」。这是可玩性的第一杀手：一次失败没有任何后果，也就没有「再来一次」的理由。

**F2 内容零消费** —— 260 条精心写的八股（带 `tags` / `difficulty` / `hot` / `source_ref`）没有入口。这是最容易兑现的一块，也是投入产出比最高的。

**F3 目标单层** —— 只有「下一站」一条线，没有「今天做什么 / 这周做什么 / 这个学科怎么算通关」的三层节奏。玩家打开应用时靠自觉，而不是靠牵引。

**F4 无依赖图** —— 章节有 `prerequisites` 但 UI 不用；项目没有 `requires`；图鉴条目没有章节绑定。三者互不引用，于是「学完 ch05 该做什么」这个问题没有数据能回答。

**F5 经济无出口** —— coins 只有收入（签到/通关），没有任何支出。货币没有 sink 就等于没有货币，只是装饰性数字。

## 3. 设计支柱与核心循环

三条支柱，任何新玩法必须至少满足两条，否则不做：

1. **因果可见**：玩家的每个动作，都能在另一个模块里看到结果。
2. **三层节奏**：一次会话（5 分钟）、一天（30 分钟）、一周（3 小时）各有明确目标。
3. **兑现承诺**：UI 上已经写出去的话（「答错变怪物，重做收服」）必须真的成立。

核心循环（四个环，逐层放大）：

```
内环  每日 3 题 ──► 判题 ──► 错题变怪物 / 答对收服 ──► 金币 + EXP
  │                                                  │
中环  章节 3 关 ──► 掌握度 0→100 ──► 解锁项目 ────────┤
  │                                                  │
外环  周 Boss ──► 称号 + 装扮碎片 ────────────────────┤
  │                                                  │
元环  剧情 141 幕 ──► 学科通关 ──► 图鉴全集 ───────────┘
```

## 4. 可玩性：五个系统

### S1 章节闯关化（把布尔升级成掌握度）

**规则**：每章拆 3 关，全部通过才算「掌握」。

| 关 | 内容 | 通过条件 | 权重 |
|---|---|---|---|
| 概念关 | 读 `concept/*.md` + 3 道 choice 题 | 3 题全对 | 30 |
| 演练关 | 打开该章 `examples/` 里任意 2 个示例并答对 1 道 output 题 | 1 题对 | 30 |
| BOSS 关 | 1 道 coding 或 design 题（判题/自评） | verdict=AC 或自评达标 | 40 |

**数据契约**：

```ts
interface ChapterRun {
  concept: 0 | 1; drill: 0 | 1; boss: 0 | 1;
  mastery: number;        // 0~100，由三关权重累加
  attempts: number;       // 总尝试次数，用于「反复卡住的章」提示
  lastAt: number;
}
type ChapterRuns = Record<string, ChapterRun>;
```

**UI 落点**：`LearnPage` 章节卡右侧由「展开」改为三颗星 + `mastery%` 细条；`doneChapters` 变成派生值（`mastery===100`），旧数据迁移时 `doneChapters` 里已有的章直接置 100。

**验收**：老用户升级后 `doneChapters` 一个不丢；新用户做对 3 道 choice 后，卡片从 0% 变 30%。

---

### S2 错题即怪物（**最高优先，先做这个**）

现状是图鉴页自述「判题结果只保存在会话内，所以图鉴是空的」——这句话本身就是最该修的东西。

**规则**：

1. 任何一次判题/练习失败 → 生成一只 `wild` 怪物，`hp` = 累计失败次数；
2. 同一题再次作答通过 → 变 `tamed`，计入图鉴收集；
3. 稀有度取题目难度：`easy=普通`、`medium=精英`、`hard=首领`；`hot` 标记的题给「闪光」变体；
4. 图鉴页的「情报」面板从 `_bagua.json` 里按 `tags` 命中取 1~2 条真实八股（`q/a` 折叠展示）——这一步把 260 条内容一次性接上。

**数据契约**：

```ts
interface Monster {
  questionId: string;
  chapterId: string;
  state: 'wild' | 'tamed';
  fails: number;
  firstAt: number;
  tamedAt?: number;
}
type Bestiary = Record<string, Monster>;   // key = questionId
```

**为什么先做它**：

- 激活已有资产最多（979 题 + 260 图鉴条目）；
- 新增状态最少（一个 map）；
- 兑现 UI 上已经承诺的玩法，成本最低、感知最强；
- 它同时是 S3（每日试炼）的数据源。

**验收**：随便做错一题 → 切到图鉴，立刻出现一只怪物并带该题所属章节；重做通过 → 卡片翻面变「已收服」；刷新页面状态不丢。

---

### S3 每日试炼动态化

**规则**：每天 3 题，来源固定优先级：

1. `wild` 怪物里 `fails` 最高的 2 道（错题优先复习）；
2. 当前章未做过的新题 1 道（推进度）。

完成 3 题 → `+50` 金币、连胜保持；3 题全对额外 `+20`。

**数据契约**：

```ts
interface DailyRun { date: string; qids: string[]; done: string[]; allCorrect: boolean }
```

**UI 落点**：`HomePage` 的「今日试炼」卡由硬编码改为 `0/3` 进度 + 三题入口；全部完成显示「今日已清空，凯喵睡了」。

**验收**：连续两天打开，题目集合随错题变化；清空后按钮变灰且在次日 0 点重置。

---

### S4 周 Boss

**规则**：每周从项目池按难度取 1 个 T2 项目作为周 Boss，前置门槛可检查：

- 本周完成 ≥3 章（`mastery≥80`）；
- 该项目 `requires` 里的章节全部 `mastery≥60`。

通关 → 称号 + 1 个装扮碎片（装扮碎片可累积，用于 S5 抽取）。

**数据契约**：

```ts
interface WeeklyBoss { weekKey: string; slug: string; accepted: boolean; doneAt?: number }
```

**验收**：门槛未达成时按钮禁用并显示缺哪一章；达成后可接，完成后称号出现在个人档案。

---

### S5 经济闭环（给金币一个出口）

| 收入 | 数额 | 支出 | 数额 |
|---|---|---|---|
| 每日试炼清空 | +50 | 看一条提示 | −20 |
| 章节三关全通 | +60 | 判题失败续命（保连胜） | −50 |
| 项目通关 | +100×tier | 抽装扮（碎片折价） | −200 |
| 签到 | +20 + 连胜×5 | 跳过每日冷却 | −30 |

**数据契约**：`coinLedger: {ts, delta, reason}[]`，只保留最近 50 条，背包页展示最近 10 笔。

**验收**：任何一笔金币变动都能在背包页看到原因；余额不会被写成负数（`¥` 不足时按钮禁用并提示差额）。

## 5. 连贯性：四条机制

### C1 单一事件流（所有页面的唯一真相源）

现在每个页面各自读 `doneChapters` / `doneProjects` 算自己的东西，所以新增一个维度就要改 N 个页面。改成「动作 → 事件 → reducer → 派生状态」：

```ts
type ProgressEvent =
  | { type: 'stage';  chapterId: string; stage: 'concept' | 'drill' | 'boss'; ok: boolean }
  | { type: 'judge';  questionId: string; chapterId: string; ok: boolean; verdict: string }
  | { type: 'project'; slug: string; ok: boolean }
  | { type: 'checkin'; date: string }
  | { type: 'spend';  delta: number; reason: string };

function dispatch(e: ProgressEvent): void;   // 纯函数 reducer，写 localStorage + 通知订阅者
```

所有页面只从 `useProgress()` 读派生结果（`mastery` / `bestiary` / `daily` / `nextAction`），不再自己算。这一条是后面所有系统的地基，必须先做。

---

### C2 依赖图（章节 → 项目 → 图鉴）

三张表现成的关联字段：`chapters[].prerequisites`、图鉴 `tags`、项目 `stack`。

补齐缺的两个：

1. 项目加 `requires: string[]`（章节 id）——可用脚本按 `stack` 与章节标题的标签重合度自动生成初稿，再人工抽检；
2. 图鉴条目补 `id` 与 `chapterIds: string[]`——按 `tags` 匹配章节标题，脚本生成。

**自检**：`scripts/audit_graph.py` 检查①无环 ②无指向不存在章节的边 ③每个项目至少 1 个 requires ④每个图鉴条目至少绑 1 章。

---

### C3 NextAction 引擎（只推一件事）

现在首页只有一条「下一站」，而且不会变。改成一个按优先级打分的函数：

```
1. 今日试炼未完成        → 「今日试炼 0/3」          → /lab
2. 有 wild 怪物          → 「3 只怪物等你收服」      → /bestiary
3. 当前章有未通过的关    → 「继续 ch05 第 2 关」     → /learn
4. 有解锁未开始的项目    → 「ch05 通了，可以开 TinyRenderer」 → /projects
5. 下一章前置满足        → 「开新章 ch06」            → /learn
6. 今日未签到            → 「祭坛的火要灭了」        → /checkin
```

返回 `{ title, subtitle, cta, target }`，首页大卡、侧栏徽标、「继续闯关」按钮**共用同一个结果**——这是「连贯」最直接的体感来源。

---

### C4 叙事映射（141 幕，而不是 5 条）

现状 5 个里程碑里最后一条是「通关 T4 项目」，对绝大多数玩家永久锁死。

改法：每章一句「凯喵旁白」，来源是 `goals.md` 里已有的「三句关键认知」（脚本抽取，不新增写作量）：

```ts
interface Narration { chapterId: string; line: string; act: number }  // act = 每 5 章一幕
```

剧情页按学科分幕展示：完成的章点亮对应台词，未完成的显示「？？？」但**露出幕标题**（保持牵引）。累计 5 句推进一幕，学科 20 章 = 4 幕 + 终章。

**验收**：完成 ch01 后剧情页出现该章台词；抽检 10 条台词与该章 `goals.md` 的关键认知一致。

**P2 的两个设计取舍**（P3 会沿用，别改）：

1. **三关是作答的投影，不是独立字段。** `chapterRuns` 由 `answers` 每次重算（`deriveRuns`），

   硬锁会让"我做过类似项目"的用户感到被程序否定，软门槛只做推荐。

## 8. 度量与自检

### 8.1 可玩性指标（本地可测，不依赖账号）

- 图鉴「空态 → 有记录」转化率（做错一题即 100%，看有多少人到过图鉴页）
- 每日试炼清空率（当日完成 3/3 的会话占比）
- 错题 7 日内重做率（`tamed.tamedAt - firstAt ≤ 7d` 的比例）
- 单会话完成关卡数（`stage` 事件计数）

### 8.2 连贯性指标

- NextAction 点击率（首页大卡的点击 / 首页曝光）
- 「章节 → 项目」转化率（完成某章后 24h 内开始一个 requires 含该章的项目）
- 跨模块跳转率（一次会话内访问 ≥3 个不同页面的会话占比）

### 8.3 自动化自检 `scripts/audit_playability.py`

沿用本项目「审计脚本化」的习惯，检查四件事：

1. 每个导航页都有非空数据源（禁止把硬编码空态文案当最终态）；
2. 每条 `_bagua.json` 条目至少能被一个页面读取（现在 260 条全部不通过）；
3. 每个项目的 `requires` 指向真实章节；
4. 每条金币变动都在 `coinLedger` 里可追溯。

## 9. 非目标（明确不做）

- **不做假数据**：不编造怪物、不编造好友榜、不编造"学习曲线"。没有数据就显示空态 + 入口（现有原则，继续保持）。
- **不做实时对战/好友排行**：无账号体系，只保留接口位。
- **不做付费与广告**。
- **不推翻视觉体系**：所有新组件沿用 `kaimao.css` 令牌，不引入新配色。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 判题依赖后端（当前 8000 未起、Docker 未启动） | P1 无法端到端 | 判题结果**先落 localStorage**，后端只做同步；离线可用 |
| `progress` schema 变更 | 老用户数据丢失 | v2 键 + 显式迁移 + 保留 v1 只读副本；迁移失败回默认并提示 |
| 内容侧仍在改 86 章来源 | 图鉴 tags 漂移 | 图鉴用「按 tags 匹配」而非硬编码章节映射；匹配不到就归入「未归类」 |
| 章节掌握度口径与题库题量不匹配（130 题 / 20 章） | 掌握度失真 | 掌握度只由「每章 3 关」决定，题库题量仅用于每日试炼抽取 |
| 玩法膨胀掩盖学习 | 本末倒置 | 每个系统必须有「离开它学习仍可完成」的降级路径 |
