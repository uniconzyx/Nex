# DeepTutor 能不能接进凯喵？—— 接入可行性评估与推荐

> 评估日期：2026-10-30
> 评估对象：`HKUDS/DeepTutor`（v1.7.0，2026-10-28 发布）
> 评估范围：CppMind「凯喵」AI 助手（`/ai/chat` + `lib/agent`）

---

## 0. 结论先说

| 接法 | 一句话 | 建议 |
|---|---|---|
| **A 整仓嵌入**：把它整个跑起来，前端 iframe / 子进程，用它的界面 | 拿到 9 种模式，但要背两套用户体系、两套 UI、一个 Node 22 运行时 | **不做** |
| **B Sidecar 服务**：Docker 起 `3782/8001`，只调它的 CLI 或 `/api/*` | 多格式解析 + 多引擎 RAG + 深度研究，作为「用户自带资料」的问答后端 | **可选**，只在做「上传讲义/PDF」时值得 |
| **C 只借设计**：不跑它的代码，抄它的记忆模型 | 三层记忆能被你现有数据 80% 覆盖，补齐只要 1–2 天 | **推荐** |
| **D 更轻的替代**：自己的 Postgres 加 pgvector | 目标只是「能问自己的资料」时，比 B 便宜一个数量级 | **推荐**（按需） |

**推荐组合：C 先做，D 按需补；B 留作「多格式文档」的备选；A 明确不做。**

## 1. DeepTutor 客观参数（不掺评价）

| 项 | 值 |
|---|---|
| 归属 / 许可 | HKUDS（港大数据智能实验室）/ **Apache-2.0**，可商用可改 |
| 体量 | 约 **200k 行** Python；~48k stars；224 contributors |
| 版本节奏 | 2025-12 建仓，**每周发版**；v1.0.0-beta.1 → v1.7.0 半年 |
| 后端 | FastAPI，容器内 **8001**，路由挂 `/api/*`、`/ws/*` |
| 前端 | **Next.js 16 + React 19**，容器内 **3782**（唯一必须发布的端口） |
| 运行时 | Python **3.11–3.14**、Node **20+**（源码装要 22 LTS） |
| 存储 | SQLite（工作区注册表）、JSON 配置文件在 `data/user/settings/` |
| RAG 引擎 | LlamaIndex / PageIndex / GraphRAG / LightRAG / WeKnora / Kiwix / Obsidian / FAISS，可插拔 |
| 记忆 | **L1 轨迹 → L2 表面摘要 → L3 综合**，Memory Graph 把 L3 挂回 L1 证据，可见可改 |
| 认证 | 默认**关闭**（`AUTH_ENABLED=false`）；开启后 JWT + 多用户隔离 + 管理员角色 |
| 扩展 | MCP servers、CLI apps、EduHub 技能、图像/视频/语音生成 |
| 编程入口 | PyPI `deeptutor` / `deeptutor[full]`；CLI（`deeptutor run deep_solve "..." --kb my-kb`）；源码可 import |

**关键事实：它是一个「产品」，不是一个「库」。** 官方给的程序入口是 **CLI 和整包安装**，`/api/*` 是前端自己用的内部路由（认证提交记录里能看到路径，但没有对外 API 契约文档）。

## 2. 你现在已经有什么（这决定了值不值得接）

| DeepTutor 能力 | CppMind 现状 | 判断 |
|---|---|---|
| 检索增强（RAG） | `server/app/services/retrieval.py`：**BM25 RAG-lite**，中英混分、subject/chapter 过滤、命中带 `source_ref` 回传 | 已覆盖 80%，且零外部依赖 |
| 出题 / 题库 | 962 道前端题、553 道后端可判、判题三件套闭环（:`8000` + `judge_local:2358` + arq worker） | 已覆盖且更深（能真判代码） |
| 掌握度 / 学习路径 | progress v2：`answers` → `chapterRuns` → mastery → 三关 → `NextAction` | 已覆盖，差「跨章排序视图」 |
| 学习轨迹 | `dispatch` 事件流 + `get_progress` 工具 | **就是天然的 L1** |
| 多格式文档解析（PDF/PPT/视频字幕） | 无（内容都是自写 Markdown） | **真缺口** |
| 深度研究 / 多引擎 RAG 对比 | 无 | 真缺口，但你现在不需要 |
| 视频课 / 音频概览 | 无（有 B 站 BV 直链，只是链接） | 缺口，属可选 |
| MCP / CLI 工具生态 | agent 层 7 个工具（本地函数），无 MCP | 缺口，但你自己写工具更可控 |
| 会话记忆 | 无（每次 chat 无长期记忆） | **真缺口，且是 C 方案的主战场** |

结论：DeepTutor 的**主体能力（RAG + 题库 + 掌握度）你已经有了，而且更贴合 408**。它对你真正新增的只有三样：**多格式解析、深度研究、三层记忆**。

## 3. 三种接法详评

### A. 整仓嵌入 —— 不推荐

做法：Docker 起 DeepTutor，CppMind 用 iframe / 新窗口嵌它的 Next.js 页面，或反过来把它当主界面。

- **收益**：一次拿到 9 种模式（Chat / Quiz / Research / Visualize / Solve / Mastery / 沉浸阅读 / 音频）。
- **代价**：
  1. **两套用户体系**。它以 JWT + 多用户为默认，你已有 `session.ts` + 云端进度镜像。要么它关认证当单机用（多用户隔离就没了），要么你写 SSO 桥。
  2. **两套 UI**。它是 Next.js 16 自带皮肤，你的 `--km-*` 令牌、深浅双主题、7 组左侧导航全作废。等于把刚敲定的设计体系让位。
  3. **两套内容**。它认「知识库」，你的 141 章 Markdown + 962 题要重新灌成 KB 才能被它用；而你的 `bundle_id` 1:1、判题、掌握度它一概不认。
  4. **运行时成本**：多一个 Node 22 + Python 3.11+ 的常驻栈，再加 ≥1 个模型 provider。
  5. **升级绑架**：每周发版的项目，你嵌得越深，越不敢升。
- **判断**：付出的是「架构主导权」，换回来的是「你已经有的功能」。**不做**。

### B. Sidecar 服务 —— 可选，条件明确

做法：`docker run -p 127.0.0.1:3782:3782 -p 127.0.0.1:8001:8001 -v deeptutor-data:/app/data`，CppMind 后端在 `/ai/chat` 里加一个 `deeptutor` provider；**调 CLI 而不是调 `/api/*`**。

- **适用前提**：你要做「用户上传自己的讲义 / 真题 PDF / 网课字幕，然后问凯喵」。这是你现有内容体系之外的场景。
- **为什么调 CLI 不调 HTTP**：`/api/*` 是它前端自用的内部路由，随版本变动无契约；CLI 是它文档里公开的入口（`deeptutor run <mode> "<q>" --kb <name>`），版本间更稳。
- **必须写的三件事**：
  1. **进程守卫**：sidecar 不在 → `/ai/chat` 静默退回本地 BM25（不能因为没开容器就整页报错）。
  2. **超时**：深度研究动辄 30s+，要 SSE 心跳 + 可取消，别把 SSE 连接拖死。
  3. **数据边界**：上传的文件落在 `deeptutor-data` 卷，不进你的 Postgres，避免两套真源。
- **代价**：一个 ~GB 级镜像、一份额外模型账单、一个需要长期跟版本的适配层。
- **判断**：**只有当 B 的收益（多格式解析）被真实需求触发时才上**。现在就上，是为一个还没出现的功能付维护税。

### C. 只借设计 —— 推荐，且成本最低

不跑它的代码，只把它的**记忆模型**翻译成你已有数据的视图：

| DeepTutor 层 | 你已有的对应物 | 要补什么 |
|---|---|---|
| **L1 轨迹**（原始交互与证据） | `dispatch` 事件流、`answers`、每次判题记录 | 落一张 `agent_trace` 表（或 localStorage 追加），带 `evidence_ref` |
| **L2 表面摘要**（从 L1 提炼的事实） | `chapterRuns` / mastery / 错题即怪物 | 一条「逐章画像」：掌握度 + 常错知识点 + 最近 N 次正确率 |
| **L3 综合**（高阶画像） | `NextAction`、`get_progress` 的 stuck-first 排序 | 一个「学习画像」页：三条结论 + 每条能点回 L2/L1 证据 |
| Memory Graph | 无 | **不做图**。用「结论 → 证据 id 列表」的纯文本链接即可，视觉上就是你已有的证据链样式 |

为什么这条最划算：
- 你的 **L1 已经存在**（事件流是 P2 已交付的），只是没有当下游素材用；
- 你的 **L2 已经 90% 存在**（mastery + chapterRuns 就是事实摘要）；
- 你缺的只是**把 L1/L2 组织成 L3 并让用户能审查**——这正是 DeepTutor 论文里最值得学的部分（「个性化可见可编辑」）。
- 1–2 天，零新依赖，零新进程，不动 UI 体系。

### D. 更轻的替代（如果目标只是「能问自己的资料」）

- 你**已有一个 Postgres**（Docker 里那个）。加 `pgvector` 扩展 + 一张 `doc_chunk` 表（`embedding vector(1024)`），chunk 你的 Markdown 和用户上传的 PDF（PDF 用 `pypdf` 抽文本即可）。
- 检索走「BM25 召回 20 条 → 向量重排」的混检，比纯 BM25 明显好，比拉一套 LlamaIndex 便宜得多。
- 1–2 天，不引入 Node 22 / Next.js / 第二个向量库。

**什么时候 D 不够、必须上 B**：要解析扫描版 PDF（要 OCR）、PPT 图形、视频字幕并做时间戳定位。这三个是 DeepTutor 的真正护城河，也是你短时间内自己写不出来的。

## 4. 落地顺序（如果按推荐走）

1. **本周**：C 方案。写 `docs/` 里的画像页规格 → `lib/agent/profile.ts`（纯函数，可从 progress 推导）→ 一个「学习画像」页，三条结论各挂证据。
2. **下一轮**：D 方案，前提是「用户想传自己的资料」这个需求被确认。先只支持 Markdown / TXT，PDF 后置。
3. **触发条件**：出现 OCR / PPT / 视频字幕需求 → 再评估 B。评估时先跑 `deeptutor run` 的 CLI 冒烟，别先写适配层。
4. **永不做**：A。

---

## 5. 与当前正在做的 UI 优化的关系

- 本评估**不改动** UI 优化批次一（横幅 / 字号 / hash 路由）的结论，两者独立。
- 但 C 方案的「学习画像」页会新增一个路由，**必须先定路由名再动**，避免和批次二的「就业工作台三 Tab」抢导航位。
- 建议路由：`#profile` 已被 `me` 占用语义（`ProfilePage`），新页用 **`#insight`**（后端已有 `services/insight.py`，语义一致）。

## 6. 风险清单

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 跟版本成本失控 | 接了 B 且它改 `/api/*` | 只依赖 CLI；锁 PyPI 版本号 |
| 双真源（文件在它那、进度在你这） | 接了 B 且用户用它做练习 | 明确分工：它只做「资料问答」，练习一律回 CppMind |
| 记忆写坏无法回滚 | C 方案的 L2/L3 落库 | 全部可从 L1 重算（派生而非真源），与你 progress v2 的既有原则一致 |
| 模型账单翻倍 | B + 它自己的 provider 配置 | 复用同一个 `ai_provider` 配置，不另开 key |
