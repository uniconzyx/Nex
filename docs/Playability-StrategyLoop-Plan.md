# 高可玩性策略循环 · 阶段化交付方案

> 在 **CppMind / 凯喵 Code 试炼录** 现有「冰蓝奶白磨砂玻璃拟态」视觉体系之上，新增一整套
> 轻 RPG / Roguelite 风格的策略外循环。本文档把主人一次性提出的 12 个子系统拆成可独立验收、
> 可增量交付的阶段，并锁定「不推翻现有视觉语言」这一硬约束。

---

## 0. 硬约束（必须全程遵守）

1. **保留现有视觉体系**（来自主人的明确要求，覆盖 `design-taste-frontend` skill 的 no-glass / no-shadow 铁律）：
   - 冰蓝奶白磨砂玻璃拟态（`--km-surf1/2` + `backdrop-filter: blur`）
   - 14px 统一圆角、柔和阴影（`--km-sh-soft`）
   - 轻 RPG 学习闯关语义（错题=怪物、掌握度、三关、依赖图）
   - 手机安全区（`env(safe-area-inset-*)`）、圆润字体 + 代码等宽、超大触控按钮
   - 冰蓝下划线标签、页面顺滑淡入、隐藏滚动条
2. **延展而非另起炉灶**：新系统复用现有 token、卡片、弹窗、导航骨架，只新增「策略层」专属 token（稀有度、羁绊、词条、粒子层）。
3. **Mock 数据仅限原型阶段**：真实功能必须接现有的 `progress.v2` / `dispatch` 事件流 / `mastery` / `chapterRuns`，不另造一套状态。
4. **借用 skill 的「反 AI 套路」内核**（忽略其视觉禁令）：每屏真实内容密度、每屏一个可交互的 *live thing*、统一动效层、不做千篇一律的图标卡片栅格。

## 2. 推荐阶段顺序（每阶段可独立验收）

- **阶段 0 · 统一交互骨架（S0）**：抽象出 `KaimaoFab` / `BottomSheet` / `useLongPress` / `PressableCard` / `Particles` / `usePageFade` / 全局滚动条隐藏 / 安全区 wrapper。验收：在现有页面套用后视觉无回退 + 真机安全区截图。
- **阶段 1 · 章节分支路线地图（S1）**：复用现有内容图，渲染分支路线。验收：`#route` 页可看可点，标注推荐/支线/卡点。
- **阶段 2 · Build 雏形 + 秘境爬塔（S3+S2）**：先有 Build 数据结构与面板，再做每日秘境三选一词条爬塔。验收：真能开一局、选词条、结算。
- **阶段 3 · 牧场 + 合成（S5+S6）**：错题怪物养成/派遣 + 资源合成闭环。验收：派遣产出 → 工坊消耗 → 新道具。
- **阶段 4 · 回合策略连携（S4）**：在试炼/秘境接入回合战斗与连携结算。验收：一局连携伤害正确。
- **阶段 5 · 周常/无尽 + 赛季/收藏（S7+S10）**：周常挑战、无尽模式、通行证轨道。验收：赛季等级推进 + 奖励解锁。
- **阶段 6 · 事件多结局 + 每日联动 + 复盘 + 榜单（S8+S11+S9+S12）**：动态事件流、每日目标联动、失败自动复盘、本地多榜与档案。

## 3. 统一交互骨架的技术骨架（S0 设计）

```
src/
  components/
    KaimaoFab.tsx          # 右下角悬浮按钮（冰蓝发光，谐振微动）
    BottomSheet.tsx        # 底部上滑弹窗（磨砂玻璃，drag-to-dismiss）
    PressableCard.tsx      # 卡片按压下沉 + 柔光（:active 态）
    Particles.tsx          # 冰蓝粒子层（CSS/轻量 canvas，prefers-reduced-motion 降级）
    LongPressPreview.tsx   # 长按预览（tooltip / 弹层）
  hooks/
    useLongPress.ts
    usePageFade.ts         # 路由切换顺滑淡入
    useSafeArea.ts         # 安全区 inset 读取
  styles/
    interaction.css        # 隐藏滚动条 / 按压 / 淡入 / 粒子 keyframes
```

所有新页默认套用 `BottomSheet` 做次级操作、`KaimaoFab` 做主入口、`PressableCard` 做列表项。

## 4. 视觉体系延展（仅新增策略层 token，不动现有）

```css
/* 在 kaimao.css 的 :root / 暗色块内追加，沿用 --km- 命名 */
--km-rarity-1: #8aa0b8;  /* 普通 */
--km-rarity-2: #5b9bd5;  /* 稀有 · 冰蓝主色 */
--km-rarity-3: #b98cff;  /* 史诗 · 注意：skill 禁用紫，但作为稀有度语义色可接受，需主人拍板 */
--km-rarity-4: #f0b35b;  /* 传说 · 暖金，仅作点缀 */
--km-bond: #6fd3c0;      /* 羁绊高亮 */
--km-particle: rgba(91,155,213,0.5);
```

> 注：`--km-rarity-3` 用了紫，与 `design-taste-frontend` 的「禁用紫」冲突。因其在游戏语义里是「史诗稀有度」而非装饰，建议保留；若主人介意，可改青绿梯度。

## 5. 首刀建议

单轮无法稳交付 12 个系统。建议**本会话先落阶段 0（S0 统一交互骨架）**，因为它：
- 是所有后续系统公共底座，先做能显著降低后续返工；
- 风险低、可独立验收、不碰业务数据；
- 能立刻让现有页面交互质感统一提升，主人可先感受方向对不对。

待 S0 验收通过后，再按阶段 1→6 逐块推进，每块增量验证并给你下一步选项（符合主人一贯的「分阶段、增量验证」节奏）。

## 6. 需主人拍板的开放问题

1. **首刀切哪块**：阶段 0 骨架（推荐）/ 还是直接做阶段 1 路线地图 / 还是先出一版静态 HTML 视觉稿锁风格？

3. **数据持久化**：策略循环新增状态（Build、牧场、赛季）是否仍走本地 `progress.v2`（无后端），还是本期就要接后端账户？
