## 方案 A ｜ 密度重构（Evolution）

**一句话**：不动设计语言，只把「看不见的信息」摊开、把「没用的占位」收掉。约 1.5 天。

### A1 保留什么
- `--km-*` 全部令牌、蓝色主色（`#5b9bd5`）、圆角与阴影体系
- 左侧 7 组导航、右侧凯喵栏的结构
- 所有现有路由与数据

### A2 改什么

1. **顶栏合并**：后端状态从 3 行横幅收进顶栏右侧一个圆点 + tooltip（灰=离线/绿=在线，点开才展开重试）。
   首屏立刻多出 ~90px。
2. **字号体系升一档**：正文 13→15px，说明性文字 12→13px，页标题 22→28px；`ink-faint` 只用于元信息（时间/计数），说明文字改用 `ink-soft`。
3. **右栏按页收缩**：`#employment` `#reexam` `#agent` `#diagrams` 这类「工具页」把凯喵栏折成 56px 竖条（只留头像与今日目标进度环），主内容区 +180px。
4. **就业板块信息架构**（本方案的合并做法）：
   - 导航项改名：`就业八股` → **`就业`**
   - 单页三 Tab（Tab 而不是分区堆叠，避免一页三块互相挤）：
     - **八股图谱**：现有四区 A/B/C/D 改为左侧可折叠分类树 + 右侧详情面板（选中即显示，不再点击展开）
     - **面试冲刺**：复用现有 Agent 八股专项 + 新增「按岗位归类」的面试题卡（数据待补，见 A4）
     - **简历优化**：见 A4
5. **章节列表**：`01/02/03` 序号改为「进度环 + 掌握度数字」；三关的三个圆点改为文字 `概念✓ 演练· BOSS·`，颜色不再是唯一编码（解决 UX-003）。
6. **修 P6**：`App.tsx` 加 `hashchange` 监听，浏览器前进/后退与手改 hash 都生效（~15 行）。

### A3 视觉规格
- 字号：`28 / 20 / 15 / 13`（4 级）
- 间距：区块间 `28px`，卡片内 `14~16px`
- 圆角：沿用 `--km-r 16 / --km-r-sm 12`
- 新增令牌：`--km-ink-mute`（`#6b7d92`，替代说明文字的 faint）
- 不加新色相，不引入新字体

### A4 简历优化（功能骨架）
纯前端离线，四步：

| 步骤 | 做什么 | 数据来源 |
|---|---|---|
| 1 生成初稿 | 从**你的真实学习数据**自动生成简历条目：通关章节 → 技能清单，完成项目 → 项目经历（含技术栈与验收指标） | `progress.ts` + `graph.ts` + `projects` |
| 2 粘贴 JD | 文本框粘贴岗位描述；前端 BM25（复用 `agent/tools.ts` 的 `searchLocal` 那套分词）提取关键词 | 用户输入 |
| 3 三态匹配 | 每个关键词标 **已支撑 / 可补强 / 缺口**；缺口**如实标红，不自动塞进简历**（对齐 ai-job-search 的诚实规则） | 步骤 1+2 |
| 4 导出 | Markdown → 浏览器打印为 PDF；同时给 `atsText` 纯文本视图，模拟 ATS 读到的内容 | 复用 `agent/report.ts` 的导出思路 |

不做：LaTeX 编译、真实投递、爬取招聘网站（离线原则）。

### A5 验收
- `shot_ui_audit.mjs` 同类脚本：4 页 × 2 宽度截图，断言首屏不含横幅、就业页 Tab 切换正常
- `check_contrast.mjs` 全绿；新增文字对底色 ≥ 4.5:1
- 键盘 Tab 能走完就业页所有节点（修 UX-004）
- 前进/后退 5 次，页面正确切换

### A6 风险
- 字号整体上调会让现有紧凑布局溢出（learn 页行高需同步调），要逐页过一遍
- Tab 化后「八股图谱」从一屏全览变成需切换，**扫描性下降**——这是本方案最大的取舍

## 方案 B ｜ 工作台重构（Redesign）

**一句话**：把「就业」从一个资源清单页改成真正的求职工作台，视觉上引入第二中性色与 Bento 网格。约 3~4 天。

### B1 保留什么
- `--km-*` 蓝色主色相（品牌识别）
- 左侧导航、移动端单列折叠逻辑
- 所有数据与路由

### B2 视觉方向（ui-ux-pro-max 推导结果）
引擎对「career services dashboard for CS students」的推导：产品类型 **Job / Career**（置信 10.457），风格 **Corporate/Enterprise**（备选 Minimalism / Card-Based），调色板 **#68 Warm Triadic**：

| 角色 | 值 | 与现有体系的关系 |
|---|---|---|
| primary | `#3173C4` | 与 `--km-accent #5b9bd5` 同色相（~212°），更深一档，可用于「主行动」 |
| bg | `#F6F7F9` | 替代现在偏蓝的 `#eef4fb`，让内容区更中性 |
| surface | `#FFFFFF` | 与现状一致 |
| border | `#D7DFEA` | 替代现在的半透明 `--km-line`，边界更确定 |
| text | `#16181D` | 替代 `#26364a`，正文对比度 16.57:1 |

字体：**Inter**（现有未指定字体族，用系统栈）。字号 4 级：`32 / 20 / 15 / 13`。
效果：**Bento 网格**——用面积表达重要性，而不是用描边。

### B3 改什么

1. **首屏重构**：删除横幅，把「后端状态 / 主题 / 搜索」收进顶栏图标；首屏第一屏只剩「你现在的状态 + 今天该做的一件事」。
2. **就业板块改成三视图工作台**：
   - **图谱视图（Bento）**：四区按内容量占不同面积（A 区 2 个资源 → 小格，B 区 5 个 → 大格），格内直接显示节点名 + 角色，不需要点开
   - **冲刺视图**：左「岗位 JD」右「预测问题」（对齐 ai-job-search 的 `/interview`），问题按 JD 关键词生成，标注「会追问什么」
   - **简历视图**：见 B4（这是本方案的核心差异化）
3. **简历视图 = 双栏工作台**：
   ```
   ┌───────────── 左：编辑器 ─────────────┬────── 右：体检报告 ──────┐
   │ 基本信息 / 技能 / 项目 / 教育         │ 总分环 78                │
   │ （由学习数据预填，可直接改）          │ 关键词覆盖 12/17         │
   │                                      │ 量化密度 3/9 条          │
   │ 每条 bullet 旁有「改写」按钮          │ 动词强度 弱→强           │
   │                                      │ ATS 可读性 ✓            │
   └──────────────────────────────────────┴─────────────────────────┘
   ```
   右侧四项实时计算（纯函数，可单测），改动左边即时反映。
4. **动效层**：分数变化 200ms 数字滚动；切换视图 160ms 淡入位移；`prefers-reduced-motion` 全降级。

### B4 简历优化的四个机制（对标 ai-job-search，标注哪些是真借鉴）

| ai-job-search 的机制 | 我们怎么做 | 差异 |
|---|---|---|
| `/setup` 从文档建档案 | **从 app 的学习数据建档案**（通关章节/项目/掌握度） | 我们独有：数据是真的，不用用户手填 |
| 起草者 + 审查者双 agent | 复用 `lib/agent`：起草用一套 prompt，审查用另一套且**不看草稿上下文**，只拿成品挑刺 | 同源设计，已验证可行 |
| ATS 文字层检查（pdftotext） | 纯前端无法解析 PDF → 改为**约束排版本身**：单栏、无表格、无图标替代文字、标准小节标题、联系方式纯文本 | 手段不同，目的一致 |
| 关键词缺口如实标注 | 三态：已支撑 / 可补强 / 缺口；缺口不给「硬塞」按钮，只给「怎么补」建议 | 一致 |
| LaTeX 编译 + 版面校验 | 不做。导出 Markdown + 打印样式 | 明确砍掉 |

### B5 验收
- 简历体检四项指标有纯函数单测（`scripts/check_resume.mjs`）：给 3 份样例简历（差/中/好）断言分数单调
- 双 agent 评审能抓到至少 2 条真实问题（用固定样本回归）
- 全站 4 页 × 2 宽度截图无回归；对比度全绿
- ATS 文本视图与简历内容逐字一致（防"看着有其实没有"）

### B6 风险
- **改动面大**：涉及 4 个页面 + 新组件库，需要 3~4 天且中间态不能发布
- 引入 Inter 需要联网加载（离线 APK 场景要内嵌字体，+120KB）；也可以继续用系统栈，视觉收益略降
- Bento 网格在资源数量差异大时会出现「空格」，需要人工调面积

## 3. 两个方案对比

| 维度 | A 密度重构 | B 工作台重构 |
|---|---|---|
| 工期 | ~1.5 天 | ~3.5 天 |
| 动设计语言 | 否（只调字号/间距/信息展开） | 是（新增中性色、Inter、Bento） |
| 解决 P1~P6 | 全部覆盖 | 全部覆盖，且更彻底 |
| 就业板块 | 三 Tab，扫描性下降 | 三视图工作台，扫描性与深度兼顾 |
| 简历优化 | 能用（四步骨架） | 核心亮点（双栏实时体检 + 双 agent 评审） |
| 回归风险 | 低（局部） | 中高（全站） |
| 可回滚 | 逐页可回滚 | 需要 feature flag 或分支开发 |

**我的建议**：选 **B**，但**分两批落地**——先做 B 的「P1 横幅 + 字号/色板 + hash 路由」这三项（约 1 天，立刻见效且低风险），再做就业工作台与简历优化。A 的价值主要在于「不折腾就能变好」，如果你近期要发布，选 A 更稳。

## 4. 需要你敲定的三件事

1. **选 A 还是 B**（或 B 分两批）
2. **简历优化是否允许用你的真实学习数据预填**（这是最大差异化，但也意味着简历里会出现「在 CppMind 通关了哪些章节」）
3. **导航项改名**：`就业八股` → `就业`，页面内分「八股 / 面试 / 简历」——确认这个口径，还是你希望「面试」独立成一个顶层入口
