## 二、本次补齐的本地配置（改动清单）

1. **`server/.env`**：`database_url` 端口 `5433 → 5432`。
   原值指向 5433，而 `server/docker-compose.yml` 把 PG 映射到宿主机 `5432`，
   5433 是悬空端口，导致后端永远连不上库。现已对齐。
   （`.env` 已被 .gitignore 忽略，不会进版本库，符合"本机敏感配置不提交"铁律。）

2. **`server/alembic.ini`**：第 4 行中文注释改为 ASCII。
   原注释为 UTF-8 中文，Windows 下 configparser 以 GBK 读 ini 会抛
   `UnicodeDecodeError: 'gbk' codec can't decode ...`，使 `alembic upgrade head` 在任意
   Windows 机器必失败。这是一处真实的跨平台 bug，已修。

3. **首次执行数据库建表**：`alembic upgrade head` → 生成 41 张表
   （users / user_profiles / progress / exercises / wrong_questions / submissions /
   test_cases / ai_conversations / ai_messages 等）。

4. **重启后端**以加载新的 `.env`（database_url 指向 5432）。

## 三、一键复跑命令

前置：Docker Desktop 已启动（`server/docker-compose.yml` 中 PG/Redis 设了
`restart: unless-stopped`，守护进程起来后会自动拉起容器）。

```bash
# 0. 基础设施（PG + Redis），首次或重启 Docker 后执行
cd server && docker compose up -d

# 1. 建/更新表结构（有迁移变更时必须；首次已执行过）
server/.venv/Scripts/python.exe -m alembic upgrade head

# 2. 起后端 + 前端（会自动打开浏览器）
server/.venv/Scripts/python.exe scripts/dev_stack.py
# 仅后端： scripts/dev_stack.py --backend-only
# 仅检查： scripts/dev_stack.py --check

# 3. 浏览器打开 http://127.0.0.1:1420/
```

> venv 已建好（Python 3.13.14），依赖已装。换机器时：
> `python -m venv .venv && .venv\Scripts\python.exe -m pip install -r requirements.txt`
> （安装时需直连 PyPI：本机沙箱会把 pip 指到本地代理 127.0.0.1:31181，
> 该代理未起时设置 `no_proxy=* HTTP_PROXY= HTTPS_PROXY=` 走直连即可。）
