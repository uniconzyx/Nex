# 常见陷阱：Linux 文件系统与权限

> 每条都是「编译/执行能通过，但结果或安全性是错的」类型。按「现象 → 根因 → 正确做法」组织。

1. **`chmod 777` 当万能钥匙** —— 现象：权限报错就 `chmod 777`，问题"消失"了。根因：`777` 对目录意味着**任何人都能删改其中任何文件**（除非 sticky 位），对可执行/脚本文件意味着**任何人都能替换它**。若该目录在 web 根或 PATH 中，等于开放了任意代码执行入口。正确做法：先 `id` + `stat` 定位是哪个分组缺权限，把**属组**设对（`chgrp` + setgid）而不是放开其他人；确需共享写时用 `775` + setgid 目录。

2. **`chmod -R 777` 递归放开上传目录** —— 现象：图片上传失败，于是对 upload 目录递归 `777`。根因：`-R` 会把**执行位加到所有文件上**（包括上传的 `.php`、`.jsp`），配合 web 服务器解析 = 直接 RCE。历史上大量 webshell 事件源于此。正确做法：`chown -R www-data:www-data upload/` + `chmod 755`（目录）/ `644`（文件），需要写权限就只给**目录**加组写位。

3. **只看 `rwx` 不看属主/属组，误判 `Permission denied`** —— 现象：文件权限明明是 `777` 却仍报拒绝访问。根因：**权限判定是短路的** —— 命中属主分支时就用属主三位，不会再去尝试属组/其他位。若文件属主位是 `000`、你恰好是属主，即使其他位是 `777` 也会被拒。另一个常见变体：你不在文件属组、附加组也没生效（需重新登录才刷新组）。正确做法：排查三步 `id`（我是谁/在哪些组）→ `stat file`（属主属组权限）→ 分组比对；路径中间层缺 `x` 用 `namei -l` 逐级查。

4. **把 `rm` 理解为"彻底删除数据"** —— 现象：误删后尝试恢复，或惊讶于 `du` 与 `df` 不一致。根因：`rm` 只是删除**目录项**并把 `i_nlink` 减一；`i_nlink == 0` **且无进程打开**时才真正释放数据块。正确认知：① 有进程持有 fd 时数据仍可从 `/proc/<pid>/fd/` 拷回（真实救援手段）；② 排查 `df` 满但 `du` 小：`lsof +L1` 找"已删仍被占用"的文件；③ 删硬链接的一个名字不影响其他名字。

5. **以为符号链接的权限会生效** —— 现象：`chmod 400 link` 想限制访问。根因：符号链接自己的权限**恒为 `lrwxrwxrwx` 且不参与判定**，权限检查作用在**目标**上；`chmod link` 实际改的是目标文件（`chmod -h` 在多数系统不支持）。正确做法：要控制访问应改目标文件的权限，或把链接放进一个权限受控的目录（利用目录的 `x` 位控制穿越）。

6. **`sed -i` 原地修改把软链接变成普通文件** —— 现象：改完配置文件后，原本指向 `sites-available/` 的符号链接变成了独立文件，配置管理关系悄悄断裂。根因：`sed -i` 的实现是"写临时文件 + rename"，rename 会替换掉链接本身。正确做法：① 用 `sed -i.bak` 至少留备份；② 对软链接先 `readlink -f` 拿到真实路径再改；③ 用配置管理工具（Ansible/symlink + 模板）而非就地 `sed`。

7. **`grep -E '\d'` 匹配不到数字（却可能匹配到字母 d）** —— 现象：写 `grep -E '\d+'` 想抓数字，结果为空或抓到了含字母 d 的内容。根因：`\d` 是 **PCRE 专有**，ERE 里未定义；GNU grep 在 ERE 下可能把 `\d` 退化为字面量 `d`，BSD grep 行为又不同 —— **静默错误**最难查。正确做法：`grep -P '\d+'`（GNU 专用）或统一写 `[0-9]+`（POSIX 可移植，推荐）。

8. **`sed -n '2p'` 忘写 `-n`，输出全部行** —— 现象：只想看第 2 行，结果打印了整个文件（且第 2 行出现两次）。根因：sed 的循环**默认自动打印每行**，`p` 命令是额外再打印一次。正确做法：只要"选择性输出"就必须 `-n`；混用时的记忆法是「`-n` 与 `p` 配对出现」。

9. **`find . -name "*.log" | xargs rm` 删错文件** —— 现象：文件名含空格时被拆成多个参数，可能删除非目标文件；文件名含换行时更彻底错乱；文件名以 `-` 开头会被当成选项。根因：**POSIX 文件名可含除 `/` 与 NUL 外的任意字节**，空格/换行分隔天然有歧义。正确做法：`find . -name "*.log" -print0 | xargs -0 rm`，或 `find ... -delete`；遍历时 `for f in ./*; do ...; done` 并给 `$f` **加双引号**。另外**批量删除必须先用 `-print` 干跑确认**。

10. **`umask` 依赖继承值导致凭据泄露** —— 现象：生成的私钥/`token` 文件是 `-rw-r--r--`（全世界可读）。根因：`umask` 由环境继承，脚本在 cron/容器/CI 中的 umask 可能不同；默认 `022` 让新文件变成 `644`。正确做法：处理敏感数据的脚本开头显式 `umask 077`，并对凭据文件 `chmod 600`；审计用 `find . -name "*.pem" -o -name "*.key" | xargs -r ls -l`。SSH 会因 `UNPROTECTED PRIVATE KEY FILE` 直接拒绝加载私钥，这是该问题的显性告警。

11. **`444` 目录被认为"安全"** —— 现象：把含敏感文件名的目录设成 `444`，以为保护住了。根因：目录的 `r` 是"**可列出名字**"，`444` 明确给出 `r`，所以**文件名全部泄露**（`ls` 只需读目录数据块，不需要穿越权限）。正确做法：要隐藏名字应去掉 `r`（如 `111`，只允许按已知路径访问）；要真正保护内容需同时控制文件权限与中间路径的 `x`。

12. **`ln -sf` 在目标已是目录时把链接建到目录内部** —— 现象：部署脚本 `ln -sf releases/new current`，当 `current` 已是目录时，链接被创建为 `current/new`，切换未生效。根因：路径尾部的解析规则 —— 目标是已存在的目录时，`ln` 视为"在目录内创建"。正确做法：用 `ln -sfn`（`-n` = no-dereference，把目录当普通文件处理），或先 `rm -f current` 再建链接。

13. **对 `/proc`、`/sys` 写入后以为永久生效** —— 现象：`echo 1 > /proc/sys/net/...` 当时有效，重启后失效。根因：`/proc/sys` 是内核参数（sysctl）的运行时视图，**不持久化**。正确做法：持久化写 `/etc/sysctl.conf` 或 `/etc/sysctl.d/*.conf`，再用 `sysctl -p` 加载；排查时用 `sysctl -a` 读当前值。

14. **`cp -r` 备份把软链接解引用、`rsync` 默认同样解引用** —— 现象：备份体积暴涨（把链接指向的整份数据都复制了），或备份后链接关系丢失。根因：`cp -r` 会跟随符号链接复制目标内容；`rsync` 默认（`-a` 之外）也不保留链接。正确做法：`cp -a`（archive，保留链接/权限/时间）或 `rsync -a`；需要明确保留**硬链接**关系时加 `rsync -H`（不做这一步，去重备份会退化成全量复制）。
