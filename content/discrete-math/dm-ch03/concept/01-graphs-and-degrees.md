# 图与度数：顶点、边与握手定理

## 1. 背景/动机

图是离散数学里最"看得见"的结构——社交网络的好友关系、城市的道路网、服务的调用依赖、编译的先修图，全都是图。它把"谁和谁有关联"这件事抽象成两个集合：顶点集 V（实体）和边集 E（实体之间的关联）。图论研究的就是这些关联的形态：能不能连通、最短要走几步、有没有环、能不能一笔画完。

工程上最容易混淆的是"有向 / 无向"和"加权 / 无权"。把有向图当无向图用，会漏掉"关注 ≠ 互关""调用 ≠ 被调用"；把加权图当无权图，会算出"边数最少"而不是"代价最小"。这些坑在 pitfalls 里会专门讲。

## 2. 定义/要点

图是离散数学里"关系"的几何化：把 dm-ch02 的关系 `R ⊆ A×B` 画出来——顶点是集合元素，边是序对 `(a,b)∈R`，那么**有向图就是关系的图表示，无向图就是对称关系**。所以本章不是凭空新概念，而是把"关系"可视化、可计算。两种"版本"各有适用：有向图表达单向依赖（调用、关注、水流），无向图表达双向可达（道路、无向好友）。度数刻画"一个顶点有多忙"：出度是它发出多少边，入度是它接收多少边，无向图里直接就是与它相连的边数。握手定理是图论第一恒等式——它把"每个顶点的度数"和"边的总数"用一条不可能错的等式绑死，是所有度数题的出发点。

### 2.1 图的几种"版本"

- **无向图** `G=(V,E)`：边是无序对 `{u,v}`，`u-v` 与 `v-u` 是同一回事。
- **有向图** `G=(V,E)`：边是有序对 `(u,v)`，表示"u 指向 v"；有出度 `deg⁺(u)` 与入度 `deg⁻(u)`。
- **加权图**：边上带权重 `w(u,v)`（距离、费用、延迟）；无权图可视为所有边权为 1。
- **多重图 / 简单图**：简单图不含自环、不含重边；自环 `{u,u}` 在度数上记 2（无向）或出=入各 1（有向）。

### 2.2 握手定理（度数和）

无向图所有顶点的度数之和等于边数的两倍：

$$\sum_{v \in V} deg(v) = 2|E|$$

推论：**任何无向图，奇数度顶点的个数必为偶数**（度数和偶数，偶数度顶点贡献偶数，奇数度顶点必须成对出现）。有向图则分别满足 $\sum deg^+(v) = \sum deg^-(v) = |E|$。

```text
例：4 顶点，边 (0-1)(1-2)(2-3)(0-2)
deg(0)=2, deg(1)=2, deg(2)=3, deg(3)=1
度数和 = 2+2+3+1 = 8 = 2×4 = 2|E|   ✓
奇数度顶点 {2,3} 共 2 个（偶数个）   ✓
```

### 2.3 邻接矩阵 / 邻接表 / 边表

| 存储 | 空间 | 查边 | 遍历邻接点 | 适用 |
|---|---|---|---|---|
| 邻接矩阵 `A[n][n]` | $O(V^2)$ | $O(1)$ | $O(V)$ | 稠密图、要快速判边、 Floyd 传递闭包 |
| 邻接表 `vector<int> adj[n]` | $O(V+E)$ | $O(deg)$ | $O(deg)$ | 稀疏图、绝大多数工程场景 |
| 边表 `list of (u,v,w)` | $O(E)$ | 需扫描 | — | Kruskal 排序边、批量处理 |

邻接矩阵还有个隐藏好处：它的 k 次幂 `A^k[i][j]` 等于"i 到 j 长度为 k 的路径数"——这是矩阵与图论最漂亮的对偶之一。

### 2.4 同构与子图

- **子图** `H⊆G`：顶点集与边集都是 G 的子集。
- **生成子图**：保留全部顶点、只删边。
- **同构** `G₁≅G₂`：存在顶点的一一对应，使"是否有边"完全一致。同构只关心"连接结构"，不关心"画在哪、编号怎么排"。**图同构判定至今没有已知的高效（多项式）算法**，是理论计算机科学里的著名难题。

## 3. 可运行代码

下面两段代码把"邻接矩阵存储 + 度数统计"和"握手定理验证"落到可运行的 C 程序。重点不是语法，而是"图的两种基本操作（存、数）如何变成机器能算的东西"：邻接矩阵用二维数组，度数就是某行/列上 1 的个数；握手定理则是用一次求和验证数据自洽。所有示例输出都来自真实编译/运行，可对照本章 exercises 的度数题人工核对。

### 3.1 邻接矩阵存储与度数统计（C）

```c
/* ex-style：无向图，4 顶点，边 (0-1)(1-2)(2-3)(0-2)，统计度数 */
#include <stdio.h>
int main(void){
    int n=4;
    int adj[4][4]={0};
    int e[][2]={{0,1},{1,2},{2,3},{0,2}};
    int m=4;
    for(int k=0;k<m;k++){ adj[e[k][0]][e[k][1]]=1; adj[e[k][1]][e[k][0]]=1; }
    for(int i=0;i<n;i++){
        int d=0;
        for(int j=0;j<n;j++) d+=adj[i][j];
        printf("deg(%d)=%d\n", i, d);
    }
    return 0;
}
```

### 3.2 握手定理验证（Python）

```python
deg = [2, 2, 3, 1]          # 取自上方矩阵
n = len(deg)
s = sum(deg)
edges = s // 2
assert s == 2 * edges, "度数和必须是偶数"
assert sum(1 for d in deg if d % 2 == 1) % 2 == 0, "奇度顶点必为偶数个"
print(s, 2 * edges, edges)   # 8 8 4
```

## 三视角解析

### 🧑‍💻 程序员视角

邻接矩阵 vs 邻接表是图题第一道分水岭：城市路网、社交关系这种**稀疏图**用邻接表（省空间、遍历快）；而"两点是否直达""所有点对最短路（Floyd）"这种要快速查边或做矩阵运算的，用邻接矩阵。一个真实坑：用邻接矩阵存百万级顶点的稀疏图，空间直接炸成 `10¹²`，必须换邻接表。度数统计在代码里就是"数某行/列的 1"，握手定理则常用来**校验输入数据是否自洽**（度数和必须偶数）。

### 🎓 博士生视角

握手定理是更一般的**度序列可图化**问题的特例（Erdős–Gallai 定理判定一串数字能否成为某个简单图的度数）。邻接矩阵的 k 次幂 `A^k[i][j]=路径数` 把图论和线性代数焊在一起，谱图论（用特征值研究连通性、割、聚类）正是从这里长出来的。同构判定没有已知多项式算法，提示"结构等价"本身可能是本质困难的。

### 📚 考研者视角

握手定理、奇度顶点个数必为偶数、邻接矩阵/邻接表的取舍是高频小题，背熟直接套。常考变体：给一串度数问"能否构成简单图"——先看度数和是否偶数，再看最大度是否超过 `n-1`。这些点也常和 ch01 的逻辑、ch02 的关系串联成综合题。
