# lambda 表达式与捕获

lambda 是"内联的匿名函数对象"，常用于算法谓词与回调。语法：`[捕获](参数) -> 返回类型 { 函数体 }`（返回类型可省略，由 `return` 推导）。

它不是"轻量函数"，而是**编译器生成的一个类**：捕获列表变成数据成员，函数体变成 `operator()`。理解这句话，所有 lambda 的行为都能推出来。

## 一、捕获方式与它们的真实含义

- `[=]` 值捕获：外部变量被**拷贝**进闭包对象，成为成员。默认只读（`operator()` 是 const），加 `mutable` 才能改副本。
- `[&]` 引用捕获：闭包对象里存的是**引用**，修改会影响外部变量。
- `[x]` / `[&x]`：显式指定单个变量，是最推荐的写法——**捕获什么一眼可见**。
- `[=, &count]`：混合，其余值捕获，`count` 引用捕获（反向写法 `[&, count]` 也合法）。
- `[p = std::move(ptr)]`（C++14）：**初始化捕获**，支持移动语义，这是把 `unique_ptr` 移进 lambda 的唯一方式。

```text
lambda 展开后的等价类（[&total](int x){ total += x; }）

  struct __lambda_1 {
      int& total;                          // 引用捕获 → 引用成员
      void operator()(int x) const { total += x; }   // 默认 const
  };

  [=] 展开 → 成员是 int total;（副本）
  [x] 展开 → 成员是 int x;（同名副本）
```

## 二、闭包类型的四个硬事实

1. **每个 lambda 的类型唯一且无名**：两个写法完全相同的 lambda 也是不同类型，所以只能用 `auto` 或模板参数接，不能写类型名。
2. **`operator()` 默认是 `const`**：这就是"值捕获的变量不能改"的机制原因——不是语言额外规定，而是成员函数 const 性。`mutable` 去掉这个 const。
3. **无捕获 lambda 可隐式转成函数指针**：因为无状态闭包可以退化为普通函数。这正是 `qsort` 这类 C API 只能接收无捕获 lambda 的原因。
4. **`[=]` 只捕获实际用到的变量**：不是"捕获所有局部变量"，闭包大小取决于用到的捕获集合，因此 `[=]` 不会因为函数局部变量多而变大。

## 三、生命周期：唯一真正危险的地方

按引用捕获不改变任何生命周期，**它只是一个引用**。因此当 lambda 比被捕获变量活得长时就会悬垂：

```cpp
std::function<void()> make() {
    int local = 42;
    return [&local]() { std::cout << local; };   // 悬垂：local 已销毁
}
```

三种常见事故场景：

- **异步回调**：`[&]` 捕获局部变量，回调在另一个线程稍后执行 → 读到已销毁的栈。
- **存入容器的 lambda**：`vec.push_back([&x]{...})` 之后 `x` 离开作用域。
- **成员函数里的 `[=]` 隐式捕获 `this`**：对象被销毁后调用 lambda → 悬垂 `this`。C++20 起要求显式写 `[=, this]`，编译器会警告这种隐式捕获。

对策：跨作用域存活就**值捕获**（或 `[p = std::move(p)]` 移动捕获），只读小对象也可以直接拷贝；确实需要共享状态时用 `std::shared_ptr` 捕获。

## 四、lambda 与 `std::function`、模板的取舍

- **`auto` 接 lambda**：零开销，闭包类型直接内联，编译器可完全优化。
- **`std::function` 接 lambda**：类型擦除，可存异构可调用对象，代价是可能堆分配 + 一次间接调用。频繁调用的热路径上应避免。
- **模板参数接可调用对象**：零开销且泛型，是标准库算法与 `std::sort` 的做法；缺点是每次传不同 lambda 都会实例化一份代码（可能增大二进制）。

选择依据：需要存储/传递异构可调用对象 → `std::function`；就地使用 → `auto` 或模板。

## 五、泛型 lambda 与 `constexpr`

```cpp
auto add = [](auto a, auto b) { return a + b; };   // C++14 泛型 lambda
auto twice = [](auto x) constexpr { return x * 2; }; // C++17 起可 constexpr
```

泛型 lambda 的 `operator()` 是**模板**，因此每个实参类型组合都实例化一份。这带来一个坑：**同一个泛型 lambda 对不同类型可能返回不同类型**，用它做 `std::function` 参数时会因类型不一致而编译失败。

## 六、边界与陷阱

- **引用捕获不能逃逸**：返回、存容器、投递到线程池，都可能让 lambda 活过被捕获对象。
- **`[=]` 隐式捕获 `this`**：成员函数里写 `[=]` 实际捕获的是 `this` 指针（不是对象副本），对象销毁即悬垂。
- **`mutable` 只影响副本**：`[=]() mutable { ++x; }` 改的是闭包里的副本，外部 `x` 不变——这与"值捕获=拷贝"是一致的，但常被误读成"能改外部"。
- **循环里捕获循环变量**：`for (int i = 0; ...) fns.push_back([&i]{...});` 所有 lambda 共享同一个 `i`，全部看到最终值。值捕获 `[i]` 才是每个一份。
- **lambda 不是函数指针**：不能赋给 `int(*)(int)` 除非无捕获；也不能用 `sizeof` 推断"它有多大"（实现相关）。

## 七、可运行示例：三种捕获的实际效果

```cpp
#include <functional>
#include <iostream>
#include <vector>

int main() {
    int total = 0;
    std::vector<int> v{1, 2, 3};

    auto by_ref  = [&total](int x) { total += x; };
    auto by_val  = [total](int) mutable { return ++total; };   // 改的是副本

    for (int x : v) by_ref(x);
    std::cout << "after_ref=" << total << "\n";       // 6

    std::cout << "copy=" << by_val(0) << " " << by_val(0) << "\n";  // 7 8
    std::cout << "total_unchanged=" << total << "\n";               // 6

    int (*fp)(int) = [](int x) { return x * x; };     // 无捕获 → 函数指针
    std::cout << "fp=" << fp(5) << "\n";

    std::function<int(int)> erased = [base = total](int x) { return base + x; };
    std::cout << "erased=" << erased(10) << "\n";
}
```

关键看两处：`by_val` 连调两次得到 7、8（副本被累加，外部 `total` 不变），以及无捕获 lambda 能赋给函数指针——后者是"闭包无状态才能退化"的直接证据。`[base = total]` 演示初始化捕获，这个副本在 lambda 创建时求值一次。

## 三视角解析

### 🧑‍💻 程序员视角
- 捕获要克制：`[&]` 捕引用**绝不能逃逸**（异步/回调里会悬垂）；`[=]` 也会在成员函数里隐式捕获 `this`（C++20 起显式要求 `[=, this]`）。
- 需要移动捕获用 C++14 的初始化捕获：`[p = std::move(ptr)]`。
- 无捕获的 lambda 可隐式转成**函数指针**（可传给 C API）；带状态的不能。
- 默认写显式捕获列表（`[&count, i]`），别用 `[=]`/`[&]` 图省事——省下的是几秒，赔上的是排查悬垂引用的半天。

### 🎓 博士生视角
- lambda 会被编译器展开成一个**唯一的闭包类型**，捕获的变量成为其**数据成员**（按值捕获是成员拷贝，按引用捕获是引用成员）。`operator()` 默认是 `const` 的，因此要修改按值捕获的成员必须加 `mutable`。
- 「无捕获 lambda → 函数指针」的转换之所以成立，是因为此时闭包类型可以退化为普通函数指针（无状态）；这也是 `qsort` 这类 C API 只能接收无捕获 lambda 的原因。
- **按引用捕获的生命周期风险无法被类型系统检查**，这是 C++ 把生命周期责任交给程序员的又一个实例；Rust 的闭包捕获会做借用检查，代价是更复杂的类型。
- 从实现看，`[=]` 只捕获**实际用到的**变量（不是全部），因此闭包大小取决于用到的捕获集合。
- 闭包类型没有默认构造、没有赋值运算符（C++20 前），其拷贝/移动行为逐成员继承捕获的 cv 与引用性质：引用成员使闭包不可赋值——这就是"捕获了引用的 lambda 不能放进 `std::vector` 再整体赋值"的原因。

### 📚 考研者视角
- 与**函数对象（仿函数）**、闭包的概念对应：lambda 是「编译器生成的函数对象」的语法糖。
- 常考概念题：「lambda 与函数指针的区别」「按引用捕获为什么危险」。
- 常考辨析：值捕获（拷贝，独立）vs 引用捕获（共享，可悬垂）；`mutable` 的作用范围（只作用于副本）。
- 记忆锚点：**lambda 类型唯一**；**无捕获才能转函数指针**；**引用捕获不能逃逸**。
