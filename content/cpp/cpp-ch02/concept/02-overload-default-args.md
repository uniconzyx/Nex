# 函数重载与默认参数

## 一、重载解决的是什么问题

同名函数，只要**参数列表不同**（类型 / 个数 / 顺序）即可重载；返回类型不参与。表面上是"少记几个名字"，本质是**把同一个抽象操作的多种实现放在一个名字下**，让调用点表达意图而不是表达类型。

```cpp
int square(int x)       { return x * x; }
double square(double x) { return x * x; }   // 合法重载
```

`std::cout <<` 就是重载的极端案例：同一个 `<<` 对 `int`/`double`/`string`/自定义类型分别有实现，调用方完全不需要知道选的是哪个。

## 二、重载决议的四级阶梯

编译器把候选函数按**实参到形参的转换序列**排序，优先级从高到低：

1. **精确匹配**（含数组到指针、函数到函数指针的退化，以及仅加/去 `const`）
2. **类型提升**（`char`/`short` → `int`，`float` → `double`）
3. **标准转换**（`int` → `double`、`double` → `int`、指针 → `bool` 等）
4. **用户定义转换**（经由转换构造函数或 `operator T()`）

外加最次的**省略号 `...`**。只有当最优候选唯一时才通过，否则报"调用有歧义"。

这套阶梯解释了很多"为什么编译不过"：

```cpp
void f(long x);
void f(double x);
f(1);        // 有歧义：int→long 与 int→double 同为「标准转换」
```

而 `f(1.0f)` 会选 `f(double)`，因为 `float→double` 是**提升**，优先级高于 `float→long` 的转换。

```text
重载决议排序（实参 int 时，各候选的转换序列等级）

  候选 f(int)     精确匹配      ← 最高，直接胜出
  候选 f(long)    整型转换
  候选 f(double)  浮点转换
  候选 f(MyType)  用户定义转换  ← 最低
  候选 f(...)     省略号        ← 最次
```

### 更细的 tie-breaker

当两个候选同为某一级时，还有若干细化规则：非模板优先于模板、更特化的模板优先于更通用的、`T&` 绑定左值优先于 `const T&`、派生类到基类的转换优先于到更远基类……这些规则合起来构成重载决议的完整定义。工程上的结论只有一条：**不要设计需要靠 tie-breaker 才能区分的重载**，读代码的人几乎必然读错。

## 三、默认参数：调用点的静态填充

默认参数**只能从右往左连续给定**，且只能在声明或定义中提供一次。

```cpp
void greet(const std::string& name, const std::string& suffix = "!");
// 调用 greet("Cat") 等价于 greet("Cat", "!")
```

两个机制性事实：

- **默认实参不进入函数签名**，因此不参与重载决议，也不能靠它区分重载。`f(int)` 与 `f(int, int = 0)` 并存时，`f(1)` 会报歧义。
- **默认值在调用点填充**，是编译期的文本替换。这意味着默认实参的表达式在**调用方**求值——如果它引用了只在定义处可见的东西就会编译失败，也意味着每次调用都会重新求值（不同于 Python 的"默认值只求值一次"）。

### 虚函数 + 默认参数 = 陷阱

这是本章最值得记住的一条：

```cpp
struct Base {
    virtual void log(int level = 1) { /* ... */ }
};
struct Derived : Base {
    void log(int level = 2) override { /* ... */ }
};

Derived d;
Base& b = d;
b.log();     // 调用 Derived::log，但传入 level = 1（按 Base 的静态声明填充）
d.log();     // 调用 Derived::log，传入 level = 2
```

**函数体是动态绑定的，默认参数是静态绑定的**——两者来自不同机制，混用时就会出现"调的是子类实现，参数却是父类的默认值"。工程结论：**虚函数不要用默认参数**。

## 四、`= delete` 与 `= default`：对重载集合做精确控制

`= delete` 把一个函数声明"删除"，它仍参与重载决议但被选中时编译报错。这是禁止隐式转换的标准手段：

```cpp
void process(int x);
void process(double) = delete;   // 禁止 process(3.14) 静默截断
```

`process(3.14)` 会优先选中被删除的那个，于是**编译期报错**，而不是悄悄变成 `process(3)`。这比运行时断言好得多。

`= default` 用于显式要求编译器生成默认实现（拷贝构造、赋值、析构等），常与"声明了其中一个就补齐其他"的规则配合使用。两者都是"在重载集合上做外科手术"的工具。

## 五、边界与陷阱

- **默认参数重复提供**：声明写了 `= "!"`，定义又写一遍，报"默认参数重定义"。只在一处给，且应放在头文件的声明里。
- **默认参数从中间断档**：`void f(int a = 1, int b);` 非法，必须连续靠右。
- **重载仅靠返回类型区分**：`int f();` 与 `double f();` 非法——调用点无法从返回值反推该选谁。
- **`nullptr` 与 `0` 的重载歧义**：同时存在 `f(int)` 与 `f(char*)` 时，`f(NULL)` 会选 `f(int)`（NULL 是整数常量 0）。用 `nullptr` 消除。
- **重载与 `using` 声明冲突**：派生类定义同名函数会**隐藏**基类的所有同名重载，要用 `using Base::f;` 把它们拉回来。

## 六、可运行示例：验证动态绑定与静态默认参数

```cpp
#include <iostream>

struct Base {
    virtual ~Base() = default;
    virtual void log(int level = 1) const { std::cout << "Base/" << level << "\n"; }
};

struct Derived : Base {
    void log(int level = 2) const override { std::cout << "Derived/" << level << "\n"; }
};

int main() {
    Derived d;
    Base& b = d;
    d.log();     // Derived/2 —— 静态类型 Derived，用 Derived 的默认值
    b.log();     // Derived/1 —— 动态绑定到 Derived::log，默认值来自 Base
    b.Base::log();  // Base/1 —— 显式限定绕过多态
}
```

这段程序把"函数体动态、默认参数静态"这条规则钉死了：同一个对象、同一个函数体，默认值却不同。

## 三视角解析

### 🧑‍💻 程序员视角
- 重载挑选顺序：**精确匹配 → 提升 → 标准转换 → 用户定义转换**（＋省略号），越靠前越优先。
- **虚函数与默认参数混用是陷阱**：默认值是**静态绑定**的，按指针/引用的静态类型决定，而函数体是动态绑定的——两者可能「对不上」。
- 别让重载之间产生**歧义**（如 `f(long)` 与 `f(double)` 同时存在时传 `int`），报错信息会很难读。
- 需要禁止某个隐式转换的重载，用 `= delete` 而不是靠文档约定。

### 🎓 博士生视角
- `default` 实参**不出现在函数签名里**，因此不参与重载决议，也不能被重载；它是在**调用点静态填充**的（这就是「虚函数 + 默认参数」坑的根源）。
- 重载决议可形式化为「可行函数集合 → 按转换序列排序」：**标准转换序列**有等级（精确匹配 / 提升 / 转换），用户定义转换统一视为最差等级。若最优者不唯一则报歧义。
- 「更好」的比较还有若干细化规则（左值/右值绑定偏好、`const` 限定偏好、非模板优先于模板、更特化的模板优先）——这些共同构成 C++ 重载决议的完整定义。
- `= delete` 可以主动「删除」某个重载（常用于禁止特定转换的重载），`= default` 显式要求生成特殊成员函数，两者都是「在重载集合上做精确控制」的手段。
- 名字修饰把形参类型编码进符号，因此重载在链接层就是不同符号；这也意味着**返回值类型不同不构成重载**——它不是符号的一部分，链接器无法区分。

### 📚 考研者视角
- 与编译原理的**重载解析（overload resolution）**、类型转换对应。
- 常考概念题：「默认参数为什么不能与重载混用」「虚函数的默认参数是静态还是动态绑定」。
- 常考辨析：重载（overload，同作用域同名不同参）/ 重写（override，虚函数派生类覆写）/ 隐藏（hide，派生类同名函数遮蔽基类）。
- 记忆锚点：**默认参数在调用点静态填充、不参与重载决议**；**虚函数 + 默认参数 = 陷阱**；**返回类型不参与重载**。
