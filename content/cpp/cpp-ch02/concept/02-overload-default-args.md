# 函数重载与默认参数

## 函数重载

同名函数，只要**参数列表不同**（类型 / 个数 / 顺序）即可重载；返回类型不参与。

```cpp
int square(int x)    { return x * x; }
double square(double x) { return x * x; }   // 合法重载
```

重载决议优先级：精确匹配 > 类型提升 > 标准转换 > 用户定义转换。

## 默认参数

默认参数**只能从右往左连续给定**，且只能在声明或定义中提供一次。

```cpp
void greet(const std::string& name, const std::string& suffix = "!");
// 调用 greet("Cat") 等价于 greet("Cat", "!")
```

> 陷阱：声明给了默认参数，定义处再写一遍会"重定义默认参数"报错——**只在一处给**。

---

## 三视角解析

### 🧑‍💻 程序员视角
- 重载挑选顺序：**精确匹配 → 提升 → 标准转换 → 用户定义转换**（＋省略号），越靠前越优先。
- **虚函数与默认参数混用是陷阱**：默认值是**静态绑定**的，按指针/引用的静态类型决定，而函数体是动态绑定的——两者可能「对不上」。
- 别让重载之间产生**歧义**（如 `f(long)` 与 `f(double)` 同时存在时传 `int`），报错信息会很难读。

### 🎓 博士生视角
- `default` 实参**不出现在函数签名里**，因此不参与重载决议，也不能被重载；它是在**调用点静态填充**的（这就是「虚函数 + 默认参数」坑的根源）。
- 重载决议可形式化为「可行函数集合 → 按转换序列排序」：**标准转换序列**有等级（精确匹配 / 提升 / 转换），用户定义转换统一视为最差等级。若最优者不唯一则报歧义。
- 「更好」的比较还有若干细化规则（左值/右值绑定偏好、`const` 限定偏好、非模板优先于模板、更特化的模板优先）——这些共同构成 C++ 重载决议的完整定义。
- `= delete` 可以主动「删除」某个重载（常用于禁止特定转换的重载），`= default` 显式要求生成特殊成员函数，两者都是「在重载集合上做精确控制」的手段。

### 📚 考研者视角
- 与编译原理的**重载解析（overload resolution）**、类型转换对应。
- 常考概念题：「默认参数为什么不能与重载混用」「虚函数的默认参数是静态还是动态绑定」。
- 记忆锚点：**默认参数在调用点静态填充、不参与重载决议**；**虚函数 + 默认参数 = 陷阱**。
