# 指针基础

指针是"保存内存地址的变量"。通过 `&` 取地址，通过 `*` 解引用访问所指对象。

指针本身并不复杂，复杂的是它承载的**所有权语义**：这个指针是否拥有它指向的对象、谁负责释放、能否为空、能活多久。现代 C++ 的做法是把这些语义交给类型——裸指针只表达"观察"，所有权交给智能指针。

## 一、指针的四个要素

一个指针值包含的信息只有"地址"，但使用它时需要同时知道四件事：

1. **地址**：指向哪里。
2. **类型**：解引用时如何解释这段内存、算术时步长多少。
3. **有效性**：指向的对象是否还活着（语言不检查）。
4. **所有权**：谁负责释放（语言不检查，靠约定）。

后两条**完全靠程序员**。这是 C++ 指针所有坑的根源：编译器只知道前两条。

```text
指针的语义分层

  T* p
   ├─ 地址         可比较、可打印（%p）
   ├─ 类型         *p 的类型是 T；p+1 前进 sizeof(T)
   ├─ 有效性       ✗ 不检查（悬垂、野指针都是 UB）
   └─ 所有权       ✗ 不表达（由命名/接口约定承载）
```

## 二、空指针与 `nullptr`

```cpp
int* p = nullptr;      // 推荐：类型是 std::nullptr_t
int* q = NULL;         // 可行但不推荐：NULL 通常是 0
int* r = 0;            // 可行但不推荐
```

`nullptr` 的类型是 `std::nullptr_t`，能隐式转为任意指针类型，但**不是整数**。这解决了两个老问题：

- **重载歧义**：同时有 `f(int)` 与 `f(char*)` 时，`f(NULL)` 会选 `f(int)`（因为 `NULL` 是 0），而 `f(nullptr)` 明确选指针版。
- **模板推导**：`template<typename T> void g(T)` 传 `NULL` 推出 `int`，传 `nullptr` 推出 `std::nullptr_t`。

**解引用空指针是 UB**，标准不保证崩溃。所以在"优化掉了"的构建里，`if (p) *p;` 之后 `p` 可能被假设非空，导致检查被删除之外的诡异行为。要主动断言就用 `assert(p)`。

## 三、指针算术：按类型缩放

`p + 1` 前进的不是 1 字节，而是 `sizeof(*p)` 字节。这是数组下标能工作的基础：`a[i] == *(a + i)`。

```cpp
int a[3] = {10, 20, 30};
int* p = a;
// p+1 的地址比 p 大 4（sizeof(int)），不是 1
```

三条约束值得记住：

- **只能在同一数组（或末尾后一位）内做算术**，跨对象相减是 UB。
- **两个指针相减**得到元素个数（`ptrdiff_t`），前提是同一数组。
- **越界指针即使不解引用也是 UB**：`p = a + 5;` 已经是未定义行为，不只是"读的时候才出错"。

## 四、`const` 与指针的四种组合

### 读法：从右往左，`*` 是分界线

读法是从右往左：`const` 修饰它左边最近的东西，`*` 分隔"指针本身"与"所指对象"。

```cpp
int x = 1;
const int* p1 = &x;         // 指向 const int：*p1 不可改，p1 可改指向
int* const p2 = &x;         // const 指针：p2 不可改指向，*p2 可改
const int* const p3 = &x;   // 都不可改
int const* p4 = &x;         // 与 p1 等价（const int 与 int const 同义）
```

工程习惯：**函数参数用 `const T*` 表达"只读、不拥有、可空"**，这是最常用的裸指针形态。

## 五、函数指针与回调

```cpp
int add(int a, int b) { return a + b; }
int (*fp)(int, int) = &add;      // & 可省略
int r = fp(1, 2);                // 解引用也可省略
```

函数指针的语法难读，现代做法是 `using Callback = int(*)(int,int);` 或直接用 `std::function`/模板。函数指针的价值在于**零开销**（无类型擦除），C API 回调只能用它。

## 六、边界与陷阱

- **未初始化指针解引用**：`int* p; *p = 1;` 写随机地址，UB。
- **`delete` 后继续用**（use-after-free）：`delete p; *p;` 是 UB，且常"看起来正常"。释放后置 `nullptr` 只是防重复 delete，不防其他副本。
- **返回局部变量地址**：栈帧销毁后悬垂。
- **指针算术越界**：即使不解引用也 UB，编译器可据此优化出意外行为。
- **`void*` 解引用**：必须先转回具体类型，`void*` 不能直接 `*`。
- **`NULL` 传给重载**：见上，用 `nullptr`。

## 七、可运行示例：地址、步长与 const 位置

```cpp
#include <cstddef>
#include <iostream>

int main() {
    int a[3] = {10, 20, 30};
    int* p = a;
    int* q = a + 2;

    std::cout << "*p=" << *p << " *(p+1)=" << *(p + 1) << " *(p+2)=" << *(p + 2) << "\n";
    std::cout << "diff=" << (q - p) << "\n";                       // 2 个元素
    std::cout << "byte_diff=" << (reinterpret_cast<char*>(q) - reinterpret_cast<char*>(p)) << "\n";
    std::cout << "sizeof(int*)=" << sizeof(p) << " sizeof(int)=" << sizeof(int) << "\n";

    int x = 1;
    const int* pc = &x;        // 所指对象只读
    int* const cp = &x;        // 指针本身只读
    x = 2;
    std::cout << "via_pc=" << *pc << " via_cp=" << *cp << "\n";
    // *pc = 3;   // 编译错误
    // cp = &a[0];// 编译错误
}
```

`byte_diff=8` 而 `diff=2` 是关键对照：指针相减按**元素**计，转成 `char*` 后才是字节差。这直接对应 408 的地址计算题。

## 三视角解析

### 🧑‍💻 程序员视角
- 空指针一律用 **`nullptr`**（类型安全），不要用 `NULL` 或 `0`——后者在有 `int` 与 `T*` 两个重载时会歧义或选错。
- 指针算术按**所指类型大小**缩放；越界指针即使不解引用也是 UB。
- `delete`/`free` 之后把指针置 `nullptr`，能防住大量重复释放与 use-after-free。
- 裸指针只表达"观察"，所有权用 `unique_ptr`/`shared_ptr` 表达；接口签名里这两者不该混。

### 🎓 博士生视角
- `nullptr` 的类型是 `std::nullptr_t`，可隐式转为任意指针类型但**不是整数**，因此消除了 `0`/`NULL` 带来的重载歧义——这是「用类型表达意图」的又一例证。
- 指针是实现**间接访问**与**运行时多态**的基础设施：函数指针、vtable、动态内存都建立在它之上。
- 指针与引用在多数 ABI 上实现相同，但语言语义不同（可空 vs 不可空、可重绑定 vs 不可）。**可空性是否进入类型系统**，是 C++ 与「可选类型（`optional`/`Option`）」路线的重要分野。
- 与计组交叉：指针的位宽决定可寻址空间；压缩指针、分段寻址等技巧都建立在「低位可利用对齐」这一事实上。
- 严格别名规则（strict aliasing）限制了"用不相关类型的指针访问同一内存"，违反即 UB；`reinterpret_cast` 后的解引用往往踩这条规则，`std::memcpy` 或 `std::bit_cast` 才是合法途径。

### 📚 考研者视角
- **408 高频**：指针的定义与运算、指针与数组、多级指针、函数指针、`const` 与指针的组合。
- 常考计算：指针加减后的地址、`&a` 与 `a` 的类型差异（`+1` 的跳距不同）、二维数组的行列地址换算。
- 常考辨析：指针与引用的区别；`const int*` 与 `int* const` 的读法。
- 记忆锚点：**用 `nullptr`**；**指针算术按元素大小缩放**；**越界指针即 UB（即使不解引用）**。
