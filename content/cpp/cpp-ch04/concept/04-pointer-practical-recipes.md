# 凯喵实战手记：指针与内存——C++ 一半的 Bug 都长在这儿

> 指针是 C++ 的灵魂，也是崩溃、泄漏、段错误的老家。凯喵在内存布局上翻过的车，足够写一本错题集。这 12 个现场，每一个都对应一个你迟早会遇到的真实崩溃。

### 1. 空指针解引用：最朴素的段错误

凯喵第一次看到程序崩在 `cout << *p`：

```cpp
int* p = nullptr;
// ... 某些分支没赋值 ...
cout << *p;   // SIGSEGV
```

解引用前永远先判 `if (p)`。更稳的是从设计上避免「可能为空」的裸指针——用 `std::optional<T>` 或引用（引用必须绑定有效对象）。

### 2. 悬垂指针：对象早死了，指针还活着

凯喵返回局部变量的地址，调用方拿到野指针：

```cpp
int* danger() {
    int x = 42;
    return &x;   // x 在函数返回时已销毁，返回的是悬垂指针
}
```

栈对象生命周期随作用域结束。返回指针只能指向「调用方生命周期更长」或「堆上 new 出来」的对象，且要明确所有权。

### 3. 数组退化与 `sizeof` 陷阱

凯喵把数组当参数传，算长度算错：

```cpp
void f(int a[10]) {
    // sizeof(a) 是指针大小，不是 10*sizeof(int)！
}
int b[10];
f(b);
```

数组传给函数会**退化成指针**，`sizeof` 拿不到元素个数。长度要么显式传，要么用 `std::array`/`std::span`（带 size 信息）。

### 4. 指针算术越界：一步踏出数组

凯喵用 `p + i` 遍历时 i 算错，踩到邻居内存：

```cpp
int a[5] = {};
int* p = a;
for (int i = 0; i <= 5; ++i)  // i=5 越界
    p[i] = i;
```

`p[i]` 等价于 `*(p+i)`。越界读是未定义行为，可能读到脏数据；越界写可能悄无声息 corrupt 别的变量。用 `std::vector` + 范围 for 基本能杜绝。

### 5. `new`/`delete` 必须配平，且配对

凯喵混用 `new[]` 和 `delete`，内存布局错乱：

```cpp
int* a = new int[10];
delete a;        // 错！应该用 delete[] a;
```

`new[]` 配 `delete[]`，`new` 配 `delete`，类型也要一致。现代 C++ 直接用 `std::vector`/`std::unique_ptr`，让 RAII 替你管生命周期。

### 6. 内存布局：栈、堆、全局、代码段各住哪

凯喵调一个「偶发错乱」的 bug，最后发现是搞错了存储期：

```cpp
// .data：已初始化全局变量；.bss：未初始化全局；栈：局部；堆：new
int g_init = 10;     // .data
int g_uninit;        // .bss
void f() { int x; }  // 栈，函数返回即失效
```

理解「栈向下生长、堆向上、全局在程序生命周期存活」能帮你判断「这个变量活多久、会不会悬垂」。

### 7. 浅拷贝与深拷贝：指针成员被「共享」

凯喵的 struct 默认拷贝，两个对象指向同一块堆：

```cpp
struct Buf { int* p = new int[10]; };
Buf a; Buf b = a;   // 默认拷贝只复制指针值
// 析构时 double free！
```

含裸指针成员的类必须定义（或 `=delete`）拷贝/移动/析构（Rule of Three/Five）。最省事：把裸指针换成 `std::unique_ptr`，拷贝自动被禁用，移动语义接管所有权。

### 8. 智能指针才是现代写法

凯喵把手动 `new/delete` 全换成智能指针后，泄漏几乎消失：

```cpp
auto p = std::make_unique<int>(42);  // 离开作用域自动释放
std::shared_ptr<int> s = std::make_shared<int>(7);
```

`unique_ptr` 表达独占所有权，`shared_ptr` 表达共享（带引用计数），`weak_ptr` 打破循环引用。别再用裸 `new` 管理生命周期。

### 9. 跨编译单元的全局初始化顺序

凯喵两个 `.cpp` 的全局对象互相依赖，结果读到未初始化值：

```cpp
// a.cpp
extern int y; int x = y + 1;
// b.cpp
extern int x; int y = x + 1;   // 谁先构造？未定义
```

不同翻译单元间的全局对象构造顺序**未定义**。修法：用「函数内 `static` 局部变量」做延迟初始化（Meyers Singleton 思路），把顺序控制权收回到调用时。

### 10. `memcmp` 比较结构体不可靠

凯喵用 `memcmp` 判两个结构体相等，偶尔错：

```cpp
struct S { int a; char b; /* 填充字节未指定 */ };
// memcmp 会比较填充字节，内容不确定 → 相同逻辑值可能比较不等
```

结构体有**对齐填充字节**，内容未指定。`memcmp` 逐字节比会受填充干扰。逐成员比较，或定义 `operator<=>`（`=default`）让编译器生成正确比较。

### 11. `delete` 后置空防不住所有副本

凯喵以为 `p = nullptr` 就安全了：

```cpp
int* p = new int(1);
int* q = p;        // 另一个副本
delete p; p = nullptr;
// q 仍然是悬垂指针，use-after-free 仍在
```

置空只影响那一个变量，其他指向同一对象的指针副本依然是野指针。根治靠所有权设计（一个对象一个主人）和 ASan 排查。

### 12. 强转去掉 `const` 写只读段是 UB

凯喵改字符串字面量，直接段错误：

```cpp
const char* s = "abc";
*(char*)s = 'x';   // UB：字面量在 .rodata 只读段，通常立即段错误
```

字符串字面量存于只读段，强转掉 `const` 去写是未定义行为。需要改的字符串用 `char[]` 数组或 `std::string`。

> 凯喵总结：指针的坑九成在「悬垂」「越界」「配平」「拷贝共享」「强转写只读段」。记住 RAII 接管生命周期、智能指针替代裸 new、返回指针先想清楚所有权。把这 12 个现场刻进手感，段错误少一大半。

> 现场之外：现代 C++ 的黄金法则是「尽量不碰裸指针」。`unique_ptr` 默认首选，`vector` 替代原始数组，只有和 C API 交互或做底层数据结构时才允许裸指针出现，且边界清晰、所有权明确。

> 一句话收尾：指针给你极致控制，也把「不崩溃」的责任全交还给你——每一根指针都得有人负责它的生死。

### 凯喵复盘：指针问题的根，都在「所有权」

这 12 个坑几乎都能归到一个词：**所有权**。悬垂指针是「对象死了指针还活着」；浅拷贝双重释放是「一个对象有两个没约定的主人」；`delete` 后置空防不住副本，是因为「所有权没真正移交」；跨编译单元初始化顺序、强转写只读段，则是把「生命周期」和「存储期」搞混。现代 C++ 的答案不是更小心地用裸指针，而是**用类型系统把所有权写进代码**：`unique_ptr` 表达独占、`shared_ptr` 表达共享、`vector` 替代原始数组。当你不再靠「记得释放」而靠「编译器强制」，指针的一半 Bug 就自动消失了。落到写代码上，记住一句话：**能用智能指针就别 new，能 vector 就别裸数组，能引用就别裸指针**。把生命周期交给 RAII 和类型系统，你只需要在和 C API 交互的边界上保持清醒，其余时间让编译器替你盯着每一根指针的生死。面试和实战里，能把「所有权」讲清楚的人，指针题基本不会翻车；反之，只会背 `new/delete` 配平却说不清谁拥有哪块内存的人，迟早在某个悬垂或双重释放上栽跟头——理解永远比记忆重要。当你能把所有权说清楚，指针就褪去神秘感，剩下的只是语法细节与边界检查而已。
