# 04 · 变参模板/折叠表达式 与 完美转发

## 一、变参模板与折叠表达式

变参模板接受任意数量/类型的模板参数 `template<typename... Ts>`；C++17 **折叠表达式** `(pack op ...)` 把二元运算符规约到整个参数包，省去递归展开。

```cpp
template <typename... Ts>
auto sum(Ts... ts) { return (ts + ... + 0); }   // 左折叠，初值 0
```

## 二、完美转发

`std::forward<T>(x)` 在「引用折叠」配合下，把 `T&&` 参数原始的「左值/右值」值类别还原后转发给下游，实现「转发不丢类别」。

```cpp
template <typename T>
void wrapper(T&& x) { callee(std::forward<T>(x)); }  // 不写 forward 会永远当左值
```

### 🧑‍💻 程序员视角
- 折叠表达式让「求和/逻辑与/逗号序列」一行搞定，取代了 C++11/14 繁琐的递归展开（`sum(first, rest...)` 递归到空包），可读性与编译速度都更好。
- 完美转发是写泛型工厂/`emplace`/`make_shared` 的基石：`vector::emplace_back` 正是靠它把参数原样转发给元素构造器，避免多余拷贝。
- 真实坑：忘记 `std::forward`，或把 `forward` 用错变量（必须转发原 `T&&` 形参 `x`，而不是中间产物），都会导致右值退化成左值、多一次拷贝。

### 🎓 博士生视角
- 折叠表达式的语义可由两种初值方向界定：左折叠 `(pack op ...)` 与右折叠 `(... op pack)`，以及带初值的 `(pack op ... init)`；它本质是参数包上的**二元运算归约**，编译期展开为固定代码。
- 引用折叠规则：`T& &`→`&`、`T& &&`→`&`、`T&& &`→`&`、`T&& &&`→`&&`。`T&&` 在模板里是**通用引用/转发引用**，能绑左值也能绑右值；`forward<T>` 据此还原类别。
- 完美转发不成立的情形：`T` 被推导为值（非引用）时转发会拷贝；以及当形参不是 `T&&` 时（如 `const T&`）无法转发右值性。

### 📚 考研者视角
- 面试标准问法：「什么是完美转发？为什么需要 `std::forward`？」「引用折叠的四条规则？」「折叠表达式怎么写？」
- 易错口径：`std::move` 是无条件转右值（不「移动」任何东西），`std::forward` 是**有条件**地还原类别；二者用途不同，不要混用。
- 变参模板考点：参数包展开位置（函数参数、`sizeof...`、折叠）；`sizeof...(ts)` 求包大小。

## 三、实现变参的「类型安全打印」

用 `if constexpr` + 折叠可写通用打印，避免 SFINAE/递归：

```cpp
template <typename... Ts>
void print_all(Ts&&... ts) {
    ((std::cout << std::forward<Ts>(ts) << ' '), ...);
}
```

### 🧑‍💻 程序员视角
- `(expr, ...)` 逗号折叠逐次执行，常用于「对每个参数做同一件事」；比手写递归基线更短、更易维护。
- 注意 `std::cout << ... << ' '` 这里用了字符字面量 `' '` 而非字符串——在需要字符串分隔时注意避免裸字符串字面量带来的移植/编码问题。

### 🎓 博士生视角
- 逗号折叠 `(E, ...)` 利用逗号运算符的序列求值语义，把「侧效序列」规约到包上；它与 `if constexpr` 组合可在同一次展开中按类型分流。
- 完美转发在折叠里必须对每个元素单独 `forward<Ts>(ts)`（`Ts` 各元素独立推导），不能整体 `forward`，否则值类别信息丢失。

### 📚 考研者视角
- 标准问法：「用折叠表达式实现可变参数求和/打印」「`std::forward` 在折叠里怎么用才正确？」
- 易错口径：`(ts + ...)` 无初值要求包非空；空包编译失败，需加初值 `(ts + ... + 0)` 兜底。
