# 01 · 继承的本质：子对象模型、访问边界与对象切片

## 一、理论根基：继承不是「代码复用」那么简单

从语言设计视角，**继承在 C++ 里首先是一种「子类型（subtyping）+ 子对象组合」机制**，而非 Java/C# 那种单纯的类型层级。它同时承担两种语义：

- **接口复用（is-a）**：公有继承表达「派生类对象可以当作基类对象使用」（Liskov 替换原则）。这是多态的前提。
- **内存组合**：派生类对象**在物理上包含**一个完整的基类子对象（base subobject）。这一点是 C++ 与「仅类型层级」语言的根本区别，也是后面所有机制（vptr 布局、this 调整）的物理基础。

三种继承方式的本质差异在于**派生类外对基类成员的可见性改写**：

| 方式 | 基类 public | 基类 protected | 基类 private | 典型用途 |
|---|---|---|---|---|
| `public` | public | protected | 不可见 | 真正的 is-a、多态 |
| `protected` | protected | protected | 不可见 | 给进一步派生的「实现继承」 |
| `private` | private | private | 不可见 | 仅复用实现，**不暴露接口**（已非 is-a） |

> **程序员视角**：`private` 继承意味着「我借用基类的实现，但不想让用户把我当成基类」——此时往往优先考虑**组合（member）**而非继承。继承会暴露基类 protected 接口、引入生命周期耦合；能用组合就用组合。

## 二、实现机制：派生类对象的真实内存布局

编译器把派生类对象布局为「基类子对象在前，派生成员在后」（标准保证基类子对象地址可经适当转换得到，常见实现里基类子对象就在对象起始）。

```
struct Base { int a; char b; };          // sizeof(Base)=8 (int 4 + char 1 + pad 3)
struct Der : Base { long c; double d; }; // 布局如下：

  Der 对象（从高地址到低地址简化表示）:
  +-------------------+  <- Der 起始 == Base 子对象起始
  | int  a   (4)      |      Base 子对象
  | char b   (1)      |
  | pad     (3)       |
  +-------------------+  <- 偏移 8
  | long c   (8)      |      Der 自己的成员
  | double d (8)      |
  +-------------------+

  sizeof(Der) = 24  （Base 8 + long 8 + double 8，已按 8 对齐）
```

关键推论：
1. `Der` 对象的起始地址**恰好等于**其 `Base` 子对象的地址，因此 `static_cast<Base*>(der_ptr)` 通常**零成本**（偏移为 0）。
2. `sizeof(Der)` 不是简单相加——基类子对象本身带 padding，派生成员再对齐。
3. 把 `Der*` 赋给 `Base*` 安全；反过来 `Base*` 转回 `Der*` 叫「向下转型」，编译器**不校验**安全性（见 03-RTTI）。

## 三、对象切片（Slicing）：值语义的代价

当派生对象被**按值**赋给/传给基类对象时，拷贝的是「基类子对象」那一块，**派生部分被丢弃**：

```cpp
Der d; d.a = 1; d.c = 99;
Base b = d;        // 只拷贝 Base 子对象 → b.c 不存在，d.c 被切片
```

```
   d (Der): [Base{a=1,b}] [c=99, d]      → 赋值时只取左侧 [Base{a=1,b}]
   b (Base): [a=1, b]
```

后果：即便 `Base::f()` 是虚函数，经切片的 `b` 是一个**纯基类对象**，虚调用只能落到 `Base`——多态彻底失效。这是 C++ 「值语义默认」与「运行期多态需要引用/指针」之间的根本张力。

> **工程结论**：多态对象永远通过 `T&` / `T*` / `unique_ptr<T>` 传递；绝不按值传递基类。

## 四、构造/析构顺序（与 ch05 衔接）

构造**由内向外**（先基类子对象，再派生成员），析构**由外向内**（先派生，再基类）。这保证：在基类构造函数执行时，派生部分尚未存在；在派生析构执行时，基类子对象仍然有效。

## 五、边界与陷阱

- **基类成员遮蔽**：派生类同名成员会隐藏基类所有该名重载（见 pitfalls 第 6 条）。
- **private 继承下 `Base&` 不可用**：因为 is-a 关系不成立，不能把 `Der&` 隐式转成 `Base&`（需显式 `using` 或接口转发）。
- **空基类优化（EBO）**：空基类不占额外空间（`sizeof(Der)` 可能因 EBO 比预期小），这是标准允许的布局优化。

## 六、可运行示例：验证构造顺序与内存布局

```cpp
#include <iostream>
struct Base {
    Base()  { std::cout << "Base-ctor "; }
    ~Base() { std::cout << "Base-dtor "; }
};
struct Der : Base {
    Der()  { std::cout << "Der-ctor "; }
    ~Der() { std::cout << "Der-dtor "; }
};
int main() {
    std::cout << "创建: "; Der d; std::cout << "\n销毁: ";
}
```

**输出**：
```
创建: Base-ctor Der-ctor
销毁: Der-dtor Base-dtor
```

> 观察点：构造先 Base 后 Der，析构逆序——这是「基类子对象必须先生效、最后失效」的保证。

## 三视角解析

### 🧑‍💻 程序员视角
- 公有继承表达 **is-a**；只想复用实现就用**组合**（继承会绑定父类实现细节，父类一改子类就可能坏）。
- **对象切片**是最隐蔽的坑之一：把派生对象按值传给「基类参数」或赋给基类对象，派生部分被静默切掉，**不报错**。要传多态对象就用引用或指针。
- 访问级别与继承方式两两组合共 9 种；实践中 99% 用 `public` 继承。

### 🎓 博士生视角
- 派生类对象布局是「**基类子对象 + 派生类新增成员**」；在多重继承下，各基类子对象依次排列，因此**某个基类子对象的地址与派生类对象地址可能不同**——这就是「this 指针调整」的根源（`static_cast` 到基类会做地址修正）。
- **对象切片**（slicing）的本质是「按值拷贝只复制了基类子对象那部分」，因此虚表指针也变成基类的，多态彻底失效。它是「值语义 + 继承」交互的必然结果，无法靠编译器报错拦截。
- 私有/保护继承改变的是**访问控制与类型关系**（私有继承下派生类不是基类的子类型），因此「is-a」不再成立——这类继承只是「实现复用」的一种表达，现代 C++ 更推荐用组合或成员。
- 从类型论看，公有继承建立子类型关系，必须满足**里氏替换原则**：子类对象应能在任何父类出现处正确工作。

### 📚 考研者视角
- 与「继承与组合的取舍」「里氏替换原则」等软件工程概念对应（408 本身不考 C++ 继承）。
- 常考概念题：「对象切片是什么」「基类指针与派生类指针的转换」。
- 记忆锚点：**对象切片静默发生，只能用引用/指针规避**；**多重继承下基类子对象地址可能偏移**。
