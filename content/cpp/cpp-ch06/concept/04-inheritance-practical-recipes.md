# 凯喵实战手记 · 继承、虚函数与 RTTI 的「多态陷阱」

> 凯喵说：继承是 C++ 面向对象最迷人的部分，也是最容易「以为懂了其实没懂」的部分。虚函数表、构造期虚调用、名字遮蔽、切片……每一个都能让程序表现出和你想象完全不同的行为。我们一个一个拉到现场看。

### 现场 1：基类指针调派生类方法，忘了 `virtual`

```cpp
struct Base { void f() { cout << "B"; } };
struct Der : Base { void f() { cout << "D"; } };
Base* p = new Der;
p->f(); // 输出 "B"，不是 "D"
```

非虚函数按「静态类型」`Base` 决议，根本不走派生类。凯喵的规矩：想要多态行为，基类函数必须 `virtual`；现代 C++ 派生端加 `override` 让编译器帮你查签名。

### 现场 2：构造/析构里调虚函数不触发多态

```cpp
struct Base {
    Base() { virt(); }          // 调的是 Base::virt
    virtual void virt() { cout << "B"; }
};
struct Der : Base { void virt() override { cout << "D"; } };
Der d; // 输出 "B"（构造 Base 时 Der 还没出生）
```

构造基类时对象还是「基类半成品」，虚表指向基类版本；析构对称。凯喵铁律：绝不在构造/析构里依赖虚函数的多态，把多态初始化推迟到构造完成后。

### 现场 3：名字遮蔽（Name Hiding）掩盖基类重载

派生类写了 `void f(int)`，基类的 `void f(double)`、`void f()` 会被整个隐藏，调用 `d.f(1.0)` 直接编译失败。凯喵的修法：派生类里写 `using Base::f;` 把基类重载集拉进来；或显式转发。

### 现场 4：对象切片（Slicing）悄悄丢数据

```cpp
Der d; Base b = d; // 只拷了 Base 子对象，Der 部分被切掉
```

按值赋值时只拷贝基类子对象，派生部分凭空消失。凯喵铁律：需要多态就只用指针/引用（`Base&` / `Base*` / 智能指针），绝不对多态类型按值传参或返回。

### 现场 5：`dynamic_cast` 对引用失败抛异常

`dynamic_cast<Der&>(base)` 失败时抛 `std::bad_cast`，而非返回 null（引用不能为空）。凯喵：对指针用 `dynamic_cast<Der*>(p)`（失败返回 nullptr，判空即可），对引用要准备好 catch。且基类必须有虚函数，否则 `dynamic_cast` 编译不过。

### 现场 6：基类成员遮蔽与 `protected`

派生类写了同名成员会遮蔽基类成员，`:` 访问到的未必是你想的那个。凯喵提醒：继承体系里命名要克制，必要时用 `Base::member` 显式指明；能 `private` 继承表达「实现复用」就别用 `public`。

### 现场 7：纯虚析构必须给定义

```cpp
struct Base { virtual ~Base() = 0; }; // 声明了纯虚析构
// 但派生类析构会调用 Base::~Base()，若没定义 → 链接错误
```

纯虚析构函数仍需在类外提供函数体 `Base::~Base() {}`。凯喵：想让类「抽象不可实例化」，用纯虚函数即可，析构别也标纯虚，徒增麻烦。

### 现场 8：多重继承的菱形与虚继承

```cpp
struct A { int x; };
struct B : A {};
struct C : A {};
struct D : B, C {}; // D 里有两份 A::x，d.x 歧义
```

菱形继承产生两份基类子对象。凯喵的修法：`B : virtual A`、`C : virtual A`，让 D 共享一份 A（`virtual` 继承），访问 `x` 不再歧义，但对象布局变复杂、构造顺序由最派生类负责。

### 现场 9：`override` / `final` 让你的意图被编译器校验

```cpp
struct Der : Base {
    void virt(int) override; // 编译报错：基类没有 void virt(int)，你以为是重写其实签名不符
};
```

没写 `override` 时这是「新函数」而非重写，Bug 静默产生。凯喵：所有重写都写 `override`；不希望再被覆盖的写 `final`。这两个关键字是免费的安全网。

### 现场 10：RTTI 的代价与禁用

`dynamic_cast` / `typeid` 依赖运行期类型信息，开 `-fno-rtti` 时不可用，且对性能敏感路径有开销。凯喵：能靠虚函数多态解决就别用 RTTI；确实需要「按类型分发」时，考虑 `std::variant` + `std::visit`，既类型安全又零运行期查表。

### 现场 11：虚析构是基类的最低底线

基类若可能被多态删除（`delete basePtr`），析构必须是 `virtual`，否则只调基类析构，派生部分泄漏。凯喵铁律：任何打算被继承并经由基类指针释放的类，`virtual ~Base() = default;` 必写。

### 现场 12：拷贝/移动与继承的微妙

派生类没写拷贝构造时，编译器生成的会调用基类拷贝 + 逐成员拷贝，通常 OK；但自己写了 `=delete` 或只定义移动，派生类可能继承到不合预期的行为。凯喵：继承体系里明确「五法则」，需要深拷贝就基类虚一个 `clone()` 返回 `unique_ptr<Base>`。

> 凯喵总结：继承的坑九成在「忘了 virtual」「构造期多态」「名字遮蔽」「切片」「析构非虚」。把这 12 个现场刻进手感，面向对象的设计就不会变成运行期的惊吓。

> 一句话收尾：多态是契约——基类承诺「我能被以基类指针使用」，派生类承诺「我遵守虚函数契约」，少写任何一环都会导致行为偏离你的预期。

### 凯喵复盘：对象的「出生与死亡」决定多态是否成立

这 12 个现场里最反直觉的就是构造/析构期的虚函数行为。凯喵总跟人说：对象在构造函数执行期间，**它还不是完整的派生类**，虚表指针还指向基类版本，所以你在 `Base()` 里调 `virt()` 只能看到基类自己。析构对称——当派生部分已经销毁，虚表又被改回基类，此时调 `virt()` 同样只看到基类。记住「对象一生中，只有完全构造完成之后、开始析构之前，才是真正的派生类」这条时间线，所有构造期多态的怪象都能解释通。

第二类坑是**切片与按值**。C++ 的继承在值语义下会「丢信息」：你把 `Der` 赋给 `Base` 变量，多余的部分直接被切掉，此后多态彻底失效。凯喵的底线：凡是和继承体系打交道的类型，传递与存储只用指针或引用（裸指针、引用、`unique_ptr`/`shared_ptr`），绝不对多态类型按值。这条规则挡掉了无数「为什么我的重写没生效」的工单。

第三类是**名字与契约的微妙**。名字遮蔽让基类重载集体消失，`override`/`final` 缺失让「以为重写其实是新函数」静默成功。现代 C++ 编译器其实能帮你查——只要肯写 `override`，签名对不上立刻报错。凯喵把它当免费的安全网，所有重写必写。把这些契约意识刻进设计阶段，比事后调试省心得多。

### 凯喵速记：三句话记住继承的命脉

若只记三句：第一，想多态就基类函数 `virtual`、派生端 `override`，编译器替你查签名；第二，多态类型绝不对值传递或返回，只用指针/引用，否则对象切片让派生部分凭空消失；第三，基类若可能被经指针 `delete`，析构必 `virtual`。这三句把八成继承坑挡在门外。剩下的名字遮蔽用 `using`、菱形用虚继承、RTTI 慎用，都是进阶细节，遇事回来翻这 12 个现场即可，不必一次性背全。

最后再说一句设计层面的心里话：继承关系画得越浅越稳，深继承树往往是维护灾难的开始。每多一层，你就多一份对基类契约的隐式依赖，改动了顶层可能悄悄震碎最底层，而编译器不会给你任何提示。宁可多写几个小而专的接口，也别堆一座高高的类型塔；宁可组合，也别为了省几行代码去硬套继承。判断标准其实很简单：如果你说不清子类与父类之间是不是严格的是一种关系，那就不要用继承。这条直觉一旦建立，前面那些运行期的多态怪象根本不会有机会发生，因为它们本就是设计阶段埋下的种子。

## 三视角解析
### 🧑‍💻 程序员视角
基类指针调用派生类重写的方法却没加 `virtual`，走的是静态绑定——运行时不会报错，只是「行为不对」，这类 bug 极难定位。构造/析构函数里调虚函数同样不触发多态：构造基类时派生类部分还没构造，虚表指针仍指向基类版本。最阴的是对象切片：把派生类对象按值传给 `void f(Base b)`，派生部分被静默切掉，虚函数也回退成基类行为——参数写成 `const Base&` 就能避免。

### 🎓 博士生视角
虚函数的实现依赖虚表（vtable）与虚表指针（vptr）：每个多态类一张表，每个对象一个指针，调用时经两次间接寻址。这解释了「虚函数不能内联」以及「对象体积多一个指针」的代价。RTTI 的 `dynamic_cast` 依赖虚表里的类型信息，因此只能用于多态类型，且失败时对指针返回 `nullptr`、对引用抛 `bad_cast`。从设计角度看，继承表达的是「is-a」且要求「可替换性」（LSP），组合表达「has-a」——绝大多数场景应优先组合。

### 📚 考研者视角
面试必问：
1. **虚函数表机制**：画出含虚函数的类对象内存布局（vptr + 成员），说明动态绑定过程。
2. **为什么构造函数不能是虚函数、析构函数应该是虚函数**：前者对象还没建好没有 vptr，后者保证 `delete base_ptr` 能调到派生析构。
3. **纯虚函数与抽象类**：含纯虚函数的类不可实例化，接口类通常配虚析构。
4. **`override` 与 `final`**：前者让编译器检查是否真的重写，后者禁止继续重写。
