# 02 · 综合项目二：线程池与简易 HTTP 服务器

并发组件是现代 C++ 工程能力的试金石：它强迫你把生命周期、优雅退出、确定性输出都想清楚。

## 一、线程池：任务队列 + 条件变量 + 优雅关闭

线程池 = 固定数量工作线程 + 一个线程安全任务队列（见 ex06）。提交任务即入队，空闲线程被
条件变量唤醒取任务执行。难点在**优雅关闭**：不能简单 `join`——若有任务在飞，`join` 会死等。
正确做法是先置 `stop=true`，`notify_all` 唤醒所有线程，再 `join`；在飞的线程跑完手头任务自然退出。

### 🧑‍💻 程序员视角
- **决策顺序**：任务量突发 -> 线程池复用线程省开销；需要结果可拿 -> 返回 `std::future`（`packaged_task`）；要限流 -> 队列加容量上限。
- **易错点**：`stop` 标志必须用 `std::atomic` 或锁保护；唤醒用 `notify_all` 而非 `notify_one`（避免漏唤醒导致线程空等）。
- **确定性输出**：验证只断言提交 N 个任务全部执行完和优雅关闭后线程数归零，**绝不打印顺序相关日志**，否则回放非确定。

### 🎓 博士生视角
- **第一性原理**：线程池是生产者-消费者模型在 N 个消费者上的推广；条件变量解决的不是通知而是等待-唤醒的竞态——必须用 `while(!pred)` 而非 `if` 防**虚假唤醒**。
- **形式化**：设队列为临界资源 R，P 个生产者、C 个消费者，正确性 = 互斥（任一刻至多 1 线程改 R）x 活性（队列非空则必有消费者被唤醒）x 无丢失唤醒（notify 不丢于 wait 之前）。

### 📚 考研者视角
- **408/笔试关联**：生产者-消费者、条件变量、死锁四个必要条件（互斥/占有等待/不可抢占/循环等待）是 OS 核心考点；线程池的优雅关闭就是避免占有等待死锁的实例。
- **标准问法**：条件变量为什么用 `while` 不用 `if`、线程池如何优雅退出——前者答虚假唤醒，后者答先置停止标志再唤醒全部再 join。

## 二、简易 HTTP 请求行解析

HTTP 请求行形如 `METHOD SP URI SP HTTP/1.1 CRLF`（见 ex07）。解析要做到**确定性**：只做字符串切分，
不依赖网络、不依赖随机，给定输入必有唯一输出。生产里这一步后面接路由表、参数解析、Body 读取。

### 🧑‍💻 程序员视角
- **决策顺序**：先把请求行和头部用状态机解析，再按 `Content-Length` 读 Body；不要边读边猜。
- **上线事故形态**：按 `\n` 而非 `\r\n` 切分，遇到 Windows 客户端的 `\r\n` 多出 `\r` 污染 URI，路由永远匹配不上。

### 🎓 博士生视角
- **第一性原理**：HTTP 是行结构文本协议，解析本质是在分隔符集合 `{SP, CRLF}` 上的确定有限自动机（DFA）；DFA 保证单遍扫描、O(n)、无回溯。
