# 03 · 代码规范与可读性：const 正确、RAII 与异常安全

能跑和写专业之间，差的就是这几条可判断的标准。

## 一、异常安全等级（Basic / Strong / No-throw）

异常安全有三档（见 ex08）：
- **基本保证**：异常发生后，对象仍处于有效但未指定状态，无泄漏、无损坏。
- **强保证**：异常发生后，**对象状态完全不变**（像没调用过）——事务语义。
- **不抛（noexcept）**：承诺绝不抛异常（析构、`std::move`、`swap` 应该 noexcept）。

### 🧑‍💻 程序员视角
- **决策顺序**：写修改状态的函数 -> 先定要基本还是强保证；强保证用 **copy-and-swap**（先改副本，成功再 swap）实现；会析构的资源一律 noexcept。
- **易错点**：在 `catch` 里吞掉异常导致调用方以为成功了；析构函数抛异常会与在传播中的异常相撞 -> `std::terminate`。

### 🎓 博士生视角
- **第一性原理**：强保证 = 提交性原子——所有修改要么全生效要么全回滚，对应事务 ACID 里的 A。copy-and-swap 把回滚变成副本本就未被提交，用值语义换取原子性。

### 📚 考研者视角
- **408/笔试关联**：异常安全不直接在考纲，但 RAII 如何保证资源不漏、析构抛异常为何 terminate 是 C++ 深问的高频延伸。
- **标准问法**：基本保证和强保证区别、为什么析构函数不应抛异常。

## 二、RAII 与所有权：把释放钉死在析构里

RAII（Resource Acquisition Is Initialization）：资源在构造函数取得、在析构函数释放（见 ex05）。
所有句柄类（文件、锁、连接、智能指针）都该是 RAII 类型。推论：**`new` 出来的东西必须立刻交给智能指针**，
不要让裸指针在作用域里裸奔。`unique_ptr` 表达独占所有权，默认优先于 `shared_ptr`。

### 🧑‍💻 程序员视角
- **决策顺序**：独占 -> `unique_ptr`；共享且明确无环 -> `shared_ptr`；只观察 -> `weak_ptr`；可调用的释放逻辑 -> 自定义 deleter 或 scope_guard。
- **易错点**：把 `unique_ptr` 当参数要 `std::move`；`shared_ptr` 传值会增加引用计数开销，传 `const&` 更省。

### 🎓 博士生视角
- **第一性原理**：RAII 把资源生命周期绑定到作用域生命周期，用**确定性的栈展开（stack unwinding）**替代手动 free/close，从语言层面消除忘了释放这一类错误。

### 📚 考研者视角
- **标准问法**：RAII 解决了什么问题、`unique_ptr` 和 `shared_ptr` 怎么选——前者答资源随作用域自动释放，后者答独占 vs 共享计数。
