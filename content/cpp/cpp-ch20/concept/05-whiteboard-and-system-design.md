# 05 · 白板 coding 与系统设计题答法

收官章不只"会"，还要能在面试里讲清楚、写出来、比优劣。

## 一、白板 coding 训练法

白板题（如 LRU Cache，见 ex13）的答法有固定套路：
1. **边界先行**：先问清输入规模、是否允许重复、内存限制。
2. **先说思路再写**：用 O(容量)、O(1) 命中这样的复杂度目标倒逼数据结构选择。
3. **复杂度分析**：LRU 用 `list` + `unordered_map` 做到 get/put 均摊 O(1)，map 存 list 迭代器保证 splice 后迭代器仍有效。
4. **自测用例**：最小容量、满淘汰、重复 key、并发（先说不考虑，再议加锁代价）。

### 🧑‍💻 程序员视角
- **决策顺序**：要 O(1) 查找 -> 哈希；要 O(1) 淘汰最久 -> 有序结构（list 头尾）；二者结合 -> 哈希存迭代器 + 链表维护顺序。
- **易错点**：`unordered_map` 用 `operator[]` 会**插入**缺失 key，破坏只查不插语义——用 `find` 代替。

### 🎓 博士生视角
- **第一性原理**：LRU 是最近使用偏序上的缓存替换策略；`list` 维护偏序、哈希提供 O(1) 定位，二者组合把定位 + 重排都压到 O(1)。

### 📚 考研者视角
- **标准问法**：LRU 怎么设计、get/put 复杂度——答双向链表 + 哈希，均摊 O(1)。

## 二、系统设计题答法

C++ 岗的系统设计题通常偏高性能组件而非分布式架构，答法六步：
**澄清需求 -> 量级估算 -> 定义接口 -> 画数据流 -> 找瓶颈 -> 给取舍**。
例如设计一个线程安全的连接池：澄清并发量 -> 估算连接数 = QPS x 平均占用时长 -> 接口 `acquire/release` ->
数据流（队列 + 健康检查）-> 瓶颈（锁竞争 / 连接泄漏）-> 取舍（用 `weak_ptr` 还是 `unique_ptr` 持有、超时回收策略）。

### 🧑‍💻 程序员视角
- **决策顺序**：先定 SLA（QPS、延迟、可用性），再选数据结构，再谈并发模型；C++ 场景优先谈零拷贝 / 无锁 / 对象池而非堆机器。

### 🎓 博士生视角
- **第一性原理**：系统设计是在约束（延迟、吞吐、内存）下做折中；每个组件都是正确性 x 性能 x 可维护性三维 Pareto 前沿上的点。

### 📚 考研者视角
- **关联**：系统设计把前面所有知识（并发、RAII、容器、复杂度）串成能交付的形态，是综合能力的检验。
