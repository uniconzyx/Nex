# cpp-ch20 · 易错点清单

以下条目是综合项目与面试冲刺中最常踩的坑，每条均对应已验证示例，可回放对照。

1. `reserve(n)` 只把 `capacity` 顶到 n，**不保证 `data()` 地址不变**；`push_back` 触发扩容后所有迭代器/指针/引用失效（对应 ex01 / ex12）。误以为 reserve 后就能安全持有引用必翻车。
2. copy-and-swap 惯用法让自赋值安全，但 `swap` 必须 `noexcept`；若 swap 可能抛异常，移动赋值会退化成拷贝并破坏强异常安全（对应 ex02）。
3. 移动后对象处于有效但未指定状态——不能假设它变空、不能读它的值，只能析构或重新赋值。误把被移动对象当空对象用会读到垃圾（对应 ex02 / ex09）。
4. `shared_ptr<T>(new T)` 分两次堆分配（对象一次、控制块一次）；`make_shared<T>()` 一次分配两者，且构造即入控制块，异常更安全（对应 ex03）。
5. 两个对象互相持有 `shared_ptr` 会形成循环引用，use_count 永不为 0，析构永不触发 -> **内存泄漏**。打破手段是用 `weak_ptr` 持有其中一方（对应 ex04）。
6. `weak_ptr::lock()` 取空对象已析构，必须判空再解引用；不解引用判空直接用会段错误（对应 ex04）。
7. RAII 的释放必须写在**析构函数**里，不是 try/finally 的 finally 块；写在 finally 里一旦别处早 return 仍有遗漏风险，析构是作用域退出唯一确定的落点（对应 ex05）。
8. 异常安全基本保证下，失败后对象处于任意但**有效**状态，不能假设字段没变；只有强保证才承诺状态完全不变。误把基本保证当强保证去读字段值会读到半更新状态（对应 ex08）。
9. 析构函数里抛异常，若恰有另一异常在传播栈上，会触发 `std::terminate` 直接崩进程；析构里一律吞掉或 noexcept（对应 ex05 / ex08）。
10. 在会走 RVO 的返回处写 `return std::move(obj)` 是反模式：它强制走移动构造，**反而丧失 NRVO 机会**并多一次移动（对应 ex10）。
11. `std::move` 只是**无条件右值转换**，不产生任何代码、不移动任何东西；它只是允许移动。误以为 move 之后源对象就清空是错的（对应 ex09 / ex10）。
12. **对象切片（slicing）**：把派生类对象按值赋给基类对象，派生部分被切掉，多态失效。多态必须靠指针/引用传递（对应 ex11）。
13. 基类析构函数非 `virtual` 时，经基类指针 `delete` 派生对象只调基类析构，派生资源泄漏；只要类会被继承并经基类指针释放，析构必须 `virtual`（对应 ex11）。
14. `vector::erase` 使被删及之后元素失效，循环里必须 `it = c.erase(it)` 用返回值续接，不能 `it++` 后再 erase（对应 ex12）。
15. LRU 用 `unordered_map` 时别用 `operator[]` 探测缺失 key——它会**插入**新条目破坏只查不插语义；用 `find`。`list` 的 `splice` 后 map 里存的迭代器仍有效（对应 ex13）。
