# cpp-ch05 易错点（Pitfalls）

1. **忘记定义拷贝控制导致双重释放**
   管理裸指针却不写拷贝构造/赋值/析构，编译器浅拷贝使两个对象指向同一内存，析构时 `delete` 两次崩溃。
   ✅ 用智能指针（ch10）或严格实现 Rule of Three/Five。

2. **拷贝赋值未处理自赋值与内存泄漏**
   ```cpp
   Vec& operator=(const Vec& o) {
       delete[] data_;          // 若 this==&o，先销毁了共享内存
       data_ = new double[...]; // 已悬空
   }
   ```
   ✅ 先 `if (this == &o) return *this;`，再释放旧资源、深拷贝。

3. **const 对象调用非 const 成员函数**
   `const Counter c; c.inc();` 编译失败——`inc()` 未声明 `const`。
   ✅ 不修改状态的函数一律加 `const`。

4. **构造函数内调用虚函数不触发多态**
   基类构造期间对象尚未成为派生类，虚调用绑定到当前构造中的类（见 ch06）。

5. **在构造函数/析构函数中抛异常导致资源泄漏**
   构造中途抛异常，已分配成员由编译器自动析构，但裸指针手动 `new` 的部分需谨慎。
   ✅ 用成员初始化列表 + 智能指针（RAII），让异常安全由析构保证。

6. **返回局部对象的引用**
   `Money& f() { Money m; return m; }` 返回已销毁对象的引用——悬垂引用。
   ✅ 返回值的场景用值返回（RVO 会避免拷贝）。

7. **初始化列表顺序 ≠ 声明顺序**
   初始化按成员**声明顺序**执行，与列表书写顺序无关；乱序会触发警告/未定义行为。
   ✅ 列表顺序与成员声明顺序保持一致。

8. **滥用 `friend` 破坏封装**
   随意 `friend` 全局函数会让 `private` 形同虚设。
   ✅ 仅在运算符对称性等必要时使用，保持最小暴露。

9. **返回值类型写成引用，返回了局部对象**
   `Counter& scaled(int k) const { return Counter{value_*k}; }` 返回的是函数内临时对象的引用，调用方拿到悬垂引用，可能在某些机器上「看起来正常」。
   ✅ 返回新对象的用值，返回自身的用 `*this` 引用：`Counter scaled(int) const` 返回值，`Counter& add(int)` 返回引用。

10. **只写 `operator==` 不写 `operator!=`，或两者基于不同字段**
   自定义类型的 `operator<` 只比 id、`operator==` 却比 id 和名字，导致 `std::set` 认为两个对象相同（互不小于），去重逻辑认为不同，两边打架。
   ✅ C++20 直接用 `auto operator<=>(const T&) const = default;` 一行生成全部比较；老标准下手写时保证 `==` 与 `<` 基于同一组字段。

11. **静态成员变量只声明不定义**
   类内写 `static int instances;` 后忘了类外的 `int Config::instances = 0;`，编译全部通过、链接时报 undefined reference，报错位置还在使用处。
   ✅ C++17 起直接用 `inline static int instances = 0;` 在类内定义；被困在 C++14 就补齐类外定义。

12. **禁止拷贝用「private 且不实现」的老写法**
   把拷贝构造声明成 private 但不给实现，错误被推迟到链接期，报错信息晦涩，而且友元类仍能调用。
   ✅ 用 `= delete` 显式删除，编译期就报错且信息清晰；确实需要转移所有权时再补移动构造并标 `noexcept`。

13. **移动构造漏了 `noexcept`**
   写了移动构造却没标 `noexcept`，`std::vector` 在扩容时检测到移动可能抛出，退回去用拷贝，性能莫名其妙掉一半。
   ✅ 移动构造与移动赋值一律标 `noexcept`（只要不分配可能失败的新资源），这是让容器走移动路径的前提。

14. **移动后没把源对象置成可安全析构的状态**
   `Socket(Socket&& o) : fd_(o.fd_) {}` 转移了 fd 却没把 `o.fd_` 置 -1，源对象析构时把同一个 fd 关掉，目标对象手里的句柄立刻失效。
   ✅ 移动后必须把源对象置为「空且可析构」：`o.fd_ = -1;`。移动是「转移」，不是「复制」。

15. **构造/析构函数里调用虚函数，期待多态生效**
   在基类构造函数里调虚函数，以为会调到派生类实现，实际调到的是基类版本——因为构造期间派生类部分还没初始化。
   ✅ 构造函数里的虚调用一律按「当前已构造的层级」解析；需要派生类参与初始化，就把逻辑拆到 `init()` 由派生类显式调用，或用工厂函数在两段构造之后再做。
