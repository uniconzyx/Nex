# 03 · 运算符重载：重载决议、ADL 与对称性

## 一、理论根基：运算符本质上是"有语法糖的函数调用"

写 `a + b` 时，编译器把它变换为：
- **成员形式**：`a.operator+(b)`（左操作数必须是该类对象）
- **非成员形式**：`operator+(a, b)`（自由函数，通常声明为友元）

**第一性原理**：运算符重载不改变运算符的**优先级、结合性、目数**，只是让它对用户定义类型拥有重载的函数语义。因此设计准则只有一条——
> **让自定义类型的行为符合内置类型的直觉**（可替换原则 / Liskov 风格的"最小惊讶"）。用 `+` 做减法、用 `<<` 做输入，是灾难性设计。

## 二、实现机制：重载决议与 ADL

调用 `a + b` 时编译器要做**重载决议（overload resolution）**：

1. **名字查找**：先在类作用域找成员函数 `operator+`；再在**实参关联命名空间**找非成员函数——即 **ADL（Argument-Dependent Lookup，Koenig 查找）**。
   ```cpp
   namespace geom { struct Vec{}; Vec operator+(Vec, Vec); }
   geom::Vec a, b;
   auto c = a + b;     // 无需写 geom::operator+，ADL 自动在 geom 中找到
   ```
   ADL 是 **`operator<<`、swap 惯用法**能工作的根本原因。
2. **可行性与最佳匹配**：对候选集按转换序列排名（精确匹配 > 提升 > 标准转换 > 用户定义转换），选出**唯一最佳**；平局则**歧义（ambiguous）**编译错误。

## 三、成员函数 vs 非成员函数：对称性判据

| 判据 | 选择 |
|---|---|
| 需要访问私有成员 | 成员函数，或**非成员 + friend** |
| 左操作数可以是别的类型（如 `2 * vec`） | **非成员**（成员形式要求左操作数必须是本类） |
| `=`、`[]`、`()`、`->` | **必须**是成员函数（语言规定） |
| `<<`（流输出） | **必须非成员**（左操作数是 `ostream`，不能改标准库） |

```cpp
struct Vec { double x, y; };
Vec operator*(double k, const Vec& v) { return {k*v.x, k*v.y}; }  // 非成员：支持 2 * v
Vec operator*(const Vec& v, double k) { return k * v; }           // 再提供 v * 2
```
> 若只写成成员函数 `Vec::operator*(double)`，则 `2 * v` **无法编译**。

## 四、工程实践：返回类型与复合赋值的约定

约定俗成（遵守它，你的类型才能与泛型代码、标准算法良好协作）：

1. **复合赋值 `+=` 返回 `T&`（引用）**，支持链式：`a += b += c`。
2. **二元 `+` 返回新对象（值）**，且**用 `+=` 实现 `+`**（只有一份逻辑，避免重复）：
   ```cpp
   Vec& operator+=(const Vec& o) { x += o.x; y += o.y; return *this; }
   friend Vec operator+(Vec a, const Vec& b) { a += b; return a; }  // 传值+复用
   ```
   传值形参天然获得"拷贝一份再改"的语义，还能利用移动语义。
3. **比较运算**：C++20 起只需定义 `operator<=>`（三路比较），编译器自动合成 `==`、`!=`、`<` 等：
   ```cpp
   auto operator<=>(const Vec&) const = default;   // 编译器按成员字典序生成
   bool operator==(const Vec&) const = default;
   ```
4. **`operator<<` 输出**：非成员，返回 `ostream&` 以支持链式。

## 五、边界与陷阱

1. **不要为了"聪明"重载**：运算符语义应与数学/内置类型直觉一致。
2. **单参数构造函数会引入隐式转换**，可能让重载决议产生意外匹配 → 用 `explicit` 封堵。
3. **重载 `&&`、`||`、`,` 会丧失短路求值**（因为变成函数调用，两个实参都要先求值）——**几乎总是错误**。
4. `&&` / `||` 在重载后失去短路；`operator&` 取地址重载会让对象难以放入标准容器。
5. **不可重载**的运算符：`.`、`.*`、`::`、`?:`、`sizeof`、`typeid` 等。

## 六、可运行示例

```cpp
#include <iostream>

struct Vec {
    double x, y;
    Vec& operator+=(const Vec& o) { x += o.x; y += o.y; return *this; }   // 返回引用
    friend Vec operator+(Vec a, const Vec& b) { a += b; return a; }        // 复用 +=
    friend Vec operator*(double k, const Vec& v) { return {k*v.x, k*v.y}; }// 非成员：支持 2*v
    friend Vec operator*(const Vec& v, double k) { return k * v; }
    friend std::ostream& operator<<(std::ostream& os, const Vec& v) {
        return os << '(' << v.x << ',' << v.y << ')';
    }
};

int main() {
    Vec a{1, 2}, b{10, 20};
    Vec c = a + b;              // 用 += 实现
    std::cout << "a+b=" << c << '\n';
    std::cout << "2*a=" << 2 * a << "  a*3=" << a * 3 << '\n';  // 对称性
    a += b += Vec{1, 1};        // 链式：返回引用才可行
    std::cout << "a=" << a << '\n';
}
```

**输出**：
```
a+b=(11,22)
2*a=(2,4)  a*3=(3,6)
a=(12,23)
```

> 观察点：① `2 * a` 只有在**非成员**形式下才成立；② `a += b += ...` 链式依赖 `+=` 返回 `Vec&`；③ `<<` 返回 `ostream&` 才能继续链式输出。

## 三视角解析

### 🧑‍💻 程序员视角
- 运算符重载要**符合直觉**：`+` 不该做破坏性操作，`==` 要与 `!=` 一致；滥用比不用更糟。
- 二元运算符优先实现为**非成员**（保持左右对称、支持隐式转换）；`+=` 等复合赋值实现为成员。
- `operator<<` / `operator>>` 必须是**非成员**（左操作数是流对象）；C++20 的 `operator<=>` 可一键生成全部比较运算符。

### 🎓 博士生视角
- 重载决议的完整流程：**候选集收集（含 ADL）→ 可行函数筛选 → 最佳匹配排序**。运算符只是「名字特殊的函数」，享有完全相同的重载规则。
- 运算符的**元数、优先级、结合性、短路语义都无法改变**（只能重载已有运算符、且不能改变其「形状」）。这保证了 `a + b * c` 的解析不会因重载而变——语法与语义的边界由此划清。
- **ADL（参数依赖查找）**让运算符能在操作数的关联命名空间中自动找到——这就是为什么重载的 `operator+` 不必显式限定命名空间也能被调用（与「通用名字不该依赖 ADL」形成对照）。
- **成员 vs 非成员的关键差异**：成员版本的左操作数**不参与隐式转换**（因为它是 `this`），而非成员版本对两侧都做隐式转换。这正是「对称性」问题的技术根源，也是「二元运算符优先非成员」的理由。

### 📚 考研者视角
- 与编译原理的**重载解析、名字查找**对应（ADL 是 C++ 特有的查找规则）。
- 常考概念题：「哪些运算符不能被重载」（`::`、`.`、`.*`、`?:`、`sizeof`）、「成员与非成员重载的区别」。
- 记忆锚点：**不能改优先级与元数**；**二元运算符优先非成员（对称性）**；**流运算符必须非成员**。
