# 01 · 类与对象：从对象模型到内存布局

## 一、理论根基：为什么要引入"类"

从计算机科学的视角看，**类（class）不是语法糖，而是一种抽象机制**：它把「数据」与「作用于数据的操作」绑定，并用**访问控制**划出一条"不变式（invariant）边界"。

- **封装的本质**：不是"藏起来"，而是**收窄状态的合法取值空间**。把字段设为 `private` 后，对象状态只能通过成员函数改变，于是类的作者可以在每个成员函数入口校验不变式——这是**抽象数据类型（ADT）**理论在语言层面的落地。
- **对比 C 的 struct**：C 的 `struct` 只是一段内存的布局声明，任何代码都能任意改写其字段，不变式靠"程序员自觉"维持；C++ 的 `class` 把不变式的维护责任从调用方转移到类型自身。

> 设计哲学：如果一个类型的所有字段都可被任意写入，那它与 `struct` 无异，封装也就失去意义。

## 二、实现机制：对象在内存里到底是什么

这是**程序员必须掌握的底层事实**（C++ 对象模型，参见 Stanley Lippman《深度探索 C++ 对象模型》）：

1. **成员函数不占对象空间**。类的非静态成员函数被编译器改写为普通函数，只是多了一个隐式参数 `this`。因此：
   ```cpp
   sizeof(MyClass) // 只统计非静态数据成员 + 对齐填充（+ 若有虚函数则多一个 vptr）
   ```
2. **`this` 指针**：指向当前对象的首地址。成员函数内访问 `member_` 实际是 `this->member_`。
3. **访问控制是编译期概念，不是运行期保护**。编译后 `private` 信息消失——它约束的是"名字查找与访问权限检查"，而非内存保护（这也是为什么可以用指针技巧绕过，但那是 UB）。
4. **空类的大小为 1 字节**：为了**保证两个不同对象有不同地址**（若为 0，数组元素地址会重合）。
   ```cpp
   struct Empty {};
   sizeof(Empty) == 1;  // 保证对象地址唯一性
   ```
5. **成员布局与对齐**：非静态数据成员按**声明顺序**排布（同一访问级别内），并遵循 `alignof` 对齐规则，可能产生 padding。**把大对齐成员放前面、小成员聚在一起，可减少 padding**：
   ```cpp
   struct Bad  { char c; double d; char c2; };  // 1+7pad+8+1+7pad = 24
   struct Good { double d; char c; char c2; };  // 8+1+1+6pad = 16
   ```

## 三、工程实践：程序员视角的取舍

- **优先用构造函数建立不变式**，而不是提供一堆 setter 让对象处于"半初始化"状态。
- **不修改状态的函数一律加 `const`**：`size() const`。这既是给编译器的承诺，也是给调用者的文档；`const` 对象只能调用 const 成员函数。
- **聚合数据用 `struct`，有不变式用 `class`**（二者仅默认访问权限不同）。
- **数据成员尽量 `private`**，除非确实是纯数据载体（如 POD、DTO）。

## 四、边界与陷阱

- `sizeof` 不含静态成员（静态成员属于类，存储在静态存储区）。
- 成员初始化顺序 = **声明顺序**，与初始化列表书写顺序无关，乱序会触发 `-Wreorder`。
- 访问控制的"绕过"（如 `reinterpret_cast`）属未定义行为，不要依赖。

## 五、可运行示例：眼见为实

```cpp
#include <iostream>

struct Empty {};

struct Bad  { char c; double d; char c2; };
struct Good { double d; char c; char c2; };

class Counter {
    int value_ = 0;                      // private：不变式由类维护
public:
    void inc() { if (value_ < 100) ++value_; }   // 不变式：0 <= value_ <= 100
    int get() const { return value_; }           // const 成员函数
};

int main() {
    std::cout << "sizeof(Empty)=" << sizeof(Empty) << '\n';
    std::cout << "sizeof(Bad)=" << sizeof(Bad) << " sizeof(Good)=" << sizeof(Good) << '\n';
    std::cout << "sizeof(Counter)=" << sizeof(Counter) << " (成员函数不占对象空间)\n";
    Counter c; c.inc(); c.inc();
    const Counter& cc = c;
    std::cout << "value=" << cc.get() << '\n';   // const 引用只能调 const 函数
}
```

**输出**：
```
sizeof(Empty)=1
sizeof(Bad)=24 sizeof(Good)=16
sizeof(Counter)=4 (成员函数不占对象空间)
value=2
```

> 关键结论：`sizeof(Counter)==4` 印证了"成员函数不占对象空间"；`Bad` 与 `Good` 的差距直观展示了**对齐 padding 的代价**。

## 三视角解析

### 🧑‍💻 程序员视角
- `class` 与 `struct` 唯一区别是**默认访问级别**（与默认继承方式）；团队内应统一约定（例如「数据载体用 struct、有不变式的用 class」）。
- 成员函数定义在类内**隐含 `inline`**，因此小函数放类内、大函数放 `.cpp` 是常见布局。
- `const` 成员函数是对调用者的承诺（不改对象状态），也是「能被 const 对象调用」的前提。

### 🎓 博士生视角
- 对象的内存布局只包含**非静态数据成员**（按声明顺序排列，并考虑对齐填充）；成员函数不占对象空间，虚函数只贡献一个 `vptr`。
- **空类 `sizeof` 为 1**：标准要求每个对象有唯一地址，因此不能为 0。但「空基类优化（EBO）」允许空基类子对象不占空间（这就是 `std::unique_ptr` 能把删除器「免费」存下的原因）。
- `this` 是一个隐式参数（在成员函数中是指针）；`const` 成员函数里 `this` 的类型是 `const T*`。因此「成员函数是否是 const」本质上是**重载**：两者可以共存，且 const 版本被 const 对象优先选中。
- 从语言设计看，类把「数据 + 操作 + 访问控制 + 重载决议」打包，是 C 的结构体加上「封装与函数式绑定」的产物。

### 📚 考研者视角
- 与计组的**记录类型内存布局**、对齐填充直接对应。
- 常考计算：给定成员列表求 `sizeof` 与各成员偏移（按「偏移必须是该成员对齐数的整数倍」逐步推）。
- 记忆锚点：**空类 `sizeof` = 1**；**成员函数不占对象空间**；**`class` 与 `struct` 只差默认访问级别**。
