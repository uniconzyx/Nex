# C 风格数组与指针

C 数组是一段连续内存；数组名在多数语境下会**退化（decay）为指向首元素的指针**。这两个事实（连续、退化）几乎解释了所有与数组相关的坑：`sizeof` 失效、函数传参丢长度、下标越界不报错。

## 一、数组的真实类型

`int a[5];` 的类型是 `int[5]`——**长度是类型的一部分**。这一点在三个地方能看出来：

```cpp
int a[5];
sizeof(a) == 20;              // 5 * sizeof(int)，长度参与计算
&a;                           // 类型是 int(*)[5]，指向整个数组
sizeof(&a) == sizeof(void*);  // 8，但指向的是「5 个 int」这个整体
```

而 `int* p = a;` 之后，`sizeof(p)` 恒为 8，`p` 也再无从得知长度。**长度信息在退化的一瞬间丢失，不可恢复**。

数组不能拷贝、不能赋值、不能按值传参——这三条限制都是"长度在类型里"的后果：编译器不知道该怎么处理不同长度的数组之间的赋值。

### 下标是语法糖

`a[i]` 定义为 `*(a + i)`，因此 `i[a]` 同样合法（`*(i + a)`）。这也是为什么**下标越界不报错**：它就是一次指针加法加一次解引用，语言层面没有边界概念。

```text
数组与指针的类型差异（int a[5];）

  a            类型 int[5]        可 sizeof → 20
  a + 1        类型 int*          地址偏移 4 字节
  &a           类型 int(*)[5]     地址相同，但 +1 走 20 字节
  &a[0]        类型 int*          与 a 的地址相同（值），类型不同
```

`&a` 与 `&a[0]` 的**地址值相同、类型不同、步长不同**，这是理解多维数组与指针算术的关键细节。

## 二、退化发生在哪里

退化不是"数组就是指针"，而是**在特定语境下的一次隐式转换**。退化发生：

- 赋给指针：`int* p = a;`
- 传给以指针/数组为形参的函数
- 参与算术：`a + 1`
- 用于 `if (a)` 这类布尔语境

退化**不发生**：

- `sizeof(a)`、`&a`、`decltype(a)`
- 引用绑定：`int (&ref)[5] = a;` 保留完整类型
- 模板推导的引用形参：`template<typename T, size_t N> void f(T (&arr)[N])` 能推出 `N`

最后一条是"用模板恢复长度"的经典手法——在 `std::array`/`std::span` 之外，这是让函数知道数组长度的唯一编译期办法。

## 三、函数传参：长度信息的丢失与重建

```cpp
void print(int a[5]);   // 骗人的写法：等价于 void print(int* a)
void print(int* a, std::size_t n);   // 正确：长度一起传
```

`int a[5]` 在形参位置会被编译器**直接改写成 `int* a`**，`5` 被忽略，且不产生任何告警。这就是"形参写成数组很安全"这个直觉错在哪。

现代做法按优先级排序：

1. `std::span<const int>`（C++20）：指针 + 长度，能接任意连续容器。
2. `std::vector<int> const&` / `std::array<int,N> const&`：携带长度的容器。
3. `(const int* a, std::size_t n)`：C 接口的原始形态，给 C API 用。
4. `int a[]`：**不要用**，除非你在定义函数指针类型去匹配 C 库签名。

## 四、字符串字面量与 `const char[]`

字符串字面量 `"abc"` 的类型是 `const char[4]`（含结尾 `\0`），存放在**只读数据段**。C++11 起禁止隐式转成 `char*`——因为写它属于 UB（历史上很多崩溃就是这么来的）。

```cpp
const char* s = "abc";     // OK，只读
char* bad = "abc";         // C++11 起编译错误
char arr[] = "abc";        // OK，拷贝到栈上，可修改
```

`char arr[] = "abc"` 与 `const char* s = "abc"` 的区别是**有无副本**：前者在栈上有一份可写的 4 字节数组，后者只是指向只读段的一个指针。这个区别决定了"能不能改"和"sizeof 是多少"。

## 五、边界与陷阱

- **形参写 `int a[5]` 会丢长度**：`sizeof(a)` 变成指针大小，编译器不警告。
- **`sizeof` 只对真正的数组类型有效**：一旦变量被声明为指针，`sizeof` 恒为指针大小。
- **`&a` 与 `a` 类型不同**：`(&a)[1]` 越过整个数组，`a[1]` 越过一个元素。
- **越界不检查**：`a[5]` 在 5 元素数组上是 UB，可能读到相邻变量，也可能触发栈保护。
- **C 字符串忘 `\0`**：`char buf[3] = {'a','b','c'};` 不是字符串，传给 `strlen` 会越界读。
- **`strcpy`/`sprintf` 无边界**：用 `strncpy`/`snprintf` 或干脆用 `std::string`。

## 六、可运行示例：让 `sizeof` 自己说话

```cpp
#include <cstddef>
#include <iostream>

void by_array_param(int a[5]) {           // 形参被改写成 int*
    std::cout << "in_func=" << sizeof(a) << "\n";
}

template <std::size_t N>
void by_ref_param(int (&a)[N]) {          // 引用绑定，保留完整类型
    std::cout << "by_ref_N=" << N << " size=" << sizeof(a) << "\n";
}

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    std::cout << "in_main=" << sizeof(a) << "\n";
    by_array_param(a);                    // 打印指针大小
    by_ref_param(a);                      // 打印 5 与 20

    std::cout << "diff_ptr=" << (&a[1] - &a[0]) << "\n";
    std::cout << "diff_arr=" << ((char*)(&a + 1) - (char*)&a) << "\n";
}
```

两处对比最值钱：`by_array_param` 里 `sizeof` 退化，而 `by_ref_param` 通过模板把 `N` 拿到手；`&a + 1` 跨越 20 字节而不是 4 字节，证明 `&a` 的类型是 `int(*)[5]`。

## 三视角解析

### 🧑‍💻 程序员视角
- 现代 C++ 里 C 数组基本只剩两个场景：与 C API 交互、以及作为 `std::array`/`std::vector` 的底层。默认用 `std::array`（定长）或 `std::vector`（变长）。
- 函数参数里的 `int a[]` 与 `int* a` **完全等价**（都退化为指针），长度信息当场丢失。
- 字符串字面量的类型是 `const char[N]`，C++11 起**不能**隐式转成 `char*`（写只读内存是 UB）。
- 需要"只读的连续区间"时，C++20 的 `std::span` 是比 `(指针, 长度)` 更安全的现代写法。

### 🎓 博士生视角
- 数组退化（array-to-pointer decay）是「隐式转换」，不是「数组就是指针」：`sizeof(a)` 与 `&a` 能区分二者。
- `std::array<T, N>` 把长度提升为**类型的一部分**（模板参数），因此 `sizeof` 正确、可拷贝、可迭代，且**零运行时开销**（不引入额外存储）。这是「用类型承载信息」的思想。
- 字符串字面量存放在**只读数据段**，修改它是 UB；把它赋给 `char*`（C++11 前允许）正是历史上大量崩溃的来源，因此标准收紧了这条隐式转换。
- 从 ABI 看，数组传参退化为指针是 C 的「按值传递做不到大对象高效」的妥协；C++ 用 `std::span`（C++20）提供了「指针 + 长度」的现代包装。
- 退化规则的精确表述：数组在**除 `sizeof`、`alignof`、`&`、引用绑定、decltype 与字符串字面量初始化 `char[]` 之外**的语境中，都会转成指向首元素的指针。

### 📚 考研者视角
- **408 高频**：「数组名与指针的关系」「数组作函数参数的变化」——`sizeof` 在函数内失效是必考细节。
- 与计组的**地址计算**（`base + i*sizeof(T)`）直接对应；一维/二维数组的行优先存储与下标换算常考。
- 常考辨析：`a`、`&a`、`&a[0]` 三者的值相同但类型与步长不同。
- 记忆锚点：**优先 `std::array`/`std::vector`**；**字符串字面量类型是 `const char[N]`**；**形参数组会退化成指针**。
