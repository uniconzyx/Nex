# C 风格数组与指针

C 数组是一段连续内存；数组名在多数语境下会**退化（decay）为指向首元素的指针**。

## 要点

- `int a[5];` 元素连续；`a[i]` 等价于 `*(a + i)`
- 数组作为函数参数时会退化为指针，**丢失长度信息**：`void f(int a[])` 实即 `void f(int* a)`，此时 `sizeof(a)` 是指针大小
- 正确传递数组长度：显式传 `size` 或用 `std::array` / `std::vector`

```cpp
void print(int* a, size_t n) {
    for (size_t i = 0; i < n; ++i) std::cout << a[i] << " ";
}
```

> 优先用 `std::vector` / `std::array` 替代裸数组，避免退化与越界。

---

## 三视角解析

### 🧑‍💻 程序员视角
- 现代 C++ 里 C 数组基本只剩两个场景：与 C API 交互、以及作为 `std::array`/`std::vector` 的底层。默认用 `std::array`（定长）或 `std::vector`（变长）。
- 函数参数里的 `int a[]` 与 `int* a` **完全等价**（都退化为指针），长度信息当场丢失。
- 字符串字面量的类型是 `const char[N]`，C++11 起**不能**隐式转成 `char*`（写只读内存是 UB）。

### 🎓 博士生视角
- 数组退化（array-to-pointer decay）是「隐式转换」，不是「数组就是指针」：`sizeof(a)` 与 `&a` 能区分二者。
- `std::array<T, N>` 把长度提升为**类型的一部分**（模板参数），因此 `sizeof` 正确、可拷贝、可迭代，且**零运行时开销**（不引入额外存储）。这是「用类型承载信息」的思想。
- 字符串字面量存放在**只读数据段**，修改它是 UB；把它赋给 `char*`（C++11 前允许）正是历史上大量崩溃的来源，因此标准收紧了这条隐式转换。
- 从 ABI 看，数组传参退化为指针是 C 的「按值传递做不到大对象高效」的妥协；C++ 用 `std::span`（C++20）提供了「指针 + 长度」的现代包装。

### 📚 考研者视角
- **408 高频**：「数组名与指针的关系」「数组作函数参数的变化」——`sizeof` 在函数内失效是必考细节。
- 与计组的**地址计算**（`base + i*sizeof(T)`）直接对应。
- 记忆锚点：**优先 `std::array`/`std::vector`**；**字符串字面量类型是 `const char[N]`**。
