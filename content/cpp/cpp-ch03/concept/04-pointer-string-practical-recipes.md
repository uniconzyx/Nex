# 凯喵实战手记 · 数组、指针与字符串的那些「当场爆炸」

> 凯喵说：C++ 里最让人头秃的不是模板元编程，而是「数组怎么就退化成指针了」「字符串怎么就 O(n²) 了」「string_view 怎么就悬垂了」。这一章我们把这些坑一个个拉到现场，让你亲眼看着它炸，再亲手把它修好。

### 现场 1：数组退化成指针，`sizeof` 当场翻车

凯喵刚接手一段老代码，想算数组长度：

```cpp
void foo(int a[]) {
    std::cout << sizeof(a); // 输出 8（指针大小），不是数组总字节
}
int main() {
    int b[10];
    foo(b);
}
```

`a[]` 在参数里等价于 `int* a`，`sizeof(a)` 退化成指针大小。`sizeof(b)` 在主函数里才是 40。要传数组大小，请用 `std::span` 或显式传 `size_t n`，别指望 `sizeof` 帮你数元素。

### 现场 2：`char[]` 与 `char*` 的本质区别

凯喵写了 `char* s = "hello"; s[0] = 'H';`，程序直接段错误。原因：字符串字面量存在只读段 `.rodata`，`char*` 指向它，写入是 UB。正确做法：要改就拷到栈上 `char s[] = "hello";`（数组初始化自动拷贝），或只读时用 `const char*`。

### 现场 3：字符串拼接用 `+` 在循环里 O(n²)

```cpp
std::string s;
for (auto& w : words) s = s + w; // 每次都分配新内存并拷贝
```

每次 `+` 都产生新字符串，整体复杂度 O(n²)，大文本能慢到离谱。凯喵的修法：先 `reserve` 预估容量，循环里用 `s += w`；或对字符串列表直接用 `std::accumulate`/`join`（C++23 `std::ranges::join_with`）。

### 现场 4：`std::string` 的 SSO 与扩容

短字符串（通常 ≤15 字节）存在对象内部的「小字符串优化」缓冲区，不堆分配；超长才去堆上。凯喵提醒：频繁 `+=` 小规模字符串时，提前 `reserve` 能避免多次 realloc 拷贝。但别盲目 reserve 超大值，那是浪费。

### 现场 5：`string_view` 悬垂的经典场景

```cpp
std::string_view sv = std::string("temp"); // 临时对象销毁，sv 悬垂！
sv[0]; // UB
```

`string_view` 不拥有数据，只是指针+长度。凡是来源是临时 `string`、函数返回局部 `string`、或被后续的 `erase`/`clear` 改动，view 都会悬垂。凯喵的规矩：view 的寿命必须严格短于它指向的对象。

### 现场 6：`substr` 的零拷贝替代

取后缀时 `s = s.substr(1)` 每次复制剩余全部字符。凯喵改用 `std::string_view(s).substr(1)` 做零拷贝切片，只在最终需要持久化时才 `.str()` 转回 `string`。注意切出来的 view 仍受原串寿命约束。

### 现场 7：C 风格字符串结尾 `\0` 的坑

`char buf[3] = "abc";` 其实越界了——字面量有 4 字符含 `\0`，但 buf 只有 3。凯喵的修法：让编译器定大小 `char buf[] = "abc";`（自动 4）。函数接收 C 串时务必确认调用方传的是以 `\0` 结尾的合法字符串，否则 `strlen` 会越界乱读。

### 现场 8：`c_str()` 返回的指针有效期

```cpp
const char* p = s.c_str();
s += "x";      // 可能 realloc，p 失效
std::cout << p; // UB
```

`c_str()` 返回的指针在下次「非 const 修改」或析构前有效。凯喵的规矩：要长期持有就 `strdup`/拷贝，别存裸指针。

### 现场 9：混用 `string` 与 `string_view` 重载歧义

同时提供 `f(std::string)` 和 `f(std::string_view)`，传字面量 `"x"` 时两者都可匹配，编译报歧义。凯喵只保留 `f(std::string_view)` 版本（它既能接 `string` 也能接字面量），消除二义性。

### 现场 10：`reserve` 避免反复扩容

构造大字符串前 `s.reserve(total)` 一次性预留，循环里 `+=` 不再触发 realloc。凯喵在解析日志、拼 SQL 时必做这步，性能能差一个数量级。

### 现场 11：字符串比较别退化成裸指针

`if (s == "abc")` 是 OK 的（`string` 重载了 `==`）。但 `if (strcmp(s.c_str(), "abc") == 0)` 容易写成 `=` 误赋值，且要记得包含 `<cstring>`。凯喵优先用 `string` 的原生比较，可读性更好也更安全。

### 现场 12：宽字符与 UTF-8 的混乱

`std::wstring` 在 Windows 是 UTF-16、在 Linux 是 UTF-32，跨平台不一致。现代项目凯喵统一用 `std::string` 存 UTF-8，需要按「字符（而非字节）」遍历时用第三方库或手动解码，别直接当下标当字符数用。

### 现场 13：只读字符串字面量写入 UB

`const char* s = "abc"; const_cast<char*>(s)[0] = 'x';` 即使强转去掉 const 也照样段错误，因为底层在只读段。凯喵铁律：字面量只读，要改先拷贝到可写缓冲区。

### 现场 14：字符串查找返回 `npos` 的判等

```cpp
if (s.find("k") == std::string::npos) { /* 没找到 */ }
```

`find` 返回 `size_t`，找不到时返回 `npos`（最大无符号值）。凯喵提醒：别拿 `find(...) == -1` 去判等（`-1` 转成无符号会变成巨大正数），必须和 `npos` 比。

> 凯喵总结：数组/指针/字符串的坑九成在「退化」「悬垂」「O(n²) 拼接」「只读段写入」。记住数组传参要带大小、view 寿命短于源、拼接先 reserve、字面量只读。把这 14 个现场刻进手感，字符串相关 Bug 少一大半。

> 一句话收尾：字符串看似简单，却是 C++ 里最容易「编译通过、运行爆炸」的地带——敬畏它的内存归属，胜过背任何 API。

### 凯喵复盘：把字符串当成「有主之物」

这 14 个现场背后其实是一条主线：字符串不是抽象的值，而是**有所有者、有生命周期、有内存布局的具体对象**。C 风格 `char*` 指向只读段或某块缓冲区，`std::string` 拥有堆（或 SSO 内部）内存，`string_view` 则完全不拥有任何东西，只是别人内存上的一扇窗。凯喵带新人排查字符串 Bug 时，第一句话永远是「这串内存现在归谁管、能活到哪一行」——想清楚这个，九成的问题当场现形。

第二类高频事故来自**规模效应被忽略**：单次的 `+=`、单次 `substr` 看着无所谓，放进循环就变成 O(n²)，数据一大立刻卡死。凯喵的习惯是：凡是「字符串在循环里反复改动」的代码，先问自己有没有 `reserve`、有没有零拷贝替代、有没有把 O(n²) 退化成 O(n)。这种直觉不是背出来的，是几次线上超时事故换来的。

最后提醒一句：现代 C++ 里能用 `string_view` 做只读切片的场景非常多，但它和 `const string&` 不是一回事——前者零成本但悬垂风险高，后者安全但可能多一次构造。选型时按「生命周期是否短于源、是否只读」来定，别为了炫技无脑上 view。这条边界守住，字符串相关的半夜告警会少一大半。

### 凯喵速记：面试与实战最爱考的串

如果时间只够记三句：第一，数组作参数会退化成指针，长度信息用 `span` 或显式传；第二，`string_view` 是别人的内存上的窗，寿命必须短于源，别跨函数返回；第三，字符串拼接和切片在循环里是 O(n²) 重灾区，先 `reserve` 或改零拷贝。这三句覆盖了八成字符串面试题和九成线上字符串事故。其余的细节点，遇到时回来翻这 14 个现场，照着对号入座即可，不必硬背。

最后留一段给真正会动手的人：把上面这些现场亲手敲一遍，比读十遍都管用。亲手改坏一个字符、放开一个越界下标、让拼接在十万次循环里跑一跑，亲眼看见耗时从毫秒涨到分钟，亲眼看见视图在临时对象析构之后读出乱码，那种触电感才会变成真正的肌肉记忆。调试器里盯着指针的地址与长度，比任何口诀都更能让你记住这块内存归谁、它能活到哪一行。写字符串代码时养成三个小动作：动笔前先想清楚数据归谁，循环前先估一下复杂度，交付前先跑一遍空串、超长串、含零字节的边界用例。这三个动作不需要天赋，只需要日复一日的坚持，坚持久了，字符串相关的半夜告警自然会离你越来越远。
