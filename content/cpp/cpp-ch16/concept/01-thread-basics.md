# 01 · std::thread：启动、join/detach 与数据竞争

## 一、理论根基：线程到底是什么，为什么要它

线程是**操作系统调度的最小执行单元**，同一进程内多个线程**共享地址空间**（堆、全局、打开的文件），但各有独立栈。多核时代，线程是榨干硬件并行度的唯一手段。

- **第一性原理**：并发的正确性不来自「多个线程同时跑」，而来自**对共享状态的受控访问**。线程本身不难，难的是「共享可变状态」。
- **内存模型（happens-before）**：C++11 引入形式化内存模型。若操作 A **happens-before** 操作 B，则 B 必能看到 A 的写。线程间没有同步原语时，**不存在 happens-before**，读写顺序完全不可预测——这就是数据竞争（data race），属于**未定义行为（UB）**。

## 二、实现机制：std::thread 背后发生了什么

```cpp
std::thread t(f, arg);   // 1) 构造即启动（不像 pthread_create 分开）；2) 把 arg 按值拷贝进线程
t.join();                // 阻塞当前线程，等待 t 结束并回收资源
// 或 t.detach();        // 脱离：t 在后台自生自灭，结束后由 runtime 回收
```

- **析构铁律**：`std::thread` 析构时，若仍是 `joinable()`（既没 join 也没 detach），标准规定 **`std::terminate()`**——直接崩。所以「启动线程后必须 join 或 detach 之一」。
- **按值传参**：线程函数参数被**拷贝**（或移动）到新线程栈，引用需 `std::ref`。这是 data race 的第一来源：把局部变量引用传进去，线程还没跑完，变量已销毁 → 悬垂。

## 三、工程实践：程序员视角的取舍

- 优先 `join`（可预测的资源回收），`detach` 仅在「守护型后台任务、且生命周期明显长于主线程」时使用，且要**确保被引用的对象活得够久**（常配合 `shared_ptr`）。
- 用 RAII 包装 thread（如 `jthread`），避免忘记 join 导致 terminate。
- 共享状态要么**不共享**（各线程独立，最后汇总），要么用 mutex/atomic 保护。

## 四、边界与陷阱

- **忘记 join/detach → terminate**（pitfalls 第 1 条）。
- **按值捕获/传引用导致悬垂**：`std::thread t([&](){ use(local); });` 若 t 晚于 local 析构则 UB。
- **数据竞争未保护 `++`**：`counter++` 不是原子的（读-改-写三步），多线程下会丢失更新，结果不确定（见 examples 对比）。

## 五、可运行示例（见 examples/ex01-thread-join.md 对应 ex01）

```cpp
#include <iostream>
#include <thread>
#include <vector>

int main() {
    std::vector<std::thread> ts;
    for (int i = 0; i < 3; ++i)
        ts.emplace_back([i]{ /* 各自独立工作，无共享 */ });
    for (auto& t : ts) t.join();   // 必须 join，否则 terminate
    std::cout << "all joined\n";
}
```

**输出**：`all joined`

## 三视角解析

### 🧑‍💻 程序员视角
- **`std::thread` 析构前必须 `join()` 或 `detach()`**，否则 `std::terminate`——这是最常见的崩溃来源。C++20 的 `std::jthread` 析构自动 join，可直接替代。
- **传参默认按值拷贝**：要传引用必须 `std::ref(x)`（否则会拷贝一份，改动无效）；lambda 捕获引用要注意**被捕获对象的生命周期**（异步场景易悬垂）。
- **`++` 不是原子的**：多线程累加必须用 `std::atomic` 或加锁，否则数据竞争导致结果丢失更新（可能少算很多）。

### 🎓 博士生视角
- 数据竞争的定义是「**两个线程并发访问同一内存位置、至少一个写、且无同步**」，后果是**未定义行为（不是「结果不确定」这么温和）**——编译器可据此做激进优化。
- `join` 的语义是**建立 happens-before 关系**：子线程所有写操作对 join 之后的代码可见。这是 C++ 内存模型里「同步点」的最小例子。
- `std::thread` 是 **1:1 映射到 OS 线程**（无 M:N 调度），因此创建成本约等于 `pthread_create`（微秒级 + 栈内存），线程池的存在正是为了摊薄这个成本。

### 📚 考研者视角
- 408 进程/线程考点：**线程共享进程资源（地址空间、fd、信号处理），但各有独立栈与寄存器**；切换开销小于进程。
- 常考辨析：**进程通信（管道/共享内存/消息队列/信号/socket）vs 线程通信（共享内存 + 同步）**。
- 记忆锚点：**`join` = 等待并建立同步点**；**未同步的共享写 = 数据竞争 = UB**。
