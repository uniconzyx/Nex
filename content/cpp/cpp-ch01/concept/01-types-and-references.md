# 变量、类型与引用

C++ 是静态强类型语言：每个变量在编译期就有确定类型。类型不是给编译器看的装饰，它同时决定了三件事——**这段内存占多少字节、这些字节允许参与哪些运算、运算结果如何解释**。理解了这一点，"为什么 `-1 > 0u` 成立""为什么 `double avg = sum / n` 会丢小数"这类问题就不再是记忆题。

## 一、类型决定了什么

- **宽度与对齐**：`int` 在主流平台是 4 字节、`double` 是 8 字节；`sizeof` 是编译期常量，但**具体数值由实现决定**，标准只保证 `sizeof(char)==1` 与最小宽度。
- **值域与符号语义**：`int` 与 `unsigned int` 宽度相同、解释不同。无符号的"回绕"是定义良好的模运算，有符号溢出则是**未定义行为**（编译器可以假设它不发生，从而做出让程序员意外的优化）。
- **可参与的操作集**：指针能解引用、数组能退化、类类型能调用成员函数。类型系统在编译期挡掉的错误，运行时就不用再检查。
- **重载与模板的匹配资格**：函数重载决议、模板特化的选择，全部建立在"实参的静态类型"之上，而不是运行时的真实对象。

## 二、初始化的四种写法不是同义词

### 拷贝初始化、直接初始化、列表初始化、值初始化

```cpp
int a = 42;        // 拷贝初始化
int b(42);         // 直接初始化
int c{42};         // 列表初始化（C++11）
int d{};           // 值初始化 → 0
```

四种写法对内置类型几乎无差别，对类类型却有实质区别：拷贝初始化要求类型可隐式转换且**不允许用 explicit 构造**；直接初始化允许；列表初始化**禁止窄化转换**（`int x{3.14}` 直接编译失败），因此它是现代 C++ 推荐默认。

更隐蔽的是**默认初始化的分叉**：

```cpp
int g;             // 命名空间作用域：静态存储期，零初始化 → g == 0
void f() {
    int x;         // 局部变量：默认初始化 → 值不确定（垃圾值）
    static int s;  // 静态局部：零初始化 → s == 0
}
```

同一句 `int x;` 在函数内和函数外语义完全不同。这是无数"偶发崩溃"的源头，也是为什么工程规范要求**变量声明即初始化**。

### 窄化转换与整型提升

内置类型的二元运算遵循"先提升、再转公共类型"：`char`/`short` 先提升为 `int`；`int` 与 `unsigned` 相遇时，`int` 被转成 `unsigned`。于是 `-1 > 0u` 为真——`-1` 被解释成 `4294967295u`。这类规则在循环边界上尤其危险：

```cpp
for (int i = 0; i < v.size(); ++i)   // v.size() 是 size_t（无符号）
```

当 `v.size()` 超过 `INT_MAX` 时 `i` 永远追不上；更常见的是 `i` 为负数时与无符号比较得到意外结果。现代写法是 `for (std::size_t i = 0; ...)` 或直接用范围 for。

```text
窄化发生的位置（编译期可查 vs 运行期静默）

  int x{3.14}        → 编译错误（列表初始化禁止窄化）   ✔ 早发现
  int x = 3.14       → 编译通过，x == 3，无任何提示     ✘ 静默
  int x = big_long   → 实现定义，可能截断高位           ✘ 静默
  double d = 1/2     → d == 0.0，整除发生在赋值之前     ✘ 静默
```

## 三、引用是别名，不是指针

`int& r = a;` 让 `r` 成为 `a` 的另一个名字。三条硬规则：**必须初始化、不可重新绑定、没有空引用**。语言层面引用**不是对象**：它没有地址、不能放进数组、不存在"引用的引用"（`int&&` 是右值引用，另一回事）。

实现上引用几乎总是一个指针，但语义差异让编译器能做更强的假设：无空引用意味着不必插空检查，不可重绑定意味着别名分析更简单。所以"引用就是语法糖"这句话在**语义**上错，在**实现**上对——混用这两种视角会导致错误的性能推断。

`const T&` 还额外获得一项能力：**绑定临时对象并延长其生命周期**到引用作用域结束。

```cpp
const std::string& s = std::string("tmp") + "!";
// 临时对象生命周期被延长到 s 离开作用域，此处安全

const std::string& bad() {
    return std::string("tmp");   // 返回引用，但被绑定的临时对象在此销毁
}                                // → 悬垂引用，未定义行为
```

区别在于：**延长只发生在"引用直接绑定到一个临时对象"时**。函数返回的是引用（而不是值），临时对象在返回语句处就已经销毁，调用方拿到的是悬垂引用。

## 四、传参怎么选：一张决策表

```text
参数传递决策表

  内建类型（int/double/指针）      → 按值 T
  只读的大对象（string/vector/自定义类） → const T&
  需要修改调用方的对象             → T&
  需要表达"可能没有"               → T* （或 std::optional<T>）
  需要转移所有权                   → std::unique_ptr<T>（移动）
  需要共享所有权                   → std::shared_ptr<T>
```

判据是**语义**而不是"快不快"：按值传递表达"我拿到一份副本，改它不影响你"；`const T&` 表达"我要看，不复制"；`T&` 表达"我要改你的"。当语义确定后，性能自然跟着来——反过来按性能选语义，就会写出"参数是 `T&` 却从不修改"这种让调用方误以为会被改的接口。

## 五、边界与陷阱

- **返回局部变量的引用**：`int& f() { int x; return x; }` 是悬垂引用，UB。
- **引用成员让类失去赋值语义**：含引用成员的类，编译器生成的 `operator=` 被定义为 deleted，因为引用不可重绑定。需要"可重置的引用"就用指针。
- **`using namespace std;` 写进头文件**：污染所有包含者的命名空间，只允许在 `.cpp` 内、且尽量限定作用域使用。
- **`std::vector<bool>` 不是普通容器**：它是位压缩特化，`&v[0]` 拿不到 `bool*`，元素不是真正的 `bool` 对象。
- **整数除法截断**：`double avg = sum / n;` 中除法先按整数算，再转 `double`。正确写法 `sum / static_cast<double>(n)`。

## 六、可运行示例：验证别名与生命周期

```cpp
#include <iostream>
#include <string>

struct Probe {
    std::string tag;
    explicit Probe(std::string t) : tag(std::move(t)) { std::cout << "ctor " << tag << "\n"; }
    ~Probe() { std::cout << "dtor " << tag << "\n"; }
};

int main() {
    int a = 1;
    int& r = a;          // r 是 a 的别名
    r = 2;
    std::cout << "a=" << a << " same_addr=" << (&a == &r) << "\n";

    {
        const Probe& p = Probe("temp");   // 生命周期延长到此作用域结束
        std::cout << "inside " << p.tag << "\n";
    }                                     // 此处才 dtor

    std::cout << "unsigned_cmp=" << (-1 > 0u) << "\n";
    std::cout << "int_div=" << (7 / 2) << " real_div=" << (7 / 2.0) << "\n";
}
```

这段程序把本章三个核心事实一次验证完：引用与原变量同地址、`const&` 延长临时对象寿命（析构发生在作用域末尾而不是语句末尾）、有符号与无符号比较、整除截断。

## 三视角解析

### 🧑‍💻 程序员视角
- 引用是**别名**：必须初始化、不可重绑定、没有「空引用」。函数参数优先用引用（`const T&`）而不是指针，除非需要表达「可空」。
- `const T&` 能绑定临时对象并**延长其生命周期**到引用作用域结束——这是「传参用 const 引用」既快又安全的原因。
- 需要「可重新指向」时才用指针；需要「所有权语义」时用智能指针。三者各司其职，别混用。
- 工程习惯：变量声明即初始化；能用 `{}` 初始化就用，让窄化在编译期炸出来。

### 🎓 博士生视角
- 标准表述是「**引用不是对象**」：它没有地址、不占存储、不能被数组化。实现上通常就是一个指针，但语言层面不承认这一点（因此无法取引用的地址、无法有引用的引用）。
- 引用与指针在 **ABI 上往往相同**，语义却关键不同：无空引用（编译器可据此做优化假设）、不可重绑定（别名分析更简单）。这解释了为什么「引用只是语法糖」的直觉会误导优化推理。
- `const T&` 绑定临时对象时的生命周期延长有一个著名例外：若绑定的是**函数返回的引用**（而非返回值），则不延长（因为临时对象在那一步根本没被创建为返回引用的对象）。
- 有符号溢出是 UB 而非"回绕"，这一点让编译器可以假设 `i + 1 > i` 恒成立，从而把某些带符号循环优化成无限循环的等价形式。这是语言规范与硬件行为的刻意背离，为的是保留优化空间。
- 与 Rust 的借用（带生命周期检查）、Java 的引用（都指向对象、可空）对比可见：C++ 把生命周期正确性**完全交给程序员**，这是它性能上限高、错误率也高的根源。

### 📚 考研者视角
- 与 408 的**间接寻址**、**指针与地址**概念直接对应；引用的实现常被描述为「const 指针的语法糖」。
- 常考辨析：引用与指针的区别（必须初始化/可重绑定/可否为空/是否参与运算）。
- 常考计算：`sizeof` 与对齐、有符号/无符号混合运算的转换结果、整除与浮点除的差异。
- 记忆锚点：**引用必须初始化、不可重绑定、不存在空引用**；**`const T&` 可绑定临时对象并延长其生命周期**；**局部 `int x;` 不初始化，全局的才清零**。
