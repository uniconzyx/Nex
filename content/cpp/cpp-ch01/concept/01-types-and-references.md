# 变量、类型与引用

C++ 是静态强类型语言：每个变量在编译期就有确定类型。

## 要点

- 基本类型：`int` / `double` / `char` / `bool`，注意整型提升与窄化转换
- `auto` 类型推导（C++11）：`auto v = std::vector<int>{1,2,3};`
- 引用是别名：`int& r = a;` 必须在定义时初始化，不可重新绑定
- 常量引用 `const T&` 是无拷贝传参的默认选择

```cpp
void touch(std::string& s) { s += "!"; }   // 原地修改
void show(const std::string& s) { /* 只读 */ }
```

---

## 三视角解析

### 🧑‍💻 程序员视角
- 引用是**别名**：必须初始化、不可重绑定、没有「空引用」。函数参数优先用引用（`const T&`）而不是指针，除非需要表达「可空」。
- `const T&` 能绑定临时对象并**延长其生命周期**到引用作用域结束——这是「传参用 const 引用」既快又安全的原因。
- 需要「可重新指向」时才用指针；需要「所有权语义」时用智能指针。三者各司其职，别混用。

### 🎓 博士生视角
- 标准表述是「**引用不是对象**」：它没有地址、不占存储、不能被数组化。实现上通常就是一个指针，但语言层面不承认这一点（因此无法取引用的地址、无法有引用的引用）。
- 引用与指针在 **ABI 上往往相同**，语义却关键不同：无空引用（编译器可据此做优化假设）、不可重绑定（别名分析更简单）。这解释了为什么「引用只是语法糖」的直觉会误导优化推理。
- `const T&` 绑定临时对象时的生命周期延长有一个著名例外：若绑定的是**函数返回的引用**（而非返回值），则不延长（因为临时对象在那一步根本没被创建为返回引用的对象）。
- 与 Rust 的借用（带生命周期检查）、Java 的引用（都指向对象、可空）对比可见：C++ 把生命周期正确性**完全交给程序员**，这是它性能上限高、错误率也高的根源。

### 📚 考研者视角
- 与 408 的**间接寻址**、**指针与地址**概念直接对应；引用的实现常被描述为「const 指针的语法糖」。
- 常考辨析：引用与指针的区别（必须初始化/可重绑定/可否为空/是否参与运算）。
- 记忆锚点：**引用必须初始化、不可重绑定、不存在空引用**；**`const T&` 可绑定临时对象并延长其生命周期**。
