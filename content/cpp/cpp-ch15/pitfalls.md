# cpp-ch15 易错点（Pitfalls）

1. **头文件里写 `using namespace std;` 污染全局**
   在 `.h` 中 `using namespace std;` 会把整个 `std` 的名字注入**每一个包含该头的翻译单元**，极易与用户/第三方名字冲突，且名字冲突可能在远离头文件处才爆发，极难定位。
   ✅ 头文件中只用**限定名**（`std::vector`）或**局部 `using` 声明**（如只 `using std::size_t;`）；`using namespace` 仅限 `.cpp` 内且作用域尽量小。

2. **ADL 意外选中别处的重载**
   当函数调用实参含用户自定义类型，编译器会把该类型所在命名空间也拉进候选集。若你在本地定义了同名函数，却因实参类型在别处而被「别人家」的重载抢先匹配，结果出乎意料。
   ✅ 调用库函数时尽量**显式限定**（`ns::foo(x)`）；或为自定义类型提供同命名空间的友元/自由函数，让 ADL 可控。

3. **匿名命名空间误当「全局可见」**
   `namespace { ... }` 内的符号是**内部链接**，只在当前 TU 存在；想跨文件共享却放进匿名命名空间，链接期会报「未定义引用」，或各 TU 各有一份、互不相等。
   ✅ 仅本文件私有逻辑才用匿名命名空间；跨 TU 共享必须放头文件 + `inline`/普通定义。

4. **`using namespace std;` 进头文件（同一坑的极端版）**
   不仅污染，还可能让某次升级 `std` 新增同名模板后**悄然改变你代码的重载决议**，导致「没改代码却编译不过/行为变了」。
   ✅ 严守「头文件禁用 `using namespace`」铁律；代码评审把这当红线。

5. **模块与头文件混用导致 ODR 问题**
   同一实体（函数/变量）若既以 `#include` 头文件形式、又以模块 `export` 形式各定义一次，会触发**单一定义规则（ODR）违反**，链接期或运行期出现重复符号/未定义行为。
   ✅ 一个符号「只走一边」：要么全部进模块 `export`，要么全部走头文件 + `inline`；迁移时整库切换，避免半模块半头。

6. **`using` 指令掩盖了名字来源，制造「幽灵冲突」**
   `using namespace A; using namespace B;` 后，`A::x` 与 `B::x` 同时存在且都是候选，后续看似无害的 `x` 会触发歧义错误，且错误位置远离引入点。
   ✅ 优先 `using A::x;`（点名引入，可快速暴露冲突）；多命名空间并存时尽量保留限定名。

7. **在头文件里写 `using namespace std;`**
   它会把「包含该头文件的所有翻译单元」的 `std` 全部打开，`count` / `distance` / `size` / `data` 这类同名函数立刻出现二义性，而且报错位置与**包含顺序**有关，极难复现。
   ✅ 头文件里用完全限定名或只引入单个名字（`using std::string;`）；`using namespace` 只放在 .cpp 的局部作用域或函数体内。

8. **把类型定义在匿名 namespace 里却放进头文件**
   匿名 namespace 的实质是「每个翻译单元一份唯一命名」，同一头文件被多个 TU 包含会得到**互不相同的类型**。一旦被 `inline` 函数或模板跨 TU 使用，就违反 ODR，链接期可能静默选中其中一份，行为随构建顺序变化。
   ✅ 头文件里用具名 namespace（必要时 `inline namespace`）或 `inline` 变量/函数；匿名 namespace 只用于 .cpp 内部的实现细节。

9. **以为 `#include` 进模块单元的内容会被自动导出**
   `export { #include "x.h" }` 不合法；模块单元里 `#include` 进来的声明默认**属于模块私有**，下游 `import` 后看不到，报「未声明标识符」。
   ✅ 用 `export module m;` 并逐条 `export` 声明；需要导出第三方头时，写一个 wrapper 模块做 `export import`；标准库优先用 `import <vector>;` 这类头单元。
10. **头文件里写 `using namespace std;`** —— 所有包含它的源文件都被污染，易与自己定义的同名符号冲突。正确写法：头文件用完整限定名 `std::`，`using` 只放源文件或函数内部。
11. **把类型定义在匿名命名空间里放头文件** —— 每个包含它的翻译单元得到一份「不同类型」，链接与行为都可能不一致。正确写法：匿名命名空间只用于源文件的内部实现，头文件里别用。
12. **头文件里定义非 inline 函数或全局变量** —— 被多个源文件包含就违反 ODR，链接报 `multiple definition`。正确写法：头文件只放声明，定义放源文件或用 `inline`。
13. **自定义运算符放错命名空间** —— ADL 只在实参类型所在命名空间查找，放错地方就报「找不到匹配的 operator」。正确写法：运算符重载与类型放在同一命名空间。
14. **模块里 `#include` 的内容以为自动导出** —— 模块单元里 `#include` 进来的声明默认是模块私有，下游 `import` 看不到。正确写法：需要导出就显式 `export`，或写 wrapper 模块做 `export import`。
15. **同一实体既 `#include` 又 `import`** —— 迁移期混用导致重复定义或符号二义。正确写法：一个实体只走一条路径，头文件包成头单元再 `import`，别两套并存。
