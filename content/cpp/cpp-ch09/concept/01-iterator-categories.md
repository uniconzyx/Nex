# 01 · 迭代器分类：算法契约与复杂度边界

## 一、理论根基：迭代器是「算法与容器之间的接口契约」

从计算机科学的视角看，**迭代器模式（Gamma 等《设计模式》）把「遍历」与「数据结构」解耦**。C++ 没有为此发明新概念，而是把它锚定到一组**递增的能力层级（concept 雏形）**：

| 类别 | 关键操作 | 代表容器 | 复杂度承诺 |
|---|---|---|---|
| 输入/输出迭代器 | `*` 读 / `++` | `istream_iterator` | 单次pass，`++` 后旧值悬空 |
| 前向迭代器 | 可多次 `++`、可相等比较 | `forward_list` / `unordered_*` | `++` 摊还 O(1) |
| 双向迭代器 | 额外支持 `--` | `list` / `map` / `set` | `--` O(1) |
| 随机访问迭代器 | `+n` / `-n` / `[]` / 随机比较 | `vector` / `deque` / `string` | 跳转 O(1) |
| 连续迭代器(C++20) | 元素在连续内存 | `vector` / `array` | 可转原生指针 |

> 设计哲学：**算法只要求「刚好够用」的迭代器范畴**。例如 `std::sort` 要求随机访问迭代器——因为它需要 `O(1)` 跳跃来原地 `partition`；`std::list` 没有提供随机访问，所以它自带成员函数 `list::sort`（基于归并，不能调 `std::sort`）。

## 二、实现机制：范畴如何被编译器强制（concept 之前 vs 之后）

在 C++20 `concept` 之前，STL 用 **“鸭子类型 + 模板实例化错误信息”** 表达范畴约束：`sort` 的实现里一旦对前向迭代器使用 `it + n`，就会在实例化时报一长串模板错误。C++20 起直接用 `std::random_access_iterator` 约束入参，错误更早更可读。

从硬件视角，**随机访问迭代器对应「指针算术」**：`it + k` 就是 `ptr + k * sizeof(T)`，是单条 `lea` 指令；而双向/前向迭代器只能靠 `++` 一步步走——这正是「为什么 `vector` 的 `sort` 比 `list` 的归并 `sort` 通常更快」的硬件层原因：更好的局部性 + 无节点指针跳转。

## 三、工程实践：程序员视角的取舍

- **优先用 `auto` 让编译器选迭代器类型**，少手写 `vector<int>::iterator`。
- **不要用 `>` 这类「大于」比较来 sort 随机访问容器之外的结构**——很多算法只要求双向，比较只支持 `==`。
- **`begin()/end()` 与范围 for 本质就是迭代器契约的两个端点**；C++17 的 `std::begin`/`std::end` 对原生数组也适用。

## 四、边界与陷阱

- **失效（invalidation）是迭代器最大的灰色地带**：`vector` 扩容后所有迭代器失效；`list` 只失效被删节点；`map` 删除只失效该节点（见 `pitfalls.md` 与 `examples/ex09`）。
- 输入迭代器**只能读一次**（如 `istream_iterator`），再次解引用结果未定义——这是「单遍」语义。

## 五、可运行示例：迭代器范畴差异（编译期可观察）

```cpp
#include <iostream>
#include <vector>
#include <list>
#include <iterator>
int main() {
    std::vector<int> v = {1,2,3};
    auto it = v.begin();
    std::cout << "随机访问: *(it+2) = " << *(it + 2) << '\n';  // O(1) 跳跃

    std::list<int> L = {1,2,3};
    auto lit = L.begin();
    std::advance(lit, 2);        // 双向迭代器只能一步步走（O(n)）
    std::cout << "双向迭代器 std::advance 后 = " << *lit << '\n';
}
```

**输出**：
```
随机访问: *(it+2) = 3
双向迭代器 std::advance 后 = 3
```

> 关键结论：`vector` 的 `it + 2` 是 O(1) 指针算术；`list` 必须 `std::advance` 逐步移动（O(n)），这正是范畴差异在复杂度上的直接体现。

## 三视角解析

### 🧑‍💻 程序员视角
- **越界的 end() 不能解引用**；`find` 未找到返回 `end()`，判断要用 `it != v.end()` 而非 `<`（后者仅随机访问迭代器可用）。
- 算法用「半开区间 [first, last)」：`v.begin(), v.end()` 覆盖全量，`v.begin()+1, v.end()` 覆盖第 2 个起。
- 迭代器失效规则**跟容器绑死**（vector 扩容全失效、list 只失效被删元素），写循环删除前先确认。

### 🎓 博士生视角
- 迭代器是把**「指针」一般化**的抽象：它把「解引用 / 前进 / 比较」这套运算协议化，使同一算法可作用于数组、链表、流（输入迭代器）。
- 六类迭代器构成**能力阶梯**（输入→前向→双向→随机访问→连续），算法声明所需最低类别，这是**编译期契约检查**的早期范例（早于 `concept`）。
- 复杂度约束写在标准里（如 `std::sort` 要求 O(N log N) 次比较），因此实现必须选**随机访问迭代器**；对双向迭代器只能提供 `list::sort` 的归并版本。

### 📚 考研者视角
- 408 层面：这是**遍历抽象**与**算法复用**的工程体现，与「数据结构 + 算法分离」的思想一致。
- 记忆锚点：**半开区间 [first, last)**、**`find` 失败返回 `end()`**、**`list` 不支持 `std::sort`（需随机访问迭代器）**。
- 若考 C++ 与 C 的区别：数组名退化为指针**丢失长度信息**，迭代器/范围则保留了「区间」语义，这正是 `span`/`ranges` 的设计动机。
