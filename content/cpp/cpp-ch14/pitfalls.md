# cpp-ch14 易错点（Pitfalls）

1. **宏参数不加括号导致优先级错乱**
   `#define SQUARE(x) x*x`，`SQUARE(1+2)` 展开为 `1+2*1+2=5`，而非 9。
   ✅ 每个参数与整体都加括号：`#define SQUARE(x) ((x)*(x))`。

2. **宏参数的多重求值副作用**
   即便写成 `((x)*(x))`，`SQUARE(x++)` 中 `x++` 仍会被求值两次，产生意料之外的多次自增。函数 `f(x++)` 只求值一次。
   ✅ 带副作用的实参或「像函数」的逻辑，改用 `inline` 函数或模板，保证单次求值与类型检查。

3. **多语句宏未用 do-while(0) 包裹**
   `#define F() a(); b();` 用于 `if (c) F(); else g();` 时，展开后 `else` 悬空编译失败。
   ✅ 用 `do { ... } while(0)` 把多语句包成单条复合语句，分号语义也正确。

4. **头文件缺少守卫导致重定义**
   同一头文件被多条包含路径间接包含多次，类/函数声明重复 → 编译报 redefinition。
   ✅ 每个头文件顶部加 `#ifndef HEADER_H / #define HEADER_H / #endif`，或与 `#pragma once` 并用。

5. **`#pragma once` 的局限**
   它依赖「同一物理文件」判重：符号链接、文件副本、不同包含路径可能让编译器误判为不同文件，守卫失效。
   ✅ 对强可移植性或多副本风险场景，优先传统 `#ifndef` 守卫；二者可并存。

6. **宏名与变量名/类型名冲突**
   宏是全局文本替换，若 `#define max` 之类覆盖了标准库或你自己用的名字，所有 `max` 都会被替换，引发诡异错误。
   ✅ 宏名用全大写 + 项目前缀（如 `MYLIB_MAX`）；避免定义过于通用的短名；头文件里的宏用完及时 `#undef`。

7. **在头文件中写 `using namespace std;`**
   头文件经 `#include` 被多处包含，`using namespace std;` 会把 `std` 名字注入所有包含者的全局命名空间，造成名字冲突且难以定位。
   ✅ 头文件中绝不放 `using namespace`；源文件里也尽量只 `using` 具体名字。
