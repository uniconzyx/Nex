# 02 · 宏的卫生问题：括号、多重求值与 do-while(0)

## 一、理论根基：宏是「无类型、无作用域的 token 替换」

因为宏在预处理阶段（语法分析之前）发生，它**看不到类型、也看不到运算符优先级**。于是「看起来像函数」的宏，实则只是把实参 token 序列塞进形参位置再整体替换。这带来三类经典卫生问题。

## 二、实现机制与坑

### 1. 参数不加括号 → 运算符优先级错乱
```cpp
#define SQUARE(x) x*x
SQUARE(1+2)   // 替换为 1+2*1+2 = 5，而非期望的 9
```
✅ 每个参数与整体都加括号：`#define SQUARE(x) ((x)*(x))`。

### 2. 多重求值副作用（最危险）
即便加了括号，`#define SQUARE(x) ((x)*(x))` 中 `x` 仍出现**两次**。若实参带副作用：
```cpp
int x = 2;
int m = SQUARE(x++);   // 替换为 ((x++)*(x++))：x 自增两次，m=6, x=4
```
相比真正的函数，`f(x++)` 中 `x++` 只求值一次。宏会让**副作用发生多次**，结果既依赖求值顺序又难以调试。
✅ 这种场景必须用 `inline` 函数或模板：`inline int square(int x){ return x*x; }`——参数只求值一次，且带类型检查。

### 3. 多语句宏未包裹 → if/else 断裂
```cpp
#define LOG() std::cout<<"a\n"; std::cout<<"b\n"
if (cond) LOG(); else foo();   // 展开后 else 悬空，编译失败
```
✅ 用 `do { ... } while(0)` 把多语句包成**一条复合语句**，末尾的分号语义也正常：
```cpp
#define LOG() do { std::cout<<"a\n"; std::cout<<"b\n"; } while(0)
```

## 三、`#` 与 `##` 运算符

- `#x`（字符串化）：把参数变成字符串字面量。`STR(hello)` → `"hello"`。
- `a##b`（记号拼接）：把左右 token 拼成新标识符。`CONCAT(my,Var)` → `myVar`。
- 注意：若参数本身也是宏，`#`/`##` 会**阻止其先展开**——需要「双层间接宏」（`#define STR2(x) #x` + `#define STR(x) STR2(x)`）才能先展开参数再字符串化。

## 四、工程实践：宏与 inline 的取舍

| 维度 | 宏 | inline 函数 |
|---|---|---|
| 类型检查 | 无 | 有 |
| 参数求值 | 可能多次（副作用陷阱） | 一次 |
| 调试/符号 | 无（展开即消失） | 有（可设断点、可重载） |
| 能做而函数不能 | 字符串化、记号拼接、条件编译相关 | — |
| 适用 | 日志宏、断言、X-Macro、跨类型泛型（C 时代） | 绝大多数「像函数」的逻辑 |

> 现代 C++ 准则：**能用 `constexpr`/`inline`/模板解决，就不要写宏**。宏仅保留在「函数做不到」的地方（如 `__FILE__`/`__LINE__` 日志、`#`/`##` 元编程、条件编译开关）。

## 五、可运行示例：括号、多重求值、do-while

```cpp
#include <iostream>
#define SQUARE(x) x*x
#define SAFE(x) ((x)*(x))
#define LOG() do { std::cout << "a\n"; std::cout << "b\n"; } while(0)
int main() {
    std::cout << SQUARE(1+2) << '\n';     // 5（优先级错）
    std::cout << SAFE(1+2) << '\n';       // 9（正确）
    int x = 2;
    std::cout << "m=" << SAFE(x++) << " x=" << x << '\n';  // 副作用两次
    if (false) LOG(); else LOG();          // do-while 包裹后合法
}
```

**输出**：
```
5
9
m=6 x=4
a
b
```
> 观察点：① 不加括号的 `SQUARE(1+2)` 算出 5；② 加了括号也得注意 `SAFE(x++)` 仍让 `x++` 求值两次（`x` 变成 4）；③ `do{}while(0)` 让多语句宏可安全用于 `if/else`。

## 三视角解析

### 🧑‍💻 程序员视角
- **宏参数必须整体加括号**：`#define SQ(x) ((x)*(x))`；否则 `SQ(a+b)` 展开成 `a+b*a+b` 结果错。
- **避免多重求值**：`#define MAX(a,b) ((a)>(b)?(a):(b))` 中 `a` 被求值两次，传 `i++` 就是 UB——这种场景用 `inline` 函数或 `std::max`。
- **多语句宏用 `do { ... } while(0)` 包裹**：否则 `if (cond) MACRO(); else ...` 会因分号问题编译失败。

### 🎓 博士生视角
- 宏卫生问题的根源是**「文本替换 + 无作用域」**：宏不遵守词法作用域，其展开结果在**调用点的语法上下文**中重新解析，因此括号、分号、优先级全都可能被上下文改变。
- `do{}while(0)` 惯用法的作用是**把多语句宏包装成「单个语句」**，使其在 `if/else`、`for` 等需要单语句的位置语义正确。
- 从宏系统理论看，C 宏是**非卫生的（unhygienic）**，与 Scheme 的卫生宏形成对照——后者用重命名避免捕获，这是「宏系统设计」的经典议题。

### 📚 考研者视角
- 记忆锚点：**宏参数加括号、避免多重求值、多语句用 `do{}while(0)`**——三条几乎是「宏」考点的全部。
- 常考计算题：给宏定义 + 调用，**手写展开结果**并计算（注意运算符优先级与结合性）。
- 常考辨析：**宏与常量的区别**（宏无类型、无作用域、不占存储；`const` 有类型、可调试）。
