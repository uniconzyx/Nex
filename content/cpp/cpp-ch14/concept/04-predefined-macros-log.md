# 04 · 预定义宏与日志：__FILE__/__LINE__ 的工程用法

## 一、理论根基：预定义宏是编译器注入的「编译期常量」

C/C++ 标准与实现定义了一组**预定义宏（predefined macros）**，由编译器在预处理阶段直接提供，无需 `#define`：

| 宏 | 含义 |
|---|---|
| `__FILE__` | 当前源文件名（常为相对/绝对路径） |
| `__LINE__` | 当前行号（整数） |
| `__func__`（C99/C++11） | 当前函数名（注意不是宏，是隐式局部变量） |
| `__DATE__` / `__TIME__` | 编译日期 / 时间 |
| `__cplusplus` | 语言标准版本号（C++17=201703L，C++20=202002L） |
| `__STDC_VERSION__` | C 标准版本 |

> 第一性原理：这些宏在**预处理/编译期**就被替换为字面量，因此可参与字符串拼接、`static_assert`、模板非类型参数等编译期机制，且不产生运行期开销。

## 二、实现机制：日志宏如何「携带位置信息」

把 `__FILE__` 与 `__LINE__` 包进一个宏，就能在**任何调用点**自动记录「这条日志来自哪个文件哪一行」，这是几乎所有 C/C++ 日志库（spdlog、glog）的基础：

```cpp
#define LOG(msg) \
    std::cout << __FILE__ << ":" << __LINE__ << " " << msg << '\n'
```
因为宏在**调用处**展开，`__LINE__` 自然解析为调用所在行，而非宏定义所在行——这正是它比手填行号可靠的原因。

**进阶卫生写法**：为了支持「流式输出 `LOG("x=" << x)`」且保证单条表达式、可被 `if` 安全使用，常配合 `do{}while(0)` 与 `std::ostream`：
```cpp
#define LOG(stream_expr) do { \
    std::cerr << __FILE__ << ":" << __LINE__ << " " << stream_expr << std::endl; \
} while(0)
```

> 注意：`__FILE__` 在很多编译器下是**完整路径**，会使日志冗长。生产日志库通常用 `#define STRINGIZE(x) #x` + 编译期选项，或运行时 `basename()` 裁剪；也可通过 `-D` 传入短模块名。

## 三、工程实践：调试开关与版本信息

- **调试开关**：`#ifdef NDEBUG` 关闭断言/调试日志；发布构建定义 `NDEBUG` 是惯例。
- **版本与平台分支**：`#if __cplusplus >= 202002L` 启用 C++20 特性；`#ifdef _WIN32` / `__linux__` 做平台适配。
- **编译期指纹**：把 `__DATE__`/`__TIME__` 拼进版本字符串，便于确认二进制对应的源码时刻。

## 四、边界与陷阱

1. `__FILE__` 带路径，日志可能泄露绝对路径（安全/隐私考量）。
2. 宏展开后 `__LINE__` 是**整数字面量**，想拼进字符串需借助字符串化（`#`）或 `std::to_string`。
3. 频繁用 `std::endl`（flush）的日志宏会拖慢性能，调试期可接受，热路径应避免。

## 五、可运行示例：位置感知日志宏

```cpp
#include <iostream>
#define LOG(msg) std::cout << __FILE__ << ":" << __LINE__ << " " << msg << '\n'
int main() {
    LOG("start");
    LOG("done");
}
```

**输出**（路径随编译命令而变，文件名部分固定）：
```
c14_ex07.cpp:4 start
c14_ex07.cpp:5 done
```
> 观察点：`__LINE__` 解析为**调用处**的行号（4、5），而非宏定义行；这正是日志宏能精准定位现场的原因。

## 三视角解析

### 🧑‍💻 程序员视角
- **`__FILE__`/`__LINE__`/`__func__` 是日志三件套**：把「文件:行号:函数」打进日志，排查线上问题时价值极高（比后加断点快得多）。
- 落地写法：日志宏用 `do{}while(0)` 包裹，并把 `__FILE__`、`__LINE__` 作为参数传给真正函数，避免宏展开的副作用。
- `__func__` 是**变量不是宏**（它是函数内的静态字符数组），所以能正常参与作用域与类型检查。

### 🎓 博士生视角
- 预定义宏由**编译器在预处理阶段注入**，值是**编译期常量字符串/整数**，因此零运行时代价（`__LINE__` 只是编译期替换的字面量）。
- `__FILE__` 的具体值**依赖编译命令的路径写法**（相对/绝对），这导致不同构建系统下日志中的路径不一致——工程上常用 `-ffile-prefix-map` 做路径归一化。
- 从设计看，这类宏是「**把编译环境信息暴露到运行时**」的最小接口；它无法被普通函数替代（普通函数拿不到调用点的行号），这正是宏不可被完全淘汰的原因之一。

### 📚 考研者视角
- 记忆锚点：**`__FILE__`/`__LINE__` 是预定义宏，编译期替换**；**`__func__` 是预定义标识符（变量）不是宏**。
- 常考辨析：宏不可替代的场景——**需要调用点上下文（行号/文件名）**时，函数做不到、宏才能做到。
- 与调试章节对照：日志里的**行号**使「二分定位」成为可能，这是调试方法论（ch19 工程化）里的基础手段。
