# 02 · 缓存层次、局部性与 false sharing

现代 CPU 的访存瓶颈不在「算得快不快」而在「数据到不到得了」。本主题先讲清缓存的作用方式，
再聚焦最隐蔽的性能杀手——伪共享。

## 一、缓存层次与局部性（locality）

**中立陈述**：CPU 访存走 **L1 → L2 → L3 → 主存**的层次，容量递增、延迟递增。
数据在层次间以**缓存行（cache line，主流 64 字节）**为单位搬运。程序若具备：
- **时间局部性**：刚访问过的数据很快再被访问（如循环变量、热表）；
- **空间局部性**：访问某地址后紧接着访问其附近地址（如数组顺序遍历）；
就能命中上层缓存，把主存访问藏起来。此外，**硬件预取器**会识别顺序/固定步长访存模式，
提前把下一行拉进缓存——这正是「连续遍历比跳跃遍历快」的物理原因。

### 🧑‍💻 程序员视角
- **工程决策树**：循环优化先看访存模式（顺序？步长？），再看数据规模是否超过末级缓存工作集。
  工作集超过 L3 时，随机访问会让每次访问都打到主存，比顺序访问慢一个数量级。
- **可操作的改法**：① 交换循环次序让内层走连续内存；② 分块（tiling/blocking）把工作集切到
  缓存装得下；③ 把「只用一个字段」的 AoS 改成 SoA；④ 用扁平数组替指针图。
- **不要靠墙钟断言**：本机 `clock()`/`chrono` 抖动极大，且受频率调节/其它进程影响。
  教学与自测一律用**确定性判据**：缓存行未命中计数（自写缓存模型）、指针跳转次数、布尔结论。

### 🎓 博士生视角
- **为什么是 64 字节**：一次 DRAM 猝发（burst）与一条缓存行的容量对齐，可在一条总线事务内
  填满整行；行太小则空间局部性收益不足，太大则替换代价与伪共享概率上升。64B 是成本-收益的平衡点。
- **延迟量级（数量级，非精确）**：寄存器 <1ns，L1 约 4 周期，L2 约 12 周期，L3 约数十周期，
  主存约 200+ 周期。理解这一点就能明白：**减少缓存未命中的收益远大于微优化指令数**。
- **关联度与冲突**：缓存按组相联组织，直接映射缓存中「地址相差整数倍行长」的两次访问会争用同一组，
  产生**冲突未命中**——这也是列优先遍历矩阵（步长正好跨若干行）代价极高的机制之一。

### 📚 考研者视角
- **408 计算机组成原理考点**：Cache 的三种映射方式（直接/全相联/组相联）、
  替换算法（LRU/FIFO）、写策略（写直达/写回）、**命中率与平均访问时间计算**。
- **常考口径**：`平均访存时间 = 命中时间 + 缺失率 × 缺失代价`；给定地址位数、块大小、
  组数算「主存地址 → 标记/组号/块内偏移」的划分。
- **易混点**：Cache **按块（行）交换**、主存按字节编址；「时间局部性/空间局部性」是
  程序性质而非缓存结构；命中率与缺失率互补。

## 二、false sharing：成因、复现与消除

**中立陈述**：**伪共享**指多个线程**各自**修改**不同**变量，但这些变量恰好落在**同一条缓存行**上。
每次写都要把整行在所有核心间搬运以维持一致性，于是两个线程虽然不共享数据，却被迫**竞争同一条行**，
吞吐急剧下降。**结果依然正确**——这是纯粹的性能问题（这一点决定了对策：不是加锁，而是**让变量分行**）。

消除手段：
- `alignas(64)` 把每个热点变量对齐到独立缓存行；
- 用 `std::hardware_destructive_interference_size` 做可移植的间距；
- 结构体里插入填充成员把后继变量推到下一行。

**确定性判据**（examples/ex09 实测）：两原子变量放在 `alignas(64)` 结构体内（偏移 0 与 8）
→ 「同一缓存行: 1」；用填充把它们推到偏移 0 与 64 → 「同一缓存行: 0」。
缓存行迁移模型计数：同一行 **2000000** 次迁移，对齐后 **2** 次。

### 🧑‍💻 程序员视角
- **上线事故**：多线程计数器数组 `struct Counter{ long v; };` 相邻排布，线程各写一个元素，
  结果「加线程反而更慢」。原因就是 64 字节内塞了 8 个计数器，8 个核心互相踩同一行。
  修法：每个计数器 `alignas(64)`（或每 8 个一组）。
- **排查顺序**：① 用 `perf c2c` / 缓存未命中指标确认是否 coherence 相关；
  ② 打印变量地址判断是否同行；③ 加 `alignas` 隔离；④ 用计数/布尔判据验证隔离生效。
- **权衡**：padding 会**浪费内存**（每个计数器占 64B）。只有**高频写**的热点才值得；
  读多写少或低频变量不值得，盲目 padding 反而降低缓存密度、得不偿失。

### 🎓 博士生视角
- **一致性协议视角**：x86 用 MESI 系协议，核心要写某行须先取得该行的**独占/修改**状态，
  这会**使其它核心的副本失效**。伪共享的本质是「**行**的粒度远大于**变量**的粒度」——
  一致性以行为单位，而程序语义以变量为单位，两者错位即产生虚假竞争。
- **与数据竞争的区别（形式化）**：数据竞争是「两个线程对同一内存位置的访问存在无同步的冲突」，
  属**未定义行为**；伪共享是「对**不同**位置的访问在缓存行层面冲突」，属**性能退化**，
  程序语义完全确定。混为一谈会开错药方。
- **量化**：伪共享下单次写的有效代价 ≈ 一次缓存行所有权转移（数十到上百周期），
  比 L1 命中高 1~2 个数量级；退化倍数随核心数增长——这正是它在大核数服务器上尤其致命的原因。

### 📚 考研者视角
- **408 操作系统/组成原理考点**：Cache 一致性（MESI/嗅探协议）、**总线仲裁**、
  多核共享数据的一致性维护；「写回」与「写直达」对一致性的影响。
- **常考口径**：一致性的**基本单位是缓存行**；「写使其它副本失效」（write-invalidate）是主流策略；
  伪共享是 write-invalidate 协议的**副作用**。
- **易混点**：伪共享 ≠ 数据竞争（前者正确后者 UB）；伪共享 ≠ 真共享
  （后者线程确实读写同一变量，需要同步）；`volatile` 既不解决数据竞争也不解决伪共享。
