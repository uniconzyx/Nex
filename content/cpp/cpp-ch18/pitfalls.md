# cpp-ch18 易错点（Pitfalls）

1. **把带填充的结构体直接 memcpy/memcmp** —— 填充字节是**未初始化内存**，`memcmp` 结果不确定，
   `memcpy` 到网络会泄漏栈上残留数据且跨平台不可读。
   ✅ 显式逐字段序列化；或用 `#pragma pack(1)` 并固定字节序；比较时逐字段比较。

2. **对含 `std::atomic` / SIMD / 指针的"业务结构体"用 `#pragma pack(1)`** —— 会把成员推到**未对齐地址**，
   原子操作可能失效、SIMD 访存可能崩溃。
   ✅ `pack` 只用于纯数据协议结构；对齐敏感的成员要么不 pack，要么逐字段拷贝进 packed 结构。

3. **以为 `alignas` 可以降低对齐** —— `alignas(N)` 只能**抬高**对齐（N 不小于自然对齐）；
   想降低只能靠 `#pragma pack` 或改成员类型。
   ✅ 记住方向：`alignas` 抬、`pack` 降，二者作用于不同层级。

4. **以为字段重排总能减小 sizeof** —— 重排只能消除**内部/尾部填充**；若成员本无填充（如全是
   `int`）则毫无收益，还会**破坏 ABI**（已发布的二进制接口不能重排）。
   ✅ 先实测 `sizeof` 与偏移再决定；对外接口的结构体一旦发布就不许重排。

5. **把 false sharing 当成数据竞争** —— 伪共享**结果正确**，只是性能问题；加锁/原子**解决不了**它。
   ✅ 对策是**让变量分处不同缓存行**（`alignas(64)` / 填充 / `hardware_destructive_interference_size`）。

6. **给结构体加 `alignas(64)` 就以为两个成员分行了** —— `alignas` 只管**结构体起始地址**，
   成员间距要靠**填充成员**。实测：同一 `alignas(64)` 结构内偏移 0 与 8 的两个变量仍在同一行。
   ✅ 要分行就把后继成员推到偏移 ≥64（插 `char pad[...]`），并用地址判据验证。

7. **用墙钟时间/耗时做性能断言** —— 本机 `clock()`/`chrono` 抖动极大，受频率调节与其它进程影响，
   结论不可复现。
   ✅ 一律改用**确定性判据**：`sizeof`/`offsetof`、操作计数、缓存行未命中计数、布尔结论，
   并注明「定性结论，具体数值依机器而定」。

8. **以为 `inline` 是"强制内联"** —— `inline` 的本义是**允许多 TU 定义**（ODR 例外）并暗示内联；
   是否内联由优化器决定。想强制用 `always_inline`，但仍可能被拒绝。
   ✅ 想加速就开 `-O2`；`inline` 主要用于头文件里的函数定义。

9. **以为 `final` 一定会去虚化** —— 只有编译器能**证明动态类型唯一**时才去虚化；
   通过没有 `final` 的基类指针/引用调用，仍走虚表。
   ✅ 热路径上确定不再派生才标 `final`；配合 `-O2`（及 `-flto`）观察是否消除虚调用。

10. **以为 `[[likely]]`/`[[unlikely]]` 会改变程序语义** —— 它只是分支提示，影响布局与预测命中率，
   不改变任何结果；标反了只影响性能甚至更慢。
    ✅ 只在"确实高度偏斜"的分支上标注，且以 profile 数据为依据。

11. **跨模块/跨语言直接传 `std::string` / `std::vector`** —— 其布局是标准库实现细节，
    不同编译器/标准库/`_GLIBCXX_USE_CXX11_ABI` 都不同，会崩溃或内存损坏。
    ✅ 跨边界只传 `extern "C"` 的 POD 或不透明指针 + C 风格函数接口。

12. **忘记 `extern "C"` 导致 C 端链接不到符号** —— C++ 名字被修饰（如 `_Z3addii`），
    C 代码按未修饰名查找必然失败。
    ✅ 供 C/其它语言调用的接口加 `extern "C"`，头文件用 `#ifdef __cplusplus` 包裹。

13. **以为所有空类都能被优化掉（EBO 万灵）** —— 同类型的两个子对象**不能有相同地址**，
    故「同类型空基类 ×2」或「空类成员与同类型基类并存」时 EBO 失效，各占至少 1 字节。
    ✅ 需要零尺寸成员用 C++20 `[[no_unique_address]]`；注意**同类型多个成员仍不能重叠**。

14. **认为 `std::vector` 一定比链表快、或只按复杂度选结构** —— 二者遍历都是 O(n)，
    实差在**访存层级**；反之在「频繁中间插入 + 元素巨大」时链表可能更合适。
    ✅ 默认优先 `std::vector`（连续性/缓存友好/可向量化），确有不适合之处再用其它结构，
    并以实测（计数/判据）而非直觉定夺。
