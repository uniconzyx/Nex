# cpp-ch07 易错点（Pitfalls）

1. **模板声明与定义分离到不同文件导致链接错误（undefined reference）**
   把函数/类模板的**定义**放进 `.cpp`、声明放进 `.h`，别的翻译单元 `#include` 后使用时，实例化点看不到定义，链接报 `undefined reference to `f<int>(int)` `。
   ✅ 模板定义应放在头文件（**包含模型**）；若坚持分离，需在 `.cpp` 用 `template void f<int>(int);` 显式实例化导出。

2. **依赖名前漏写 `typename` / `template` 关键字**
   在模板里写 `T::value_type x;` 或 `c.push_back<X>(...)`（其中 `T`/`c` 类型依赖模板参数）会编译错：编译器默认依赖名不是类型、`<` 不是模板参数列表。
   ✅ 嵌套依赖类型名前加 `typename`（`typename T::value_type`）；成员模板调用前加 `template`（`c.template push_back<X>(...)`）。

3. **模板特化优先级理解错导致选中错误版本 / 歧义**
   偏特化之间若存在"无可比特化关系"的重叠，或全特化晚于主模板却未被优先选中，会选错或报歧义。
   ✅ 记牢顺序：**全特化 > 越具体的偏特化 > 主模板**；偏序规则是"能把 A 的参数代入 B、反之不行，则 B 更特化"。避免写出无法比较的重叠偏特化。

4. **误入"非推导上下文"却指望自动推导**
   `template<class T> void f(typename Traits<T>::type);` 中 `T` 嵌套在依赖类型里，**无法从实参推导**，调用必须显式 `f<int>(...)`；否则报"无法推导模板参数"。
   ✅ 把需要推导的参数放在"非嵌套"位置；或在调用处显式指定模板实参。

5. **跨类型调用函数模板时推导冲突硬报错**
   `my_max(3, 2.5)` 一边 int 一边 double，两个参数要推出同一 `T` → 冲突 → 编译错误。
   ✅ 显式指定 `my_max<double>(3, 2.5)`，或封装一层转为同类型，或用 `auto`/公共类型（`std::common_type_t`）。

6. **SFINAE 误用：约束放在函数体内而非签名位置**
   把 `enable_if` 检查写进函数体，类型不满足时不是"候选出局"，而是**直接硬错误**；且两个 `enable_if` 条件若不互斥会**歧义**。
   ✅ 把 `enable_if`/`requires` 放在**返回类型或默认模板参数**等签名位置；条件务必互斥；优先用 C++20 `concept` 替代 `enable_if`。

7. **模板错误信息爆炸（代码膨胀 + 实例化链嵌套）**
   深度嵌套模板（如 `std::vector<std::map<...>>`）一旦实例化失败，编译器吐出几十层 `in instantiation of ...` 栈，定位困难。
   ✅ 用 `static_assert` + concept 在入口给出"人话"约束；缩小模板接口、把非依赖逻辑抽成非模板函数；善用 `-fsyntax-only` 与编译器缩写（GCC/Clang 的 `{%raw%}` 概念诊断）。

8. **以为模板是"运行时多态"，滥用导致二进制膨胀**
   把本可用 `virtual` / `std::function` 的类型分发硬写成大量类模板特化，导致每类型一份代码、二进制变大、编译变慢。
   ✅ 能用运行期多态（接口稳定、类型集开放）就用虚函数；模板适合"类型集在编译期已知、要零开销"的场景；必要时用类型擦除（`std::function`/`any`）折中。
