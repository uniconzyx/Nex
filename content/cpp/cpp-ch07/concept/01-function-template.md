# 01 · 函数模板：类型参数化、实参推导与重载决议

## 一、理论根基：模板解决的到底是什么问题

**泛型编程（Generic Programming）的第一性原则是"代码复用的最小重复单元是算法，而非类型"**。
在没有模板之前，要写"对任意类型 T 都成立的 max"，只能：

- 用宏：`#define MAX(a,b) ((a)>(b)?(a):(b))` —— 文本替换，无类型安全、多次求值（`MAX(++i, j)` 灾难）、无作用域；
- 用 `void*` + 回调：丧失类型信息，调用方强制转换，易错。

函数模板把"**类型**"提升为**编译期参数**：

```cpp
template <typename T>
T my_max(T a, T b) { return a > b ? a : b; }
```

它的本质是：**模板本身不是函数，而是一个"函数工厂的配方"**。只有当编译器拿到具体实参、推断出 `T` 后，才会**实例化（instantiate）**出一份真实的 `int my_max(int,int)` 机器码。`my_max` 这个名字在源码里存在，但**目标文件中并没有"模板函数"这一实体**，只有被实例化出来的各个具体版本（见 §四 代码膨胀）。

> 对比 Java 泛型：**Java 的泛型是类型擦除（type erasure）**——`List<Integer>` 与 `List<String>` 在运行时是**同一份 `List` 字节码**，类型参数被擦成 `Object`，仅由编译器插入强制转换保证类型安全。C++ 模板则在编译期**生成不同的真实函数/类**。这是二者性能、表达力与错误信息风格差异的根本来源（详见 §五）。

## 二、实现机制：模板实参推导（Template Argument Deduction）

调用 `my_max(3, 7)` 时，编译器要做**实参推导**：

1. 对每个函数参数 `T a`，从对应实参 `3`(int) 推断出 `T = int`。
2. **多个参数必须推导出同一个 T**，否则推导失败：`my_max(3, 2.5)` → 一边 int 一边 double → 推导冲突 → 编译错误（除非用转换或显式指定）。
3. 推导只看**函数参数**，不看返回类型；`auto x = my_max(3, 7)` 的 `auto` 不影响推导。

**推导的"非推导上下文（non-deduced contexts）"**是高频考点：以下位置不参与推导，必须显式给出：
- 默认实参里出现的参数：`template<class T> void f(T = 0, T* = nullptr);` 第二个 `T*` 无法从默认实参推导；
- 函数参数中"被另一模板参数包住"的位置：如 `template<class T> void f(typename Traits<T>::type);` 的 `T` 在嵌套类型里，**不能**从实参推导（必须在调用时显式 `<T>`）；
- 数组到指针退化时：`template<class T> void f(T, T*)`，传入 `int[3]` 会退化但形参长度信息丢失。

**显式指定模板实参**可覆盖推导：`my_max<double>(3, 2.5)` 强制 `T=double`，两实参都转 double。这在实参与模板参数不直接对应时必需（如 `std::forward<T>`、`std::make_shared<T>(args...)` 的 `T` 无法从参数推出）。

## 三、实现机制：重载决议（Overload Resolution）与模板

函数模板与手写函数（以及多个模板之间）参与同一套重载决议，规则要点（来自 [over.match]）：

1. **名称查找**收集所有候选（普通函数 + 模板实例化的可行特化）；
2. **模板实参推导**：模板候选先尝试推导，推导失败则该候选直接出局（**注意：推导失败不是错误，只是该候选不参与**——这正是 SFINAE 的土壤，见 concept 03）；
3. **可行性 + 最佳匹配**：
   - **更特化（more specialized）胜出**：对于 `f(42)`，同时存在 `void f(int)`（普通）与 `template<class T> void f(T)`，普通函数被认为"更特化"，优先选中普通版本；
   - 若只剩模板候选，则**偏序（partial ordering）**：更特化的模板胜出；
   - 用 `f<>(42)` 可强制只从模板里选（禁用普通函数候选）。

这一机制是 STL 算法重载的基石：`std::swap` 有通用模板，又为 `std::vector` 等提供更优特化/重载。

## 四、工程实践：实例化成本与头文件（包含模型）

- **隐式实例化**：首次以某实参组合使用模板时，编译器才生成对应代码。因此模板的**定义必须对其所有使用者可见**——这就是"模板实现通常放头文件"的根本原因（**包含模型 / Inclusion Model**）。若把模板实现放进 .cpp，别的翻译单元看不到定义，链接时会报 `undefined reference to `my_max<int>(int,int)``。
- **显式实例化**：`template int my_max<int>(int,int);` 在某一 .cpp 中强制生成一份实例，可把模板定义留在 .cpp 并显式导出，减小头文件体积（但失去泛型透明性，工程上少用）。
- **代码膨胀（code bloat）**：每个不同的实参组合都生成一份独立机器码，`std::vector<int>` 与 `std::vector<double>` 是完全不同的类型、不同代码。缓解手段：把与类型无关的逻辑抽成非模板函数（如 `std::vector` 把内存管理委托给一个接受 `void*` 的底层实现），或用**类型擦除**（如 `std::function`）。

## 五、边界与陷阱

- 模板是**图灵完备**的：可在编译期用模板递归做任意计算（现代已被 `constexpr` 取代）。
- 推导冲突不会"默默选一个"，而是**硬报错**；务必在混合类型时显式指定 `T`。
- 模板函数的**返回类型参与不了推导**，需要推导返回类型时用 `auto`/尾置返回或 `decltype`。

## 六、可运行示例：眼见为实

```cpp
#include <iostream>

template <typename T>
T my_max(T a, T b) { return a > b ? a : b; }   // 模板：类型参数化

// 普通函数与模板同名，用于演示重载决议
void demo(int x) { std::cout << "普通函数 demo(int): " << x << '\n'; }
template <typename T>
void demo(T x)    { std::cout << "模板 demo(T): " << x << '\n'; }

int main() {
    // ① 推导：T 从实参推出
    std::cout << "my_max(3,7)=" << my_max(3, 7) << '\n';
    std::cout << "my_max(2.5,1.2)=" << my_max(2.5, 1.2) << '\n';

    // ② 显式指定 T 以解决类型不一致
    std::cout << "my_max<double>(3,2.5)=" << my_max<double>(3, 2.5) << '\n';

    // ③ 重载决议：普通函数更特化，优于模板
    demo(42);       // 选普通函数
    demo<>(42);     // 强制只选模板
    demo(3.14);     // 只有模板能匹配 double
}
```

**输出**：
```
my_max(3,7)=7
my_max(2.5,1.2)=2.5
my_max<double>(3,2.5)=3
普通函数 demo(int): 42
模板 demo(T): 42
模板 demo(T): 3.14
```

> 关键结论：① `my_max` 的 `T` 由实参唯一确定；② 跨类型调用需显式 `<double>`；③ `demo(42)` 选中普通函数（更特化），`demo<>(42)` 强制走模板——这正是重载决议与模板偏序的直观体现。

## 三视角解析

### 🧑‍💻 程序员视角
- **模板不是宏**：它在编译期做类型检查，错误信息虽然长但根因明确（多数是「实参推导失败」）。
- 落地规则：能推导就别显式写 `f<int>(x)`；需要转换时（如 `max<double>(1, 2.5)`）才显式指定——因为**推导不做隐式转换**，两种不同类型会直接推导失败。
- 工程惯例：把「对类型的要求」写进命名（如 `stable_sort` 要求可移动赋值），比写注释可靠；C++20 起优先用 `concept` 替代长串 `enable_if`。

### 🎓 博士生视角
- 实参推导本质是一次**模式匹配 + 一致性约束**：`T&` 与左值匹配、`T&&` 是转发引用（可绑定左值也可绑定右值，此时 T 推导为引用类型并触发**引用折叠**）。
- 重载决议分两轮：先选**函数模板 + 普通函数**参与的重载集，再用**偏序（partial ordering）**决定更特化的模板优先——这解释了为什么 `f(T*)` 比 `f(T)` 优先。
- 模板实例化是**图灵完备**的编译期计算，代价是「代码膨胀 + 编译时间」，这是「泛型」与「运行时多态」的本质权衡（静态分发 vs 动态分发）。

### 📚 考研者视角
- 考研「泛型/模板」考点集中在**「模板是编译期展开、不产生运行时代价」**与**「模板不能分离编译（定义须可见）」**两条因果链上。
- 计算题会给「实例化了几份代码」——答：每个不同类型参数各生成一份，与调用次数无关。
- 记忆锚点：**推导不做隐式转换；转发引用 `T&&` 不是右值引用**（两个高频易错点）。
