# 02 · 移动语义的本质：值类别、右值引用与 `std::move`

## 一、理论根基：为什么要「移动」

拷贝大对象（长字符串、大 `vector`）代价高。很多场景下，源对象在「交出资源」后就不再被使用——例如函数返回一个局部 `vector`、把一个临时对象存进容器。**移动语义**让这种场景从「深拷贝整块资源」变成「把指针/句柄从源偷给目标」，代价是常数时间。

## 二、值类别（Value Categories）：理解移动的前提

C++11 把表达式按「是否拥有身份（identity）」与「是否可被移动」分为三类：

```
        可移动(move) ──┐
                       │
   lvalue ──── xvalue ─┤── 泛左值 glvalue（有身份）
                       │
   prvalue ───────────┘

  lvalue  : 有身份、通常不可移动（如变量名、*p、++i 的结果）
  prvalue  : 无身份、可移动（如 42、T() 临时量、a+b 的结果）—— 纯右值
  xvalue  : 有身份、但可被移动（eXpiring value，如 std::move(x) 的结果）—— 将亡值
```

> **反直觉但必须记住**：`T&&` 这种「右值引用」**本身是左值**（它有名字、可取地址）。它只是在「被初始化时」只能绑定到右值；一旦你给它起了名字（如 `Buffer&& r = ...;`），`r` 作为表达式是左值。这正是 `std::move` 存在的原因——要把它重新变成右值。

## 三、实现机制：`std::move` 只是一次无条件 cast

`std::move(x)` 不做任何运行期动作，**它只是把 `x` 无条件转换为右值引用（`static_cast<T&&>`）**，告诉编译器「我允许你移动它」。真正的资源转移发生在**移动构造函数 / 移动赋值运算符**里。

```cpp
template<class T>
constexpr remove_reference_t<T>&& move(T&& arg) noexcept {
    return static_cast<remove_reference_t<T>&&>(arg);   // 仅类型转换，零开销
}
```

ASCII 示意一次移动：

```
  移动前:  src ──拥有──> [堆内存 0x1000: 数据]
           dst ──拥有──> [堆内存 0x2000: 空]

  Buffer d = std::move(src);   // 调用移动构造
   ① 把 src.p 的指针值拷给 d.p
   ② 把 src.p 置空(nullptr)，使 src 不再拥有那块内存

  移动后:  src ──拥有──> nullptr   （有效但未指定状态，已「掏空」）
           dst ──拥有──> [堆内存 0x1000: 数据]   ← 资源被「偷」过来，无拷贝
```

## 四、实现机制：为什么移动构造要标 `noexcept`

`std::vector` 在 `push_back` 触发扩容时，需要把旧元素搬到新内存。搬完之后旧内存要释放——若移动过程中**抛异常**，标准库必须保证「强异常安全」：要么全部成功，要么原状。

- 若移动构造**可能抛异常**，标准库不敢用移动（否则搬到一半异常，旧元素已丢、新元素没建好，数据损坏）→ **回退到拷贝构造**（拷贝通常强异常安全）。
- 若移动构造标了 `noexcept`，标准库确认「移动不会抛」→ **放心用移动**，性能翻倍。

```cpp
Buffer(Buffer&& o) noexcept : p(o.p) { o.p = nullptr; }   // noexcept 让 vector 扩容走移动
```

（实测见 ex05：`noexcept` 的移动构造扩容时全程 `move`，未标 `noexcept` 的退化为 `copy`。）

## 五、工程实践

- 写管理资源的类，给**移动构造与移动赋值标 `noexcept`**（只要内部操作不抛）。
- 被 `std::move` 之后的对象：**不要再用它的值**，只允许「重新赋值 / 析构 / 查询是否为空」等不依赖原值的操作。
- 标准库容器、`std::unique_ptr`、`std::string`、`std::thread` 等都已正确支持移动；优先用它们（Rule of Zero）。

## 六、边界与陷阱

1. **`std::move` 不移动任何东西**，只是 cast；实体移动在构造/赋值里发生。
2. **移动后源对象处于「有效但未指定状态」**：再次读取其值（如 `src.p[0]`）是 UB 还是合法取决于类型——对 `string` 读是空的，对自定义类型取决于你如何「掏空」。
3. **右值引用变量本身是左值**：`void f(Buffer&& b){ g(b); }` 这里 `b` 是左值，`g` 收到的是左值；要再传递右值需 `g(std::move(b))`。
4. **返回值不要用 `std::move`**：`return res;` 中 `res` 是左值，但处于「即将销毁」上下文，标准会优先走移动（NRVO 优先于移动），加 `std::move(res)` 反而会**抑制 RVO**（见 ch05）。

## 七、可运行示例（见 examples/ex04.json、ex05.json）

- `ex04`：`Buffer b = std::move(a)` 触发移动构造（`b.p[0]` 仍可读，说明资源被偷而非拷贝），析构各一次。
- `ex05`：`vector<M>`（移动 `noexcept`）扩容全 `move`；`vector<C>`（移动非 `noexcept`）扩容退化为 `copy`。

## 三视角解析

### 🧑‍💻 程序员视角
- **`std::move` 只是 `static_cast<T&&>`**，它**不移动任何东西**、不释放源对象；真正的移动发生在**移动构造/移动赋值**被调用时。
- 移动后源对象处于「有效但未指定」状态——**只能用「重置」类操作**（如 `clear()`、重新赋值），不能再读它的值。
- 返回局部变量**不要写 `return std::move(x)`**：会**抑制 NRVO/RVO**，反而多一次移动（或拷贝）。

### 🎓 博士生视角
- 移动语义的物理基础是**值类别**：右值（prvalue/xvalue）代表「可以被掏空的临时对象」，因此允许把内部指针**窃取**过来、把源置空——这是**所有权的转移**而非数据的复制。
- 拷贝/移动对构造开销的影响是数量级的（深拷贝 O(n) vs 指针交换 O(1)），这直接决定容器（`vector` 增长、`sort` 交换）的整体性能量级。
- 移动与 `noexcept` 耦合：容器为维持强保证，只在移动构造 `noexcept` 时才用移动（否则回退拷贝）——**语言语义直接决定运行期策略**。

### 📚 考研者视角
- 记忆锚点：**`std::move` 是类型转换不是移动**；**移动后源对象「有效但未指定」**；**返回局部变量别 `std::move`**。
- 若考「拷贝构造 vs 移动构造」：答**拷贝是 O(n) 深复制，移动是 O(1) 指针窃取**，并说明它如何把「传值返回大对象」的成本降到可接受。
- 与 C 对照：C 里靠指针 + 手动 `free` 表达「转移所有权」，C++ 用类型系统把它**语义化、自动化**。
