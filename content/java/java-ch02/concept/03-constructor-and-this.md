# 03 · 构造器与 this：对象诞生的唯一入口

## 一、理论根基：构造器是"建立不变式"的契约

没有构造器，对象可能处于"半初始化"状态（字段是默认值 0/null/false），调用方一用就崩。构造器的第一性原理是：**保证对象一旦离开构造器，就满足不变式**。Java 不给"未构造完成的对象"被外部引用的机会——构造期间 `this` 虽已存在，但在构造器返回前对象尚未"发布"。

## 二、实现机制：重载、this() 链与初始化顺序

- **重载**：构造器可同名不同参（它没有返回类型声明，重载决议只看参数）。编译器按实参做重载决议，选最具体的匹配。
- **`this(...)` 调用同类构造器**：一个构造器可用 `this(args)` 委托给另一个，**且必须是方法体第一条语句**。这样把"公共初始化逻辑"收敛到一处（见 ex04：无参构造 → `this(1,1)` → 真正干活的有参构造）。
- **字段初始化顺序（关键）**：对象创建时按以下顺序执行：
  1. 父类静态字段/静态块（按文本序）
  2. 子类静态字段/静态块
  3. 父类实例字段初始化 + 实例块（按文本序）
  4. 父类构造器
  5. 子类实例字段初始化 + 实例块
  6. 子类构造器体
  见 ex06 的逐行输出：`static block → static field init` 在最前且只一次，之后每次 `new` 都走 `instance block → instance field init → constructor`。
- **默认构造器**：若类**没有任何**构造器，编译器插入一个无参、`public`、空体的默认构造器；一旦你写了任意构造器，默认构造器**不再自动提供**（这是"子类构造器必须显式/隐式调用父类构造器"这个坑的根源，见 ch03）。

## 三、工程实践

- 用 `this()` 链消除重复初始化；把校验放在"最具体"的构造器里。
- 优先"重叠构造器（telescoping constructor）"或 Builder（Effective Java 第 2 条）处理多可选参数，避免写几十个构造器重载。
- 构造器里**不要调用可被重写的方法**（见 ch03 陷阱：动态分派会调到子类覆写，而那时子类字段还没初始化，得到错误/部分值）。

## 四、边界与陷阱

1. `this()` 与 `super()` 不能共存，都必须是第一条语句。
2. 字段显式初始化 `int x = 5;` 实际被编译器搬到构造器体**最前面（在 `super()` 之后、你写的语句之前）**，但语义上属于实例初始化阶段。
3. 不要在构造器里做耗时操作或抛未受检异常而未处理，否则对象永远建不出来。
4. 静态字段的初始化只发生一次（类加载时），与 `new` 次数无关——ex06 的 `static block / static field init` 只打印一次即为证。

## 三视角解析

### 🧑‍💻 程序员视角
- 构造器链用 `this(...)` / `super(...)`，且**必须放在第一行**。
- 优先用**静态工厂方法**（如 `List.of`、`Optional.of`）替代构造器：可命名（表达意图）、可缓存（单例/复用）、可返回子类型。
- 绝不要「在构造器里把 `this` 泄漏出去」（注册回调、启动线程、放进集合），否则其他线程可能看到**未初始化完成**的对象。

### 🎓 博士生视角
- 构造器不是方法：无返回类型、**不能被继承、不能被重写、不能被直接调用**；`super()` 由编译器隐式插到子类构造器开头，形成**构造器链**。
- 对象创建顺序：分配内存 → 内存清零（保证字段有默认值）→ 沿构造器链自顶向下执行（父类构造器先跑完）→ 返回引用。因此**父类构造器中调用被子类重写的方法会看到子类字段的默认值**——这是「不要在构造器中调用可被重写的方法」的原因。
- 「构造器泄漏 this」在并发下等价于**不安全发布**：其他线程可能读到 `final` 以外的字段为空（JMM 只对 `final` 字段提供构造完成后的可见性保证）。
- 与 C++ 对比：C++ 的构造顺序是「基类 → 成员（按声明顺序）→ 自身」，Java 无成员初始化列表，成员初始化在构造器链中的注入点固定。

### 📚 考研者视角
- 与 C++ 的构造/析构顺序、C 的「结构体初始化」形成对比，是对象生命周期问题的三种语言解法。
- 若考程序设计语言，常考「对象的创建与初始化过程」「构造器与静态工厂的区别」。
- 记忆锚点：**构造器不能被继承或重写**；**构造过程中不要泄漏 `this`**。
