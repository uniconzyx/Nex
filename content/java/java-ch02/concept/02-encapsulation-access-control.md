# 02 · 封装与访问控制：不变式边界，而非"藏起来"

## 一、理论根基：封装是收窄合法状态空间

封装的第一性原理来自**抽象数据类型（ADT）**：类型的价值不在于"能存什么"，而在于"**能保证什么**"。把字段设为 `private` 后，对象状态只能经成员方法改变，类的作者得以在每一个写入路径上**维护不变式（invariant）**——例如"年龄必须 ≥0 且 ≤150"、"余额不能为负"。

这不是"把数据藏起来不给人看"，而是**把"状态如何变化"的控制权收归类型自身**。对比 C 的 `struct`：任何代码都能直接改写字段，不变式全靠程序员自觉；Java 的访问控制把责任从调用方转移到类型。

## 二、实现机制：访问修饰符是编译期名字查找规则

`private` / `包私有（默认）` / `protected` / `public` 都是**编译期**的可见性约束，影响的是"名字是否可被当前上下文解析"，**不生成任何运行期保护**。字节码层面，私有字段仍可被 `反射（setAccessible(true)）` 突破——所以访问控制是"防君子不防小人"的工程纪律，不是安全沙箱。

- `private`：仅本类可见。
- 默认（包私有）：同包可见。
- `protected`：同包 + 子类可见（注意：子类可见**不要求同包**）。
- `public`：任意可见。

> 经典坑：`protected` 字段在**不同包的非子类**中"通过父类引用不可访问，但通过子类引用可访问"——源于 JLS §6.6.2 的复杂规则，实践中建议字段一律 `private` 再用 `protected` 方法暴露。

## 三、工程实践

- 字段一律 `private`；需要暴露时用 `getter/setter`，并在 setter 中校验不变式（见 ex05——年龄非法直接抛 `IllegalArgumentException`，对象永不变"坏"）。
- 不可变对象更优：用 `final` 字段 + 构造器一次性初始化，不提供 setter，天然线程安全、随处可共享。
- Java 16+ 的 **`record`** 是"纯数据载体"的官方解法：编译器自动生成 `private final` 字段、访问器（命名即 `x()` 而非 `getX()`）、`equals/hashCode/toString`，把"封装 + 不可变 + 值语义"一次性搞定（见 ex08）。
- Getter/Setter 命名必须 `getXxx`/`setXxx`/`isXxx`（布尔），否则 Jackson、JPA、Spring 等框架的依赖注入/序列化会失败——这是"约定优于配置"的硬约束。

## 四、边界与陷阱

1. 仅加 `getXxx` 不加校验的 setter 等于没封装（任何值都能进）。
2. 返回可变对象（如 `Date`、`List`）的 getter 会泄露内部引用，调用方改了它对象状态就变——应返回**防御性拷贝**或不可变视图（`List.copyOf`、`Collections.unmodifiableList`）。
3. `record` 的字段是 `final`，不能重新赋值；想要可变请用普通类。
4. Lombok 的 `@Data` 等会生成 getter/setter，但隐藏了不变式校验点，复杂对象仍建议手写。

## 三视角解析

### 🧑‍💻 程序员视角
- `private` + getter/setter 不是仪式：目的是让**状态修改必须经过受控入口**，可以在入口处校验、记日志、触发通知。
- 优先设计**不可变对象**（`final` 字段、无 setter），它天然线程安全、可安全共享。
- 需要「包内可见但对外隐藏」时用默认（package-private）访问级别，而不是 `public` + 文档约定。

### 🎓 博士生视角
- 四种访问级别的语义：`private`（本类）→ 默认（本包）→ `protected`（本包 + 子类）→ `public`（全部）。**`protected` 的「包 + 子类」双重语义是 Java 特有**，常被误解为「只有子类可见」。
- 封装的真正目标是**维护不变式（invariant）**：让对象在任何可观察时刻都满足内部一致性约束。这在理论上是「抽象数据类型（ADT）」的思想——数据表示对外不可见，只有操作可见。
- 与 Haskell 的模块导出列表、C++ 的 `friend`、Rust 的 `pub(crate)` 对比可以看出：语言在「如何划定可见性边界」上的设计差异，最终反映的是「封装粒度」的不同取舍。
- 从信息隐藏原理（Parnas）看，封装的收益是**降低模块间耦合**，从而让内部实现可独立演化。

### 📚 考研者视角
- 与**软件工程**的「高内聚、低耦合」「信息隐藏」原则直接对应，是简答题常见素材。
- 若考程序设计语言，常考「访问控制级别的语义」「封装与继承的关系」。
- 记忆锚点：**封装 = 维护不变式**；**`protected` 包含包级可见性**（易错点）。
