# 常见陷阱 · 并查集与字符串高级
1. **find 不路径压缩导致退化成链** —— 只做按秩合并不压缩时最坏 O(log n)；若连按秩都省掉、且 union 总把 a 挂到 b，会退化成链，find 变成 O(n)。正确做法：find 与 union 同时用"路径压缩 + 按秩/按大小合并"，二者缺一不可（除非需要可撤销）。
2. **KMP next 回退写成 k=next[j]（应为 k=next[k]）** —— 自底向上求 next 时，回退的是"已匹配长度 k"对应的前缀位置，必须写 k = next[k]；若误写成 k = next[j] 会越界或死循环。考研手推时也要区分"位置 j 的 next 值"与"回退到的比较位置"。
3. **字符串哈希模数选合数与冲突** —— Rabin-Karp 选合数模数且不用双哈希，易构造冲突使误报。正确做法：模数选大素数（如 1e9+7、998244353），或配合自然溢出 + 双哈希（两个不同模数）降低碰撞概率；长文本去重务必校验原串而非仅比哈希。
4. **并查集忘记 init** —— parent 全 0 会让所有点被当成根 0 的子节点，逻辑全错。正确做法：每次使用前 for i: parent[i]=i; rank[i]=0；多测试用例注意重置。
5. **递归 find 深链爆栈** —— n=1e6 的链状输入递归 find 会 SIGSEGV。正确做法：用迭代版（两趟法：先找根，再回压路径）。
6. **把 rank 当真实树高** —— 路径压缩后 rank 只是高度上界，不再等于实际高度；用它去算"树高"会得到错误值。正确做法：rank 仅用于合并决策，不要外推语义。
7. **Trie 动态分配未初始化 children 指针** —— 新建节点时 children 数组未清零，后续访问野指针段错误。正确做法：calloc 而非 malloc，或在插入时判空再 new。
8. **KMP next 与 nextval 概念混淆** —— 前缀长度数组（0-indexed π）与"回退位置 next"（1-indexed，next[1]=0）是两种约定，直接把 π 当回退位会让 j 停在原地。正确做法：明确所用约定；408 王道采用 1-indexed，next[1]=0，失配时 j = next[j]。
9. **BM 坏字符 shift 未与 1 取 max** —— 若坏字符在模式更右侧出现，j - last[c] 可能 ≤0，造成模式左移或原地踏步。正确做法：shift = max(1, j - last[c])。
10. **并查集需要"拆集合"却仍用普通并查集** —— 普通并查集只合不拆，撤销/删边无能为力。正确做法：需要回滚用"按秩合并 + 不压缩 + 栈记录"的可撤销并查集；需要历史版本用可持久化并查集。
11. **Rabin-Karp 滚动哈希溢出变负** —— 不取模、用 int 累积 hash*base 会溢出成负数，比较失效。正确做法：用 long long 或及时取模，并正确减去 base^(m-1) 那一项（见 ex08）。
12. **AC 自动机 fail 指针 BFS 从根开始漏掉第一层** —— 只把根入队忘了把根的直接子节点的 fail 指向根，会导致深层失配回退错误。正确做法：根入队；根的每个孩子 fail=根并入队；之后按 BFS 用 fail[cur]->children[c] 续接。

13. **并查集只写路径压缩，不写按秩合并**
   极端构造下（不断把大树挂到小树上）树高仍可能达到 O(log n) 甚至退化，最坏情况性能不达标。
   ✅ 两个优化都写：`find` 做路径压缩，`union` 按秩（或按大小）合并，才能保证近 O(α(n))。

14. **KMP 的 next 数组两套约定混用**
   一套是 `next[0] = -1` 且长度 m，另一套是 `next[0] = 0` 且长度 m+1，混用必然差一位，匹配结果全错。
   ✅ 选定一套约定并统一：推荐「`next[i]` = 前 i 个字符的最长公共前后缀」，长度 m+1，失配时 `k = next[k]`。

15. **字符串哈希用 `int` 累积、减法后不补模**
   `hash*base` 溢出成负数，`% MOD` 得到异常值；`h[r] - h[l]*pw` 为负时也不修正，比较永远失败。
   ✅ 用 `unsigned long long` 自然溢出或 `long long` 配合及时取模；减法后统一 `(x % MOD + MOD) % MOD`。
