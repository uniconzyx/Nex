# 并查集：路径压缩 + 按秩合并

## 动态连通性：只合不拆的集合问题为什么值得专门造结构
**动态连通性**：不断合并集合、不断查询"两点是否同集合"，且**只合不拆**（这是它能这么快的前提）。典型场景：Kruskal 最小生成树判环、社交网络好友圈合并、编译器寄存器分配的合一、图像处理连通域标记、等价类合并。

朴素实现用"父指针森林"表示集合，根代表集合：

```text
初始（5 个独立集合，parent[i]=i）:
     0    1    2    3    4
     ↑    ↑    ↑    ↑    ↑

依次 union(0,1)、union(1,2)、union(2,3)、union(3,4)，且每次都"把前者挂到后者"：
     0 ← 1 ← 2 ← 3 ← 4        ← 退化成一条链，find(4) 要爬 4 层
```

若 union 随意挂，最坏退化成链，单次 find 是 O(n)，n 次操作 O(n²)——n=1e5 直接超时。两个优化正是冲着这两个退化来的：

- **按秩合并**：控制树的**高度**（不让它长歪）；
- **路径压缩**：把已经走过的路**顺手压平**（下次更快）。

## 按秩合并与路径压缩：两行优化如何把复杂度压到反阿克曼

### 2.1 按秩合并（union by rank / size）
始终让**小树挂到大树下**，用 `rank[]`（树高上界）或 `size[]`（节点数）度量。

```text
union(4, 5) 前：           按 size 合并后：
   A(size=3)   B(size=1)       A(size=4)
   /    \        |            /   |   \
  1      2       4           1    2    5
                              \
                               4    ← 小树整体挂到大树根上，高度不增加
```

为什么树高是 O(log n)：**每次某节点深度 +1，说明它所在的树至少翻倍**（小并大）。翻倍最多 log₂n 次，所以树高 ≤ ⌊log₂n⌋。

### 2.2 路径压缩（path compression）

```text
find(4) 前:  0 ← 1 ← 2 ← 3 ← 4       （深度 4，要走 4 步）

find(4) 后:  0 ← 1
             ↑  ↑  ↑  ↑
             2  3  4   （路径上所有点直接挂到根，深度变 1）
```

一次 find 把路径上所有节点直接接到根，代价不变却让后续查询极快。注意：**路径压缩只压这一次走过的路**，没走的不动。

### 2.3 复杂度：反阿克曼函数
- 仅路径压缩 / 仅按秩合并：均摊 O(log n)；
- **两者合用：O(m·α(n))**，α 是反阿克曼函数。对任何能写进内存的 n（n ≤ 2^65536），α(n) ≤ 4，工程上视作常数。

```text
n 的量级            α(n)
----------------------------
10                 1~2
10^6               3
10^18              3~4
2^65536            4      ← 物理世界不可能达到
```

### 2.4 标准 C 实现（迭代 find 防爆栈）

```text
int parent[N], rnk[N];

int find(int x) {                 /* 迭代版：两趟，第一趟找根，第二趟压平 */
    int r = x;
    while (parent[r] != r) r = parent[r];        /* ① 找根 */
    while (parent[x] != r) {                     /* ② 路径压缩 */
        int t = parent[x];
        parent[x] = r;
        x = t;
    }
    return r;
}

void unite(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return;                        /* 已同集合，无操作 */
    if (rnk[ra] < rnk[rb])      parent[ra] = rb; /* 小秩挂大秩 */
    else if (rnk[ra] > rnk[rb]) parent[rb] = ra;
    else { parent[rb] = ra; rnk[ra]++; }         /* 等秩：指定一方为根，秩 +1 */
}
```

> 面试常追问：为什么 find 用迭代不用递归？——路径很长（或被恶意构造的链）时递归会爆栈；迭代版只用 O(1) 额外空间。

## 三视角解析
### 🧑‍💻 程序员视角
- 并查集是"动态连通性"的标准解法：判连通、等价类归并、Kruskal 判环、账户合并类题。
- **真实工作场景**：用并查集做微服务调用环检测——把服务当点、调用关系当边，每加一条依赖就 `find` 判两端是否已连通，连通即说明这条边会成环，能在发布前拦住循环依赖（比每次跑一遍 DFS 便宜得多）。
- 需要**可撤销**（回滚）时改用"按秩合并 + 不路径压缩"，把每次合并压栈即可撤销，这是线段树分治 / 离线二分的常用搭子。
### 🎓 博士生视角
- 复杂度为 **O(α(n))**，α 为反阿克曼函数，对一切可想象的 n（< 2^65536）都有 α(n) ≤ 4，因此"接近 O(1)"。
- Tarjan 给出下界证明：在只允许并查操作的比较模型下，O(α(n)) 的摊还界是紧的，是"数据结构下界"的经典成果。
- 变体谱系：带权并查集（维护到根的差值/异或，解"关系链"问题）、可持久化并查集（用可持久化数组保存历史版本）。
### 📚 考研者视角
- **408 考点**：并查集定义、**Find（含路径压缩）与 Union 的实现**、按秩合并的作用。
- 常考选择题：给双亲表示法数组，问 `Find(x)` 的返回值，或问"压缩后数组变成什么样"；也问"合并后树的形态/树高"。
- 应用类：求**无向图连通分量个数**（数根）、判断加边是否成环（Kruskal 判据）、等价类划分。
- 记忆锚点：**路径压缩把查找路径上所有结点直接挂到根**；**按秩合并保证树高 O(log n)，配合路径压缩进一步降到 α(n)**。
