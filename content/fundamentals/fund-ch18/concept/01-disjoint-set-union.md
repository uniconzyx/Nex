# 并查集：路径压缩 + 按秩合并

## 1. 背景/动机
**动态连通性**：不断合并集合、不断查询"两点是否同集合"，且**只合不拆**（这是它能这么快的前提）。典型场景：Kruskal 最小生成树判环、社交网络好友圈合并、编译器寄存器分配的合一、图像处理连通域标记、等价类合并。

朴素实现用"父指针森林"表示集合，根代表集合：

text
初始:  0  1  2  3  4        union(0,1),union(1,2),union(2,3),union(3,4) 不加优化:
       ↑  ↑  ↑  ↑  ↑
                            0 <- 1 <- 2 <- 3 <- 4   （退化成链，find(4) 要爬 4 层）

若 union 随意挂，最坏退化成链，find 是 O(n)，n 次操作 O(n²)，n=1e5 直接超时。

## 2. 定义/要点
两个优化：

### 2.1 按秩合并（union by rank / size）
始终让**小树挂到大树下**，用 rank[]（树高上界）或 size[]（节点数）度量。**保证树高 ≤ O(log n)**：子树高度每 +1，规模至少翻倍。

### 2.2 路径压缩（path compression）
text
find(4) 前:  0 <- 1 <- 2 <- 3 <- 4
find(4) 后:  0 <------------------- 1,2,3,4 全部直接挂到根

一次 find 把路径上所有节点直接接到根，代价不变却让后续查询极快。

### 2.3 复杂度：反阿克曼函数
- 仅路径压缩：最坏 O(log n)；仅按秩合并：O(log n)；
- **合用：O(m·α(n))**，α 是反阿克曼函数。对任何可写进内存的 n（n ≤ 2^65536），α(n) ≤ 4，工程上即常数。

合并后的标准 C 实现（迭代 find 防爆栈）：

text
int find(int x){ int r=x; while(parent[r]!=r) r=parent[r];
    while(parent[x]!=r){ int t=parent[x]; parent[x]=r; x=t; } return r; }
void unite(int a,int b){ int ra=find(a),rb=find(b); if(ra==rb) return;
    if(rank[ra]<rank[rb]) parent[ra]=rb;
    else if(rank[ra]>rank[rb]) parent[rb]=ra;
    else { parent[rb]=ra; rank[ra]++; } }

## 三视角解析
### 🧑‍💻 程序员视角
- 并查集是"动态连通性"标准解法：判连通、等价类归并、Kruskal 判环、账户合并类题。
- **真实工作场景**：用并查集做微服务调用环检测——把服务当点、调用关系当边，每加一条依赖调用 find 判两端是否已连通，连通即发现循环依赖，及时熔断。
- 需要**可撤销**（回滚）时改用"按秩合并 + 不路径压缩"，把每次合并压栈即可撤销，是线段树分治 / 离线二分的常用搭子。
### 🎓 博士生视角
- 复杂度为 **O(α(n))**，α 为反阿克曼函数，对一切可想象的 n（< 2^65536）都有 α(n) ≤ 4，因此"接近 O(1)"。
- Tarjan 给出下界证明：在只允许并查操作的比较模型下，O(α(n)) 的摊还界是紧的，是"数据结构下界"经典成果。
- 变体谱系：带权并查集（维护到根的差/异或，解关系链）、可持久化并查集（可持久化数组实现历史版本）。
### 📚 考研者视角
- **408 考点**：并查集定义、**Find（含路径压缩）与 Union 实现**、按秩合并作用。
- 常考选择题：给双亲表示法数组，问 Find(x) 返回值或压缩后数组形态；问"合并后树的形态"。
- 应用类：求**无向图连通分量个数**、判断加边是否成环（Kruskal 判据）。
- 记忆锚点：**路径压缩把查找路径上所有结点直接挂到根**；**按秩合并保证树高 O(log n)，配合路径压缩进一步降为 α(n)**。
