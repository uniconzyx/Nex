# 字符串哈希（Rabin-Karp）与 Trie 字典树

## 1. 背景/动机
KMP 解决"一个模式 vs 一个文本"。当问题是"多模式 / 大量子串比较 / 前缀检索"时，两类结构更合适：**滚动哈希**把串比较降为数值比较；**Trie** 把公共前缀共享，支撑前缀与集合查询。

## 2. 定义/要点
### 2.1 Rabin-Karp 滚动哈希
把串视为 base 进制数（如 base=131/100），模大素数避免溢出。窗口右滑时：

text
hash("ell") = (e*base^2 + l*base + l) mod M
滑动: 新hash = ((旧hash - T[s-1]*base^(m-1)) * base + T[s+m-1]) mod M

例：base=100, "hello" 查 "ell" -> 窗口 [0]hel=80512, [1]ell=51212(匹配), [2]llo=121215。
要点：必须正确减去最高位那一项 base^(m-1)，且用 long long / 取模防溢出。

### 2.2 Trie 字典树
每个结点代表一个前缀，边是字符，标记 end 表示"到此为一个完整单词"。

text
        根
       / | \
      c  d
     / \  \
    a    o  o
   / \    \
  t   r    g
(cat,car,dog,do)

插入/查询都按字符逐层下降，时间 O(|s|)。前缀查询（如"ca"）只需走到该结点再判断 end。

## 三视角解析
### 🧑‍💻 程序员视角
- **真实工作场景**：用 Rabin-Karp 做"大规模文本去重/网页指纹"——对每段算哈希入库，O(1) 判重，比逐字符比快得多（注意双哈希防碰撞）。
- **真实工作场景**：用 Trie 做"输入框前缀联想"与"敏感词过滤"——把词典建成 Trie，用户输入时沿路径走即可提示或拦截；比每次全量正则快几个量级。
### 🎓 博士生视角
- 滚动哈希的碰撞概率：单模数 M 下为 1/M；双哈希把误报降到 (1/M1)(1/M2)。形式化需"通用哈希族"保证安全性。
- Trie 的空间可用**压缩前缀树（Radix/Patricia Trie）**压缩单链；在路由表（最长前缀匹配）中正是这种结构。
### 📚 考研者视角
- **408 / 面试高频**：Trie 的应用场景（前缀统计、词频、自动补全、异或最大值）；哈希冲突与取模。
- 选择题常考：Trie 插入/查找时间复杂度 O(L)（L 为串长），空间与字符集大小相关。
- Rabin-Karp 用于"多模式匹配"时启发 AC 自动机思路。
