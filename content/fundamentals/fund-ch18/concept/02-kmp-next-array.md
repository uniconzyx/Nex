# KMP 算法与 next 数组推导

## 1. 背景/动机
BF（朴素）匹配失配时文本指针 i 回退、模式整体右移一格，最坏 O(n·m)。KMP 的核心洞察：**已匹配的那段前缀里藏着"能跳过多少"的信息**——失配时文本指针 i 不回退，只把模式指针按 `j = next[j]` 回退，整体右滑 `j - next[j]` 位。

## 2. 定义/要点

### 2.1 next 数组（王道 1-indexed，next[1]=0）
`next[j]` = 模式串 `P[1..j-1]` 的**最长公共真前后缀长度 + 1**（也就是失配时 j 应回退到的位置，让 P 的第 1 位对上原来的第 `longest+1` 位）。

```text
模式 P:     a  b  a  b  c
位置 j:     1  2  3  4  5
next[j]:    0  1  1  2  3
nextval:    0  1  0  1  3

推导（看 P[1..j-1] 的最长公共真前后缀）：
  j=1: 规定 next[1]=0
  j=2: P[1..1]="a"            无真前后缀            -> 长度0 -> next=1
  j=3: P[1..2]="ab"           前缀 a / 后缀 b 不等   -> 长度0 -> next=1
  j=4: P[1..3]="aba"          "a" == "a"            -> 长度1 -> next=2
  j=5: P[1..4]="abab"         "ab" == "ab"          -> 长度2 -> next=3
```

> 别死记"长度还是长度+1"：**王道教材用 1-indexed，next[j] = 长度 + 1**；LeetCode / 多数库用 0-indexed 的 π（prefix function），`π[i] = 长度`，失配时 `j = π[j-1]`。两者只差一个下标约定，混用必错。

### 2.2 nextval（优化 next）
若 `P[j] == P[next[j]]`，说明回退之后拿同一个字符再比一次必然还失配，于是直接 `nextval[j] = nextval[next[j]]`；否则 `nextval[j] = next[j]`。

```text
例 1：P="ababc"，next=[0,1,1,2,3]
  j=2: P[2]=b, next[2]=1, P[1]=a  -> 不等 -> nextval[2]=next[2]=1
  j=3: P[3]=a, next[3]=1, P[1]=a  -> 相等 -> nextval[3]=nextval[1]=0
  j=4: P[4]=b, next[4]=2, P[2]=b  -> 相等 -> nextval[4]=nextval[2]=1
  j=5: P[5]=c, next[5]=3, P[3]=a  -> 不等 -> nextval[5]=next[5]=3
  nextval = [0,1,0,1,3]

例 2：P="aaaa"，next=[0,1,2,3]，全等 -> nextval 塌缩为 [0,0,0,0]
  （失配时一步退回开头，不用一层层试）
```

### 2.3 匹配主流程（i 不回退）

```text
i = 1; j = 1;
while (i <= n) {
    if (j == 0 || T[i] == P[j]) { i++; j++; }   /* j==0 是"退到模式之前"，直接重来 */
    else j = next[j];                           /* 只退 j，i 不动 */
    if (j > m) { 记录匹配位置 i-m; j = next[m+1] /* 或 nextval */; }
}
```

失配回退示意（T="ababcabcacbab"，P="abcac"，m=5）：

```text
第 1 轮：
T: a b a b c a b c a c b a b
P: a b c a c
        ↑ 失配：T[3]='a' vs P[3]='c'

j = next[3] = 1  ->  模式整体右滑 3-1 = 2 位，从 P[1] 与 T[3] 重新比
T: a b a b c a b c a c b a b
P:     a b c a c
        ↑ 这次 T[3]='a' 与 P[1]='a' 对上，继续往后比
```

### 2.4 复杂度
- 求 next：O(m)；匹配：O(n)。关键在于 **i 只增不减、j 的每次回退都对应之前的某次前进**，均摊后总步数 ≤ 2n。
- 空间：O(m) 存 next。

## 三视角解析
### 🧑‍💻 程序员视角
- **真实工作场景**：日志脱敏/模板匹配时要在大文本里找固定模式，KMP 比 `strstr` 的朴素实现在重复模式（如半结构化日志、DNA 重复序列）下快几个数量级。
- 工程里更常见的是 `strstr` / Two-Way / BM；但 KMP 有个不可替代的优势——**可增量匹配流数据**：只需维护 `j`，边读边匹配，不必把整个缓冲区留在内存里（适合网关逐包扫描）。
- 踩坑提醒：自己实现时用 0-indexed π 更自然，但教材题是 1-indexed next，**两者不可混用**，否则结果差 1。
### 🎓 博士生视角
- KMP 的状态转移等价于一个**确定有限自动机（DFA）**：next 数组刻画"当前已匹配长度 → 读到字符 c 后的新长度"，nextval 相当于把等价状态合并（最小化 DFA）。
- 复杂度证明依赖势函数：`Φ = j`，每次 `i++` 使 Φ 至多 +1，每次回退使 Φ 严格减小，故回退总次数 ≤ n。
### 📚 考研者视角
- **408 高频**：给模式串手推 next（1-indexed，next[1]=0）；选择题常给 next 数组问某步 j 的回退值，或问"第几次比较后匹配成功"。
- 易错：把 next 与 nextval 搞混；求 next 时看的是 `P[1..j-1]`（**不含 P[j] 本身**）；nextval 的递归依据是 `P[j] == P[next[j]]`。
- 应用：求模式首次/全部出现位置、判断子串、统计出现次数。
