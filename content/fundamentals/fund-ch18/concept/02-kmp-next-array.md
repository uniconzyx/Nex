# KMP 算法与 next 数组推导

## 1. 背景/动机
BF（朴素）匹配失配时文本指针 i 回退、模式整体右移一格，最坏 O(n·m)。KMP 的核心洞察：**已匹配的前缀里藏着"能跳过多少"的信息**，失配时文本指针 i 不回退，只移动模式指针 j = next[j]。

## 2. 定义/要点
### 2.1 next 数组（王道 1-indexed，next[1]=0）
next[j] = 模式串 P[1..j-1] 的**最长公共真前后缀长度**（即失配时 j 应回退到的比较位置）。手推用"前后缀递推"：

text
模式 P:     a  b  a  b  c
位置 j:     1  2  3  4  5
next[j]:    0  1  1  2  3
推导:
  j=1: next[1]=0 (规定)
  j=2: "a" 前后缀无公共 -> next[2]=1 (回到比较 P[1])
  j=3: "ab": 前缀a/后缀b 不等 -> next[3]=1
  j=4: "aba": 最长公共前后缀 "a" 长1 -> next[4]=2
  j=5: "abab": 最长公共前后缀 "ab" 长2 -> next[5]=3

### 2.2 nextval（优化 next）
若 P[j] == P[next[j]]，则失配时回退后还会再失配，直接 nextval[j] = nextval[next[j]]，否则 nextval[j] = next[j]。例 P="aaaa" 的 next=[0,1,2,3]，nextval 全部塌缩为 [0,0,0,0]。

### 2.3 匹配主流程（i 不回退）
text
while i<=n:
   若 j==0 或 T[i]==P[j]: i++, j++
   若 j>m: 找到匹配，j=next[j] 继续找下一处
   否则: j = next[j]   (j==0 时下一步 i++)

失配指针回退示意：
text
T: a b a b c a b c a c b a b
P: a b c a c
        ↑失配于 P[3]='c' 与 T 的 'b'
        j = next[3] = 1，模式右滑对齐已匹配前缀 "ab"
P:     a b c a c

## 三视角解析
### 🧑‍💻 程序员视角
- **真实工作场景**：用 KMP 做"大文本里精确子串检索/脱敏占位替换"，比 BF 在重复模式（如日志模板、DNA 重复序列）下快几个数量级。
- 工程里更多用 strstr / Two-Way 算法；但 KMP 的价值在于"可增量匹配流数据"——维护 j 即可边读边匹配，无需回溯整个缓冲。
### 🎓 博士生视角
- KMP 自动机等价于一个**确定有限自动机（DFA）**：next 数组刻画的是"在当前状态读到某字符后的转移"，nextval 则是把等价状态合并后的最小 DFA。
- 复杂度 O(n+m) 的严格证明依赖"i 与 j 的总前进步数不超过 2n"。
### 📚 考研者视角
- **408 高频**：给模式串手推 next（1-indexed，next[1]=0）；选择题常给 next 数组问某步 j 的回退值。
- 注意与"前缀长度数组 π"（0-indexed）区分：王道采用 1-indexed，失配 j=next[j]，不要写成 j=next[j-1] 或 j=next[j]-1。
- 应用：求模式出现位置、判断子串、统计出现次数。
