# BM 算法与 AC 自动机简介

## 1. 背景/动机
KMP 让模式指针不回退，但仍是"从左到右、逐字符比较"。两个不同的改进方向：

- **BM（Boyer-Moore）**：**从右往左**比较，利用"坏字符 + 好后缀"一次右移多位，实际库（GNU grep、多数编辑器查找）的核心；
- **AC 自动机（Aho-Corasick）**：把"多模式匹配"做成一张自动机，一次扫描文本命中**所有**模式，敏感词过滤的标配。

## 2. 定义/要点

### 2.1 BM：坏字符规则（bad character）
从模式末尾向前比。失配于模式位 `j`、文本字符 `c` 时：

- 若 `c` 在模式中更左侧出现过，位置记为 `last[c]`，则右移 `j - last[c]`，让这个 `c` 对上；
- 若 `c` 在模式里根本没出现（`last[c] = -1`），可以直接把整个模式移过 `c`。

```text
shift = max(1, j - last[c])      ← 必须与 1 取 max，否则可能算出 0/负数而"左移"死循环

实例（只用坏字符规则）：P = A B C A B D，T = A B C A B C A B C A B D
last: A->3, B->4, C->2, D->5

第 1 轮  s=0:  A B C A B C ...   （比 P[0..5]）
          P:   A B C A B D
                          ↑ j=5 失配：T[5]='C'，last['C']=2
          shift = max(1, 5-2) = 3      -> 模式右移 3 位

第 2 轮  s=3:  ... C A B C ...
          P:       A B C A B D
                          ↑ j=5 失配：T[8]='C'，last['C']=2
          shift = max(1, 5-2) = 3      -> 模式右移 3 位

第 3 轮  s=6:  ... A B C A B D       与 P 全等 -> 命中于位置 6
```

**好后缀规则**：失配时已匹配的后缀 `P[j+1..m-1]`，若它在模式中别处也出现（且前一个字符不同），就把它对齐过去；否则找它的最长后缀使得等于模式的前缀。工程实现取 `max(坏字符位移, 好后缀位移)`，平均可跳到 O(n/m) 量级。

### 2.2 AC 自动机（Aho-Corasick）
三步：**建 Trie → BFS 补 fail 指针 → 扫描文本**。`fail` 指针指向"当前路径的最长真后缀，且该后缀也是某个模式的前缀"所在的结点——它就是 KMP 里 next 在树上的推广。

```text
模式集 {he, she, his, hers} 的 Trie 与 fail 指针（fail 已用程序核实）：

                (root)
               /      \
              h        s
             / \        \
       [he] e   i        h
           /     \        \
          r       s[his]   e[she]
          |                 
          s[hers]          

结点        路径       fail 指向        说明
---------------------------------------------------------------
h           h          (root)          单字符无真后缀
he          he         (root)          "e" 不是任何模式的前缀
s           s          (root)
sh          sh         h               "h" 是模式 he 的前缀
she         she        he              "he" 是模式 -> 命中 she 时同时命中 he
hi          hi         (root)
his         his        s               "s" 是模式 she 的前缀
her         her        (root)          "er"/"r" 都不是前缀
hers        hers       s               "s" 是前缀 -> 命中 hers 后还能续 s
---------------------------------------------------------------

建 fail（BFS）：
  根的孩子们 fail = root，入队；
  对 u 的每个孩子 v（边字符 c）：
     f = fail[u]；while (f 且 f 没有 c 这条边) f = fail[f]；
     fail[v] = f 有 c 边 ? f.c : root；
  同时 out[v] |= out[fail[v]]      ← 这样 she 结点能直接报出 "he" 也命中
```

扫描文本时沿 Trie 走，失配就跳 `fail`，总复杂度 **O(|T| + 匹配数)**，与模式个数无关——这正是它比"k 次 KMP"强的地方（后者 O(k·|T|)）。

## 三视角解析
### 🧑‍💻 程序员视角
- **真实工作场景（AC）**：内容安全网关的敏感词实时过滤——一次扫描就把一条评论里所有命中词标出来，还要能报出"命中了哪些词、在哪个位置"；用 k 次 KMP 在几千词词典下直接超时。
- **真实工作场景（BM）**：编辑器大文件"查找"、`grep` 的快速路径——从右往左比能在"字符不在模式里"时大步跳过，普通英文文本上平均只需看 1/3~1/2 的字符。
- 踩坑：自己实现 AC 时忘记 `out[v] |= out[fail[v]]`，会出现"`she` 命中了但 `he` 漏报"——因为 `he` 是 `she` 的后缀，只能靠 fail 链继承过来。
### 🎓 博士生视角
- AC 自动机是**多模式确定有限自动机（DFA）**：Trie 给"结构"，fail 指针给"失配转移"，两者合起来对任意输入字符都有确定下一状态，等价于把 KMP 的 next 推广到树形结构。
- 形式化上它是在做"模式集合的后缀闭包"：`out` 沿 fail 链向上传递，本质是把"A 是 B 的后缀"这一偏序关系预先算成闭包，查询变成 O(1) 链式读取。
- BM 的好坏后缀规则可看作"自重叠结构"的两个不同侧面，其正确性与 KMP 同源（都靠"已匹配部分的后缀=某前缀"）。
### 📚 考研者视角
- **408 / 面试**：理解 BM"为什么能跳多位"、AC 的 fail 指针含义即可，一般不要求手推整棵自动机。
- 常考选择题：单模式各算法复杂度——BF O(nm)、KMP O(n+m)、BM 平均接近 O(n)；多模式用 AC 自动机 O(n + Σ|模式|)。
- 与 **ch03 树 / ch04 图**：AC 的 Trie 是树，fail 指针把这些树结点连成图——"树 + 额外边 = 图"的又一处落地。
