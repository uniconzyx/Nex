# 并查集与串匹配实战手记：凯喵的十二次「答案对了但超时」

> 这一篇来自凯喵刷算法题与做日志去重的经历。并查集与 KMP 都是「看起来简单、写起来细节多」的算法：并查集忘了路径压缩就退化成链，KMP 的 next 数组下标差一就全错。十二个现场记录下来的结论是：**这两个算法的坑几乎全在「初始化」和「下标约定」上**。这篇按「并查集 → KMP → 哈希/Trie → AC 自动机」的顺序展开。

## 开场：并查集是最简单的「高级结构」

并查集只支持两个操作：`find(x)` 找 x 所在集合的代表，`union(a, b)` 合并两个集合。用数组存「父指针」就能实现，代码不到二十行。

但它有两个优化，不写就退化成链表：**路径压缩**（find 时把路径上的节点直接挂到根上）和**按秩/按大小合并**（矮树挂到高树上）。两者都写，单次操作均摊接近 O(1)。

凯喵最初只写了 `find` 的朴素版本，在一个 10 万节点的图上超时了——因为合并成了链，每次 find 都是 O(n)。

### 现场一：并查集的初始化是「自己是自己的父亲」

```c
int parent[MAXN];
void init(int n) {
    for (int i = 0; i < n; ++i) parent[i] = i;
}
```

这行初始化看起来平淡，但漏了就是灾难：`parent` 是全局数组，默认全 0，于是所有节点的父亲都是 0，`find(0)` 会死循环（`parent[0] == 0` 时如果不加判断）。

凯喵见过更隐蔽的版本：`init` 只初始化了 `1..n`，而数据里有 0 号节点，导致 0 号永远是自己的父亲，合并永远失败。

规约：**节点编号从 0 开始就初始化 `0..n-1`，从 1 开始就初始化 `1..n`**，两处保持一致。

### 现场二：朴素 find 会退化成链

```c
// 朴素版：每次向上走到根
int find(int x) {
    while (parent[x] != x) x = parent[x];
    return x;
}
```

如果一直做 `union(1,2), union(2,3), union(3,4)...`，会形成一条长链，每次 find 都是 O(n)。n 次操作总复杂度 O(n²)。

修法是路径压缩：

```c
int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);   // 递归压缩
    return parent[x];
}

// 迭代版：避免深递归爆栈
int find_iter(int x) {
    int root = x;
    while (parent[root] != root) root = parent[root];
    while (parent[x] != root) {          // 第二遍：路径上全部挂到根
        int next = parent[x];
        parent[x] = root;
        x = next;
    }
    return root;
}
```

路径压缩后，树的深度接近 2，后续 find 几乎是 O(1)。**递归版在节点数超过十万时可能爆栈**，凯喵的建议是默认写迭代版。

### 现场三：按秩合并防止树变高

路径压缩解决「查询慢」，按秩合并解决「树太高」。合并时把矮树挂到高树上，树高不会超过 log n。

```c
int rank_[MAXN];
void union_sets(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    if (rank_[ra] < rank_[rb]) { int t = ra; ra = rb; rb = t; }
    parent[rb] = ra;
    if (rank_[ra] == rank_[rb]) ++rank_[ra];
}
```

注意 `rank` 只在「两棵树一样高」时增加，因为挂上去之后高度才 +1。这一步很多人写错成「每次都加」。

凯喵的实践：**两个优化都写**。只写路径压缩已经很快，但加上按秩能在最坏情况下也有保证。

### 现场四：并查集判连通，比 DFS 更适合「动态加边」

给一个图，不断加边，问两个点是否连通。DFS/BFS 每次加边后要重跑一遍，O(n+m) 一次；并查集每次加边 O(α(n))，查询 O(α(n))。

```c
// 动态加边 + 查询连通性
for (each edge (u, v)) union_sets(u, v);
if (find(a) == find(b)) printf("connected\n");
```

这个场景是并查集的主场：**只加不删、只问连通性**。如果边会删除，并查集就不适用了（要换成 LCT 等复杂结构）。

凯喵的提醒：并查集不支持「撤销」，所以离线算法里常配合「倒序处理」使用——把删除变成添加。这是并查集最经典的技巧之一。

### 现场五：KMP 的 next 数组到底是什么

`next[i]` 表示「`pattern[0..i]` 的最长相等前后缀长度」（不含整个串本身）。理解这一点，KMP 就不神秘了。

举例：`pattern = "ababaca"`

```text
i=0: "a"            → 0
i=1: "ab"           → 0
i=2: "aba"          → 1（前 "a" = 后 "a"）
i=3: "abab"         → 2（"ab" = "ab"）
i=4: "ababa"        → 3（"aba" = "aba"）
i=5: "ababac"       → 0
i=6: "ababaca"      → 1（"a" = "a"）
next = [0, 0, 1, 2, 3, 0, 1]
```

凯喵的记法：**next[i] 是「失配时可以直接跳到的位置」**——因为前 next[i] 个字符已经匹配上了，不需要重新比。

### 现场六：next 数组的两种约定，混用必错

有人定义 `next[0] = -1`，有人定义 `next[0] = 0`；有人把 next 长度设为 `m`，有人设为 `m+1`。混用两套约定，代码就会差一位。

凯喵推荐用「`next[i]` = 前 i 个字符的最长公共前后缀」这套（长度 m+1，`next[0] = 0`）：

```c
void build_next(const char* p, int m, int* next) {
    next[0] = 0;
    int k = 0;                        // k = 当前最长公共前后缀长度
    for (int i = 1; i < m; ++i) {
        while (k > 0 && p[i] != p[k]) k = next[k - 1];
        if (p[i] == p[k]) ++k;
        next[i + 1] = k;              // next 长度比 pattern 多 1
    }
}
```

然后匹配时：

```c
int kmp(const char* s, int n, const char* p, int m, const int* next) {
    int k = 0;
    for (int i = 0; i < n; ++i) {
        while (k > 0 && s[i] != p[k]) k = next[k];
        if (s[i] == p[k]) ++k;
        if (k == m) return i - m + 1;   // 找到
    }
    return -1;
}
```

关键细节：`while` 里是 `k = next[k]` 而不是 `next[k-1]`，因为这套约定的 `next[k]` 表示「前 k 个字符的公共前后缀」。**两套约定不能混，混了就差一位**。

### 现场七：KMP 的「跳过」是跳已匹配的前缀

KMP 的核心洞察：当在 `pattern[j]` 处失配时，`pattern[0..j-1]` 已经匹配上了。如果这段前缀有一个「长度 k 的相等前后缀」，那前 k 个字符可以复用，只需从 `pattern[k]` 继续比。

```text
文本：... a b a b a X ...
模式：    a b a b a c
                  ↑ 失配（c vs X）
此时已匹配 "ababa"，它的最长公共前后缀是 "aba"（长度 3）
所以可以跳到：
文本：... a b a b a X ...
模式：        a b a b a c
              ↑ 从 pattern[3] 继续比
```

这个跳转不丢失任何可能的匹配位置，因为「更短的匹配」已经被公共前后缀的性质排除了。这就是 KMP 保证 O(n+m) 的原因。

### 现场八：字符串哈希要取模，且要防溢出

Rabin-Karp 用哈希做滚动匹配。核心是 `hash(s[i..i+m-1]) = hash(s[i-1..i+m-2]) * base - s[i-1]*base^(m-1) + s[i+m-1]`。

```c
typedef unsigned long long ull;
const ull BASE = 131, MOD = 1000000007ULL;

ull h[MAXN], pw[MAXN];
void build(const char* s, int n) {
    pw[0] = 1;
    for (int i = 0; i < n; ++i) {
        pw[i + 1] = pw[i] * BASE % MOD;
        h[i + 1] = (h[i] * BASE + s[i]) % MOD;
    }
}
ull get(int l, int r) {     // [l, r)
    return (h[r] - h[l] * pw[r - l] % MOD + MOD) % MOD;
}
```

三个必须注意的点：**滚动时要先减再加**（顺序错了就出错）、**减法后要 `+MOD` 防负数**、**用 `unsigned long long` 自然溢出可以省一次取模**（但模数要选大质数或直接用 2^64）。

凯喵踩过的坑：用 `int` 累积哈希，乘法溢出成负数，`% MOD` 后得到一个奇怪的值，比较永远失败。

### 现场九：单哈希会被构造碰撞，双哈希更稳

哈希的碰撞概率取决于模数。`MOD = 1e9+7` 在随机数据下碰撞概率约 1e-9，但**对抗性输入可以构造碰撞**（比如某些 OJ 的 hack 数据）。

```c
// 双哈希：两个不同模数，同时相等才认为匹配
int h1 = get1(l, r), h2 = get2(l, r);
if (h1 == target1 && h2 == target2) { /* 匹配 */ }
```

双哈希的碰撞概率降到 1e-18 量级，实际等于不可能。代价是常数翻倍。

凯喵的建议：**比赛/刷题用双哈希，工程里用 `std::string_view` 直接比较更简单**（除非对性能有极高要求）。

### 现场十：Trie 的节点数是「字符总数」，不是「单词数」

Trie 的每个节点代表一个前缀。插入 n 个长度不超过 m 的串，最多 n×m 个节点。数组实现时要开这么大。

```c
int trie[MAXN][26];    // MAXN = 总字符数 + 1
int cnt[MAXN];         // 该节点作为单词结尾的次数
int tot = 0;

void insert(const char* s) {
    int p = 0;
    for (int i = 0; s[i]; ++i) {
        int c = s[i] - 'a';
        if (!trie[p][c]) trie[p][c] = ++tot;
        p = trie[p][c];
    }
    ++cnt[p];
}
```

开小了会越界（RE），开大了浪费内存（如果 `MAXN = 1e6`，`int[1e6][26]` 是 104MB，可能超限）。

凯喵的实践：**先算总字符数上限再定 `MAXN`**，或者改用 `unordered_map<int, int>` 的稀疏表示（慢但省内存）。

### 现场十一：AC 自动机的 fail 指针 BFS 要处理第一层

AC 自动机 = Trie + fail 指针（类似 KMP 的 next，但是树上的）。fail 指针的构建必须按 BFS 顺序，而且根的直接子节点的 fail 要指向根。

```c
void build_fail() {
    queue<int> q;
    for (int c = 0; c < 26; ++c) {
        if (trie[0][c]) { fail[trie[0][c]] = 0; q.push(trie[0][c]); }
    }
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int c = 0; c < 26; ++c) {
            int v = trie[u][c];
            if (!v) { trie[u][c] = trie[fail[u]][c]; continue; }  // 补全转移
            fail[v] = trie[fail[u]][c];
            q.push(v);
        }
    }
}
```

两个关键点：**根的孩子先入队**（否则深层节点的 fail 无法正确计算）、**空转移要「补全」成 fail 链上的转移**（这样匹配时不需要在失配时反复回溯）。

`trie[u][c] = trie[fail[u]][c]` 这行是 AC 自动机的灵魂：它把「失配后要跳几次」压缩成「一次跳转」，让匹配复杂度严格 O(n)。

### 现场十二：并查集与 KMP 的复杂度别记错

并查集的单次操作复杂度是 O(α(n))，α 是反阿克曼函数，对任何现实中的 n 都小于 5。所以工程上说「近似 O(1)」是对的，但**考试要说 α(n)**。

KMP 的复杂度是 O(n+m)，这是**严格最坏情况**，不是均摊。这一点比 Rabin-Karp 强——后者最坏是 O(nm)（全部哈希碰撞）。

凯喵的提醒：题目如果给 1e6 的字符串，KMP 稳过，Rabin-Karp 用双哈希也基本稳过，但朴素匹配必超时。选算法时先看数据规模，再看最坏情况。

## 三视角解析
### 🧑‍💻 程序员视角
凯喵第一次写并查集，只做了 `find` 的路径压缩，忘了按秩合并，结果在一个 10 万节点的图上超时——单独用其中一个优化，复杂度都到不了反 Ackermann，最坏仍可能退化成链。**两个优化必须一起上**，这是并查集唯一的门槛。串匹配那边踩的坑更隐蔽：KMP 的 `next` 数组定义在不同教材里差一位（有的是「最长公共前后缀长度」，有的是「失配后跳转位置」），照着 A 书写代码、用 B 书的样例测，必错。实战里更常用的是 `strstr` 或正则引擎的 Boyer-Moore，因为真实文本的字符集大、坏字符规则能一次跳过一大段——**理论最优不等于工程最快**。

### 🎓 博士生视角
并查集的摊还复杂度是 `O(α(n))`，α 是反 Ackermann 函数，在 `n < 10^600` 时不超过 4，因此可视为常数。这个界是紧的：Tarjan 证明了在「路径压缩 + 按秩合并」下，任意操作序列的总代价是 `O(m α(n))`，且存在达到该下界的序列。串匹配的理论图景更丰富：KMP 用前缀函数把「失配后回退」的代价摊还到 `O(n+m)`，其正确性可用势能法证明——每次 `j = next[j]` 至少让势能下降 1，而势能总增量不超过 m；Boyer-Moore 靠坏字符与好后缀规则做到亚线性平均复杂度，但最坏仍是 `O(nm)`。这些结构共同说明一件事：**字符串问题的复杂度取决于「你允许自己回退多少」**。

### 📚 考研者视角
408 数据结构对这两块的要求不对等：
1. **并查集**：考「用双亲表示法实现，写出 `Find` 与 `Union` 的代码」，重点在「路径压缩后树高」与「按秩/按大小合并」的选择。选择题常问「n 个元素做 n-1 次 union 后树的最大高度」，答案是 `⌊log₂n⌋ + 1`（按大小合并时）。
2. **KMP**：必考 `next` 数组的手算。规则是「`next[j]` = 前 j 个字符的最长相等前后缀长度」，手算时从长度 1 开始逐个试，不要跳步。常配一道「模式串在文本串中第几次出现」的应用题。
3. **对比题**：朴素匹配 `O(nm)`、KMP `O(n+m)`，要能说清 KMP 的改进点是「主串指针不回溯」。

## 收尾：两个算法的共同心法

凯喵最后总结：并查集和 KMP 看似无关，但它们的核心思想是同一个——**复用已经计算过的信息**。

并查集复用「谁和谁已经连通」这个信息，通过路径压缩把它记录下来；KMP 复用「这段前缀的公共前后缀」这个信息，通过 next 数组把它保存下来。两者都是「用空间换时间」，而空间就是那张表。

所以写这类算法的关键不是背代码，而是回答三个问题：**这张表存的是什么？它在什么时机被查询？它怎么被更新？** 三个问题答清楚，代码自然写出来；答不清楚，就只能靠试。

凯喵的最后一个经验：这两个算法都值得手写十遍。不是为了让手记住，而是为了让脑子把「下标约定」这件小事彻底内化——因为出错的地方永远在那里，而理解永远比记忆可靠。

再补一层关于「怎么在考场上快速写对」的建议。这两个算法的代码都不长，但细节多，考场上一紧张就容易差一位。凯喵的做法是把它们拆成「骨架 + 填空」两段来记：骨架是固定的循环结构和变量含义，填空是那几个容易错的下标表达式。写之前先在草稿上标清每个变量的语义——`next[i]` 表示什么、`k` 当前代表什么长度——标清楚了再写，几乎不会错。另一个经验是：写完立刻用一个短例子手推一遍，比如 `pattern = "abab"`，把 next 数组算出来对照。这个验证只要一分钟，但能抓住绝大多数下标错误。凯喵见过太多人写完就交，结果样例过不了又找不出问题，白白浪费时间。手推一遍的习惯建立起来之后，这类算法的正确率会有质的提升，因为它把「我以为对」变成了「我验证过对」。

还有一个容易被忽略的点：这两个算法都有「离线」和「在线」两种用法，而它们的适用边界完全不同。并查集天然适合离线：所有加边操作先做完，再回答查询。如果查询和加边交替出现，就得用「带撤销的并查集」或者干脆换结构。KMP 天然适合在线：文本流式输入，模式串固定，一次扫描就能给出所有出现位置，不需要把全文读完。选择算法时要先问「数据是分批到的还是一次给全」，这个问题往往比复杂度更能决定方案。凯喵见过在流式日志上硬套离线算法的实现，最后不得不把整个日志缓存在内存里，既不优雅也不安全。

再补一句：这两个算法的代码量都不大，真正值钱的是「知道什么时候用它」。并查集处理等价类，KMP 处理单个模式匹配，AC 自动机处理多模式匹配，哈希处理「两个子串是否相同」。把这四个问题和四个结构对应起来，比会背任何一段代码都有用，因为选择方案的能力才是稀缺的那一项。
所以练习的重点应该放在「识别问题类型」上，而不是「默写代码」上，前者决定你能否想到它，后者只是执行细节。
识别对了，代码自然写得出来；识别错了，写得再流畅也没有用。这才是算法训练真正该追求的能力。
