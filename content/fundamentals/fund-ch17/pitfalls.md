# 常见陷阱 · I/O 系统
1. **以为中断方式不占用 CPU** —— 中断方式只是把「CPU 主动轮询等待」换成了「外设就绪后打断 CPU」，但**中断服务程序（ISR）仍然在 CPU 上执行**，数据搬运、寄存器读写都吃 CPU 时间。真正的「几乎不占 CPU」是 DMA。正确认识：中断解决的是**等待效率**（CPU 不用干等），不是**搬运效率**（搬运仍由 CPU 做）。线上排查时若发现 `si`（软中断）CPU 占比异常高，往往是中断处理本身太重或中断风暴，而不是「硬件在自动搬运」。

2. **把 DMA 和中断方式混为一谈** —— 两者常被并列成「四种 I/O 方式」里的两项，但角色不同：**DMA 负责数据在内存与外设间的批量搬运（不占 CPU）**，而**DMA 传送结束通常仍靠一次中断来通知 CPU「我传完了，去做后处理」**。所以一次典型的磁盘读 = DMA 搬运数据（CPU 干别的） + 结束中断（CPU 进入 ISR 做收尾）。陷阱题常考：「DMA 方式是否完全不需要 CPU？」答案：预处理和后处理仍需 CPU，仅数据传送阶段脱离 CPU。

3. **统一编址 / 独立编址记反** —— 统一编址（Memory-Mapped I/O，MMIO）是**把 I/O 端口当作内存地址的一部分**，CPU 用普通 `load/store`（访存指令）访问设备，不专设 I/O 指令，地址空间与内存共享；独立编址（Isolated I/O）是**另开一套独立 I/O 地址空间**，需专用 `IN/OUT` 指令。记法：x86 是独立编址（有 `in/out` 指令、有 `0x3F8` 这类 I/O 端口），ARM/RISC-V 通常是统一编址（寄存器映射到内存地址）。考题让你「判断某架构用哪种」「IN/OUT 指令说明什么」时最容易张冠李戴。

4. **中断响应的第一步记成「保存断点」** —— 标准顺序是：**① 关中断 → ② 保存断点 → ③ 引出中断服务程序**。第一步必须是**关中断**（屏蔽新的可屏蔽中断），否则刚进入 ISR 又被更高优先级中断打断、且断点没保存完，就会乱套；保存断点（把 PC 压栈/存入特定寄存器）在关中断之后。口诀：「先关门（关中断），再记账（保存断点），最后找人（取向量、跳 ISR）」。

5. **以为关了中断就一定能多重中断（嵌套）** —— 多重中断（中断嵌套）要求**在处理中主动「开中断」**才能被更高优先级中断再次打断。若全程关中断，则当前 ISR 执行期间任何中断都被屏蔽，无法嵌套，等同于单级中断。所以「能否嵌套」取决于 **ISR 内部何时、是否重新开中断**，以及**中断优先级是否高于当前**。这也是为什么设置中断屏蔽字、合理安排优先级是硬件/OS 的关键工程点。

6. **把「中断屏蔽字」的方向搞反** —— 屏蔽字里某位为 `1` 通常表示**屏蔽（禁止）**该级别中断；为 `0` 表示**允许**。很多分析题给出各中断源的屏蔽字，要求求实际响应顺序：规则是——**只有优先级更高、且未被屏蔽的中断，才能在当前 ISR 执行期间（开中断后）抢占**。常见错误是直接按静态优先级排，忘了「被屏蔽的高优先级也进不来」。工程上这就是 `irq_disable()`/`local_irq_save()` 的语义，写驱动时漏开/漏关中断会导致丢中断或死锁。

7. **把「向量中断」和「查询中断」弄混** —— 向量中断是**硬件在响应时直接给出该中断源对应的 ISR 入口地址（或向量号→中断向量表查表）**，CPU 一步跳转，快且支持多个不同设备；查询中断（或叫「 polling 中断」/ 软查询）是 CPU 进入一个公共中断入口后**逐个询问「是谁申请的」**。考题问「中断向量表的作用」「向量中断的优点」时，要答出「硬件自动定位服务程序、响应快、可区分来源」。这是现代 x86 的 `IDT`、ARM 的「向量表 + 异常号」的底层原理。

8. **以为通道就是 DMA、或者以为通道很慢** —— 通道（Channel）是**专门负责 I/O 的 I/O 处理器（协处理器）**，它执行**通道程序（由通道命令字 CCW 组成）**来完成一组数据传送，CPU 只需发一条「启动 I/O」指令，之后完全由通道接管，比 DMA 更独立（DMA 通常只管一块连续内存的搬运，通道能处理带格式、带跳转的复杂 I/O）。别把「通道方式」和「DMA 方式」合并成同一个。三种通道类型（字节多路 / 选择 / 数组多路）的差别也是高频辨析点：字节多路轮流服务多个低速设备，选择通道独占服务一个高速设备，数组多路是「分块+轮流」兼顾两者。

9. **I/O 软件层次顺序记错** —— 自底向上是：**中断处理程序 → 设备驱动程序 → 与设备无关的操作系统软件 → 用户层 I/O 软件**。「设备驱动」紧挨硬件（直接读写寄存器、处理中断），「与设备无关」做统一缓冲、命名、保护（如 `read()` 系统调用抽象），「用户层」是库函数/SPOOLING 等。考题问「缓冲、错误处理、设备分配在哪个层次」「SPOOLING 属于哪层」时，常错答到驱动层。工程对应：Linux 里 `irq handler` → `驱动 probe/ISR` → `block/char 子系统` → `glibc read()`。

10. **DMA 与 CPU 访存「冲突」的三种方式分不清** —— 当 DMA 和 CPU 同时想访问内存（同一根内存总线）时，硬件用三种仲裁策略：**① 停止 CPU 访存**（DMA 独占总线，最简单但 CPU 被冻住）；**② 周期挪用 / 透明 DMA**（DMA 偷取 CPU 不用的总线周期，CPU 几乎无感，最常用）；**③ 交替访存 / 分时**（总线分成 CPU 周期和 DMA 周期，各用各的，需硬件支持）。陷阱在于把「周期挪用」说成「CPU 完全停转」，或把「交替访存」和「双端口内存」混为一谈。实际网卡/磁盘控制器多用周期挪用：数据来一小块就偷一个总线周期搬进内存，CPU 同时照常跑。

11. **忽略 DMA 与 CPU Cache 的一致性（cache coherency）** —— 经典考题/工程坑：DMA 把数据**直接写进内存**，但若 CPU 的 **Cache 里还有这块内存的旧副本**，CPU 读到的就是脏数据；反之 CPU 改了数据在 Cache 没写回，DMA 发出去的是旧数据。解决：**DMA 缓冲区用非缓存（uncached）内存**，或传输前 `cache flush/invalidate`。这在嵌入式（ARM 的 `dma_map_single`）和驱动开发里是真实 bug 源，表现为「DMA 收包内容偶尔错乱」「发送数据偶发旧内容」，极难复现。

12. **把「程序查询方式」当成落后而无用的方式** —— 它确实 CPU 利用率最低（CPU 不停轮询状态寄存器直到就绪），但对**极简单、极低速、单次、要求确定性的场景**（如单片机读一个按键、BIOS 早期初始化串口输出）反而最省事、零中断延迟、逻辑可控。陷阱在于「四种方式优劣对比」题里，不能无脑说查询方式「最差不能用」，要答「适用场景」维度。工程里裸机/固件阶段常用轮询，进了 OS 才切到中断/DMA。

13. **把「中断屏蔽」当成「中断禁止」的等价做法** —— 关中断（`cli`）只屏蔽**可屏蔽中断**，NMI（不可屏蔽中断）和异常（缺页、除零）照常发生；而且关中断时间过长会丢时钟中断、抬高系统抖动。正确理解：关中断是「短暂保护临界区的手段」，不是「让系统安静下来」的开关，临界区应尽量短，长操作改用自旋锁/信号量。
14. **以为中断嵌套越深越好、不设优先级** —— 不配优先级的嵌套会让低优先级中断抢占高优先级中断的处理，导致高优先级响应时间不可控（优先级反转）。正确做法：配置中断优先级分组，高实时性外设给高抢占优先级，并在临界区用 `BASEPRI` 精确屏蔽到某一级而不是全关。
15. **DMA 传输完成后忘记处理「半传输/传输错误」标志** —— 只等传输完成标志，忽略了 DMA 控制器的 HT（半传输）、TE（传输错误）、DME（直接模式错误）标志，出错时程序一直阻塞或读到半截数据。正确做法：使能错误中断，在 ISR 里分别处理 TC/HT/TE，并为每次传输设超时。
