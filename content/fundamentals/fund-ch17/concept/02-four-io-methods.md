# 四种 I/O 方式对比与适用场景

```text
CPU 与外设交换数据的四种方式（按"CPU 参与度"从最高到最低）：

  ① 程序查询方式 (Programmed I/O / Polling)
       CPU 不断读状态端口，READY 才搬 1 个数据；全程被"焊"在设备上。
       特点：最简单、最浪费 CPU、可确定性响应。

  ② 程序中断方式 (Interrupt-Driven I/O)
       CPU 先去干别的；外设就绪 → 发中断 → CPU 暂停当前程序 → 进 ISR 搬数据。
       特点：等待时不占 CPU，但"搬数据"仍在 ISR 里由 CPU 做。

  ③ DMA 方式 (Direct Memory Access)
       由 DMA 控制器在内存↔外设间批量搬运，CPU 只做"发命令+收结束中断"。
       特点：数据传送阶段完全脱离 CPU，适合大块、高速数据。

  ④ 通道方式 (Channel)
       专门的 I/O 处理器，执行"通道程序(CCW)"完成复杂 I/O；CPU 只发"启动I/O"。
       特点：比 DMA 更独立、更智能，多见于大型机/服务器 I/O 子系统。
```

> 本章要点：四种方式不是「越新越好」，而是**在 CPU 开销、硬件成本、并行度、适用数据量之间权衡**。考试常考「给场景选方式」「四种方式多维对比」。

## 1. 背景/动机

外设速度跨度极大：键盘一次敲键间隔几十毫秒，而万兆网卡每秒要收 10^9 bit。若让 CPU 全程盯着慢设备（程序查询），CPU 利用率趋近于零；若每次只收 1 字节就中断一次（程序中断），高速设备会把 CPU 淹没在中断里。于是演进路线是：

**查询（CPU 忙等）→ 中断（CPU 等待时去干活，但搬运仍靠 CPU）→ DMA（连搬运都外包给硬件）→ 通道（外包给专用处理器）。**

核心权衡维度：

| 维度 | 说明 |
|---|---|
| CPU 参与度 | 查询最高，通道最低 |
| 数据传送单位 | 查询/中断常是「字节/字」，DMA/通道是「块/连续区」 |
| 并行度 | 查询零并行，DMA/通道可与 CPU 并行 |
| 硬件开销 | 查询最少（几乎无额外硬件），通道最多（独立处理器） |
| 适用数据量 | 查询适合极少数据，DMA/通道适合大块 |

## 2. 定义/要点

### 2.1 四种方式逐一定义与流程

```text
① 程序查询（Polling）
  CPU: while ((SR & READY)==0) { /* 空转 */ }   // 一直在问"好了吗"
       data = DR;                                // 好了就读
  ─ 全程 CPU 被占用，外设慢则 CPU 闲等。

② 程序中断（Interrupt）
  CPU: 启动设备; 去做别的事;            // 不被设备拖住
       ... (设备就绪) → 硬件置 IRR, 发 INTR
       CPU 响应: 关中断→保存断点→取向量→跳 ISR
       ISR: 读 DR 把数据搬进内存; 开中断; IRET 返回
  ─ "等待"阶段 CPU 自由，但每次只搬少量数据，且搬运在 ISR 内由 CPU 完成。

③ DMA
  CPU: 设 DMAC(源/目的/长度/方向); 启动 DMAC; 去做别的事;
       DMAC: 每来一个"设备就绪"就偷一个总线周期，把 1 个字/1 块搬进内存;
             全部传完 → 向 CPU 发一次"DMA 结束中断"
  ─ 数据传送完全不经过 CPU 寄存器，仅开始/结束需 CPU。

④ 通道（Channel）
  CPU: 在内存写好"通道程序(CCW 链表)"; 执行一条"启动 I/O"指令;
       通道: 取 CCW → 执行(读/写/转移/停止) → 取下一条 → ...
             全部完成 → 发"通道中断"通知 CPU
  ─ 通道是 I/O 处理器，能处理带格式、带分支的复杂传送。
```

### 2.2 四维对比速查表（408 必背）

```text
方式          CPU参与度   每次传送单位   与CPU并行   硬件成本   典型适用
─────────────────────────────────────────────────────────────────────
程序查询      最高(忙等)   字节/字        否          极低      极低速/偶发/固件初始化
程序中断      中(等中断)   字节/字        等待时可并行 低        中低速、不定时(键盘/鼠标)
DMA          低(仅首尾)   块/连续区     是          中        高速大块(磁盘/网卡/声卡)
通道          极低        复杂I/O流     是          高(处理器) 大型机多设备/复杂格式
```

### 2.3 选型口诀

```text
  数据少又急不得  → 查询(简单确定)
  来了不知道何时  → 中断(等通知)
  一大块猛搬      → DMA(省 CPU)
  一堆设备多格式  → 通道(专业外包)
```

### 2.4 真实世界的混合

现代计算机几乎**四种同时存在**：键盘用中断，磁盘/网卡用 DMA + 结束中断，固件早期用查询，大型存储子系统用通道（或现代等价物如 `IOMMU + 专用 DMA 引擎`）。所谓「四种 I/O 方式」不是历史演进的替代关系，而是**按场景并存的工具箱**。

### 🧑‍💻 程序员视角

你写的每一行业务代码，底层都可能踩在这些 I/O 方式上：

- **`read()` 从网卡收包**：网卡 DMA 把帧搬进内核 ring buffer，再发中断唤醒 `softirq`（软中断）处理协议栈；你用户态的 `recv()` 只是从内核 buffer 拷贝到用户 buffer。所以「中断方式不占 CPU」是错的——**softirq 吃掉的那部分 CPU 就是中断处理的延伸**，用 `top` 看 `si` 列、用 `cat /proc/softirqs` 能看到网卡中断的软中断计数。
- **零拷贝减少 DMA 次数**：`sendfile(fd_out, fd_in, ...)` 让数据**直接从文件页缓存 DMA 到网卡**，不经过用户态，省掉「磁盘→内存→用户→内存→网卡」的多轮拷贝与多次 DMA 建立。工作场景：高并发静态文件服务器（nginx）用 `sendfile` 后，CPU 占用与上下文切换明显下降——本质就是**把「多次小搬运」压缩成「一次 DMA + 描述符传递」**，贴近 DMA 思想。
- **select/poll/epoll 与中断的关系**：`epoll` 不是「替代中断」，而是**把「每个事件一次唤醒」聚合成「一批事件一次通知」**，减少进程被中断唤醒的次数，避免「中断风暴」把 CPU 冲垮。线上曾遇到某项服务 `epoll` 监听 10 万 fd，每次中断都唤醒一个线程去遍历，结果 softirq 占满单核——这就是「中断/通知太频繁」的工程代价。
- **真实踩坑——轮询 vs 中断的抉择**：某高频交易网关把网卡从「中断模式」切到「**忙轮询（busy poll / PMD）**」，换取更低的收包延迟（中断有几百纳秒~微秒的响应抖动），代价是那颗 CPU 核心 100% 占用。这是把「程序查询」主动请回来换确定性的典型工程取舍。

### 🎓 博士生视角

从体系结构建模看，四种方式对应不同的**「CPU—设备—内存」总线仲裁与数据流」**设计：

- 查询方式是**纯同步、CPU 主动轮询状态机**；其吞吐上限由 `1 / (轮询开销 + 单字传输时间)` 决定，CPU 利用率 `U = T_data / (T_poll_overhead + T_data) → 0` 当设备很慢。
- 中断方式引入**异步控制流**：CPU 的执行流被外部事件「打断—恢复」，需要保存/恢复上下文（寄存器现场），因此单次中断有固定开销 `T_isr_setup`。当数据率 `R` 很高时，`R × T_isr_setup` 可超过 CPU 能力 → 中断饱和（interrupt saturation），这正是引入 DMA 的动机。
- DMA 把数据流从「设备→CPU 寄存器→内存」改为「设备→DMA 控制器→内存」，解耦了**数据面（data plane）**与**控制面（control plane）**；CPU 只在控制面发命令、收完成中断。
- 通道/现代 I/O 处理器（如智能网卡、GPU 的 DMA 引擎、DPU）进一步把控制面也下放，体现**「计算向数据移动」vs「数据向计算移动」**的权衡——把处理能力放到离数据最近的地方。

历史上，IBM System/360 首次系统化提出**通道（Channel）**作为独立于 CPU 的 I/O 子系统，奠定了「CPU 只发 I/O 指令、通道执行通道程序」的分层思想，深刻影响了后来的总线主控（bus master）、DMA 与 IOMMU 设计。

### 📚 考研者视角

408 高频：

- **四种方式的核心区别表**：务必能默写出「CPU 参与度 / 传送单位 / 能否与 CPU 并行 / 硬件代价 / 适用」五列。
- **易混辨析**：
  - 「DMA 是否完全不需要 CPU？」——**否**，仅数据传送阶段脱离 CPU，预处理（设寄存器/描述符）和后处理（中断里收尾、通知进程）仍需 CPU。
  - 「中断方式与 DMA 方式都能让 CPU 与外设并行？」——中断方式只有**等待阶段**并行（ISR 里仍串行搬），DMA 是**整个数据传送阶段**并行。
- **常考计算/分析**：
  - 比较两种方式完成一次传送的 CPU 占用时间：查询方式 ≈ 全程占用；中断方式 ≈ `n × T_isr`（n 次中断）；DMA 方式 ≈ `T_setup + T_complete_isr`（只两次 CPU 介入）。
  - 给场景选方式：键盘 → 中断；磁盘大块读 → DMA；固件初始化串口打印 → 查询；大型机多外设 → 通道。
