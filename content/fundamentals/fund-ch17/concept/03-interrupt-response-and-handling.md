# 中断响应与处理过程（关中断/保存断点/引出 ISR、单级/多级、向量中断、屏蔽与优先级、多重中断与嵌套）

```text
【中断响应五步】（硬件 + 软件协作）
  ① 关中断        : CPU 屏蔽新的可屏蔽中断（置屏蔽标志），防止ISR被打乱
  ② 保存断点      : 把当前 PC（断点）压栈或存入特定寄存器
  ③ 引出中断服务程序: 由硬件/软件找到 ISR 入口（向量 or 查询）
  ④ 执行 ISR      : 保护现场→开中断(如需嵌套)→具体处理→关中断→恢复现场
  ⑤ 中断返回(IRET): 恢复断点(PC)、恢复屏蔽标志，回到被中断的程序

【单级 vs 多级中断】
  单级: 只有一级中断，优先级无细分；或全程关中断，不允许任何嵌套
  多级: 中断分多个优先级；高优先级可在低优先级ISR执行时被响应 → 多重中断(嵌套)
```

> 本章要点：中断的「响应」是硬件自动完成的固定动作序列；「处理」里才涉及是否嵌套、如何按优先级仲裁。屏蔽字与优先级共同决定**实际响应顺序**——这是 408 分析题的核心。

## 按一下键为什么能打断 CPU 正在做的事

外设不能预测何时就绪，CPU 也不能一直干等（见 fund-ch17 概念 02 的程序中断方式）。中断机制让外设「就绪时主动打断 CPU」。但打断不是任意的：必须保证**被中断程序能被完整恢复**，且**更重要的事能优先得到处理**。于是引出两套机制：

- **响应流程**：硬件必须做的一套标准动作（关中断、保存断点、引出 ISR），否则上下文会乱。
- **优先级与屏蔽**：当多个中断同时或嵌套到来时，决定「先处理谁、能否打断正在处理的」。

## 中断响应的完整流程：关中断、保存断点、引出 ISR 与多重嵌套

### 2.1 中断响应全过程（408 必背五步）

```text
外设就绪 ──置 IRR 相应位、发 INTR──▶ CPU 在"指令边界"检查
   │
   ▼
① 关中断      （CPU 内部置"中断屏蔽"位；可屏蔽中断被挡住，NMI 不受此限）
   ▼
② 保存断点    （PC 当前值入栈/存专用寄存器；这是"回到原处"的依据）
   ▼
③ 引出 ISR    （取中断向量/查询入口 → 把 ISR 首地址装入 PC）
   ▼
④ 执行 ISR    （见下：保护现场→[开中断]→处理→[关中断]→恢复现场）
   ▼
⑤ 中断返回     （IRET：恢复 PC（断点）+ 恢复原来的中断屏蔽状态）
```

**关键细节**：
- **关中断必须在保存断点之前**——若先保存断点时发生新的中断，断点可能没存完就被覆盖。
- **保存断点是硬件自动的**（压栈 PC）；而「保护现场」(通用寄存器) 是 **ISR 开头软件做的**(PUSH 各寄存器)，别和「保存断点」混淆。
- **引出 ISR 的方式**区分了「向量中断」与「查询中断」。

### 2.2 向量中断 vs 查询中断

```text
向量中断（Vector Interrupt）：
  外设/中断控制器把"中断类型号/向量号"送上数据总线 → CPU 用它在
  [中断向量表/IDT] 里查到 ISR 入口。 一步定位，快，能区分来源。
      CPU: 向量号 n → 入口 = *(向量表基址 + n×表项大小)

查询中断（Polled Interrupt）：
  CPU 进一个公共入口，再依次读各设备状态位判断"是谁"：
      if (KBD_SR & INT) service_kbd();
      else if (NET_SR & INT) service_net();  // 顺序决定优先级
```

现代 x86 用 **IDT（Interrupt Descriptor Table）**，ARM 用「异常向量表 + 异常号」，本质都是向量中断。

### 2.3 中断优先级、屏蔽与多重中断（嵌套）

```text
假设 4 级中断，优先级 1 > 2 > 3 > 4（数字越小越高）。
屏蔽字 M_i：第 j 位 = 1 表示"在处理 i 时，屏蔽级别 j"（1=屏蔽,0=允许）。

  中断源   屏蔽字 (位: 1 2 3 4)
    1      1 1 1 1   ← 处理1时谁都不让进(最高)
    2      0 1 1 1   ← 处理2时只允许更高的1进来
    3      0 0 1 1   ← 处理3时允许1、2进来
    4      0 0 0 1   ← 处理4时允许1/2/3进来

多重中断(嵌套)发生的条件：
  (a) 当前 ISR 内部"开中断"（否则全程屏蔽，无法嵌套 = 单级行为）
  (b) 新中断优先级 > 当前，且其位在屏蔽字中为 0（允许）
```

**分析题算法（必会）**：
- 初始按**静态优先级**排序所有可能的中断。
- 进入某个 ISR 并**开中断后**，只有「优先级更高且未被屏蔽」的中断能抢占。
- 嵌套深度 = 同时处于活跃（已响应未返回）的 ISR 层数。

### 2.4 单级中断 vs 多级中断

```text
单级中断：
  - 所有中断同等对待，或全程关中断 → 不允许嵌套；
  - 优点简单，缺点：低优先级中断会阻塞高优先级（若先到的是低优先级且关了中断）。

多级中断：
  - 中断分优先级，高可打断低 → 支持多重中断(嵌套)；
  - 需要中断控制器做优先级仲裁（如 8259A 的 IR0~IR7 优先级、ARM GIC 的优先级分组）。
```

### 🧑‍💻 程序员视角

你写代码几乎不直接关/开中断，但**驱动与内核里到处是这套机制**：

- **Linux 的 `local_irq_save()/local_irq_restore()`**：就是「关中断（含保存原屏蔽字）/ 恢复」。写驱动时，若一段临界区既可能被进程上下文访问、又可能被中断上下文访问，就要用这种「关中断 + 自旋锁」保护，否则会**丢中断或数据竞争**。经典 bug：在中断 ISR 里调了会睡眠的函数（如 `mutex_lock` 可能睡眠）→ 系统卡死，因为中断上下文不能调度。
- **中断上半部 / 下半部（top half / bottom half）**：真实驱动里，**ISR（上半部）只做最紧急的事**（清中断、收数据到队列），把耗时处理推迟到**软中断 / tasklet / 工作队列（下半部）**。这正是「多重中断」的工程落地：ISR 越短，越不容易阻塞更高优先级中断的响应。线上「软中断 CPU 占比高、网络延迟抖动」往往就是下半部太重。
- **真实工作场景——中断风暴（interrupt storm）**：某次网卡驱动 bug，设备因「中断未被正确清除」而**每微秒重复申请中断**，CPU 100% 陷在 ISR 里，系统假死。排查用 `cat /proc/interrupts` 看某 IRQ 计数是否指数增长，修复是「在 ISR 里读状态寄存器清除中断源」。本质就是「中断优先级/屏蔽没管好 + ISR 没正确清源」。
- **优先级反转的兄弟——中断抢占用户态**：高优先级中断频繁打断了正在持有的锁的低优先级线程，导致系统整体卡顿，这类问题用 `ftrace` / `perf` 看 `irq` 事件时间分布来定位。

### 🎓 博士生视角

中断系统的形式化可看作一个**优先级驱动的抢占式调度器**，只不过被调度的「任务」是 ISR：

- 设中断源集合 `S`，每个 `i ∈ S` 有静态优先级 `p(i)` 与当前屏蔽集合 `mask(i)`。系统维护「当前最高活跃优先级」`p_cur`。新中断 `k` 在时刻 `t` 可抢占当前处理的充要条件是：
  `p(k) > p_cur` 且 `k ∉ mask(cur)` 且当前处于「开中断」状态。
- 嵌套形成一棵树/栈：每次合法抢占压栈一层，IRET 出栈一层，深度受栈空间限制（这也是为什么 ISR 不能无限嵌套）。
- **硬件仲裁实现**有三种经典方案：
  1. **菊花链（Daisy Chain）**：设备串在一条中断确认链上，越靠前优先级越高，结构简单但优先级固定、且设备多时延大；
  2. **并行优先级编码（Priority Encoder）**：中断控制器对 `IRR` 实时编码出最高优先级，灵活；
  3. **独立请求线 + 控制器**：每个设备独立请求线连到中断控制器（如 GIC），由控制器按可配置优先级仲裁——现代 SoC 主流。
- **向量中断的数学本质**是「中断源 → 地址空间的一次查表映射」`f: IRQ_id → ISR_entry`，把异步事件映射到确定的控制流入口，避免了查询中断的 `O(n)` 轮询延迟。
- 更进一步，**中断亲和性（IRQ affinity）**与**中断负载均衡**把不同 IRQ 绑到不同 CPU 核，是 SMP 下「中断处理」与「进程调度」协同的研究方向（如 `irqbalance`）。

### 📚 考研者视角

408 必考：

- **中断响应五步顺序**：关中断 → 保存断点 → 引出 ISR → 执行 ISR（保护现场/开中断/处理/恢复现场）→ 中断返回（IRET 恢复断点与屏蔽）。**第一步是关中断而非保存断点**，这是高频易错点。
- **「保存断点」与「保护现场」区分**：前者硬件自动存 PC，后者是 ISR 软件 PUSH 通用寄存器。
- **向量中断**：中断向量表存 ISR 入口，硬件据中断号直接定位；优点「响应快、可区分来源」。常与「查询中断」对比考。
- **屏蔽字求响应顺序**（分析题）：给各中断源的屏蔽字与到达时间/优先级，手算实际被响应的次序与嵌套层数。规则重温：**只有优先级更高且对应屏蔽位为 0（允许）的中断，才能在开中断后抢占**。
- **多重中断 vs 单级中断**：能否嵌套取决于「ISR 中是否开中断 + 优先级/屏蔽」；单级中断不允许嵌套。
- **易错**：把「DMA 结束也用中断通知」误以为 DMA 不需要中断；中断方式「等待时不占 CPU」但「ISR 执行时占 CPU」。
