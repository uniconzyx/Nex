# I/O 接口的功能与结构、I/O 端口编址

```text
CPU 为什么要 I/O 接口？（不能直接连外设的原因）
  1. 速度不匹配：CPU 纳秒级，键盘毫秒级、磁盘微秒~毫秒级
  2. 时序不匹配：外设有自己的握手/就绪信号
  3. 信息格式不匹配：外设是串行/并行、模拟/数字、电平不同
  4. 信息类型多：数据 / 状态 / 控制 三类信号
  → 接口 = CPU 与外设之间的"翻译官 + 缓冲 + 协调器"

典型 I/O 接口内部寄存器（端口）：
  CPU ──地址/数据/控制总线──▶ [ 数据寄存器 DR ] ◀──▶ 外设
                              [ 状态寄存器 SR ] ──▶ CPU 读"就绪/忙/错误"
                              [ 控制寄存器 CR ] ◀── CPU 写"启动/中断使能"
```

> 本章要点：I/O 接口的核心作用是**速度/时序/格式匹配**与**信号分类**；编址方式决定 CPU 用什么指令、在哪个地址空间访问这些寄存器。

## 外设五花八门，CPU 凭什么认得出它们

CPU 不能直接把外设挂在总线上读写。键盘、鼠标、磁盘、网卡的工作速度、电平、数据格式和 CPU 完全不同。若强行直连，要么 CPU 被外设的慢速拖死，要么信号根本对不上。因此需要 **I/O 接口（I/O Interface，又称 I/O 控制器 / 设备控制器）** 夹在中间：

- **数据缓冲**：接口里通常有数据寄存器，吸收速度差（如串口先把收到的字节存起来等 CPU 来取）。
- **速度/时序协调**：用状态位告诉 CPU「我好了没」（READY/BUSY）。
- **信号变换**：并串转换、电平转换（TTL ↔ RS-232）、模拟↔数字。
- **命令译码**：把 CPU 写来的控制字解释成对外设的具体动作。

接口对外暴露三类可编程寄存器，统称 **I/O 端口（Port）**：

| 端口 | 方向 | 作用 | 例子 |
|---|---|---|---|
| 数据端口（DR） | 双向 | 真正的数据 | 串口收发缓冲区 |
| 状态端口（SR） | CPU 读 | 就绪/忙/错误/中断请求 | 第 0 位 = RX_READY |
| 控制端口（CR） | CPU 写 | 启动/停止/中断使能 | 置位 START 位 |

CPU 编程的本质，就是**读状态端口判断条件、写控制端口下命令、读写数据端口搬数据**。

## I/O 接口的四项功能与端口编址的统一/独立两种方案

### 2.1 I/O 端口编址：两种方案

```text
【方案 A：独立编址 / Isolated I/O / 专用 I/O 指令】
  CPU 有"两套地址空间"：
    内存空间  0x0000~0xFFFFF       用 MOV 访问
    I/O 空间  0x0000~0xFFFF        用 IN/OUT 访问
  示例(x86):  in  al, 0x3F8      ; 从 COM1 数据端口读 1 字节
              out 0x3FD, al      ; 往线路状态端口写
  特点：地址线少（I/O 空间小）、不占内存地址、需专用指令、需 I/O 读写控制信号

【方案 B：统一编址 / Memory-Mapped I/O, MMIO】
  I/O 端口被映射到内存地址空间的一段，没有独立 I/O 空间：
    0x40000000 = UART 数据寄存器
    0x40000004 = UART 状态寄存器
  示例(ARM/RISC-V):  ldr r0, [0x40000000]   ; 读 UART 数据（就是一次"访存"）
  特点：用普通 load/store 即可、不需专用指令、占用内存地址、译码简单
```

对比速记表：

| 维度 | 独立编址 | 统一编址（MMIO） |
|---|---|---|
| 地址空间 | 内存、I/O 各一套 | 共用一套 |
| 指令 | 专用 IN/OUT | 普通访存指令 |
| 内存地址浪费 | 否（I/O 不占内存） | 是（划走一段地址） |
| 典型架构 | x86 | ARM、RISC-V、MIPS |
| 访存控制信号 | 有独立的 IOR/IOW | 复用 MEMR/MEMW |

### 2.3 程序员怎么碰这些端口

在 OS/裸机里，访问端口就是读写特定物理地址（MMIO）或执行 IN/OUT（独立编址）。例如读串口是否收到数据：

```c
/* 独立编址(x86)：读 COM1 状态端口 0x3FD 的最低位判断是否收到字节 */
static inline unsigned char inb(unsigned short port) {
    unsigned char v;
    __asm__ volatile("inb %1, %0" : "=a"(v) : "Nd"(port));
    return v;
}
int has_data(void) { return inb(0x3FD) & 0x01; }   /* 第0位=数据就绪 */
```

### 🧑‍💻 程序员视角

工作中你多半不会手写 IN/OUT，但一定会**间接碰到 I/O 端口**：

- **`/dev` 与 `mmap`**：在 Linux 里，很多设备的寄存器被映射成 `/dev` 下的文件或内核虚拟地址，驱动用 `readl()/writel()`（本质是对 MMIO 地址的访存）去读状态、写控制；用户态通过 `mmap` 把网卡/显存的一段寄存器或 buffer 映射到自己的地址空间，读写即等于访问硬件。
- **真实工作场景——网卡丢包排查**：一次线上「偶发收包丢、但 `ifconfig` 看不到 error」的故障，根因是驱动轮询状态端口的节奏和硬件 DMA 写 buffer 的节奏不匹配：硬件把数据 DMA 进 ring buffer 并置「就绪」位，驱动却因为 **NAPI 软中断被别的中断饿死**迟迟没去读状态端口，导致 ring 被覆盖。**排查手段**：`ethtool -S eth0` 看 `rx_missed_errors`、抓 `softirq` 占比、调大 `net.core.netdev_budget`。这背后就是「状态端口/DMA 就绪」与「CPU 何时去取」的协调问题。
- **嵌入式寄存器配置**：写 MCU 外设时，你会写 `UART->DR = ch;` 或 `GPIO->ODR |= (1<<5);`，这些 `->DR/->SR/->CR` 就是数据/状态/控制端口，是 MMIO。改错一位（比如把「时钟使能」位写成「发送使能」）设备就完全不工作，所以寄存器的位定义文档（datasheet）是第一手资料。

### 🎓 博士生视角

I/O 编址本质是**地址空间的划分问题**，与存储系统的「地址译码」同源：

- 独立编址可形式化为两个不相交的地址函数：`f_mem: Addr_mem → Memory`，`f_io: Addr_io → I/O`。CPU 通过**指令类型**而非地址高位来选通，因此需要在总线周期里额外给出 `IOR#/IOW#` 信号，地址译码器据此选通 I/O 接口。
- 统一编址则是 `f: Addr → Memory ∪ I/O`，靠地址高位区间做译码：`addr ∈ [A_io_low, A_io_high)` 时选通设备而非内存。优点是指令集更精简（RISC 哲学：load/store 统一），缺点是地址空间被外设「吃掉」一部分。
- 历史维度：早期 CISC（x86）偏爱独立编址以隔离 I/O；RISC 运动（MIPS/ARM/SPARC/RISC-V）几乎一律 MMIO，理由是「少一种指令类型 = 更简单的流水线 + 更统一的 MMU/缓存语义」。这也是今天 SoC 里绝大多数外围都走 MMIO 的原因。
- 进一步，现代系统还有 **Port I/O 与 MMIO 之外的第三类**——**内存映射 + DMA 描述符环**（如 PCIe 的 MMIO 控制寄存器 + 主存里的描述符环），接口结构从「三个寄存器」演进为「寄存器 + 共享内存队列」，但「状态/控制/数据」的三分逻辑依然成立。

### 📚 考研者视角

408 常考：

- **两种编址的核心区别**：有无独立 I/O 地址空间、是否需专用 I/O 指令。一句话判定：**有 `IN/OUT` 指令 / 两套地址空间 → 独立编址（x86）**；**用 `load/store` 访问设备 → 统一编址（ARM、RISC-V）**。
- **I/O 接口必备的三类端口**：数据端口、状态端口、控制端口，以及各自方向。
- **接口的功能**：速度匹配、格式转换、时序协调、提供状态/控制信号——常以选择题「以下哪项不是 I/O 接口的功能」出现。
- **易错点**：把「统一编址不占内存地址」说反（实际是**占用了内存地址空间的一段**）；或把「独立编址需要专用指令」记成「统一编址需要专用指令」。
- 本章与 fund-ch13（总线、CPU 结构）衔接：I/O 接口挂在系统总线上，地址译码由 CPU 的地址线与接口内的译码逻辑完成。
