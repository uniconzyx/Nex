# DMA 与通道、I/O 软件层次

```text
【DMA 传送三阶段】
  预处理: CPU 给 DMAC 设 源地址/目的地址/传送长度/方向，启动 DMAC，然后 CPU 去干别的
  数据传送: DMAC 接管总线，每来一个"设备就绪"就偷一个总线周期，把数据从设备搬进内存(或反之)
  后处理: 全部传完，DMAC 向 CPU 发"DMA 结束中断"；CPU 进 ISR 做收尾(通知进程/清资源)

【DMAC 与 CPU 争总线：三种仲裁】
  (1) 停止 CPU 访存     : DMA 独占总线，CPU 暂停访存(最慢但最简单)
  (2) 周期挪用/透明DMA   : DMA 偷 CPU 不用的总线周期，CPU 几乎无感(最常用)
  (3) 交替访存/分时      : 总线按时分，CPU 周期与 DMA 周期各用各的(需硬件支持)

【通道 (Channel)：I/O 处理器】
  通道程序 = 一串 CCW(通道命令字)：读/写/转移/置标志/停止
  CPU 只发"启动 I/O"，通道自己取 CCW 执行，完成发"通道中断"

【I/O 软件四层（自底向上）】
  中断处理程序 → 设备驱动程序 → 与设备无关OS软件 → 用户层 I/O 软件
```

> 本章要点：DMA 把「数据面」从 CPU 手里解放出来，但开始/结束仍要 CPU；通道更进一步把「控制面」也外包。I/O 软件层次则是从硬件中断到用户 `read()` 的完整栈。

## 大批量数据搬运为什么不该由 CPU 亲自干

程序中断方式里，**每次数据搬运仍在 ISR 中用 CPU 寄存器完成**——高速设备（磁盘、网卡、显卡）一来就是几 MB/s 到几 GB/s，CPU 会被「搬数据」彻底淹没。DMA（Direct Memory Access，直接存储器访问）让 **DMA 控制器**代替 CPU 在内存与外设间批量搬数据，CPU 只需发命令、收结束中断。

但当**大量设备、复杂格式、需做地址变换/校验**时，连「给 DMAC 下命令、管理描述符」都成了 CPU 负担——于是出现**通道（Channel）**：一台专门干 I/O 的协处理器，执行「通道程序」完成复杂 I/O，CPU 只发一条「启动 I/O」。IBM 大型机时代确立，今天演化为智能网卡/DPU/IOMMU 的思想源头。

最后，无论硬件多强，软件都要把「中断/寄存器」封装成「`read()/write()` 这样统一、安全、与设备无关的接口」——这就是 **I/O 软件层次**。

## DMA 的三种传送方式、通道结构与 I/O 软件的四个层次

### 2.1 DMA 传送三阶段（408 必背）

```text
① 预处理（CPU 做）
   CPU ──▶ DMAC: 设 源地址(MAR) / 目的地址 / 计数(DAR) / 方向(读内存还是写内存)
                发 "启动 DMA" 命令
   CPU ──▶ 去做别的（此时数据还没开始传）

② 数据传送（DMAC 做，CPU 不介入）
   设备就绪一次 → DMAC 申请总线 → 挪用一个总线周期 → 搬 1 个字/1 块
   地址寄存器 +1，计数 -1，直到计数=0

③ 后处理（CPU 做，靠中断）
   计数到 0 → DMAC 拉高 "DMA 结束中断" → CPU 进 ISR
   ISR: 通知等待的进程、更新 buffer 指针、释放资源
```

**关键认知**：DMA **不是完全不需要 CPU**，而是「只有数据传送阶段不需要 CPU」；预处理与后处理（尤其结束中断）仍需 CPU。所以「一次磁盘读」= `预处理(CPU) + 数据传送(DMAC, CPU 并行干别的) + 后处理(CPU 中断)`。

### 2.2 DMAC 与 CPU 访存争夺（三种方式）

```text
(1) 停止 CPU 访存（DMA 优先，CPU 停）
    |CPU访存|............DMA独占总线............|CPU访存|
    CPU 在 DMA 期间无法取指/取数 → 简单但浪费

(2) 周期挪用 / 透明 DMA（偷空闲周期）
    CPU周期 CPU周期 [DMA偷1周期] CPU周期 CPU周期 [DMA偷1周期]
    CPU 不访存的那一瞬间被 DMA 借用 → CPU 几乎无感

(3) 交替访存 / 分时（总线按时分）
    [C1][D1][C2][D2]...  C=CPU周期 D=DMA周期，各自专用 → 需硬件把总线时序分开
```

### 2.3 通道与通道程序（CCW）

```text
CCW（通道命令字）字段示意：
  [命令码][数据区首址][计数值][标志:链/转移/暂停...]
通道程序 = CCW0 → CCW1 → CCW2(链位=1) → ... → CCWn(链位=0,停止)

CPU 侧：
  1) 在内存写好通道程序(CCW 链)
  2) 执行 "启动 I/O" 指令(特权指令)，把通道程序首址告诉通道
  3) 通道自主取 CCW 执行：读设备→搬内存→遇"转移CCW"跳转→遇"停止"结束
  4) 完成 → 发 "通道中断" → CPU 收尾
```

**三种通道类型**（对比常考）：

```text
类型          服务方式                      适用设备
─────────────────────────────────────────────────────────
字节多路通道   轮流、分时服务多个低速设备     打印机/终端(字符流)
选择通道      独占一个高速设备直到传完       磁盘(一次一大块)
数组多路通道  分块+轮流(每块间让出)多个中高速 多台磁盘/磁带(兼顾并行)
```

### 2.4 I/O 软件四层（自底向上）

```text
┌─────────────────────────────────────────────┐
│ 用户层 I/O 软件   : 库函数、SPOOLING、用户缓冲 │  ← 你调用的 printf/read
├─────────────────────────────────────────────┤
│ 与设备无关OS软件  : 统一命名/缓冲/错误处理/保护 │  ← 抽象成 "文件/设备" 概念
├─────────────────────────────────────────────┤
│ 设备驱动程序      : 具体寄存器操作、命令序列    │  ← 直接面向硬件
├─────────────────────────────────────────────┤
│ 中断处理程序      : 清中断、收数据、唤醒进程    │  ← 最靠近硬件
└─────────────────────────────────────────────┘
         ▲ 向下逐层调用，向上逐层返回
```

### 🧑‍💻 程序员视角

这些机制在你的代码下面一层一层地发生：

- **`read()` 到底经历了什么**：你调 `read(fd, buf, n)` → 用户层库 → 系统调用陷入内核（与设备无关层做参数检查、分配内核 buffer）→ 设备驱动发命令/设 DMA 描述符 → 设备 DMA 把数据搬进内核 buffer → 设备发中断 → 中断处理程序收尾、唤醒进程 → 内核把数据拷贝到你的 `buf`。**所以「等 I/O」等的是「设备 + DMA + 中断 + 调度」整条链**，不是某一环。
- **零拷贝省的就是 DMA 次数**：`splice()` / `sendfile()` 让「磁盘文件 → 网卡」只走「磁盘 DMA 进页缓存 + 网卡 DMA 出页缓存」，描述符传递代替数据拷贝，CPU 几乎不参与搬运——这是把概念 02 的「DMA 省 CPU」用到极致。
- **真实工作场景——大块文件拷贝 CPU 飙高**：某服务做磁盘→内存→网络的三段拷贝，单核 CPU 100%。改用 `io_uring` + `sendfile` 后，DMA 直接在内核页缓存与网卡间搬运，CPU 占用降到个位数。排查时看 `perf` 里 `copy_user_enhanced_fast_string` 这类「内存拷贝」符号占比即可定位。
- **SPOOLING（假脱机）**：打印机的「打印队列」就是用户层 I/O 软件的典型——多个进程「同时打印」其实是写入一个**假脱机目录（spool）**，由后台守护进程（设备无关层之上的服务）真正串行送给打印机。这让你「以为」设备被多进程共享，实则被软件虚拟化。

### 🎓 博士生视角

- **DMA 与 cache 一致性**：DMA 绕开 CPU 直接改内存，而 CPU 可能缓存了同一块内存 → 出现「CPU 看到旧值 / DMA 发出旧值」。需 `cache flush/invalidate` 或采用**硬件一致性（硬件 snooping）**的 `DMA-coherent` 内存。这是嵌入式与驱动开发中最隐蔽的 bug 来源之一（数据偶发错乱、不可复现）。
- **IOMMU / DMA 重映射**：现代系统用 IOMMU 把设备看到的「总线地址」映射到「物理地址」，既做隔离（防恶意/坏设备 DMA 越权访问内存）又做地址转换（设备用 32 位地址访问 >4GB 内存）。它是「DMA 控制器 + MMU」思想的融合，也是虚拟化里设备直通（VFIO/PCIe passthrough）的基础。
- **通道的当代演化**：今天的「通道」已不是独立大机部件，而是 **智能网卡（DPU/IPU）、GPU 的 Copy Engine、存储控制器的专用 DMA 引擎**。它们执行由 CPU 下发的「描述符程序」，本质就是 CCW 的现代化——把 I/O 控制面从 CPU 卸载到专用处理器。
- **I/O 软件层次的工程映射**：Linux 里 `irq handler`（顶半部）→ `驱动 probe/ISR`（底半部 softirq/tasklet）→ `block/char 子系统 + VFS`（与设备无关）→ `glibc read/write + stdio 缓冲`（用户层），与教科书四层一一对应，是研究真实系统的最佳样本。

### 📚 考研者视角

408 必考：

- **DMA 三阶段**：预处理（CPU 设地址/计数/方向并启动）、数据传送（DMAC 接管总线批量搬）、后处理（DMAC 发结束中断，CPU 收尾）。**数据传送阶段 CPU 不参与**，但首尾参与。
- **DMAC 与 CPU 争总线三种方式**：停止 CPU 访存、周期挪用（透明 DMA）、交替访存。最爱考「周期挪用」的特点——偷空闲周期、CPU 几乎无感。
- **通道 vs DMA**：通道是**I/O 处理器**，执行**通道程序（CCW）**，比 DMA 更独立、能处理复杂/多设备 I/O；DMA 更像「自动搬运工」，通道是「带脑子的小 CPU」。
- **三种通道类型**：字节多路（多低速、轮流）、选择（独占高速、整块）、数组多路（分块轮流、兼顾）。给设备选类型常考。
- **I/O 软件四层（自底向上）**：中断处理程序 → 设备驱动 → 与设备无关 OS 软件 → 用户层 I/O 软件。考题「缓冲/设备命名/保护属于哪层」→ 与设备无关层；「SPOOLING」→ 用户层。
- **易错**：把 DMA 说成「完全不需 CPU」；把「通道」和「DMA」等同；把 I/O 软件层次顺序记反（应与「用户→硬件」方向相反，自底向上是「硬件最近→用户最远」）。
