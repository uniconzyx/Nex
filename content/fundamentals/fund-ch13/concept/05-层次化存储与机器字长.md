# 层次化存储、机器字长 与 数据通路宽度

## 容量够大为什么还不够快：存储介质的剪刀差与局部性

两个常被混淆、却决定"机器能算多大数、能访问多少内存、部件间一次搬多少"的基础量：**机器字长**和**数据通路宽度**；它们又和"为什么有 Cache、为什么内存够大还不够快"的**层次化存储**密不可分。本章把它们归到一起，是因为它们都是"系统级参数"——你写应用代码时感受不到，但选型、排错、理解性能时躲不开。

## 机器字长、数据通路宽度与层次化存储的层间契约

**层次化存储（Memory Hierarchy）**：依据"速度↑容量↓成本↑"的剪刀差，把存储分成多层，用**局部性原理**（时间局部性：刚访问的很可能再访问；空间局部性：相邻地址很可能访问）让"上层快但小、下层慢但大"组合起来，对程序员呈现"一个既快又大的单一存储"。

```text
        速度        容量        成本/位      对程序员
寄存器   最快(~1周期)  极小        最高        不透明(汇编可见)
  ↑ L1 Cache  ~1ns     几十KB      高          透明
  ↑ L2/L3    ~10ns     几MB        中          透明
  ↑ 主存      ~100ns    几GB~TB     低          透明(但虚存机制可见)
  ↑ SSD      ~100μs     TB级       更低        透明
  ↑ 磁盘/网络  ~10ms+    PB级       最低        透明
  局部性原理让 90%+ 的访问落在上层 → 平均访问时间远低于主存
```

**机器字长（Machine Word Length）**：CPU 中**ALU 一次能处理的二进制位数**，也是**通用寄存器的位宽**。它决定：
- 能直接运算的最大整数范围（n 位 → 无符号 0~2ⁿ−1）；
- 地址总线常见与字长相关（如 32 位字长常配 32 位地址线 → 寻址 2³²=4GB，这就是"32 位系统只能用 4GB 内存"的根因）；
- 数据表示与对齐方式。

**数据通路宽度（Datapath Width）**：CPU 内部/部件之间**一次能并行传输的位数**，常体现在数据总线位宽、内部总线、访存接口。例如：
- 32 位 CPU 配 64 位外部数据总线 → 一次访存可取 8 字节；
- 它**不等于**字长：字长是"算多宽"，数据通路宽度是"搬多宽"。

```text
易混三点（常考辨析）：
  机器字长   = ALU/寄存器位宽   → 决定"算多大、地址空间多大"
  数据通路宽 = 总线/内部互连位宽 → 决定"一次搬多少"
  存储器字长 = 一次访存读出的位数 → 常等于或小于数据通路宽度
三者数值可以完全不同：如早期 32 位字长 CPU，外部数据总线 64 位。
```

**量化小工具**：地址线 n 位 → 可寻址 2ⁿ 字节；字长 w 位 → 无符号整数上界 2ʷ−1；数据通路 w_d 位 → 一次最多搬 w_d/8 字节。

## 三视角解析

### 🧑‍💻 程序员视角
- **字长坑真实案例**：我们维护过一个跑在**32 位嵌入式 Linux**上的采集程序，用 `int` 当时间戳（毫秒）。系统跑了约 49.7 天后 `int` 溢出回绕（32 位有符号 int 上界 2³¹−1 毫秒 ≈ 24.8 天，若用无符号约 49.7 天），导致所有"时间差"算错、任务调度错乱。根因就是**机器字长决定整数范围**这一章讲的——32 位环境下 `int` 只有 32 位。改成 64 位 `long long` 后解决。**选类型先看字长**。
- **数据通路/对齐**：`struct` 里字段顺序影响实际占用，因为要按字长/总线宽度对齐（详见后续存储章节），不当排列会浪费数据通路搬运量、拖慢访存。写高性能序列化时，"字节对齐 packed vs 非 packed"就是字长与通路宽度的实战体现。
- **层次化存储的体感**：同样循环，按行访问二维数组（连续地址，空间局部性好）比按列访问快数倍——因为一次 Cache 行（如 64 字节）加载能喂饱后续多次访问。这是透明层（Cache）对你"看不见但很要命"的典型。

### 🎓 博士生视角
- 层次化存储的**平均访问时间（AMAT）**可递归建模，是量化透明层的钥匙：
  `AMAT = h₁·t₁ + (1−h₁)·(t₁ + h₂·t₂ + (1−h₂)·(t₂ + t_mem))`，
  其中 hᵢ 为第 i 级命中率，tᵢ 为访问时延。它说明"上层快"省下的时间取决于**命中率**而非上层本身速度——这也解释了为什么"加大 Cache 容量"比"加一级更快但更小的 Cache"更稳。
- 字长与数据通路宽度的分离，本质是**计算粒度（ALU 位宽）与传输粒度（总线位宽）的解耦**。从信息论/吞吐角度看，理想设计时二者应匹配以**避免气泡（bubble）**：总线比 ALU 窄 → ALU 等数据；ALU 比总线窄 → 总线用不满。真实设计在面积/功耗约束下取折中，这正是体系结构量化研究的对象。
- 字长还牵动**地址空间与碎片化**：32 位地址空间 4GB 中还要给内核、MMIO 留窗，用户态实际可用更少——这不是"内存条不够"，而是**字长锁死的地址位宽**，是 Amdahl 式结构性上限。

### 📚 考研者视角
- **408 高频考点**：
  1. 层次化存储的层次与"速度/容量/成本"关系，以及**局部性原理**（时间/空间）的作用。
  2. 机器字长 / 数据通路宽度 / 存储器字长 的**辨析**（最易出选择题混淆）。
  3. 地址线位数 ↔ 寻址空间（如 20 位→1MB、32 位→4GB、36 位→64GB）计算。
  4. 字长对整数表示范围的决定（溢出问题）。
- **易错点**：(a) 把字长等同于数据通路宽度；(b) "32 位系统内存上限 4GB"的根因是**地址总线 32 位（寻址 2³²）**，不只是"CPU 是 32 位"一句话；(c) 字长通常指**运算器一次处理位数**，不是"操作系统位数"的同义反复——但二者通常一致。
- **标准口径**：机器字长 = ALU/寄存器位宽，决定运算能力与地址空间；数据通路宽度 = 部件间一次并行传输位数，决定传输吞吐；二者独立，可不相等。
