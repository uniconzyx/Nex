# 主要性能指标：时钟周期/主频、CPI、MIPS、FLOPS、Amdahl 加速比

## 1. 背景/动机

"机器快不快"是工程里最常被问、也最容易被答错的问题。很多人张口就是"我 CPU 3.5GHz，比你 2.0GHz 快"。但**主频只是节拍器**，真实快慢由"干了多少活 × 每活几拍 × 每秒几拍"共同决定。本章把所有性能抓手统一到一条主公式下，并给出量化加速的硬上限（Amdahl 定律）。

## 2. 定义/要点

**核心公式（必须背）**：

```text
CPU 时间 = 指令数(IC) × CPI ÷ 主频(f)
         = 指令数 × 每条指令平均时钟周期数 ÷ 时钟频率
```

- **时钟周期 T** = 1 / 主频 f。主频 1 GHz ⇒ 周期 1 ns。
- **主频 f**：每秒时钟周期数（Hz）。越高≠越快（见陷阱 #1）。
- **CPI**（Cycles Per Instruction）：执行**一条**指令平均需要的时钟周期数。注意它是**指令混布的加权平均**，不是常数（见陷阱 #5）：

```text
平均 CPI = Σ (第 i 类指令占比 × 该类指令 CPI)
例：整数 60%@CPI1，浮点 30%@CPI2，访存 10%@CPI4
   → 0.6×1 + 0.3×2 + 0.1×4 = 1.6
```

- **IPC**（Instructions Per Cycle）= 1 / CPI，每周期执行多少条指令。
- **MIPS**（Million Instructions Per Second）= f ÷ (CPI × 10⁶)。**仅在同一 ISA 内有比较意义**（陷阱 #8）。
- **FLOPS**（Floating-point Operations Per Second）：衡量浮点算力，常用 GFLOPS/TFLOPS/PFLOPS（10⁹/10¹²/10¹⁵）。适合比算力，跨架构也比 MIPS 公平。
- **吞吐率（Throughput）**：单位时间完成的任务数/指令数/事务数（如 300 req/s）。
- **响应时间（Response time / 等待时间）**：从发出请求到收到结果的总时间（含排队、计算、IO 等待）。延迟敏感业务（如推荐、交易）看这个。
- **加速比 S = 老时间 / 新时间**；若新时间 = 老时间 / k，则 S = k。

**Amdahl 定律（量化加速的硬上限）**：

```text
设可优化部分在原任务占比为 f（0≤f≤1），该部分加速 S 倍，
则整体加速比：
        S_total = 1 / ( (1 − f) + f / S )

当 S → ∞（把可优化部分瞬间完成）：
        S_max = 1 / (1 − f)
例：f=0.9, S→∞ ⇒ 上限 1/0.1 = 10 倍；f=0.5 ⇒ 上限 2 倍
```

含义：系统的整体加速**受串行部分（1−f）钳制**。只堆可优化部分的硬件，收益会很快饱和（陷阱 #7）。

```text
性能关系一览：
  CPU时间 ↑  ⟺   指令数↑ / CPI↑ / 主频↓
  主频↑     ⟹   周期↓（但 CPI 可能变化）
  优化算法  ⟹   指令数↓    （最能影响，且不限 Amdahl 上限）
  优化微架构⟹   CPI↓       （受 Amdahl：仅当该部分占比高才有效）
```

## 三视角解析

### 🧑‍💻 程序员视角
- **选型与排查都用得上**。真实工作场景：团队要换一批推理服务器，A 卡主频 2.0 GHz、B 卡 2.5 GHz，老板倾向 B"主频高 25%肯定快"。我们按公式算：同样模型（指令数 IC 近似相同），A 的 IPC 约 1.4、B 约 1.1（B 频率高但流水线更深、分支预测弱）。CPU 时间 ∝ CPI/主频 → A: 1/1.4≈0.71，B: 1/1.1≈0.91。结果 A 反而快约 28%。**只看主频会被坑**——得看 CPI/ IPC。
- **定位瓶颈**：线上服务慢，先拆维度。CPU 利用率高、缓存命中率高 → 多半是**指令数太多**（算法/实现问题）；CPU 不高但 P99 大 → 多半是**访存/IO 等待**（响应时间里排队与等待占比高）。这直接决定你是去改算法还是去加缓存/换 SSD。
- 估算 MIPS 用公式即可：`MIPS = f / (CPI × 1e6)`，例如 3 GHz、CPI=1.5 → 3e9/(1.5e6)=2000 MIPS=2.0 GIPS。

### 🎓 博士生视角
- Amdahl 定律可推广到**多段可优化**：若各部分占比 `f_i`、加速 `S_i`，整体加速 `= 1 / Σ(f_i / S_i + (1 − Σf_i))`。这是"系统加速受最慢串行段钳制"的形式化表述，与排队论里的瓶颈分析同源。
- 更深一层：**Amdahl 假设"任务总量固定"**。若任务可随算力扩展（如大规模并行仿真，给更多核就跑更大问题），则是 **Gustafson 定律**：`S = (1−f) + f × N`（问题规模随处理器数 N 线性放大），结论与 Amdahl 相反——并行越狠，能解决的总问题越大。两定律之争本质是"固定规模 vs 可扩展规模"的建模差异。
- CPI 本身是一个**条件期望**：`CPI = Σ P(op_i) · cycles(op_i)`，可进一步分解为 `CPI_base + 罚分(分支预测失败、Cache miss、TLB miss…)`，这把"微架构事件"和"宏观性能"通过一条等式连起来，是现代性能剖析（perf、VTune）的理论基础。

### 📚 考研者视角
- **408 高频计算题**（必练）：
  1. 给主频、指令数、CPI 求 CPU 时间（单位换算：GHz→周期 ns，注意 10⁹）。
  2. 给指令混布求平均 CPI（加权平均）。
  3. 给主频与 CPI 求 MIPS。
  4. **Amdahl 定律**：给 f 和 S（或给加速后占比）求整体加速比/上限。
- **标准口径**：CPU 时间 = IC × CPI ÷ f；MIPS = f ÷ (CPI×10⁶)；Amdahl 整体加速 = 1/((1−f)+f/S)。计算时务必统一单位（主频用 Hz 还是 MHz、时间用 s 还是 ms 要一致）。
- **易错点**：(a) 把 MIPS 当跨架构绝对指标；(b) Amdahl 里 S 与 f 张冠李戴；(c) "指令数减少"是最不受上限约束的优化（改变的是 IC，不在 Amdahl 的串行占比里），所以**算法优化往往比堆硬件更划算**——这是 408 简答题常让论证的点。
