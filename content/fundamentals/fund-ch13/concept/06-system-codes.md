# fund-ch13 · 计算机系统量化与层次

> §1–§5 偏概念，这一节把「性能」「加速」「透明性」落成可算的式子，408 选择题常考。

```text
性能公式的三条主线（单位统一到 s 再代）：
    CPU时间 = 指令数 × CPI × 时钟周期 = 指令数 × CPI / 主频
    MIPS    = 主频(MHz) / CPI
    加速比  = 1 / ((1-p) + p/k)        <- Amdahl：p 为可加速部分占比，k 为该部分提速倍数
                                       当 k→∞ 时上界收敛到 1/(1-p)
三层存储的量化视角：
    寄存器  <1ns  |  L1  ~1ns  |  L2 ~4ns  |  L3 ~15ns  |  内存 ~80ns  |  SSD ~100μs
    ——「层次结构 + 局部性」是把 80ns 的平均访问时间压到个位数的唯一办法
```

### 冯诺依曼瓶颈与改进

指令与数据走同一总线，CPU 与存储器速率差导致瓶颈。改进：缓存（弥合速率差）、指令流水线、多核、哈佛结构（指令/数据分开存储）。

### CPI / MIPS / FLOPS 计算

`CPU时间 = 指令数 × CPI × 时钟周期`；`MIPS = 指令数 / (执行秒数 × 10^6)`；`FLOPS` 看每秒浮点运算次数。注意 CPI 是「平均每条指令周期数」。

```python
insts, cpi, hz = 1_000_000, 1.5, 2e9
seconds = insts * cpi / hz
print(seconds)                  # 0.00075 s
print(insts / seconds / 1e6)    # 1333 MIPS
```

### 加速比 Amdahl 定律

`S = 1 / ((1−f) + f/s)`，`f` 是可加速部分占比，`s` 是该部分加速倍数。可加速比例越小，整体加速越受限。

```python
def amdahl(f, s): return 1 / ((1 - f) + f / s)
print(amdahl(0.4, 10))          # 1.56 倍
print(amdahl(0.95, 10))         # 6.13 倍（占比越大越好）
```

### 机器字长与寻址

字长决定一次处理位数与可寻址空间：`n` 位地址可寻 `2^n` 字节。64 位机能寻 16EB，远超 32 位的 4GB。

### 透明性层次分析

「对某层用户透明」= 该层看不到。Cache 对高级语言程序员透明，对汇编/编译器不透明。谈透明性必须指明「对谁」。

### 软硬件逻辑等价（微程序）

一条机器指令可用硬连线逻辑实现，也可用微程序（存控存里的微指令序列）实现——功能等价，只是性能/灵活性取舍。

### 数据通路与时钟周期

数据通路是「取指→译码→执行→访存→写回」的硬件路径；时钟周期要 >= 最慢段延迟，流水化可让吞吐接近每段时长。

### 层次化存储量化

容量越大越慢越便宜，层级间靠「局部性」命中上级，使整体接近最快层的速率、接近最慢层的容量与成本。

## 三视角解析
### 🧑‍💻 程序员视角
性能公式不是考卷上的装饰：`perf stat` 打出来的 `instructions` 与 `cycles` 一比，就是 CPI。凯喵排查一个报表接口慢，第一反应是「CPU 不行」，实测 CPI 只有 0.9，说明 CPU 吃饱了在等——真正的病根是一次请求发了 3000 条 SQL，指令数比同事实例高两个数量级。**优化先问「能不能少做」，再问「每条能不能更快」**：加索引减少的是访存指令数，批量化减少的是往返次数，换更高主频只是把 CPI 的分母抬高，收益远不如前两者。另一个坑是拿 MIPS 跨架构比机器：同一条 `memcpy` 在 CISC 上是一条指令、在 RISC 上要十几条，MIPS 高不代表程序快，只有「跑完同一负载的墙钟时间」可比。

### 🎓 博士生视角
Amdahl 定律可以写成加速比上界 `S ≤ 1 / ((1-p) + p/k)`，当 `k → ∞` 时上界收敛到 `1/(1-p)`。这个式子的意义不是算数，而是给出了**优化的天花板**：串行部分占 10%，无论并行度多高都拿不到 10 倍。更严格地说，CPI 是「指令级」的宏观量，在乱序多发射处理器上它已被 IPC 取代，因为同一时刻有多条指令在飞；此时性能模型要换成 `Time = (Instructions / IPC) × CycleTime`，且 IPC 受限于依赖链长度、发射宽度与重排序窗口，不再是一个常数。工程上更常用 Roofline 模型：`Attainable = min(Peak FLOPs, Bandwidth × Arithmetic Intensity)`，它把「算力受限」和「带宽受限」画在同一张图上，比单一 CPI 更能指导优化方向。

### 📚 考研者视角
408 选择题固定考三件事，公式必须默写到不假思索：
1. **CPU 时间三因子**：`CPU时间 = 指令数 × CPI × 时钟周期 = 指令数 × CPI / 主频`。给出主频单位 GHz 时先换成 `10^9 Hz`，这一步每年都有人栽。
2. **CPI 的加权平均**：多条指令混合时 `CPI = Σ(CPI_i × 占比_i)`，占比之和必须为 1。题目常给「指令类型 A 占 40%，CPI=2」这样的表格，直接加权即可。
3. **加速比与 Amdahl**：`加速比 = 旧时间 / 新时间`；「某部分提速 k 倍、占比 p」则整体加速比为 `1 / ((1-p) + p/k)`。注意区分「加速比」与「效率」，后者要除以处理器数。
另外 MIPS 的定义式 `MIPS = 主频(MHz) / CPI` 常被拿来反算 CPI，别和 `指令数/时间` 混淆——两者等价的前提是主频用 MHz。
