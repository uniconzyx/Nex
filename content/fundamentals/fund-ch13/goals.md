# fund-ch13 学习目标：计算机系统概述

> 一句话引出本章：为什么程序员需要懂"计算机到底由什么组成、怎么衡量快慢"？——因为**你写的每一行代码最终都落在五大部件上**，而"快不快"不是形容词，是由主频、CPI、指令数、存储层次共同决定的可量化指标。不懂组成原理，性能优化就是盲猜；不懂衡量方法，你永远说不清"为什么换了更好的 CPU 反而更慢"。

## 一、知识目标

1. **说清计算机硬件五大部件**：运算器（ALU/寄存器）、控制器（取指·译码·执行）、存储器（主存/缓存）、输入设备、输出设备，以及它们通过**数据总线 / 地址总线 / 控制总线**如何协作完成一条指令。
2. **掌握冯·诺依曼结构的核心五特征**：存储程序、指令驱动、二进制表示、运算器中心、五大部件。能讲清"存储程序"与"指令驱动"到底改变了什么（对比手摇/插线计算机）。
3. **区分冯·诺依曼结构与哈佛结构**：核心差异是"指令与数据是否分存"；能说明现代 CPU（指令 cache 与数据 cache 分离）其实是一种改良哈佛结构，以及这种区分在嵌入式/单片机上的真实意义。
4. **理解层次化存储与"透明性"**：寄存器→Cache→主存→磁盘→网络存储的金字塔，以及"某层对程序员是否透明"的判断方法；能解释为什么你在 C 里写 `a[i]` 完全不用管它此刻在 L1 还是主存。
5. **掌握主要性能指标及其关系**：时钟周期/主频、CPI、IPC、MIPS、FLOPS、吞吐率、响应时间、加速比（Amdahl 定律），并用统一公式串起来：CPU 时间 = 指令数 × CPI ÷ 主频。
6. **理解机器字长与数据通路宽度**：字长决定 ALU 一次处理多少位、地址总线位数决定可寻址空间；数据通路宽度决定一次能在部件间搬多少位，二者常被混淆但含义不同。
7. **理解软硬件的逻辑等价性（固件）**：同一功能既可用硬件电路实现，也可写成软件/微程序实现；固件介于二者之间，能举例说明"用软件模拟硬件"在工程上的取舍。

## 二、能力目标

- 能给一个真实系统（手机 SoC / 服务器 CPU / 单片机）**画出五大部件的协作数据流**，并指出瓶颈在哪条总线。
- 拿到一组硬件参数（主频、CPI、指令混布、缓存命中率）能**手算 CPU 时间、MIPS、AMAT、Amdahl 加速比**，而不是只会看跑分软件。
- 能在做技术选型/性能排查时，用本章指标**定位瓶颈**：是"指令太多"（算法问题）、"CPI 太高"（微架构/分支预测问题）、还是"访存太慢"（存储层次/缓存问题）。
- 能向非科班同事用"透明性""存储层次"解释**为什么加内存、换 SSD、调大缓存命中率**会有效或无效。

## 四、前置

本章独立自足（或前置：无）。仅需最基础的二进制与"程序=指令序列"的直觉，不需要任何先修章节，建议放在数据表示、存储、CPU、总线、IO 之前作为总览。

## 五、本章与后续的关系

| 后续章节 | 本章为它埋下的种子 |
|---|---|
| 数据表示（定点/浮点） | 机器字长决定了能直接运算的位数，溢出与精度都源于此 |
| 存储器与 Cache | 层次化存储 + 透明性：本章讲"为什么有 Cache、它对程序员透明" |
| CPU 数据通路与指令系统 | 五大部件中的运算器/控制器细化；CPI 就来自指令执行的具体微操作 |
| 总线 | 五大部件靠总线连接，本章的"数据通路宽度"在总线章展开 |
| 输入输出（IO） | 输入/输出设备的控制方式（程序查询/中断/DMA）是五大部件协作的延伸 |
