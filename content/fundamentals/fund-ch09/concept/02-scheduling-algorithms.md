# 处理机调度：六种算法的演算与对比

## 1. 调度的三个层次与评价指标

**三级调度**：
- **高级调度（作业调度）**：从外存后备队列选作业调入内存（次数少，分钟级）；
- **中级调度（内存调度）**：把暂时不能运行的进程换出到外存（挂起态），需要时再换入；
- **低级调度（进程调度）**：从就绪队列选进程分配 CPU（**最基本，必须配置**，毫秒级）。

**评价指标（必背公式）**：

| 指标 | 公式 | 含义 |
|---|---|---|
| 周转时间 | `完成时间 − 到达时间` | 从提交到完成的总时间 |
| 平均周转时间 | `Σ 周转 / n` | 越低越好 |
| 带权周转时间 | `周转时间 / 服务时间` | ≥1，越接近 1 越优 |
| 等待时间 | `周转时间 − 服务时间` | 在就绪队列里等的总时间 |
| 响应时间 | `首次被响应时刻 − 到达时间` | 交互式系统的关键指标 |

## 2. 六种调度算法

### ① FCFS（先来先服务）
按到达顺序服务，**非抢占**。对长作业有利、对短作业不利；
**护航效应（convoy effect）**：一个长作业后面跟着一堆短作业，短作业的带权周转时间会非常大。
对 CPU 密集型进程有利，对 I/O 密集型不利（I/O 设备空闲）。

### ② SJF / SPF（短作业/短进程优先）
每次选**估计运行时间最短**的。可证明：**在所有进程同时到达时，SJF 的平均周转时间最小**（最优）。
缺点：**长作业饥饿**；且「运行时间」只能靠估计（用上一轮实际运行时间做指数平滑预测）。
分为非抢占（SPF）与抢占版（**SRTN，最短剩余时间优先**）。

### ③ HRRN（高响应比优先）
`响应比 = (等待时间 + 服务时间) / 服务时间 = 1 + 等待时间/服务时间`
**非抢占**。它动态地兼顾了 SJF（服务时间短的响应比高）与 FCFS（等待久的响应比升高），
**不会让长作业饥饿**——等待越久响应比越高。这是 408 的高频考点。

### ④ RR（时间片轮转）
按 FCFS 排成队列，每个进程用完一个**时间片**就被剥夺并排到队尾。**抢占式**，专为分时系统设计。
时间片 q 的选取：
- q 太大 → 退化为 FCFS，响应时间变差；
- q 太小 → 切换过于频繁，上下文切换开销占比过高；
- 经验取法：**q 略大于一次典型交互的时间**（保证 80% 的交互在一个时间片内完成）。

### ⑤ 优先级调度
每个进程一个优先级，选最高者。分**静态优先级**（创建时确定，不变）与**动态优先级**
（随等待时间升高而提高，用于防饥饿——**老化 aging** 技术）。
可抢占或不可抢占。

### ⑥ MLFQ（多级反馈队列）—— UNIX/Windows 的实际做法
设多个就绪队列，优先级从高到低，**时间片逐级加倍**；
新进程进最高级队列，用完时间片未完成则**降级**；
低优先级队列长时间得不到服务则**升级**（老化）。
**它是 RR + 优先级 + 老化的综合**，兼具响应时间短（交互式进程在高优先级）与周转时间可接受（长作业最终在低级队列大时间片跑完）。

### 🧑‍💻 程序员视角

现代 OS 的实际调度器：Linux 的 **CFS（完全公平调度器）** 不用时间片，
而是给每个进程维护 **vruntime（虚拟运行时间）**，每次选 vruntime 最小的运行——
本质上是「按权重比例公平分配 CPU」，`nice` 值就是权重的体现。
Java 线程优先级在 Linux 上基本无效（映射到 nice 值，而 CFS 下差别很小），
**不要依赖 Java 线程优先级保证执行顺序**。

工程上真正该关心的是：① 别让线程数远超核数（避免切换开销与内存）；
② I/O 密集型与 CPU 密集型任务**分开用不同的线程池**（前者可以多给线程，后者应≈核数）；
③ 用 `taskset`/cgroup 做 CPU 亲和性绑定，减少跨核缓存失效。

### 🎓 博士生视角

SJF 最优性的证明用**交换论证（exchange argument）**：
设有两个进程 i、j，服务时间 t_i < t_j，若调度顺序中 j 在 i 前，
则交换二者后，j 的完成时间推后 t_i、i 的完成时间提前 t_j，
总周转时间的变化为 `Δ = t_i − t_j < 0`，即总周转时间下降。
反复交换直到有序，即得最短服务时间优先的顺序最优。

而 MLFQ 的巧妙之处在于它**不需要预知运行时间**：
用「降级」隐式识别出长作业（跑不完一个时间片就说明它不是交互式的），
这本质上是一种**在线学习**——用过去行为预测未来，与 SJF 的指数平滑预测同源。

### 📚 考研者视角

**必背对照表**：

| 算法 | 是否抢占 | 特点 | 是否饥饿 |
|---|---|---|---|
| FCFS | 非抢占 | 有利于长作业、CPU 密集型；有护航效应 | 否 |
| SJF/SPF | 非抢占 | **平均周转时间最小**（同时到达时） | **是**（长作业） |
| SRTN | 抢占 | 最短剩余时间优先，SJF 的抢占版 | 是 |
| HRRN | 非抢占 | 响应比动态升高，**兼顾长短** | 否 |
| RR | 抢占 | 为分时设计，响应时间好，周转时间一般 | 否 |
| 优先级 | 可抢占/不可抢占 | 实时系统常用；需老化防饥饿 | 可能 |
| MLFQ | 抢占 | 综合最优，实际 OS 采用 | 否（有老化） |

**计算题标准步骤**：画甘特图 → 算每个进程的完成时间 → 算周转 → 算带权周转 → 取平均。
**高频陷阱**：问「**平均周转时间最小**的算法」——答案 **SJF**（前提：同时到达、非抢占）；
若问「**响应时间**最短」——答案 **RR**。

## 3. 实时调度简介

实时系统要求**在截止时间内完成**。
- **硬实时**：超时即失败（飞行控制、工业控制）；
- **软实时**：偶尔超时可接受（音视频播放）。

经典算法：**RM（速率单调，周期越短优先级越高）**、**EDF（最早截止时间优先）**。
RM 的可调度充要条件（Liu & Layland）：n 个任务在 RM 下可调度的充分条件是
`Σ(C_i/T_i) ≤ n(2^{1/n} − 1)`，n→∞ 时上界趋于 **ln2 ≈ 0.693**。
这是 408 的常见冷门考点。

### 🧑‍💻 程序员视角

实时性在通用 OS 上做不到硬实时——Linux 的 `SCHED_FIFO`/`SCHED_RR` 只是软实时，
内核里还有不可抢占的临界区。真正需要硬实时要上 RTOS（FreeRTOS、VxWorks）或
Linux 的 PREEMPT_RT 补丁。音视频、高频交易场景要注意 GC 停顿与页错误带来的抖动。

### 🎓 博士生视角

Liu & Layland 的 69.3% 上界揭示了一个深刻事实：**固定优先级调度无法充分利用 CPU**，
最坏情况下 CPU 利用率只能到 69.3% 就必须保证可调度。而 **EDF 是动态优先级的最优算法**，
可调度上界为 **100%**（只要 `Σ(C_i/T_i) ≤ 1` 就一定可调度）。
这个对比是「静态策略 vs 动态策略」在可调度性上的经典结论。

### 📚 考研者视角

**必背**：硬实时 / 软实时的区别；RM = 周期短优先；EDF = 截止早优先；
RM 可调度上界 `n(2^{1/n} − 1)`，n→∞ 时 → **ln2 ≈ 0.69**；EDF 上界 100%。

**易错**：把「RM 是静态优先级、EDF 是动态优先级」记反；
记不住上界公式时至少记住 **0.69 / ln2** 这个数。
