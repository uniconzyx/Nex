# 四种机器数：原码、反码、补码、移码

## 1. 为什么要发明补码

先看一个朴素想法：用一个 bit 专门当符号位，其余 bit 存绝对值 —— 这就是**原码**。
它直观，但会让硬件设计师绝望：

- **有两个零**：`0000_0000`（+0）与 `1000_0000`（-0），比较大小要先判符号，电路复杂一倍；
- **加减法不能统一**：`5 + (-3)` 不能直接按位加，必须"先比大小、再定符号、再做大减小"。

**补码**的动机可以用一句话概括：**把减法变成加法**。

在模 $2^n$ 意义下，$-x$ 与 $2^n - x$ 是同余的。8 位下 $-3 \equiv 253$，
于是 $5 + (-3) = 5 + 253 = 258 \equiv 2 \pmod{256}$ —— 结果正确，而且**加法器不用改**，
进位自然丢弃就完成了取模。这就是"补码"名字的来源：$-x$ 的补码是 $x$ 的"模补数"。

## 2. 四种表示的定义

设机器字长 $n$ 位，最高位 $x_{n-1}$ 为符号位，真值 $x$（以 $n=8$ 为例）：

| 表示法 | 正数 / 零 | 负数 | 特点 |
|---|---|---|---|
| **原码** | 最高位 0，其余同 $\lvert x \rvert$ | 最高位 1，其余同 $\lvert x \rvert$ | 有 ±0；表示范围 $-(2^{n-1}-1) \sim +(2^{n-1}-1)$ |
| **反码** | 同原码 | 符号位不变，数值位**逐位取反** | 仍有 ±0；几乎只作补码的中间步骤 |
| **补码** | 同原码 | 反码 + 1（即 $2^n - \lvert x \rvert$） | **唯一一个 0**；范围 $-(2^{n-1}) \sim +(2^{n-1}-1)$ |
| **移码** | 真值 + 偏置（通常 $2^{n-1}$） | 同左 | 用于**阶码**，让"比大小"退化为"无符号比较" |

关键数字（$n=8$）：补码范围 $-128 \sim +127$，**负数比正数多一个**，
因为 `1000_0000` 被定义为 $-128$（它没有对应的原码表示）。

## 3. 手算口径

- **原码 → 补码**：符号位不动，数值位取反加一。正数三者相同，不用转换。
- **补码 → 真值**：若符号位为 1，按 `取反加一` 还原绝对值再加负号；或直接按位权展开：
  $-128 + \sum_{i} b_i 2^i$。
- **移码 = 补码的符号位取反**（这一条在 IEEE 754 里到处用）。

## 4. 为什么 IEEE 754 的阶码用移码

浮点数要比较大小，阶码是"主序"。若阶码用补码，负数阶码最高位为 1，
无符号比较时负数会被误判为"很大"。用移码（真值 + 偏置）把阶码抬成**全非负**，
硬件上就能直接用无符号比较器判阶码大小 —— **比较电路省一半**。

这正是工程里"改变编码让电路变简单"的典型手法。

## 5. 现代 CPU 的实际选择

现代通用 CPU **只有补码**，没有原码/反码运算单元。原码只出现在：
- 浮点数的**符号位**（IEEE 754 用"符号 + 幅值"表示尾数符号）；
- 少数专用场景（比如某些定点 DSP 的原码乘、以及教材的中间步骤）。

## 三视角解析

### 🧑‍💻 程序员视角

**工程决策树：看到"位运算"先问三件事**

1. **有符号还是无符号？** C/C++ 里有符号数的右移是**实现定义**（gcc 上做算术右移），
   无符号一定是逻辑右移。做位掩码、哈希、协议解析时**一律用无符号类型**，
   否则 `x >> 1` 的行为在负数上不可移植。
2. **移位会不会越界？** `1 << 31` 在 `int` 上是**未定义行为**（有符号溢出），
   正确写法是 `1u << 31`。这类 bug 在开启 `-fstrict-overflow` 优化后会被"优化掉"。
3. **有没有隐式符号转换？** `unsigned int u = 1; if (u > -1)` 恒为真，因为 `-1` 被转成了 `UINT_MAX`。
   编译器会警告 `-Wsign-compare`，**别关掉这个警告**。

**排查顺序**：先看类型签名（`-Wsign-conversion`）→ 再看是否有 UB（`-fsanitize=undefined`）→
最后才怀疑算法逻辑。位级 bug 几乎都出在前两步。

**为什么"负数右移"要小心**：`-8 >> 1` 在算术右移下是 `-4`（向下取整），
而 `-7 / 2` 是 `-3`（向零取整）。两者不等 —— 用移位代替除法**只对非负数成立**。

### 🎓 博士生视角

**第一性原理：补码不是"约定"，而是环 $\mathbb{Z}/2^n\mathbb{Z}$ 的天然表示。**

$n$ 位补码建立了一一对应 $\varphi: \{-2^{n-1}, \dots, 2^{n-1}-1\} \to \{0,\dots,2^n-1\}$，
且满足 $\varphi(a + b) = (\varphi(a) + \varphi(b)) \bmod 2^n$ —— 即**同构于模 $2^n$ 加法群**。
因此加法器天然正确，减法退化为加补码，乘法、移位也都有对应的模运算解释。
相反，原码不能构成群（±0 让"逆元"不唯一），所以原码上的加减法必须**分支处理**。

**移码与偏置的意义**：移码就是把区间 $[-2^{n-1}, 2^{n-1}-1]$ 平移到 $[0, 2^n-1]$，
使序关系 $\le$ 在两种编码下一致。这本质上是"找一个保序双射"，
在对数域、定点 DSP、以及"浮点数的对数近似"（如 fast log2 算法）里反复出现。

**舍入的边界**：需要意识到补码的"溢出"与浮点的"上溢"是两码事 ——
整数溢出是**模回绕**（在无符号下被标准明确定义），浮点上溢是**饱和到 Inf**。
前者是代数结构决定的，后者是 IEEE 754 规范人为规定的。

### 📚 考研者视角

**高频考点 1：给定机器数求真值。**
标准答法：先判符号位，再按规则还原。
> 例：8 位补码 `1011_0110` 的真值？答：符号位 1 为负，取反得 `0100_1001`，加 1 得 `0100_1010` = 74，
> 故真值为 **-74**。（也可按位权：$-128 + 32 + 16 + 4 + 2 = -74$，两法互验。）

**高频考点 2：把 -0 与 -128 问清楚。**
- 原码/反码有 ±0，补码**只有一个 0**；
- **`1000_0000` 在补码里是 $-2^{n-1}$（8 位即 -128），它不是"-0"**；
- 因此补码的负数范围比正数范围**多一个**。

**高频考点 3：$n$ 位补码的范围必须背成条件反射。**

$$-2^{n-1} \le x \le 2^{n-1} - 1$$

**高频考点 4：移码的定义与用途。**
> 移码 = 真值 + $2^{n-1}$；IEEE 754 阶码用移码（单精度偏置 127），**目的是便于比较阶码大小**。

**易错口径**：
1. 反码的"取反"**不包括符号位**（说成"全部取反"必扣分）；
2. 补码求负是"取反加一"应用于**数值位**，正数转补码**不需要**这一步；
3. 别把补码范围写成 $-(2^{n-1}-1)$ —— 那是原码的范围。
