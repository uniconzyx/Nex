# IEEE 754：浮点数的机器表示与特殊值

## 1. 为什么不用定点数

定点数把小数点位置**写死**在某个 bit 上，表示范围与精度互相绑死：
要表示 $10^{-9}$ 就得准备 30 位小数，而这时整数部分只剩 2 位。
浮点数用**科学计数法**解决这个矛盾：小数点位置由**阶码**动态指定。

$$x = (-1)^S \times M \times 2^{E}$$

## 2. IEEE 754 单精度（binary32）的位布局

```
 bit: 31        30 ......... 23   22 ................... 0
      ┌───┬──────────────────────┬────────────────────────┐
      │ S │        E (8 位)       │       M (23 位)         │
      └───┴──────────────────────┴────────────────────────┘
        1        阶码（偏置 127）          尾数（隐含最高位 1）
```

- **符号位 $S$**：0 正 1 负。注意 IEEE 754 用**符号 + 幅值**，不是补码。
- **阶码 $E$（8 位）**：存放的是 $e + 127$（**偏置 127**，即移码）。所以真阶码 $e = E - 127$。
- **尾数 $M$（23 位）**：**隐含最高位 1**，即实际有效数字是 $1.M$。
  这一招叫"隐藏位"，白赚 1 位精度。所以单精度的有效位是 **24 位**。

真值公式（规格化数，$1 \le E \le 254$）：

$$x = (-1)^S \times 1.M \times 2^{E-127}$$

双精度（binary64）：S=1 位、E=11 位（偏置 **1023**）、M=52 位、有效位 53 位。

## 3. 三类特殊编码（必须背）

| E 全 0 | E 全 1 | M 全 0 | M ≠ 0 | 含义 |
|---|---|---|---|---|
| ✓ | | ✓ | | **±0** |
| ✓ | | | ✓ | **非规格化数**：$x = (-1)^S \times 0.M \times 2^{-126}$ |
| | ✓ | ✓ | | **±∞** |
| | ✓ | | ✓ | **NaN**（Not a Number） |

两个关键点：

1. **偏置要"减一"**：非规格化数的公式里指数固定为 $-126$（= $1-127$）而不是 $-127$。
   这样设计是为了让**最大的非规格化数与最小的规格化数无缝衔接**（渐进下溢）。
2. **NaN 的两种类型**：quiet NaN（`0.0/0.0`）会继续传播，signaling NaN 触发异常。
   Java 的 `Float.NaN`、C 的 `NAN` 都是 quiet NaN。

## 4. 为什么 0.1 存不准

十进制 $0.1 = 1/10$，其二进制展开是**无限循环**的：

$$0.1_{10} = 0.0001100110011\ldots_2 = 1.1001100110011\ldots_2 \times 2^{-4}$$

23 位尾数放不下无限循环，必须**截断/舍入**。于是存进去的值精确等于

$$0.100000001490116119384765625$$

（这就是 `printf("%.20f", 0.1)` 会看到的东西）。所以 `0.1 + 0.2` 得到的不是 $0.3$ 而是
$0.3000000000000000444\ldots$，**`0.1 + 0.2 == 0.3` 判为假**。

**这条不是 bug，而是二进制浮点的必然结果** —— 就像十进制里 $1/3$ 写不完一样。

## 5. 浮点数的比较

- **绝对相等几乎总是错的**：要用 `fabs(a - b) < eps`（绝对误差）或
  `fabs(a - b) <= eps * fmax(fabs(a), fabs(b))`（相对误差）。
- **`NaN != NaN` 恒真**，所以 `x != x` 是检测 NaN 的经典技巧（C99 起有 `isnan()`）。
- **不要用 `==` 比较浮点**，开启 `-Wfloat-equal` 让编译器帮你抓。

## 三视角解析

### 🧑‍💻 程序员视角

**工程决策树：什么时候能用 float/double？**

1. **要判断"相等"吗？** 要 → 你必须设计一个容差口径，或者干脆换整数/定点。
2. **是钱吗？** 是 → **绝对不要用二进制浮点**。金额用「最小货币单位的整数」（分）或十进制类型
   （Java `BigDecimal`、Python `decimal.Decimal`、C# `decimal`）。
3. **要做累积求和吗？** 是 → 大数吃小数会丢精度（经典案例：把 $10^7$ 和 $1.0$ 相加，
   结果仍是 $10^7$）。**按绝对值从小到大排**再加，或用 Kahan 补偿求和。
4. **要并发/确定性吗？** 是（科学计算复现、跨平台一致性）→ 小心 x87 80 位扩展精度、
   FMA 融合乘加、`-ffast-math` 会破坏结合律。

**排查一个"浮点算错"的顺序**：
① 打印 `%a`（十六进制浮点）看位模式 → ② 检查是否大数吃小数 → ③ 检查是否误用 `==` →
④ 检查是否发生非规格化下溢为 0（`FLT_MIN` 以下）。

**常用工具**：`printf("%a")` 打印精确位模式；`nextafter()` 取相邻可表示数；
`-fsanitize=float-cast-overflow` 抓浮点转整数的越界。

### 🎓 博士生视角

**非规格化数的设计动机（渐进下溢）。**
如果只有规格化数，最小正数是 $2^{-126}$，与 0 之间有个**巨大空洞**。
一旦结果小于它就直接跳到 0 （突然下溢），会让 `x - y == 0` 掩盖真实的微小差异，
并导致"除以微小量"爆炸。非规格化数把指数钉在 $-126$、放弃隐藏位，
从而在 0 附近提供**均匀间隔**的值，使误差随数值减小而平滑缩小。
代价是精度位数递减（精度损失，gradual underflow）。

**舍入的模式。** IEEE 754 定义了四种：就近偶数（默认）、朝零、朝 $+\infty$、朝 $-\infty$。
默认"**就近偶数**（round-to-nearest-ties-to-even）"的原因：它**无系统性偏差**——
若总是"四舍五入"，累加 $n$ 次的期望偏差是 $O(n)$ 而不是 $O(\sqrt n)$，误差会线性累积。
就近偶数在统计上把偏差抵消掉。

**误差界的经典结论。** 一次浮点运算的相对误差至多 $u = 2^{-p}$（$p$ 为有效位，单精度 $2^{-24}$），
称为 unit roundoff。$n$ 次累加的最坏情况误差界是 $O(nu)$，而**朴素求和的实际误差与 $n$ 相关**；
两两求和（pairwise）可降到 $O(\log n \cdot u)$ —— 这也是 `numpy.sum` 用 pairwise 的原因。

**结构对应关系**：浮点数系统 $\mathbb{F}$ 不是域（加法不满足结合律！），
但它是"近似封闭"的，且有唯一分解 $x = m\cdot 2^e$。
这个结构使它可以被看作**对数域上的等距网格**，从而解释了 `log2` 近似算法（fast inverse sqrt）的原理。

### 📚 考研者视角

**必背三个数**：单精度偏置 **127**、双精度偏置 **1023**、单精度有效位 **24**（含隐藏位）。

**高频考点 1：给定十进制小数，写出 IEEE 754 单精度位模式。**
标准四步答法：
1. 转二进制（含小数部分"乘 2 取整"）；
2. 写成 $1.xxx \times 2^e$ 的规格化形式；
3. 阶码字段 $= e + 127$（转 8 位二进制）；
4. 尾数取小数点后 23 位（不足补 0）。
> 例：$-0.5 \to -1.0 \times 2^{-1}$ → $S=1$，$E = -1 + 127 = 126 = 0111\_1110$，
> $M = 000\ldots0$ → `1 01111110 00000000000000000000000` = `0xBF000000`。

**高频考点 2：给定位模式，求真值。** 按公式反推，注意 $E$ 全 0 / 全 1 的特殊处理。

**高频考点 3：为什么阶码用移码而不用补码？**
> 为了**便于比较阶码大小**（移码保持序关系，可直接用无符号比较器）。

**高频考点 4：浮点加减法五步。**
> ① **对阶**（小阶向大阶看齐，尾数右移）→ ② 尾数加减 → ③ **规格化**（左规/右规）→
> ④ 舍入（就近偶数）→ ⑤ 判溢出（阶码上溢为 $\infty$，下溢为 0）。
> **必须指出：对阶时右移会丢失低位，这是浮点加法误差的主要来源。**

**高频考点 5：0.1 + 0.2 ≠ 0.3 的原因（近年在概念题中出现）。**
> 0.1 与 0.2 的二进制为无限循环小数，存入双精度时已被舍入，
> 两者之和再舍入一次，得到的是 $0.30000000000000004$ 而非 0.3。
> 根因是**二进制浮点无法精确表示这些十进制小数**。

**易错口径**：
1. 隐藏位：规格化数的尾数**隐含最高位 1**，写位模式时常有人多写一位，必扣分；
2. 阶码的偏置：单精度是 127 不是 128（IEEE 的偏置定义为 $2^{k-1}-1$）；
3. 非规格化数指数是 $-126$ 而**不是** $-127$（"偏置减一"规则）；
4. $\pm 0$ 是有的（IEEE 754 保留 ±0），别与补码的"唯一 0"混淆。
