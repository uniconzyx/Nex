# 补码加减运算与溢出判断

## 1. 运算规则

设 $n$ 位完成补码加法 $[x]_补 + [y]_补$：

- **符号位与数值位一同参与运算**，产生的结果就是 $[x+y]_补$；
- 最高位产生的**进位直接丢弃**（这就是"模 $2^n$"的实现）；
- **减法**统一为 $[x - y]_补 = [x]_补 + [-y]_补$，其中 $[-y]_补$ 由 $[y]_补$ 连同符号位
  **全部取反再加 1** 得到。

这一点是补码最漂亮的地方：**减法不需要单独的电路**，加一个"取反加一"的前置逻辑即可。

## 2. 溢出：不是"进位"而是"结果超出可表示范围"

**溢出的必要条件是：两个同号数相加，结果的符号与之相反。** 两个异号数相加永不溢出。

### 判据一：单符号位 —— 符号位进位与数值位进位异或

设 $C_{n-1}$ 为符号位的进位（最高位向外的进位），$C_{n-2}$ 为最高数值位的进位，则

$$\text{溢出} = C_{n-1} \oplus C_{n-2}$$

直觉：正常情况下"内部进位"与"溢出进位"同进同出；一旦两者不同，
说明结果的符号被"顶翻"了。

### 判据二：双符号位（变形补码）

把符号位扩成两位：正数 `00`，负数 `11`。相加后看两位符号位：

- `00` → 正数，正确；
- `11` → 负数，正确；
- `01` → **正溢出**（上溢）；
- `10` → **负溢出**（下溢）。

双符号位的额外好处：**它还能区分"正确结果"与"溢出方向"**，
所以硬件里常用双符号位实现，代价只是多一个触发器。

### 判据三（工程口径）：同号相加、异号结果

$$\text{溢出} \iff (x_s = y_s) \land (result_s \ne x_s)$$

这一条最适合写代码，因为一行位运算就能判。

## 3. 无符号数的"溢出"其实是模回绕

对无符号数，C 语言标准**明确规定**运算按模 $2^n$ 回绕，**这不是 UB**：

```c
uint8_t a = 200, b = 100;
uint8_t c = a + b;      /* 300 mod 256 = 44，标准保证 */
```

而对有符号数，溢出是**未定义行为（UB）**——编译器可以假设它不发生，
并据此做激进的优化。所以"用无符号做哈希/校验和"不只是风格问题，而是**正确性问题**。

## 4. 溢出与饱和

工程上经常需要的不是"回绕"而是"饱和"（clamp 到类型边界）。这在音频处理、
图像像素运算、以及 NPU 的量化推理里是标准做法。C 语言没有内建饱和运算，
需要显式写，或者用编译器内建（`__builtin_add_overflow` 系列）来**先探测再决定**。

## 三视角解析

### 🧑‍💻 程序员视角

**排查顺序：先怀疑类型，再怀疑算法。**

1. **改用更宽类型是否就对了？** 如果 `int` 换 `int64_t` 后结果正确，那就是溢出，不是逻辑错。
2. **累加器是否选择了足够宽的类型？** 32 位累加 `n` 个 $2^{31}$ 量级的数必然溢出，
   而 `size_t`/`int64_t` 能顶住。
3. **是否在"乘完再存"？** `int a = x * y;` 里乘法本身在 `int` 域完成，
   即使 `a` 是 `int64_t` 也救不了。必须先提升：`(int64_t)x * y`。

**两个实战要点**

- **用 `-fsanitize=signed-integer-overflow` 抓有符号溢出**，它在 CI 里比 code review 有效得多；
- **需要主动检测溢出时用 `__builtin_add_overflow(&r, a, b)`**：
  它在**不引入 UB** 的前提下完成运算并返回是否溢出，比"先把操作数提升到更宽类型再比"更可靠。

**带符号 vs 无符号的除法**：`INT_MIN / -1` 在 `int` 上是 UB（结果 $2^{31}$ 无法表示），
而在 `int64_t` 上就正常。这也是"宽类型优先"的一个理由。

### 🎓 博士生视角

**为什么"同号相加"是必要条件而不是充分条件？**
溢出要求结果与数学真值的差恰为 $2^n$ 的整数倍方向。两异号数相加，真值落在一个
**绝对值不超过两操作数较大者**的区间内，因而必然在当前可表示范围内 —— 这是"异号不溢出"的证明思路：
设 $x \ge 0 > y$，则 $y \le x + y \le x$，两端都在范围内。

**UB 的语义学意义**：C 标准把有符号溢出定为 UB，目的是允许编译器假定数学整数语义成立，
从而把 `x + 1 > x` 优化为恒真。这不是"编译器流氓"，而是**语言选择把优化空间让给编译器**。
代价是程序员必须自己用无符号或内建函数表达"我要模运算"。

**与硬件的关系**：x86 的 `add` 指令**同时**写出结果与若干标志位（CF 进位、OF 溢出、SF 符号、ZF 零），
`OF = C_{n-1} \oplus C_{n-2}`。所以判据一不是教学玩具，而是**CPU 的物理实现**。
高级语言里"溢出检测慢"的说法，本质上是"语言没有把 OF 暴露出来"，而非硬件做不到。

### 📚 考研者视角

**必背公式（背到条件反射）**

$$[-y]_补 = \overline{[y]_补} + 1 \quad(\text{连同符号位一起取反})$$

**高频考点 1：给两个操作数与运算，问是否溢出、结果是啥。**
标准答法三步：① 写出两操作数补码；② 按位相加（符号位参与）；③ 用异或判据或"同号得异号"判溢出。
> 例：8 位下 $x = 105, y = 65$。$[x]_补 = 0110\_1001$，$[y]_补 = 0100\_0001$，
> 相加得 $1010\_1010$（进位丢弃）→ 两正数相加得负，**正溢出**。正确结果 170 超出 127。

**高频考点 2：双符号位判据的写法。**
> 变形补码 `00` 或 `11` 为正确，`01` 正溢出，`10` 负溢出。**必须记住 01 对应正溢出**（易错）。

**高频考点 3：溢出与进位的区别。**
> **进位只影响无符号数的正确性；溢出只影响有符号数的正确性。**
> 无符号加法有进位不代表有符号加法溢出，反之亦然。（这一条几乎每年都考概念辨析。）

**高频考点 4：$x - y$ 的溢出判断。**
> 化为 $x + (-y)$ 后按同号相加判据处理，**不要**去判减法本身。

**易错口径**：
1. 判溢出**不能**只看最高位有没有进位 —— 那是进位不是溢出；
2. "两个负数相加结果为正" = **负溢出**，别写成正溢出；
3. 无符号数谈"溢出"时，正确说法是**模 $2^n$ 回绕**，它不回绕成"错误"，只是语义上的取模。
