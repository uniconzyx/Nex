# 超标量、多发射与 CPU 性能公式

> 流水线之后如何进一步提速？本章第四篇讲"每个周期多干几件事"以及用公式量化性能。

## 1. 背景 / 动机

经典五段流水线是**单发射（single-issue）**：每个时钟周期最多"开始/完成一条"指令，理想 IPC ≤ 1。要让 IPC > 1，就得在同一拍**发射（issue）多条指令**进入多条并行的流水线——这就是**超标量（superscalar）/ 多发射**。再配合乱序执行、分支预测、超线程，现代 CPU 的 IPC 轻松达到 2~4 甚至更高。但"多发射"不等于"主频高"，真实性能必须回到**CPU 性能公式**用数据说话。

## 2. 定义 / 要点

### 2.1 CPU 性能公式（一切的起点）

```text
CPU 时间 = 程序指令数(IC) × 平均 CPI × 时钟周期时间(T_clock)
         = IC × CPI / 主频

其中：
 - IC  ：执行的指令条数（与 ISA、编译器、算法有关）
 - CPI ：每指令平均时钟周期数（与微架构、冒险、Cache 有关，是加权平均）
 - T_clock = 1 / 主频

推论：加速比也可写成  S = (IC × CPI_old) / (IC × CPI_new) = CPI_old / CPI_new
      （同程序、同主频下，性能提升只取决于 CPI 下降）
```

### 2.2 超标量与多发射

```text
单发射（每周期 ≤1 条，理想 CPI ≥ 1）：
  拍:  [I1][I2][I3][I4]...   一个发射口、一条流水线

超标量 2 发射（每周期最多 2 条，理想 CPI 可 = 0.5）：
  拍:  [I1 I2][I3 I4][I5 I6]...   两个发射口 + 多套执行单元
  约束：同拍发射的两条指令不能有结构/数据冒险（否则只能发 1 条或 stall）

多发射宽度 w：每周期最多发射 w 条 → 理想 IPC ≤ w
```

- **静态多发射**：编译器在编译期配对指令（VLIW 风格），硬件简单。
- **动态多发射（超标量）**：硬件运行时检测可并行指令对，灵活但控制复杂。

### 2.3 超线程（SMT）与多核

```text
超线程(SMT)：一个物理核内两套上下文(PC/寄存器)，共享执行单元/Cache。
  → 当一个线程因访存/分支停顿空出执行单元，另一线程立刻用上 → 提升吞吐
  → 但两线程共享 Cache/带宽，单线程延迟未必改善，甚至互相挤占而变慢
多核：多个完整核，真正并行，共享末级Cache；与超标量是正交的两个维度。
```

### 2.4 性能公式的"陷阱"：主频 ≠ 性能

```text
A 核：3.0 GHz，CPI = 1.5  → CPU时间 ∝ 1.5 / 3.0 = 0.50 (每指令)
B 核：2.5 GHz，CPI = 1.0  → CPU时间 ∝ 1.0 / 2.5 = 0.40 (每指令)
→ B 虽主频低，但 CPI 更优，跑同一程序更快！
```

## 三视角解析

### 🧑‍💻 程序员视角
**真实工作场景**：曾有一次线上服务迁移到新代 CPU（主频更低但更宽超标量 + 更好分支预测），单看主频以为会慢，实测 QPS 反而涨了 18%——因为 `perf` 显示热点 IPC 从 1.1 升到 1.7，CPI 下降盖过了主频下降（CPU 时间 ∝ CPI/主频）。另一个常见坑：把**串行瓶颈**的代码（长依赖链、大量分支、随机访存）搬到宽核上，IPC 上不去，多发射"吃不饱"，性能提升远不如预期。优化顺序应是：**先减 IC（更好算法/编译器）/ 减 CPI（消冒险、提预测命中）**，最后才看主频。超线程上线前务必 A/B：高并发下有时因共享 Cache 互相失效而劣化。

### 🎓 博士生视角
CPU 性能公式可写成约束优化：在 `IC × CPI × T_clock` 三维上，超标量/多发射是在**降低有效 CPI**（靠提高每拍完成指令数），但受到两个硬约束：(1) **指令级并行度（ILP）的天花板**——Amdahl 式定律表明，可并行部分占比决定多发射宽度的收益上限；(2) **冒险相关停顿**随宽度增加而更易触发（发射窗口里找不到不冲突的指令对）。因此真实 IPC 随发射宽度呈**边际递减**，而非线性。Tomasulo/乱序的本质就是**在不改程序语义的前提下，最大化每拍能合法并行发射的指令数**，把 CPI 向 `1/w` 逼近。

### 📚 考研者视角
408 考法聚焦"算"与"比"：
- **性能公式必背**：CPU 时间 = IC × CPI × T_clock = IC × CPI / 主频。给两组主频与 CPI，比较谁快、算加速比（同程序时 `S = CPI_old/CPI_new` 或考虑主频）。
- **超标量/多发射**：每周期发射多条，理想 IPC ≤ 发射宽度 w；**单发射理想 CPI≥1，超标量可 <1**。区分"流水线深度（段数）"与"发射宽度（每拍几条）"两个维度。
- **IPC 与 CPI 互为倒数**：IPC = 1/CPI。
- 超线程：**提升吞吐、不保证降延迟**，共享执行单元与 Cache，可能争用。
- 易错：把"多核"和"超标量"混为一谈；或认为"主频翻倍 = 性能翻倍"（忽略 CPI 与 IC）。
