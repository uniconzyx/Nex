# CPU 结构与数据通路

> 本章位置：fund-ch15 第一篇。先把"CPU 由什么组成、数据在内部怎么流动"讲清楚，才能理解后面流水线与冒险的来由。

## CPU 不是几个盒子：从寄存器堆到单总线数据通路

指令系统（fund-ch14）定义了"CPU 能做什么"——有哪些指令、操作码与地址码怎么编码、支持哪些寻址方式。但**指令本身只是一串二进制，真正让这串二进制"动起来"的是 CPU 的硬件结构**。

一个问题自然浮现：一条 `ADD R1, R2, R3`（R1 ← R2 + R3）从取指到写出结果，中间数据在哪些部件之间、沿什么路径流动？这些路径就是**数据通路（datapath）**。数据通路的设计直接决定了 CPU 的速度上限、冲突来源和复杂度。

## 数据通路的微操作序列与单总线为什么必须分多节拍

### 2.1 CPU 四大组成

```text
        ┌─────────────────────────────────────────────┐
        │                   CPU                         │
        │                                               │
        │   ┌──────────┐        ┌──────────┐            │
        │   │ 运算器 ALU│◀──────▶│ 寄存器堆 │            │
        │   │ (算/逻/移位)│       │ (通用+暂存)│            │
        │   └────┬─────┘        └────┬─────┘            │
        │        │                    │                  │
        │   ┌────▼────────────────────▼────┐            │
        │   │       内部总线 (单/多/专用)     │            │
        │   └────┬────────────────────┬────┘            │
        │        │                    │                  │
        │   ┌────▼────┐        ┌─────▼─────┐            │
        │   │ 控制器   │        │  MAR/MDR  │            │
        │   │(取指/译码/│        │ (地址/数据 │            │
        │   │ 发微命令) │        │  缓冲)    │            │
        │   └─────────┘        └──────────┘            │
        └─────────────────────────────────────────────┘
                   │
        系统总线 ──▶ 内存 / 外设（注意：这是系统总线，不是上面的内部总线）
```

- **运算器**：以 ALU 为核心，完成算术/逻辑/移位运算；结果常经暂存器、标志寄存器（零/溢/负/进位）反馈。
- **控制器**：取指令、分析操作码、按时序发出"微命令"驱动数据通路（控制 PC 自增、寄存器读使能、ALU 功能选择、写回使能等）。
- **寄存器**：PC（程序计数器）、IR（指令寄存器）、MAR/MDR、通用寄存器堆、PSW（状态字）、暂存器（ALU 的两个输入常要先锁存）。
- **内部总线**：上述部件之间的内部连线，是本章讨论"单/多/专用通路"的对象。

### 2.2 三种数据通路

```text
(1) 单总线结构：所有部件挂同一条内部总线，任意时刻只有一对部件能传数
       ALU ─┐
       REG ─┼──[内部总线]── MAR/MDR ─ 系统总线 ─▶ 内存
       PC  ─┘
       缺点：ALU 双操作数需分两拍（先送一个到暂存器）；总线是瓶颈。

(2) 多总线结构：2~3 条内部总线（如 A 总线 / B 总线 / 结果总线）
       ALU 可同时从总线A、总线B取两操作数，结果走结果总线
       并行度提高，节拍数下降，硬件成本上升。

(3) 专用通路（专用数据通路）：为关键路径单独连线（如 REG 直连 ALU 输入）
       速度最快、无总线争用，但连线爆炸、不灵活。
```

| 结构 | 并行度 | 节拍数 | 成本/复杂度 | 典型用途 |
|---|---|---|---|---|
| 单总线 | 低（分时） | 多 | 低 | 教学模型、简单 8/16 位机 |
| 多总线 | 中 | 中 | 中 | 多数经典设计 |
| 专用通路 | 高 | 少 | 高 | 高性能/超标量内部 |

### 2.3 取指—译码—执行的节拍（以单总线为例）

```text
一条 ADD R1,R2,R3 的典型流程（多周期，每拍走总线一次）：
  T1  PC → MAR, 读内存          （取指：送地址）
  T2  MDR → IR, PC+1 → PC       （取指：取回指令、PC 自增）
  T3  R2 → 暂存Y,  R3 → 暂存Z    （译码 + 取源操作数到 ALU 输入锁存）
  T4  Y + Z → 暂存结果          （执行：ALU 加法）
  T5  结果 → R1                 （写回）
  （若是间址/转移，还会插入间址周期、转移周期）
```

## 三视角解析

### 🧑‍💻 程序员视角
你写的 `a = b + c` 在机器里最终变成"从寄存器取两个操作数 → ALU 相加 → 写回寄存器"一连串受控的数据通路动作。**真实工作场景**：在性能敏感的服务里，我们常看 `perf stat` 的 `IPC`（每周期指令数）。如果一段热点 IPC 很低（比如 < 0.5），很多时候不是 ALU 慢，而是数据通路级别的依赖链太长——指令被卡在"等前一条结果"上（数据冒险，见 concept 03）。此时**重排计算顺序、减少跨寄存器长依赖链**比加 CPU 主频更管用。另一个场景：超线程（SMT）让两个线程共用一套运算器/数据通路，当一个线程在访存停顿时空出的执行单元给另一个线程用——本质就是"内部总线/执行单元别闲着"。

### 🎓 博士生视角
数据通路可以形式化为一个**有限状态机 + 数据流动网**：每个寄存器/暂存器是状态变量，每个时钟沿按控制信号的使能集合发生一次状态转移，ALU 是组合逻辑函数 `f(oper, A, B)`。控制器的输出是一组布尔微命令 `C(t)`，数据通路的合法行为约束为"同一总线同一拍至多一个驱动源"。从这个视角看，**单总线结构的瓶颈就是"总线带宽是 1 对 1 时分复用"这一约束**，而多总线/专用通路是在放松该约束——这是资源维度（结构冒险）与数据维度（数据冒险）冲突的统一出发点。

### 📚 考研者视角
408 计组 CPU 章的必背：
- **CPU 四部分**：运算器、控制器、寄存器、内部总线（注意问"内部总线"不要答成系统总线）。
- **单总线数据通路**：所有部件连一条内部总线，**同一时刻只能传送一对部件间的数据**，因此 ALU 两操作数要分拍送暂存器——这是单总线节拍数多的根本原因。
- **取指周期**一定包含：PC→MAR、存储器读、MDR→IR、PC+1；**间址周期**要再访存取有效地址；**执行周期**做运算。
- 常考：**给定指令与数据通路图，写出各机器周期/节拍的控制信号序列**（哪拍哪些寄存器读使能、ALU 选什么功能、哪拍写回）。答题模板就是上面 T1~T5 那样逐拍列信号。
