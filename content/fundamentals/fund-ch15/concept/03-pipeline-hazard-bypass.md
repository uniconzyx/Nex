# 流水线：时空图、吞吐率与三类冒险（旁路/预测/乱序）

> 流水线是 CPU 提速的核心手段。本章第三篇讲清"时空图怎么画、加速比怎么算、冒险怎么治"。

## 流水线为什么能加速：时空图、吞吐率与加速比的正确算法

单周期/多周期 CPU 每个时钟周期最多"在一条指令上推进一个阶段"，硬件利用率低。把一条指令的执行拆成若干**阶段（段）**，让多条指令在不同阶段**重叠**进行——这就是流水线。理想情况下 n 条 k 段指令总时间从 `n×k` 拍降到约 `n+k-1` 拍。但重叠会引入**冒险（hazard）**：当后续指令依赖前面还没完成的结果、或争用资源、或遇到分支时，流水线必须停顿或猜测，性能由此打折。

## 三类冒险的识别与对策：结构冒险、数据冒险、控制冒险

### 2.1 五段式流水线与时空图

经典 RISC 五段：`IF(取指) → ID(译码/取寄存器) → EX(执行/算地址) → MEM(访存) → WB(写回)`。

```text
时空图（4 条无冒险指令，每段 1 拍）：
 拍:  1   2   3   4   5   6   7   8
I1:  IF  ID  EX  MEM WB
I2:      IF  ID  EX  MEM WB
I3:          IF  ID  EX  MEM WB
I4:              IF  ID  EX  MEM WB
  → 4 条指令 8 拍完成（理想 = n + k - 1 = 4 + 5 - 1 = 8）
  → 稳态每拍流出 1 条，吞吐率 ≈ 1/拍
```

### 2.2 吞吐率 / 加速比 / 效率

```text
设 k 段流水线，处理 n 条指令，总时钟周期 T = k + (n-1) + 停顿拍
  吞吐率 TP = n / T           （单位：指令/拍；再 × 时钟频率得 指令/秒）
  实际加速比 S = (n × k) / T  （相对非流水 k 拍/条的理想）
  效率    E = (k × n 段·拍) / (k × T) = (n) / T = TP × 1拍
        （即"被占用的段·拍" / "总段·拍"）
理想（无停顿，n 很大）：TP → 1/拍，S → k，E → 1。
```

- **吞吐率瓶颈**：段间存在最慢段（瓶颈段），整体节拍受它限制，TP ≤ 1 / 瓶颈段时长。
- **效率随段数 k 增大、n 较小而下降**（填充/排空占比变大）。

### 2.3 三类冒险

```text
(1) 结构冒险（Structural）：两个指令同拍争同一资源
     例：单口存储器既要 IF 取指又要 MEM 访存 → 冲突
     解：分离 I-Cache / D-Cache、增加端口、或插入 stall

(2) 数据冒险（Data）：RAW/WAR/WAW，后指令要前指令还没写回的结果
     例： ADD R1,R2,R3
          SUB R4,R1,R5     ← R1 还没 WB，SUB 的 ID/EX 就要用 → RAW
     解：① 旁路/转发（forwarding）：把 EX/MEM 或 MEM/WB 的结果直接送回
           当前指令的 ALU 输入，避免等 WB；② load-use 来不及则插 1 拍 stall

(3) 控制冒险（Control）：遇分支，下一条该取哪？
     例： BEQ 之后，PC 目标未知，简单实现要等 EX 算出才知
     解：① 排空（最慢）；② 分支预测 + 预测执行；③ 延迟槽
```

### 2.4 旁路（转发）示意

```text
无旁路（RAW 需 2 暂停）：
I1: IF ID EX MEM WB
I2:    IF ID -- -- EX MEM WB      (两拍 stall 等 I1.WB)

有旁路（EX→EX 转发，0 暂停）：
I1: IF ID EX MEM WB
I2:    IF ID EX MEM WB            (I1.EX 结果在末尾直接旁路给 I2.EX 输入)
但 load-use：
I1: IF ID EX MEM WB               (结果在 MEM 末尾才出)
I2:    IF ID -- EX MEM WB          (仍须 1 拍 stall，因 MEM 才出数)
```

### 2.5 乱序执行与 Tomasulo 思想（简介）

```text
核心思想：别让"前面慢指令"堵死"后面无关快指令"。
 - 寄存器重命名：用保留站/物理寄存器消除 WAR、WAW 假相关
 - 保留站(Reservation Station)：指令发射后等操作数就绪即可乱序执行
 - 公共数据总线(CDB)：结果广播，所有等待者同时拿到
 - 顺序提交(Reorder Buffer)：执行可乱序，但写回/提交按程序顺序，保证异常正确
Tomasulo 是这一思想的奠基算法（1967）。
```

## 三视角解析

### 🧑‍💻 程序员视角
**真实工作场景**：用 `perf stat -e cycles,instructions,branch-misses,cache-misses` 看三个指标就能诊断大部分 CPU 侧瓶颈：
- `IPC = instructions / cycles` 低 → 多在停顿。若是 `branch-misses` 高，说明**控制冒险**严重（分支预测老误判），可改造成"无分支"写法（如用位运算/`cmov` 代替 `if`，或让热点循环分支更可预测）。
- 若是数据相关长链（如指针追逐 `a = a->next->next`），`load-use` 类停顿多，**旁路救不了访存延迟**，只能靠预取或重排数据布局（结构体数组 SoA）。
- 超线程在"一个线程访存停顿时空出执行单元给另一线程"，正是用**结构/数据冒险产生的空拍**换吞吐——但两个线程共享 Cache，互相争用反而可能降速，需实测。

### 🎓 博士生视角
冒险本质都可归约为**依赖在时空网格上的冲突**：
- 数据冒险 = 真/假**数据依赖**（RAW/WAR/WAW），RAW 是真相关无法消除，WAR/WAW 是"名字相关"可用**寄存器重命名**消除；
- 结构冒险 = **资源依赖**（同一硬件单元的时间冲突）；
- 控制冒险 = **控制依赖**（后续指令的存在性依赖分支结果）。
旁路是**用额外连线（空间）把"未来拍才写回的值"提前送到当前 ALU 输入**，把数据冒险的停顿从"等写回"压缩到"等产生"；load-use 仍要 stall 是因为访存延迟大于一个流水段。Tomasulo 用**动态调度**把"按序发射"和"乱序完成"解耦，再用 ROB 把"乱序完成"和"按序提交"解耦——三层解耦分别对应三类冒险的系统性解法。

### 📚 考研者视角
408 计组 CPU 大题绝对核心，务必会画会算：
- **时空图**：横轴拍、纵轴指令/段，重叠画。n 条 k 段理想总拍 = `n + k - 1`。
- **吞吐率 TP = n / 总拍**；**加速比 S = (n·k) / 总拍**；**效率 E = n / 总拍**（或 = 占用段拍 / 总段拍）。
- **三类冒险**：结构（争资源）、数据（RAW 最常见，用旁路/stall）、控制（分支，用预测/延迟槽）。考法：给指令序列，标出数据冒险位置、算插几个 stall，或"加旁路后能否消除"。
- **旁路能消 EX→EX 的 RAW，但 load-use（MEM 才出结果）仍需 1 拍 stall**——这是高频易错点。
- 控制冒险误预测惩罚 ≈ 流水线深度量级；算平均 CPI 时别忘乘 `误预测率 × 惩罚`。
- 乱序/Tomasulo：**简答**层面知道"寄存器重命名消 WAR/WAW、保留站、CDB、顺序提交"即可，不要求手算。
