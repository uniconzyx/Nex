# 哈希表：构造方法、冲突处理与装填因子

## 1. 哈希函数的构造方法

哈希表通过哈希函数 `h(key)` 把关键字映射到表地址。**构造方法**（408 常考）：

```
- 直接定址法：h(key) = a·key + b。适合关键字连续，无冲突但表大、不灵活。
- 除留余数法：h(key) = key mod p。最常用；p 取**不大于表长 m 的素数**，散列最均匀。
- 数字分析法：取关键字中「分布较随机」的若干位。适合关键字已知且位数固定。
- 平方取中法：key² 后取中间几位。中间位受各位影响，较均匀。
- 折叠法：把关键字分段叠加。适合位数很多的关键字。
```

### 🧑‍💻 程序员视角
- 工程里 99% 用「除留余数法 + 好一点的散列」，但**字符串/复合键**要用专门的字符串哈希（BKDR、DJB2、MurmurHash、FNV）。`std::unordered_map` 对字符串用的是 CityHash/Murmur 类高质量函数，而不是简单取模。
- p 取素数不是玄学：若 p 与 key 的某个因子有公因数，key 会只映射到少数桶。例如 key 都是偶数、p 取偶数 → 一半桶永远空。所以 p 取素数（且与数据分布互质）能打散聚集。

### 🎓 博士生视角
- 衡量散列质量的是「桶命中的分布接近均匀」：理想情况下每个桶命中概率 = 1/m，此时期望探测次数与 m（表长）而非 n 直接相关。除留余数法取素数 p 是为了让 `key mod p` 对常见结构化 key（等差、倍数）仍保持良好混合，等价于「模一个与数据周期互质的数」。数字分析/平方取中则是利用「高位变化慢、低位/中间位更随机」的经验规律。
- 从随机化视角，若把散列函数视为从「键分布」到「桶」的一个随机映射，则冲突数服从近似泊松分布，期望冲突数 = n(n−1)/(2m) ≈ n²/(2m)。这是后面 ASL 公式的概率学基础。

### 📚 考研者视角
- **408 统考点**：五种构造方法（直接定址、除留余数、数字分析、平方取中、折叠）的**定义与适用场景**；除留余数法 p 的取法（≤m 的素数）。
- **必背**：除留余数法 `h(key)=key mod p`，p 取**不大于 m 的素数**，冲突最少。
- **选择题常考**：给定一组 key，用某种方法手算地址；或问「哪种方法无冲突」（直接定址法，但浪费空间）。

## 2. 冲突处理：开放定址 vs 拉链法

冲突（不同 key 映射到同址）不可避免，两种主流策略：

```
开放定址（所有元素都在表里，冲突就找下一个空位）：
  - 线性探测：  hᵢ = (h(key) + i) mod m            （i=0,1,2,...）
  - 二次探测：  hᵢ = (h(key) + i²) mod m            （或 ±i²）
  - 双重散列：  hᵢ = (h₁(key) + i·h₂(key)) mod m     （再散列）
拉链法（链地址法）：同一桶的关键字挂成单链表（或动态数组）。
```

### 🧑‍💻 程序员视角
- 开放定址的「线性探测」有**一次聚集**：冲突会连成一片，ASL 随 α 飙升。工程上多用**双重散列或拉链法**规避。拉链法在 α 较高（0.9+）仍稳健，且支持「删除就是删链表节点」这种 O(1) 删除（开放定址删除要打 tombstone 标记，麻烦）。
- 现代语言默认哈希表（Python dict、Go map、Java HashMap）都是**拉链法（或开放寻址的变体 Robin Hood / Swiss Table）**。注意删除语义：开放定址不能简单置空（会切断后续探测链），必须标记「已删除」；拉链法直接断链即可。

### 🎓 博士生视角
- **线性探测**的期望 ASL 有闭式近似：成功 ASL ≈ (1 + 1/(1−α))/2，失败 ASL ≈ 1/(1−α)。当 α→1 失败 ASL→∞，正是聚集的代价。
- **二次探测**缓解一次聚集但仍有「二次聚集」（同 hash 值的 key 走相同平方序列）；且仅当 m = 4k+3 型素数且 α<0.5 时保证能找到空位。
- **双重散列**用两个独立散列，使探测序列近乎随机，ASL 最接近理想；它是开放定址里理论最优的。
- **拉链法**成功 ASL ≈ 1 + α/2（链表平均长度 α，命中平均要查半条链），与 α 线性相关、无聚集爆炸；失败 ASL ≈ α（平均查一整条链）。当 α 很大时拉链法稳定，但指针带来缓存不友好（跳指针 cache miss）。
- 统一的「期望比较次数」分析依赖桶分布近似泊松，这是哈希表「平均 O(1)」的形式化来源。

### 📚 考研者视角
- **408 统考点**：开放定址三种探测的**地址递推式**、拉链法思想、**装填因子 α = n/m** 对 ASL 的影响、各类 ASL 的近似公式口径。
- **必背公式**：
  - 线性探测：成功 ASL ≈ (1+1/(1−α))/2；失败 ASL ≈ 1/(1−α)。
  - 拉链法：成功 ASL ≈ 1 + α/2；失败 ASL ≈ α（或 1+α/2 视口径）。
- **常考计算**：给定 key 集合与表长 m、素数 p，手算线性探测的插入地址序列与查找 ASL（逐个 key 递推 hᵢ）。
- **易混点**：开放定址的「失败 ASL」要沿探测序列查到第一个空位才算失败（步数计入），不是简单 n+1。

## 3. 装填因子与 ASL：一切回到负载

装填因子 `α = n / m`（n 已存关键字数，m 表长）是衡量哈希表「满不满」的核心量：

```
- α 越大 → 冲突越多 → ASL 越大 → 性能越差；
- α 越小 → 空间浪费越多 → 但查找越快；
- 开放定址一般把 α 控制在 0.5~0.75 并触发扩容（rehash）；
- 拉链法 α 可更高（0.75~1+），靠链表吸收。
```

### 🧑‍💻 程序员视角
- **扩容（rehash）** 是哈希表的隐藏成本：当 α 越过阈值，要新建更大的表、把全部元素重新插入（O(n) 突刺）。工程优化用「渐进式 rehash」（如 Redis dict 分多次搬迁）把 O(n) 尖峰摊平成 O(1) 均摊。
- 选初始容量要预估数据量：宁可开大一点也别频繁扩容。Go/Java 的 map 默认负载因子约 0.75 触发扩容，这是「空间换时间」的经验平衡点。

### 🎓 博士生视角
- ASL 对 α 的依赖可以严格推导：在「均匀散列」假设下，成功查找的期望比较次数对线性探测是 (1+1/(1−α))/2，对拉链法是 1+α/2。二者都是 α 的**单调增函数**，但斜率与奇异点不同——线性探测在 α→1 时发散（聚集），拉链法线性增长（无发散）。
- 从摊还分析看，扩容使「插入均摊代价」保持 O(1)：虽然单次 rehash 是 O(n)，但两次扩容之间至少插入 O(m) 个元素，故均摊到每次插入仍是 O(1)。

### 📚 考研者视角
- **408 统考点**：装填因子的定义 `α = n/m`、它对 ASL 与冲突率的影响、**开放定址与拉链法各自合适的 α 区间**。
- **必背**：α 是 ASL 的单调增因子；开放定址 α 宜 < 0.75，拉链法可更高。
- **常考**：「为什么哈希表平均查找是 O(1) 却要控制 α？」——答平均 O(1+α)，α 升高 ASL 升高且线性探测会聚集发散，故要限 α 并在超阈值时扩容。

## 三视角小结

| 维度 | 哈希构造 | 冲突处理 | 装填因子 |
|---|---|---|---|
| 程序员 | 字符串用 BKDR/DJB2/Murmur；p 取素数 | 默认拉链法/现代开放定址；删除语义不同 | 超阈值扩容，渐进式 rehash |
| 博士生 | 均匀性=桶分布接近 1/m | 各法 ASL 闭式：线性(1+1/(1−α))/2 等 | 期望 ASL 随 α 单调增，摊还 O(1) |
| 考研 | 五种方法定义+适用 | 线性/二次/双散列递推式、拉链法 | α=n/m，限 α 区间 |
