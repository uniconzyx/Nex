# 线性表上的查找：顺序、折半与分块

## 1. 查找的基本概念：先统一口径

「查找」是在集合中找到关键字等于给定值的元素。度量查找效率的**唯一统一口径**是**平均查找长度 ASL（Average Search Length）**：

```
ASL(成功) = Σ_{i=1..n} pᵢ · cᵢ        （pᵢ 为找到第 i 个元素的概率，cᵢ 为比较次数）
ASL(失败) = Σ_{j=1..n+1} qⱼ · cⱼ     （失败位置通常 n+1 个，qⱼ 为其概率）
```

等概率且各元素等可能被查时，pᵢ = 1/n，ASL 退化为「比较次数之和 / n」。**所有查找结构的性能都落回到 ASL 上比较**，这是本章的主线。

### 🧑‍💻 程序员视角
- 工程里 ASL 不是纸面公式，而是「P99 延迟」的近似：你真正关心的是**最坏情况下的尾延迟**，所以顺序查找在大数据集上会被直接淘汰。
- 库函数（如 C 的 `bsearch`、C++ 的 `std::binary_search`/`lower_bound`）背后就是折半查找；它们要求**区间已排序**，否则是 UB。上线前务必确认数据源的有序性，否则会静默返回错误结果。
- 真实系统里大量「查找」其实是「存在性判断 + 取值」，哈希表（see 03-hash.md）是默认答案；只有需要**范围查询/有序遍历**时才回到折半/树形结构。

### 🎓 博士生视角
- ASL 是查找过程的**期望比较次数**，本质是决策树上的「带权路径长度」：每个结点的深度 = 比较次数，权 = 该元素被查概率。于是「最优查找」=「构造一棵平均深度最小的决策树」。
- 折半查找的判定树是**唯一能让等概率 ASL 达到信息论下界 ⌈log₂(n+1)⌉ 的静态结构**（静态最优），因为它让判定树尽可能平衡——这正是香农熵给出的下界 ⌈log₂(n+1)⌉ 可在平衡二叉判定树上达到。
- 顺序查找的失败 ASL = n+1 而非 n，是因为「查到哨兵/越界」本身是一次比较；这一细节在证明渐近界时不能丢。

### 📚 考研者视角
- **408 统考点**：ASL 的定义（成功/失败两种加权口径）、顺序/折半/分块三种查找的 ASL 公式，**必须会手算**。
- **公式口径（严蔚敏·等概率）**：
  - 顺序查找：ASL_成功 = (n+1)/2，ASL_失败 = n+1。
  - 折半查找：ASL_成功 = 各结点深度之和 / n；**最坏比较次数 = 判定树高度 = ⌈log₂(n+1)⌉**（这是必背结论）。
  - 分块查找：ASL ≈ (s+1)/2 + (b+1)/2，其中 s 为块数、b 为块长，n = s·b。
- **常考问法**：给 n 个有序元素，画出折半判定树并求 ASL；或反推「判定树高度」。记住判定树是**满/完全二叉判定树**，失败结点恰好 n+1 个。

## 2. 顺序查找：最朴素但最鲁棒

顺序查找从头到尾逐个比对，**不要求有序**，哨兵法（把 key 放到 `a[0]`）可省去每次的边界判断，使最坏比较次数从 n+1 降到 n（一次必然命中哨兵）。

### 🧑‍💻 程序员视角
- 哨兵法在循环里少一次 `i>=0` 的判断，是嵌入式/高频循环里值得做的微优化，但现代编译器对「带边界判断的 for」常能自动优化掉，收益有限——可读性优先。
- 顺序查找的真正价值在「无序小数据 / 链表」：链表无法随机访问，折半无从谈起，只能顺序查。所以「是否有序」「是否支持随机访问」决定了能否用折半。

### 🎓 博士生视角
- 顺序查找是**无结构假设**下的查找：不对数据做任何预处理，比较次数只由位置决定。它在比较模型下的 ASL 是 (n+1)/2，已是最优（没有任何算法能在「不利用顺序信息」时做得更好）。
- 带哨兵的版本把「边界检查」合并进「与 key 比较」，是「把不变的条件并入循环体」这一优化的经典范例，把 n+1 次比较压到 n 次。

### 📚 考研者视角
- **必背**：ASL_成功 = (n+1)/2，ASL_失败 = n+1（无哨兵时成功也是 (n+1)/2，带哨兵成功最坏 n 次但期望不变）。
- **易混点**：哨兵只改变「失败时的比较次数下限」，不改变期望 ASL。考题常问「带哨兵后 ASL 是否变小」——答「期望不变，最坏比较次数从 n+1 变 n」。
- 顺序查找**不要求有序**这一点常作为选择题的陷阱项出现。

## 3. 折半查找：静态有序数据的最优解

在有序数组上，每次取中点比较，把搜索区间折半。递归/迭代皆可，迭代写法注意边界。

```
mid = (lo + hi) / 2
if a[mid] == key: 命中
elif key < a[mid]: hi = mid - 1
else: lo = mid + 1
```

### 🧑‍💻 程序员视角
- 边界是 bug 重灾区：`while (lo <= hi)` 才是正确终止条件；用 `lo < hi` 会漏掉 `hi` 处的元素。中点建议写 `lo + (hi-lo)/2` 防 `lo+hi` 溢出（虽然 int 很少爆，但这是防御性编程的肌肉记忆）。
- 折半查找常配合「lower_bound / upper_bound」做**二分定位插入点**，是去重、求 LIS、在有序数组找区间的基石。STL 的 `lower_bound` 返回「第一个 ≥ key」的位置，比裸折半更常用。

### 🎓 博士生视角
- 折半查找的判定树是一棵**高度 = ⌈log₂(n+1)⌉** 的近似满二叉树，且层数越深结点越少，故成功 ASL ≈ log₂(n+1) − 1，比顺序查找的 (n+1)/2 在 n 大时好几个数量级。
- 信息论下界：在「比较决策树」模型下，区分 n 个元素至少需要 ⌈log₂(n+1)⌉ 次比较（叶子 = n 个成功 + n+1 个失败 = 2n+1 个，故深度 ≥ ⌈log₂(2n+1)⌉，对成功结点即 ⌈log₂(n+1)⌉）。折半查找**恰好达到**这个下界，因此静态最优。
- 若元素被查概率不均，**静态最优二叉树（Huffman 式构造的带权最优判定树）** 才最优；折半只对应等概率最优。

### 📚 考研者视角
- **必背结论**：n 个元素折半查找，**最多比较 ⌈log₂(n+1)⌉ 次**；判定树高度 h 满足 2^(h−1) ≤ n < 2^h 即 h = ⌈log₂(n+1)⌉。
- **手算 ASL**：画出判定树，把每个成功结点的「层数（比较次数）」求和除以 n。例：n=11 时 h=4，成功 ASL = (1·1+2·2+4·3+4·4)/11 = (1+4+12+16)/11 = 33/11 = 3。
- **失败结点 n+1 个**是高频填空/选择考点。

## 4. 分块查找：顺序与折半的折中

把数组分块，**块内无序、块间有序**（第 i 块最大值 < 第 i+1 块最小值），另建「索引表」存每块的最大关键字与起始下标。查找分两步：① 在索引表里定位 key 属于哪块（顺序或折半）；② 在块内顺序查。

```
索引表:  [max=22 @0] [max=48 @6] [max=86 @12]
数据块:  {22,12,13,8,9,20} {33,42,44,38,24,48} {60,58,74,49,86,53}
```

### 🧑‍💻 程序员视角
- 分块查找是「索引 + 局部顺序」的工程雏形：数据库「分区表」、LSM-Tree 的 SSTable 分层、跳表的稀疏上层，本质上都是「块间有序、块内可乱」的思想放大版。
- 它的插入比纯有序数组便宜（只需插到对应块里，块内无序不必移动大批元素），适合「写多、查也要快」的中等规模场景。

### 🎓 博士生视角
- 分块查找的 ASL 是「两级查找 ASL 之和」：块间定位 ASL + 块内顺序 ASL。当 n = s·b（s 块、b 块长）且等概率时，ASL ≈ (s+1)/2 + (b+1)/2 = (s + n/s)/2 + 1，对 s 求导得 s ≈ √n 时取最小 ≈ √n + 1，这就是「分块把 O(n) 降到 O(√n)」的来源。
- 它处于顺序 O(n) 与折半 O(log n) 之间的原因在于：索引表把「搜索空间」从 n 压到 √n，但块内仍是顺序的。

### 📚 考研者视角
- **必背公式**：ASL_分块 ≈ (s+1)/2 + (b+1)/2（s 块数、b 块长、n=s·b）。当 s = b = √n 时 ASL 最小 ≈ √n。
- **核心约束**：块间必须有序、块内可无序——这是选择题常考的「分块查找对数据的要求」。
- **对比口径**：顺序 O(n) < 分块 O(√n) < 折半 O(log n)（查找时间），但分块插入比折半（需维护有序）更灵活，是性价比折中。

## 三视角小结

| 结构 | 程序员关注 | 博士关注 | 考研必背 |
|---|---|---|---|
| 顺序 | 无序/链表的唯一选择，哨兵微优化 | 无结构假设下最优，比较模型下界 | ASL=(n+1)/2，失败 n+1 |
| 折半 | 边界 `lo<=hi`、配 lower_bound | 静态最优，达信息论下界 | 最坏 ⌈log₂(n+1)⌉ |
| 分块 | 索引+局部顺序（分区/LSM 雏形） | 两级 ASL 叠加，最优 s=√n | ASL≈(s+b)/2+1 |
