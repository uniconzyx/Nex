# DFS、BFS 与拓扑排序：两种搜索序的分野

## 1. DFS 与 BFS 不是「两种写法」，是「两种序」

二者代码只差一个容器（栈 vs 队列），但产生的**搜索序**完全不同，这决定了它们能解决的问题不同。

```
     A
    ╱ ╲
   B   C
   │   │
   D   E
    ╲ ╱
     F

DFS（从 A，栈）：A → C → E → F → D → B      一路到底再回头
BFS（从 A，队列）：A → B → C → D → E → F     一层一层摊开
```

**博士视角 —— 递归即栈**：
DFS 的递归写法之所以成立，是因为**函数调用栈天然就是栈**：每次递归把「当前顶点 + 已探索到第几条边」
压进栈帧，回溯时自动恢复现场。所以「递归 DFS」与「显式栈 DFS」是同一个算法的两种表示，
显式栈版本价值在于**避免深图爆栈**（V = 10⁵ 的链状图，递归深度 10⁵ 会 SIGSEGV）。

**程序员视角 —— 迭代加深与 visited 的三色标记**：
- `visited` 用 `int` 而非 `bool`（0 白 / 1 灰 / 2 黑）是**判环的关键**：
  有向图判环要看「是否遇到灰色节点」（回边），无向图判环看「是否遇到非父节点的已访问节点」。
  只用 bool 无法区分「祖先」与「已完成的兄弟分支」。
- 无向图 DFS 必须传 `parent`，否则 `(u,v)` 双向边会被误判成环。

## 2. BFS 为什么能求无权最短路

这是 BFS 最被低估的性质。**BFS 的队列按「距离起点的边数」单调递增**——因为：
1. 队列里元素的距离序列是非降的（归纳可证）；
2. 每个顶点第一次出队时，其距离即为最短距离。

于是 `dist[]` 只需在入队时 +1 即可，无需松弛。这个性质的工程落点极广：
- **社交网络的「几度好友」**（LinkedIn 的 2nd / 3rd 就是 BFS 层数）；
- **单词接龙 / 迷宫最短步数**；
- **网络跳数（hop count）**、垃圾回收的可达性扫描（Java GC 的标记阶段本质是 BFS/DFS）。

对比：DFS **不能**求最短路——它找到的是「某条路径」，不是最短的。

## 3. 拓扑排序：把偏序变成线序

**适用前提：有向无环图（DAG）**。语义是「若存在边 u→v，则 u 必须排在 v 之前」。

### 3.1 Kahn 算法（入度法，BFS 风格）

```
1. 统计所有点入度，入度 0 者入队
2. 取队首 u，输出 u
3. 对 u 的每条出边 u→v：indeg[v]--；若 indeg[v]==0 则 v 入队
4. 重复 2-3 至队空
5. 若输出点数 < V ⇒ 有环，无解
```

**它为什么对**：入度为 0 意味着「没有任何未输出的前驱」，立刻输出必然合法；
每输出一个点就相当于「解除它对后继的约束」，可能让后继入度归零。

**它的独特优势**：能**判环**（输出数 < V），而且**同一层的点可以同时处理**——
这天然对应「并行构建」：Makefile / Gradle 的任务调度、Maven 依赖解析、
编译器的指令调度、Spark 的 stage 划分，都是 Kahn 的实例。

### 3.2 DFS 后序逆序法

```
对未访问点 u 做 DFS，在「u 的所有后继都已完成」后把 u 压入栈；
最后逆序弹出栈即为拓扑序。
```

- 不能判环（若要判需额外三色标记检测回边）。
- 但它在**求「字典序最小拓扑序」配合贪心**、以及**关键路径**计算里更顺手。

### 3.3 关键路径（AOV → AOE）

把「顶点=事件、边=活动、边权=持续时间」后：
- 最早发生时间 `ve[k]`：按拓扑序取 `max(ve[j] + w(j,k))`；
- 最晚发生时间 `vl[k]`：按逆拓扑序取 `min(vl[j] - w(k,j))`；
- **关键路径 = 所有 `ve == vl` 的活动构成的路径**，它的长度就是项目最短工期，
  缩短它才能缩短总工期（缩短非关键活动只会增加该活动的松驰时间）。

这是 408 的经典考点，也是项目管理（PERT/CPM）的数学基础。

## 4. 复杂度

| 算法 | 邻接表 | 邻接矩阵 | 空间 |
|---|---|---|---|
| DFS | O(V + E) | O(V²) | O(V)（递归栈/显式栈） |
| BFS | O(V + E) | O(V²) | O(V)（队列最宽 V） |
| 拓扑排序 | O(V + E) | O(V²) | O(V) |

**注意矩阵版本退化**：矩阵下「遍历某点的出边」要扫整行 O(V)，V 个点即 O(V²)。
这与边数无关，所以稀疏图用矩阵会白白多付 V²/(V+E) 倍的代价。

## 三视角解析

### 🧑‍💻 程序员视角
- DFS 递归写法简洁但受栈深限制；大图必须改迭代（显式栈）或设置更大栈。
- 拓扑排序是**构建系统/包管理器**的核心：Make、Bazel、npm 用它在依赖图中定序，同时用「剩余节点数 ≠ 总数」来报**循环依赖**。
- BFS 求出的是**无权最短路（最少跳数）**，常用于网络跳数、社交关系层级、迷宫最短路径。

### 🎓 博士生视角
- DFS 用「白-灰-黑」三色刻画状态：灰边指向灰节点即**后向边**，存在后向边 ⇔ 有环——这是判环的统一视角。
- 拓扑排序与**偏序的线性扩展**同一回事：DAG 的拓扑序就是其偏序关系的一个线性扩展，存在性由 DAG 保证。
- Kahn（入度法）天然能给出「字典序最小」的拓扑序（配最小堆）；DFS 后序法在需要「逆后序」时更直接。
- 连通分量/强连通分量（Tarjan、Kosaraju）是 DFS 的深度应用，强连通分量缩点后得到 DAG。

### 📚 考研者视角
- **408 必考**：
  1. 从给定顶点出发写出 **DFS / BFS 遍历序列**——注意**结果依赖存储结构**（邻接表按编号小到大、邻接矩阵按列扫描），必须按题意顺序写；
  2. **拓扑排序**的算法步骤与「判定有向图无环」；
  3. **关键路径（AOE 网）**：求最早/最迟发生时间、关键活动——与拓扑排序配套的高频大题。
- 复杂度：邻接表 O(V+E)，邻接矩阵 O(V²)。
- 记忆锚点：**「BFS 靠队列、DFS 靠栈（或递归）」**；**「拓扑排序能排出序列 ⇔ 图中无环」**。
