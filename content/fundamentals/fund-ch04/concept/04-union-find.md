# 并查集：从 O(log n) 到「实际常数」的反阿克曼之旅

## 1. 它解决什么问题

**动态连通性**：不断合并集合、不断查询「两点是否同集合」，且**只合不拆**（这是它能这么快的前提）。

典型场景：
- Kruskal 最小生成树（选边时判两端是否已连通）
- 社交网络的好友圈合并（朋友圈、连通块计数）
- 编译器中寄存器分配的合并、类型变量合一（union-find unification）
- 图像处理的两遍连通域标记、 percolation（渗流）模拟
- 等价类合并、Kruskal 重构树

## 2. 朴素实现的困境

用「父指针森林」表示集合，根代表集合：

```
初始:  0  1  2  3  4        union(0,1), union(1,2), union(2,3), union(3,4) 不加优化:
       ↑  ↑  ↑  ↑  ↑
                            0 ← 1 ← 2 ← 3 ← 4     （退化成链，find(4) 要爬 4 层）
```

**若 union 随意挂（总是 a 挂到 b），最坏退化成链，find 是 O(n)。**
n 次操作即 O(n²) —— 在 n = 10⁵ 时直接超时。

## 3. 两个优化

### 3.1 按秩合并（union by rank）

始终让**小树挂到大树下**。用 `rank[]`（树高上界）或 `size[]`（节点数）作为「大小」度量：
- 按 rank：只有两树 rank 相等时新根 rank 才 +1；
- 按 size：直接比较节点数，更直观，且对「合并后要统计大小」的需求天然适配。

**保证**：树高 ≤ O(log n)。因为「挂到下面」的树，其高度每增加 1，所在树规模至少翻倍。

### 3.2 路径压缩（path compression）

```
find(4) 前:  0 ← 1 ← 2 ← 3 ← 4
find(4) 后:  0 ←─────────────── 1,2,3,4 全部直接挂到根
```

一次 `find` 把路径上所有节点直接接到根。代价不变（本来就要爬一次），但**后续查询变得极快**。

## 4. 合用的复杂度：反阿克曼函数

- 只用路径压缩：最坏 O(log n)（可构造让压缩无效的序列），实际很快；
- 只用按秩合并：O(log n)；
- **合用：O(m · α(n))**，α 是反阿克曼函数。

**α(n) 有多小**：α(n) = 使阿克曼函数 A(k, 1) ≥ n 的最小 k。

| n | α(n) |
|---|---|
| 1 | 0 |
| 2 | 1 |
| 4 | 2 |
| 16 | 3 |
| 65536 | 4 |
| 2^65536 | 5 |

**任何你能写进内存的输入规模（n ≤ 2^65536），α(n) ≤ 4。** 因此工程上直接视作常数。

> 注意：这是**均摊（amortized）**界，不是最坏界；且严格来说需要「按秩合并」，
> 只做路径压缩的最坏界是 Θ(log n)（1985 年由 Tarjan 与 van Leeuwen 分别给出证明）。

## 5. 实现细节与踩坑（C 语言）

```c
#define MAXN 100000
int parent[MAXN], rank_[MAXN];   /* rank 是 C++ 关键字，C 里不冲突但习惯加后缀 */

void init(int n) {
    for (int i = 0; i < n; i++) { parent[i] = i; rank_[i] = 0; }
}

int find(int x) {
    /* 迭代版避免深递归；递归版在 n 大时也可能爆栈 */
    int r = x;
    while (parent[r] != r) r = parent[r];      /* 先找到根 */
    while (parent[x] != r) {                    /* 第二趟压缩 */
        int nxt = parent[x];
        parent[x] = r;
        x = nxt;
    }
    return r;
}

void unite(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return;                       /* 已同集：Kruskal 用它判环 */
    if (rank_[ra] < rank_[rb]) parent[ra] = rb;
    else if (rank_[ra] > rank_[rb]) parent[rb] = ra;
    else { parent[rb] = ra; rank_[ra]++; }
}
```

**坑点清单**：
1. **忘记 `init`**：`parent` 全 0 会让所有点都被当成根 0 的子节点，逻辑全错。
2. **只压缩不按秩**：均摊已很好，但最坏界退化；竞赛大数据可能被卡。
3. **递归 find 爆栈**：n = 10⁶ 的链状输入会 SIGSEGV，用迭代版（两趟法）。
4. **把 rank 当真实树高**：路径压缩后 rank 只是**上界**，不再等于实际高度——
   这不影响正确性（按它比较仍能保证对数上界），但别拿它去算树高。
5. **需要「拆集合」时并查集不适用**：那要用 Link-Cut Tree 或可撤销并查集（按秩合并 + 栈记录）。

## 6. 一句话总结

> **并查集 = 父指针森林 + 按秩合并 + 路径压缩；三者缺一，最坏界就从「实际常数」退回 O(log n) 甚至 O(n)。**

## 三视角解析

### 🧑‍💻 程序员视角
- 并查集是「动态连通性」的标准解法：判连通、等价类归并、Kruskal 判环、账户合并类题。
- 实现要点：**路径压缩 + 按秩/按大小合并**同时用，实测近乎常数；数组实现极短，适合手写进工程。
- 需要**可撤销**（回滚）时改用「按秩合并 + 不路径压缩」，把每次合并压入栈即可撤销——这是线段树分治/离线二分的常用搭子。

### 🎓 博士生视角
- 复杂度为 **O(α(n))**，α 为反阿克曼函数，对一切可想象的 n（< 2^65536）都有 α(n) ≤ 4，因此「接近 O(1)」在工程上就是常数。
- Tarjan 给出了该问题的下界证明：在只允许并查操作的比较模型下，O(α(n)) 的摊还界是紧的——这是「数据结构下界」的经典成果。
- 变体谱系：带权并查集（维护到根的差/异或，解决关系链问题）、可持久化并查集（用可持久化数组实现历史版本查询）。
- 与图论的联系：并查集维护的是**等价关系的划分**，路径压缩本质上是在维护「代表元」这一商结构的规范形。

### 📚 考研者视角
- **408 考点**：并查集的定义、**Find（含路径压缩）与 Union 的实现**、按秩合并的作用。
- 常考选择题：给一棵「双亲表示法」的数组，问 `Find(x)` 的返回值或压缩后的数组形态；问「合并后树的形态」。
- 应用类：求**无向图的连通分量个数**、判断加入某条边是否成环（Kruskal 的判据）。
- 记忆锚点：**路径压缩把查找路径上的所有结点直接挂到根**——答题时画出压缩前后的双亲数组最直观；**「按秩合并」保证树高 O(log n)，配合路径压缩进一步降为 α(n)**。
