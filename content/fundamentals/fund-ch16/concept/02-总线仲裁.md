# 总线仲裁（Bus Arbitration）

```text
多个主设备(Master)要同时用总线：
  CPU ─┐
  DMA ─┼──[ 仲裁器 ]── 决定这一拍谁上总线 ──[ 总线 ]── 从设备
  GPU ─┘
核心矛盾：总线同一时刻只能被一个主设备占用 → 必须"裁判"。
```

> 一句话：仲裁就是**决定多个竞争总线的主设备中，谁获得下一次总线使用权**的规则。分"集中式"（一个仲裁器拍板）与"分布式"（各设备自己协商）。计组 408 重点在**三种集中式仲裁**。

## 1. 背景/动机

系统里往往不止一个能发起总线事务的主设备：CPU、DMA 控制器、GPU、网卡都可能要抢内存总线。若不做裁决，就会"两个都在写、数据撞车"。仲裁要解决三件事：① 谁优先（优先级策略）；② 如何公平（避免饿死）；③ 裁决本身要快、线不能太多（硬件成本）。

## 2. 定义/要点

### 2.1 集中式仲裁三兄弟

**(1) 链式查询（Daisy Chain，串行优先级）**

```text
仲裁器                      设备链（物理顺序=优先级）
  ├── BG(Bus Grant) ──▶ 设备0 ──BG──▶ 设备1 ──BG──▶ 设备2 ──▶ ...
  ▲                         │            │            │
  └─────────────── BS(Bus Status / 忙) ┘            ┘
请求：各设备共用一根 BR(Bus Request)

工作：仲裁器收到 BR → 发 BG(高电平) → 沿链传；
      第一个"有请求"的设备截住 BG（不发往下游），并占用总线；
      总线忙时 BS 拉高，仲裁器不再发新 BG。
```

- **线数**：约 3 根（BR、BG、BS），最少。
- **优先级**：**物理链靠前 = 永远最高**，固定不可调。
- **致命伤**：① 不公平，低号饿死；② 链上某设备断连，其**下游全部失效**（单点故障敏感）；③ 授权沿链传递有延迟。

**(2) 计数器定时查询（Counter/Timer，轮转优先级）**

```text
仲裁器                      设备0  设备1  设备2 ... 设备N-1
  ├── BR(请求，共用)          │      │      │
  ├── 设备地址线(⌈log₂N⌉根) ─┴──────┴──────┴── (二进制计数)
  └── BS(忙)

工作：收到 BR → 仲裁器启动计数器，把计数值放到"设备地址线"上；
      被选中编号的设备若有请求 → 占用总线并拉 BS；
      计数器可"从 0 递增"(近似轮转) 或"从中断点续数"(更公平)。
```

- **线数**：`⌈log₂N⌉`（地址线）+ 2（BR、BS），比链式多但远少于独立。
- **优先级**：可由**计数器初值与计数方式配置**：从 0 计 = 偏向低号；轮转 = 较公平。
- **优点**：无链式单点故障；灵活性好。**缺点**：仍非严格实时公平。

**(3) 独立请求（Independent Request，并行优先级）**

```text
仲裁器
  ├── BR0 ─ 设备0
  │    BG0 ─ 设备0
  ├── BR1 ─ 设备1     每个设备一对线，全部并行连到中央仲裁器
  │    BG1 ─ 设备1
  ├── BR2 ─ 设备2
  │    BG2 ─ 设备2
  └── (内部优先级编码器，速度最快)

工作：各设备独立发 BRi；仲裁器内"优先级编码器"立刻算出最高优先级，
      直接回 GBi，无链式传播延迟。
```

- **线数**：**2N** 根（每设备 BR+BG 各一），最多。
- **优先级**：完全可程序化（编码器逻辑任意配），响应最快。
- **缺点**：线数随设备线性增长，硬件成本高；仲裁器逻辑最复杂。

**(4) 三者对比表（408 必背）**

| 仲裁方式 | 控制线数（约） | 优先级特点 | 公平性 | 故障敏感性 | 速度 |
|---|---|---|---|---|---|
| 链式查询 | 3（BR/BG/BS） | 固定，链前最高 | 差（易饿死） | 高（链断下游失联） | 慢（链传延迟） |
| 计数器定时 | `⌈log₂N⌉+2` | 可配（轮转/偏置） | 中 | 低 | 中 |
| 独立请求 | `2N` | 完全可编程 | 好 | 低（独立） | 最快 |

### 2.2 分布式仲裁（了解）

各设备自带仲裁逻辑，通过**仲裁号**（如以太网式或优先级号）在总线上"比大小"决定胜者，无需中心仲裁器。典型如 **IEEE 1394（FireWire）**。优点是去中心、无单点，缺点是协议复杂，现代 SoC 内部互连（如 AXI 的 QoS）也吸收了其"带优先级标签"的思想。

### 2.3 三视角解析

### 🧑‍💻 程序员视角
真实系统里仲裁=**性能与公平的天平**，两个踩坑点：

1. **DMA 与 CPU 抢内存总线导致卡顿**：音视频 DMA 持续占用系统总线搬运数据，若仲裁偏向 DMA，CPU 取指会被 stall，表现为"播放时界面卡"。调法：在仲裁器/CPU 侧设**总线带宽预留**或**突发长度上限**（给 CPU 留时间片）。Linux 里 `iommu`/`dma-coherent` 配置、ARM 的 `QoS` 寄存器都与此相关。
2. **PCIe 的 "bus master" 仲裁**：设备声明 `Bus Master` 能力后可直接发起 DMA（成为 master）。驱动里忘了开 `pci_set_master()`，设备就**永远抢不到总线**，DMA 全部超时——这是内核驱动里一个很隐蔽的 bug。

### 🎓 博士生视角
把仲裁建模为**带优先级的排队网络**。链式查询等价于"严格优先级 + FIFO 串联"，低优先级类在无高优先级到达时才能服务，其稳态等待时间差异可由**优先级排队论（HOL priority queueing）**给出闭式解；独立请求则是"每类独立服务器 + 中央调度"，延迟下界由编码器组合逻辑深度决定（门延迟）。分布式仲裁更接近**博弈/竞标**，要额外证明**无死锁**（无环优先级）与**活性**（总有胜者）。分离式事务（concept 03）与仲裁配合，能进一步把"占用总线等从设备"的时间释放出来，提升有效吞吐。

### 📚 考研者视角
408 高频题型：

- **排线数**：链式（最少，约 3）< 计数（`⌈log₂N⌉+2`）< 独立（`2N`，最多）。选择题常给 N 让你比大小。
- **比公平性/故障敏感性**：链式最不公平且链断下游全挂；独立最公平、无链式单点；计数居中、可配。
- **比速度**：独立请求最快（无传播延迟）；链式最慢（沿链传 BG）。
- 记一句口诀：**"链式省线不公平，计数折中可轮转，独立最快线最多"**。
