# fund-ch16 学习目标：总线

> 一句话引出：五大部件之间靠什么"说同一种话"？——CPU、内存、I/O 设备没有自己的方言，全靠一条**分时共享**的**总线**来握手、寻址、传数。

> 学科：`fundamentals`（408 考研 · 计算机组成原理）
> 前置：`fund-ch13`（计算机系统概述）
> 本章属于计组模块，与 `fund-ch14`（数据的表示与运算）、`fund-ch15`（存储器与 Cache）、后续 `fund-ch17`（I/O 与中断）共同构成" CPU 如何与外面的世界通信"的完整链路。

## 一、知识目标
1. 能说清**总线的定义与作用**：什么是"分时、共享"，为什么现代计算机要用总线而不是两两专线互连（成本、可扩展性、标准化）。
2. 掌握**总线的分类**三套正交维度：按功能（片内 / 系统 / 通信总线）、按传输方式（串行 / 并行）、按定时方式（同步 / 异步）；并知道每类代表总线。
3. 记住**总线特性与性能指标**：总线宽度、总线带宽（MB/s）、时钟频率、传输率、总线复用，并能根据题目给出的参数**手算带宽**。
4. 掌握**集中式总线仲裁**三种：链式查询、计数器定时查询、独立请求，能对比三者在**线数、公平性、故障敏感性、速度**上的差异。
5. 掌握**总线定时**两类：同步定时与异步定时（不互锁 / 半互锁 / 全互锁），以及半同步、分离式事务；能画并能解释**握手时序图**。
6. 了解主流**总线标准** PCI / PCIe / USB / AXI 的定位与关键差异（并行→串行、共享→交换、带宽与拓扑）。
7. 理解**总线事务与突发（burst）传送**：地址相位 + 数据相位，burst 如何靠"一次寻址、连续传数"提升有效带宽。

## 二、能力目标
- 给定总线位宽、时钟频率、每周期传输次数，能**正确计算总线带宽**，并区分"总线带宽"与"实际传输率"。
- 给定多个主设备的请求序列，能**模拟集中式仲裁**，输出授权（grant）时序与总线占用率。
- 能为一个"主从握手"场景**画出异步全互锁时序**，并指出半互锁可能引发的"请求丢失 / 应答悬挂"风险。
- 能在排障时把"PCIe 带宽不够""USB 枚举失败""I²C 总线挂死"等真实故障**归因到总线层的某个机制**。
- 能向非科班同事用一句话解释：为什么 USB 用异步、为什么 PCIe 用串行、为什么 AXI 要分多个通道。

## 三、三视角导航
| 视角 | 本章重点 |
|---|---|
| 🧑‍💻 程序员 | 总线不是"玄学"：PCIe 通道数决定 GPU 训练吞吐、USB 枚举顺序决定设备能否识别、I²C 上拉电阻决定总线会不会挂死。写驱动 / 调板子时这些都会咬人。 |
| 🎓 博士生 | 把"仲裁"看成资源分配的多方博弈（优先级、公平性、死锁避免），把"定时"看成时钟域之间的同步协议（同步的保守 vs 异步的弹性），可用排队论量化总线利用率。 |
| 📚 考研者 | 408 高频：三种集中仲裁的线数对比、同步/异步定时的握手区别、分离式事务为什么提高利用率、带宽计算公式。选择题与大题都爱考。 |
