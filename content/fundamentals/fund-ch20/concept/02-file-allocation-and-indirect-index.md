# 物理结构：连续、链接、索引，以及那道必考的三级间接计算题

## 1. 背景/动机

逻辑结构决定"用户怎么找记录"，物理结构决定"磁盘怎么放块"。而所有物理结构的设计，都在回答同一个矛盾：

> **要让文件能随便长大（增长性），又要能随便跳到任意位置（随机访问），还要省元数据（空间开销）。** 三者不可兼得。

```text
   连续分配            链接分配（隐式）           索引分配
┌──────────────┐    ┌──────────────┐        ┌──────────────┐
│ 块100..107    │    │ 100→205→310  │        │ 索引块:      │
│ 一段连着的块   │    │ 块尾存下一块号 │        │ [100,205,310]│
└──────────────┘    └──────────────┘        └──────────────┘
 读第k块 = 1 次 I/O   读第k块 = k+1 次 I/O     读第k块 = 2 次 I/O
 增长：难（要挪）     增长：易（挂到链尾）      增长：易（加索引项）
 随机访问：最快       随机访问：最差            随机访问：好
```

## 2. 定义/要点

### 2.1 三种基本分配方式

| 方式 | 目录项里存什么 | 读第 k 块 I/O | 增长 | 碎片 | 备注 |
|---|---|---|---|---|---|
| **连续分配** | `(起始块, 长度)` | **1** | 难 | **外部碎片**（需紧凑） | 随机/顺序都最快，用于 `/boot`、表空间 |
| **链接分配 · 隐式** | `(首块, 末块)`，块内含 next | **k+1** | 易 | 无外部碎片 | 只能顺序访问；一块坏则链断 |
| **链接分配 · 显式（FAT）** | `(首块)`，FAT 表集中存 next | **1** | 易 | 无外部碎片 | 链在**内存**走；FAT 常驻内存，容量受限 |
| **索引分配** | `(索引块地址)` | **2**（索引块 + 数据块） | 易 | 无外部碎片 | 支持随机访问；索引块本身占空间 |

### 2.2 FAT 的容量陷阱（计算题常考）

FAT 表项数 = 磁盘块数；FAT 大小 = 块数 × 表项字节数。
例：1TB 磁盘、4KB 块、4B 表项 → 块数 = 2^28，FAT = 2^28 × 4B = **1GB**，占磁盘 0.1%——听起来不多，但**必须常驻内存**，这才是 FAT32 单分区上限 32GB 的真正原因。

### 2.3 索引分配的三种形态

- **单级索引**：一个索引块放满块号 → 最大文件 = 指针数 × 块大小。
- **多级索引**：索引块指向索引块 → 容量指数级增长，但 I/O 次数也增加。
- **混合索引（UNIX inode）**：**10 个直接 + 1 个一级间接 + 1 个二级间接 + 1 个三级间接**。小文件用直接块（快），大文件才用间接块（省）。

**必考公式**（块大小 B、块号占 p 字节，则每块可放 `B/p` 个块号）：

```text
最大文件 = 10·B + (B/p)·B + (B/p)²·B + (B/p)³·B
访问第 k 块的 I/O 次数：
  前 10 块            → 1 次（直接读数据块）
  一级间接范围内       → 2 次（索引块 + 数据块）
  二级间接范围内       → 3 次
  三级间接范围内       → 4 次
```

## 3. 可运行代码（C，含中文注释 + 真实输出）

先用一张表把"四种方式读第 k 块要几次 I/O"钉死：

```c
#include <stdio.h>
/* ex10：三种分配方式读第 k 块的 I/O 次数对比
 * 假设目录项已在内存（拿到首块/索引块地址不需 I/O）：
 *   连续：1 次
 *   隐式链接：k+1 次（沿链走）
 *   显式链接(FAT)：1 次（链在内存里走）
 *   索引：1 次索引块 + 1 次数据块 = 2 次
 * 这张表解释了「为什么 FAT 当年能赢隐式链接，后来又输给 ext4 的索引」。*/
int main(void) {
    int ks[] = {0, 1, 9, 99, 999};
    printf("%-10s %-10s %-16s %-14s %s\n", "读第k块", "连续", "隐式链接", "显式链接FAT", "索引");
    printf("--------------------------------------------------------------------\n");
    for (int i = 0; i < 5; i++) {
        int k = ks[i];
        printf("%-10d %-10d %-16d %-14d %d\n", k, 1, k + 1, 1, 2);
    }
    printf("--------------------------------------------------------------------\n");
    printf("结论:\n");
    printf("  连续分配最快但难增长；\n");
    printf("  隐式链接最省空间但随机访问退化成 O(k)；\n");
    printf("  FAT 把链搬到内存解决随机访问，但整表常驻内存；\n");
    printf("  索引分配用「多读一个索引块」换来 O(1) 随机访问 + 可增长，成为现代主流。\n");
    return 0;
}
```

输出（`gcc -std=c11 -O2` 真实运行结果）：

```text
读第k块 连续     隐式链接     显式链接FAT 索引
--------------------------------------------------------------------
0          1          1                1              2
1          1          2                1              2
9          1          10               1              2
99         1          100              1              2
999        1          1000             1              2
--------------------------------------------------------------------
结论:
  连续分配最快但难增长；
  隐式链接最省空间但随机访问退化成 O(k)；
  FAT 把链搬到内存解决随机访问，但整表常驻内存；
  索引分配用「多读一个索引块」换来 O(1) 随机访问 + 可增长，成为现代主流。
```

再把混合索引的容量账算一遍（**注意用 64 位整型，否则 4GB 以上会溢出成 0**——这是写这类程序最容易踩的坑）：

```c
#include <stdio.h>
/* ex05：UNIX 混合索引（inode 里的 13 个地址项）
 * 10 个直接 + 1 个一级间接 + 1 个二级间接 + 1 个三级间接 */
int main(void) {
    int blk = 1024;              /* 块大小 1KB */
    int ptr = 4;                 /* 块号 4B */
    int per = blk / ptr;         /* 每块 256 个块号 */
    long long direct = 10LL * blk;
    long long l1 = (long long)per * blk;
    long long l2 = (long long)per * per * blk;
    long long l3 = (long long)per * per * per * blk;
    long long total = direct + l1 + l2 + l3;

    printf("块大小=%dB 每块可放 %d 个块号\n", blk, per);
    printf("-----------------------------------------------------------\n");
    printf("%-16s %-14s %-14s %s\n", "区域", "覆盖字节范围", "容量", "访问需 I/O 次数");
    printf("%-16s 0 ~ %-10lld %-14lld %d\n", "10 个直接块", direct - 1, direct, 1);
    printf("%-16s %lld ~ %-6lld %-14lld %d\n", "一级间接", direct, direct + l1 - 1, l1, 2);
    printf("%-16s %lld~%-6lld %-14lld %d\n", "二级间接", direct + l1, direct + l1 + l2 - 1, l2, 3);
    printf("%-16s %lld~%-6lld %-14lld %d\n", "三级间接", direct + l1 + l2, total - 1, l3, 4);
    printf("-----------------------------------------------------------\n");
    printf("最大文件 = %lld 字节 = %.2f GB\n", total, total / 1024.0 / 1024 / 1024);
    printf("占用的索引块总数（全部写满时）= %lld 个\n", 1LL + per + (long long)per * per);
    return 0;
}
```

输出（真实运行结果）：

```text
块大小=1024B 每块可放 256 个块号
-----------------------------------------------------------
区域           覆盖字节范围 容量         访问需 I/O 次数
10 个直接块  0 ~ 10239      10240          1
一级间接     10240 ~ 272383 262144         2
二级间接     272384~67381247 67108864       3
三级间接     67381248~17247250431 17179869184    4
-----------------------------------------------------------
最大文件 = 17247250432 字节 = 16.06 GB
占用的索引块总数（全部写满时）= 65793 个
```

**手算校验**（考试就按这个写）：直接块 10×1KB = 10KB；一级间接 256×1KB = 256KB；二级 256²×1KB = 64MB；三级 256³×1KB = 16GB。合计约 16.06GB。

## 三视角解析

### 🧑‍💻 程序员视角

真实场景：一个服务要存**几十万个小文件**（每个 2KB），用 ext4 默认配置，跑一周后 `df -i` 显示 **inode 用满 100%**，写入报 `No space left on device`，但 `df -h` 还有 60% 空间。原因：ext4 默认 `bytes-per-inode = 16384`，1TB 盘只有约 6500 万个 inode，小文件一多先撞 inode 上限。解法是 `mkfs.ext4 -i 4096`（或改用对象存储/打包成大文件）。

第二个场景：**同样的数据，块大小不同性能差 3 倍**。4KB 块适合大量小文件（内碎片少）；1MB 块适合大文件顺序读（元数据少、连续性强）。`dd` 压测时 `bs` 与文件系统块大小对齐能明显提速——这就是"物理结构影响实际吞吐"的直接证据。

第三个场景：写数据库时要选 `O_DIRECT` 还是 buffered。`O_DIRECT` 绕过页缓存（自己管缓存、避免双重缓存），但对齐要求严格（偏移与长度必须是块大小整数倍），不对齐会 `EINVAL`——这就是物理结构约束暴露到 API 层的例子。

### 🎓 博士生视角

现代文件系统早已不用"三级间接"这种定长数组，而用 **extent（区段）**：一个 inode 里存若干个 `(逻辑起始, 物理起始, 长度)` 三元组，一个 extent 能覆盖成百上千个连续块。ext4 的 extent 树（默认 4 层）把"20 万块的连续文件"从"20 万个索引项"压缩成"1 个 extent"——这直接降低了元数据开销与大文件顺序读的 I/O。

更激进的是**写时复制 + 范围树**（Btrfs/ZFS）：永远不原地改块，而是写新块、改指针，最后原子切换根节点。这把"崩溃一致性"问题从"日志重放"变成"指针切换的原子性"，顺带免费获得**快照**与**校验和**能力。代价是**碎片化**（尤其随机写）与**写放大**——这也是 ZFS 在生产环境需要定期 `scrub` 与充足预留空间的原因。

### 📚 考研者视角

1. **"混合索引最大文件"计算**：一定先算 `每块块号数 = 块大小 / 块号字节数`，再逐级乘。写答案时把四项分开列，比直接写总数更容易拿步骤分。
2. **"访问某偏移要几次 I/O"**：直接块 1 次、一级间接 2 次、二级 3 次、三级 4 次（前提：inode 已在内存）。若题目问"包含读 inode"，各自 +1。
3. **"FAT 与隐式链接的区别"**：核心是**链存在哪里**——隐式链接存在数据块里（每次都要读块），FAT 存在内存的表里（零 I/O 走链）。别只答"一个是显式一个是隐式"。
4. **易错**：把"索引分配"和"索引文件"混为一谈；忘了连续分配会产生**外部碎片**（链接/索引只有内部碎片）；算 FAT 大小忘记"块数"而不是"文件数"。
