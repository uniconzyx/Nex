# fund-ch19 · 操作系统概述与运行机制

> 一句话引出：为什么「用户态写错一行代码」不会把整台机器搞崩，而「驱动里写错一行」会蓝屏？

## 一、知识目标

1. **说清操作系统到底是什么**：它是**资源管理者**（处理机、内存、文件、设备）+ **虚拟机**（向上提供比裸硬件更好用的抽象接口）+ **用户与硬件的唯一中介**。能解释"没有 OS 的机器只能跑一个程序"这句话的真实含义。
2. **掌握 OS 的四大特征及其内在关系**：**并发**（宏观同时、微观交替，与并行区分）、**共享**（互斥共享/同时共享）、**虚拟**（时分复用/空分复用）、**异步**（走走停停、不可预知）。能说清"并发是共享的前提，虚拟是并发的手段"这条链。
3. **能按发展阶段说清 OS 演进逻辑**：手工操作 → 单道批处理（解决人机矛盾但 CPU 等 I/O）→ 多道批处理（解决 CPU 空转，代价是失去交互）→ 分时（解决交互，牺牲部分吞吐）→ 实时（解决时限）→ 网络/分布式/嵌入式。**每一代都在解决上一代的某个具体瓶颈**。
4. **掌握 CPU 运行模式**：内核态（管态/核心态）与用户态（目态）的划分依据是**特权指令**；PSW 中的模式位如何决定"这条指令能不能执行"；为什么必须有两种模式（保护）。
5. **区分中断与异常**：外中断（可屏蔽 INTR / 不可屏蔽 NMI，来自 CPU 外部）、内中断（**故障 fault** 如缺页、**自陷 trap** 如系统调用、**终止 abort** 如除零之外的硬件错误）；中断处理流程（关中断→保存断点与现场→引出服务程序→恢复→开中断返回）。
6. **讲清系统调用全过程**：用户程序为何不能直接调用内核函数；传参（寄存器/栈）→ 执行**陷入指令**（`int 0x80` / `syscall`）→ 硬件切换到内核态并跳到入口 → 按系统调用号查表 → 执行服务例程 → 返回用户态。能区分**系统调用**与**库函数**（`printf` 是库函数，最终可能落到 `write` 系统调用）。
7. **比较 OS 体系结构**：大内核（monolithic，Linux 属此类但支持可加载模块）、微内核（只留进程通信/低级调度/中断处理，其余下沉为用户态服务）、分层、模块化、外核，以及**性能 vs 可靠性的权衡**（微内核 IPC 频繁导致切换开销）。
8. **说清操作系统引导链**：BIOS/UEFI 自检 → 读 MBR/ESP → 引导加载程序（GRUB）→ 加载内核与 initramfs → 内核初始化 → `init`/`systemd`。理解"引导块"为什么必须放在固定位置。
9. **掌握程序装入与链接**：绝对装入（编译时定址，单道时代）、可重定位装入（静态重定位，装入时一次性改地址、之后不能移动）、动态运行时装入（重定位寄存器，运行时可移动）；静态链接 / 装入时动态链接 / 运行时动态链接。
10. **说清进程地址空间布局**：text（只读代码）、data（已初始化全局/静态）、bss（未初始化，零填充）、heap（向上增长）、mmap 区（共享库/文件映射）、stack（向下增长）、内核空间（用户态不可访问）。

## 二、能力目标

- 能用 `strace` 把「一个 `printf` 背后发生了什么」拆成系统调用序列，并解释每一步为什么要进内核。
- 遇到「进程卡在 D 状态」「服务 P99 抖动」这类线上问题，能判断是**系统调用阻塞**、**缺页**还是**调度等待**，而不是盲猜。
- 能手算中断响应时间与多道批处理下的 CPU 利用率，判断批处理 vs 分时的取舍。
- 能向同事解释清楚：**容器不是轻量虚拟机**（共享内核、无硬件虚拟化层）、**微内核为什么没统治服务器**（IPC 开销 vs 可靠性的历史选择）。

## 四、前置

本章独立自足，是操作系统的**总纲章**。后续：fund-ch09（进程、线程与调度）、fund-ch10（内存管理）、fund-ch20（文件管理）、fund-ch21（I/O 管理与磁盘）。建议先读本章再读其余四章。

| 后续章节 | 本章埋下的种子 |
|---|---|
| 进程、线程与调度（fund-ch09） | 系统调用是进程从用户态进入内核态的唯一通道；`fork/execve` 就是进程创建的原语 |
