# 常见陷阱 · 操作系统概述与运行机制

1. **把「并发」当成「并行」** —— 单核 CPU 上两个进程"同时"在跑，其实是**交替执行**（并发）；并行要求物理上多个处理单元真的同时工作。408 选择题的标准口径：**并发是宏观同时、微观交替；并行是微观也同时**。单核永远只能并发，不能并行。

2. **以为「用户程序可以通过指针直接访问内核数据」** —— 用户态下访问内核地址空间（如 Linux x86-64 的 `0xffff8000_00000000` 以上）会触发**页错误**进而变成段错误，因为页表项里的 U/S 位（User/Supervisor）根本不允许用户态访问。这不是"能不能找到地址"的问题，而是硬件在 MMU 层就拦住了。

3. **把系统调用等同于普通函数调用** —— 普通函数调用只在用户态压栈跳转；系统调用要**切换特权级**（保存现场、换栈、跳内核入口、查表、执行、恢复）。开销是普通调用的数十到数百倍。所以"性能优化"里"减少系统调用次数"（批量写、`mmap`、`io_uring`）往往比优化算法本身更有效。

4. **把 `printf` 当系统调用** —— `printf` 是 **glibc 库函数**，它做格式化并写入 stdio 缓冲区，**只有缓冲区满或 flush 时才调用 `write` 系统调用**。这就是为什么程序 `printf` 后崩溃、日志可能丢一行；也是为什么重定向到文件（全缓冲）和输出到终端（行缓冲）表现不同。

5. **混淆「中断」与「异常」** —— 外中断（键盘、网卡、时钟）来自 **CPU 外部**，与当前指令无关，发生在指令边界；异常（缺页、除零、`int` 指令）由**当前指令**引起，是同步的。408 里"缺页中断"其实属于**内中断/故障**，叫"中断"但归类是异常。

6. **以为「故障（fault）」和「终止（abort）」是一回事** —— 故障（如缺页、缺段）处理完**可以返回原指令重新执行**；终止（如硬件校验错、总线错误）是**不可恢复**的，进程只能被杀死。自陷（trap，如系统调用）则是"主动陷入"，返回时执行**下一条**指令。三者返回地址不同，是常考细节。

7. **以为微内核「一定比大内核快」** —— 恰恰相反：微内核把文件系统、驱动等移到用户态，每次服务都要**进程间通信 + 特权级切换**，IPC 开销使它历史上性能落后于宏内核。微内核的优势是**可靠性与可验证性**（内核小、攻击面小），seL4 做了形式化验证。Linux 是宏内核 + 可加载模块的折中路线。

8. **把「静态重定位」理解成「可以随便移动」** —— 静态重定位（可重定位装入）在**装入时一次性改好所有地址**，之后程序在内存里**不能移动**，否则地址又错了；只有**动态运行时装入**（靠重定位寄存器）才允许运行时移动，也才支持虚拟内存与换出换入。

9. **以为 bss 段「不占空间」** —— bss 不占**磁盘文件**空间（ELF 里只记大小），但运行时**占内存**且被清零。所以 `int a[1000000];`（全局未初始化）编出来的可执行文件很小，运行时却要多 4MB 内存。反过来 `static int a[1000000] = {0};` 显式初始化会进 data 段，文件就变大了。

10. **以为容器就是"轻量级虚拟机"** —— 虚拟机靠 hypervisor 虚拟硬件、有独立内核；容器**共享宿主内核**，靠 `namespace` 做视图隔离、`cgroup` 做资源限制、`capabilities` 收窄特权。所以容器里不能跑不同内核版本，也**不是安全边界**（内核漏洞可逃逸）。

11. **把「陷入指令」当成特权指令** —— 陷入指令（`int 0x80`、`syscall`、`sysenter`）**恰恰是用户态可以主动执行的**，它的作用就是"合法地进内核"。真正不能碰的是关中断、改 PSW、设置页表基址、I/O 指令、停机指令这类**特权指令**。

12. **忽略「中断处理要关中断」的代价** —— 进入中断服务程序后通常先关中断（保护现场），这期间到来的新中断会被挂起。如果服务程序写得很长（比如在中断里做耗时 I/O），就会**丢中断、拉高响应延迟**。工程铁律：中断上半部只做最少的事，重活丢给下半部/工作队列——这正是 ch21 缓冲与驱动分层要解决的问题。

13. **以为引导就是"BIOS 直接启动程序"** —— 真实链条是：BIOS/UEFI 自检 → 读第一个可引导设备的 **MBR（前 512 字节，末尾 `0x55AA`）** 或 EFI 系统分区 → 交给**引导加载程序（GRUB）** → GRUB 加载内核镜像与 initramfs → 内核解压并初始化 → 挂载根文件系统 → 启动 `init`/`systemd`。中间任何一环坏了都表现为"开机黑屏"或 `grub rescue>`。
