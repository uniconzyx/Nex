# 并发、共享、虚拟、异步：操作系统的四个字到底在说什么

## 背得下「并发、共享、虚拟、异步」，却分不清它们谁依赖谁

初学者背"OS 有四大特征：并发、共享、虚拟、异步"，但一到选择题就分不清"并发和并行的区别""虚拟和共享谁依赖谁"。

原因在于：**这四个词不是并列的四个属性，而是一条因果链**。把链条记住，比背四个词有用得多：

```text
      物理上只有一颗 CPU、一份内存
                │
        ┌───────┴────────┐
        │  ① 并发         │  多个程序在"同一段时间"内都在推进
        │  (交替执行)     │  —— 这是 OS 存在的前提
        └───────┬────────┘
                │ 要并发，就必须让它们共用资源
        ┌───────┴────────┐
        │  ② 共享         │  互斥共享(打印机/临界区) / 同时共享(只读代码段)
        └───────┬────────┘
                │ 资源只有一份怎么办？把"一份"变出"多份"
        ┌───────┴────────┐
        │  ③ 虚拟         │  时分复用(CPU→每进程一个"自己的CPU")
        │                 │  空分复用(内存→每进程一个"自己的地址空间")
        └───────┬────────┘
                │ 交替+抢占+中断，导致程序走走停停
        ┌───────┴────────┐
        │  ④ 异步         │  程序以不可预知的速度推进
        └────────────────┘
```

一句话：**并发是目的，共享是约束，虚拟是手段，异步是代价。**

## 四大特征的准确表述与常见辨析：并发不是并行

| 特征 | 准确表述 | 常考辨析 |
|---|---|---|
| **并发** | 两个或多个事件在**同一时间间隔内**发生（宏观同时、微观交替） | 单核也能并发，**不能并行**；并行需要多处理机/多核 |
| **共享** | 系统中的资源可供内存中多个并发进程共同使用 | **互斥共享**（一段时间只允许一个进程用，如打印机、临界区）；**同时共享**（一段时间内允许多个进程"同时"访问，如只读代码段、磁盘文件） |
| **虚拟** | 把一个物理实体变为若干个逻辑对应物 | **时分复用**（CPU 分时、虚拟处理器）；**空分复用**（虚拟存储器把内存"变大"） |
| **异步** | 进程以不可预知的速度向前推进 | 异步的根源是"走走停停"；同步机制（信号量、锁）正是为了**把异步收敛成可控** |

再补两个容易漏的点：

- **并发 ≠ 并行**：并行（parallel）要求**同一时刻**真的在多个处理单元上执行。单核上的"同时听歌和写代码"是并发；四核上同时跑四个线程才是并行。
- **共享必须以并发为条件，并发又必须以共享为前提**——这句话是王道教材的原话，考试喜欢考"二者的关系"，答"互为存在条件"。

## 3. 可运行代码（C，含中文注释 + 真实输出）

下面这段程序把"并发 vs 并行"变成两张可以逐行核对的时间表：

```c
#include <stdio.h>
/*
 * c01：并发 vs 并行——用时间片表把两个字说清楚
 * 并发：单核上轮流执行（宏观同时，微观交替）
 * 并行：多核上真的同时执行
 */
typedef struct { const char *name; int need; } Task;   /* need = 需要的总时间片数 */

int main(void) {
    Task t[3] = {{"进程A", 3}, {"进程B", 2}, {"进程C", 2}};
    int left[3] = {3, 2, 2};
    int slot = 0, finished = 0;

    printf("【单核 · 并发】时间片轮转（每片 1 个单位）\n");
    printf("时间片  运行  就绪队列\n");
    while (finished < 3) {
        for (int i = 0; i < 3 && finished < 3; i++) {
            if (left[i] > 0) {
                left[i]--;
                printf("%4d    %-4s ", ++slot, t[i].name);
                printf("[");
                for (int j = 0; j < 3; j++) if (left[j] > 0) printf("%s%d ", t[j].name, left[j]);
                printf("]\n");
                if (left[i] == 0) finished++;
            }
        }
    }
    printf("总时间片 = %d\n\n", slot);

    printf("【双核 · 并行】同一时刻两个核各跑一个\n");
    printf("时刻  核0      核1\n");
    int rem[3] = {3, 2, 2};
    int core[2] = {-1, -1};
    int total = 0, doneCount = 0;
    while (doneCount < 3) {
        total++;
        /* 每拍开始：把跑完的核重新分配任务（两个核不能接同一个任务） */
        for (int c = 0; c < 2; c++) {
            if (core[c] == -1 || rem[core[c]] == 0) {
                core[c] = -1;
                for (int i = 0; i < 3; i++) {
                    if (rem[i] > 0 && core[1 - c] != i) { core[c] = i; break; }
                }
            }
        }
        printf("%4d  %-7s  %-7s\n", total,
               core[0] >= 0 ? t[core[0]].name : "(空闲)",
               core[1] >= 0 ? t[core[1]].name : "(空闲)");
        for (int c = 0; c < 2; c++) {
            if (core[c] >= 0) {
                rem[core[c]]--;
                if (rem[core[c]] == 0) doneCount++;
            }
        }
    }
    printf("总耗时 = %d 个时间单位（单核并发需要 %d 个）\n", total, slot);
    printf("\n结论：并行缩短的是墙钟时间，并发只是让多个任务都能「有进展」。\n");
    return 0;
}
```

输出（`gcc -std=c11 -O2` 真实运行结果）：

```text
【单核 · 并发】时间片轮转（每片 1 个单位）
时间片  运行  就绪队列
   1    进程A [进程A2 进程B2 进程C2 ]
   2    进程B [进程A2 进程B1 进程C2 ]
   3    进程C [进程A2 进程B1 进程C1 ]
   4    进程A [进程A1 进程B1 进程C1 ]
   5    进程B [进程A1 进程C1 ]
   6    进程C [进程A1 ]
   7    进程A []
总时间片 = 7

【双核 · 并行】同一时刻两个核各跑一个
时刻  核0      核1
   1  进程A  进程B
   2  进程A  进程B
   3  进程A  进程C
   4  (空闲)  进程C
总耗时 = 4 个时间单位（单核并发需要 7 个）

结论：并行缩短的是墙钟时间，并发只是让多个任务都能「有进展」。
```

**读表要点**：总工作量是 3+2+2=7 个时间单位。单核无论怎么调度都要 7 拍（并发不减少工作量）；双核理论下界 `ceil(7/2)=4`，而表里恰好达到 4——所以"并行才是速度的来源，并发只是让多个任务都能推进"。

## 三视角解析

### 🧑‍💻 程序员视角

线上真实场景：某服务**单请求 P99 正常，但 QPS 一上就雪崩**。看 `top` 发现 CPU 只有 40%，不少人第一反应"机器还闲，加并发！"——错。

真实原因是这台机器上跑着 **4 个容器共 2 核**：并发度早就超过物理并行度，每个线程的时间片被切得极碎，**上下文切换（`vmstat` 里 `cs` 字段）从 2 万/秒涨到 18 万/秒**，大量 CPU 花在保存/恢复现场而不是干活——这就是"并发上去了、吞吐反而掉了"。正确做法是把并行度对齐到核数（`worker_num = CPU 核数`，或按 `cgroup` 配额算），而不是无脑加线程。

另一个日常现象：`time` 命令的两个数 `real` 与 `user`。单线程程序 `real ≈ user`；多线程程序 `real < user`（比如 `real 2s, user 8s` 说明 4 核并行）；如果 `real` 远大于 `user`，说明在**等 I/O**（异步等待），不是算得慢。这条判据比任何监控面板都直接。

### 🎓 博士生视角

"并发"在理论上对应 **交错语义（interleaving semantics）**：n 个进程的执行被建模为 n 条指令序列的所有交错排列，程序正确性必须对**所有交错**成立——这就是为什么并发 bug 难复现（某个交错概率极低）。

形式化工具上，线性一致性（linearizability）给出了"并发对象可以被视作原子操作"的判定标准；而 **C++/Java 内存模型**把"没有数据竞争的程序，其行为等价于顺序一致执行"写成了定理（DRF-SC），这条定理是整个无锁编程的合法性基础。

虚拟化的极限也有理论边界：单核上用时间片模拟 k 个 CPU，`k` 越大每个任务获得的 CPU 份额越接近 `1/k`，但**切换开销随 k 线性增长**，因此有效并行度存在上界——这解释了为什么"超卖比"（vCPU/物理核）在云厂商那里是有限制的经验参数。

### 📚 考研者视角

408 高频考法：

1. **"下列关于并发与并行的说法正确的是"**——标准口径：并发是**同一时间间隔**内多个事件发生；并行是**同一时刻**多个事件发生；单处理机只能并发。
2. **"共享与并发的关系"**——答：**互为存在条件**。没有并发就谈不上共享（只有一个程序在跑，谈不上"共同使用"）；没有共享，并发也无意义。
3. **"虚拟技术分几类"**——**时分复用**（虚拟处理器）与**空分复用**（虚拟存储器）；CPU 分时是时分复用，把内存"扩容"是空分复用。
4. 易错点：把"异步"答成"程序执行速度快慢不一"——准确说法是**进程以不可预知的速度向前推进**，根源是"走走停停"（等 I/O、等锁、被抢占）。
