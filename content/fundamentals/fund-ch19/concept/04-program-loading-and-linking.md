# 从 boot 到 main：装入、链接与地址空间

## 从 a.c 到能跑：编译、链接、装入这三道工序各自解决什么

你写的 `a.c` 到"能跑"，中间隔了三道工序：**编译 → 链接 → 装入**。绝大多数人只会敲 `gcc a.c && ./a.out`，但一旦遇到这几个问题就答不上来：

- 为什么报 `undefined reference to 'xxx'`？（**链接**阶段的事）
- 为什么程序被 ASLR 随机化后还能正确访问全局变量？（**动态重定位**）
- 为什么"未初始化的全局数组"不占可执行文件体积，却占内存？（**bss 段**）
- 为什么开机黑屏停在 `grub rescue>`？（**引导链**断了）

这些问题全部属于"程序如何被装进内存并开始执行"，也是 408 第 1 章与第 3 章的连接点。

```text
   编译                 链接                    装入                执行
 a.c ──► a.o        a.o + libc ──► a.out      a.out ──► 内存映像       PC 指向 _start
 (-c)               (符号解析+重定位)            (地址重定位)          → main
```

## 三种装入方式、静态与动态链接以及地址空间的建立

### 2.1 三种装入方式

| 方式 | 何时确定物理地址 | 能否移动 | 是否支持换出换入 | 时代 |
|---|---|---|---|---|
| **绝对装入** | **编译时**（按程序一定装在固定位置） | 不能 | 不支持 | 单道批处理 |
| **可重定位装入（静态重定位）** | **装入时**一次性把地址全加上装入地址 | **不能**（表项已写死） | **不支持** | 早期多道 |
| **动态运行时装入（动态重定位）** | **运行时**由重定位寄存器 + 逻辑地址现算 | **能** | **支持** | 现代 OS |

一句话记忆：**绝对装入"编译定死"，静态重定位"装完锁死"，动态重定位"寄存器兜底"。**

### 2.2 三种链接方式

| 方式 | 符号解析时机 | 可执行文件体积 | 典型代价 |
|---|---|---|---|
| **静态链接** | 链接时把库代码**拷进**可执行文件 | 大（每个程序一份） | 内存里多份副本、库升级要重新链接 |
| **装入时动态链接** | **装入时**解析并映射共享库 | 小 | 启动时做重定位，启动变慢 |
| **运行时动态链接** | **第一次调用**才加载（懒绑定 `dlopen`/PLT） | 最小 | 首次调用有抖动（打进 P99） |

### 2.3 进程地址空间布局（x86-64 典型）

```text
 高地址  ┌──────────────────────────┐
         │ 内核空间（用户态不可访问）    │  ← ring3 访问触发段错误
         ├──────────────────────────┤
         │ 栈 stack（向下增长）        │  ← 局部变量、返回地址
         │      ↓                   │
         │      ...                 │
         │      ↑                   │
         │ 堆 heap（向上增长）         │  ← malloc / new
         ├──────────────────────────┤
         │ bss（未初始化全局，清零）    │  ← 不占文件，占内存！
         │ data（已初始化全局/静态）    │
         │ rodata（字符串常量、只读表）  │
         │ text（代码段，只读可执行）    │
 低地址  └──────────────────────────┘
```

**一个必须记住的反差**：`int big[1048576];`（全局、未初始化）编出来的可执行文件几乎不变大（bss 在 ELF 里只记录大小），但运行时真的要 4MB 内存并且被清零。反过来 `int big[1048576] = {0};` 显式初始化会落到 `data` 段，文件立刻膨胀 4MB。

### 2.4 引导链六阶段

| 阶段 | 做什么 | 失败现象 |
|---|---|---|
| ① BIOS/UEFI 自检 | POST 自检、枚举设备、按启动顺序选设备 | 无显示/蜂鸣 → 内存或显卡硬件 |
| ② 读引导扇区 | 读 MBR 前 512 字节（末尾须 `0x55AA`） | `Missing operating system` |
| ③ 引导加载程序 | GRUB 读 `grub.cfg`，加载内核镜像 + initramfs | `grub rescue>` |
| ④ 内核解压与初始化 | 建页表、初始化调度/中断/驱动子系统 | `Kernel panic - not syncing` |
| ⑤ 挂载根文件系统 | 按 `root=` 挂 `/`，必要时从 initramfs 切换根 | `VFS: Unable to mount root fs` |
| ⑥ init/systemd | 启动用户态服务，给出登录提示 | `emergency mode` |

## 3. 可运行代码（C，含中文注释 + 真实输出）

三种链接方式的差异，可以用"符号在什么时机被解析"来量化：

```c
#include <stdio.h>
#include <string.h>
/*
 * c04：三种链接方式的符号解析时机
 *   静态链接      ：链接时把所有 .o 和库函数「拷进」可执行文件 -> 体积大、启动快、无运行时依赖
 *   装入时动态链接：装入时解析符号，把共享库映射进地址空间 -> 体积小，但启动要做重定位
 *   运行时动态链接：直到第一次调用才加载（dlopen/lazy binding）-> 启动最快，但首次调用有抖动
 */
typedef struct { const char *sym; int defined; } Sym;

int main(void) {
    Sym lib[] = {
        {"printf", 1}, {"malloc", 1}, {"pthread_create", 1}, {"crypt", 1}, {"foo_custom", 1}
    };
    int n = (int)(sizeof(lib) / sizeof(lib[0]));

    int used[] = {1, 1, 0, 1, 1};     /* 程序实际用到了哪些符号 */

    int in_file = 0, at_load = 0, at_call = 0;
    for (int i = 0; i < n; i++) {
        if (!used[i]) continue;
        in_file++;                    /* 静态：全进可执行文件 */
        if (strcmp(lib[i].sym, "crypt") != 0) at_load++;   /* 常用库装入时解析 */
        else at_call++;               /* 冷门库留到调用时 */
    }

    printf("%-16s %-12s %-14s %s\n", "链接方式", "进文件符号", "装入时解析", "首次调用解析");
    printf("--------------------------------------------------------------\n");
    printf("%-16s %-12d %-14d %d\n", "静态链接", in_file, 0, 0);
    printf("%-16s %-12d %-14d %d\n", "装入时动态链接", 0, at_load, 0);
    printf("%-16s %-12d %-14d %d\n", "运行时动态链接", 0, 0, at_load + at_call);
    printf("\n程序共用到 %d 个外部符号，依赖库里有 %d 个。\n", in_file, n);
    printf("\n工程含义：\n");
    printf("  静态链接 -> 单文件分发（Go 默认），代价是每个进程一份副本；\n");
    printf("  动态链接 -> 多进程共享同一份 .so 的物理页，省内存但怕「依赖地狱」；\n");
    printf("  懒绑定   -> 启动快，但第一次调用的延迟会打进你的 P99 指标里。\n");
    return 0;
}
```

输出（`gcc -std=c11 -O2` 真实运行结果）：

```text
链接方式     进文件符号 装入时解析 首次调用解析
--------------------------------------------------------------
静态链接     4            0              0
装入时动态链接 0            3              0
运行时动态链接 0            0              4

程序共用到 4 个外部符号，依赖库里有 5 个。

工程含义：
  静态链接 -> 单文件分发（Go 默认），代价是每个进程一份副本；
  动态链接 -> 多进程共享同一份 .so 的物理页，省内存但怕「依赖地狱」；
  懒绑定   -> 启动快，但第一次调用的延迟会打进你的 P99 指标里。
```

再补一个可以自己动手验证的实验（三条命令，能直接看到"文件大小 vs 内存"的反差）：

```bash
echo 'int big[1048576]; int main(void){return big[0];}' > bss.c
gcc -c bss.c && ls -l bss.o          # 目标文件很小：bss 只记大小
echo 'int big[1048576]={1}; int main(void){return big[0];}' > data.c
gcc -c data.c && ls -l data.o        # 目标文件暴涨：data 要存初值
```

## 三视角解析

### 🧑‍💻 程序员视角

真实踩坑一：**分阶段发布时"新版本一上线就全量卡 300ms"**。排查发现新版本引入了一个冷门共享库，且用了**懒绑定**——每个进程第一次调用那个函数时都要 `dlopen` + 符号解析，而这一下正好落在首屏请求路径上。修复方式有两种：在启动时预热调用一次（把抖动挪到启动阶段），或链接时加 `-Wl,-z,now`（立即绑定，用启动时间换运行时确定性）。

真实踩坑二：**容器镜像 1.2GB**，其中一半是静态链接的二进制被复制进了十几个服务镜像。改成动态链接 + 基础镜像共享 `.so` 后，镜像降到 300MB，节点磁盘压力也随之下降——这就是"静态链接的副本代价"在云原生时代的具体账。

真实踩坑三：**开机停在 `grub rescue>`**。典型原因是 `/boot` 单独分区被格式化，或内核升级后 `grub.cfg` 指向了不存在的内核版本。修复靠 `ls (hd0,gpt1)/` 逐个分区找 `/boot`，再 `set root=`/`linux`/`initrd`/`boot` 手动引导——这一段正是"引导链每一环都依赖上一环"的实证。

### 🎓 博士生视角

地址重定位的本质是**符号绑定（symbol binding）**：程序里的 `&foo` 在编译期只是一个**未解析的占位符**（重定位表条目），链接器负责算出最终值。动态链接把这件事推迟到运行时，于是需要一个**间接跳转表**（ELF 的 PLT/GOT）：首次调用走 PLT → 动态链接器解析 → 回填 GOT → 后续直接跳。这也解释了为什么"函数地址"在动态链接下不能当编译期常量用（`-fno-plt`/`-fno-semantic-interposition` 是可选的优化开关）。

安全维度上，ASLR 与 PIE 让"绝对装入"彻底退场：每次运行的基址都不同，所以必须靠**相对寻址 + 运行时基址寄存器**。而这也催生了新的攻防——ROP 攻击靠的就是在已知模块里找 gadget；对应地，CFI（控制流完整性）与 CET（影子栈）在内核/编译器层把"合法跳转目标"约束住。

引导链在体系结构上的关键是**信任根的传递（chain of trust）**：UEFI Secure Boot 用固件里的公钥验签 bootloader，bootloader 验签内核，内核验签模块（`CONFIG_MODULE_SIG`）。这条链上任何一环缺失，"可信启动"就无从谈起——这是"程序如何被装入"在安全语境下的延伸。

### 📚 考研者视角

408 高频考法：

1. **"静态重定位与动态重定位的区别"** —— 标准答法从三处切：**时机**（装入时 vs 运行时）、**是否支持移动**（不能 vs 能）、**是否支持换出换入**（不支持 vs 支持）。
2. **"bss 段占不占磁盘空间"** —— 不占文件、占内存、且**清零**。常与 `data` 段对比出题。
3. **"引导扇区多大、结束标志是什么"** —— **512 字节**，最后两字节 `0x55AA`。
4. **"MBR 与分区表的关系"** —— MBR 前 446 字节是引导代码，接着 64 字节是分区表（4 个 16 字节表项），最后 2 字节是标志。
5. 易错：把"装入"与"链接"混为一谈。**链接解决"符号在哪"，装入解决"放在哪"**；`undefined reference` 是链接错误，`Segmentation fault` 是运行期地址错误。
