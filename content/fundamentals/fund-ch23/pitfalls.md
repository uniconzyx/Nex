# 常见陷阱 · 数据链路层

1. **把「组帧」当成「封装」** —— 封装是「加首部」，组帧是「让接收方能从连续比特流里切出帧边界」。加了首部不等于能切边界：一段纯 0x7E 的数据如果不做字节填充，接收方会把它切成好几帧。正确做法：先想「定界符/长度字段怎么保证数据里不出现」，再谈首部字段。
2. **零比特填充的规则记反** —— 不是「遇到 `01111110` 就插 0」，而是**发送方每出现 5 个连续 1 就立即插一个 0**（无论后面是 0 还是 1）。这样才能保证数据区永远不出现 6 个连续 1，也就永远不会与定界符 `01111110` 撞车。接收方是对称操作：每见到 5 个连续 1，就把紧跟的那个 0 删掉。
3. **以为 CRC 能纠错** —— CRC 只做**检错**：余数为 0 判无错，非 0 就丢弃等重传。它不给「错在第几位」的信息。想纠错要用海明码 / BCH / RS。以太网选 CRC-32 是因为「丢弃 + 上层重传」比「复杂纠错」便宜，这是端到端原则的体现。
4. **CRC 计算忘记「先补 r 个 0」** —— 求 FCS 时必须把数据左移 r 位（补 r 个 0）再做模 2 除法，余数才是 r 位。少补 0 会得到位数不足的余数，且结果错误。速记：`r = deg(G(x))`，补 0 的个数就是 r。
5. **海明码校验位位置记错** —— 校验位必须放在 **1, 2, 4, 8, ...（2 的幂）** 的位置，数据位占其余位置。位置放错时，指误字不再等于「出错位编号」，整套纠错就失效了。
6. **海明码的 r 用「k/2」或「log2(k)」估** —— 正确下界是 `2^r >= k + r + 1`（那个 +1 是「无错」状态）。k=4 时 r=3（2^3=8 ≥ 8），只按 log2(4)=2 取 r=2 会漏掉「无错」状态，纠错失败。
7. **以为 GBN 的窗口能取 2^n** —— GBN 必须 `W <= 2^n - 1`。取满 `W = 2^n` 时，若整窗 ACK 全丢，发送方重传的帧号与接收方「下一轮期待的新帧号」完全重合，接收方无法区分新旧，会重复交付。SR 因为收发窗口都要占序号空间，所以 `W <= 2^(n-1)`。
8. **二进制指数退避的范围记成 `[0, 2^k]`** —— 是 `[0, 2^k - 1]`，共 `2^k` 个取值，平均退避 `(2^k - 1)/2` 个争用期。第 1 次冲突 k=1 → 取 {0,1}，不是 {0,1,2}。
9. **最小帧长公式忘了「2τ 是往返」** —— `最小帧长 = 速率 × 2τ`，其中 2τ 是**往返**传播时延（最远两站信号来回一趟）。若误用单程 τ，算出的帧长只有一半，冲突会漏检。10Mbps 以太网 2τ = 51.2 μs → 512 bit = 64 B，正好对上「目的 6 + 源 6 + 类型 2 + 数据 ≥46 + FCS 4 = 64」。
10. **把 CSMA/CD 的关键说成「先听后发」** —— 「先听后发」只是 CSMA；CD 的关键是**边发边听、冲突即停**。它把冲突代价从「整帧发送时间」压到「检测到冲突的时间」（约一个争用期），这才是以太网在共享介质上能跑到 90% 以上利用率的原因。同理，无线不能做 CD 是因为自己发射功率远大于接收信号（可达 60 dB 差），听不到别人的冲突，只能改用 CSMA/CA + ACK 确认。
11. **把交换机当成「隔离广播域」的设备** —— 交换机隔离的是**冲突域**（每个端口一个冲突域），广播帧仍然泛洪到所有端口。隔离广播域要靠 **VLAN 或路由器**。集线器（hub）则两者都不隔离。
12. **以为 VLAN Tag 加在帧最前面 / 会改 MTU** —— 802.1Q 的 4 字节 Tag 插在**源 MAC 之后、类型字段之前**（TPID 0x8100 + TCI），帧头从 14 B 变 18 B；MTU 仍是 1500，但帧长上限从 1518 变 1522，老设备会把这个当「超长帧（baby giant）」丢掉。
13. **以为「CRC 通过」就等于「数据正确」** —— CRC 只能保证「传输过程没有可检出的比特错误」，防不住：① 上层写入时就已经错了；② 恶意构造的 CRC 碰撞；③ 顺序错乱/重复（那是序号要解决的）。所以可靠传输必须靠「序号 + 确认 + 重传」，CRC 只是第一道筛子。
14. **停等协议效率低，归因为「协议太简单所以慢」** —— 真正原因是**每帧都要等一个 RTT**：`U = Td/(Td+RTT)`。带宽越高 Td 越小，U 反而更低（长肥管道问题）。所以必须用滑动窗口把「在途帧数」提到 `1 + RTT/Td` 以上。
