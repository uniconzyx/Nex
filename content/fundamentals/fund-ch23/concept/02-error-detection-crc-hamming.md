# 差错控制：CRC 与海明码

## 1. 背景/动机

链路上一定有误码：双绞线上的串扰、光纤的色散、无线的衰落，都会让某个比特从 0 变成 1。链路层必须能回答两个问题：

1. **这一帧有没有错？** —— 检错（error detection）
2. **错了能不能改回来？** —— 纠错（error correction）

工程上这两个问题的答案很不相同：以太网选择「只检错，错了就丢，让上层重传」；内存 ECC 和深空通信选择「必须纠错，因为重传代价太高」。为什么同一个问题会有两种答案？这取决于**重传的成本**与**纠错的开销**哪个更划算——这是理解本章的关键。

## 2. 定义/要点

### 2.1 三种手段的定位

```text
手段        冗余        能力                     典型场景
--------------------------------------------------------------------
奇偶校验    1 bit       检 1 位错（检不出偶数个）  串口校验位、内存老式校验
CRC         r bit 余数   强检错（不纠错）          以太网 FCS、压缩包、磁盘扇区
海明码      r bit 校验   纠 1 位错（可检 2 位）     内存 ECC、卫星链路
```

### 2.2 CRC：模 2 除法

CRC 的核心是**模 2 除法**（减法即异或，不借位、不进位）：

```text
给定：数据 D（k 位），生成多项式 G(x)（r+1 位，最高位与最低位必须为 1）
步骤：
  1) 在 D 后面补 r 个 0  -> D·2^r
  2) 用 D·2^r 除以 G（模 2），得到 r 位余数 R
  3) 发送 T = D·2^r XOR R   （即把余数填进那 r 个 0 的位置）
校验：
  接收方算 T 除以 G 的余数，为 0 则判无错
```

例：`D = 1101011011`，`G = 10011`（即 `x^4 + x + 1`，r = 4）

```text
被除数（补 4 个 0）：1101011011 0000
逐位异或消去最高位的 1 ...
最终余数 R = 1110
发送帧 = 1101011011 1110
接收端 11010110111110 ÷ 10011 余 0000  -> 认为无错
```

### 2.3 海明码：用校验位指出「错在第几位」

海明码的思路完全不同：它不满足于「知道错了」，而是要让**校验位组合起来直接给出错误位置的二进制编号**。

```text
位置编号： 1  2  3  4  5  6  7
类型    ： P1 P2 D1 P4 D2 D3 D4
校验关系：
  P1 负责位置 1,3,5,7 （二进制最低位为 1 的位置）
  P2 负责位置 2,3,6,7 （二进制次低位为 1 的位置）
  P4 负责位置 4,5,6,7 （二进制第三位为 1 的位置）
接收端重算 S1,S2,S4：
  指误字 = S4 S2 S1（二进制），其值就是出错位的编号；为 0 表示无错
```

最少校验位数由**信息论下界**决定：

```text
2^r >= k + r + 1
        ↑       ↑
        数据位   「无错」这一种状态
```

代入验证：k=4 → r=3（2³=8 ≥ 4+3+1=8，恰好取等）；k=8 → r=4（16 ≥ 13）；k=512 → r=10（1024 ≥ 523）。

### 2.4 为什么链路层「检错不纠错」

海明码纠 1 位需要 `d_min >= 3`（码距 3），纠 1 位并检 2 位需要 `d_min >= 4`。码距越大，冗余越大。而链路层的误码多为**突发错误**（一次坏一串），海明码对突发错误无能为力，需要交织或 RS 码——复杂度陡增。

于是出现了**端到端原则**（Saltzer/Reed/Clark, 1984）的选择：链路层只做「便宜的检错 + 丢弃」，把「可靠交付」交给传输层（TCP）用「序号 + 确认 + 重传」实现。这样：
- 链路层保持简单、高速（硬件可实现，几十 ns 出结果）；
- 可靠性集中在一处实现，不必每跳都做；
- 对「误码极低的光纤」不浪费冗余，对「误码高的无线」由上层重传兜住。

## 3. 可运行代码

下面的程序不套记忆公式，**按定义逐位试出最少校验位 r**，并把不等式两边的实际数字打出来，方便手工核对。

```c
#include <stdio.h>
/* c02：差错控制——CRC 与海明码的分工 */
int main(void) {
    int ks[] = {4, 8, 16, 32, 64, 512};

    printf("Hamming: find min r such that 2^r >= k + r + 1\n");
    printf("--------------------------------------------------------------\n");
    printf("%-6s %-5s %-8s %-8s %-6s %s\n", "k", "r", "2^r", "k+r+1", "n", "redundancy");
    for (int i = 0; i < 6; i++) {
        int k = ks[i];
        int r = 1;
        while ((1 << r) < k + r + 1) r++;      /* 按定义试，不套记忆公式 */
        int n = k + r;
        printf("%-6d %-5d %-8d %-8d %-6d %.1f%%\n", k, r, 1 << r, k + r + 1, n,
               100.0 * r / n);
    }
    printf("--------------------------------------------------------------\n");
    printf("关键趋势：r 只随 k 的位数「对数增长」，所以 k 越大冗余率越低：\n");
    printf("  k 从 4 增到 512（128 倍），冗余率从 %.1f%% 降到 %.1f%%。\n",
           100.0 * 3 / (4 + 3), 100.0 * 10 / (512 + 10));
    printf("\nCRC 的能力边界（r 位余数，G(x) 为 r 阶生成多项式）：\n");
    printf("  1) 能检出所有「长度 <= r 位」的突发错误（含所有单比特错）；\n");
    printf("  2) 若 G(x) 含 (x+1) 因子，能检出所有奇数个比特错误；\n");
    printf("  3) 长度 = r+1 的突发错误，只有当它恰好等于 G(x) 时才漏检；\n");
    printf("  4) 长度 > r+1 的突发错误，漏检概率约为 2^-r。\n");
    printf("\n工程取向：\n");
    printf("  · 以太网用 CRC-32（r=32，漏检概率约 2^-32 = %.2e），只检错不纠错；\n",
           1.0 / 4294967296.0);
    printf("  · 内存 ECC / 卫星链路用海明码或 BCH，因为「重传代价极高」；\n");
    printf("  · 链路层选检错 + 上层重传，而不是纠错，这是「端到端原则」的体现。\n");
    return 0;
}
```

真实输出：

```text
Hamming: find min r such that 2^r >= k + r + 1
--------------------------------------------------------------
k      r     2^r      k+r+1    n      redundancy
4      3     8        8        7      42.9%
8      4     16       13       12     33.3%
16     5     32       22       21     23.8%
32     6     64       39       38     15.8%
64     7     128      72       71     9.9%
512    10    1024     523      522    1.9%
--------------------------------------------------------------
关键趋势：r 只随 k 的位数「对数增长」，所以 k 越大冗余率越低：
  k 从 4 增到 512（128 倍），冗余率从 42.9% 降到 1.9%。

CRC 的能力边界（r 位余数，G(x) 为 r 阶生成多项式）：
  1) 能检出所有「长度 <= r 位」的突发错误（含所有单比特错）；
  2) 若 G(x) 含 (x+1) 因子，能检出所有奇数个比特错误；
  3) 长度 = r+1 的突发错误，只有当它恰好等于 G(x) 时才漏检；
  4) 长度 > r+1 的突发错误，漏检概率约为 2^-r。

工程取向：
  · 以太网用 CRC-32（r=32，漏检概率约 2^-32 = 2.33e-10），只检错不纠错；
  · 内存 ECC / 卫星链路用海明码或 BCH，因为「重传代价极高」；
  · 链路层选检错 + 上层重传，而不是纠错，这是「端到端原则」的体现。
```

对照 `k=4` 那一行：`2^3 = 8`，而 `k+r+1 = 4+3+1 = 8`，**恰好取等**——这就是「4 位数据配 3 位校验」的来历，也解释了为什么 k=4 时冗余率高达 42.9%（7 位里 3 位是校验）。

## 三视角解析

### 🧑‍💻 程序员视角

CRC 是你每天都在用、却很少自己实现的东西——但**误用它的方式非常多**。

真实工作实例：一个日志采集服务把每条记录序列化后算 CRC32 存进文件头。某次升级后，运维发现「校验失败率从 0.001% 涨到 3%」，但磁盘 SMART 全绿、网络无丢包。排查了三天，原因是：新版本把结构体直接 `fwrite` 到文件，而结构体里有 3 字节的 padding 未初始化——**CRC 算的是内存里的字节（含未初始化的 padding），而读的时候 padding 被清零了**。数据本身没错，是「参与校验的字节范围」不一致。

这次事故的教训直接对应本章：
- **CRC 保护的是「字节序列」，不是「字段语义」**。凡是参与计算的范围不一致，校验必然失败。
- 真正要防「程序自己写坏」的场景，CRC 帮不了你——它能检出传输错误，检不出「写的时候就算错了」。所以关键路径常配「双写 + 比对」或「写后读校验」。
- 另一个常见坑：**CRC32 的初值与反射（reflected）约定**。zlib 的 CRC32 用「初值 0xFFFFFFFF + 输入输出反射 + 末值取反」，而某些嵌入式库直接用「初值 0」，两者对同一段数据算出的值完全不同。跨语言（C ↔ Java ↔ Python）对接时，必须显式确认这五个参数（poly / init / refin / refout / xorout），否则会出现「同一份数据两边算不一样」的诡异 bug。

### 🎓 博士生视角

CRC 的数学结构是**有限域 GF(2) 上的多项式环**：把比特串看成多项式系数，模 2 除法就是多项式除法，余数是 `D(x)·x^r mod G(x)`。这带来几个可证明的性质：

- **线性**：取余运算 `D ↦ D(x)·x^r mod G(x)` 是 GF(2) 上的线性映射，所以**当初值为 0 且不做末值取反时**有 `CRC(a XOR b) = CRC(a) XOR CRC(b)`。注意「初值非 0」会让它变成仿射映射（常数项不为 0），此时上式不成立——这也是为什么跨库对接必须对齐 init 参数。线性性让 CRC 可以**增量更新**：网络设备转发时只改几个字段，可以先「撤销旧字段的贡献」再「叠加新字段的贡献」，无需重算整帧。Linux 内核与 DPDK 都利用了这一点。
- **突发错误检出**：设错误多项式为 `E(x)`，漏检当且仅当 `G(x) | E(x)`。长度 ≤ r 的突发对应 `E(x) = x^i·e(x)`，`deg e < r`，而 `deg G = r`，故只有 `e = 0` 才整除——所以**所有长度 ≤ r 的突发错误必被检出**，这是定理而非经验。
- **海明码与线性分组码的统一**：海明码是 `(n, k)` 线性分组码的一个特例，校验矩阵 `H` 的列恰好是 1..n 的二进制表示，所以 `H·r = 综合式`（syndrome）直接给出错误位置。它的最小距离 `d_min = 3`，因此「纠 1 位」或「检 2 位」二选一；要「纠 1 检 2」必须扩成 SECDED（加一个总校验位，`d_min = 4`）。
- 更深一层，CRC 与**伪随机序列/扰码**同源：`G(x)` 为本原多项式时，`x^i mod G(x)` 的周期达到 `2^r - 1`，这正是 m 序列发生器的原理——所以「CRC 生成多项式」和「扩频码」在代数上是同一类对象。

### 📚 考研者视角

**408 高频考法**：

1. **给数据与生成多项式，求 CRC 余数与发送帧**。答题步骤固定：补 r 个 0 → 模 2 除 → 写余数 → 拼成发送帧。**必须写出除法过程**（408 大题按步骤给分）。
2. **给 k 求最少校验位 r**：用 `2^r >= k+r+1`，代入试。常见答案：k=4→r=3，k=8→r=4，k=16→r=5，k=32→r=6。
3. **海明码纠错**：给接收到的码字，算三个（或更多）校验组的异或值，组成指误字，指出错位并翻转。
4. **判断 CRC 能否检出某类错误**：靠「`G(x)` 是否含 `(x+1)` 因子」判断奇偶错检出能力。

**标准答题口径**：
- 「CRC 只能检错不能纠错，因为余数只提供『是否出错』的信息，不提供错误位置。」
- 「海明码能纠 1 位错，是因为指误字的值恰好等于出错位的编号；当发生 2 位错时，指误字会指向第三个位置，造成『越纠越错』。」

**易错点**：
- 补 0 的个数 = `deg G(x)` = `r`，不是 `r+1`，也不是「G 的位数」。
- 模 2 除法中「够减就减」的判据是**当前最高位是否为 1**，不是数值大小比较。
- 海明码校验位放在 `1,2,4,8,...` 位置；若题目把数据位放在 1,2,3,4 而校验位放后面，那是另一种约定，**必须按题目给定布局算**，不要硬套。
- 「检错」与「纠错」的能力不能同时按最大值取：码距 3 的码，要么纠 1 位，要么检 2 位；想两者兼得必须提高码距。
