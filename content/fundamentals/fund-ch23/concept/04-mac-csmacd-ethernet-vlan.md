# 介质访问控制与以太网

## 1. 背景/动机

多个站点共用一条信道时，必然要回答「**现在谁能说话**」——这就是介质访问控制（MAC, Medium Access Control）。

这个问题的解空间只有三类：

1. **事前分配**（信道划分）：把信道切成互不重叠的片，各用各的，绝不冲突。代价是「空闲也占着」。
2. **事后仲裁**（随机访问）：谁想说话谁就说，冲突了再处理。代价是冲突浪费。
3. **集中调度**（轮询/令牌）：按顺序一个个来。代价是调度开销与单点故障。

以太网选的是第 2 类里的 CSMA/CD，而它之所以能成功，关键不在「先听后发」，而在「**边发边听、冲突即停**」。

## 2. 定义/要点

### 2.1 三类 MAC 方法

```text
① 信道划分（静态、无冲突）
   FDM 频分：不同频段并行         （有线电视、早期宽带）
   TDM 时分：不同时隙轮流         （传统电话网 E1/T1）
   WDM 波分：光纤里不同波长       （骨干光传输）
   CDM 码分：不同正交码扩频       （3G/CDMA，军用抗干扰）
   特点：重负载下效率高，轻负载下浪费（分到的片用不完也不给别人）

② 随机访问（动态、可能冲突）
   ALOHA      ：想说就说              S = G·e^(-2G)，峰值 1/(2e) ≈ 18.4%
   时隙 ALOHA ：只在时隙边界发          S = G·e^(-G) ，峰值 1/e  ≈ 36.8%
   CSMA       ：先听后发（1-坚持 / 非坚持 / p-坚持）
   CSMA/CD    ：先听后发 + 边发边听     （有线以太网）
   CSMA/CA    ：先听后发 + 冲突避免 + ACK（无线 802.11）
   特点：轻负载下延迟低，重负载下冲突剧增

③ 轮询访问（受控、无冲突）
   令牌传递（Token Ring / FDDI）、轮询（polling）
   特点：可保证上限延迟，适合工业控制；但有令牌维护/主站单点问题
```

### 2.2 ALOHA 的吞吐上界（为什么它必然低效）

```text
纯 ALOHA：一帧的「易冲突窗口」= 2 个帧时（自己发之前 & 之后各一帧时）
          S = G·e^(-2G)  ->  dS/dG=0 得 G=0.5，S_max = 1/(2e) ≈ 0.184
时隙 ALOHA：只在时隙边界发，易冲突窗口缩到 1 个帧时
          S = G·e^(-G)   ->  G=1，S_max = 1/e ≈ 0.368
```

只把「易冲突窗口减半」，吞吐就翻倍——这说明 MAC 协议的性能对冲突窗口大小极其敏感。CSMA 再进一步：先听，有人说话就不发，把冲突概率压到远低于 ALOHA。

### 2.3 CSMA/CD 的三个关键数字

```text
① 最小帧长
   要求：发送方在帧发完之前必须能听到冲突
   最坏情况：两站相距最远，信号要走一个往返（2τ）
   故：发送时延 >= 2τ   =>   最小帧长 = 速率 × 2τ
   10 Mbps 以太网：2τ = 51.2 us
   最小帧长 = 10e6 × 51.2e-6 = 512 bit = 64 字节
   帧结构核对：目的6 + 源6 + 类型2 + 数据46 + FCS4 = 64 ✓

② 争用期（slot time）
   10 Mbps：512 bit 时间 = 51.2 us
   100 Mbps：5.12 us；1000 Mbps：4096 bit 时间 = 4.096 us
   （千兆用「载波扩展」把短帧补齐到 512 字节，否则 2τ 对应的最小帧只有 64 字节的 1/10）

③ 二进制指数退避
   第 i 次冲突：k = min(i, 10)，r 均匀取自 [0, 2^k - 1]
   等待 r 个争用期后重试；16 次仍失败 -> 丢弃并向高层报错
```

### 2.4 以太网帧格式与 VLAN

```text
前导码 7B | SFD 1B | 目的MAC 6B | 源MAC 6B | 类型 2B | 数据 46~1500B | FCS 4B
10101010... 10101011   <- SFD 的最后两位 11 表示「帧开始了」

帧长（不含前导码与 SFD）= 6+6+2+46+4 .. 6+6+2+1500+4 = 64 .. 1518 字节
帧间最小间隔 IFG = 12 字节时间（让接收方有时间处理）

802.1Q VLAN Tag（4 字节）插在「源 MAC」之后、「类型」之前：
  +--------+------------------+
  | TPID   | TCI              |
  | 0x8100 | PCP(3) DEI(1) VID(12) |
  +--------+------------------+
  后果：帧头 14B -> 18B；帧长上限 1518 -> 1522（老设备可能当超长帧丢弃）
```

### 2.5 交换机、冲突域、广播域

```text
设备        冲突域        广播域        说明
------------------------------------------------------------
集线器 hub   全部一个       全部一个      物理层转发，等于一根共享电缆
交换机 switch 每端口一个     全部一个      数据链路层，按 MAC 表转发
路由器 router 每端口一个     每端口一个    网络层，隔离广播
```

交换机自学习（无任何配置）：
1. 收到帧 → 记下「**源 MAC → 入端口**」到 MAC 表（带老化时间，默认 300 s）；
2. 查「目的 MAC」：命中 → 单播从该端口转发；未命中 → **泛洪**（除入端口外所有端口）；
3. 广播帧 / 未知单播 → 泛洪。

这解释了两件事：**交换机不隔离广播域**（广播会泛洪），以及**环路会导致广播风暴**（所以需要 STP/RSTP 生成树协议来阻塞冗余链路）。

## 3. 可运行代码

下面的程序量化「边发边听」到底省了多少：对比「发完才知道冲突」与「冲突即停」两种策略的时间浪费。

```c
#include <stdio.h>
/* c04：CSMA/CD 的「边发边听」——冲突检测能省多少时间
 * 不检测冲突（如 CSMA/CA 的无线场景）：整帧发完才发现白发了。
 * 检测冲突：一旦检测到冲突立即停止，只浪费「检测到的时间」。
 * 本程序对比两者在冲突场景下的时间浪费。*/
int main(void) {
    double frame_us = 1200.0;      /* 1500 字节 @10Mbps = 1200us */
    double detect_us = 25.6;       /* 最坏 2τ/2，即一个单向传播时延 */

    printf("发送一帧（1500B @10Mbps）需要 %.0f us\n", frame_us);
    printf("------------------------------------------------------------------\n");
    printf("%-12s %-14s %10s%%  %s\n", "policy", "waste(us)", "ratio", "适用场景");
    printf("%-12s %-14.1f %10.2f%%  %s\n", "no-detect", frame_us, 100.0,
           "无线（无法边发边听）");
    printf("%-12s %-14.1f %10.2f%%  %s\n", "CSMA/CD", detect_us,
           100.0 * detect_us / frame_us, "有线以太网");
    printf("------------------------------------------------------------------\n");
    printf("检测让冲突代价降低 %.0f 倍\n", frame_us / detect_us);
    printf("\n为什么无线不能边发边听？\n");
    printf("  无线是全双工受限的：自己发射的功率远大于接收到的信号（可达 60dB 差），\n");
    printf("  自己的信号会把别人的信号完全淹没，根本「听不到」冲突。\n");
    printf("  所以 802.11 改用 CSMA/CA：用 ACK 确认代替冲突检测，并加 RTS/CTS 缓解隐藏终端。\n");
    printf("\n结论：CSMA/CD 的关键不是「先听后发」，而是「边发边听、冲突即停」，\n");
    printf("      它把冲突代价从「整帧」压到一个争用期，这是以太网高效的根本原因。\n");
    return 0;
}
```

真实输出：

```text
发送一帧（1500B @10Mbps）需要 1200 us
------------------------------------------------------------------
policy       waste(us)           ratio%  适用场景
no-detect    1200.0             100.00%  无线（无法边发边听）
CSMA/CD      25.6                 2.13%  有线以太网
------------------------------------------------------------------
检测让冲突代价降低 47 倍
```

**47 倍**这个数字就是以太网能跑起来的根本原因：一次冲突只损失 25.6 μs 而不是 1200 μs，冲突成本被压到原来的 1/47，于是「随机争用」这个看似粗糙的策略在工程上变得可接受。

## 三视角解析

### 🧑‍💻 程序员视角

链路层看起来最「底层」，但它的问题在容器化时代全部回来了——因为**容器网络就是软件实现的一套二层/三层设备**。

真实工作实例：某 Kubernetes 集群的节点上，`docker0`/`cni0` 网桥下的 Pod 之间 RTT 抖动严重，`ping` 同节点 Pod 出现 5~20 ms 的毛刺。排查发现节点上跑着 600+ 个 Pod，网桥的 **FDB（MAC 表）频繁老化 + 泛洪**：容器重建后 MAC 变了，旧表项未过期，新 MAC 未知 → 泛洪到所有 veth → 每个 Pod 都收到一遍 → 所有 veth 的中断/软中断同时抬升，`ksoftirqd` 打满一个核。

这与本章的两个知识点完全对应：
- **交换机靠源地址学习、靠目的地址转发、未知目的泛洪** —— 容器频繁重建让「未知目的」成为常态，泛洪量随 Pod 数量线性增长。
- **广播域不隔离** —— 同网段 Pod 全在一个广播域里，ARP 广播会打到所有 600 个 veth。

修复方向也都来自本章：把大网段切成多个小网段（缩小广播域）、给节点网桥设更短的 `ageing_time`、或换成基于 eBPF 的三层转发（如 Cilium）直接绕过网桥泛洪。**如果你不知道交换机是怎么学 MAC 的，这个故障基本无法定位。**

另一个日常可见的现象：`ip -s link` 里 `errors`/`dropped` 计数增长、`ethtool -S` 里的 `rx_crc_errors` 增长，就是本章「CRC 校验失败 → 丢弃」的现场——它不是应用层的 bug，而是物理层/线缆问题（劣质网线、接头氧化、光模块衰减）。

### 🎓 博士生视角

MAC 协议的性能分析是**随机接入理论**的核心，几条结论有严格推导：

- ALOHA 的 `S = G·e^(-2G)` 来自「泊松到达 + 易冲突窗口 2T」的假设：一帧在其前后各 T 内无其他帧到达才成功，概率 `e^(-2G)`。时隙 ALOHA 的窗口缩为 T，得 `e^(-G)`。这两个上界（18.4% / 36.8%）是**协议结构决定的天花板**，与实现无关。
- CSMA 的分析需要引入「传播时延归一化参数」`a = τ/T`（τ 单程传播时延，T 帧时）。吞吐随 `a` 增大而下降：`a → 0` 时 CSMA 接近理想（冲突窗口趋零），`a` 大时退化为 ALOHA。这解释了为什么「同一套协议在局域网好用、在广域网上不行」——不是协议变了，是 `a` 变了。
- CSMA/CD 的最小帧长约束 `T >= 2τ` 等价于 `a <= 0.5`，即**冲突检测要求归一化传播时延不超过半帧时**。千兆以太网用「载波扩展」把最小帧拉到 512 字节，本质是把 `T` 变大以继续满足这个不等式；10G 以太网干脆放弃 CSMA/CD 改用全双工交换，因为 `2τ` 约束在大跨度下无法满足。
- 更深一层：随机接入的稳定性是**双稳态**问题。重负载下「冲突 → 重传 → 更多冲突」会形成正反馈，使系统从高吞吐态跌到低吞吐态（这就是以太网「拥塞崩溃」）。二进制指数退避的作用是**给这个正反馈加阻尼**，它本质是一个分布式拥塞控制律，与 TCP 的 AIMD 同源。

### 📚 考研者视角

**408 高频考法**：

1. **ALOHA 吞吐计算**：给 G 求 S；问「峰值是多少、在 G 等于多少时取到」。
2. **CSMA/CD 最小帧长**：给速率、距离、传播速度求最小帧长；或反求最大跨距。**必须会用 `2τ`（往返）**。
3. **二进制指数退避**：给冲突次数求退避范围与平均等待时间。
4. **以太网帧长边界**：为什么最小 64 B、最大 1518 B；VLAN 之后变 1522 B。
5. **冲突域/广播域计数**：给一张 hub/switch/router 拓扑图，数冲突域与广播域个数（年年考）。
6. **交换机自学习过程**：给一串帧的收发，写出 MAC 表变化与转发动作。

**标准答题口径**：
- 「CSMA/CD 采用二进制指数退避：第 i 次重传时从 `{0,1,...,2^k-1}` 中随机取 k=min(i,10)，退避 k 个争用期；16 次失败后丢弃该帧并向上层报告。」
- 「交换机根据帧的**源 MAC 地址**学习端口映射，根据**目的 MAC 地址**转发；目的地址未知时向除入端口外的所有端口泛洪；因此交换机隔离冲突域但不隔离广播域。」

**易错点**：
- 最小帧长算成 `速率 × τ`（漏了往返的 2）。
- 帧长 64 B 里包含前导码（**不包含**：前导码 8 B 是物理层加的，64 B = 6+6+2+46+4）。
- 把 ALOHA 的峰值记成 `1/e`（那是时隙 ALOHA）；纯 ALOHA 是 `1/(2e)`。
- 认为「交换机每个端口一个广播域」（错，广播域仍是 1 个）。
- 认为 1000BASE-T 的最小帧也是 64 B（标准值仍是 64 B，但**发送时**要用载波扩展补到 512 B，考试常考这个区别）。
- VLAN Tag 位置画错：必须画在源 MAC 与类型字段之间。
