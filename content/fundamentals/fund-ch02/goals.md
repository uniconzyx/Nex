# fund-ch02 学习目标：栈、队列与串

## 一、先修与定位

- **先修**：fund-ch01（顺序表与链表）——本章所有结构都建立在「连续内存 / 链式节点」两种底座之上。
- **后续衔接**：fund-ch03（树）——递归遍历靠**系统调用栈**，层序遍历靠**显式队列**；fund-ch04（图）——DFS 用栈、BFS 用队列；fund-ch06（操作系统）——进程调度队列、函数调用栈帧。
- **本章在面试中的权重：极高**。栈/队列是「白板题第一层」，而**单调栈与 KMP** 是从「会用」区分到「会用得对」的分水岭。

## 二、能力目标

学完本章，你应当能够：

1. 解释**栈为什么必须由硬件支撑**，并能画出 x86-64 下一次函数调用前后的栈帧变化。
2. 说清**循环队列为什么要牺牲一个空位**，以及 `(rear+1)%cap==front` 这个判满条件的取舍代价。
3. 见到「下一个更大元素 / 窗口最值 / 直方图最大矩形」时，**条件反射地想到单调栈/单调队列**，并说明它为什么是 O(N) 而不是 O(N²)。
4. 手写 **KMP 的 next 数组**，并解释「公共前后缀长度」与「失配后指针不回退」之间的因果链。
5. 判断一个具体问题该用栈、队列还是双端队列 —— 即**结构选择能力**，而不只是会写 API。

## 三、复杂度与工程目标

| 结构 | 关键操作 | 复杂度 | 工程要点 |
|---|---|---|---|
| 顺序栈 | push/pop | O(1) 均摊 | 动态扩容，与 vector 同源 |
| 链栈 | push/pop | O(1) | 无扩容但有指针开销与 cache miss |
| 循环队列 | enqueue/dequeue | O(1) | 必须牺牲一个空位或用 size 计数 |
| 单调栈 | 全数组一次扫描 | O(N) | 每个元素至多入栈出栈各一次 |
| 单调队列 | 滑窗最值 | O(N) | 双端队列 + 队首过期淘汰 |
| KMP | 匹配 | O(N+M) | 预处理 O(M)，主串指针永不后退 |

## 四、常见误区（先看，带着问题读）

- 以为「栈」只是 `std::stack` 这种容器 —— 其实**函数调用栈**才是栈最重要的存在形式。
- 以为数组实现的队列可以直接 `front++` —— 跑几轮就撞到数组尾部，**空间浪费**才是引入循环队列的真实原因。
- 以为单调栈是「某种特殊数据结构」—— 它**只是普通栈 + 一个维持单调性的 while 循环**，是「用法」不是「结构」。
- 以为 KMP 的核心是「跳转表」—— 核心是**利用已匹配信息避免主串指针回退**，next 数组只是这个思想的编码。
