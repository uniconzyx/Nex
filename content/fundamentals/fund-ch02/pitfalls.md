# fund-ch02 常见坑与避坑指南

1. **循环队列判空判满条件搞反 → 丢数据或死循环**
   牺牲一个空位时，**满**是 `(rear+1)%cap == front`，**空**是 `front == rear`。写反了会导致「明明还有空间却判满」或「空队列被当作满」。
   修法：写完后手动推演 cap=4、依次入 1/2/3、再出 1 个、再入 4 —— 逐步打印 front/rear 验证。

2. **数组队列直接 `front++` 不取模 → 假溢出**
   跑满一轮后 `rear` 撞到数组尾部，即使前面已空也判满。
   修法：所有下标推进一律 `(x + 1) % cap` 或 `(x + 1) & (cap-1)`（cap 取 2 的幂）。

3. **递归深度不可控 → 栈溢出（Segment Fault）**
   处理用户可控深度（链表长度、表达式嵌套、目录树）时用递归，深层数据直接崩，且**无法捕获恢复**。
   修法：改显式栈；或先估算最大深度并与栈上限（Linux 默认 8MB）比较。

4. **`sizeof` 求数组长度在函数参数里退化为指针**
   ```c
   void f(int a[]) { int n = sizeof(a)/sizeof(a[0]); }  /* 错：a 已是指针，n = 2 或 1 */
   ```
   根因：数组作为函数参数**退化为指向首元素的指针**，`sizeof` 得到的是指针大小（8 字节）。
   修法：把长度作为独立参数传入，或用 `size_t` 显式传递 + `assert`。

5. **单调栈存了值而不是下标 → 无法判断过期/算宽度**
   直方图最大矩形需要 `当前下标 - 左边界下标`，只存高度就算不出宽度。
   修法：**单调结构一律存下标**，需要值时用 `a[stk[i]]` 取。

6. **单调队列忘记淘汰队首过期元素 → 答案取自窗口外**
   只做了队尾淘汰，没做 `if (q[head] <= i - k) head++`，队首可能是早就滑出窗口的最大值。
   修法：**每轮先淘汰过期队首，再取答案**；顺序颠倒会读到过期值。

7. **KMP 的 next 数组下标含义混淆 → 整体错位**
   `next[j-1]` 与 `next[j]` 一字之差，会把「失配后跳到哪里」算错；有的教材用 `next[0]=-1` 的另一套约定。
   修法：**选定一套定义并在纸上推演 `P = "ababaca"` 的完整 next 表**，与代码打印结果比对。

8. **链式队列出队后忘了 `free` → 内存泄漏**
   出队只移动了 `front` 指针，节点内存没释放，长时间运行后 RSS 持续上涨。
   修法：出队时保存节点指针、改 `front`、再 `free`；用 valgrind 或简单计数器核对 malloc/free 次数。

9. **栈用数组实现却不对动态扩容做均摊分析 → 误判性能**
   以为 push 是 O(1) 就敢在循环里调用，忽略某次 push 会触发 O(N) 搬移。
   修法：明确「**均摊 O(1)**」的表述；若要最坏 O(1)，用链栈或预分配足够容量。
