# 栈：LIFO 与函数调用栈的硬件支撑

## 一、LIFO 不是「一种规定」，而是内存生长的自然结果

栈的语义是后进先出。但更值得问的是：**为什么计算机需要一个 LIFO 结构？**

答案在**函数调用**里。函数 A 调用函数 B、B 又调用 C，返回时必须「先回到 B、再回到 A」——返回顺序**恰好是调用的逆序**。任何「支持嵌套」的系统，其撤销顺序天然是逆序，所以 LIFO 是被**嵌套语义**逼出来的，不是人为设计。

## 二、调用栈的硬件支撑：栈指针与栈帧

x86-64 上，`rsp` 寄存器指向栈顶。`call` 指令做两件事：把**返回地址**压栈、跳转；`ret` 从栈顶弹出地址并跳回。整个过程**不需要任何软件数据结构**，是 CPU 指令级的。

一次调用的栈帧大致布局（地址从高到低）：

```
高地址
+------------------------+  <- 调用者的栈帧
|  调用者的局部变量      |
+------------------------+
|  传入的第 7+ 个参数    |  <- 前 6 个走寄存器 rdi/rsi/rdx/rcx/r8/r9
+------------------------+
|  返回地址（call 压入） |  <- ret 时弹出
+------------------------+  <- 被调用者栈帧起点（rbp 指向这里）
|  保存的旧 rbp          |
|  被调用者的局部变量    |
|  ...                   |  <- rsp 向下生长
+------------------------+  <- 当前栈顶
低地址
```

**关键推论**：

1. **栈是向下生长的**（地址递减），所以「栈溢出」是 `rsp` 一直接近甚至越过保护区。
2. **局部变量在栈上**，函数一返回就失效 —— 这解释了 fund-ch01 里「返回局部数组地址」为什么是悬垂指针。
3. **递归深度 = 栈帧数量**，每帧几十到几百字节，8MB 默认栈空间大概只能撑几万层，这就是递归算法在深链路上崩溃的原因。

## 三、递归与显式栈：等价但代价不同

任何递归都能改写成「显式栈 + 循环」。两者数值行为一致，但：

| 维度 | 系统调用栈 | 显式 `std::stack` |
|---|---|---|
| 空间位置 | 栈区（通常 1–8 MB，超了直接崩） | 堆区（可达 GB，可扩容） |
| 溢出表现 | SIGSEGV / stack overflow，**不可恢复** | 可判空、可限深、可降级 |
| 每帧开销 | 返回地址 + 保存寄存器 + 对齐填充 | 只存你需要的状态 |
| 速度 | 极快（mov/sub 几条指令） | 稍慢（堆分配 + 间接寻址） |

工程结论：**深度可控用递归（代码清晰），深度不可控（处理用户输入/深链）必须改显式栈**。

## 四、栈的三个经典用法

1. **括号匹配 / 标签闭合**：遇到开符号入栈，遇到闭符号比对栈顶。本质是「嵌套结构校验」。
2. **表达式求值**：中缀转后缀（调度场算法），再扫描后缀求值。运算符优先级 + 结合性被**编码成入栈/出栈时机**。
3. **DFS（深度优先搜索）**：栈顶就是「下一个要探索的节点」，天然对应回溯。

## 五、与程序员的对话：什么时候不该用栈

- 需要**随机访问中间元素**时 —— 栈只暴露栈顶，取中间元素要 pop 掉上面的，O(N) 且破坏结构。
- 需要**优先级出队**时 —— 那是堆（fund-ch03），不是栈。
- 需要**FIFO 公平性**（任务调度、消息队列）时 —— 用队列，LIFO 会导致饥饿。

## 三视角解析

### 🧑‍💻 程序员视角
- 深递归会爆栈：默认线程栈常为 1～8 MB，递归深度上万就有风险。改写为显式栈迭代，或调大 `ulimit -s`（治标）。
- C 语言**不保证尾调用优化**，不要把「递归写法」当作能自动优化成循环。
- 调试技巧：栈溢出（SIGSEGV）往往表现为「崩溃在看似无关的函数」，看 backtrace 的深度与重复模式即可判断。

### 🎓 博士生视角
- 调用栈是 **ABI 的物理体现**：参数按调用约定（SysV AMD64 用寄存器传前 6 个整型参数）入栈/入寄存器，返回地址压在栈上，返回时一次性重设 `rsp` 完成回收。
- 栈保护机制（stack canary）、`-fstack-protector`、NX 位与 ASLR 共同构成对抗栈溢出攻击的防线；红区（red zone）是 ABI 允许叶子函数临时使用的 128 字节栈下空间。
- 递归与显式栈**等价可证**：显式栈就是把「激活记录」从运行时搬到了堆上，代价是分配与指针开销，收益是深度不再受栈大小限制。

### 📚 考研者视角
- **408 必考**：栈的三种经典应用——**括号匹配、表达式求值（中缀转后缀/后缀求值）、递归到非递归**。
- 计组交叉考点：子程序调用时**返回地址压栈**、栈帧指针 EBP、参数传递顺序；「栈向低地址增长」是常考记忆点。
- 高频题型：给出中缀表达式写出后缀并逐步演算求值；给定入栈序列判断合法出栈序列（Catalan 数相关）。
- 记忆锚点：**中缀转后缀时，栈里存的是「还没确定优先级的运算符」**；左括号直接入栈，右括号弹出到左括号为止。
