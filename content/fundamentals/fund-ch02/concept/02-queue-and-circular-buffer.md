# 队列与循环队列：FIFO 与空间的循环复用

## 一、FIFO 的语义价值：公平性与有序性

队列保证先来先服务。它出现的场景和栈正好互补：

- **BFS**：按层扩散，靠队列保证「距离近的先被处理」→ 无权图最短路。
- **任务调度**：就绪队列、打印队列、消息队列，LIFO 会让早到的任务永远饿死。
- **缓冲区**：生产者-消费者之间的速度削峰。

## 二、数组队列的致命问题：假溢出

用数组实现队列，最朴素的做法是维护 `front` 和 `rear` 两个下标：

```c
int data[CAP]; int front = 0, rear = 0;
/* 入队 */ data[rear++] = x;
/* 出队 */ x = data[front++];
```

跑几轮后：`front` 和 `rear` 都推到了数组尾部，`rear == CAP` 但队列里其实只有几个元素——**前面的空间被出队释放了却再也用不上**。这就是「假溢出」（false overflow）。

可以搬移元素（O(N) 每次出队），也可以**让下标绕回来**——后者就是循环队列。

## 三、循环队列：让下标绕圈

核心是把线性下标**映射到环上**：

```c
/* 入队 */ data[rear] = x; rear = (rear + 1) % CAP;
/* 出队 */ x = data[front]; front = (front + 1) % CAP;
```

到这里一切顺畅，但**判空与判满会撞车**：当 `front == rear` 时，可能是空，也可能是满。有两种解法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **牺牲一个空位** | 队满条件 `(rear+1)%CAP == front` | 最多存 `CAP-1` 个，浪费一个槽 |
| **额外 size 计数** | 维护 `size`，空=`size==0`，满=`size==CAP` | 多一个变量与一次自增/自减 |

**为什么教材偏爱「牺牲一个空位」**：不需要额外状态，判满条件是一个纯函数式表达式，且写并发代码时少一个共享变量。**为什么生产代码偏爱 size**：容量利用率 100%，且 `size` 在无锁队列里往往本来就要维护（用于 CAS 判断）。

## 四、位运算优化：容量取 2 的幂

把 `% CAP` 换成 `& (CAP-1)`，前提是 `CAP` 是 2 的幂。现代环形缓冲区（如 Linux `kfifo`）几乎都这么做：

```c
#define CAP 1024
rear = (rear + 1) & (CAP - 1);   /* 等价于 % CAP，但快得多 */
```

原因是取模是除法指令（几十个周期），而与运算是单周期。这也是**为什么那么多库要求缓冲区大小必须是 2 的幂**。

## 五、扩展到双端队列（deque）

`deque` 两端都能进能出，是「栈 + 队列」的超集。它支撑两个重要场景：

1. **单调队列**（下一节）——需要队首淘汰 + 队尾淘汰。
2. **滑动窗口 / 撤销最近操作**——两端操作不对称的问题（如「滑动窗口内最大值的两端收缩」）。

## 六、与程序员的对话：队列的隐藏成本

- **数组队列**：扩容时要搬移所有元素；`memcpy` 的代价与容量成正比。
- **链式队列**：每次入队一次 malloc，**分配器锁**在高并发下成为瓶颈；且节点离散导致 cache miss。
- **环形缓冲 vs 链表**：前者一次分配、内存连续、可无锁（单生产者单消费者场景只用原子下标），这正是它成为**日志系统、音视频管线、网络协议栈**默认选择的原因。

## 三视角解析

### 🧑‍💻 程序员视角
- 环形缓冲是**生产者-消费者**的标准结构：单生产者单消费者（SPSC）场景可以用原子 head/tail 做到无锁。
- 容量取 2 的幂，把 `% cap` 换成 `& (cap-1)`，在热路径上省掉一次除法。
- 真实用途：音视频抖动缓冲、串口/网络收包队列、打点日志批量落盘。

### 🎓 博士生视角
- 无锁环形缓冲的正确性依赖**内存序**：生产者写完数据要让 `head` 以 release 发布，消费者读 `head` 用 acquire，否则会出现「看到有新元素但内容是旧的」。
- **伪共享（false sharing）** 是环形缓冲的经典性能陷阱：head 与 tail 落在同一 cache line 时，两个核会反复互相失效缓存行。测出吞吐异常低时优先怀疑它，用 padding 或 alignas(64) 隔开。
- 环形缓冲也是离散事件仿真、流式窗口聚合（滑动平均/分位数）的底层容器。

### 📚 考研者视角
- **408 必考**：循环队列判空/判满的三种方法——**牺牲一个存储单元**、**设标志位**、**设计数器**；对应判空 `front == rear`、判满 `(rear+1)%m == front`。
- 元素个数公式 `(rear − front + m) % m` 是必考计算题。
- 队列应用：BFS、树的层次遍历、缓冲区、打印机任务队列、页面置换的部分实现。
- 记忆锚点：**「牺牲一个单元」换取「判满不歧义」**——答题时说明这个权衡比只背公式更容易拿分。
