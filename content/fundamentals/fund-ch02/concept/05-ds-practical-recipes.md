# 凯喵实战手记：栈、队列与字符串匹配——数据结构入门的「第一道坎」

> 栈和队列看着简单，凯喵在刷题和写业务时却在「边界」「单调技巧」「KMP 的 next 数组」上反复栽。这一章我们钻进几个真实现场，把最朴素的两种结构用出花来。

### 1. 栈是「后进先出」，队列是「先进先出」

凯喵第一次用错：用栈存任务结果却期望按提交顺序返回，全乱了。栈（`push/pop`）只从同一端进出，最后进的最先出，适合「撤销、括号匹配、函数调用」；队列（`enqueue/dequeue`）从一端进另一端出，先来的先服务，适合「缓冲、BFS、任务调度」。选结构前先想清楚「你要的是最近优先还是最早优先」。

### 2. 数组栈的均摊分析：push 不是真 O(1)

凯喵把数组栈当「永远 O(1)」在循环里疯狂 push，偶尔卡顿：

```
动态数组栈：容量满时扩容为 2 倍，搬运 N 个元素
均摊下来每次 push 仍是 O(1)，但「某一次」是 O(N)
```

单次扩容触发 O(N) 搬移，但均摊到所有 push 仍是 O(1)。表述要说清「**均摊 O(1)**」，若业务要求**最坏 O(1)**，用链栈或预分配足够容量。混淆两者会误判性能。

### 3. 循环队列：用模运算复用空间

凯喵的普通队列出队后前面空着却不断越界：

```cpp
// 循环队列：front/rear 用 % capacity 回绕
rear = (rear + 1) % cap;
front = (front + 1) % cap;
// 判空：front == rear；判满：留一个空位 (rear+1)%cap == front
```

普通数组队列出队后前面空间难复用；循环队列用取模让首尾相接，空间利用率高。注意「判满要预留一个空位」或用计数变量，否则满和空都是 `front==rear` 无法区分。

### 4. 单调栈：O(n) 求「下一个更大元素」

凯喵用两层循环求每个元素右侧第一个比它大的，超时：

```python
# 单调（递减）栈：栈里存下标，遇到更大的就弹出并计算
stack = []
for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:
        j = stack.pop()
        ans[j] = i   # j 的「下一个更大」是 i
    stack.append(i)
```

维护一个**单调性**的栈，把「暴力 O(n²)」压成 O(n)。变体：每日温度、柱状图最大矩形、接雨水。核心套路是「入栈时处理掉所有能被当前元素结算的历史」。

### 5. 单调队列：滑动窗口最大值

凯喵每滑一格就扫一遍窗口，O(nk) 超时：

```python
# 双端队列存下标，队首始终是当前窗口最大值的下标
from collections import deque
q = deque()
for i, x in enumerate(nums):
    while q and nums[q[-1]] <= x: q.pop()
    q.append(i)
    if q[0] == i - k: q.popleft()   # 移出窗口
    if i >= k-1: res.append(nums[q[0]])
```

双端队列维护「窗口内单调递减」，队首即最大值，整体 O(n)。和单调栈的区别：栈处理「下一个」，队列处理「窗口内」。

### 6. 双栈模拟队列 / 双队列模拟栈

凯喵被面试官要求「用栈实现队列」：

```
栈模拟队列：入队压栈 A；出队时若栈 B 空，把 A 全部倒进 B，再弹 B 顶
均摊 O(1)，但单次倒栈可能 O(n)
```

理解「两种结构可互相模拟」能加深对它们本质的理解，也是经典面试题。关键是想清「哪个栈负责入、哪个负责出、何时倒腾」。

### 7. 括号匹配：栈的招牌应用

凯喵做表达式校验时，用栈三行搞定：

```python
st = []
for c in s:
    if c in "({[": st.append(c)
    elif c in ")}]":
        if not st or not matches(st.pop(), c): return False
return not st   # 栈空才合法
```

遇到左括号入栈，右括号弹出栈顶比对。最后栈空才是合法串。这是「嵌套结构」类问题的通用思路（XML、HTML 标签、函数调用栈都同理）。

### 8. 字符串是不可变还是可变：先看清语言

凯喵在 Python 里反复拼接字符串，性能差十倍；在 C 里改字符数组却越界：

```python
# Python：str 不可变，循环 += 是 O(n²)
parts = []; [parts.append(x) for x in seq]; "".join(parts)   # O(n)
```

不同语言字符串语义不同：Python/Java 字符串不可变（拼接要新建），C 是字符数组（要自己管 `\0` 和长度）。做题先确认「我能不能原地改」，选错会导致超时或缓冲区溢出。

### 9. KMP 的核心：next 数组是「最长公共前后缀」

凯喵用暴力匹配在长文本里 TLE：

```
next[j] = 模式串 p[0..j-1] 的「最长相等前后缀长度」
失配时模式串不回退到开头，而是按 next 跳到「已匹配部分的后缀能对接的前缀」
匹配复杂度 O(n+m)，暴力是 O(n*m)
```

KMP 把「已经比对过的信息」利用起来，避免主串指针回退。`next` 数组本身用「自己匹配自己」的递推预处理得到。核心就一句：**失配后跳到哪，由模式串自身的结构决定**。

### 10. 求 next 数组：自己匹配自己的递推

凯喵卡在 next 怎么算，其实是「前缀函数」：

```python
def build_next(p):
    n = len(p); nxt = [0]*n; j = 0
    for i in range(1, n):
        while j and p[i] != p[j]: j = nxt[j-1]
        if p[i] == p[j]: j += 1
        nxt[i] = j
    return nxt
```

`j` 表示「当前已匹配的前缀长度」，失配就沿 `nxt` 回退（类似 KMP 主流程）。这个递推是理解 KMP 的钥匙，背下来不如推一遍。

### 11. 字符串哈希：把匹配变成数值比较

凯喵在「多次子串查询」时用哈希替代 KMP：

```python
# 滚动哈希：H[i..i+L) = (H[i-1]*B + s[i+L] - s[i-1]*B^L) % MOD
# 比较子串 = 比较哈希值，O(1)；注意模冲突可用双模或自然溢出
```

Rabin-Karp 思路：用多项式滚动哈希把子串映射成数，比较哈希即比较内容。适合「多模式/多查询」。代价是哈希冲突，可用双模或随机基数缓解。和 KMP 互补：KMP 无冲突但只单模式，哈希灵活但有碰撞风险。

### 12. 边界与退化：空串、单字符、全相同

凯喵的 KMP 在「模式全相同」时 next 全 0 差点栈溢出，字符串题九成 bug 在边界：

```
必测：空串、单字符、模式=文本、模式全是同一字符、文本不含模式、模式比文本长
```

任何字符串/栈/队列实现都要先过一遍边界：空输入、长度 1、全相同字符、超长输入。边界不过，逻辑再漂亮也白搭。

> 凯喵总结：栈队列字符串的坑九成在「均摊分析混淆」「循环队列判满」「单调栈/队列套路」「KMP 的 next 本质」「字符串不可变语义」「边界测试」。把这 12 个现场刻进手感，数据结构第一关稳过。

> 现场之外：单调栈和单调队列是「把暴力压成 O(n)」的两把利器，看到「下一个更大/更小」「窗口最值」先想它们；KMP 和字符串哈希是「多模式匹配」的双保险。三者都不是死记硬背，而是「如何利用已算信息避免重复劳动」。

> 一句话收尾：栈和队列是数据结构里最朴素的两个，但朴素不等于简单——把它们的边界和单调技巧吃透，大半算法题的骨架就有了。

### 凯喵复盘：单调与匹配，都是「复用已算信息」

这 12 个现场里藏着一条通用心法：**凡是「暴力会重复算」的地方，都有办法把已算的信息存下来复用」。单调栈/队列把「之前比过的大小关系」留在栈/队列里，省掉暴力里的内层循环；KMP 的 next 数组把「模式串自身的结构」预处理好，省掉主串指针回退；字符串哈希把「子串比较」变成「数值比较」。它们的共同点是「不白算第二遍」。刷题时只要发现自己在写两层循环，先停一下问：有没有一个单调结构或前缀信息能替我记住历史？这一问，往往就是 O(n²) 到 O(n) 的差距。

## 三视角解析
### 🧑‍💻 程序员视角
凯喵写过一个「最近打开的 10 个文件」功能，用 `list` 每次 `remove` 再 `append`，数据量一大就卡——换成 `collections.deque(maxlen=10)` 之后复杂度从 O(n) 降到 O(1)。循环队列的坑更经典：用 `(rear+1) % capacity == front` 判满，就必须牺牲一个空位，否则「队空」和「队满」的条件完全一样，无法区分。单调栈则是面试高频：求「下一个更大元素」时，栈里存的是**下标**而不是值——存值就没法算距离，这是第一次写最容易犯的错。**栈解决「最近的未匹配项」，队列解决「按层/按序推进」，看到这两类特征就该想到它们。**

### 🎓 博士生视角
栈与队列是「受限的线性表」，其价值在于把「访问顺序」这一约束显式化：栈对应后进先出的括号嵌套结构（与上下文无关文法的推导同构），队列对应广度优先的层序展开（与图的最短路径分层同构）。单调栈的均摊分析同样用势能法：每个元素最多入栈出栈各一次，故总代价 O(n)。字符串匹配的 KMP 用前缀函数把「失配回退」摊还到线性，本质是复用已匹配部分的自相似性；而 AC 自动机把 KMP 推广到多模式，用 Trie + 失配指针实现一次扫描匹配全部模式，是字典匹配的标准解。

### 📚 考研者视角
408 对栈队列的要求集中在「循环队列的下标运算」与「栈的应用」：
1. **循环队列判空判满**：牺牲一个单元时，队空 `front == rear`，队满 `(rear+1) % MaxSize == front`，元素个数 `(rear - front + MaxSize) % MaxSize`。这三个式子必须能默写并互相推导。
2. **栈的应用**：括号匹配、表达式求值（中缀转后缀）、递归转非递归、进制转换。常考「给出中缀表达式，写出后缀表达式并求值」。
3. **栈与队列的相互模拟**：两个栈模拟队列（一个入、一个出，出栈为空时整体倒过去），两个队列模拟栈。要能说清「为什么需要两个」。
4. **KMP**：`next` 数组手算 + 匹配过程，注意主串指针不回溯。
