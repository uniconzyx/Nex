# 02 · 分页、分段与地址转换：一次访存到底几次内存

## 一、分页的基本机制

- 逻辑地址空间划分为**页（Page）**，物理内存划分为**页框（Frame）**，两者**大小相同**（必须是 2 的幂）。
- **页表（Page Table）** 建立「页号 → 页框号」映射，存放在**内存**（现代实现由 MMU 硬件走页表）。
- **逻辑地址结构**：

```
|     页号 P (k 位)     |    页内偏移 W (n 位)    |
            ↓ 查页表
|   页框号 F (m 位)     |    页内偏移 W (n 位)    |  = 物理地址
```

**核心公式（必背）**：

$$
\text{页大小} = 2^n,\quad \text{页内偏移位数} = n = \log_2(\text{页大小}),\quad \text{页号位数} = \text{逻辑地址位数} - n
$$

$$
\text{页表项数} = 2^{\text{页号位数}},\quad \text{页表大小} = \text{页表项数} \times \text{页表项字节数}
$$

**例题**：32 位逻辑地址、页大小 4KB、页表项 4B。
- 页内偏移 $n = \log_2 4096 = 12$ 位；页号 $= 32 - 12 = 20$ 位。
- 页表项数 $= 2^{20} = 1\text{M}$ 项；**单级页表大小 $= 1\text{M} \times 4\text{B} = 4\text{MB}$**。
- **问题**：每个进程都要 4MB 连续页表 ⇒ 1000 个进程就是 4GB，光页表就撑爆内存。

## 二、多级页表：为什么能省下 99% 的空间

把 20 位页号再切成两段（各 10 位）：

```
| 一级页号(10) | 二级页号(10) | 页内偏移(12) |
```

- **页目录**：$2^{10} = 1024$ 项，每项 4B ⇒ **4KB（正好一页）**。
- **二级页表**：$2^{10}$ 张，每张 $2^{10}$ 项 × 4B = 4KB。

**关键收益**：一个只用了几 MB 的进程，其一级页号与二级页号在**高位**上只有极少数组合非零。**二级页表可以按需分配**——用到的才建。于是常驻内存的页表从 4MB 降到「4KB 页目录 + 少数几张 4KB 二级页表」。

$$
\text{实际节省} = 1 - \frac{4\text{KB} + k \times 4\text{KB}}{4\text{MB}} \quad (k \text{ 为实际用到的二级页表数})
$$

**代价**：一次逻辑地址转换需要**两级页表 + 最终数据** ⇒ **3 次访存**（两级页表各一次 + 数据一次）。

## 三、TLB（快表）：把 3 次访存压回 1 次

**TLB** 是 MMU 内的**相联存储器**，缓存「页号 → 页框号」的映射，按内容并行查找，命中则**无需访存查页表**。

**有效访问时间（EAT）**：设访存一次为 `t`，TLB 查找耗时 `ε`（通常忽略或计入），命中率 `h`：

$$
\text{EAT} = h \times (t + \varepsilon) + (1-h) \times (t + \varepsilon + 2t) \quad \text{（两级页表，不含 TLB 命中时的访存）}
$$

更常见的单级页表写法：

$$
\text{EAT} = h \times t + (1-h) \times 2t = t\,(2 - h)
$$

**例题**：`t = 100ns`，`h = 98%`，单级页表。
$$\text{EAT} = 100 \times (2 - 0.98) = 102\,\text{ns}$$
**命中率从 98% 掉到 90%，EAT 变成 110ns（慢 8%）**——TLB 命中率对性能极其敏感，这就是**大页**（2MB Huge Page）能显著提速的根源：**同样的 TLB 表项数覆盖更多内存 ⇒ 命中率提升**。

## 四、分段与段页式

| 维度 | 分页 | 分段 | 段页式 |
|---|---|---|---|
| 划分依据 | **物理**（等长，对用户不可见） | **逻辑**（按代码/数据/栈，长度可变，对用户可见） | 先按逻辑分段，段内再分页 |
| 地址结构 | 页号 + 页内偏移 | 段号 + 段内偏移 | 段号 + 页号 + 页内偏移 |
| 碎片 | **内部碎片**（最后一页） | **外部碎片** | **内部碎片**（最后一页/段） |
| 是否共享/保护方便 | 不易（逻辑单位被切开） | **容易**（按段共享） | 兼具两者 |
| 访存次数 | 1 次查页表 + 1 次取数 = 2 | 1 次查段表 + 1 次取数 = 2 | **2 次查表 + 1 次取数 = 3** |

**段页式的访存次数是经典考点**：`段表 → 页表 → 数据` 共 **3 次**访存，加 TLB 后命中可降为 1 次。

**地址转换流程（段页式）**：
1. 用**段号**查段表 → 得到该段的**页表始址**与**页表长度**；
2. 用**页号**查页表 → 得到**页框号**；
3. **页框号 × 页大小 + 页内偏移** = 物理地址。

## 五、可运行代码：地址转换与 EAT 计算

```c
#include <stdio.h>

/* 例：32 位逻辑地址、4KB 页、页表项 4B，两级页表各 10 位 */
int main(void) {
    int page_bits = 12, pa_bits = 32, pte_bytes = 4, level_bits = 10;
    int page_size = 1 << page_bits;
    int vpn_bits = pa_bits - page_bits;
    long pte_count = 1L << vpn_bits;
    long single_pt = pte_count * pte_bytes;

    printf("page size          = %d B\n", page_size);
    printf("page offset bits   = %d\n", page_bits);
    printf("page number bits   = %d\n", vpn_bits);
    printf("PTE count          = %ld\n", pte_count);
    printf("single-level PT    = %ld B = %ld KB\n", single_pt, single_pt / 1024);

    long l1_entries = 1L << level_bits;
    long l2_entries = 1L << level_bits;
    printf("2-level: L1 entries= %ld (L1 size = %ld B)\n", l1_entries, l1_entries * pte_bytes);
    printf("         L2 tables = %ld, each %ld B\n", l2_entries, l2_entries * pte_bytes);

    /* 三次访存 vs TLB 命中 */
    double t = 100.0;
    for (int hp = 90; hp <= 99; hp += 3) {
        double h = hp / 100.0;
        double eat1 = h * t + (1 - h) * 2 * t;   /* 单级页表 */
        double eat2 = h * t + (1 - h) * 3 * t;   /* 两级页表 */
        printf("h=%2d%%  EAT(1-level)=%.1f ns  EAT(2-level)=%.1f ns\n", hp, eat1, eat2);
    }
    return 0;
}
```

## 三视角解析

### 🧑‍💻 程序员视角
- **`madvise(MADV_HUGEPAGE)` 与大页**：现代服务里把大内存区标注为 THP，能把 TLB 未命中降低一个数量级（TLB 表项数有限，2MB 页覆盖的内存是 4KB 页的 512 倍）。数据库（PostgreSQL/Oracle）、JVM（`-XX:+UseLargePages`）都吃这一口。
- **`minor fault` 与 `major fault`**：页表项存在但页不在物理内存 ⇒ **major fault**（要读磁盘，慢几个数量级）；页表项不存在需建立 ⇒ **minor fault**。用 `/usr/bin/time -v` 的 `Major (requiring I/O) page faults` 一栏就能看出来。
- **`mmap` 做文件映射是分页机制的直接产物**：把文件页映射进地址空间，**读写内存就是读写文件**，缺页时由内核自动从磁盘取页。这就是为什么 DBMS、`mmap`-based 索引（LMDB）能绕开 `read()` 的拷贝。
- **段错误（SIGSEGV）不是「分段」造成的**：现代 OS 用分页实现保护，`SIGSEGV` 来自**页表项的权限位**（读/写/执行/用户态位）不匹配。名字是历史遗留，别被术语误导。

### 🎓 博士生视角
- **多级页表的空间收益是「稀疏性假设」的产物**：它假设地址空间**稀疏使用**（进程只在少量高位组合上有映射）。对**密集使用**整个地址空间的进程（如大型数值模拟），多级页表并不省空间，反而多一次访存——这正是 **倒排页表（inverted page table）** 存在的理由：表项数只与**物理页框数**相关（与地址空间无关），代价是需要哈希查找。
- **TLB 的「覆盖度（reach）」与「命中率」是两回事**：覆盖度 = 表项数 × 页大小。`h` 依赖**局部性**。工作集若超过 TLB 覆盖度，命中率会**断崖式下跌**——这与 Cache 的容量-冲突-强制失效分类是一致的分析范式。
- **EAT 公式的建模前提**：上面公式假设 TLB 查找与访存**串行且无重叠**，且忽略 TLB 未命中时的**页表页本身也可能缺页**（此时会产生**页表缺页**，代价更高）。严格的 EAT 模型应该是期望值对**完整事件树**求和——考试给的是简化模型，**要说清你用的是哪个模型**。
- **分页与分段的哲学差异**：分页把地址空间视为**一维的线性对象**（页码是算术量），分段视为**二维对象**（段号是名字、偏移是量）。前者便于硬件实现，后者贴合程序员心智。**段页式是「用硬件的线性机制模拟逻辑结构」的妥协产物**。

### 📚 考研者视角
- **408 存储管理计算题标准解法**（一步一步，不跳）：
  1. 由页大小求**页内偏移位数** $n = \log_2(\text{页大小})$；
  2. **页号位数** = 逻辑地址位数 $- n$；
  3. **页表项数** $= 2^{\text{页号位数}}$，**页表大小** = 项数 × 每项字节数；
  4. 两级页表：把页号**等分**（题目若给不等分，按题目给）。
- **EAT 常考两种写法**，务必看题目给不给 TLB 查找时间：不给则 `EAT = h·t + (1-h)·2t`；给了则 `EAT = h(t+ε) + (1-h)(t+ε+2t)`。**答错往往就错在这一步**。
- **段页式访存次数 = 3**（段表 + 页表 + 数据），加 TLB 命中 = 1。**这是必背数字**。
- **易错点**：分页的**页表项数与进程大小无关**（只与地址位数有关）——很多同学误以为「进程小页表就小」，那说的是**多级页表按需分配**后的**实际占用**。
- 记忆锚点：**「页内偏移位数 = log₂页大小」**、**「页表项数 = 2^(地址位数 − 偏移位数)」**、**「段页式三次访存、TLB 命中一次」**。
