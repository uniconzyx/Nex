# 01 · 连续分配与碎片：首次/最佳/最坏适应到底差在哪

## 一、连续分配的三种方式

| 方式 | 做法 | 碎片类型 | 说明 |
|---|---|---|---|
| **单一连续分配** | 内存分「系统区 + 用户区」，同一时刻只放一个程序 | **内部碎片** | 最简单、无外部碎片，但内存利用率极低 |
| **固定分区分配** | 预先划分若干**大小固定**的分区 | **内部碎片** | 分区大小与作业大小不匹配 ⇒ 分区内浪费 |
| **动态分区分配** | 按作业需求**动态**切分，分区数可变 | **外部碎片** | 灵活，但会产生大量小到无法利用的空洞 |

**关键判据（必背）**：
- **内部碎片** = 分配给你的块**比你要的大**，多出来的部分在**你占的块内部**浪费掉。
- **外部碎片** = 空闲内存**总量够**，但被切得太碎、**没有一块连续空间装得下**。

> 记忆锚点：**「内部碎片是『分多了』，外部碎片是『太碎了』」**。固定分区只有内部碎片，动态分区只有外部碎片，分页只有内部碎片（最后一页填不满），分段只有外部碎片。

## 二、动态分区的四类放置算法

设空闲分区链（按地址递增）为 `[100K, 500K, 200K, 300K, 600K]`，现在要分配一块 `212K`：

| 算法 | 规则 | 本例选中 | 特点 |
|---|---|---|---|
| **首次适应 FF** | **从头**找第一个够大的 | 第 2 块 500K | 快；低地址区易被反复切碎 |
| **最佳适应 BF** | 找**最小够用**的 | 第 4 块 300K | 看似省，实际**留下最小碎片**，加剧外部碎片 |
| **最坏适应 WF** | 找**最大**的 | 第 5 块 600K | 留下的大空洞还可再用，但大分区很快耗尽 |
| **邻近适应 NF** | 从**上次结束位置**继续找 | 视上次位置而定 | 避免低地址区被切碎，但**高地址大分区被破坏** |

**考试常考结论**：
- **首次适应**综合性能最好（不必排序、开销小、保留高地址大空间）。
- **最佳适应**在**理论上**碎片最小，但工程上**最差**——因为它制造大量「几乎不可用」的微小碎片。
- **最坏适应**看似聪明，实际让大分区迅速消失，遇到大作业就分配失败。
- **邻近适应**是首次适应的改进，但当分配-释放频繁时，会让**整个内存空间都被切碎**。

## 三、紧凑与对换

- **紧凑（Compaction）**：移动所有进程**拼合**空闲区，得到一个大的连续空闲块。代价是**必须搬迁所有进程**、更新地址映射，且**不是所有系统都能做**（需重定位支持）。
- **对换（Swapping）**：把**整个进程**换出到外存，让出内存。它是「内存不够」的**粗粒度**解法，而分页是**细粒度**解法。

**为什么 OS 最终都走向分页？** 因为连续分配的根本矛盾是「**程序大小与分区大小必须匹配**」，无论是内部还是外部碎片都在浪费内存。分页用「**离散分配 + 页表映射**」把这个矛盾彻底消除——代价是**每次都多一次访存查页表**（用 TLB 弥补）。

## 四、可运行代码：三种适应算法的分配模拟

```c
#include <stdio.h>
#include <string.h>

#define N 5

/* 空闲分区链：按地址递增 */
int free_blk[N] = {100, 500, 200, 300, 600};

/* 返回选中的下标，-1 表示分配失败 */
int first_fit(int need) {
    for (int i = 0; i < N; i++) if (free_blk[i] >= need) return i;
    return -1;
}
int best_fit(int need) {
    int best = -1;
    for (int i = 0; i < N; i++)
        if (free_blk[i] >= need && (best == -1 || free_blk[i] < free_blk[best])) best = i;
    return best;
}
int worst_fit(int need) {
    int w = -1;
    for (int i = 0; i < N; i++)
        if (free_blk[i] >= need && (w == -1 || free_blk[i] > free_blk[w])) w = i;
    return w;
}

int main(void) {
    int need = 212;
    int a = first_fit(need), b = best_fit(need), c = worst_fit(need);
    printf("free blocks(Top to bottom): ");
    for (int i = 0; i < N; i++) printf("%d%s", free_blk[i], i + 1 < N ? ", " : "");
    printf("\nrequest = %d\n", need);
    printf("first-fit  picks idx=%d (size=%d) leftover=%d\n", a, free_blk[a], free_blk[a] - need);
    printf("best-fit   picks idx=%d (size=%d) leftover=%d\n", b, free_blk[b], free_blk[b] - need);
    printf("worst-fit  picks idx=%d (size=%d) leftover=%d\n", c, free_blk[c], free_blk[c] - need);
    printf("best-fit leaves the SMALLEST hole -> most tiny unusable fragments\n");
    printf("worst-fit leaves the LARGEST hole  -> big blocks vanish fast\n");
    return 0;
}
```

## 三视角解析

### 🧑‍💻 程序员视角
- **真实分配器不用上面任何一种**：glibc 的 `malloc` 用**显式空闲链表 + bin（按大小分箱）+ tcache（每线程缓存）**，Linux 内核用 **buddy system（伙伴系统）** 处理页级分配 + **slab/slub** 处理小对象。它们要解决的是**O(1) 快路径 + 低碎片**，而不是「考试题里挑哪块」。
- **伙伴系统的巧思**：空闲块大小永远是 2 的幂，释放时检查「伙伴块」是否空闲，空闲则合并并**递归向上**。用地址位运算就能算出伙伴地址：`buddy = addr XOR size`。这让「合并」从「遍历链表」变成**一次异或**。
- **工程上防外部碎片优先于「选哪个算法」**：现代分配器的思路是**把对象按大小分箱**（同箱内块大小相同 ⇒ 天然无外部碎片，只有内部碎片），再用 `mmap` 处理超大对象直接交给内核。
- **代码里最实在的一条**：长生命周期进程反复申请/释放**不同大小**的块，碎片会累积；能复用缓冲池（`sync.Pool` / 对象池 / 内存池）就别反复 `malloc`。

### 🎓 博士生视角
- 动态分区分配的**放置算法是「一维装箱（1-D Bin Packing）」的在线版本**。装箱问题是 **NP-hard**，而在**在线**（不预知后续请求）约束下，任何确定性算法的竞争比都有下界——首次适应约为 `2`（即最多浪费一倍空间），最佳适应可达 `O(log n)` 倍。**这解释了为什么「最佳适应理论最优」是个误区：它优化的是单步，而非全局**。
- **碎片的形式化**：设已分配块数 `n`、空闲块数 `m`，则外部碎片比例可用「空闲总量 / 最大空闲块」刻画。当该比值 → ∞ 而最大空闲块 < 请求时，就发生「**假性内存不足**」——这与虚拟内存的「**请求分页下的缺页**」是不同层面的问题，**别混为一谈**。
- **紧凑的不可行性**：紧凑要求「进程可搬迁」，而搬迁需要**重定位寄存器**或**基址-限界**支持。在分页模型下，紧凑退化为「**页框重映射**」（只改页表，不动数据），成本从 `O(内存)` 降到 `O(页表)`——**这是分页相对连续分配最本质的收益之一**。
- 「内部碎片恒存在于分页的最后一页」这一事实有量化的**期望浪费**：若页大小为 `p`、平均进程大小 `s`，则期望内部碎片约 `p/2` 每进程。**页越小碎片越少，但页表越大**——这是分页设计里的核心权衡，也是「多级页表 + 大页（2MB/1GB）」并存的原因。

### 📚 考研者视角
- **408 存储管理必考**：连续分配 ↔ 分页 ↔ 分段 ↔ 段页式的**碎片类型对照**（固定分区=内部、动态分区=外部、分页=内部、分段=外部、段页式=内部）。
- **高频计算题**：给定一串「分配 60K、释放、分配 100K…」与初始空闲链，要求画出**每次操作后的空闲分区链**，并比较 FF/BF 的结果。**答题要点：BF 每次都要扫描全表并选最小满足者，别忘了「若相等取地址小的」这条约定**。
- 常考的**「紧缩（紧凑）」前提**是「进程可重定位」，而重定位又分**静态重定位**（装入时改地址，不能紧凑）与**动态重定位**（运行时由基址寄存器计算，可紧凑）。**只有动态重定位的系统才能做紧凑**——这是标准答案里的关键句。
- **内部碎片 vs 外部碎片**的量化举例：固定分区 64K 装 60K 作业 ⇒ 内部碎片 4K；动态分区装完还剩 10K+5K 两块而请求 12K ⇒ 外部碎片 15K 却分配失败。
- 记忆锚点：**「首次不看大小、最佳留最小坑、最坏留最大坑、邻近从上回继续」**；**「分页内部碎、分段外部碎、段页式只有内部碎」**。
