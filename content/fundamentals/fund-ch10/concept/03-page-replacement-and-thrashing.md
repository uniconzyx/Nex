# 03 · 页面置换算法与抖动：FIFO 为什么会「越给越差」

## 一、四种置换算法的判定规则

给定**引用串** $R$ 与**可用帧数** $m$，逐个引用判断「命中 / 缺页」，缺页且帧满时按算法淘汰一页。

| 算法 | 淘汰谁 | 实现代价 | 特点 |
|---|---|---|---|
| **OPT（最佳）** | 淘汰**将来最长时间不再访问**的页 | **不可实现**（需预知未来） | 作为**理论下界**，用来衡量其他算法 |
| **FIFO** | 淘汰**最先进入**内存的页 | 只需一个队列，**极低** | 简单，但**有 Belady 异常** |
| **LRU** | 淘汰**最久未被访问**的页 | 需按访问时间排序，**较高**（栈 / 时间戳 / 链表） | 性能接近 OPT，**无 Belady 异常** |
| **Clock（NRU）** | 环形扫描，遇**访问位=1** 则清 0 并跳过，遇 **0** 则淘汰 | **低**（只维护一位 + 指针） | LRU 的廉价近似 |

**经典引用串与结果**（帧数 = 3）：`7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1`
- **OPT**：9 次缺页
- **FIFO**：15 次缺页
- **LRU**：12 次缺页

> 顺序永远是 **OPT ≤ LRU ≤ Clock ≤ FIFO**（对本例），但**这个不等关系不是普遍成立的**——FIFO 与 Clock 在特定串上可能优于 LRU。

## 二、Belady 异常：FIFO 的「反直觉」

**定义**：对同一引用串，**增加可用帧数反而导致缺页次数增加**。

**最小复现例**：引用串 `1,2,3,4,1,2,5,1,2,3,4,5`

| 帧数 | FIFO 缺页次数 |
|---|---|
| **3 帧** | **9** |
| **4 帧** | **10** |

**为什么 LRU 不会**？因为 LRU 满足**栈算法（Stack Algorithm）**性质：$m$ 帧常驻的页集合**永远是** $m+1$ 帧常驻页集合的**子集**。于是增加帧数只可能让「命中集」单调扩张，缺页数**单调不增**。

**FIFO 不满足**该性质——它按「进入时间」淘汰，与访问历史无关，$m$ 帧的驻留集**不是** $m+1$ 帧驻留集的子集。这就是异常的根源。

**Clock 与 LRU 的关系**：Clock 是 LRU 的近似，但它**也不满足**严格的栈性质（因为访问位只在扫描时被清），因此在极端串上同样可能出现类 Belady 现象。

## 三、改进型 Clock：为什么要看「修改位」

朴素 Clock 只看**访问位 A**。但被淘汰的页若**被修改过（脏页）**，淘汰时必须**写回磁盘**——代价极高。

**改进型 Clock 同时看访问位 A 与修改位 M**，四类页优先级：`(0,0) < (0,1) < (1,0) < (1,1)`（越左越优先淘汰）。

**四步扫描规则（必背）**：
1. **第一轮**：从指针开始找 **A=0 且 M=0** 的页，找到即淘汰；遇 A=1 则**置 A=0**（给它第二次机会），继续。
2. **第二轮**（第一轮没找到）：再找 **A=0 且 M=1** 的页，找到即淘汰（**最多一次写回**，因为第一轮已把所有 A 清 0）。
3. **第三轮**：指针回到起点，重复第一轮（此时所有页 A 都是 0，必然能选出一个）。
4. **第四轮**：重复第二轮（兜底）。

**收益**：优先淘汰**干净页**，把写回次数降到最低。**代价**：可能多扫描几轮 CPU 时间——**用 CPU 换 I/O**，在 I/O 昂贵时值得。

## 四、抖动与工作集模型

**抖动（Thrashing）**：进程**频繁缺页**，把大部分时间花在换页上，CPU 利用率骤降。

**恶性循环（必背）**：
```
多道程序度 ↑ → 每进程分到的帧数 ↓ → 缺页率 ↑ → 需更多换入换出
     → CPU 利用率 ↓ → 调度器以为「CPU 空闲」→ 调入更多进程 ↑ → 回到第一步
```
**这正是 408 反复考的机制**：**CPU 利用率下降不是「CPU 空闲」，而是「在等 I/O」**，但调度器无法区分，于是越调越糟。

**工作集模型（Working Set Model）**：设窗口为 $\Delta$（如最近 10000 次访存），
$$
\text{WSS}_i = \text{进程 } i \text{ 在最近 } \Delta \text{ 次引用中访问到的不同页数}
$$
$$
\text{总需求} D = \sum_i \text{WSS}_i
$$
- 若 $D > m$（总帧数）⇒ **必然抖动**，应**挂起某个进程**（降低多道程序度）；
- 若 $D \le m$ ⇒ 可安全运行。

**缺页率（Page Fault Rate）**：
$$
P = \frac{\text{缺页次数}}{\text{总访问次数}}, \qquad
\text{有效访问时间} = (1-P) \times \text{访存时间} + P \times \text{缺页处理时间}
$$
**注意缺页处理时间包含**：陷入内核 + 查外存地址 + 读盘（毫秒级）+ 更新页表 + 恢复现场。**它比访存慢 5~6 个数量级**，所以 $P$ 稍涨，EAT 就爆炸。

**全局置换 vs 局部置换**：
- **局部置换**：只在本进程的帧中淘汰 ⇒ 抖动被限制在单进程内，但**帧数不足时无解**。
- **全局置换**：可从任意进程的帧中淘汰 ⇒ 灵活，但**一个抖动的进程会抢夺其他进程的帧**，可能引发**连锁抖动**。

## 五、可运行代码：四种置换算法与 Belady 异常

```c
#include <stdio.h>
#include <string.h>
#include <limits.h>

#define MAXF 8
#define MAXR 32

int faults_fifo(const int *r, int n, int m) {
    int q[MAXF], head = 0, cnt = 0, f = 0;
    for (int i = 0; i < n; i++) {
        int hit = 0;
        for (int j = 0; j < f; j++) if (q[j] == r[i]) { hit = 1; break; }
        if (hit) continue;
        cnt++;
        if (f < m) q[f++] = r[i];
        else { q[head] = r[i]; head = (head + 1) % m; }
    }
    return cnt;
}

int faults_lru(const int *r, int n, int m) {
    int q[MAXF], last[MAXF], f = 0, cnt = 0;
    for (int i = 0; i < n; i++) {
        int hit = -1;
        for (int j = 0; j < f; j++) if (q[j] == r[i]) { hit = j; break; }
        if (hit >= 0) { last[hit] = i; continue; }
        cnt++;
        if (f < m) { q[f] = r[i]; last[f] = i; f++; }
        else {
            int victim = 0;
            for (int j = 1; j < m; j++) if (last[j] < last[victim]) victim = j;
            q[victim] = r[i]; last[victim] = i;
        }
    }
    return cnt;
}

int faults_opt(const int *r, int n, int m) {
    int q[MAXF], f = 0, cnt = 0;
    for (int i = 0; i < n; i++) {
        int hit = 0;
        for (int j = 0; j < f; j++) if (q[j] == r[i]) { hit = 1; break; }
        if (hit) continue;
        cnt++;
        if (f < m) { q[f++] = r[i]; continue; }
        int victim = -1, far = -1;
        for (int j = 0; j < m; j++) {
            int k = i + 1;
            while (k < n && r[k] != q[j]) k++;
            if (k > far) { far = k; victim = j; }
        }
        q[victim] = r[i];
    }
    return cnt;
}

int main(void) {
    int ref[] = {7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1};
    int n = 20;
    printf("reference string (len=%d)\n", n);
    printf("frames |  OPT |  FIFO |  LRU\n");
    printf("-------+------+-------+------\n");
    for (int m = 3; m <= 5; m++)
        printf("  %d    | %4d | %5d | %4d\n", m, faults_opt(ref, n, m), faults_fifo(ref, n, m), faults_lru(ref, n, m));

    int bel[] = {1,2,3,4,1,2,5,1,2,3,4,5};
    int bn = 12;
    printf("\nBelady anomaly demo (FIFO on 1,2,3,4,1,2,5,1,2,3,4,5)\n");
    printf("  frames=3 -> faults=%d\n", faults_fifo(bel, bn, 3));
    printf("  frames=4 -> faults=%d\n", faults_fifo(bel, bn, 4));
    printf("  more frames, MORE faults  => Belady anomaly\n");
    printf("  LRU(3)=%d  LRU(4)=%d  (stack algorithm: never worsens)\n",
           faults_lru(bel, bn, 3), faults_lru(bel, bn, 4));
    return 0;
}
```

## 三视角解析

### 🧑‍💻 程序员视角
- **Linux 实际用的是「双 LRU 链表 + 二次机会」**：`active` 与 `inactive` 两条 LRU 链表，新页进 inactive 头部，被二次访问则升到 active。当需要回收时从 inactive 尾部取——这就是 **Clock 思想的链表化实现**，避免了环形扫描的 CPU 开销。
- **`/proc/sys/vm/swappiness` 是「换出倾向」旋钮**：调高会让内核更积极换出匿名页。**数据库服务器通常设为 1~10**，因为换出会带来不可预测的延迟毛刺（`major fault` 是毫秒级）。
- **OOM Killer 与抖动是两件事**：抖动是「慢」，OOM Killer 是「杀」。容器里没有 swap 时，内存超限直接走 **cgroup OOM**；有 swap 时可能先经历长时间抖动再被杀。**排查时要看 `/proc/vmstat` 的 `pgmajfault` 和 `pswpin/pswpout`**。
- **性能调优的优先顺序**：先**减少工作集**（数据结构紧凑化、流式处理替代全量加载），再考虑**加内存**。因为抖动是**非线性灾难**，而减少工作集是**线性收益**，前者更便宜。

### 🎓 博士生视角
- **Belady 异常与「栈算法」**：设 `B(m, i)` 为访问前 `i` 次后驻留的页集合。栈算法要求 `B(m, i) ⊆ B(m+1, i)` 对所有 `i` 成立。LRU 满足（按最后一次访问时间排序的栈，帧数增加只是保留栈底更多项）；FIFO 不满足（它按进入顺序，与访问模式脱钩）。**这个证明是「置换算法是否可能异常」的判定准则**。
- **OPT 的下界性质**：由**交换论证（exchange argument）**可证 OPT 在每一步都最小化缺页数；这也是为什么 OPT 被用作**竞争比**分析的基准。LRU 的竞争比是 `k`（k 为帧数），即 LRU 的缺页数最多是 OPT 的 `k` 倍——**这是一个紧界**，存在达到该界的对抗性序列。
- **抖动的形式化**：设进程 $i$ 的缺页率为 $P_i$，则 CPU 有效利用率
  $$
  U = 1 - \sum_i P_i \cdot \tau_{\text{fault}} / T
  $$
  当 $\sum_i \text{WSS}_i > m$，$P_i$ 会随多道程序度**超线性增长**（因为被换出的页又会立刻被访问），形成**正反馈**。**工作集模型的本质是把这个正反馈回路斩断**——通过限制驻留进程数。这与网络拥塞控制里的「拥塞崩溃」在数学结构上同构。**
- **改进型 Clock 的扫描轮次分析**：第一轮把所有 A 清 0，保证第二轮必然成功；因此**最坏情况扫描 `2n` 个表项**（n 为帧数），摊还意义下是 `O(1)`（每个表项在一次淘汰中最多被看两次）。这解释了为什么 Clock 能取代 LRU 成为实际实现。

### 📚 考研者视角
- **408 必考「引用串 + 帧数 → 缺页次数」**，几乎每年都有。**答题规范**：画一个表格，每列一次引用，每行一个帧，**缺页打 ×**，最后统计。**不要跳步**，因为步骤分很重。
- **Belady 异常只在 FIFO（以及 Clock 等非栈算法）出现，LRU 与 OPT 不会**——这是标准答案。给例子时用 `1,2,3,4,1,2,5,1,2,3,4,5`（3 帧 9 次 < 4 帧 10 次），**这个例子要背下来**。
- **抖动原因的答题模板**（三步）：① 多道程序度过高 ⇒ 每进程帧数不足；② 缺页率上升 ⇒ 进程频繁等待换入换出 ⇒ CPU 利用率下降；③ 调度器误判 CPU 空闲 ⇒ 继续调入进程 ⇒ 恶性循环加剧。**必须写出「CPU 利用率下降≠CPU 空闲」这一句**。
- **工作集 $\text{WSS}_i$ 与驻留集**：408 常给「窗口大小 Δ」与访问序列，要求算某时刻的工作集。**口径：取最近 Δ 次引用中访问到的「不同页号」个数**。
- **有效访问时间公式**：`EAT = (1-p)·访存时间 + p·缺页处理时间`，其中 `p` 是缺页率。**注意「缺页处理时间」包含磁盘 IO（毫秒级）**，这是小题常设的陷阱（给「磁盘读取 8ms」）。
- 记忆锚点：**「OPT 看未来、LRU 看过去、FIFO 看进队、Clock 看访问位」**、**「只有 FIFO 有 Belady」**、**「抖动三步走：帧少→缺页多→误判空闲」**。
