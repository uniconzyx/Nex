# 存储层次与局部性原理

## 1. 一个无法回避的矛盾

CPU 的时钟频率几十年涨了上千倍，而 DRAM 的访问延迟只降了不到十倍。
这个剪刀差（**存储墙**）意味着：如果 CPU 每次都要去内存取数据，它会长期空转。

解决方案不是"造一种又快又大又便宜的存储器"（物理上不存在），
而是**搭一个层次结构**，让绝大多数访问落在快的那几层：

```
        容量小 / 快 / 贵                      容量大 / 慢 / 便宜
   ┌──────────┐
   │ 寄存器    │  ~1 周期        < 1 KB
   ├──────────┤
   │ L1 Cache │  ~4 周期        32~64 KB
   ├──────────┤
   │ L2 Cache │  ~12 周期       256 KB ~ 1 MB
   ├──────────┤
   │ L3 Cache │  ~40 周期       数 MB ~ 数十 MB
   ├──────────┤
   │  主存     │  ~200 周期      数 GB
   ├──────────┤
   │  磁盘/SSD │  ~10^5~10^7 周期  数 TB
   └──────────┘
```

**层次能成立的前提就是局部性（locality）** —— 如果程序的访问是均匀随机的，加多少层都没用，
因为每一层都会被穿透。

## 2. 两种局部性

- **时间局部性**：刚被访问过的数据，很可能马上又被访问（循环变量、反复调用的函数）。
- **空间局部性**：访问了地址 $x$，很可能接着访问 $x$ 附近的地址（顺序遍历数组、指令顺序执行）。

程序里这两条极其普遍：一个 $O(n)$ 的循环遍历数组，就同时具备两种局部性。
**这就是为什么 Cache 的一次"取块"能带来远大于 1 的收益**。

## 3. 量化：命中率与 AMAT

设命中率为 $h$，命中时间为 $T_c$，缺失代价为 $T_m$（衡量时要统一"单位"）：

$$T_{avg} = h \cdot T_c + (1-h) \cdot T_m$$

更常用的写法是**分层的缺失代价**：

$$\text{AMAT} = T_{hit} + \text{miss\_rate} \times \text{miss\_penalty}$$

**关键敏感性**：命中率从 99% 掉到 95% 看起来只差 4 个百分点，
若 $T_{hit} = 1$、$T_m = 100$，则

- $h = 0.99$：$\text{AMAT} = 1 + 0.01 \times 100 = 2$
- $h = 0.95$：$\text{AMAT} = 1 + 0.05 \times 100 = 6$

**性能下降到 1/3**。所以工程上"把命中率从 95% 提到 99%"往往是巨大的优化。

## 4. 缺失代价为什么这么高（多级层次的影响）

若 L1 缺失后去 L2 命中，则 L1 的"缺失代价"其实是 L2 的 AMAT。于是有递推：

$$\text{AMAT}_{L1} = T_{L1} + m_{L1}\left( T_{L2} + m_{L2}\left( T_{L3} + m_{L3} \cdot T_{mem} \right) \right)$$

这个**嵌套结构**是本章最重要的公式形态，408 的 AMAT 大题基本都是它的展开。

## 5. 局部性不是"自然规律"，而是可被破坏的

- **跨步访问**：遍历 $A[i][j]$ 时按列访问二维数组，会破坏空间局部性（每次跳过一整行）；
- **伪共享（false sharing）**：两个线程写同一缓存行里的不同变量，硬件无法区分，
  导致该行在两核之间反复失效 —— 这是"数据布局错误引发性能灾难"的经典案例；
- **指针追逐（pointer chasing）**：链表遍历的每一步都依赖上一次的结果，
  预取器无法工作，延迟完全暴露。

## 三视角解析

### 🧑‍💻 程序员视角

**工程决策树：这个循环为什么慢？**

1. **是不是跨步访问？** 二维数组的遍历顺序与内存布局不一致是最常见的原因。
   C/C++ 是行主序（row-major），内层循环应遍历**最后一个下标**。
2. **数据是否太大？** 若工作集超过 L2/L3，命中率会断崖式下跌。
   对策是**循环分块**（loop tiling / blocking），把工作集切到能装进 Cache 的规模。
3. **是否伪共享？** 多线程写的计数器若挨在一起，性能可能比单线程还差。
   对策是**按缓存行填充**（C++17 的 `std::hardware_destructive_interference_size`，
   或用 `alignas(64)`）。
4. **是否指针追逐？** 把链表换成数组（`vector`、邻接表用 `vector<int>` 压平）常常带来数倍提升，
   因为顺序访存能被预取。

**验证手段**：不要靠猜 —— 用 `perf stat -e cache-misses,cache-references,LLC-load-misses` 看数据，
用 `perf record` 找热点行。**优化必须先有测量，否则就是在赌。**

**一句话总结**：现代程序的性能瓶颈八成在**访存**而不是**运算**，
所以"数据布局优先于算法微调"是一条非常实用的原则。

### 🎓 博士生视角

**局部性的统计本质**：可以把一个程序的访存序列建模为随机过程，
把局部性表述为"转移概率矩阵的对角带占优"——即 $P(x_{t+1} \approx x_t + \delta) \gg P(x_{t+1} \text{ 远离 } x_t)$。
Cache 的收益是这个分布的熵的函数：访问分布越集中（熵越小），
固定容量能覆盖的概率质量越大，命中率越高。

**AMAT 的固定点形式**：把层次视为自相似结构，AMAT 满足
$\text{AMAT} = T_1 + m_1 \cdot \text{AMAT}_2$。
这种"线性分式"结构在分析存储系统、以及更一般的"带惩罚的重试系统"时反复出现，
可以写成矩阵形式并求不动点。它也解释了为什么**降低 $m_1$（哪怕很小）比降低 $T_1$ 收益更大**：
$m_1$ 是乘性因子，$T_1$ 是加性因子。

**容量-命中率的经验规律**：命中率随容量近似按幂律增长（miss rate $\propto C^{-\alpha}$，
$\alpha$ 与程序局部性强弱相关）。这来自 Zipf 型访问分布的尾部分析。

**为什么"层次"是最优策略**：在同时约束"成本"与"延迟"的多目标优化问题里，
层次结构等价于把存储按"访问频率"分层，是一个带权最优量化问题（类似可变长编码的最优性论证）。

### 📚 考研者视角

**必背公式**

$$\text{AMAT} = T_{hit} + m \times T_{miss}, \qquad h + m = 1$$

$$\text{命中率} = \frac{\text{命中次数}}{\text{总访问次数}}$$

**高频考点 1：AMAT 递推计算（几乎每年都考）**
> 例：L1 命中时间 1 周期、命中率 95%，L2 命中时间 10 周期、命中率 80%，主存 200 周期。
> 求 AMAT。
> 答：$\text{AMAT}_{L2} = 10 + 0.2 \times 200 = 50$；
> $\text{AMAT}_{L1} = 1 + 0.05 \times 50 = 3.5$ 周期。
> **易错点**：不要写成 $1 + 0.05 \times (10 + 0.2 \times 200)$ 却忘了 10 本身也要算 —— 见下一条。

**高频考点 2：命中时间是否重复计算。**
这类题的两种常见口径：
- **"缺失代价已包含访问下一级的时间"** → 直接用 $\text{AMAT} = T_{hit} + m \cdot T_{miss}$；
- **"缺失代价是额外开销"** → 需要写成 $T_{hit} + m \cdot (T_{next\_hit} + \dots)$。
**答题时按题目给出的定义走，并在卷面上写出你采用的公式** —— 这是避免口径失分的关键。

**高频考点 3：存储层次的容量/价格计算。**
> 用 $C_i$ 与单价 $c_i$ 求总价格与平均每字节价格、平均访问时间。
> 全部按**加权平均**算，不要漏掉某一层。

**高频考点 4：局部性的判断。**
> 给一段循环（如按行/按列访问二维数组），问哪个局部性好。
> 答法：**空间局部性看"地址是否连续"**，时间局部性看"同一地址是否被反复访问"。
> C 语言按行主序存储，"外层循环变量对应第一维、内层对应最后一维"时访存连续。

**易错口径**：
1. 命中率与缺失率之和为 1，别写成"缺失率 = 1 - 命中时间"；
2. "命中时间"是访问 Cache 本身的耗时，**不包含**访问下一级的时间；
3. Cache 的**块（block）大小**决定空间局部性的捕获能力，块越大空间局部性越好，
   但块内不用的数据也会被搬进来（可能反而降低命中率）；
4. 说"Cache 提高了程序的时间复杂度"是错的 —— 它**降低的是常数与访存延迟**，不改变渐进复杂度。
