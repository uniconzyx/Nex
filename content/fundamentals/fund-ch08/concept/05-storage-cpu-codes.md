### Cache 命中率与平均访问时间

平均访问时间 `AMAT = hit_time + miss_rate × miss_penalty`。命中率 `h` 时 `AMAT = (1−h)×hit + h×miss`。

```python
hit, miss = 0.92, 100      # 命中 1 拍，缺失惩罚 100 拍
amat = 1 + (1 - 0.92) * miss
print(amat)                # 9.0 拍
```

### 地址字段划分（标记 / 组 / 块内）

32 位地址、64 字节块、4 路组相联、512 组：块内偏移 `log2(64)=6`，组索引 `log2(512)=9`，剩余 `32−6−9=17` 位是标记。

```python
addr, b, s = 32, 6, 9
tag = addr - b - s
print(tag)                 # 17 位标记
```

### 直接映射 vs 全相联 vs 组相联

- 直接映射：每组 1 行，冲突多但查找快；
- 全相联：任意行，命中率高但比较器贵；
- 组相联：折中，组内全相联、组间直接映射。

### 替换算法（LRU / FIFO / 随机）

LRU 命中率最高但需维护访问序；FIFO 实现简单却可能「Belady 异常」（增大容量反而缺页更多）；随机最省硬件。

### 写策略（写回 vs 写直达）

写直达每次都写回下级，简单但带宽压力大；写回只改本地、替换时才写回，需脏位标记。

### 虚拟地址到物理地址翻译

页式：虚地址 = 虚页号 + 页内偏移；用页表把虚页号映射成物理页框号，偏移不变。

```python
vpn, off = 0x1234 // 0x1000, 0x1234 % 0x1000   # 假设 4KB 页
pfn = page_table[vpn]
phys = pfn * 0x1000 + off
```

### 流水线数据冒险与转发

`ADD R1,R2,R3` 后紧接 `SUB R4,R1,R5`，R1 未写回就被读——靠**转发（forwarding）**把 ALU 结果直接喂下一级，否则需插入空拍（bubble）。

### 流水线控制冒险与分支预测

分支指令改变 PC，取指级已错取后续指令。用**分支预测**（总是/not-taken、BTB）减少清空；预测失败才排空流水线。

### CPI 与加速比计算

`CPU时间 = 指令数 × CPI × 时钟周期`。流水线理想加速比受限于最长段与段数。

### 存储层次带宽与延迟权衡

`MBW = 并发度 × 单通道带宽`；延迟靠层次（寄存器→Cache→内存→磁盘）隐藏，带宽靠通道数与预取提升。

### 真实场景：命中率掉到 80% 先算 AMAT

凯喵接手一个缓存系统，监控说命中率从 95% 掉到 80%。先别急着改代码，算清楚代价：

```python
before = 1 + 0.05 * 100   # 命中 1 拍，缺失惩罚 100 拍
after  = 1 + 0.20 * 100
print(round(after / before, 2), "倍变慢")   # 3.5 倍
```

AMAT 翻三倍多，优先救命中率（查冲突/容量），而不是加机器。

### 真实场景：地址翻译手算演练

给定 32 位虚地址 `0x12345678`、4KB 页：高 20 位是虚页号，低 12 位是页内偏移。

```python
addr = 0x12345678
off = addr & 0xFFF            # 0x678
vpn = addr >> 12             # 0x12345
print(hex(vpn), hex(off))    # 页表查 vpn 得页框号，拼回物理地址
```

### 真实场景：流水线冒险的隐藏代价

一段 `ADD R1` 后紧接依赖它的 `SUB R1`，无转发需插 1 个气泡；放进 10 亿次循环就是 10 亿拍凭空浪费。

```python
bubbles = 1_000_000_000
print(int(bubbles * 0.3), "拍可经转发省下（示意）")
```

## 三视角解析
### 🧑‍💻 程序员视角
凯喵做矩阵乘法优化，把 `for i, for j, for k` 改成 `for i, for k, for j` 之后快了 4 倍——因为按行访问 `B[k][j]` 时内层循环连续走同一行的相邻元素，缓存行被充分利用；原来的写法每次内层都在跨行跳，每个元素都要一次缓存缺失。地址字段划分也是实测出来的：给了 32 位地址、64B 块、8 路组相联，就必须先算「块内偏移 6 位、组索引 `log₂(组数)` 位、剩下是标记」，组数是「缓存容量 / (块大小 × 路数)」。**Cache 题的错误九成出在「组数」这一步，忘了除以路数。**

### 🎓 博士生视角
平均访问时间 `AMAT = 命中时间 + 缺失率 × 缺失代价`，这个式子把优化方向拆成三条：降命中时间（小容量、低延迟）、降缺失率（大容量、高相联、好的替换策略）、降缺失代价（多级缓存、预取、非阻塞缓存）。LRU 的「栈距离」模型给出了一个漂亮的性质：容量为 C 的 LRU 命中率等于「栈距离 ≤ C 的访问比例」，且增大容量不会降低命中率（栈算法性质）；而 FIFO 不满足该性质，会出现 Belady 异常。现代处理器用多级缓存把「快而小」与「大而慢」串起来，L1 求延迟、L3 求容量，这是存储层次结构的核心思想。

### 📚 考研者视角
408 存储系统是计算题的重灾区，套路固定：
1. **地址划分**：`地址位数 = 标记 + 组索引 + 块内偏移`。块内偏移 `log₂(块大小)`；组索引 `log₂(缓存容量 / (块大小 × 路数))`；标记是剩下的位。**一定要先除以路数**。
2. **AMAT**：`AMAT = 命中时间 + 缺失率 × 缺失代价`，多级缓存时逐级套用。
3. **替换算法**：LRU 用「最近最久未使用」，手算时画出每列的访问序列并标注命中；FIFO 用队列；注意 Belady 异常只在 FIFO 出现。
4. **写策略**：写直达（write-through）一致性好但写流量大，写回（write-back）需要脏位。常考「写回法下一次写命中时是否需要访存」。
5. **虚拟内存**：TLB 命中 → 直接得物理地址；TLB 缺失 → 查页表（可能多次访存）→ 缺页则调页。题目会给各级命中率，求平均访存时间。
