# 虚拟内存、页表与 TLB 的协同

## 1. 虚拟内存解决的三个问题

1. **隔离**：每个进程看到独立的地址空间，不能随意读写别人的内存；
2. **容量**：程序可以"看起来"拥有比物理内存更大的空间（按需调页）；
3. **重定位**：程序编译时不需要知道最终加载到物理内存的哪一块。

实现手段是把地址空间切成固定大小的**页（page）**，用一张**页表**做映射：

$$\text{虚拟地址} = \underbrace{\text{虚拟页号 VPN}}_{\text{查页表}} \parallel \underbrace{\text{页内偏移}}_{\text{直接照搬}}$$

**页内偏移在翻译前后不变**，只有页号被改写 —— 这也是"页大小必须是 2 的幂"的原因
（否则要除法/取余，翻译就无法只靠位拼接完成）。

## 2. 单级页表太大，所以要多级

设 32 位地址、页大小 4 KB、页表项 4 B：

- 虚拟页数 $= 2^{32}/2^{12} = 2^{20}$ → 单个页表需要 $2^{20} \times 4\text{B} = 4\text{MB}$；
- 每个进程都要 4 MB 常驻内存，100 个进程就是 400 MB —— **不可接受**；
- 而且绝大多数进程只用到很小一部分地址空间，**页表里大部分是空的**。

**解决方案：多级页表**。把页号再切段，顶级页表只覆盖"用到的那些段"，
未使用的段根本不分配下级页表。代价是**一次翻译要访存多次**（几级就几次）。

## 3. TLB：给地址翻译加 Cache

多级页表把每次访存变成"$n$ 次读页表 + 1 次取数据"。TLB（Translation Lookaside Buffer）
就是**专门缓存页表项**的小型全相联（或高相联）Cache：

- **TLB 命中**：直接得到物理页号，无额外访存；
- **TLB 缺失**：走多级页表遍历（page walk），可能还要访问内存；
- **TLB 命中且有效**：正常访问；
- **有效位为 0（缺页）**：触发**缺页异常**，操作系统从磁盘调入页面，
  更新页表，**然后重新执行那条指令**（注意是"重新执行"，不是"继续"）。

**关键点：TLB 用虚拟页号 VPN 索引（不含页内偏移）**，
因为同一页内的所有地址共享同一个页表项 —— 这也是需要"页着色"时考虑 TLB 容量的原因。

## 4. 一次访存的完整路径

```
CPU 给出虚拟地址
   │
   ├─ 拆成 VPN + offset
   │
   ▼
 TLB 查 VPN ──命中──► 物理页号 PPN ──► 拼接 offset ──► 物理地址
   │                                                     │
   └─未命中─► 多级页表遍历 (访问内存 2~4 次)               │
                │                                        │
                ├─ 页表项有效位 = 1 ──► 填 TLB，返回 PPN   │
                └─ 页表项有效位 = 0 ──► 缺页异常 → 调入 → 重执行
                                                          │
                                                          ▼
                                              用物理地址访问 Cache
```

注意顺序：**先翻译地址，再查 Cache**（物理索引 Cache 的前提；
若用虚拟地址索引 Cache，就要处理"同名不同页"的重名问题）。

## 5. 三条容易混淆的"缺失"

| 名称 | 触发条件 | 处理代价 |
|---|---|---|
| **TLB 缺失** | TLB 里没有该页表项 | 页表遍历（page walk），可能仅需访问内存 |
| **缺页（page fault）** | 页表项存在但**有效位为 0** | 磁盘 I/O + 内核处理，**代价极高（~10^6 周期量级）** |
| **Cache 缺失** | 数据不在 Cache | 从下级存储取块（~200 周期或更多） |

**记忆锚点**：TLB 缺失是"没查到记录"，缺页是"记录在但页不在内存"。两者代价差 3~4 个数量级。

## 三视角解析

### 🧑‍💻 程序员视角

**决策树：内存相关的性能问题怎么查？**

1. **看 `perf stat` 的 dTLB-load-misses 与 page-faults**。
   缺页数异常高（每次都涨）说明**工作集超过物理内存**或存在"内存泄漏 + 换页抖动"。
2. **缺页多 → 要么减小工作集，要么用大页（huge page）**。
   2 MB/1 GB 大页把需要的 TLB 条目数减少 512/262144 倍，
   对遍历大数组、数据库缓冲池这类场景收益极大（Linux 的 `madvise(MADV_HUGEPAGE)`）。
3. **TLB 缺失多但缺页正常 → 局部性太差**。
   典型的反例是"随机访问一个大哈希表"，改善方法是改数据布局提高页内局部性。
4. **注意 fork 与写时复制（COW）**：`fork()` 后父子共享物理页，
   任一方写入触发缺页复制。**大量 fork + 写**会让缺页数暴涨，这也是
   Redis RDB 快照时"内存翻倍"现象的原因。

**实践要点**：
- **分配策略**：频繁小对象分配会导致页表碎片与 TLB 压力，用**对象池/竞技场分配器**改善；
- **避免 mmap 滥用**：大量稀疏 `mmap` 会撑爆页表；
- **透明大页（THP）不是万能药**：它可能带来**内存碎片与延迟抖动**（后台合并页时的停顿），
  延迟敏感的服务常选择关闭 THP 或改用显式大页。

### 🎓 博士生视角

**多级页表是一棵稀疏树**：把虚拟地址空间看作 $2^{32}$ 个叶子的完美树，
页表就是这棵树的**稀疏表示**。单级页表 = 深度 1 的全展开数组；
$n$ 级页表 = 深度 $n$ 的树，只在实际使用到的路径上分配节点。
于是"页表空间开销"从 $O(\text{地址空间})$ 降到 $O(\text{已使用页数})$，
代价是查询复杂度从 $O(1)$ 变为 $O(n)$ —— 这正是**用时间换空间**的典型交易，
而 TLB 的作用是把这个 $O(n)$ 复杂度**用缓存摊平回 $O(1)$（摊还意义上）**。

**TLB 覆盖范围（reach）**：$= \text{TLB 条目数} \times \text{页大小}$。
这是评估 TLB 是否够用的核心指标：若工作集 $>$ reach，TLB 就开始抖动。
增大页大小是最直接的扩 reach 手段；页大小固定时，只能增加条目数（硬件成本高）。

**缺页处理是"重启语义"**：指令在翻译阶段失败，必须保证恢复到"该指令尚未开始执行"的状态。
这与事务内存、以及可恢复计算（recoverable computing）里的
**幂等重启点**概念一致 —— 区别在于缺页是硬件/内核协作实现的透明重启。

**地址翻译与缓存索引的交互**：若 Cache 用虚拟地址索引（VIVT），
会在进程切换时残留同索引不同物理页的"别名（aliasing）"问题，需要靠 ASID 或刷新解决；
用物理地址索引（PIPT）则要在 Cache 查询前完成翻译，延迟更高。
现实中多用 **VIPT**（虚拟索引、物理 tag），既省延迟又避免别名 —— 但要求
"页大小 ≥ Cache 组数 × 块大小"，这正是页大小选 4 KB 之外的工程约束之一。

### 📚 考研者视角

**必背公式**

$$n = \frac{\text{虚拟地址位数} - \log_2(\text{页大小})}{\text{每级页号位数}} \quad(\text{级数})$$

$$\text{页表大小} = \text{页表项数} \times \text{页表项大小}$$

**高频考点 1：求页表大小与页表项数。**
> 例：32 位地址，页大小 4 KB，页表项 4 B，单级页表多大？
> 答：页数 $= 2^{32}/2^{12} = 2^{20}$，页表大小 $= 2^{20} \times 4\text{B} = \mathbf{4\ MB}$。

**高频考点 2：多级页表的地址划分与访存次数。**
> 例：同上，采用两级页表，页号各占 10 位，问一级页表大小、二级页表项数、一次访存需几次内存访问。
> 答：一级页表 $2^{10} \times 4\text{B} = 4\text{KB}$（正好一页）；
> 二级页表最多 $2^{10} \times 2^{10} = 2^{20}$ 项，但**按需分配**，实际只分配用到的；
> 翻译需访问内存 2 次（两级各一次）+ 取数据 1 次，**共 3 次**；若 TLB 命中则为 1 次。

**高频考点 3：TLB 命中/缺失与缺页的组合判断。**
> 四象限：TLB 命中 + 页在内存（最快）；TLB 缺失 + 页在内存（页表遍历）；
> TLB 命中但有效位 0（不可能，命中即有效，除非做了 TLB 刷新前的竞态，试题不会这么出）；
> 缺页（无论 TLB 是否命中标记，都要进缺页处理）。
> **标准口径**：**缺页优先**，一旦有效位为 0 就触发缺页异常，与 TLB 是否命中无关。

**高频考点 4：TLB 的有效范围 / 覆盖的虚存大小。**
> $\text{覆盖范围} = \text{TLB 条目数} \times \text{页大小}$。
> 若 TLB 有 64 项、页 4 KB，则覆盖 256 KB；工作集超过它就会 TLB 抖动。

**高频考点 5：页表项里有什么。**
> 至少包含：**物理页号（帧号）+ 有效位（驻留位）+ 修改位（脏位）+ 访问位 + 保护位（读/写/执行）**。
> 修改位与访问位**供页面置换算法使用**（如时钟算法、改进型时钟算法），这是 408 常考细节。

**易错口径**：
1. **页内偏移在翻译前后不变**，只有页号变；
2. **缺页不是"访问越界"**，越界是段错误（segmentation fault），缺页是"页合法但不在内存"；
3. **缺页处理后是"重新执行该指令"**，不是从中断处继续；
4. 多级页表**按需分配下级页表**，别把"最多需要的项数"当成"实际分配的内存"；
5. TLB 是**硬件**（现代 CPU 内置，一般对 OS 透明），页面置换是**操作系统**职责，不要混。
