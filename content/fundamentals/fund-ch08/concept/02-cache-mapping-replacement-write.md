# Cache 映射方式、替换算法与写策略

## 1. 地址怎么被切分

Cache 与主存之间以**块（block / line）**为单位交换。一个主存地址 $A$ 被切成三段：

```
  ┌──────────────┬──────────────┬────────────┐
  │     tag      │     index    │   offset   │
  └──────────────┴──────────────┴────────────┘
     用于比对          选择组/行       块内位置
```

- **offset（块内偏移）**：块大小 $B$ 字节 → 需要 $\log_2 B$ 位；
- **index**：组数 $S$ → 需要 $\log_2 S$ 位（直接映射时行数即组数）；
- **tag**：剩下的高位，用于确认"这一组里待着的确实是我们要的块"。

**总位数 = $\log_2(\text{主存大小}) $，三段之和必然相等**，这是最有效的自检。

## 2. 三种映射方式

设 Cache 总容量为 $C$ 字节、块大小 $B$、每组 $k$ 行（相联度 $k$）。

| 方式 | 组数 $S$ | index 位 | 特点 |
|---|---|---|---|
| **直接映射** | $S = C/B$ | $\log_2(C/B)$ | 每个主存块只能落在唯一一行；硬件最省、比较最快；**冲突缺失最严重** |
| **全相联** | $S = 1$ | 0 | 可放任意一行；命中率最高；**需要与所有 tag 并行比较**，硬件代价大 |
| **组相联**（$k$ 路） | $S = C/(B \cdot k)$ | $\log_2 S$ | 折中：组内全相联、组间直接映射；工程主流（$k=4,8,16$） |

**换算关系必须记牢**：$S = \dfrac{C}{B \cdot k}$。
$k=1$ 时退化为直接映射，$S=1$ 时退化为全相联。

## 3. 替换算法

全相联与组相联在同一组满时需要替换。候选：

- **随机（RAND）**：硬件最简单，但命中率不稳定，无法复现性能；
- **FIFO**：先进先出，实现简单；有 **Belady 异常**（块变多反而命中率下降）；
- **LRU**：替换最久未使用的。命中率接近最优，但需要记录每次访问的顺序，
  路数大时硬件代价高（所以实际 CPU 用**近似 LRU**，如树形伪 LRU）；
- **LFU**：按访问频次，可能被"历史热点"锁死（新数据进不来）；
- **OPT（最佳，Belady 最优）**：替换"未来最久才会被用到"的块。
  **需要预知未来，现实中不可实现**，只作为命中率的**理论上界**用于评估其他算法的差距。

## 4. 三类缺失（3C）

| 名称 | 别名 | 成因 | 优化方向 |
|---|---|---|---|
| **强制缺失** | 冷启动缺失 | 块第一次被访问，Cache 里必然没有 | 预取（prefetch）、增大块（利用空间局部性） |
| **容量缺失** | — | 工作集大于 Cache 容量，旧块被挤出后又要用 | 增大 Cache、循环分块降低工作集 |
| **冲突缺失** | 碰撞缺失 | 多个块映射到同一组而互相挤出（**全相联下不存在**） | **提高相联度**、改变数据布局/填充 |

**重要结论**：**冲突缺失只在非全相联时才存在**。所以"直接映射换 4 路组相联，命中率明显上升"，
上升的部分几乎全是冲突缺失被消掉。而当相联度继续增大到某个点后收益递减 ——
此时剩下的主要是容量缺失，只有加容量才能解决。

## 5. 写策略：写命中与写缺失各两种

| 场景 | 选项 | 说明 |
|---|---|---|
| **写命中** | 写直达（write-through） | 同时写 Cache 与主存。一致性简单，但**写流量大**，需写缓冲 |
| | 写回（write-back） | 只写 Cache 并置"脏位"，被替换时才写回。**写流量小**，但一致性复杂 |
| **写缺失** | 写分配（write-allocate） | 先把块取进 Cache 再写。配写回用得多 |
| | 写不分配（no-write-allocate） | 直接写入主存，不取块。配写直达用得多 |

**常见组合**：写回 + 写分配（CPU 主流）、写直达 + 写不分配（简单实现）。

**写回的关键收益**：同一个块被写 $n$ 次，主存只写 1 次；
写直达则是 $n$ 次。这对"反复更新的变量"差别巨大。

## 三视角解析

### 🧑‍💻 程序员视角

**决策树：我现在改什么最有效？**

1. **先测缺失类型**。用 `perf stat -e L1-dcache-load-misses,LLC-load-misses` 看缺失集中在哪层。
   LLC 缺失多 → 容量问题（要分块/缩小工作集）；
   L1 缺失多但 LLC 命中好 → 冲突/布局问题（要改访问模式或加填充）。
2. **冲突缺失 → 改布局**。典型手法是给二维数组的"列方向"插入 padding，
   或者把频繁同时访问的结构体字段拆开（AoS → SoA）。
3. **容量缺失 → 分块**。矩阵乘法的三层循环分块是最经典案例：
   把 $B \times B$ 的子块装进 L1，可以带来数倍加速。
4. **强制缺失 → 预取**。对可预测的顺序访问，硬件预取器已经做了；
   对间接访问（如稀疏矩阵），需要软件预取指令或重排数据。

**伪共享与写策略的联系**：写回 + 写分配下，一个核心写某行会**独占**该行
（MESI 协议的 M 状态），另一个核心要读同一行就会触发所有权转移。
这就是伪共享代价巨大的机制原因 —— 不是"带宽不够"，而是**缓存一致性协议的乒乓**。

**一个反直觉的建议**：**不要手工"优化"到极致**。
Cache 参数（组数、相联度、替换策略）在不同 CPU 上不同，
过度依赖某个微架构的实现细节会让代码在下一代 CPU 上变慢。
优先做"布局与访问模式"层面的优化，它的收益更稳健。

### 🎓 博士生视角

**映射方式的数学结构**：直接映射就是一次哈希 $h(A) = \lfloor A/B \rfloor \bmod S$；
组相联是"桶"（组）内再维护一个 $k$ 元集合；全相联是单桶。
命中率随 $k$ 的增长服从**边际递减**：冲突缺失的期望值近似 $\propto 1/k$ 的尾部分布，
而容量缺失与 $k$ 无关 —— 这解释了为什么 $k$ 从 1 提到 4 收益最大，从 8 提到 16 几乎无感。

**Belady 异常的机制**：FIFO 的替换决策不满足"栈性质"（stack property）。
**栈算法**（LRU 属于此类）满足：容量为 $C$ 时的驻留集合恒为容量 $C+1$ 时驻留集合的子集，
因此命中率随容量**单调不减**。LRU 与 OPT 都是栈算法 —— 这是 LRU 在理论上"体面"的根本原因。
Belady 异常只可能出现在非栈算法上（FIFO、随机）。

**3C 分类的不可判定性**：严格区分容量缺失与冲突缺失需要"知道全相联下的表现"，
而命中序列本身依赖于替换策略，因此 3C 的精确划分在一般情况下需要模拟实验（如 LRU 栈距离法）。
**栈距离（stack distance）** 给出了 LRU 下"如果容量为 $C$ 会不会命中"的判据：
若某次访问的栈距离 $> C$，则为缺失。把访问序列的栈距离做成直方图，
就得到了命中率随容量变化的完整曲线 —— 这是 Cache 分析里最漂亮的工具之一。

**写策略与一致性**：写回策略使 Cache 与主存出现"暂时不一致"，这要求替换时写回脏行；
在多核下还要维护 MESI 之类的所有权协议。从分布式系统视角看，
**多核 Cache 一致性本质上是一个分布式共享内存的一致性协议**，
而"伪共享"就是该协议里的**假竞争（false contention）**。

### 📚 考研者视角

**高频考点 1：给主存地址与 Cache 参数，求 tag/index/offset 位数。**
标准答法（三步）：
1. 由块大小 $B$ 得 **offset 位 $= \log_2 B$**；
2. 由组数 $S$ 得 **index 位 $= \log_2 S$**，其中 $S = C/(B k)$；
3. **tag 位 = 主存地址位 − offset 位 − index 位**。
> 例：主存 4 GB（32 位地址），Cache 64 KB，块 64 B，4 路组相联。
> 答：$S = 64\text{KB}/(64\text{B} \times 4) = 2^4 \times 2^3 / 2^3 = 2^4$... 逐步算：
> $64\text{KB} = 2^{16}$，$B = 2^6$，$k = 2^2$ → $S = 2^{16-6-2} = 2^8$，index 8 位；
> offset $= \log_2 2^6 = 6$ 位；tag $= 32 - 8 - 6 = 18$ 位。**三段相加必须等于 32，务必自检**。

**高频考点 2：LRU 替换过程模拟。**
> 给一个访问序列与相联度，写出每一步后 Cache 组内的内容与命中/缺失。
> 答题要点：**画出组内容并标出"最近使用顺序"**，不要只在脑子里推。
> 常见坑：把 LRU 与 FIFO 弄混 —— **LRU 在命中时也要更新该块的使用顺序**，FIFO 命中时不改变队形。

**高频考点 3：写策略的写次数计算。**
> 写回 + 写分配：每个被写过的块在被替换时写回 1 次主存；同一块多次写**只算 1 次**。
> 写直达：每次写都写主存。
> 常考"1000 次写操作，其中 200 次写缺失"，问主存写次数 → 写回是 200（若每个缺失块只写一次）；
> 写直达是 1000。**务必看清题给的是"写命中"还是"写缺失"，以及块是否被多次写。**

**高频考点 4：平均访存时间的计算。**
> $\text{AMAT} = T_{hit} + m \times T_{miss}$，注意单位统一（周期 or 纳秒）。

**高频考点 5：命中率与块大小的关系。**
> 块增大 → 空间局部性捕获更多 → 强制缺失减少，
> 但块数减少 → 冲突缺失增加，且块内无用数据增多 → 命中率可能下降。
> **结论：块大小对命中率的影响是"先升后降"的非单调曲线。**

**易错口径**：
1. **组数不等于行数**（组相联下 $S = \text{行数}/k$），这是最高频的失分点；
2. tag 是"主存地址高位"，**不是**"主存块号"；
3. 直接映射的"冲突"与"容量"缺失要分清：直接映射换高相联度解决的是**冲突**缺失；
4. "全相联没有冲突缺失" —— 这句话是对的，但全相联仍有容量缺失与强制缺失。
