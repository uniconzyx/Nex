# 01 · 分层模型与封装：每一层到底加了什么

## 一、OSI 七层 vs TCP/IP 四层

| OSI 七层 | TCP/IP 四层 | 五层教学模型 | 典型协议 | 典型设备 | PDU |
|---|---|---|---|---|---|
| 应用层 | 应用层 | 应用层 | HTTP / DNS / SMTP / FTP / SSH | 网关、代理 | 报文（message） |
| 表示层 | 应用层 | 应用层 | TLS / JPEG / ASCII | — | — |
| 会话层 | 应用层 | 应用层 | RPC / NetBIOS | — | — |
| 传输层 | 传输层 | 传输层 | **TCP / UDP** | — | **报文段 / 数据报** |
| 网络层 | 网际层 | 网络层 | **IP / ICMP / ARP** | 路由器 | **分组 / 数据报** |
| 数据链路层 | 网络接口层 | 数据链路层 | 以太网 / PPP / Wi-Fi | 交换机、网桥 | **帧（frame）** |
| 物理层 | 网络接口层 | 物理层 | 双绞线 / 光纤 / 编码 | 中继器、集线器 | **比特（bit）** |

**记忆锚点**：**「物链网传会表应」**（自下而上）。**OSI 的「表示层 + 会话层」在 TCP/IP 里都被并进应用层**——这是四层与七层最大的差异，考试常考「OSI 有而 TCP/IP 没有的层」。

## 二、封装与分用

发送时**逐层加首部**（封装），接收时**逐层剥首部**（分用）：

```
应用数据  "GET / HTTP/1.1\r\n..."                 (1400 B)
   ↓ + TCP 首部 (20 B)
TCP 报文段  |TCP头|data|                          (1420 B)
   ↓ + IP 首部 (20 B)
IP 数据报   |IP头|TCP头|data|                     (1440 B)
   ↓ + 以太网首部(14 B) + FCS(4 B)
以太网帧    |前导码|目的MAC|源MAC|类型|IP头|TCP头|data|FCS|
```

**关键数字（必背）**：
- **以太网 MTU = 1500 B** ⇒ IP 数据报**最大 1500 B** ⇒ TCP 载荷最多 **1500 − 20 − 20 = 1460 B**，这就是 **TCP MSS（最大报文段长度）**的由来。
- 以太网帧最小 **64 B**（不含前导码），不足要**填充（padding）**——这是「小包要凑够 64 字节」的原因。
- 以太网首部 **14 B**（目的 MAC 6 + 源 MAC 6 + 类型 2），**FCS 4 B**。

**有效载荷率**（应用数据 / 物理层总字节）：
$$
\eta = \frac{1400}{1400 + 20 + 20 + 14 + 4 + 8(\text{前导码})} = \frac{1400}{1466} \approx 95.5\%
$$
**包越小，有效载荷率越低**——这是「TCP_NODELAY 关掉 Nagle 反而可能更慢」的原因：大量小包会吃掉带宽。

## 三、各层的职责边界（考试最爱问「这是第几层的事」）

| 问题 | 属于哪层 | 说明 |
|---|---|---|
| 端口号冲突 | 传输层 | 端口是传输层的复用/分用标识 |
| IP 地址不够用 | 网络层 | NAT / CIDR / IPv6 都在这一层解决 |
| 同一个网段内怎么找到对方 | 数据链路层 | MAC 地址 + ARP |
| 收到数据错了怎么办 | 链路层 + 传输层 | 链路层用 CRC **丢弃**；传输层用序号重传**恢复** |
| 网络拥塞 | 传输层 | TCP 的拥塞控制（网络层 IP 不做拥塞控制） |
| 域名解析 | 应用层 | DNS 是应用层协议（它自己跑在 UDP/TCP 上） |

**关键辨析**：
- **链路层只检错不纠错**（CRC 只能发现错误，不能定位并修复），发现错误就**丢帧**，靠上层重传。
- **IP 提供「尽力而为（best-effort）」服务**：不保证不丢、不保证有序、不保证不重复。**可靠性是 TCP 加上去的**。
- **路由器只看 IP 层**（解封装到网络层），**交换机只看链路层**（解封装到链路层），**集线器只看物理层**。

## 四、可运行代码：封装开销与有效载荷率

```python
MTU = 1500
ETH_HDR, ETH_FCS, PREAMBLE = 14, 4, 8
IP_HDR, TCP_HDR = 20, 20

def frame(payload):
    seg = payload + TCP_HDR
    pkt = seg + IP_HDR
    eth = pkt + ETH_HDR + ETH_FCS + PREAMBLE
    return seg, pkt, eth

print(f"{'app bytes':>10} {'TCP seg':>8} {'IP datagram':>12} {'on-the-wire':>12} {'efficiency':>11}")
for app in (1, 100, 536, 1400, 1460, 2000):
    seg, pkt, eth = frame(app)
    print(f"{app:>10} {seg:>8} {pkt:>12} {eth:>12} {app/eth*100:>10.2f}%")

print()
print("MTU           =", MTU)
print("MSS           =", MTU - IP_HDR - TCP_HDR, "(IP+TCP headers subtracted)")
print("small packets waste bandwidth: 1 byte of data costs", frame(1)[2], "bytes on the wire")
```

## 三视角解析

### 🧑‍💻 程序员视角
- **MSS 与分片**：`MSS = MTU − IP 首部 − TCP 首部`，双方在 SYN 里协商（`MSS` 选项）。**IP 分片是有害的**——任一分片丢失都要重传整个数据报，且分片会显著增加设备负担。现代实践是 **PMTUD（路径 MTU 发现）**，用「DF 位置 1 + ICMP 不可达」探测路径 MTU。**服务端要正确处理 ICMP type 3 code 4**，否则会出现「小包能通、大包卡死」的经典故障。
- **`TCP_NODELAY`**：关掉 Nagle 算法，让小包立即发出。**交互密集**的场景（Redis、RPC）要开；**批量传输**的场景让 Nagle 合并小包更划算。
- **抓包第一眼看什么**：`tcpdump -i eth0 -nn -vv 'tcp port 443'` 看 **三次握手是否完成** → **`seq/ack` 是否连续**（有没有重传）→ **`win` 是否缩到 0**（对端读得慢）→ **有没有 `RST`**（被拒或被中间设备切断）。**`[TCP Retransmission]` 与 `[TCP ZeroWindow]` 是两个最常见的性能信号。**
- **同网段判断**：`ip route get 8.8.8.8` 直接告诉你走哪个网卡、下一跳是谁。**排查「同网段不走网关」时这是最快的命令。**

### 🎓 博士生视角
- **分层的本质是「关注点分离 + 接口标准化」**：每层只暴露**服务接口（SAP）**，隐藏实现。这让「在 IP 上换掉以太网」或「在 TCP 上换掉 HTTP」成为可能。代价是**层间信息隔离**：TCP 无法直接得知链路状态，只能靠**端到端的丢包与延迟推测**拥塞——这就是 **BBR 这类基于测量的拥塞控制**出现的动因（它试图从端到端信号反推瓶颈带宽与 RTT，绕过「丢包即拥塞」的过强假设）。
- **「端到端论证（End-to-End Argument）」**（Saltzer, Reed, Clark 1984）：功能应尽量放在**通信的两端**实现，而非网络中间。IP 的「尽力而为」正是这条原则的体现：网络不做可靠传输，因为**只有两端才知道自己需要多强的可靠性**。TCP 的可靠性、TLS 的加密都在端上实现。
- **MTU 与 TCP 的「自时钟（self-clocking）」**：ACK 的到达节奏反过来控制发送节奏。MSS 增大能提升效率（首部占比下降），但**增加了单个包丢失的惩罚**（重传成本更高）。于是 MSS 的最优值取决于**丢包率与首部开销的权衡**——这是「包大小优化」问题的形式化。
- **前导码在「分组交换」模型里不是首部**：它是**物理层的同步序列**，用于接收端时钟恢复。教学模型里常忽略它，但在**有效载荷率**的严格计算里必须算上（8 B）。

### 📚 考研者视角
- **408 网络必考第一题就是分层**：给一个功能（如「差错控制」「流量控制」「拥塞控制」），问「哪些层提供」。**标准答案**：差错控制——链路层（CRC 检错）+ 传输层（重传恢复）+ 网络层（首部校验和，仅校验首部）；流量控制——链路层（停等/滑动窗口）+ 传输层（滑动窗口）；**拥塞控制——只有传输层**。
- **设备与层的对应是必考送分题**：中继器/集线器（物理层）、网桥/交换机（链路层）、路由器（网络层）、网关（应用层）。
- **PDU 名称要精确**：应用层叫 **报文（message）**，传输层叫 **报文段（segment, TCP）/ 用户数据报（datagram, UDP）**，网络层叫 **分组（packet）/ 数据报（datagram）**，链路层叫 **帧（frame）**，物理层叫 **比特**。**考试写错 PDU 名称会扣分。**
- **常考计算**：MTU 1500 时 TCP 的 MSS = 1460；以太网帧最小 64 B；分片时每片都要带 IP 首部。
- 记忆锚点：**「物链网传会表应」**、**「交换机看 MAC、路由器看 IP」**、**「链路层只检错丢帧、传输层才重传恢复」**、**「拥塞控制只在传输层」**。
