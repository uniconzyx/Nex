# 02 · 数据链路层：成帧、差错控制与以太网

## 一、成帧方法

| 方法 | 做法 | 缺陷 |
|---|---|---|
| **字符计数法** | 首部写明帧长 | 长度字段一错，后续全乱 |
| **字节填充（转义字符）** | 用 `ESC` 转义数据中的定界符 | 依赖转义，实现繁琐 |
| **零比特填充（比特填充）** | `01111110` 作标志，数据中**每 5 个连 1 后插 0** | **HDLC/PPP 使用，最常用** |
| **违规编码法** | 用物理层不会出现的编码作定界 | 依赖编码方案 |

**零比特填充**是必考：发送端「每 5 个 1 插一个 0」，接收端「每 5 个 1 删一个 0」，保证数据里永远不会出现 6 个连 1（即标志位）。

## 二、差错控制：三种编码的能力对比

| 编码 | 原理 | 检错能力 | 纠错能力 | 开销 |
|---|---|---|---|---|
| **奇偶校验** | 补 1 位使 1 的个数为奇/偶 | 检出**奇数个**比特错 | **不能纠错** | 1 bit |
| **海明码** | 多个校验位交织覆盖 | 检 2 位错 | **纠 1 位错** | $k$ 位数据需 $r$ 位校验，满足 $2^r \ge k + r + 1$ |
| **CRC（循环冗余校验）** | 数据多项式除以生成多项式，余数作 FCS | **极强**（能检出所有奇数位错、所有 ≤ r 位的突发错） | 不纠错，只丢弃 | $r$ 位（生成多项式阶数） |

**海明码计算（必考）**：数据 `k` 位，需 `r` 位校验位，满足
$$
2^r \ge k + r + 1
$$
例：`k = 8` ⇒ `r = 4`（$2^4 = 16 \ge 8 + 4 + 1 = 13$）；`k = 4` ⇒ `r = 3`（$2^3 = 8 \ge 4 + 3 + 1 = 8$）。
**校验位放在 $2^0, 2^1, 2^2, \dots$ 位置**（即第 1、2、4、8 位），其余放数据。

**CRC 计算（手算步骤）**：
1. 数据后补 `r` 个 0（`r` = 生成多项式最高次幂）；
2. 用**模 2 除法**（异或，不借位）除以生成多项式；
3. 余数即 **FCS**，附在数据后发送。
4. 接收端用同样多项式除，**余数为 0 则无错**。

## 三、以太网帧格式与 CSMA/CD

**以太网 V2 帧**（这是 TCP/IP 实际使用的）：

```
| 前导码 8B | 目的 MAC 6B | 源 MAC 6B | 类型 2B | 数据 46~1500B | FCS 4B |
```
- **前导码（8B）**：7 字节 `10101010` + 1 字节 `10101011`，用于**时钟同步**。**不算帧的一部分**（不计入帧长）。
- **类型字段**：`0x0800` = IPv4，`0x0806` = ARP，`0x86DD` = IPv6。
- **数据字段 46~1500 B**：不足 46 要**填充**，保证帧总长 ≥ **64 B**（46 + 14 + 4 = 64，不含前导码）。
- **FCS**：CRC-32。

**为什么最小帧长是 64 B？** 与 **CSMA/CD** 的**冲突检测**有关：发送方必须在「最远端的信号到达」之前仍在发送，才能检测到冲突。设最小帧长 `L`、带宽 `C`、单程传播时延 `τ`，则
$$
L \ge 2\tau C
$$
以太网 `2τ = 51.2 μs`、`C = 10 Mbps` ⇒ `L ≥ 512 bit = 64 B`。**这就是 64 B 的来源**（千兆以太网通过「载波延伸」把最小帧扩到 512 B 来维持该条件）。

**CSMA/CD 流程**：先听后发（载波监听）→ 边发边听（冲突检测）→ 冲突则停发并**发强化干扰信号（Jamming）**→ 执行**二进制指数退避**（第 `i` 次冲突后从 $\{0, 1, \dots, 2^{\min(i,10)}-1\}$ 随机取 `k`，等 `k × 2τ` 重发）。

## 四、交换机自学习与泛洪

**交换机（多端口网桥）** 维护一张 **MAC 地址表**：`MAC → 端口`。

**自学习（backward learning）**：
1. 收到帧，记录 **「源 MAC → 入端口」**（因为源一定在那个方向）；
2. 查目的 MAC：
   - **表中有且与入端口不同** → **单播转发**到该端口；
   - **表中有且与入端口相同** → **丢弃**（无需转发，同一端口）；
   - **表中没有** → **泛洪（flooding）**：向除入端口外的所有端口转发；
3. 表项有**老化时间**（默认 300 s），过期删除。

**关键性质**：交换机**隔离冲突域**（每个端口一个冲突域），但**不隔离广播域**（广播帧仍会泛洪）。**路由器才隔离广播域**。要隔离广播域需用 **VLAN**。

**三种转发模式**：**直通（cut-through，看目的 MAC 就转，快但可能转发坏帧）**、**存储转发（store-and-forward，收完校验 FCS 再转，慢但可靠）**、**无碎片（fragment-free，收够 64 B 再转）**。

## 五、可运行代码：CRC 计算与交换机自学习

```python
def crc_remainder(data_bits: str, poly_bits: str) -> str:
    r = len(poly_bits) - 1
    bits = list(data_bits + "0" * r)
    for i in range(len(data_bits)):
        if bits[i] == "1":
            for j in range(len(poly_bits)):
                bits[i + j] = "1" if bits[i + j] != poly_bits[j] else "0"
    return "".join(bits[-r:])

print("=== CRC (mod-2 division) ===")
data = "1101011111"
poly = "10011"                      # x^4 + x + 1, r = 4
rem = crc_remainder(data, poly)
print(f"data = {data}, generator = {poly} (r={len(poly)-1})")
print(f"FCS  = {rem}")
print(f"transmitted = {data}{rem}")
print(f"verify remainder = {crc_remainder(data + rem, poly)}  (all zeros => no error)")
corrupt = data + rem[:-1] + ("0" if rem[-1] == "1" else "1")
print(f"one bit flipped  = {crc_remainder(corrupt, poly)}  (non-zero => error detected)")

print()
print("=== switch self-learning + flooding ===")
class Switch:
    def __init__(self, ports):
        self.ports = ports
        self.table = {}                      # mac -> port
    def receive(self, src, dst, in_port):
        self.table[src] = in_port            # 自学习：源 MAC 绑定入端口
        if dst in self.table:
            out = self.table[dst]
            if out == in_port:
                action = f"DROP (dst already on in-port {in_port})"
            else:
                action = f"UNICAST -> port {out}"
        else:
            outs = [p for p in self.ports if p != in_port]
            action = f"FLOOD -> {outs}"
        print(f"  src={src} dst={dst} in={in_port}  -> {action}")
        print(f"    mac table now: {dict(sorted(self.table.items()))}")

sw = Switch([1, 2, 3, 4])
sw.receive("AA", "BB", 1)     # 未知目的 -> 泛洪
sw.receive("BB", "AA", 2)     # BB 学习了, AA 已知 -> 单播
sw.receive("AA", "BB", 1)     # 都已知 -> 单播
print("broadcast domain: NOT separated by a switch (needs VLAN)")
```

## 三视角解析

### 🧑‍💻 程序员视角
- **CRC 的工程价值在于「代价极低、检测极强」**：硬件里就是一个 LFSR（线性反馈移位寄存器），一个时钟周期算一位。**但 CRC 只能检错，不能纠错**——发现错误就丢帧，靠上层重传。这就是「链路层丢帧 → TCP 重传」的协作模式。
- **`FCS` 校验失败会被网卡直接丢弃**：`ifconfig`/`ip -s link` 里的 **`RX errors` / `frame`** 计数就是这类丢弃。**看到 RX errors 增长，先换网线/网卡**，不要怀疑应用。
- **交换机 vs 集线器的真实差别**：集线器是**共享介质**（所有端口同一冲突域，半双工，靠 CSMA/CD 竞争）；交换机是**独享带宽**（每端口一个冲突域，全双工，不需要 CSMA/CD）。**现代以太网（全双工交换）里 CSMA/CD 已经不用了**，但考试仍考它——因为它是「最小帧长」的理论来源。
- **`MAC` 地址表溢出攻击**：攻击者伪造大量源 MAC 填满交换机地址表，使交换机退化为**泛洪模式**，从而嗅探流量。这是「**MAC 泛洪攻击**」，防御手段是**端口安全（port security）**限制每端口可学习的 MAC 数。

### 🎓 博士生视角
- **最小帧长的推导是一个「时间-空间」耦合条件**：要在 `2τ` 内保持发送，才能保证冲突信号能传回。把 `L ≥ 2τC` 换个角度看，它给出了 **「以太网的最大跨距」**：给定最小帧长与带宽，`τ ≤ L/(2C)`。这就是为什么**提高带宽必须缩短网段**（或引入载波延伸/帧突发）。
- **二进制指数退避的期望时延分析**：第 `i` 次冲突后期望等待为 $(2^i - 1) \cdot 2\tau / 2$，因此退避窗口**指数增长**，在高负载下能有效降低再次冲突概率——但这也让**最坏情况时延无界**。这是「**吞吐 vs 时延**」在 MAC 层的体现，与 TCP 的拥塞控制（AIMD）在数学结构上同源。
- **海明码是「线性分组码」的最简形式**：其校验矩阵 `H` 的列向量互不相同且非零，这保证了「任一位错误都对应不同的伴随式（syndrome）」⇒ 可定位并纠正 1 位错。**「检 2 纠 1」的界限**来自「纠正 1 位需要码距 ≥ 3」。海明界 $2^r \ge k + r + 1$ 就是**完美码**的等式条件。
- **交换机自学习是「分布式且无协调」的转发表构建**：没有任何中心节点分配，每台交换机只看自己收到的帧的源地址。这构成一个**收敛性可证的在线学习算法**（在拓扑无环且地址不迁移的前提下收敛到正确转发表）。它也解释了为什么**二层环路会引发广播风暴**——自学习在没有 TTL 的二层无法终止泛洪，必须靠 **STP（生成树协议）**人为打破环。

### 📚 考研者视角
- **408 链路层必考**：① 三种成帧方法（尤其**零比特填充**，会给一串比特让你写出填充后的结果）② 差错控制（**海明码的 `2^r ≥ k+r+1`**、**CRC 的模 2 除法手算**）③ **以太网帧最小 64 B 与 `L ≥ 2τC`** ④ CSMA/CD 与二进制指数退避 ⑤ **交换机自学习过程**（给一串收发事件，画出 MAC 表变化）。
- **海明码常考「给出数据位求校验位数」**：直接套 `2^r ≥ k + r + 1`，**注意是「≥」不是「=」**，取最小满足的 `r`。
- **CRC 手算的格式要求**：写清楚「补 r 个 0」「模 2 除」「取余数 r 位」。**务必用异或而不是减法**（常见错误）。
- **易错点**：① 前导码**不计入**帧长；② 以太网最小帧 **64 B** 是「目的 MAC + 源 MAC + 类型 + 数据 + FCS」的总和（不含前导码）；③ 交换机**隔离冲突域但不隔离广播域**，**路由器才隔离广播域**。
- 记忆锚点：**「零比特填充：5 个 1 插 0」**、**「海明码 2^r ≥ k+r+1，纠 1 检 2」**、**「CRC 异或除法、余数为 0 则无错」**、**「交换机学习源、转发看目的、未知就泛洪」**。
