# fund-ch11 · 陷阱清单：计算机网络的十二个高频错误

1. **把「差错控制」只归给一层** —— 它是**跨层协作**：**链路层用 CRC 检错并丢帧**（只检错不纠错）、**传输层用序号+重传恢复**、**网络层只校验 IP 首部**（不校验数据）。问「哪层提供差错控制」时，**至少要答两层**。

2. **把「拥塞控制」归给网络层或链路层** —— **拥塞控制只在传输层（TCP）**。IP 层是「尽力而为」，**明确不做拥塞控制**（所以才有 TCP 的 `cwnd`）。链路层的 CSMA/CD 是「介质访问控制」，不是拥塞控制。

3. **以太网帧长把前导码算进去** —— 前导码（8 B）是**物理层的时钟同步序列**，**不计入帧长**。以太网最小帧 **64 B** = 目的 MAC(6) + 源 MAC(6) + 类型(2) + 数据(46) + FCS(4)。**加前导码算成 72 B 就错了。**

4. **认为交换机隔离广播域** —— 交换机**隔离冲突域**（每端口一个），但**广播帧仍会泛洪到所有端口**，所以**不隔离广播域**。**路由器（或 VLAN）才隔离广播域。** 这是必考辨析。

5. **跨网段时把帧的目的 MAC 写成目的主机的 MAC** —— 跨网段时，**IP 首部的目的 IP 是最终目的主机**，但**帧的目的 MAC 是网关（路由器入接口）的 MAC**。ARP 只在同一广播域内解析；路由器**不转发 ARP**。

6. **子网计算忘记减 2** —— 可用主机数 = `2^h − 2`，**要减掉网络地址（主机位全 0）与广播地址（主机位全 1）**。另外 `/31`（点对点链路）与 `/32` 是特例，标准题里一般不用，若出现要看清题目约定。

7. **ARP 请求与应答的方向搞反** —— **ARP 请求是广播**（不知道对方 MAC，只能广播问「谁有 IP x」），**ARP 应答是单播**（已知请求者 MAC，直接单播回）。答反了直接失分。

8. **ICMP 当成传输层协议** —— ICMP **是网络层协议**，封装在 IP 数据报里（协议号 1）。它**只做差错报告与询问，不提供进程间通信**，所以**不是传输层**。同理 **ARP 也属于网络层**（虽然常被放在链路层与网络层之间讨论）。

9. **`TIME_WAIT` 与 `CLOSE_WAIT` 混淆** —— `TIME_WAIT` 是**主动关闭方**在发完最后一个 ACK 后的状态，等 **2MSL**（保证 ACK 送达 + 让旧报文消亡）；`CLOSE_WAIT` 是**被动关闭方**收到 FIN 但**还没调用 `close()`** 的状态。**`TIME_WAIT` 多是设计问题，`CLOSE_WAIT` 堆积一定是代码没关连接。**

10. **超时与三个重复 ACK 的处置写反** —— **超时**：`ssthresh = cwnd/2`、`cwnd = 1`、**回到慢启动**（最严厉）；**三个重复 ACK**：`ssthresh = cwnd/2`、`cwnd = ssthresh`、**进入快恢复（不回慢启动）**。**这是拥塞控制题的必考分界线，写反即零分。**

11. **RTT 估计忘了 Karn 算法** —— **重传过的报文段不能用于 RTT 采样**，否则无法区分 ACK 对应的是哪一次发送，会把 RTT 估计搞乱。另外注意公式：`RTO = RTT_S + 4·RTT_D`，`α = 1/8`、`β = 1/4`——**系数写错就是算错**。

12. **以为「三次握手」是为了「确认双方都在线」** —— 核心目的是**防止已失效的历史连接请求**到达服务端并建立无用连接（若只有两次，服务端会单方面进入 ESTABLISHED 并一直等一个永远不来的客户端）。另外三次才能**双向确认双方的收发能力**。答「确认双方都在」不算错但拿不到要点分。
