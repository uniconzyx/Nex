# 编码与自同步：为什么以太网要给比特"加冗余"

## 1. 背景/动机

物理层要解决的问题听起来很简单：把 `1` 变成高电平、`0` 变成低电平，发出去。

但接收方马上会问：**"我该每隔多久采一次？"** 它没有独立的时钟，只能从信号里推。如果发了 1000 个连续的 `1`，线上就是一段平直的高电平——**没有任何跳变，接收方无从判断这是 1000 个 1 还是 999 个 1**，采着采着就"漂"了。这叫**时钟漂移 / 失步**。

所以工程上必须**故意制造跳变**，用冗余换取定时信息。这就是**线路编码（line coding）**的全部动机。

## 2. 定义/要点

| 编码 | 规则 | 跳变保证 | 效率 | 用在哪 |
|---|---|---|---|---|
| **NRZ**（不归零） | 1=高，0=低 | 无（连续同值就没有跳变） | 100% | 简单串口、早期设备 |
| **NRZI**（不归零反转） | 遇 1 翻转，遇 0 保持 | 依赖数据（连续 0 会失步） | 100% | USB、100BASE-FX 的底层 |
| **曼彻斯特** | 每位中间必跳：0=高→低，1=低→高 | **每位一次**（结构保证） | **50%** | 10BASE-T 以太网、令牌环 |
| **差分曼彻斯特** | 位中间必跳；**位首有跳变=0，无跳变=1** | 每位一次 | 50% | 令牌环 |
| **4B/5B** | 4 位 → 5 位查表（共 16 个数据码字 + 16 个控制码字） | **连续 0 ≤ 3 个** | **80%** | 100BASE-TX、FDDI |
| **8B/10B** | 8 位 → 10 位 | 连续 0/1 均受限（**running disparity** 平衡） | 80% | 千兆以太网、PCIe、SATA |

```text
### 波形对照：谁能自己恢复时钟

比特:      1     0     1     1     0     0     1
          ┌─┐   ┌─┐   ┌─┐   ┌─┐   ┌─┐   ┌─┐   ┌─┐
NRZ    ───┘ └───┘ └───┘ └───┘ └───┘ └───┘ └───┘ └───
        高位持续 → 连续相同位时「零跳变」，接收方无法定时

曼彻斯特（每位中间必有跳变，跳变即时钟）
   1: ──┐___      0: ___┌──
        ↑ 位中      ↑ 位中
       低→高        高→低

差分曼彻斯特（看「位首有无跳变」）
   位首跳变 = 0 ；位首不跳 = 1 ；位中必跳
   好处：双绞线接反了也能解码（只看"变没变"，不看"高还是低"）
```

### 波特率与比特率：两个必背等价关系

**两个必须记住的等价关系**：

$$\text{波特率}_{\text{曼彻斯特}} = 2 \times \text{比特率}, \qquad \text{波特率}_{\text{4B/5B}} = \frac{5}{4} \times \text{比特率}$$

所以 **10Mbps 的 10BASE-T 实际跑 20 MBaud，100Mbps 的 100BASE-TX 实际跑 125 MBaud**。题目问"线路上的码元率"时，这两个数经常是答案。

## 3. 可运行代码（C，含中文注释 + 真实输出）

```c
#include <stdio.h>
/* c02：四种编码的「跳变密度」——为什么以太网选了曼彻斯特
 * 自同步的前提是「信号里有足够多的跳变」，接收方能从中恢复时钟。
 * 本程序统计不同数据模式下各编码的跳变次数，看 NRZ 何时失步。*/
static int transitions(const int *lv, int n) {
    int t = 0;
    for (int i = 1; i < n; i++) if (lv[i] != lv[i - 1]) t++;
    return t;
}

int main(void) {
    const char *patterns[] = {"10101010", "11111111", "00000000", "11000011"};
    int n = 8;

    printf("不同比特模式下的跳变次数（每比特 1 格）\n");
    printf("--------------------------------------------------------------\n");
    printf("%-12s %-12s %-14s %s\n", "比特模式", "NRZ 跳变", "曼彻斯特跳变", "NRZ 能否自同步");

    for (int p = 0; p < 4; p++) {
        int nrz[8], man[16];
        for (int i = 0; i < n; i++) nrz[i] = (patterns[p][i] == '1');
        for (int i = 0; i < n; i++) {
            if (patterns[p][i] == '0') { man[2 * i] = 1; man[2 * i + 1] = 0; }
            else                       { man[2 * i] = 0; man[2 * i + 1] = 1; }
        }
        int tn = transitions(nrz, n), tm = transitions(man, 2 * n);
        printf("%-12s %-12d %-14d %s\n", patterns[p], tn, tm,
               tn >= 4 ? "能" : "不能（时钟会漂移）");
    }
    printf("--------------------------------------------------------------\n");
    printf("结论：\n");
    printf("  1) NRZ 在最坏情况（全 0 或全 1）下跳变数为 0，接收方没有任何时钟参考；\n");
    printf("     工业上靠「加扰码」缓解（如 1000BASE-T 的 8B/10B、PAM5 加扰）；\n");
    printf("  2) 曼彻斯特无论什么数据，跳变数恒为 n（每位中间必跳），\n");
    printf("     所以「自同步」是结构保证的，不依赖数据内容；\n");
    printf("  3) 代价：码元率翻倍。10Mbps 的 10BASE-T 实际跑 20 MBaud。\n");
    return 0;
}
```

真实输出：

```text
不同比特模式下的跳变次数（每比特 1 格）
--------------------------------------------------------------
比特模式 NRZ 跳变   曼彻斯特跳变 NRZ 能否自同步
10101010     7            8              能
11111111     0            15             不能（时钟会漂移）
00000000     0            15             不能（时钟会漂移）
11000011     2            13             不能（时钟会漂移）
--------------------------------------------------------------
结论：
  1) NRZ 在最坏情况（全 0 或全 1）下跳变数为 0，接收方没有任何时钟参考；
     工业上靠「加扰码」缓解（如 1000BASE-T 的 8B/10B、PAM5 加扰）；
  2) 曼彻斯特无论什么数据，跳变数恒为 n（每位中间必跳），
     所以「自同步」是结构保证的，不依赖数据内容；
  3) 代价：码元率翻倍。10Mbps 的 10BASE-T 实际跑 20 MBaud。
```

注意曼彻斯特的跳变数**恒为 15**（16 个半位格 → 15 次相邻变化），无论数据是什么。**"和数据内容无关"就是"自同步"的严格含义**：定时信息是编码结构带来的，不是碰巧数据里有跳变。

## 三视角解析

### 🧑‍💻 程序员视角

**真实工作场景**：一条 100 米的 Cat5e 网线连着一台老交换机，白天没事，一到夏天空调开机就偶发丢包，`ifconfig` 看 `RX errors` 缓慢增长，应用侧表现为"偶尔一次 RPC 超时"。

排查路径：`ethtool -S eth0 | grep -i err` 看到 `rx_crc_errors` 在涨、`rx_length_errors` 不涨 → **CRC 错但长度对**，说明帧被接收但校验不过，典型是**信号质量问题**（不是网线断了）。再看 `ethtool eth0` 的协商结果：`Speed: 100Mb/s, Duplex: Full`——但两条线对里有一对的**误码率**已经接近临界。

根因：水晶头氧化 + 强电走线并行，导致**信噪比下降**。按香农，1000BASE-T 要在 100 米 Cat5e 上跑 1Gbps，需要 4 对线全双工同时工作（每对 250Mbps），对串扰和回波损耗极其敏感；某一对劣化就会触发**降速重协商**或大量重传。

**这个案例的教学价值**：应用层的"偶发超时"可以一路追到"物理层信噪比"。判据链条是 `rx_crc_errors ↑` → 物理层 → 换线/换水晶头/避开强电。**如果 `rx_crc_errors` 不涨而 `rx_dropped` 涨，那是内核缓冲区/中断问题，不是物理层**——这个区分能省掉一半的排查时间。

### 🎓 博士生视角

线路编码的本质是**在"频谱效率"与"定时信息"之间做权衡**，可以用一个统一框架看：

$$\text{所需带宽} \;\propto\; \frac{R_b}{\log_2 V} \times \frac{1}{\eta_{\text{code}}}$$

其中 $R_b$ 是比特率，$V$ 是电平数，$\eta_{\text{code}}$ 是编码效率（NRZ 100%、4B/5B 80%、曼彻斯特 50%、8B/10B 80%）。三种手段可以互相替代：

1. **加冗余**（4B/5B、8B/10B）：用带宽换定时与 DC 平衡，还能做**错误检测**（非法码字）；
2. **加电平**（PAM-5、PAM-16）：用信噪比换带宽，千兆以太网在 Cat5e 上正是用 4 对线 × PAM-5 × 125MBaud 拼出 1Gbps；
3. **加扰**（scrambler）：用伪随机序列把长串 0/1 打散，**不增加带宽**就获得跳变——这是最优雅的一招，代价是需要收发同步的 LFSR。

8B/10B 还多解决了一个 NRZ 的隐患：**DC 偏置（running disparity）**。若信号长期偏向高电平，交流耦合的变压器会"漂"掉判决门限，所以 8B/10B 用两套互补码表让 0/1 的累计差值始终在 ±2 内——**这是"编码要照顾模拟电路"的经典案例**，纯数字思维想不到。

从信息论看，编码冗余与**信道编码**（纠错码）是正交的两件事：线路编码解决"定时与模拟适配"，信道编码解决"误码纠正"。现代高速链路（PCIe 5.0、100G 以太网）两者叠加：**64B/66B 线路编码 + RS-FEC 前向纠错**，两条腿走路。

### 📚 考研者视角

**408 高频考点**：

1. **"为什么曼彻斯特编码能自同步"**（简答）：因为**每位中间必有一次跳变**，跳变本身就是时钟信号，接收方可从中提取定时，且与数据内容无关；代价是波特率翻倍（带宽利用率 50%）。
2. **波形画图题**：给比特序列，画 NRZ / 曼彻斯特 / 差分曼彻斯特。**注意差分曼彻斯特的"位首跳变=0、无跳变=1"**，画反了就全错。
3. **码元率换算**：10BASE-T 用曼彻斯特，10Mbps → 20 MBaud；100BASE-TX 用 4B/5B，100Mbps → 125 MBaud。**这是"给了比特率求波特率"的固定套路。**
4. **4B/5B 的判据**：连续 0 **不超过 3 个**（配合 NRZI），效率 4/5 = 80%。不要答成"跳变数 ≥2"。
5. **编码 vs 调制的区别**：编码是"数字→数字"（基带传输），调制是"数字→模拟"（频带传输）。题目问"把数字信号变换成适于在模拟信道传输的信号"就是在问调制。

**易错点**：
- 把曼彻斯特的"自同步"答成"不需要时钟"；
- 差分曼彻斯特规则记反；
- 忘记曼彻斯特让波特率翻倍（带宽利用率只有 50%）；
- 把 4B/5B 的效率算成 5/4（应是 4/5 = 80%，即"多花 25% 带宽"）。
