# 两个"时延"与时延带宽积：物理层设备的性能边界

## 1. 背景/动机

"网络慢"是最含糊的一句话。物理层告诉我们：**"慢"至少有两种完全不同的慢**，而它们的解法相反。

- **传输时延（transmission delay）**：把数据"推上线路"的时间 = 数据量 / 发送速率。**加带宽能直接减小它。**
- **传播时延（propagation delay）**：信号在介质里"跑过去"的时间 = 距离 / 信号速度。**加带宽对它毫无影响**，只能靠"离得更近"。

把它们混为一谈，就会得出"升级带宽能让游戏延迟变低""卫星上网加带宽就能打电竞"这类错误结论。而**时延带宽积（BDP）** 把两者乘起来，得到本章最有用的一个数：**"管道里同时能装多少比特"**。

## 2. 定义/要点

$$T_{\text{传输}} = \frac{L}{R}, \qquad T_{\text{传播}} = \frac{d}{v}, \qquad \text{BDP} = T_{\text{传播}} \times R = \frac{d}{v}\times R$$

其中 $L$ 是数据长度（bit），$R$ 是发送速率（bps），$d$ 是距离，$v$ 是信号传播速度（光纤约 $2\times10^8$ m/s ≈ 光速的 2/3）。

```text
把链路想成一根「管子」：

  发送端 ──────────────────────────────────▶ 接收端
         ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
         ↑                              ↑
      正在「推上线路」            正在「跑在路上」
       T_trans = L/R               T_prop = d/v

  管子的「粗细」 = 带宽 R
  管子的「长度」 = 传播时延 T_prop
  管子的「容积」 = BDP = T_prop × R  ← 同时"在路上"的比特数

  想让管子灌满 → 发送窗口/缓冲区 ≥ BDP
```

### 两类链路的时延对比：谁在主导

**两类链路的对比**（一个 1500 字节的包）：

| 链路 | 带宽 | 距离 | 传输时延 | 传播时延 | 谁主导 |
|---|---|---|---|---|---|
| 同机房 10m | 10Gbps | 10 m | 0.001 ms | 0.00005 ms | **带宽**（推上线路） |
| 同城 50km | 1Gbps | 50 km | 0.012 ms | 0.25 ms | **距离** |
| 跨省 2000km | 100Mbps | 2000 km | 0.12 ms | 10 ms | **距离**（差 83 倍） |
| 卫星 36000km | 50Mbps | 36000 km | 0.24 ms | **180 ms** | **距离**（差 750 倍） |

卫星那条最刺眼：**传播时延是传输时延的 750 倍**。把卫星带宽从 50M 提到 500M，单程延迟仍然是 180ms，RTT 仍然 ≥ 360ms——**TCP 三次握手就要 360ms，怎么加带宽都救不了。**

### 设备的边界：中继器与集线器到哪一层

**物理层设备及其边界**：

| 设备 | 层 | 作用 | 冲突域 | 广播域 |
|---|---|---|---|---|
| **中继器 Repeater** | 物理层 | 信号**放大整形**，延长距离（不管内容） | 不分割 | 不分割 |
| **集线器 Hub** | 物理层 | 多端口中继器，**所有端口同一冲突域**，带宽**共享** | **不分割**（1 个） | 不分割 |
| 网桥 / **交换机** | 链路层 | 按 MAC 地址转发，**每口独立冲突域** | **分割** | 不分割 |
| 路由器 | 网络层 | 按 IP 转发，隔离广播 | 分割 | **分割** |

## 3. 可运行代码（C，含中文注释 + 真实输出）

```c
#include <stdio.h>
/* c04：时延带宽积的「管道」直觉
 * 把链路想成一根管子：
 *   管子长度  = 传播时延（信号跑一趟的时间）
 *   管子粗细  = 带宽（每秒能灌多少比特）
 *   管子容积  = 时延带宽积 = 传播时延 × 带宽 = 「同时在路上」的比特数
 * 容积决定：要想「发满」，窗口/缓冲区至少要这么大。
 * 这也是 BDP 这个名字的由来（Bandwidth-Delay Product）。*/
int main(void) {
    struct { const char *name; double rtt_ms; double Mbps; } links[] = {
        {"局域网",   0.1, 10000.0},
        {"同城",     2.0,  1000.0},
        {"跨省",    40.0,   100.0},
        {"跨洋",   200.0,   100.0},
        {"卫星",   540.0,    50.0}
    };
    printf("时延带宽积 = RTT × 带宽（这里用 RTT 算「一来一回的管道容积」）\n");
    printf("----------------------------------------------------------------------\n");
    printf("%-10s %-12s %-14s %-16s %s\n", "链路", "RTT(ms)", "带宽", "BDP(字节)", "跑满所需窗口");
    for (int i = 0; i < 5; i++) {
        double bdp_bytes = links[i].rtt_ms / 1000.0 * links[i].Mbps * 1e6 / 8.0;
        printf("%-10s %-12.1f %-14.0f %-16.0f >= %.0f KB\n", links[i].name, links[i].rtt_ms,
               links[i].Mbps, bdp_bytes, bdp_bytes / 1024.0);
    }
    printf("----------------------------------------------------------------------\n");
    printf("工程含义：\n");
    printf("  1) 跨洋 200ms RTT + 100Mbps，BDP = 2.5MB —— TCP 窗口小于它就不可能跑满；\n");
    printf("  2) 这也解释了「为什么带宽升级了但单流速度没变」：\n");
    printf("     窗口没跟着调大（Windows 默认 64KB），管道再粗也灌不满；\n");
    printf("  3) 卫星链路 BDP 更大，所以必须用窗口缩放选项（RFC 1323）。\n");
    return 0;
}
```

真实输出：

```text

----------------------------------------------------------------------
链路     RTT(ms)      带宽         BDP(字节)      跑满所需窗口
局域网  0.1          10000          125000           >= 122 KB
同城     2.0          1000           250000           >= 244 KB
跨省     40.0         100            500000           >= 488 KB
跨洋     200.0        100            2500000          >= 2441 KB
卫星     540.0        50             3375000          >= 3296 KB
----------------------------------------------------------------------
工程含义：
  1) 跨洋 200ms RTT + 100Mbps，BDP = 2.5MB —— TCP 窗口小于它就不可能跑满；
  2) 这也解释了「为什么带宽升级了但单流速度没变」：
     窗口没跟着调大（Windows 默认 64KB），管道再粗也灌不满；
  3) 卫星链路 BDP 更大，所以必须用窗口缩放选项（RFC 1323）。
```

**同一个想法在设备层面的体现**（来自本章 `ex10`，10 台主机各 100Mbps）：

```text
设备             冲突域        每主机可用带宽 同时发送
集线器 Hub      1 个（共享） 10.0               不能（CSMA/CD 竞争）
交换机 Switch   10 个（每口一个） 100.0              能（全双工）
--------------------------------------------------------------
带宽差距 = 10 倍
```

集线器的 10 倍差距不是"hub 技术落后"，而是**物理层设备的定义决定的**：它在物理层只做信号放大，没有"地址"概念，所以无法把流量只送给某一台——**所有端口天然共享一条介质**。

## 三视角解析

### 🧑‍💻 程序员视角

**真实工作场景**：公司把机房从北京迁到新加坡，专线带宽从 100Mbps 升到 1Gbps，但文件同步任务（rsync 大量小文件）速度几乎没变，还是 2MB/s。运维怀疑"新专线有问题"，测了 iperf3 单流只有 5Mbps，多流并发能到 600Mbps。

根因是 **BDP + 单流窗口**：北京-新加坡 RTT ≈ 80ms，1Gbps 下 BDP = 80ms × 1Gbps / 8 = **10MB**。而 rsync 的 TCP 单流窗口默认只有几百 KB（内核 `tcp_wmem` 默认上限常见 4MB，实际有效窗口还受接收端 `tcp_rmem` 限制），于是：

$$\text{单流吞吐} \approx \frac{\text{窗口}}{\text{RTT}} = \frac{256\text{KB}}{0.08\text{s}} = 3.2\text{MB/s}$$

**正好对上实测的 2MB/s。** 这不是"专线有问题"，是"管道太粗而窗口太小"。

解法（按性价比排序）：
1. 调大 `net.ipv4.tcp_rmem` / `tcp_wmem` 并确保启用窗口缩放（`net.ipv4.tcp_window_scaling=1`）；
2. rsync 用 `--compress` 减少数据量，或改用 **多流并行**（`parallel-rsync`、`rclone --transfers`）绕开单流限制；
3. 上 **BBR 拥塞控制**（基于 BDP 建模而非丢包），在高 BDP 链路上提升显著。

**这就是"时延带宽积"的实际价值：它让你能一眼算出"理论单流上限"，从而判断该调参数还是该换链路。**

### 🎓 博士生视角

BDP 的意义在于它把**"容量"与"时延"这两个通常分开讨论的量耦合起来**。在排队论里，一个链路可以用"服务速率 $R$、传播时延 $\tau$"描述，而 $\tau R$ 正是"系统中在途的比特数"——它是**利特尔定律（Little's Law）** $L = \lambda W$ 在网络中的直接体现：稳态下"在途比特数 = 到达率 × 停留时间"。

这个量决定了三件事：

1. **协议窗口下限**：可靠传输要用窗口"填满管道"，否则发送方会在等 ACK 时空转。所以 $W_{\min} \ge \tau R$，这是所有滑动窗口协议的设计起点。
2. **缓冲区下限**：路由器要能缓存"在途"的包而不丢，缓存至少 $\tau R$。但**缓存过大又会导致 bufferbloat**（排队时延从毫秒涨到秒级）——这是 2010 年代网络界的大讨论，最终催生了 CoDel/FQ-CoDel 等 AQM 算法。
3. **拥塞控制的建模基础**：BBR 直接用"测量到的 BDP"作为发送速率的估计（$cwnd \approx BDP \times gain$），与传统"丢包即拥塞"的 Reno/CUBIC 是两条完全不同的哲学。

物理层设备的分层边界同样值得玩味：**中继器/hub 只处理"信号"，交换机才开始处理"帧"**。这条边界的经济学含义是——**越往上走，能做的优化越多，但延迟与开销也越大**。所以数据中心内部大量使用"物理层交换"（光交叉连接 OXC、AOC 直连）来榨取最后几微秒，而"要不要上交换机"取决于你是否需要"按地址分流"这个能力。

形式化地看，一个设备的"层"可以由它**能识别的地址空间**定义：hub 识别 0 维（无地址）、交换机识别 MAC（48 位）、路由器识别 IP（32/128 位）。**每上一层，就多一个可以做出转发决策的维度**——这与前面"复用的正交维度"是同一个思想的不同投影。

### 📚 考研者视角

**408 高频考点**：

1. **传输时延 vs 传播时延**（选择题常客）：给"数据 1000bit、速率 1Mbps、链路 2000km、光速 2×10⁸m/s"，求两者。传输 1ms，传播 10ms。**问"哪个占主导"就要比较这两个数。**
2. **时延带宽积**：$= \text{传播时延} \times \text{带宽}$，单位是**比特（或字节）**，含义是"管道容量"。常问"链路上最多能有多少比特在传输"。
3. **"加带宽能否降低时延"**：能降低**传输**时延（以及排队时延），**不能**降低**传播**时延。这是简答题的标准答法。
4. **hub vs switch**（必考对比）：
   | | 冲突域 | 广播域 | 带宽 | 工作层 |
   |---|---|---|---|---|
   | Hub | 1 个（不分割） | 不分割 | 共享 | 物理层 |
   | Switch | 每口一个（分割） | 不分割 | 独享 | 链路层 |
   | Router | 分割 | **分割** | 独享 | 网络层 |
5. **中继器的作用与限制**：放大整形信号以延长距离；**不能连接不同速率的网段**（不能做速率转换），**不能隔离冲突**（不分割冲突域），会**放大噪声**。
6. **"5-4-3 规则"**（10BASE-5 时代）：最多 5 段、4 个中继器、3 个有主机的段——现在考得少，但出现过。

**易错点**：
- 把"传输时延"和"传播时延"的公式写反（$L/R$ 与 $d/v$）；
- 时延带宽积的单位答成"bps"（应为比特）；
- 认为"交换机分割广播域"（错，要路由器或 VLAN）；
- 认为"hub 能连接 10M 和 100M 网段"（普通 hub 不行，双速 hub 内部其实是"两个网段 + 网桥"）。
