# 排序实战手记：凯喵在算法课上的十二次翻车

> 排序这一章的概念都熟：快排、归并、堆排、外部排序、比较下界。但凯喵发现，真正让人丢分的从来不是"不知道有归并排序"，而是边界写错、稳定性搞混、复杂度说错、外部排序的归并趟数算错。这篇手记用十二个现场把这些细节钉死，每个都给出可直接对照的代码或算式。

## 开场：排序题的三种考法

这门课里的排序有三层考法，难度递增：

1. **写代码**——给一个数组，实现快排/归并/堆排，要求能过边界用例。
2. **说性质**——稳定性、最坏/平均复杂度、原地与否、适用场景。
3. **算规模**——外部排序的归并趟数、比较次数下界、磁盘 IO 次数。

大部分人卡在第二层和第三层，因为第一层可以背模板，后两层必须理解。下面十二个现场按这三层铺开。

### 现场一：快排的 `partition` 写成死循环

最经典的翻车。初版代码写成这样：

```python
def partition(a, lo, hi):
    pivot = a[lo]
    i = lo
    for j in range(lo, hi):        # 错：j 从 lo 开始，会和 pivot 自己比较
        if a[j] <= pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[lo], a[i] = a[i], a[lo]
```

问题在于 `a[lo] == pivot`，`j = lo` 时条件成立，`a[lo]` 和自己交换、`i` 加一，最后 `a[lo]` 和 `a[1]` 交换，pivot 被挪走。正确写法是 `j` 从 `lo+1` 开始，或者用 Lomuto 的标准形式：

```python
def partition(a, lo, hi):
    pivot = a[hi]          # 取末元素为基准
    i = lo                 # i 指向「小于区」的下一个位置
    for j in range(lo, hi):
        if a[j] < pivot:   # 严格小于，等于的留在右边
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    return i               # 返回基准最终位置
```

凯喵的记忆点：**`i` 永远是"小于区的边界 + 1"，`j` 只负责扫描，最后一步把基准换到 `i`**。这三个角色搞清，`partition` 就不会错。

### 现场二：快排没做随机化，遇到有序数组退化成 O(n²)

测试用例全过，一上真实数据就超时。原因：取首元素或末元素作基准时，**已经有序的输入会让每次划分都极不平衡**（一侧 0 个、另一侧 n-1 个），递归深度变成 n，复杂度退化为 O(n²)，n=10⁵ 时直接 TLE。

修法有三条，按推荐度排序：

```python
# 方案一：随机选基准（最简单）
import random
def partition(a, lo, hi):
    r = random.randint(lo, hi)
    a[r], a[hi] = a[hi], a[r]     # 换到末尾，复用上面的逻辑
    ...

# 方案二：三数取中（无随机，行为可复现）
def median_of_three(a, lo, hi):
    mid = (lo + hi) // 2
    if a[lo] > a[mid]: a[lo], a[mid] = a[mid], a[lo]
    if a[mid] > a[hi]: a[mid], a[hi] = a[hi], a[mid]
    if a[lo] > a[mid]: a[lo], a[mid] = a[mid], a[lo]
    a[mid], a[hi] = a[hi], a[mid]     # 中位数换到末尾
```

方案二更适合考试和生产（行为确定、便于复现），方案一实现最省事。两者都能把"有序输入"的最坏情况概率降到可忽略。

顺带一个必须记住的结论：**快排的最坏是 O(n²)，平均是 O(n log n)**。有些教材写"快排 O(n log n)"是不严谨的，考试问"最坏"时答 O(n log n) 就是错的。

### 现场三：以为快排稳定，实际不稳定

"快排是原地排序，所以空间 O(1)"——前半句对，后半句错（递归栈是 O(log n)）。但更常错的是稳定性。

快排**不稳定**。原因在于 `partition` 里的交换是"远距离交换"，会把相同元素的相对顺序打乱：

```text
原数组（按第一个字段排序，关注相同 key 的相对顺序）
[(2,'a'), (1,'x'), (2,'b'), (1,'y')]
                 ↑ 两个 key=2 的元素是 a 在前、b 在后

快排一轮划分后可能变成
[(1,'x'), (1,'y'), (2,'b'), (2,'a')]
                          ↑ b 跑到 a 前面了，顺序被打乱
```

需要稳定时选归并排序或（改造后的）基数排序。**归并是稳定的**，因为合并时遇到相等元素优先取左边的。这一点是归并相对快排的核心优势之一，考试常考。

### 现场四：归并排序的合并写成"先拷完一边再说"

```python
def merge(a, lo, mid, hi):
    left = a[lo:mid+1]
    right = a[mid+1:hi+1]
    i = j = 0
    k = lo
    while i < len(left) and j < len(right):     # 必须有「双条件」
        if left[i] <= right[j]:                # <= 保证稳定
            a[k] = left[i]; i += 1
        else:
            a[k] = right[j]; j += 1
        k += 1
    while i < len(left):  a[k] = left[i];  i += 1; k += 1   # 收尾
    while j < len(right): a[k] = right[j]; j += 1; k += 1   # 收尾
```

三处易错：一是循环条件写成 `or`（会越界）；二是判断写 `<` 而不是 `<=`（不稳定）；三是忘了两个收尾循环（剩下的一边没拷进去）。

凯喵的记忆点：**"双条件循环 + `<=` + 两个收尾"**，三段缺一不可。

### 现场五：归并的"额外空间 O(n)"说成 O(1)

归并排序需要与待排数组等大的辅助数组，空间是 O(n)，这是它相对快排的劣势。有人因为"递归深度是 O(log n)"就答成 O(log n)，混了"栈空间"和"数组空间"。

准确说法是：**归并排序的空间复杂度是 O(n)**（辅助数组），递归栈另算 O(log n)。如果面试官追问"能不能原地归并"，答案是能，但实现复杂（如 block merge sort），且常数因子大，实践中不用。

### 现场六：堆排的"建堆"从 0 开始上浮，复杂度算成 O(n log n)

建堆有两种做法，复杂度差一个 log：

- **自底向上建堆（Floyd 建堆）**：从最后一个非叶节点 `n//2 - 1` 开始，逐个下沉。复杂度 **O(n)**。
- **逐个插入建堆**：从空堆开始，每次插入后上浮。复杂度 **O(n log n)**。

```python
def build_heap(a):
    n = len(a)
    for i in range(n // 2 - 1, -1, -1):    # 从最后一个非叶节点倒着来
        sift_down(a, i, n)

def sift_down(a, i, n):
    while True:
        largest = i
        l, r = 2*i + 1, 2*i + 2
        if l < n and a[l] > a[largest]: largest = l
        if r < n and a[r] > a[largest]: largest = r
        if largest == i: break
        a[i], a[largest] = a[largest], a[i]
        i = largest
```

为什么自底向上是 O(n)？因为大部分节点在底层，下沉距离很短：高度为 h 的节点有约 n/2^(h+1) 个，下沉代价 h，求和 `Σ h·n/2^(h+1) = O(n)`。这个推导考试常考，值得自己推一遍。

### 现场七：堆排的"取堆顶"忘了减 size，结果死循环

```python
def heap_sort(a):
    n = len(a)
    build_heap(a)
    for end in range(n - 1, 0, -1):
        a[0], a[end] = a[end], a[0]     # 堆顶换到末尾
        sift_down(a, 0, end)            # 关键：只在下标 [0, end) 内下沉
```

`end` 同时承担两个角色：它是"已排好的边界"，也是"当前堆的大小"。写成 `sift_down(a, 0, n)` 就会把刚换到末尾的最大值又捞回堆里，死循环或结果错乱。

凯喵的记忆点：**堆排的 `end` 是"堆的右开边界"，每轮递减**。

### 现场八：说"堆排稳定"，实际不稳定

堆排**不稳定**。因为堆顶和末尾的交换是远距离的，相同元素相对顺序会变。而且堆结构本身不维护"插入顺序"这一信息。

四种常见排序的稳定性速查：

```text
            最坏        平均        最好        空间      稳定
冒泡        O(n²)      O(n²)      O(n)       O(1)      ✅
插入        O(n²)      O(n²)      O(n)       O(1)      ✅
归并        O(nlogn)   O(nlogn)   O(nlogn)   O(n)      ✅
快排        O(n²)      O(nlogn)   O(nlogn)   O(logn)   ❌
堆排        O(nlogn)   O(nlogn)   O(nlogn)   O(1)      ❌
选择        O(n²)      O(n²)      O(n²)      O(1)      ❌
```

这张表必须能默写。考试里"哪个排序稳定且最坏 O(n log n) 且空间 O(1)"这种组合题，答案是不存在——归并稳定但空间 O(n)，堆排空间 O(1) 但不稳定。这类"三者不可兼得"的结论本身就是考点。

### 现场九：比较排序下界写成 Ω(n)，漏了 log

"基于比较的排序至少要比较多少次"——正确答案是 **Ω(n log n)**，不是 Ω(n)。

推导思路（决策树下界）：n 个元素有 n! 种排列，每次比较只有两个结果（二叉），所以决策树至少有 n! 个叶子，高度至少 `log₂(n!)`。用 Stirling 公式得 `log₂(n!) = Θ(n log n)`。

常见错误是"每个元素至少看一次，所以 Ω(n)"——这只能说明读入的下界，不能说明比较的下界。凯喵的记忆点：**"下界来自信息量，不是来自元素个数"**。

顺带一个高频延伸：要突破 O(n log n)，必须放弃"比较"这个前提，用计数排序、基数排序、桶排序。它们能到 O(n + k) 或 O(d·(n + k))，代价是对数据分布有要求。

### 现场十：基数排序的"稳定"被忽略，结果全错

基数排序（LSD，从低位到高位）**必须每轮都用稳定排序**，否则前面的排序结果会被后面的打乱，整个算法失效。

```python
def radix_sort(a):
    maxv = max(a)
    exp = 1
    while maxv // exp > 0:
        counting_sort_by_digit(a, exp)   # 这一轮必须是稳定的计数排序
        exp *= 10

def counting_sort_by_digit(a, exp):
    n = len(a)
    out = [0] * n
    cnt = [0] * 10
    for x in a:
        cnt[(x // exp) % 10] += 1
    for i in range(1, 10):
        cnt[i] += cnt[i - 1]             # 前缀和 → 定位
    for i in range(n - 1, -1, -1):       # 关键：必须从后往前！
        d = (a[i] // exp) % 10
        cnt[d] -= 1
        out[cnt[d]] = a[i]
    a[:] = out
```

那个"从后往前"就是稳定性的来源——倒序回填保证了相同键值的元素保持原有相对顺序。写成正序就变成了不稳定，结果错误。这是基数排序唯一真正难记的细节，也是面试常问"为什么必须倒序"的答案。

### 现场十一：外部排序的归并趟数算成"除以 k"就完事

外部排序的经典题：1GB 数据、内存 100MB、归并路数 k=10，问需要几趟归并？

思路是"先内部排序生成初始归并段，再多路归并"：

```text
总数据 1GB，内存 100MB → 初始归并段数 R = 1GB / 100MB = 10 段
每趟 k 路归并，段数变为 ⌈R / k⌉
第 1 趟：10 → ⌈10/10⌉ = 1 段，完成

结论：1 趟归并
```

容易错的两种：

- **忘了减 1**：有人算成"10 段需要 10 趟"，实际每趟把段数缩小 k 倍。
- **忘了向上取整**：R=11、k=10 时是 ⌈11/10⌉ = 2 段，不是 1.1；下一趟再 ⌈2/10⌉ = 1。总共 2 趟。

通用公式是 `趟数 = ⌈log_k R⌉`。凯喵的记忆点：**"段数除以 k，取整，重复到 1；趟数就是对 k 取对数"**。

### 现场十二：外部排序只优化了归并路数，忽略了 IO 才是瓶颈

最后一条是观念层面的。很多人以为"增大 k 就能减少趟数，所以 k 越大越好"，但 k 增大会带来两个副作用：

1. **k 路归并的每次选择需要比较 k 个元素**。若用朴素比较，代价 O(k)，k=100 时 CPU 开销巨大。解决办法是用**败者树**，把每次选择降到 O(log k)。
2. **k 路归并要求同时打开 k 个输入缓冲区**，每个缓冲区太小会导致频繁磁盘读。缓冲区总大小受内存限制，所以 k 增大必然让每个缓冲区变小，反而增加 IO 次数。

所以 k 的选择是一个权衡，不是单调最优。实践中常用 k = 几十到一百，配合败者树 + 双缓冲。

更根本的优化方向是**减少 IO 总量**而不是减少趟数：用置换选择（replacement selection）生成更长的初始归并段（平均长度可达内存的 2 倍），能把初始段数直接减半。凯喵的总结：**外部排序的性能几乎完全由磁盘 IO 决定，CPU 的比较开销是次要项**——记住这个主次，很多题的直觉就对了。

## 三视角解析
### 🧑‍💻 程序员视角
凯喵的 `partition` 写成死循环，原因是 `while (a[++i] < pivot)` 没有边界判断，当 pivot 是最大值时 i 会越界。修法有两种：用 `i < j` 双条件，或者把 pivot 换到末尾做「哨兵」。快排还有个隐蔽的性能坑：对已经有序的数组不做随机化，每次划分都退化成 1 与 n-1，递归深度 O(n)、时间 O(n²)——`std::sort` 用「三数取中 + 内省排序（超过 2log n 层转堆排）」正是为了封住这个最坏情况。另一个常见误解是「快排稳定」：划分时的交换会打乱相等元素的相对次序，要稳定只能用归并。

### 🎓 博士生视角
比较排序的时间下界是 `Ω(n log n)`，证明用决策树：n 个元素有 n! 种排列，每次比较最多把可能性减半，故树高至少 `log₂(n!) = Θ(n log n)`。这解释了为什么基于比较的算法无法突破该界，也解释了计数排序/基数排序为何能到线性——它们利用了「关键字范围有限」这一额外信息。堆排序的建堆过程是 O(n) 而非 O(n log n)：自底向上建堆的总代价为 `Σ(n/2^(h+1))·h = O(n)`，这是一个常被算错的经典结论。工程上 `std::sort` 用内省排序（introsort）组合快排、堆排、插入排序，在平均与最坏之间取平衡。

### 📚 考研者视角
408 排序是必考的「表格题 + 过程题」：
1. **复杂度表格**：时间（最好/平均/最坏）、空间、稳定性，八种排序必须默写。高频陷阱：快排最坏 O(n²) 且不稳定；堆排不稳定；归并稳定但空间 O(n)；希尔排序的时间依赖增量序列。
2. **一趟结果**：给出一趟排序后的序列，判断用的是哪种算法。冒泡看「最大/最小是否到位」，快排看「pivot 左边都比它小」，堆排看「堆顶是否已放到末尾」。
3. **建堆与调整**：给数组画初始堆（从 `⌊n/2⌋` 开始下沉），再写出每次删除堆顶后的调整过程。
4. **外部排序**：多路归并的趟数 `⌈log_k(m)⌉`、败者树的作用，这是大题常客。

## 收尾：凯喵的排序速记卡

五句话压住整章：

**快排三件事**——`partition` 的三角色、随机化避最坏、不稳定且栈空间 O(log n)。

**归并三件事**——双条件循环 + `<=` + 两个收尾、稳定、辅助空间 O(n)。

**堆排三件事**——自底向上建堆是 O(n)、`end` 是堆边界且每轮递减、不稳定。

**下界看信息**——比较排序 Ω(n log n) 来自 n! 个叶子，不是来自元素个数。

**外部看 IO**——趟数是 ⌈log_k R⌉，但真正的瓶颈是 IO 总量，k 不是越大越好。

这一章的价值不在于背模板（网上到处都是），而在于**知道每个模板为什么这么写、写错了会怎样**。凯喵批改过很多份排序作业，错误几乎全部集中在三处：`partition` 的边界、归并的收尾、堆排的 size 递减。这三处只要各写十遍、每遍都手推一个小例子，错误率会降到接近零。

最后补一句方法上的建议：**排序是练"手推"最好的素材**。拿 `[3,1,4,1,5,9,2,6]` 这个数组，把快排、归并、堆排各手推一遍，每一步都写出数组状态和指针位置，画在纸上。这个过程只要一小时，但它建立的直觉能撑住整个学期——因为所有的边界错误，都会在"手推时数组状态和预期不符"的那一刻暴露出来。凯喵见过的人里，凡是认真手推过三遍的，考场上从来不会在排序题上丢分。
