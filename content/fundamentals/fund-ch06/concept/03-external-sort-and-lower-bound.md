# 外部排序、比较下界与非比较排序

## 1. 外部排序：数据装不进内存时怎么办

当待排序记录量远超内存容量时，无法做内部排序，必须借助外存（磁盘）。外部排序分两个阶段：

**阶段一：生成初始顺串（run）**
把大文件切成若干能装入内存的块，逐块读入内存、内部排序、写回磁盘，得到 m 个**有序的初始顺串**。

**阶段二：多路平衡归并**
把 m 个顺串做 k 路归并（k 为归并路数），逐趟归并直到剩下一个顺串。
归并趟数 = **⌈log_k m⌉**，因此**增大 k 能显著减少趟数**，也就减少了 I/O 次数。

**代价的定量口径（408 计算题核心）**

- 归并趟数 `= ⌈log_k m⌉`
- 每趟要把全部记录读写一遍，故 **I/O 次数 ≈ 2 × 记录总数 × 趟数**（读一遍 + 写一遍）
- 增大 k 的代价：需要 k 个输入缓冲区，内存占用 O(k)；且 k 路归并每输出一个记录要做 k-1 次比较，
  靠**败者树**可把比较次数降到 O(log k)。

**三大优化**

1. **多路平衡归并**：k 越大趟数越少，总 I/O 越少（但受内存缓冲区数量限制）。
2. **败者树（loser tree）**：k 路归并时选出最小元素，朴素做法是 k-1 次比较，
   败者树只需 ⌈log₂ k⌉ 次比较，使 CPU 不再成为瓶颈。
3. **置换-选择排序（replacement selection）**：让生成的初始顺串长度**超过内存容量**
   （平均可达 2 倍内存大小），从而减少顺串个数 m，间接减少归并趟数。
4. **最佳归并树**：当初始顺串长度不等时，按 **哈夫曼（Huffman）** 思想构造 k 叉归并树——
   长度短的顺串先归并、长后归并，使**带权外部路径长度最小**，即总 I/O 次数最小。
   若 (m-1) 不能被 (k-1) 整除，需补 **虚段**（长度为 0）凑足 k 叉树。

### 🧑‍💻 程序员视角

外排的思想在现代系统里到处都是，只是换了名字：

- **数据库的外部排序算子**：MySQL 的 `filesort`、PostgreSQL 的 external sort，
  都是「分块排序 + 多路归并」，缓冲区大小由 `sort_buffer_size` / `work_mem` 控制——
  调大它就是增大 k，直接减少归并趟数，这是慢查询优化的常见手段。
- **LSM-Tree（LevelDB/RocksDB/HBase）**：SSTable 的分层 compaction 本质上就是
  「有序段的持续多路归并」，与外排同源。
- **大文件排序**（如 `sort` 命令处理大于内存的文件）：同样是分块 + 归并，
  实践中还要考虑用 **压缩** 减少 I/O、用 **SSD 随机读** 放宽顺序读约束。

判断是否需要外排的口径：数据量 > 可用内存时不要试图一次性读入，先算清
「块数 m = 总大小 / 内存块大小」和「路数 k」，再估 I/O 次数。

### 🎓 博士生视角

外部排序的复杂度模型与内部排序根本不同：**代价的度量单位不是比较次数，而是磁盘块 I/O 次数**。
因为一次随机 I/O ≈ 10⁷ 次 CPU 比较，优化重心从「减少比较」转移到「减少趟数」。

由此可推：总 I/O ≈ `2N·⌈log_k m⌉`，对 k 求导可知 I/O 随 k 对数下降；
但 k 受限于内存缓冲区数量（每路至少一个块缓冲），且 k 过大时每块的顺序读会被打散成更多寻道。
这是一个典型的 **CPU–I/O 权衡**：败者树解决前者（每记录比较 O(log k)），
缓冲区大小与预读解决后者。

置换-选择之所以能让平均顺串长度达到 2M（M 为内存容量），可用「扫雪机模型」严格证明：
在关键字随机的假设下，顺串长度的期望是内存容量的 2 倍。

### 📚 考研者视角

**必背口径**：
- 外排 = **生成初始顺串** + **多路平衡归并** 两阶段。
- 归并趟数 = **⌈log_k m⌉**（m 为顺串数，k 为归并路数）。
- 增大 k → 趟数减少 → I/O 减少；代价是需要更多缓冲区、且 k 路选最小要 ⌈log₂ k⌉ 次比较（败者树）。
- **置换-选择** 生成的顺串平均长度可达 **2M**。
- **最佳归并树** 用哈夫曼思想，短顺串先归并；需补虚段凑 (m-1) mod (k-1) = 0。

**高频计算题模板**：
> 已知文件有 N 个记录，内存可容纳 M 个记录，做 k 路平衡归并，求归并趟数与 I/O 次数。
> 解：顺串数 m = ⌈N/M⌉；趟数 = ⌈log_k m⌉；I/O ≈ 2N × 趟数（块为单位时按块计）。

**易错点**：把「内部排序的趟数」与「外排的归并趟数」混为一谈；
忘记 I/O 要乘 2（读 + 写）；忽略虚段的补充规则。

## 2. 比较排序的下界：为什么不可能比 O(n log n) 更快

**决策树（判定树）模型**
任何基于比较的排序都可以抽象成一棵二叉决策树：每个内部节点是一次比较 `a[i] < a[j]`，
左右分支对应两种结果，每个叶子对应一种可能的排列结果。

- n 个不同元素共有 **n!** 种可能的排列，故决策树至少有 **n! 个叶子**。
- 高度为 h 的二叉树最多有 `2^h` 个叶子，故 `2^h ≥ n!`，即 `h ≥ ⌈log₂(n!)⌉`。
- 由斯特林公式 `log₂(n!) = n log₂ n − O(n)`，得 **h = Ω(n log n)**。

这就是比较排序的**下界定理**：任何基于比较的排序算法，最坏情况下至少需要 Ω(n log n) 次比较。
归并、堆排达到了这个下界（渐进意义下已最优），快排平均也达到。

**排序的「决策树下界」与查找的「判定树下界」是同一个工具**——
查找的下界是 `⌈log₂(n+1)⌉`（n+1 个失败结点），排序的下界是 `⌈log₂ n!⌉`。

### 🧑‍💻 程序员视角

这个下界的工程含义是：**如果你的排序是瓶颈，别指望换一个「更聪明的比较排序」来突破 O(n log n)**，
只能从别处想办法：

1. 减少参与排序的元素数量（先过滤 / 先分区 / Top-K 用堆）；
2. 降低单次比较的成本（预计算 sort key、用整数代替字符串比较）；
3. 利用数据的**已有性质**——近乎有序用插入排序（O(n)）、整数且范围小用计数/基数排序（O(n)）；
4. 并行化（多核归并），改变的是墙钟时间而非渐进复杂度。

### 🎓 博士生视角

下界定理的前提是「**只能通过二元比较获取信息**」。一旦放宽这个信息模型，下界立即失效：

- **计数排序**利用「关键字是 [0, k] 范围内的整数」这一结构信息，复杂度 O(n + k)；
- **基数排序**利用「关键字可按位分解」的结构，复杂度 O(d(n + r))，d 为位数、r 为基数。
  当 d 为常数、r = O(n) 时，它就是 **O(n)**——突破 Ω(n log n) 下界，
  代价是**不再通用**：它要求关键字可分解为定长、均匀的位段。

这揭示了一条一般原理：**算法复杂度不是绝对的，它相对于允许的信息获取方式**。
所谓「突破下界」实质是引入了额外的先验假设（分布、范围、位数），并非逻辑上推翻了定理。

### 📚 考研者视角

**必背**：比较排序下界 **Ω(n log n)**，用**决策树**证明，叶子数 ≥ **n!**，高度 ≥ **⌈log₂ n!⌉**。

**简答模板**：
> 基于比较的排序可抽象为二叉决策树，n 个元素有 n! 种排列，故树至少 n! 个叶子；
> 高度 h 的二叉树至多 2^h 个叶子，故 h ≥ ⌈log₂ n!⌉ = Ω(n log n)。
> 因此任何比较排序最坏至少 Ω(n log n) 次比较。

**高频追问**：「计数/基数排序为什么能突破这个下界？」
答：因为它们**不基于比较**，而是利用关键字的取值范围/位数这一结构信息；
代价是只适用于关键字范围有限或可按位分解的特定场景，且需要 O(n+r) 的额外空间。

## 3. 非比较排序：计数排序与基数排序

**计数排序**：统计每个关键字值出现的次数，再按值从小到大依次输出。
复杂度 **O(n + k)**（k 为关键字范围），空间 O(n + k)，**稳定**（需从后往前填，或使用累加计数 + 逆序输出）。
适用：关键字是**小范围整数**（如年龄 0~150、成绩 0~100）。

**基数排序（radix sort）**：按关键字的**位**从低位到高位（LSD）依次做「稳定排序」，
每位用计数排序（桶）。复杂度 **O(d(n + r))**：d 为位数、r 为基数（桶数，通常取 10）。
**稳定**，空间 O(n + r)。

关键前提：**每一位的排序必须是稳定的**，否则高位的排序结果会被低位打乱。
这也是「基数排序稳定性」成为考点的主要原因。

### 🧑‍💻 程序员视角

- 计数/基数排序只在**关键字分布集中**时才划算。若 n=100 而 k=10⁹，计数排序的 O(n+k) 会瞬间爆炸。
- 基数排序对**缓存不友好**（每轮要散射到 r 个桶再收集），实践中常按字节分 8 位（r=256）做，
  在 32 位整数上只需 4 轮，这是很多高性能排序库的做法。
- 字符串排序常用 **MSD 基数排序 + 小数组切插入排序**，正是这个思路。

### 🎓 博士生视角

从信息论看，比较排序每次比较最多获得 1 bit 信息，而 n! 种排列需要 log₂(n!) ≈ n log₂ n bits，
故下界成立。基数排序每次「按位分桶」获得的是 log₂ r bits（一次读出一整位的取值），
因此 d 轮即可获得 d·log₂ r bits，足以区分全部关键字——信息获取效率的差异就是复杂度差异的根源。

### 📚 考研者视角

**必背**：
- 计数排序 **O(n+k)**，稳定，空间 O(n+k)，适用小范围整数。
- 基数排序 **O(d(n+r))**，**稳定**，空间 O(n+r)，**不基于比较**，**每一趟必须是稳定排序**。
- 「时间复杂度 O(n log n) 且稳定的排序」= **归并 + 基数**（计数在 k 小时也是 O(n)）。

**经典选择题**：「以下排序中，时间复杂度与初始序列**无关**的是？」
答案：**简单选择排序**（恒 O(n²)）、**堆排序 / 归并排序**（恒 O(n log n)）、**基数排序**。
而插入、冒泡、快排都与初始序列有关。
