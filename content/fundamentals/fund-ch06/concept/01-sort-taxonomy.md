# 排序总览：内部排序分类与复杂度/稳定性对照表

## 1. 八种内部排序的「时间·空间·稳定性」统一口径

内部排序指待排序记录全部装入内存。按「是否基于关键字比较」分两大类：

- **比较排序**：插入、希尔、冒泡、简单选择、快排、堆排、归并——它们的下界受比较决策树约束（见本节主题 2）。
- **非比较排序**：计数、基数、桶——利用关键字本身的分布，可突破 Ω(n log n)。

下面给出 408 统考前必须背熟的**三档时间复杂度（最好 / 平均 / 最坏）+ 空间 + 稳定性**对照表（n 为记录数，d 为基数排序的关键字位数，r 为基数）：

| 排序 | 最好 | 平均 | 最坏 | 空间 | 稳定 | 备注 |
|---|---|---|---|---|---|---|
| 直接插入 | O(n) | O(n²) | O(n²) | O(1) | 是 | 基本有序时最好 O(n) |
| 希尔 | — | O(n^1.3) | O(n²) | O(1) | 否 | 依赖步长序列，无统一最好 |
| 冒泡 | O(n) | O(n²) | O(n²) | O(1) | 是 | 设标志位后基本有序 O(n) |
| 简单选择 | O(n²) | O(n²) | O(n²) | O(1) | 否 | 与输入无关，恒 O(n²) |
| 快速 | O(n log n) | O(n log n) | O(n²) | O(log n) | 否 | 最坏=已有序且选端点枢轴 |
| 堆 | O(n log n) | O(n log n) | O(n log n) | O(1) | 否 | 建堆 O(n)，调整 O(log n) |
| 归并 | O(n log n) | O(n log n) | O(n log n) | O(n) | 是 | 趟数 ⌈log₂n⌉，与输入无关 |
| 基数(LSD) | O(d(n+r)) | O(d(n+r)) | O(d(n+r)) | O(n+r) | 是 | 空间含桶/计数数组 |

> 注意「最好」列：插入/冒泡在**已有序**时为 O(n)；快排、堆、归并、选择、希尔的「最好」≠ O(n)（快排最好仍是 O(n log n)）。

### 🧑‍💻 程序员视角
- 这张表的「空间」是「额外辅助空间」，不包含输入本身。工程里栈空间（快排递归深度）常被忽视：快排最坏递归深度 O(n)，在深递归 + 小栈场景会栈溢出，因此 `std::sort` 用 introsort 在递归过深时切到堆排。
- 稳定性在工程里不是学术问题，而是**正确性**问题：对「先按价格、再按时间」的多级排序，若底层排序不稳定，二级排序会打乱一级结果。数据库 `ORDER BY a, b` 依赖稳定排序或显式多键比较。
- 别迷信「O(n²) 一定慢」：插入排序在 n≤16 的小数组上常数极小，常被作为快排/归并的递归底部 base case。

### 🎓 博士生视角
- 稳定性本质是**等价关系在排列下的保持**：排序是偏序扩展为全序的过程，稳定排序在该全序与「原始下标序」的字典序一致时成立。形式化：若 aᵢ.key = aⱼ.key 且 i < j，则稳定排序保证输出中 aᵢ 仍在 aⱼ 前。
- 「最好/平均/最坏」对应输入分布下比较树的不同路径长度：最坏 = 主路径（最长），平均 = 期望路径长（假设输入均匀随机），最好 = 最短主路径。三者不一定同阶，因为 worst-case 输入是构造性的（如快排的有序输入）。
- 空间复杂度的 O(log n)（快排）来自递归调用栈，是「隐式」辅助空间；而归并的 O(n) 是「显式」辅助数组。二者对缓存与嵌入式系统的含义不同。

### 📚 考研者视角
- **408 必背表**：上面 8 行必须能默写，尤其是「稳定性」一栏（稳定：插/冒/归/基；其余否）。选择题常考「下列哪种排序不稳定」或「空间复杂度 O(1) 且时间 O(n log n) 的排序」→ 堆排序。
- **常考辨析**：
  - 快排最坏 O(n²) 但平均 O(n log n)，且**平均情况下常数最小**，故综合最快；
  - 堆排/归并最坏也是 O(n log n)，但堆排常数大、缓存差，归并需 O(n) 空间；
  - 简单选择**与输入无关恒 O(n²)**，且移动次数少（每趟最多 1 次交换），但比较次数恒 n(n−1)/2。
- **易混点**：「希尔排序最好时间」没有统一 O(n) 结论（取决于步长），不要和插入/冒泡混淆；基数排序时间不含 log，是 d(n+r) 不是 n log n。

## 2. 比较排序的 Ω(n log n) 下界与「如何突破」

**定理（比较排序下界）**：任一基于比较的排序，在最坏情况下至少需要 ⌈log₂(n!)⌉ = Ω(n log n) 次比较。

**证明（决策树模型）**：把排序过程看成一棵二叉树，每个内部结点是一次「比较 aᵢ : aⱼ」，每个叶子对应一种排列。n 个不同元素有 n! 种排列，故叶子数 ≥ n!。一棵深度为 h 的二叉树最多 2^h 个叶子，于是 2^h ≥ n!，h ≥ log₂(n!) = Θ(n log n)（斯特林公式）。即最长比较路径 ≥ Ω(n log n)。□

### 🧑‍💻 程序员视角
- 这条下界告诉你：**只要你的算法只做「比较 + 交换」，就不可能比 O(n log n) 更快**。想更快，必须放弃「纯比较」——这正是计数/基数排序的思路，也解释了为什么它们对整数/定长字符串极快、对通用对象无用。
- 工程权衡：通用排序（如 `std::sort`）走比较排序上限 O(n log n)；若你明确知道键值域很小（如 0~255 的像素、年龄），用计数排序能打到 O(n)，是实打实的加速。
- 注意下界是「最坏」口径；随机化快排的**期望**也是 Θ(n log n)，但 worst-case 仍是 O(n²)——下界约束的是 worst-case 下界，不是期望。

### 🎓 博士生视角
- 决策树模型的关键假设是「每次比较产生二叉分支、信息量 1 bit」。n! 个等可能结果需要 ≥ log₂(n!) bit 信息，这是信息论下界，与具体算法无关。
- 基数/计数排序**不在该模型内**：它们读取的是关键字的「位/数值」而非做两两比较，每次操作提取 k = log r bit 信息（r 为基数），故总信息吞吐 O(d·log r) 可小于 log(n!)。前提是**关键字能用有限位表示且 r 不大**——一旦位数 d 随 n 增长（如任意大整数），优势消失。
- 计数排序突破下界的条件是「关键字范围 k = O(n)」：此时 O(n+k) = O(n)。若 k = ω(n)（如 32 位整数 k=2³²），则 O(n+k) 退化为 O(k)，并不优于比较排序。所以「突破下界」是有前提的，不是免费午餐。

### 📚 考研者视角
- **必考证明**：408 常要求「证明比较排序最坏 Ω(n log n)」或「用决策树说明」。答题三要素：① 叶子数 = n!；② 满二叉树叶子 ≤ 2^h；③ h ≥ log₂(n!) = Ω(n log n)。斯特林近似 log₂(n!) ≈ n log₂ n − n log₂ e，主项即 n log n。
- **突破前提（选择题高频）**：基数/计数排序之所以能 O(n)，是因为**利用了关键字的值分布而非比较**，代价是要求关键字范围有限（计数）或位数固定（基数）；当关键字范围远大于 n 时退化为 O(k)，不再优于比较排序。
- **易错**：下界 Ω(n log n) 是说「存在输入需要这么多比较」，不是「每个输入都要这么多」；插/冒在已有序输入上 O(n) 与此不矛盾（那是最好情况）。
