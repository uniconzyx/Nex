# 链表家族与哨兵节点

## 一、单链表

```c
typedef struct Node { int data; struct Node *next; } Node;

/* 头插：O(1) */
Node *push_front(Node *head, int v) {
    Node *n = malloc(sizeof(Node));
    n->data = v; n->next = head;
    return n;                     /* 返回新头（头指针会变） */
}
```

**痛点**：删除/插入需要**前驱节点**，而头节点没有前驱 → 代码里到处是「如果是头节点就特殊处理」的分支。

## 二、哨兵节点（dummy head）：消除边界分支

在链表前**挂一个不存数据的哑节点**，让「删除头节点」和「删除中间节点」变成同一种情况：

```c
/* 带哨兵：删除第一个值为 v 的节点，代码没有 if (prev == NULL) 分支 */
Node dummy = {0, head};
Node *prev = &dummy;
while (prev->next && prev->next->data != v) prev = prev->next;
if (prev->next) { Node *del = prev->next; prev->next = del->next; free(del); }
head = dummy.next;               /* 新头 */
```

**工程价值**：把「N 个特例」变成「0 个特例」。这是链表题（尤其是删除类、合并类）最常用的技巧。

**另一种等价手段——二级指针**：

```c
Node **pp = &head;
while (*pp && (*pp)->data != v) pp = &((*pp)->next);
if (*pp) { Node *del = *pp; *pp = del->next; free(del); }
```

`pp` 指向「指向当前节点的那个指针」，因此**修改它等价于修改前驱的 next 或头指针本身**——同样消除了特例。

## 三、双链表

```c
typedef struct DNode { int data; struct DNode *prev, *next; } DNode;
```

- **优势**：持有某节点指针时，**O(1) 删除自己**（不需要找前驱）；可反向遍历。
- **代价**：每节点多 8 字节指针；插入/删除要维护两个方向的指针（漏一个就断链）。
- **典型应用**：**LRU 缓存**（哈希表 O(1) 定位 + 双链表 O(1) 调整顺序）、文本编辑器、浏览器历史。

## 四、循环链表

尾节点的 `next` 指向头节点（双链表则头尾互指）。**遍历必须用「回到起点」作为终止条件**，否则死循环。

典型问题：**约瑟夫环**（报数出列）、**轮转调度**（round-robin）。

## 五、C++ `std::list` 与侵入式链表

`std::list` 是双向链表，它的特性值得记住：

| 特性 | 说明 |
|---|---|
| 插入/删除**不使其他迭代器失效** | 只影响被删元素本身（vector 则可能全体失效） |
| **不支持随机访问** | 没有 `operator[]`，只有双向迭代器 |
| `size()` | C++11 起 O(1) |
| **缓存不友好** | 遍历慢于 `vector`，实测常慢数倍 |
| `splice` | **O(1) 把一个链表的一段摘到另一个链表**（这是它真正的独门优势） |

**侵入式链表（intrusive list）**：把 `prev/next` 指针**嵌进用户数据结构内部**，而不是包一层节点。Linux 内核的 `list_head` 就是这种设计——好处是**零额外分配、一个对象可同时挂在多个链表上**。

```c
struct list_head { struct list_head *prev, *next; };
struct task { int pid; struct list_head run_list; struct list_head all_tasks; };
/* 同一个 task 同时在「就绪队列」和「全进程表」两个链表里 */
```

## 六、选型速查

| 需求 | 选择 |
|---|---|
| 随机访问、遍历、批量计算 | **顺序表**（`vector`/`array`） |
| 频繁头插尾插、栈/队列 | 顺序表（尾插）或 `deque` |
| 已知位置的频繁插入删除、LRU | **双链表**（+ 哈希） |
| 需要在容器间搬移整段 | **`std::list` + `splice`** |
| 对象需要同时属于多个容器 | **侵入式链表** |
| 内存极度受限、元素固定 | 顺序表（数组） |

## 三视角解析

### 🧑‍💻 程序员视角
- **哨兵（dummy head）是消灭边界分支的利器**：头插、删头都变成普通操作，代码里不再需要「是不是第一个节点」的判断，bug 率显著下降。
- 标准库的 `std::list` / `LinkedList` 实践中很少用（缓存不友好、每个节点一次分配）；要链式结构时更常见的是侵入式链表或手写。
- 双链表是 O(1) 删除的前提（有了前驱指针才不用再扫一遍），这也是 LRU 实现必须用双链表的原因。

### 🎓 博士生视角
- 哨兵的本质是**把一个「特例」提升为「普通情形」**，从而让结构不变量在全域成立（所有节点都有前驱）。这与编译器里用统一 IR 消除特例、以及抽象数据类型中「空对象模式」是同一思想。
- 循环链表与判环：Floyd 判圈法（快慢指针）的空间 O(1) 来自「相遇点与入口的几何关系」——步长差每步缩短 1，故必相遇；Brent 算法进一步降低常数。
- 双向链表的地址运算：`prev` 的存在使节点可自描述，可在 O(1) 内把自己从链上摘除——这是「节点自治」换取「遍历成本」。

### 📚 考研者视角
- **408 必考**：带头结点 vs 不带头结点链表的**判空条件**（`head->next == NULL` 与 `head == NULL`），这是选择题送分点也是易错点。
- 高频操作题：双向链表插入/删除的指针顺序（**先接后断**，防断链）；循环链表尾指针用 `rear` 表示可 O(1) 取到头尾。
- 算法设计题常考：判断链表有环、找环入口、合并有序链表、就地逆置、删除倒数第 k 个。
- 记忆锚点：**带头结点能统一空表与非空表的处理**，答题时写「引入头结点以统一操作」通常是加分表述。
