# 复杂度、均摊分析与真实代价

## 一、渐进复杂度的边界

复杂度描述的是 **N → ∞ 时的增长趋势**，它**刻意忽略了常数因子**。但常数因子在某些场景是决定性的：

| 结构 | 复杂度 | 实测常数（数量级） |
|---|---|---|
| 数组顺序遍历 | O(N) | 1× |
| 链表顺序遍历 | O(N) | **5~20×**（cache miss + 指针解引用） |
| 数组二分查找 | O(log N) | 1× |
| 哈希查找 | 平均 O(1) | **含哈希函数开销，常数可能比数组下标大** |

**结论**：**复杂度决定「能不能用」，常数决定「用哪个」**。N 不大时（比如 100 个元素），O(N²) 的插入排序常比 O(N log N) 的快排更快——因为快排的递归、分支预测失败、函数调用开销不可忽略。

## 二、均摊分析：动态数组为什么是 O(1)

`vector::push_back` 单次可能是 O(N)（扩容时要把 n 个元素搬到新内存），但**均摊**到每次是 O(1)。

**聚合分析法**（按 2 倍扩容）：

```
容量序列：1 → 2 → 4 → 8 → ... → 2^k
第 k 次扩容的搬移成本 = 2^(k-1)
总成本 = 1 + 2 + 4 + ... + 2^(k-1) = 2^k - 1
元素总数 = 2^k
均摊成本 = (2^k - 1) / 2^k < 2  → 常数！
```

搬移总成本是**等比数列**，其和是**最大项的两倍**，所以均摊是常数。这就是「倍数增长」相对于「每次 +1 增长」的本质区别：**线性增长会让总搬移变成 O(N²)**。

## 三、扩容倍数：1.5 还是 2？

| 策略 | 使用者 | 特点 |
|---|---|---|
| **2 倍** | GCC libstdc++ | 均摊更优；但 `1+2+4+…` 的旧块**永远无法被新块复用**（内存碎片，且总内存占用可达 1.5~2 倍数据量） |
| **1.5 倍** | MSVC / Facebook folly | 增长略慢；但 `1 + 1.5 + 2.25 …` 的旧块之和**小于新块**，可复用先前释放的内存 → **碎片更少** |

**面试回答要点**：两者均摊都是 O(1)，差别在**内存碎片与峰值占用**。工程上扩容倍数常做成**可配置**（如 `folly::fbvector`）。

## 四、内存分配器开销（常被忽略）

每次 `malloc` 并不只给你请求的字节：

```
请求 malloc(4) 的实际占用：
 ┌──────────────────────────────────────────┐
 │ 分配器元数据（size/flag/链表指针）16~32B │ 实际数据区（对齐到 16B）
 └──────────────────────────────────────────┘
 总占用通常 ≥ 32 字节 —— 是你请求量的 8 倍
```

后果：
1. **链表节点越小，相对开销越大**（存 `char` 的链表，元数据占 90%+）。
2. 大量小分配会导致**堆碎片**，长跑服务的内存 RSS 持续增长。
3. 这是**内存池 / slab 分配器**的动机——批量预分配，避免每节点一次 `malloc`。

## 五、选型决策树

```
需要按下标随机访问？ ── 是 ──→ 顺序表（vector）
        │
        否
        ↓
主要在两端操作？ ── 是 ──→ vector（尾） / deque（头尾都频繁）
        │
        否
        ↓
是否持有已知位置的迭代器/指针并频繁插入删除？ ── 是 ──→ list / 双链表
        │
        否
        ↓
需要 O(1) 查找 + O(1) 顺序调整？ ── 是 ──→ 哈希 + 双链表（LRU）
        │
        否
        ↓
数据量极大且不能整体搬移？ ── 是 ──→ list / 侵入式链表
        │
        否 ──→ 默认用 vector，先测量再优化
```

## 六、方法论

**先写正确的、简单可读的代码（通常是 `vector`），再用 profiler 找热点，最后才换数据结构。** 过早选择「理论最优」的复杂结构，通常换来的是更难维护的代码和得不到验证的收益。

## 三视角解析

### 🧑‍💻 程序员视角
- 选型看**实测**而不是大 O：同一个 O(n) 在实际数据上可能差 5～10 倍。压测时固定数据规模、取多轮中位数。
- 扩容前能预估规模就 `reserve`，一次分配换掉十几次搬移，这就是「均摊 O(1)」被打破成「每次 O(n)」的常见来源。
- 内存分配器开销真实存在：一次 `malloc` 的可用载荷常比请求值大 30%～100%（元数据 + 对齐填充），小对象密集场景要考虑内存池。

### 🎓 博士生视角
- 均摊分析的三种方法各有适用边界：**聚合法**（总代价/n）、**记账法**（把未来代价预付出去）、**势能法**（构造势函数 Φ，令均摊代价 = 实际代价 + ΔΦ）。动态数组取 Φ = 2n − capacity，立得均摊 O(1)。
- **amortized ≠ average-case**：均摊是对**任意**操作序列的最坏保证，与输入分布无关；平均分析依赖概率假设。二者常被混为一谈。
- 分配器策略（首次适配 / 最佳适配 / 分离适配）对应 fragmentat 与吞吐的权衡；1.5 倍扩容之所以在工程上优于 2 倍，是因为它更容易复用前面释放的空块，降低外碎片。

### 📚 考研者视角
- **408 考点**：时间复杂度与空间复杂度的分析（给代码求复杂度是必考）；顺序表建表整体 O(n)、单点插入 O(n)。
- 循环队列的容量与元素个数计算 `(rear − front + m) % m` 是高频计算题。
- 串的模式匹配朴素算法 O(n·m) 与 KMP 的 O(n+m) 对比常出现在复杂度选择题。
- 记忆锚点：**「均摊 O(1)」不等于「每次 O(1)」**——答题时区分清楚能避免踩坑；递归复杂度分析在 408 中一般只需展开推导，无需主定理。
