# fund-ch01 常见坑与避坑指南

> 每条都给出**症状 → 根因 → 修法**，并在示例代码里有对应演示。

1. **链表插入/删除忘记维护前驱指针 → 断链**

**症状**：插入后链表少了后面的部分，或遍历时崩溃。

```c
/* 错误：先改 p->next，再想访问原来的后继 —— 已经丢了 */
p->next = newnode;
newnode->next = p->next;    /* 此时 p->next 已经是 newnode 自己！→ 自环 */
```

**根因**：指针赋值是**覆盖**，不是插入。改 `p->next` 之前必须先保存原后继。

**修法**：**先接后断**（先让新节点指向原后继，再让前驱指向新节点）：

```c
newnode->next = p->next;
p->next = newnode;
```

2. **删除节点后继续使用它（悬垂指针）**

**症状**：偶发错误值、crash，且难以复现（取决于堆是否被复用）。

```c
free(del);
printf("%d\n", del->data);   /* UB：读已释放内存 */
```

**修法**：`free` 后**立即置空**别名指针（能做多少做多少），并使用 `-fsanitize=address` 在 CI 里捕获。根本手段是**所有权约定**：谁分配谁释放，释放后所有别名失效。

3. **循环里对顺序表头插 → 悄悄退化成 O(N²)**

**症状**：数据量到十万级时突然变得极慢。

```c
/* 每次头插都要把已有元素整体后移一位 → N 次头插 = O(N²) */
for (int i = 0; i < n; i++) insert_at(arr, 0, data[i]);
```

**修法**：改为**尾插**后一次性反转；或改用链表；或反向遍历源数据直接尾插。

4. **`sizeof(arr)/sizeof(arr[0])` 在函数里失效**

**症状**：函数内算出的「数组长度」是 8（指针大小/元素大小）或 1。

```c
void f(int a[]) { int n = sizeof(a)/sizeof(a[0]); }  /* a 已退化为 int*，n=2 或 1 */
```

**根因**：数组作为函数参数**退化为指针**，`sizeof` 得到的是指针大小。

**修法**：**显式传长度**；C++ 用 `std::span` / 模板 `template<size_t N> void f(int (&a)[N])`。

5. **快慢指针循环条件写错 → 空指针解引用**

**症状**：`fast->next->next` 对空指针解引用。

```c
while (fast->next && fast->next->next)   /* 偶数长度时会漏判 fast 本身为空 */
```

**修法**：**两个条件都要检查，且顺序不能反**（短路求值）：

```c
while (fast && fast->next) { slow = slow->next; fast = fast->next->next; }
```

6. **循环链表遍历缺少终止条件 → 死循环**

**症状**：程序卡死在该循环，CPU 100%。

**修法**：用「回到起点」作为终止条件，并**设置最大步数上限**兜底：

```c
Node *p = head;
do { /* ... */ p = p->next; } while (p != head);
```

7. **顺序表的指针/迭代器在扩容后全部失效**

**症状**：`vector` 扩容后，之前保存的 `&v[0]` 或迭代器指向已释放的旧内存。

```c
int *p = &v[0];
v.push_back(x);        /* 若触发扩容，p 悬垂 */
*p = 1;                /* UB */
```

**修法**：**扩容后重新获取**；用**索引**代替指针；提前 `reserve()` 避免中途扩容；了解哪些操作会使迭代器失效（`vector` 的 `push_back` 可能全失效，`list` 不失效）。

8. **误以为「链表插入一定比数组快」**

**症状**：把数组换成链表后性能反而下降。

**根因**：忘记了**定位成本 O(N)**，以及链表的 **cache 不友好 + 分配开销**（见 concept/01 与 concept/03）。

**修法**：**先测量**。只有在「已持有位置」且「插入删除非常频繁」时，链表才有优势。多数业务场景 `vector` 更快。

9. **内存泄漏：删除节点只断链没释放**

```c
prev->next = cur->next;   /* 断开了，但 cur 没 free → 泄漏 */
```

**修法**：断链前保存 `cur`，断链后 `free(cur)`；用 RAII/智能指针管理节点生命周期。

10. **对齐与大小误判**

`sizeof(Node)` 可能因为**对齐**大于「4 字节 data + 8 字节指针」：

```c
typedef struct { int data; struct Node *next; } Node;   /* data 后要补 4 字节 → sizeof = 16 */
```

**修法**：**用 `sizeof` 而不是手算**；需要紧凑时调整成员顺序，或用 `__attribute__((packed))`（有性能代价，慎用）。

11. **把「链表插入 O(1)」当成无条件成立**
   链表插入 O(1) 的前提是「已持有前驱节点指针」。只给下标时，定位本身就是 O(n) 次随机访存，比顺序表的移动更慢。
   ✅ 需要按 key 快速定位时，配合哈希表存「key → 节点指针」；否则直接用 `vector`。

12. **用 `sizeof` 量指针得到「数组长度」**
   数组作为函数参数后退化为指针，`sizeof(arr)` 在函数内是 8（指针大小），不是数组字节数。
   ✅ 函数接收数组时同时接收长度；或在调用处算好 `sizeof(arr)/sizeof(arr[0])` 再传入。

13. **结构体字段顺序随意，填充浪费大量内存**
   `struct { char a; int b; char c; }` 是 12 字节而非 6 字节，两个 `char` 各自被填充。
   ✅ 字段按大小降序排列（`int` 在前、`char` 在后），同样的字段能压到 8 字节；存百万条时差距可观。

14. **删除链表节点只断链不释放**
   `prev->next = victim->next;` 之后就结束，`victim` 那块内存永久泄漏，长驻服务会持续涨到 OOM。
   ✅ 先保存后继、再改指针、最后 `free`/`delete`；任何 `malloc`/`new` 都必须有对应释放路径。

15. **以为 `vector` 扩容后旧指针/迭代器仍然有效**
   扩容会重新分配整块内存，之前保存的元素地址、迭代器、引用全部失效，继续使用是 UB。
   ✅ 扩容前 `reserve` 预留足够容量；或保存下标而非地址；容器可能扩容时不要缓存迭代器。
