# 二叉搜索树与平衡：从退化到红黑树

## 一、BST 的价值与致命弱点

BST 把「有序」编码进了结构，带来 O(log N) 级的查找/插入/删除——**前提是树是平衡的**。

弱点：**插入有序数据时必然退化**。依次插入 1,2,3,...,N 得到的是一条右斜链，树高 N，所有操作退化为 O(N)，且递归实现会栈溢出。**真实数据往往接近有序**（自增主键、时间戳），所以「不退化」必须是结构自身的保证，不能靠运气。

这就是自平衡二叉搜索树（BBST）的动机：**在插入删除后主动调整结构，把树高锁在 O(log N)**。

## 二、AVL 树：最严格的平衡

**定义**：任意节点左右子树高度差（平衡因子）≤ 1。

插入/删除后若失衡，通过**旋转**恢复。四种失衡型（LL / RR / LR / RL）对应单旋或双旋。

| 优点 | 缺点 |
|---|---|
| 树高最紧（≤ 1.44 log N），查找最快 | 插入删除时**旋转频繁**（可能一路旋转到根），写操作代价高 |

AVL 的平衡条件太苛刻，导致**写多读少**的场景代价过大。

## 三、红黑树：工程上的最优折中

**五条性质**（记这五条即可推出一致性）：

1. 节点非红即黑；
2. 根是黑；
3. 叶子（NIL）是黑；
4. **红节点的孩子必须是黑**（不能有连续两个红节点）；
5. **任一节点到其所有后代 NIL 的路径，黑节点数相同**（黑高一致）。

**为什么这保证平衡**：由性质 4、5 可推出「最长路径 ≤ 2 × 最短路径」，于是树高 ≤ 2 log(N+1) —— 比 AVL 松，但仍是 O(log N)。

**为什么工程选它**：

| 维度 | AVL | 红黑树 |
|---|---|---|
| 树高上界 | 1.44 log N | 2 log N |
| 插入旋转次数 | 可能 O(log N) | **≤ 2 次** |
| 删除旋转次数 | 可能 O(log N) | **≤ 3 次** |
| 调整代价 | 旋转 + 高度更新（代价重） | 旋转 + **变色**（代价轻） |
| 适用场景 | 读极多写极少 | **通用**（读略慢一点换写大幅变快） |

**结论**：红黑树的「弱平衡」换来**写操作的常数上界**。这就是 `std::map`、`Java TreeMap`、Linux 内核 CFS 调度器、epoll 就绪列表都选红黑树的原因。

## 四、B 树与 B+ 树：为磁盘而生的多叉树

当数据量大到内存放不下，必须存磁盘。**磁盘访问以「页」为单位（通常 4KB 或 16KB），一次随机 IO 是毫秒级**——而内存访问是纳秒级，差了 5~6 个数量级。

二叉树的问题：**每个节点只存 1 个 key，树高 log₂N**。N = 10⁹ 时树高约 30 —— 意味着 **30 次磁盘 IO**，太慢了。

B 树的解法：**一个节点存一页的数据（几十到几百个 key），多叉**。树高降到 log_m N（m = 几百），N = 10⁹ 时树高仅 **3~4 层** —— 3 次磁盘 IO 就够（且根节点常驻内存，实际只有 2~3 次）。

**为什么数据库最终用 B+ 树而不是 B 树**：

| 维度 | B 树 | B+ 树 |
|---|---|---|
| 数据存放 | **所有节点**都存数据 | **只有叶子**存数据，内部节点只存 key + 指针 |
| 单节点 key 数 | 较少（要留空间给数据） | **更多**（无数据占位）→ 树更矮 |
| 范围查询 | 需要中序遍历跨层回溯 | **叶子间有链表**，顺序扫描即可 |
| 查询稳定性 | 命中内部节点就返回（快慢不一） | **每次都要到叶子**（IO 次数稳定可预测） |
| 全表扫描 | 差 | **顺序读叶子链表，极优** |

数据库的查询大量是范围查询（`WHERE id BETWEEN ...`）与排序（`ORDER BY`），B+ 树的叶子链表让这些操作变成**顺序 IO**，这是决定性的。

## 五、堆：只保证「部分有序」的树

**堆**是**完全二叉树**，用数组存储，满足「父 ≤ 子」（小顶堆）。与 BST 的关键差异：

- BST 保证**全局有序**（中序即升序），堆只保证**父子偏序**（根是最值，但兄弟之间无序）。
- 正因为要求弱，堆的插入/删除只需 `sift_up/sift_down` 沿一条路径调整：**O(log N)**，且没有旋转。
- BST 可以有序遍历，堆**不能**；但堆能以 O(1) 取最值——这是优先队列的基础。

**数组表示**（下标从 0 起）：

```
父(i) = (i-1)/2      左(i) = 2i+1      右(i) = 2i+2
```

完全二叉树的性质保证**数组不浪费空间**（不像一般二叉树用数组表示会有大量空洞）。

**建堆为什么是 O(N) 而不是 O(N log N)**：从最后一个非叶节点往前 `sift_down`。直觉上每次是 O(log N)，N 次就是 O(N log N)。但**大部分节点在底层、下沉深度极浅**：高度为 h 的节点数约为 N/2^(h+1)，其下沉代价 h，求和 `Σ h·N/2^(h+1) = O(N)`。这是个**比均摊分析更精细的求和**，也是面试爱问的点。

## 六、结构选择速查

| 需求 | 选择 |
|---|---|
| 有序遍历 / 范围查询（内存） | 红黑树（`std::map`/`set`） |
| 只要最值 / Top-K | 堆（`priority_queue`） |
| 磁盘索引 / 范围扫描 | B+ 树 |
| 精确等值查找（无需范围） | 哈希表（O(1)，但无序） |
| 频繁插入删除 + 需要有序 | 跳表（Redis zset）或红黑树 |

## 三视角解析

### 🧑‍💻 程序员视角
- 生产环境的有序容器基本都基于**红黑树**（`std::map`、JDK `TreeMap`）——不是因为它最优，而是它**插入删除的旋转次数常数上界**最稳。
- 内存数据库常改用**跳表**（Redis zset）：实现简单、并发友好，性能与平衡树同量级。
- 需要「范围查询 + 磁盘友好」就选 **B+ 树**（MySQL InnoDB 索引、文件系统元数据）。

### 🎓 博士生视角
- 红黑树与 **2-3-4 树等价**（把红链接「抬平」即得多路树），这是理解它平衡条件的钥匙：黑高相同 ⇔ 所有叶子到根的黑节点数一致。
- AVL 是**高度平衡**（左右子树高差 ≤ 1），查找更优但插入最多 O(log n) 次旋转；红黑树是**弱平衡**，插入 ≤ 2 次、删除 ≤ 3 次旋转，工程上常数更可控。
- B+ 树把「树高」翻译成「磁盘 I/O 次数」，阶数由页大小决定（约几百），故百万级数据只有 3～4 层——这是「减少 IO」而非「减少比较」的设计哲学。
- 可持久化平衡树（持久化红黑树/AVL）是函数式数据结构与版本化存储的基础。

### 📚 考研者视角
- **408 必考三件套**：
  1. **BST 的删除**（叶子 / 单子 / 双子三种情况；双子要用**中序后继或前驱**替换再递归删除）；
  2. **AVL 的四种旋转**（LL / RR / LR / RL），必须会画图并说出旋转后新根是谁；
  3. **B 树 / B+ 树**的定义（阶 m、结点关键字数范围 ⌈m/2⌉−1 ~ m−1）、插入分裂、删除借位/合并，以及 **B+ 树与 B 树的区别**（B+ 只有叶子存记录、叶子链表支持范围查询、非叶只做索引）。
- 高频计算题：给定插入序列构造 AVL/B 树，写出每一步调整过程。
- 记忆锚点：**「B+ 树比 B 树更适合数据库」的答题要点是「范围查询走叶子链表 + 树高更低 → I/O 更少」**。
