# 递归思维与树形 DP：把问题切成子问题

## 一、递归的三要素

写对递归只需回答三个问题：

1. **终止条件**：什么情况下直接返回？（空节点、叶子、已到达边界）
2. **子问题定义**：`f(node)` 的语义是什么？（**必须能用一句话说清**）
3. **合并规则**：子问题的答案怎么组合成当前节点的答案？

**最容易出错的是第 2 条**。例如求树的最大深度：

- 定义 `depth(node)` = 以 node 为根的子树最大深度；
- 终止：`node == NULL` → 0；
- 合并：`1 + max(depth(left), depth(right))`。

如果定义成「从根到 node 的深度」，递归就要**带参数往下传**（自顶向下），代码形态完全不同。**先定义清楚，再写代码**。

## 二、自顶向下 vs 自底向上

| 方向 | 特征 | 典型问题 |
|---|---|---|
| **自顶向下**（前序） | 把「父节点累积的信息」作为参数传给子节点 | 路径和、求根到叶的路径、带约束的遍历 |
| **自底向上**（后序） | 先算出子树的答案，再在父节点合并 | 树高、节点数、平衡判定、树形 DP |

**自底向上更容易写对**，因为「子问题的答案」是返回值，天然对应递归的返回值；自顶向下则要在调用前把状态准备好。

## 三、树形 DP：后序递归的威力

**树形 DP = 后序遍历 + 在「位置 C」（两个子树都处理完）合并信息**。

经典例子：**判断平衡二叉树**。朴素做法是自顶向下，对每个节点都算一次子树高 → **O(N²)**（每个节点的高度被重复计算）。正确做法是后序一次遍历：

```c
/* 返回子树高度；若发现不平衡返回 -1（用哨兵短路） */
int height(Node *n) {
    if (!n) return 0;
    int lh = height(n->left);
    if (lh == -1) return -1;              /* 已失衡，提前上抛 */
    int rh = height(n->right);
    if (rh == -1) return -1;
    if (abs(lh - rh) > 1) return -1;
    return 1 + (lh > rh ? lh : rh);
}
```

**从 O(N²) 到 O(N) 的关键**：让返回值**同时携带两种信息**（高度 + 是否平衡）。这是树形 DP 的通用技巧——**用一个返回值打包多个状态**。

## 四、返回值打包的更多形态

| 问题 | 返回值语义 |
|---|---|
| 树的直径 | `{以该节点为端点的最长路径, 子树内最大直径}` |
| 打家劫舍 III | `{选该节点的最大收益, 不选该节点的最大收益}`（二选一状态） |
| 二叉树最大路径和 | `{向父节点可提供的最大单边路径, 全局最大路径和}` |
| 最近公共祖先 | 返回「子树中找到了哪些目标节点」 |

**统一套路**：`pair<A, B> dfs(node)`，A 是「能给父节点的」，B 是「已经能定下来的全局答案」。

## 五、递归的边界与陷阱

1. **空指针**：终止条件必须覆盖 `NULL`，否则解引用崩溃。
2. **重复计算**：自顶向下 + 无记忆化 = 指数级（如朴素斐波那契、无缓存的树高）。
3. **栈深度**：树退化成链时递归深度 = N，必须改显式栈。
4. **修改共享状态**：递归里改全局变量而未回溯，会导致后续分支看到脏状态（回溯法必须「改了要改回来」）。
5. **遍历顺序与副作用**：释放树必须**后序**（先孩子后自己）；复制树适合**前序**（先建自己再建孩子）。

## 六、递归的通用改写公式

```
递归版本                          迭代版本
─────────────────────────────    ─────────────────────────────
if (终止) return ...               显式栈 / 队列
f(子)                            while (栈非空) { 弹栈处理；子节点入栈 }
合并                              用「入栈顺序」编码遍历序
```

**顺序编码技巧**：想要「左先于右」，就**右孩子先入栈**（栈是 LIFO）。想要「按层处理」，就换队列。想要「后序」，就记录「上一个访问的节点」判断右子树是否已处理，或把前序结果反转。

## 三视角解析

### 🧑‍💻 程序员视角
- 树形 DP 三步走：**定义递归返回什么**（子树信息）→ 后序递归拿子树结果 → **在根处合并**。
- 返回多个值时打包成结构体/元组（如同时返回「高度」和「是否平衡」），避免重复递归导致 O(n²)。
- 递归深度 ≈ 树高，退化成链时会爆栈——生产代码中对可能退化的树要用迭代后序或显式栈。

### 🎓 博士生视角
- 递归与**结构归纳**一一对应：树上的正确性证明就是「叶子成立 + 合并规则保持性质」。
- 树形 DP 统一为**代数折叠（catamorphism）**：给定「叶子值」与「合并算子」，即可唯一确定整棵树的求值；这一视角能解释为什么很多树问题复用同一模板。
- 递归的**不动点语义**与最小/最大不动点是程序语义学的标准工具（尤其涉及递归定义的数据结构）。
- 复杂度分析要点：每个节点被访问常数次 → O(n)；若在合并处引入排序则升为 O(n log n)。

### 📚 考研者视角
- **408 算法设计题**的绝对主力题型：「写出递归算法，求二叉树的**高度 / 结点数 / 叶子数 / 度为 1 的结点数 / 交换左右子树 / 判断是否平衡**」。
- 答题模板（务必按考研阅卷习惯写）：
  1. 给出**递归定义/思路**（一句话）；
  2. 写出**结构体类型**与**函数原型**；
  3. 写出完整 C 代码（含递归终止条件）；
  4. 给出**时间复杂度**（通常 O(n)）。
- 记忆锚点：**树高 = max(左高, 右高) + 1**；**结点数 = 1 + 左 + 右**；空树返回 0（或按题意返回 −1）。
