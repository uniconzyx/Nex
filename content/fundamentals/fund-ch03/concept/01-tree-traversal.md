# 树的遍历：三种序的本质与递归的非递归改写

## 一、树的递归定义，就是遍历的模板

树 = 根 + 若干棵子树。这个定义**自带递归结构**，所以遍历代码天然是递归的：

```c
void traverse(Node *root) {
    if (!root) return;
    /* 位置 A */
    traverse(root->left);
    /* 位置 B */
    traverse(root->right);
    /* 位置 C */
}
```

**关键洞察**：所谓前序/中序/后序，**区别仅仅是你把「访问根节点」这句话放在哪个位置**：

- 位置 A（进左子树前）→ **前序**：根 → 左 → 右
- 位置 B（左子树回来、进右子树前）→ **中序**：左 → 根 → 右
- 位置 C（右子树回来）→ **后序**：左 → 右 → 根

三种遍历的代码**只差一行**。背模板不如记住「相对根的三次经过时机」。

## 二、为什么中序对 BST 是「有序」的

BST 的定义是「左子树所有值 < 根 < 右子树所有值」。中序的访问顺序恰好是「先把所有更小的访问完，再访问根，再访问更大的」——**这正是升序的定义**。

由此得到两个直接推论（都是高频考点）：

1. **验证 BST 的正确做法是「中序遍历看是否严格递增」**，而不是「递归检查每个节点与其左右子节点的大小」——后者会漏掉「孙节点越界」的情况（如右子树里藏了一个比根小的值）。
2. **求 BST 第 k 小元素**：中序遍历计数到 k 即可，O(H + k)。

## 三、递归的系统成本：栈帧

每次递归调用都会在**系统栈**上压一个栈帧（返回地址 + 保存的寄存器 + 局部变量）。树的高度就是递归深度：

- 平衡树高度 O(log N)，如 N = 10⁶ 时高度约 20 —— 完全没问题。
- **退化成链的 BST 高度 O(N)**，N = 10⁶ 时递归 10⁶ 层 —— 直接栈溢出（SIGSEGV，不可恢复）。

**这就是「平衡」在工程上不是学术洁癖的原因**：不平衡不只是慢，是**会崩**。

## 四、非递归改写：用显式栈替代系统栈

思路是**手动模拟栈帧**：把「还需要做什么」压进自己的栈。

中序的非递归版本最能体现这个思想：

```c
void inorder(Node *root) {
    Node *stk[100], *cur = root;
    int top = 0;
    while (cur || top > 0) {
        while (cur) { stk[top++] = cur; cur = cur->left; }  /* 一路向左，模拟「先处理左子树」 */
        cur = stk[--top];
        visit(cur);                                          /* 左子树处理完，访问根 */
        cur = cur->right;                                    /* 转向右子树 */
    }
}
```

**前序**更简单（根先访问，右孩子先入栈以保证左先出）；**后序**最麻烦，需要额外状态标记「右子树是否已处理」，或用「根-右-左的前序结果反转」这个技巧。

**什么时候必须改写**：输入不可控、树高可能达 N 时。生产代码（如文件系统遍历）一律用显式栈或 Morris 遍历（O(1) 空间，靠临时改指针实现）。

## 五、层序遍历与 BFS

层序用**队列**：

```c
void levelorder(Node *root) {
    Node *q[100]; int head = 0, tail = 0;
    if (root) q[tail++] = root;
    while (head < tail) {
        Node *n = q[head++];
        visit(n);
        if (n->left)  q[tail++] = n->left;
        if (n->right) q[tail++] = n->right;
    }
}
```

要**按层分组输出**时，在每轮开始前记下当前队列长度 `len = tail - head`，只处理这 `len` 个节点——这一层的全部，同时下一层的节点已入队。

## 六、遍历的工程用途

| 遍历 | 用途 |
|---|---|
| 前序 | 序列化/反序列化树、复制树、打印目录结构（先打印自己再进子目录） |
| 中序 | BST 有序输出、第 k 小、范围查询 |
| 后序 | 释放树（必须**先释放孩子再释放自己**，否则悬垂）、计算子树聚合值（树形 DP） |
| 层序 | 求树宽/最大宽度、按层处理、BFS 最短路径（无权） |

## 三视角解析

### 🧑‍💻 程序员视角
- 递归最直观，但深度大时要改迭代（显式栈）；需要 O(1) 额外空间可用 **Morris 遍历**（借叶子空指针做临时线索，遍历后还原）。
- 层序遍历是 BFS 的树版，工程上用于「按层处理/最短步数」，如树的最小深度、按层序列化。
- 序列化/反序列化、表达式求值、AST 变换都建立在遍历之上——这是把遍历当**通用迭代协议**而非练习题。

### 🎓 博士生视角
- 遍历序与树的**可唯一确定性**：前序+中序、后序+中序可唯一确定；前序+后序**不能**（无法区分单子节点的左右）。
- n 个节点的二叉树形态数为 **Catalan 数** C(2n, n)/(n+1)，这是组合数学与树的交叉常考点。
- 三种序本质是**「访问根」的时机**相对于两个子树的排列；把递归展开可看出它是结构归纳的枚举。
- 遍历与编译器 IR 的关系：前序对应自顶向下变换，后序对应自底向上求值/析构。

### 📚 考研者视角
- **408 必考**：由**前序+中序**或**后序+中序**唯一确定二叉树（务必先写「由中序定位根，划分左右子树」的思路）。
- 高频：写出三种遍历序列、求树高/结点数/叶子数、**线索二叉树**（前驱后继指针的建立规则）。
- 完全二叉树编号性质：结点 i 的左右孩子为 2i、2i+1，父为 ⌊i/2⌋——选择题常用来算「第 i 个结点所在层」或「叶子数」。
- 记忆锚点：**前序定根、中序分左右**；只给前序+后序要先说明「无法唯一确定」。
