# 凯喵实战手记 · 树的遍历、判定与递归：那些「差一」和「写崩」的现场

> 凯喵说：树的题看着简单，递归三行就写完，但真正在面试和工程里翻车的，往往是「空节点没处理」「深度高度差一」「迭代写的栈顺序反了」「递归栈溢出」。这一章我们把树的现场一个个拉出来，让你写树的时候心里有底，而不是靠试。

### 现场 1：递归的前中后序只差「访问时机」

前序是「根、左、右」，中序是「左、根、右」，后序是「左、右、根」，三者的递归骨架完全一样，区别只在于把「访问根」放在两次递归的哪一侧。凯喵提醒：先把骨架写对，再挪访问位置，比背三种模板更不容易错。

```python
def inorder(node):
    if not node:
        return
    inorder(node.left)
    visit(node)          # 访问时机决定遍历序
    inorder(node.right)
```

### 现场 2：空节点是递归的终止条件，漏了必崩

递归函数开头必须处理 `node is None`，直接返回。凯喵见过太多「忘了判空，叶子节点的 children 访问报错」。空节点不是异常，而是递归的自然边界，每个递归函数的第一行就该想清楚「空了怎么办」。

### 现场 3：BFS 用队列，DFS 用栈或递归

层序遍历天然用队列，先进先出保证按层推进；深度优先用栈或递归。凯喵的现场提醒：用栈模拟 DFS 时，入栈顺序要反过来（先右后左），否则出栈顺序和你预期相反，遍历结果看着「怪怪的」但又不报错。

```python
from collections import deque
def level_order(root):
    if not root: return []
    q, res = deque([root]), []
    while q:
        res.append([n.val for n in q])
        for _ in range(len(q)):
            n = q.popleft()
            if n.left: q.append(n.left)
            if n.right: q.append(n.right)
    return res
```

### 现场 4：深度与高度差一，是边界题的重灾区

深度通常从根往下数，高度从叶子往上数，不同教材定义还不一致。凯喵：做题前先看题目怎么定义，空树高度是零还是负一，根的深度是零还是一。定义不同，答案差一，面试里因为差一被判错的人不在少数。

### 现场 5：BST 的中序遍历是有序的

二叉搜索树的中序遍历一定单调递增，这是它最重要的性质。凯喵提醒：判断一棵树是不是 BST，不能只比较父子，而要保证「左子树全部小于根、右子树全部大于根」，用上下界递归或中序校验才严谨。

```python
def is_bst(node, lo=float('-inf'), hi=float('inf')):
    if not node: return True
    if not (lo < node.val < hi): return False
    return is_bst(node.left, lo, node.val) and is_bst(node.right, node.val, hi)
```

### 现场 6：只比较父子会误判 BST

如果只看「左孩子小于父、右孩子大于父」，一棵「右子树的某个左节点比根还小」的树会被误判为合法 BST。凯喵：BST 的约束是全局的，必须带上下界递归，或者中序遍历检查单调性，局部比较是不够的。

### 现场 7：平衡树的旋转要理解「谁当新根」

AVL 或红黑树的旋转，本质是把失衡节点降一级、让较高的子树顶上。凯喵：手写旋转时先在纸上画出三个节点和四条子树指针，标清楚旋转后谁指向谁，再落代码。凭记忆写旋转，指针一乱就是段错误。

### 现场 8：递归树形 DP 要「后序」收集子树信息

树形 DP 的套路是后序遍历：先递归拿到左右子树的结果，再在当前节点合并。凯喵提醒：合并时想清楚「当前节点需要子树提供什么信息」，比如最大路径和、子树大小、是否平衡，把这些定义成返回值，递归就自然了。

```python
def max_depth(node):
    if not node: return 0
    return 1 + max(max_depth(node.left), max_depth(node.right))
```

### 现场 9：求直径要在「经过当前节点」处更新答案

树的直径不一定经过根，而是某条路径上最远的两个节点。凯喵：递归返回「以当前节点为端点的最深深度」，同时在当前节点用「左深加右深」更新全局最大直径。把「返回值」和「全局答案」分开，是树形 DP 的关键。

```python
def diameter(root):
    best = 0
    def dfs(n):
        nonlocal best
        if not n: return 0
        l, r = dfs(n.left), dfs(n.right)
        best = max(best, l + r)
        return 1 + max(l, r)
    dfs(root)
    return best
```

### 现场 10：递归深度过大导致栈溢出

退化成一條链的树，递归深度等于节点数，Python 默认递归上限约一千，直接 `RecursionError`。凯喵：深树用显式栈迭代，或者用 Morris 遍历做到常数空间。递归写得优雅，但要知道它的边界在哪。

### 现场 11：Morris 遍历用线索指针省空间

Morris 遍历利用叶子节点的空右指针临时指回祖先，遍历完再恢复，做到常数空间的中序遍历。凯喵：面试里如果被追问「不用栈和递归怎么做中序」，Morris 就是标准答案，理解它的「建线索、用线索、拆线索」三步即可。

### 现场 12：序列化与反序列化要约定空节点

把树序列化成字符串再还原，必须显式标记空节点（比如用特殊符号），否则无法唯一还原结构。凯喵：前序加空标记是最简单的方案，反序列化时按同样的顺序消费，遇到空标记就返回空。约定清楚，才能一来一回不丢结构。

```python
def serialize(node):
    if not node: return "#"
    return f"{node.val},{serialize(node.left)},{serialize(node.right)}"
```

### 现场 13：公共祖先分「二叉搜索树」与「普通二叉树」

BST 的最近公共祖先可以用值的大小关系一路往下找；普通二叉树则要后序递归，看左右子树是否各含一个目标。凯喵：别把两套逻辑混用，BST 的性质能让解法从线性降到树高，用错了就白白多写。

### 现场 14：迭代遍历的三个状态要理清

用栈做迭代中序时，需要「一路压左、弹出访问、转右」三步循环。凯喵：写迭代版最容易漏「转到右子树」这一步，导致只遍历了最左边一条链。把三个状态在注释里写清楚，比背代码可靠。

> 凯喵总结：树的坑九成在「空节点」「差一」「顺序反了」「递归深度」。把遍历骨架、BST 的全局约束、树形 DP 的返回值与全局答案分开，你写树就会从「试出来」变成「推出来」。

> 一句话收尾：树是递归的天然舞台，但优雅的前提是边界清晰——想清楚空节点、定义、返回什么，递归才不会在你没注意的地方偷偷崩掉。

### 凯喵叮嘱：先画图，再写码，最后才优化

最后叮嘱一句：树的题不要一上来就敲代码，先在纸上把三五个节点的树画出来，标清楚递归到每个节点时要返回什么、要更新什么全局量。凯喵的经验是，画图花的三分钟，能省掉后面半小时的调试。尤其是树形 DP，返回值负责「向上汇报」，全局变量负责「就地结算」，这两个角色一旦混了，答案就会时对时错。

另外，写完递归一定要用「空树、单节点、退化链」三类边界跑一遍。空树检查递归终止，单节点检查返回值与全局更新的关系，退化链检查递归深度会不会爆栈。这三类用例过了，你的树代码基本就稳了。剩下的性能优化是后话，先把正确性钉死，再谈优雅。很多人在树上追求一行写完的炫技，结果边界一错，面试官一眼看穿。稳比花哨值钱。把这三类边界用例固化成自己的检查清单，每写一个递归函数就照着过一遍，你会发现树的题从此不再靠运气。树的递归之美，在于它把复杂结构拆成同样的子问题；而它的难，也在于你必须在拆之前就想清楚边界。把每一棵子树都当成一道独立的题，答案自然浮现；把每一次递归都当成一次契约，边界自然清晰。真正的高手写树，写的是信任——信任子问题已经被正确解决，自己只负责合并。这份信任，正是递归思维最迷人的地方。

## 三视角解析
### 🧑‍💻 程序员视角
凯喵写二叉树递归时崩了三次，原因都是「忘了判空」：`if (root->left->val == x)` 在叶子结点上直接解引用空指针。第二个高频错误是把「深度」和「高度」混用——深度从根往下数（根为 1），高度从叶往上数（叶为 1），一棵只有一个结点的树两者都是 1，但递归里 `return max(l, r) + 1` 算的是高度。判 BST 只比较父子也会错：`[5,1,4,null,null,3,6]` 里 3 小于 5 但在右子树，必须传「上下界」而不是只跟父结点比。**递归函数的参数里带上「约束」而不是只带「当前结点」，是写对树题的关键。**

### 🎓 博士生视角
二叉树的递归结构使其成为「分治」的天然载体：前中后序的差别仅在「访问根」相对于两个递归调用的位置，这一观察可形式化为三种遍历对应同一递归模板的三个插入点。形态计数由 Catalan 数给出 `C(2n,n)/(n+1)`，这也是「n 个结点能构成多少棵不同二叉树」的标准答案。平衡树（AVL、红黑树）通过旋转把高度约束在 `O(log n)`，其中红黑树用「颜色不变量」替代严格的平衡因子，把插入删除的旋转次数降到常数次——这是「用更弱的约束换更少的维护成本」的经典工程取舍。

### 📚 考研者视角
408 树部分是分值最高的模块之一：
1. **遍历序列互推**：给前序 + 中序求后序（或反之），必须能画树。**只有前序 + 后序无法唯一确定二叉树**，这是必考的判断点。
2. **性质计算**：`n0 = n2 + 1`（叶子数 = 度为 2 的结点数 + 1）、完全二叉树的高度 `⌊log₂n⌋ + 1`、第 i 个结点的左右孩子为 `2i` 与 `2i+1`（从 1 开始编号）。这几个公式每年都出现。
3. **线索二叉树**：考「某结点的前驱/后继是哪一位」，要会看线索标志位 `ltag/rtag`。
4. **哈夫曼树**：给定权值构造哈夫曼树、算 WPL。步骤是每次取最小的两个合并，注意「合并后的新结点要重新参与排序」。
