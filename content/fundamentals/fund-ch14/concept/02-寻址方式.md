# 寻址方式（有效地址 EA 计算）

## 1. 背景/动机
"操作数在哪"是指令执行前必须解决的问题。如果把地址写死在指令里，程序就无法重定位、无法访问数组。于是人们设计出多种"寻址方式"，用不同的规则从指令中的形式地址 A、寄存器、PC 等算出"操作数的有效地址 EA（Effective Address）"。不同的寻址方式在灵活性、访存次数、代码长度上各有取舍。

## 2. 定义/要点
设指令形式地址为 A，寄存器 R，基址寄存器 BR，变址寄存器 IX，程序计数器 PC，内存内容用 `M[x]` 表示。常见寻址方式与 EA 公式：

| 寻址方式 | 有效地址 EA | 访存次数（取操作数） | 说明 |
|---|---|---|---|
| 立即寻址 | 操作数就在指令中，无 EA | 0 | 快，但操作数受指令长度限制 |
| 直接寻址 | EA = A | 1 | 简单，寻址范围 = `2^(地址码位数)` |
| 一次间接寻址 | EA = M[A] | 2 | 先取地址再取数 |
| 寄存器寻址 | EA = R（操作数在寄存器） | 0 | 快，不访存 |
| 寄存器间接 | EA = (R) | 1 | 寄存器存的是地址 |
| 基址寻址 | EA = (BR) + A | 1 | BR 固定、A 变，面向重定位 |
| 变址寻址 | EA = (IX) + A | 1 | IX 变、A 固定，面向数组遍历 |
| 相对寻址 | EA = (PC) + A | 1 | A 为相对位移，面向转移/浮动代码 |
| 堆栈寻址 | EA = (SP)（隐含） | 依实现 | PUSH/POP 自动更新 SP |
| 隐含寻址 | EA 由操作码隐含规定 | 依实现 | 如累加器 AC 参与 |

ASCII 示意（基址 + 变址 + 位移的复合寻址常见于 x86）：
```
        CPU 内部                主存
   ┌──────────┐
   │ BR=5000  │──┐
   └──────────┘  │   +   位移 A=200
                 ▼
              EA = 5200 ───────► [5200] = 操作数
```
**访存次数**是 408 计算题的核心：注意"取指令"本身也要访存一次，但题目通常只统计"取操作数"的访存；间接寻址每多一层间接就多一次访存。

```text
方式            有效地址 EA            取操作数的访存次数
--------------------------------------------------------
立即寻址        ——（A 就是操作数）            0
寄存器寻址      EA = R                        0（寄存器不算访存）
直接寻址        EA = A                        1
一次间接寻址    EA = M[A]                     2   ← 先取地址，再取数
寄存器间接      EA = M[R]                     1
基址寻址        EA = (BR) + A                 1
变址寻址        EA = (IX) + A                 1
相对寻址        EA = (PC) + A                 1   ← PC 已指向下一条指令
堆栈寻址        EA = (SP)，SP 自动增减         1
--------------------------------------------------------
记法：EA = Effective Address；A = 指令中的形式地址/位移
```

## 三视角解析
### 🧑‍💻 程序员视角
真实工作场景：用 Compiler Explorer（godbolt）看 `gcc -O2` 生成的 x86-64 汇编，`a[i] = b[i] + 1` 通常会编译成 `(%rdi,%rax,4)` 这样的"基址+变址+比例因子"复合寻址，一次就完成数组下标访问，比"先算地址再取数"的两条指令更高效。另一个高频踩坑是**缓冲区溢出与指令边界**：漏洞利用里构造的 payload 要精确落在某条指令的起始字节，若把上一条指令的操作数字节误当成新指令的操作码（所谓"蹦床"/错位解码），执行流就跑飞——这正是因为攻击者需要精确理解机器码的寻址/指令边界。还有 ASLR（地址空间随机化）本质就是让"绝对地址"失效，迫使代码用相对寻址/基址寻址，避免硬编码地址。

### 🎓 博士生视角
寻址方式可抽象为地址变换函数 `f: (A, Registers, PC) → EA`，不同方式对应不同的 `f`。从程序分析角度，间接/寄存器间接寻址引入了"指针别名（aliasing）"问题，使静态分析难以确定 EA 的确定值，这正是编译器优化（如循环不变代码外提）的难点。现代体系结构还把"有效地址计算"与"cache 索引"耦合（VIPT cache），EA 的对齐与低位还会影响 cache 组冲突，属于微架构层面的延伸。

### 📚 考研者视角
408 高频考点：
1. **EA 计算题**：给 A、寄存器值、位移，求各种寻址下的 EA。务必区分"EA"和"操作数的值"——间接寻址要再访存一次。
2. **访存次数**：立即/寄存器寻址 0 次；直接/寄存器间接/基址/变址/相对 1 次；一次间接 2 次。
3. **基址 vs 变址**：公式都是加法，但语义相反（基址定基地用于重定位，变址走偏移用于数组），几乎必考辨析。
4. **相对寻址的 PC**：PC 取"下一条指令"地址，转移题常考这个 +1 指令长度的细节。
