# 指令格式与扩展操作码

## 1. 背景/动机
计算机只能执行"机器指令"，而一条指令要在有限的二进制位（指令字长）里同时说清"做什么"和"对谁做"。早期机器字长短、指令种类少，用"定长操作码"最简单：操作码占固定几位，剩下全给地址码。但随着指令越加越多，固定操作码位数很快就不够表示全部指令，于是出现"变长操作码"——用操作码的扩展来换取地址码空间，这就是扩展操作码（expanding opcode）的由来。

## 2. 定义/要点
一条指令的典型格式：
```
┌───────────┬───────────┬───────────┬───────────┐
│  操作码 OP │ 地址码 A1 │ 地址码 A2 │ 地址码 A3 │
└───────────┴───────────┴───────────┴───────────┘
```
- **操作码（OP）**：规定操作性质（加、减、转移、存……），位数决定最多能表示几种操作。
- **地址码**：给出操作数或操作数地址。按地址码个数分：
  - 三地址：`(A1) OP (A2) → A3`
  - 二地址：`(A1) OP (A2) → A1`（或 A2）
  - 一地址：`OP (A1) → A1`（如累加器隐含参与）
  - 零地址：无地址码（如栈顶运算 `ADD`）

**定长操作码**：操作码位数固定（如 RISC 多用 6/7 位定长），译码简单、硬件规整，但浪费编码空间。

**扩展操作码（重点：15/15/15/16）**：在指令字长固定（例如 16 位）、每段地址码 4 位的约束下，用"保留全 1 码点向下一级让位"的方法扩展操作码长度：
```
三地址：OP 占 4 位，地址码 3×4=12 位
        操作码 0000~1110  → 15 条三地址指令（1111 保留）
二地址：OP 占 8 位 = 1111 + 4 位
        1111 0000~1111 1110 → 15 条二地址指令（1111 1111 保留）
一地址：OP 占 12 位 = 1111 1111 + 4 位
        1111 1111 0000~1111 1111 1110 → 15 条一地址指令（1111 1111 1111 保留）
零地址：OP 占 16 位 = 1111 1111 1111 + 4 位
        1111 1111 1111 0000~1111 1111 1111 1111 → 16 条零地址指令
```
合计最多表示 `15+15+15+16 = 61` 种指令。关键规律：每一级的"全 1"码点必须保留给下一级，不能算作本级可用指令。

**地址码位数与寻址空间**：定长格式下，若地址码占 n 位，则一个地址字段可寻址 `2^n` 个存储单元（按字节编址即 `2^n` 字节）。地址码位数越多，寻址范围越大，但能留给地址字段的个数/操作码位数就越少——这是"指令字长固定"下的零和博弈。

## 三视角解析
### 🧑‍💻 程序员视角
日常写 C 不直接碰操作码，但扩展操作码的思想无处不在。比如用 `gcc -O2 -S` 看汇编时，x86 是典型变长指令（操作码 1~3 字节 + ModR/M + SIB + 位移/立即数），一条 `add eax, [ebx+4]` 里"操作码+寻址模式字节"就体现了变长编码。真实工作场景：做二进制体积优化（嵌入式固件）时，编译器会优先选短操作码/短寻址形式的指令来压低代码量——这正是"编码空间有限"在逼你做取舍。另一种踩坑：手写 shellcode 时，若指令边界算错（把操作码字节误当成操作数），程序直接崩在非法指令，本质就是没理解变长操作码的边界。

### 🎓 博士生视角
可把指令集看作一个前缀码（prefix code）：各级操作码构成一棵树，保留码点相当于内部节点，叶节点才是可用指令。这样"最多能编码多少条指令"就等价于"在前缀码约束下能容纳多少叶子"。最优扩展（Huffman 思想）应按指令使用频率分配操作码长度——高频指令给短操作码。历史上，CISC 的长变长操作码本质是手工做了一版"非最优"的熵编码；而 RISC 反其道用定长操作码，把译码复杂度推给硬件流水线的规整性。形式化上，ISA 可用操作语义（operational semantics）建模，操作码即状态转移函数 `δ: State × Instruction → State`。

### 📚 考研者视角
408 高频考点：
1. **扩展操作码设计题**：已知指令字长、地址码字段位数与个数，求各地址指令最多几条；或反过来，给定各地址指令的需求条数，判断是否装得下、怎么分配保留码点。务必记住"全 1 保留"规则。
2. **地址码位数与寻址空间**：给 n 位地址码，求 `2^n`；注意按字/字节编址的区别（按字编址时还要乘字长）。
3. **零/一/二/三地址取舍**：地址字段多 → 程序短但指令长、寻址范围受限；地址字段少 → 需多用寄存器、指令条数变多。常考"为什么需要多种地址数指令"。
