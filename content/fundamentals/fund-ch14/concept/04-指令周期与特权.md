# 指令周期与特权

## 1. 背景/动机
CPU 执行一条指令不是"一步到位"，而是由若干阶段组成。理解指令周期，才能理解"为什么取指要访存""为什么中断会打断执行""为什么有些指令普通程序不能碰"。指令周期是理解 CPU 控制流、中断响应与特权级的基础。

## 2. 定义/要点
**三级时间概念（勿混）**：
- **节拍（时钟周期）**：CPU 基本时间单位，由时钟决定。
- **机器周期（总线周期）**：完成一次总线操作（如取指、读内存）所需时间，含若干节拍。
- **指令周期**：CPU 从取一条指令到执行完该指令的全过程，由若干机器周期组成。

**指令周期的四段模型**：
```
    ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
    │ 取指周期 │──►│ 间址周期 │──►│ 执行周期 │──►│ 中断周期 │
    └────────┘   └────────┘   └────────┘   └────────┘
       (IF)        (IND)        (EX)         (INT)
```
- **取指周期（IF）**：从 PC 指向的地址取指令，PC 自增。所有指令都有。
- **间址周期（IND）**：仅当指令采用间接寻址时才需要，用于取操作数地址。可省略。
- **执行周期（EX）**：真正执行操作（运算、转移、存数等）。所有指令都有。
- **中断周期（INT）**：若其间有中断请求且允许，则保护断点、转向中断服务程序。可省略。

**特权指令与特权级**：
- 机器分**用户态（目态）**与**核心态（管态）**。
- **特权指令**：只能在内核态执行的指令，如停机、开/关中断、改 PSW、置页表基址、I/O 指令等。
- 用户程序需要这些能力时，必须通过**系统调用**（如 x86 的 `int 0x80`/`syscall`、RISC-V 的 `ecall`）**陷入（trap）**内核，由 OS 代为执行——这是"指令类型"中"特权指令"与"程序控制/输入输出"的交汇点。

**对齐与边界**：指令与主存数据的访问常要求按边界对齐（字对齐到 4 字节、双字到 8 字节）。未对齐访问可能触发异常或拆成多次访存，增加机器周期数，影响指令周期时长。

```text
        ┌───────────┐
   ┌───▶│  取指周期  │  PC → MAR → 主存 → MDR → IR，PC+1
   │    └─────┬─────┘
   │          │ 需要间址？
   │    ┌─────▼─────┐  是
   │    │  间址周期  │  M[IR.addr] → MDR → IR.addr（取出真正的 EA）
   │    └─────┬─────┘
   │          │
   │    ┌─────▼─────┐
   │    │  执行周期  │  取操作数 → ALU 运算 → 写回；或访存/转移
   │    └─────┬─────┘
   │          │ 有中断请求且允许？
   │    ┌─────▼─────┐  是
   │    │  中断周期  │  关中断 → 保存断点(PC/PSW) → 引出中断服务程序
   │    └─────┬─────┘
   └──────────┘

四个周期各自对应一个"机器周期（CPU 周期）"，每个机器周期又由若干节拍（时钟周期）组成。
特权指令（如 cli / hlt / mov cr3,eax）只能在核心态执行 —— 用户态执行会触发 #GP 异常，
由内核接管；而"陷入指令"（syscall / int 0x80）是唯一允许用户态主动进入内核的入口。
```

## 三视角解析
### 🧑‍💻 程序员视角
真实工作场景：排查"偶发卡顿"时，性能工具（perf）会显示大量 `cycles` 花在**未对齐访问**或**缺页（相当于额外机器周期）**上；把热点结构体改成 `#pragma pack` 反而不对齐、变慢就是反面教材。另一个真实踩坑：在用户态里误调用了需要特权的操作（比如某些嵌入式裸机代码直接写控制寄存器），结果在 Linux 上收到 `SIGILL`（非法指令）而崩溃——这正是"特权指令不能在用户态执行"的硬约束，正确做法是用系统调用或在内核模块/驱动里执行。调试时 gdb 单步（`si`）本质上就是让 CPU 一条条走完各自的指令周期。

### 🎓 博士生视角
指令周期的微观实现由"控制单元（CU）"通过硬布线或微程序产生时序信号驱动。可把每条指令的执行建模为状态机：状态 = 各周期，转移条件 = 寻址方式标志、中断请求线。现代超标量 CPU 把"指令周期"进一步拆成取指/译码/重命名/发射/执行/写回等多级流水线，单条"指令周期"概念退化为吞吐意义上的 CPI。特权级则对应硬件中的模式位（如 x86 的 CPL、RISC-V 的 `priv` 字段），系统调用通过"异常/陷阱"机制切换模式并切换页表与栈，这是隔离安全的基石。

### 📚 考研者视角
408 高频考点：
1. **指令周期四阶段**：取指、间址、执行、中断各干什么；哪些必有、哪些可省（间址仅间接寻址需要，中断仅在响应中断时需要）。
2. **三级时间单位**：节拍、机器周期、指令周期的包含关系，选择题常考谁包含谁。
3. **特权指令**：哪些是指令（停机、改 PSW、开关中断、I/O 等），为什么用户态不能执行，系统调用如何陷入内核。常与操作系统"用户态/核心态"联合出题。
4. **对齐**：未对齐访问的代价（异常或多次访存）可能作为综合题的一个小问。
