# 指令系统实战手记：凯喵的十二道编码与寻址计算题复盘

> 这一篇来自凯喵带新人刷 408 指令系统题的经历。这一章的题非常「数学」：给定指令字长和地址码字段，反向推操作码能编多少条；给定一条汇编，算有效地址和访存次数。做错的原因往往不是公式不会，而是**漏了一种情况**或者**把一次访存看成两次**。十二道题的复盘，按「格式 → 寻址 → CISC/RISC → 周期」的顺序展开。

## 开场：那道扩展操作码的题，我漏了「全 1」不能被占用

题目：指令字长 16 位，地址码 4 位，要求 15 条三地址指令、15 条二地址指令、15 条一地址指令、16 条零地址指令。凯喵第一次算的时候，把三地址的操作码直接用掉 4 位里的 15 个，留下 1 个作为扩展标志，然后顺利算出二地址……结果最后零地址的条数对不上。

问题在于：**扩展操作码的核心是「用留出的编码空间去扩展下一级」**，而每级的「全 1」编码必须留给下一级做扩展标志，不能被本级占用。

正确的推法是：

```text
三地址：操作码 4 位，可用 2^4 = 16 个编码
       用 15 个，留 1 个（1111）做扩展标志
二地址：扩展 4 位（地址码1的位置），共 1 × 2^4 = 16 个编码
       用 15 个，留 1 个做扩展标志
一地址：再扩展 4 位（地址码2的位置），共 1 × 2^4 = 16 个
       用 15 个，留 1 个
零地址：再扩展 4 位（地址码3的位置），共 1 × 2^4 = 16 个
       正好用 16 个，不需要再留
```

凯喵的记法：**每一级「用 n 个，留 1 个」，最后一级可以全部用完**。而且每一级可用的编码数 = 上一级留出的标志数 × 2^（本级扩展的位数）。

### 现场一：地址码个数与寻址范围是反比

指令字长固定时，地址码越多，每个地址码的位数越少，可寻址范围越小。这是最基础的一条取舍，但题目经常绕着问。

```text
16 位指令字长：
三地址（操作码 4 位）：每个地址码 (16-4)/3 = 4 位 → 寻址 16 个单元
二地址（操作码 4 位）：每个地址码 (16-4)/2 = 6 位 → 寻址 64 个单元
一地址（操作码 4 位）：地址码 12 位 → 寻址 4096 个单元
零地址：无地址码
```

凯喵提醒一个容易忽略的点：**操作码长度本身也会变**。如果题目说「操作码固定 8 位」，那三地址的地址码就是 `(16-8)/3`，除不尽说明这个方案不成立。这类题目有时候是故意给一个不成立的方案，考你会不会发现。

### 现场二：立即寻址的「访存次数」是 0

十种寻址方式里，立即寻址最特殊：操作数就在指令里，**不需要访存**。很多人习惯性地把所有寻址方式的访存次数都算成 1 次或 2 次，把立即寻址也算错。

正确的访存次数表：

```text
立即寻址：    0 次（操作数在指令中）
寄存器寻址：  0 次（操作数在寄存器中）
直接寻址：    1 次（地址在指令中，访存取操作数）
一次间接：    2 次（先取地址，再取操作数）
寄存器间接：  1 次（地址在寄存器中，访存取操作数）
基址/变址：   1 次（EA = 基址/变址 + 偏移，再访存）
相对寻址：    1 次（EA = PC + 偏移，再访存）
堆栈寻址：    1 次（EA = SP，访存取操作数）
隐含寻址：    0 次或按隐含规则
```

凯喵的口诀：**「数在指令里」和「数在寄存器里」都不用访存，只要地址需要到内存里去拿，就是一次，地址的地址就是两次**。

### 现场三：间接寻址的「几次访存」要看间接了几层

一次间接是 2 次访存（取地址 + 取操作数），二次间接就是 3 次。题目如果说「多级间接」，就要按层数加。

而且要注意区分「指令中给出的地址」和「有效地址 EA」：

```text
直接寻址：    EA = A                   访存 1 次（取 M[A]）
一次间接：    EA = M[A]                访存 2 次（先取 M[A]，再取 M[M[A]]）
寄存器间接：  EA = (R)                 访存 1 次
```

凯喵见过一道题把「一次间接」的 EA 写成 A，然后访存次数算成 1，两个都错。**EA 是「操作数所在的地址」，间接寻址时 EA 需要先去内存里读一次才能得到**。

### 现场四：基址与变址的区别在「谁变」

基址寻址：`EA = 基址寄存器 + 偏移量`，基址由操作系统设定，程序运行中不变，偏移量在指令中。用途是**程序重定位**——整个程序装载到内存任意位置，基址一变，所有地址自动跟着变。

变址寻址：`EA = 变址寄存器 + 偏移量`，变址寄存器的内容在程序运行中可变，偏移量（形式地址）在指令中。用途是**数组遍历**——偏移量指向数组首地址，变址寄存器做循环变量。

```text
基址：EA = (BR) + A    BR 不变，A 变（不同变量）
变址：EA = (IX) + A    IX 变，A 不变（同一数组的不同元素）
```

凯喵的记法：**基址是「整体搬家」，变址是「逐个访问」**。两者公式长得一样，区别全在「哪个量在循环里变化」，这也决定了它们的典型用途。

### 现场五：相对寻址的 EA 基准是「下一条指令」

`EA = PC + 偏移量`，但这里的 PC 指的是**取完当前指令后的 PC**，也就是下一条指令的地址，不是当前指令的地址。

这个细节每年都有人错。原因是对「PC 在取指后自动加一」这个机制不熟。

```text
设当前指令地址为 1000，指令长 4 字节
取指后 PC = 1004
若偏移量为 -8，则 EA = 1004 - 8 = 996
```

凯喵的建议是：**凡是相对寻址的题，先明确写出「取指后 PC 的值」**，再套公式。这一步写出来，就不会错了。

### 现场六：寻址方式影响的是「指令长度」还是「执行时间」

题目常问「采用某种寻址方式有什么好处」。答案要分两个维度看：

影响指令长度：立即寻址（操作数在指令里，指令变长）、直接寻址（地址在指令里，指令较长）。寄存器寻址（只需寄存器号，指令短）。

影响执行时间：间接寻址要多访存，慢；寄存器寻址最快；立即寻址也快（不访存）。

```text
快 ← 寄存器寻址 ≈ 立即寻址 < 直接/基址/变址 < 间接寻址 → 慢
长 ← 寄存器寻址 < 直接寻址 < 立即寻址（操作数可能很长）→ 短
```

凯喵提醒：这两条曲线方向不同，所以「选哪种寻址方式」永远是权衡。寄存器寻址又快又短，但寄存器数量有限；立即寻址快但指令长；间接寻址灵活但慢。

### 现场七：CISC 与 RISC 的差异不是「指令多少」

最常见的简化说法是「CISC 指令多、RISC 指令少」。这个说法不算错，但没抓到本质。真正的差异在**设计哲学**：

CISC 追求「一条指令做一件事，但要做得复杂」——支持复杂寻址、变长指令、内存到内存的操作。好处是程序短、编译器简单；坏处是硬件复杂、难以流水线化。

RISC 追求「指令简单规整、只做 load/store 访存」——定长指令、寻址方式少、寄存器多。好处是容易流水线、容易提高主频；坏处是程序变长、对编译器要求高。

```text
CISC（x86）：变长指令（1-15 字节）、多种寻址、内存操作数
RISC（MIPS/RISC-V）：定长 4 字节、只有 load/store 访存、三地址格式
```

凯喵的理解是：**RISC 的「简单」是为了让流水线好做**。定长指令让取指和译码可以并行，规整格式让各级耗时均衡，load/store 分离让访存只在一个阶段发生。这些设计全部服务于「让流水线满负荷」。

### 现场八：指令周期四段模型，间址段可能不存在

指令周期的四段是：取指（IF）、间址（IND）、执行（EX）、中断（INT）。但**间址段只在采用间接寻址时才存在**，中断段只在有中断请求且允许响应时才存在。

```text
取指：PC → MAR → 内存 → MDR → IR，PC + 1
间址：根据寻址方式计算 EA（只有间接寻址需要访存取地址）
执行：按操作码执行，可能访存
中断：保存断点，转中断服务程序
```

凯喵见过题目问「采用直接寻址的指令，指令周期包含哪几段」，正确答案是「取指 + 执行（+ 中断）」，不包含间址段。这个点很细，但确实是考点。

### 现场九：指令对齐影响访存次数

如果一个 32 位字需要跨两个存储字存放（未对齐），那么取这个字需要两次访存。所以编译器会把指令和数据按边界对齐，避免跨边界。

```text
对齐（地址 4 的倍数）：   [------- 一个字 -------]  → 1 次访存
未对齐（地址 4n+2）：     [--前半--][--后半--]      → 2 次访存
```

这条对性能的影响很实际：数据结构的字段顺序会影响内存占用和访存效率。凯喵在 C 语言里就踩过：一个 `struct { char a; int b; }` 因为对齐填充变成 8 字节而不是 5 字节，顺序调换后仍是 8 字节，但意义不同。

### 现场十：零地址指令不等于「没有操作数」

零地址指令常见于堆栈计算机：操作数隐含在栈顶。所以「零地址」说的是「指令里不写地址」，不是「这条指令不需要数据」。

```text
PUSH A     ; 一地址，把 A 压栈
PUSH B     ; 一地址
ADD        ; 零地址，弹出栈顶两个数相加，结果压栈
```

凯喵见过把零地址指令理解成「空操作」的错误。零地址指令在栈式虚拟机里是主力，JVM 字节码和很多解释器都是这种设计——因为栈式指令短、编译器好写。

### 现场十一：特权指令与「谁在执行」

特权指令（如修改页表基址、关中断、I/O 指令）只能在核心态执行。用户态执行特权指令会触发异常，陷入核心态，由操作系统处理。

```text
用户态可执行：普通算术、访存、跳转、系统调用（陷入指令）
仅核心态：    修改控制寄存器、I/O 指令、清空 TLB、设置中断屏蔽
```

这道题常和「中断与异常的区别」一起考。凯喵的记法：**中断是「外部来的」，异常是「指令执行引起的」**。缺页是异常，时钟中断是中断，系统调用是异常（陷入）。

### 现场十二：指令系统的兼容性是设计的隐形约束

x86 从 1978 年到现在还在用，靠的是「向后兼容」——新处理器必须能跑老程序。这个约束极大地限制了架构演进：不能改指令编码，只能在前面加前缀、在后面加扩展。

RISC-V 之所以能设计得干净，是因为它没有历史包袱。但代价是要重建整个软件生态。

凯喵的体会：**指令系统不只是一组技术选择，还是一份长期承诺**。一旦发布，就要考虑几十年后的兼容性。这解释了为什么 x86 上有很多「看起来设计得很怪」的指令——它们是历史妥协的产物，而不是设计者的失误。

## 收尾：编码题靠推，寻址题靠表

凯喵最后总结：指令系统这一章，题目分成两类，解法完全不同。

**编码类题目**（扩展操作码、地址码位数）靠推导：从「每级留一个扩展标志」这条规则出发，一级一级往下算，不背公式。算完再用「总编码数是否够用」验算一遍。

**寻址类题目**（EA、访存次数）靠表格：把十种寻址方式的 EA 公式和访存次数列成一张表，遇到题就查表，别凭记忆。表里最容易错的是「立即/寄存器是 0 次」和「相对寻址的 PC 是下一条」。

至于 CISC 与 RISC 的对比、指令周期的四段模型，这些偏概念的题，关键在于理解「为什么这么设计」——理解了取舍，选项就很好排除；只背结论，换个说法就会犹豫。

指令系统是软硬件的交界：往上它是编译器的目标，往下它是硬件的输入。站在这个位置上看，很多设计选择就变得合理了。
