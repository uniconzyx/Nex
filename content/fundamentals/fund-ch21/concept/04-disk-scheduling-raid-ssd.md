# 磁盘访问时间、调度算法与 RAID/SSD

## 1. 背景/动机

一个反直觉的实测：7200rpm 机械盘读 4KB，**传输只占 1.4% 的时间**，剩下 98.6% 全花在"把磁头挪到正确的位置"上。

这解释了磁盘子系统几乎所有工程决策：
- 为什么**顺序读写比随机快两个数量级**（相邻数据不用重新寻道）；
- 为什么数据库要**写 redo 日志而不是直接改数据页**（把随机写变成顺序写）；
- 为什么 **SSD 能碾压 HDD**（没有寻道和旋转，随机访问延迟从 12ms 降到 0.1ms）。

## 2. 定义/要点

**磁盘访问时间三要素**：

$$T_{\text{access}} = \underbrace{T_{\text{seek}}}_{\text{寻道}} + \underbrace{T_{\text{rotation}}}_{\text{旋转延迟}} + \underbrace{T_{\text{transfer}}}_{\text{传输}}$$

| 分量 | 含义 | 典型值（7200rpm SATA） | 优化手段 |
|---|---|---|---|
| 寻道时间 $T_s$ | 磁头移动到目标磁道 | 8~10ms | **减少寻道次数**（顺序化、调度、预读） |
| 旋转延迟 $T_r$ | 等目标扇区转到磁头下 | **平均半圈** = 4.17ms | 交错编号、柱面优先 |
| 传输时间 $T_t$ | 读/写数据本身 | 4KB → 0.17ms | 提高传输率（几乎无用） |

### 为什么平均旋转延迟是半圈

**为什么平均旋转延迟是半圈**：目标扇区相对磁头的初始角位置在 $[0, 1\text{圈})$ 上均匀分布，等待时间 = 剩余角度比例，均值 = 半圈。$T_r = \frac{1}{2}\cdot\frac{60}{\text{RPM}}$ 秒。7200rpm → 一圈 8.33ms → 平均 4.17ms。

### 五种调度算法的寻道距离对比

**磁盘调度算法**（设请求 98, 183, 37, 122, 14, 124, 65, 67，初始磁头 53，磁道 0~199）：

| 算法 | 思想 | 总寻道距离 | 优点 | 缺点 |
|---|---|---|---|---|
| **FCFS** | 按到达顺序 | 640 | 公平、简单 | 慢 |
| **SSTF** | 每次选最近的 | 236 | 平均最短 | **饥饿**（远端请求饿死） |
| **SCAN**（电梯） | 单向扫到头再反向 | 331 | 延迟可预测、无饥饿 | 来回扫，中间磁道占便宜 |
| **C-SCAN** | 单向扫到头，空返 | 382（含 199 磁道空返；若只算"服务请求"的移动则为 183） | **各磁道延迟最均匀** | 空返这一段白跑 |
| LOOK / C-LOOK | 到最后一个请求就反向 | 更优 | 不空跑 | 实现稍复杂 |

```text
SCAN（向大方向，初始 53，上界 199）
53 ──▶ 65 ──▶ 67 ──▶ 98 ──▶ 122 ──▶ 124 ──▶ 183 ──▶ 199(到头) ──▶ 37 ──▶ 14
        去程服务全部较大请求                          到头折返，服务较小请求

C-SCAN（同上，但返程不服务）
53 ──▶ ... ──▶ 183 ──▶ 199 ──(空返)──▶ 0 ──▶ 14 ──▶ 37
                                回程不服务，保证每个磁道的等待上界一致
```

**RAID 级别对比**（n 块盘，单盘容量 C）：

| 级别 | 可用容量 | 容错 | 随机写代价 | 典型用途 |
|---|---|---|---|---|
| RAID 0 | $nC$ | 0 | 1× | 临时数据、缓存 |
| RAID 1 | $nC/2$ | 每组 1 块 | 2× | 系统盘、小容量高可靠 |
| RAID 5 | $(n-1)C$ | 1 块 | **4×**（读旧数据+读旧校验+写新+写新校验） | 读密集、归档 |
| RAID 6 | $(n-2)C$ | 2 块 | 6× | 大容量归档 |
| RAID 10 | $nC/2$ | 每组 1 块 | 2× | **数据库、日志盘** |

**SSD 的关键指标**：

- **WAF（写放大）** = 实际写入闪存的数据量 / 主机请求写入量。随机小写会触发 FTL 异地更新 + GC 搬移，WAF 可达 3+。
- **GC（垃圾回收）**：擦除单位是 block（MB 级），写单位是 page（4KB 级）→ 必须整块擦除再重写，产生额外搬移。
- **TRIM**：文件系统告诉 SSD"这些页没用了"，GC 才不会白搬垃圾。
- **OP（over-provisioning）**：预留空间（7%~28%），降低 WAF、提升寿命。
- **TBW**：总写入字节数上限，寿命 ≈ TBW / (日写入量 × WAF)。

## 3. 可运行代码（C，含中文注释 + 真实输出）

### 3.1 验证"平均旋转延迟 = 半圈"

```c
#include <stdio.h>
/* c03：为什么「平均旋转延迟」是半圈
 * 磁头停在哪、目标扇区转到哪，都是随机的；
 * 目标扇区相对磁头的角位置在 [0, 一圈) 上均匀分布，
 * 所以平均要等半圈。这条结论每年都考，但很多人答成「一圈」。*/
int main(void) {
    int ticks = 360;             /* 把一圈分成 360 份 */
    long sum = 0, cnt = 0;
    /* 固定遍历：让磁头起始位置在 0..359 轮一遍，目标扇区固定在 0 */
    for (int head = 0; head < ticks; head++) {
        int wait = (ticks - head) % ticks;   /* 从 head 转到 0 需要的份数 */
        sum += wait;
        cnt++;
    }
    double avg = (double)sum / cnt;
    printf("一圈=%d 份（假设 1 份 = 1 个时间单位）\n", ticks);
    printf("磁头起始位置遍历一圈，等目标扇区(0 号)转过来的平均等待 = %.1f 份\n", avg);
    printf("理论值 = 一圈/2 = %.1f 份 -> 相对误差 %.2f%%\n", ticks / 2.0,
           100.0 * (avg - ticks / 2.0) / (ticks / 2.0));
    printf("\n结论：平均旋转延迟 = 半圈时间 = (1/2)*(60/RPM) 秒。\n");
    printf("      7200rpm -> 一圈 8.33ms -> 平均旋转延迟 4.17ms。\n");
    printf("      这也解释了为什么「顺序读大文件」快：同磁道相邻扇区几乎不用等旋转。\n");
    return 0;
}
```

真实输出：

```text
一圈=360 份（假设 1 份 = 1 个时间单位）
磁头起始位置遍历一圈，等目标扇区(0 号)转过来的平均等待 = 179.5 份
理论值 = 一圈/2 = 180.0 份 -> 相对误差 -0.28%

结论：平均旋转延迟 = 半圈时间 = (1/2)*(60/RPM) 秒。
      7200rpm -> 一圈 8.33ms -> 平均旋转延迟 4.17ms。
      这也解释了为什么「顺序读大文件」快：同磁道相邻扇区几乎不用等旋转。
```

相对误差 -0.28% 不是 bug：离散化到 360 份时，`head=0` 那一份的等待是 0 而不是 360，所以均值比 180 少了 $180/360 = 0.5$ 份。

### 3.2 RAID 5 的写惩罚账本

```c
#include <stdio.h>
/* c04：RAID 5 的「写惩罚」为什么是 4 次 I/O
 * 小块随机写时，RAID 5 需要：
 *   ① 读旧数据  ② 读旧校验  ③ 写新数据  ④ 写新校验（读-改-写）
 * 而 RAID 10 只需 2 次写（两个副本），RAID 0 只需 1 次。*/
int main(void) {
    int disk_iops = 200;        /* 单盘随机写 IOPS */
    int n = 6;
    int cost0 = 1, cost1 = 2, cost5 = 4, cost10 = 2;
    double iops0 = (double)disk_iops * n / cost0;
    double iops5 = (double)disk_iops * (n - 1) / cost5;
    double iops10 = (double)disk_iops * (n / 2) / cost10;

    printf("%d 块盘，单盘随机写 %d IOPS\n", n, disk_iops);
    printf("--------------------------------------------------\n");
    printf("%-12s %-18s %-14s %s\n", "级别", "每逻辑写物理I/O", "可用写IOPS", "说明");
    printf("%-12s %-18d %-14.0f %s\n", "RAID 0", cost0, iops0, "无冗余，最快");
    printf("%-12s %-18d %-14.0f %s\n", "RAID 5", cost5, iops5, "读-改-写，写惩罚 4x");
    printf("%-12s %-18d %-14.0f %s\n", "RAID 10", cost10, iops10, "两副本，无校验计算");
    printf("--------------------------------------------------\n");
    printf("RAID 10 的随机写能力是 RAID 5 的 %.1f 倍\n", iops10 / iops5);
    printf("\n但顺序写/读时 RAID 5 更划算（容量利用率高、无镜像开销）。\n");
    printf("所以：数据库 redo 日志盘用 RAID 10，归档/备份盘用 RAID 5/6。\n");
    return 0;
}
```

真实输出：

```text
6 块盘，单盘随机写 200 IOPS
--------------------------------------------------
级别       每逻辑写物理I/O 可用写IOPS  说明
RAID 0       1                  1200           无冗余，最快
RAID 5       4                  250            读-改-写，写惩罚 4x
RAID 10      2                  300            两副本，无校验计算
--------------------------------------------------
RAID 10 的随机写能力是 RAID 5 的 1.2 倍

但顺序写/读时 RAID 5 更划算（容量利用率高、无镜像开销）。
所以：数据库 redo 日志盘用 RAID 10，归档/备份盘用 RAID 5/6。
```

注意 1.2 倍这个数字并不夸张——**RAID 5 的 6 块盘里有 5 块能并行写，把 4 倍写惩罚抵消掉了大半**。所以"RAID 5 写慢"要分场景：**小块随机写慢 4 倍，大块顺序写几乎不受影响**（整条带写时校验可一次算出，不需要读旧数据）。

### 3.3 调度算法实测（本章 examples）

同一请求序列下四种算法的总寻道距离实测（初始 53，0~199）：

```text
算法     总寻道距离(磁道)
----------------------------
FCFS       640
SSTF       236
SCAN       331
C-SCAN     382  (含 199 磁道空返)

口径对照：C-SCAN 若只算服务行程（146 上扫 + 37 下扫）= 183；
          按磁头真实移动（含空返 199）= 382。做题先看题干用哪种口径。
```

FCFS 最差（640），SSTF 平均寻道最短（236）但会饥饿；SCAN 331 已经不错，C-SCAN **总路程反而更长（382）**——多出来的正是 199 磁道那段"空返"（从 199 跑回 0，谁也不服务）。

那为什么还要 C-SCAN？因为它把"来回扫"换成"单向扫 + 空返"后，**每条磁道等待时间的上界一致**：SCAN 刚被扫过的磁道要等整整一个来回，C-SCAN 最多等一个单向行程。这是「平均寻道最短 ≠ 体验最好」的活例子——SSTF 平均最优却可能饿死远端请求，C-SCAN 平均更差但延迟可预测。

> 口径提醒：不少教材/题目算 C-SCAN 时**只累加"服务请求"的移动量**（本例 183），把空返排除在外；也有教材按磁头真实移动算（本例 382）。做题时先看题干怎么定义，别把两种口径混在一张表里比——**这才是最容易扣分的地方**。

## 三视角解析

### 🧑‍💻 程序员视角

**真实工作场景**：MySQL 主库，6 块 SSD 做 RAID 5，业务写 QPS 一上去 `iowait` 就 40%，`iostat` 显示 `w/s` 很高但 `wkB/s` 很低（写请求多、每次都很小）。

诊断：`innodb_flush_log_at_trx_commit=1` 每事务都 `fsync` redo → 每次都是**小块随机写** → RAID 5 的读-改-写把每次逻辑写放大成 4 次物理 I/O。SSD 虽然没寻道，但 4 倍 I/O 依然吃满 IOPS 预算。

改法（按收益排序）：
1. **把 redo 日志单独放到 RAID 10**（或 NVMe 直连）—— 立刻把写放大从 4× 降到 2×；
2. `innodb_flush_log_at_trx_commit=2`（组提交 + 每秒刷盘），把 N 次小写并成 1 次 —— 对应本章"增大介入粒度"；
3. 关闭 `innodb_doublewrite`（在可靠存储上）—— 减少一次写。

三步后 `iowait` 降到 5%。

另一个现场案例：**"SSD 掉速"**。某日志服务跑半年后写吞吐从 2GB/s 掉到 300MB/s。`smartctl -a` 看 `Percentage Used` 已到 80%，`WAF` 高达 4.2（顺序写却按 4KB 随机落盘）。根因是文件系统碎片化 + 未开 TRIM，GC 疯狂搬移。**换盘 + 开 `discard`/`fstrim.timer` 后恢复。**

### 🎓 博士生视角

磁盘调度在 1990 年代是 OS 教材的重头戏，但今天**OS 层的调度基本消失了**。原因有三：

1. **硬件内置重排**：现代 HDD 固件有 TCQ/NCQ（最多 32 个未完成命令），盘自己知道物理几何，比 OS 更清楚该怎么排。你给 OS 的"最优顺序"，盘可能重新排过。
2. **抽象失效**：LBA（逻辑块地址）与物理扇区之间隔着 FTL/映射层，OS 眼里的"相邻 LBA"在物理上可能相距很远。**在 SSD 上"顺序 vs 随机"甚至不再有物理意义**（但仍有 FTL 层面的意义）。
3. **队列深度爆炸**：NVMe 支持 64K 队列 × 64K 深度，调度问题从"排序"变成"**多队列负载均衡**"——Linux 的 blk-mq 把请求按 CPU 分到不同软件队列，硬件队列由设备自己消费，`mq-deadline` 只在每个队列内部做 deadline + FIFO 双队列的简单排序。

所以本章的调度算法，**考试价值 > 工程价值**。但它们的**思想**没有消失：`mq-deadline` 的"deadline 队列防饥饿 + FIFO 队列保吞吐"正是 SSTF（贪心）+ 老化（aging）的组合；Kafka 的日志段顺序追加、LSM-tree 的 compaction 排序，都是"把随机变顺序"这条原理的现代变体。

SSD 带来的是**新的权衡维度**：擦除块（MB 级）远大于写页（4KB），导致"异地更新 + GC"的写放大。这与文件系统的**写时复制（COW，如 Btrfs/ZFS）**在哲学上完全一致——都是用"不原地改"换"崩溃一致性 + 磨损均衡"。代价都是**空间放大**：一份数据要占两份空间，直到 GC 回收。

形式化看，SSD 稳态下（盘满、无空闲块）的 WAF 近似为：

$$\text{WAF}_{\text{steady}} = \frac{1}{1 - u}$$

其中 $u$ 是空间利用率。这条公式解释了为什么**留 20% OP 不是浪费**：$u=0.8$ 时 WAF=5，$u=0.5$ 时 WAF=2。**买盘时多花的钱，等于买寿命。**

### 📚 考研者视角

**408 高频考点**：

1. **磁盘访问时间计算**（几乎年年考）：$T = T_s + \frac{1}{2}\cdot\frac{60}{r} + \frac{b}{rN}$，其中 $r$ 是转速（转/分），$b$ 是字节数，$N$ 是每磁道字节数。**单位换算**是最常见的失分点：rpm → 转/秒 要除以 60。
2. **调度算法总寻道距离**（手算题）：给请求序列和初始磁头，算 FCFS/SSTF/SCAN/C-SCAN 的总移动距离。**SCAN 一定要注意初始方向**，方向不同结果不同；C-SCAN 到端点后要**空返到另一端**（这段距离通常不计入"服务请求"的寻道距离，但有些题会计，看题干）。
3. **SSTF 的饥饿**：简答题标准答案——"SSTF 优先服务距离最近的请求，若新请求持续出现在磁头附近，远端请求将被无限推迟"。
4. **RAID 5 的写惩罚**：4 次 I/O（读旧数据、读旧校验、写新数据、写新校验）。RAID 6 是 6 次。
5. **RAID 5 的容量**：$(n-1)C$，**校验盘不是固定的**（分布在所有盘上），这点常被误答成"有一块专用校验盘"。
6. **提高磁盘 I/O 速度的方法**（简答）：① 磁盘调度（减少寻道）；② 交错编号/柱面优先（减少旋转延迟）；③ 提前读/延迟写/优化物理块分布（减少传输与寻道）；④ 加缓冲/盘缓存；⑤ 用 SSD/RAID。

**易错点**：
- 把平均旋转延迟算成**一圈**（应该是半圈）；
- 认为 RAID 5 坏了任意一块就只丢数据（错，RAID 5 能**重建**，只有同时坏两块才丢）；
- 认为"磁盘调度能减少传输时间"（错，它只影响**寻道**）。
