# 四种 I/O 控制方式：从"CPU 死等"到"CPU 只发命令"

## 1. 背景/动机

一台机器上，CPU 每秒能执行几十亿条指令，而一块机械盘完成一次随机读写要 10 毫秒——**两者差了七个数量级**。如果 CPU 亲自盯着设备搬数据，99.99% 的算力就浪费在"等"上了。

于是 I/O 控制方式的历史，本质就是**"如何把 CPU 从搬数据这件事里解放出来"**的历史，一共四步：

1. **程序查询**：CPU 亲自问、亲自搬（全程占用）
2. **程序中断**：CPU 只管搬，设备好了再叫它（省掉等待）
3. **DMA**：CPU 只下命令，搬运由 DMA 控制器干（省掉搬运）
4. **通道**：CPU 只发一条 I/O 指令，通道程序自己调度多台设备（省掉调度）

## 2. 定义/要点

```text
① 程序查询（轮询）
   CPU: [查状态][查状态][查状态] ... [读数据][查状态][查状态] ... 
         └────────── 传输 2048ms 期间 CPU 全程被钉住 ──────────┘

② 程序中断
   CPU: [启动设备] → 去干别的 → 中断! [传1字] → 去干别的 → 中断! [传1字] ...
        每传 1 字被打扰一次，等待时间被回收，但"搬"还是 CPU 搬

③ DMA
   CPU: [设源/目的/长度][启动] → 去干别的 → 中断! [整块已完成]
        搬运由 DMA 控制器直接读写内存（不经过 CPU 寄存器）

④ 通道
   CPU: [发一条 I/O 指令，给一个通道程序] → 去干别的 → 中断! [通道程序执行完]
        通道本身是一台小处理器，能执行通道程序、同时管多台设备
```

| 方式 | 数据搬运者 | CPU 介入粒度 | 传输期间 CPU 能并行 | 适用 |
|---|---|---|---|---|
| 程序查询 | CPU | 每字节/每字 | **不能**（忙等 100%） | 极慢设备、嵌入式小系统 |
| 程序中断 | CPU | 每字节/每字（每次中断） | 能 | 低速字符设备（键盘、串口） |
| DMA | DMA 控制器 | **每块**（一次） | 能 | 块设备（磁盘、网卡） |
| 通道 | 通道处理器 | **每条 I/O 指令** | 能（还能同时管多设备） | 大型机、现代 DPU/SmartNIC |

三个必须记住的细节：

- **中断方式省的是"等待时间"，不是"处理时间"**。传 1MB 用 16 位设备就是 52 万次中断，每次进出内核上千纳秒，累计 CPU 时间反而可能比 DMA 多。
- **DMA 不是"完全不经过 CPU"**：初始化（地址、长度、方向、启动）和结束中断处理仍要 CPU，只是**数据搬运**绕开了 CPU 寄存器。
- **通道 = 早期 I/O 处理器**，和今天的 DPU / SmartNIC / RDMA 是同一思路：把 I/O 协议栈下移到专用硬件。

## 3. 可运行代码（C，含中文注释 + 真实输出）

```c
#include <stdio.h>
/* c01：I/O 控制方式演进——CPU 参与度一路下降
 * 用「每传 1MB 数据 CPU 被打扰多少次」衡量。
 *   程序查询：每字节 1 次 -> 1048576 次
 *   中断驱动：每 2 字节 1 次 -> 524288 次
 *   DMA：每 4KB 一次 -> 256 次
 *   通道：每次 I/O 命令一次 -> 1 次
 * 这张指数级下降的表，就是「I/O 效率」的整部历史。*/
int main(void) {
    long bytes = 1024L * 1024;
    long q = bytes;
    long i = bytes / 2;
    long dma = bytes / 4096;
    long ch = 1;

    printf("传输 %ld 字节（1MB）时 CPU 被介入的次数\n", bytes);
    printf("------------------------------------------------\n");
    printf("%-12s %-14s %s\n", "方式", "介入次数", "相对程序查询");
    printf("%-12s %-14ld %.6f\n", "程序查询", q, 1.0);
    printf("%-12s %-14ld %.6f\n", "中断驱动", i, (double)i / q);
    printf("%-12s %-14ld %.6f\n", "DMA", dma, (double)dma / q);
    printf("%-12s %-14ld %.8f\n", "通道", ch, (double)ch / q);
    printf("------------------------------------------------\n");
    printf("DMA 相对程序查询减少 %.2f%% 的介入次数\n", 100.0 * (q - dma) / q);
    printf("\n注意：通道的「1 次」是指 CPU 只发一条 I/O 命令；真正的块搬运由通道程序完成，\n");
    printf("      而且一个通道能同时管多台设备 —— 这是大型机时代的「I/O 处理器」。\n");
    return 0;
}
```

真实输出（`gcc -std=c11 -O2` 编译运行）：

```text
传输 1048576 字节（1MB）时 CPU 被介入的次数
------------------------------------------------
方式       介入次数   相对程序查询
程序查询 1048576        1.000000
中断驱动 524288         0.500000
DMA          256            0.000244
通道       1              0.00000095
------------------------------------------------
DMA 相对程序查询减少 99.98% 的介入次数

注意：通道的「1 次」是指 CPU 只发一条 I/O 命令；真正的块搬运由通道程序完成，
      而且一个通道能同时管多台设备 —— 这是大型机时代的「I/O 处理器」。
```

读这张表的正确姿势：**每一行都代表"把某一层职责从 CPU 手里拿走"**。中断拿走了"等待"，DMA 拿走了"搬运"，通道拿走了"调度"。408 的答题口径也正是这三句话。

## 三视角解析

### 🧑‍💻 程序员视角

**真实工作场景**：某图片处理服务把用户上传的 20MB 图片写到 NFS，`write()` 很快返回，但 p99 延迟始终 800ms 下不来。`iostat -x` 看到 `await`（平均 I/O 等待）高达 60ms、`aqu-sz`（队列深度）持续 > 32，而 `%util` 只有 40%。

这三个数字一起读就明白了：**%util 不高说明设备没被打满，await 高 + 队列深说明请求在排队**——瓶颈不是磁盘带宽，而是"请求太碎"。20MB 分成 64KB 的小块随机写，每次都触发一次寻道 + 一次旋转等待（≈12ms），20MB/64KB = 320 次 → 320 × 12ms ≈ 3.8s 的纯寻道开销，被并发分摊后正好落在几百毫秒。

改法：把写放大到 1MB 对齐块、或改用 `O_DIRECT` + 自己合并写，`await` 立刻降到 2ms 以内。**这就是"减少寻道次数"比"提高传输率"重要一百倍的现场版。**

另一个常踩的坑：以为 `write()` 返回就落盘了。实际上它只写进**页缓存**，真正落盘由内核回写线程（`kworker`/`flush`）异步完成。要保证持久化必须 `fsync()`，而 `fsync` 的代价就是一次真实的磁盘访问——这就是数据库 redo 日志"批量组提交"存在的原因。

### 🎓 博士生视角

四种方式的分界线可以用一句话概括：**"谁拥有数据通路的所有权"**。程序查询与中断方式下，数据必须经过 CPU 寄存器（`MOV` 指令），所以 CPU 是数据通路的一部分；DMA 把总线控制权临时交给 DMA 控制器（**周期窃取 / burst 模式**），CPU 从"数据通路"退化为"配置者"；通道再进一步，把"配置"本身也程序化（通道程序存放在内存里，由通道处理器解释执行）。

这条演化线在今天的硬件里以另一种形式重演：RDMA 让网卡直接读写远端内存（绕过内核与 CPU）、DPU 把虚拟交换/存储协议栈整体下移、GPU 的 GPUDirect Storage 让 SSD 直接 DMA 到显存。**判断一个 I/O 架构是否先进，就看它把多少工作留给了通用 CPU。**

形式化一点：设单次 I/O 的数据量为 $B$，每次 CPU 介入开销为 $c$，介入粒度为 $g$（每次搬运的字节数），则 CPU 占用时间为

$$T_{\text{cpu}} = \frac{B}{g} \cdot c$$

程序查询 $g=1$（每字节查一次状态）、中断 $g=1\!\sim\!2$、DMA $g=\text{块大小}$、通道 $g=B$。这条公式解释了为什么**增大 $g$ 的收益是线性的、而代价只是"延迟变大"**——这就是 I/O 批处理（batching）永远有效的原因。

### 📚 考研者视角

**408 高频考法**（几乎每年一题，选择/综合都有）：

1. **"传输 N 字节，CPU 被中断多少次"**：中断方式按"每次中断传 1 字（16 位=2 字节）"算 → $N/2$；DMA 按"每块一次"算 → 1 次。**陷阱**：题目若给"每字节中断一次"就别除以 2，一定看清题干的设备宽度。
2. **"四种方式的 CPU 效率排序"**：通道 ≥ DMA > 中断 > 程序查询。答题要带理由（介入粒度）。
3. **中断响应过程的顺序**：**关中断 → 保存断点（PC/PSW）→ 引出中断服务程序 → 执行服务 → 恢复现场 → 开中断返回**。注意"保存通用寄存器"是**服务程序**做的，不是硬件做的，这半句经常是判分点。
4. **DMA 与中断的区别**（简答题模板）：① 数据传送是否经过 CPU；② 中断时机（每字节 vs 整块结束）；③ 优先级（DMA 请求通常高于中断请求，因为要抢总线）；④ 对 CPU 的影响（DMA 会"周期窃取"占用总线，但不需要切换上下文）。
5. **程序查询与中断的本质区别**：程序查询是 CPU **主动**反复查状态（忙等）；中断是设备**主动**通知 CPU。前者浪费 CPU，后者需要硬件支持（中断控制器）。

**易错点**：把"DMA 传送过程中 CPU 完全不能访存"当成正确——错，DMA 与 CPU 是**交替**使用总线（周期窃取），CPU 只是变慢，不是停摆。
