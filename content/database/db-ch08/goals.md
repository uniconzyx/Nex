# db-ch08 · 高可用 / 主从复制 / 分库分表 · 学习目标

## 前置
- `db-ch03` 索引与事务（B+树、ACID、隔离级别与 MVCC）—— 复制与分片都建立在「单库事务语义」之上
- `db-ch07` 备份恢复与权限安全（binlog、时间点恢复、GRANT）—— 本章的复制链路直接消费 binlog

## 本章定位
前三章解决了「一台机器上怎么把数据存对、查快」。本章回答一个不同量级的问题：
**当一台机器装不下、也停不起的时候怎么办**。三个子问题层层递进：

1. **可用性**：机器会坏，如何让「坏」不停服务？→ 主从复制 + 高可用架构 + 故障切换；
2. **扩展性**：数据装不下，如何把一张表拆到多台机器？→ 分库分表 + 分片键 + 分布式 ID；
3. **一致性**：拆开、复制之后，如何保证数据还是对的？→ CAP/BASE + Quorum + 补偿。

## 本章三条主线
1. **复制线**：binlog dump → relay log → SQL 线程重放；异步 / 半同步 / 组复制(MGR)；
   主从延迟的成因与「读己之写」的破坏与修复。
2. **分片线**：范围 / 哈希 / 一致性哈希 / 基因法四种切分维度的取舍；
   分片键选择的三条硬约束；跨分片 JOIN 与聚合（top-k 归并的正确性条件）；
   雪花算法位分配与时钟回拨；翻倍扩容（二次分片）的迁移代价。
3. **一致性线**：CAP 的正确表述与 PACELC 补全；BASE 与最终一致；
   Quorum 的 `W + R > N` 判据；半同步 / 多数派 / 补偿三层保障。

> 本章全部示例为可实跑的 **Python 3 标准库**（无第三方依赖），共 12 个；
> 每个 `expected_output` 都来自真实执行，关键定量结论（迁移率、倾斜度、冲突率、
> 脑裂判据、Quorum 判据）均以**实测数字**为准，回放脚本可复现。

## 验收标准
1. 能画出并讲清一次事务从主库提交到从库可见的**完整链路**，并说出链路上三个位点
   （master binlog pos / relay log pos / 已执行位点）的作用与 `Seconds_Behind_Master` 的口径。
2. 能对比 `STATEMENT` / `ROW` / `MIXED` 三种 binlog 格式，并说明为什么 ROW 是生产默认。
3. 能说出 GTID 相对 binlog file+pos 的两点优势（位点免维护、切换后可对比集合找缺口）。
4. 能画出异步 / 半同步 / 组复制三者的**提交路径**并给出各自的 RPO 与容错度。
5. 能说出主从延迟的五类成因，并区分「延迟导致读旧值」与「数据丢失」的本质差异。
6. 能给出「读己之写」的两种会话级修复（写后读主 / 版本号等待）及其工程代价。
7. 能对同一份 key 分布，**实测**并比较范围分片与哈希分片的数据倾斜度（极差 / 标准差）。
8. 能实现带虚拟节点的一致性哈希环，并解释「加 1 个节点迁移率约 1/N」的原因。
9. 能说出分片键选择的三条硬约束（高基数 / 业务强绑定 / 不可变），并据此判断一组查询的单分片可路由性。
10. 能用基因法把 `user_id` 的低位嵌进 `order_id`，并证明「同用户订单落同一分片」恒成立。
11. 能推导跨分片 top-k 归并的正确性条件 `k_local >= k`，并给出反例。
12. 能写出雪花算法的位分配（1+41+10+12），说出单机每毫秒上限与时钟回拨的三种处理策略。
13. 能区分「翻倍扩容」与「加 1 个分片」两种场景下取模与一致性哈希的迁移率差异。
14. 能说清 MHA / MGR / Orchestrator 的差别与选型条件，并给出切换后的七项校验清单。
15. 能解释脑裂的根因是「旧主失去仲裁后仍能写」，并说明 fencing 为何不可省略。
16. 能对给定 (N, W, R) 用 `W + R > N` 判定强一致，并说明 `W + R = N` 为什么不行。
17. 能按接口粒度而非整库粒度做 CAP 取舍，并说出 PACELC 补全了 CAP 的哪一半。
18. 能列举一致性保障的三个层次（预防 / 修复 / 检测），并说明为什么后两层不可省略。
