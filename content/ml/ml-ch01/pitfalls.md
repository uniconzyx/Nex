# ml-ch01 易错点：泛化与优化的六个认知陷阱

1. **把「训练误差低」当成模型好**
   - 现象：在训练集上 loss 降到 1e-4，验证集完全没动，误以为「再训久一点就行」。
   - 根因：训练误差是**同一批样本**上的拟合程度，与分布风险之间隔着一个泛化 gap。
   - 正确做法：只看**验证曲线**与**训练/验证间距**。间距随数据量增大会收窄 = 高方差（加数据有效）；
     两者都高且靠近 = 高偏差（加数据无效，要加容量或改特征）。

2. **把偏差-方差当成万能公式去套分类与漂移**
   - 现象：用 `Err = σ² + bias² + variance` 解释 0-1 损失下的分类误差，或解释线上掉点。
   - 根因：该恒等式**只对平方损失成立**，且要求**训练/测试同分布**。分类是 0-1 损失，
     没有这个恒等分解；分布漂移时 `f*` 与 `D` 都变了，三项的定义都不再成立。
   - 正确做法：分类里用**偏差-方差的语言类比**（边界是否偏移 vs 边界是否抖动），
     线上掉点先排查**泄漏（离线虚高）→ 漂移（分布变了）→ 训练服务偏差**，再谈模型。

3. **以为「加正则一定更好」**
   - 现象：模型已经欠拟合（训练误差都高），还先加 `λ`，结果更差。
   - 根因：正则化压的是方差、抬的是偏差。高偏差阶段加正则等于雪上加霜。
   - 正确做法：先诊断再动手——训练误差高 → 加特征/加容量/减正则；训练低验证高 → 加数据/加正则。
     `λ` 用对数网格扫，看验证误差的最低点，不要凭感觉取 0.01。

4. **忘记「标准化必须在切分之后」**
   - 现象：先对全量数据 `StandardScaler().fit_transform(X)`，再用 `cross_val_score`，
     得到漂亮但虚高的分数，上线后暴跌。
   - 根因：全量标准化把验证集的均值/方差混进了训练过程，属于**预处理泄漏**。
     在 K 折里，这等价于每一折都偷看了验证折的统计量。
   - 正确做法：用 `Pipeline([('scaler', StandardScaler()), ('model', ...)])`，
     让 `fit` 只在训练折上发生。目标编码同理，必须折外（out-of-fold）+ 平滑。

5. **以为「不收敛就是陷在局部最优」**
   - 现象：线性/逻辑回归 loss 来回震荡，第一反应是「换个初始化」。
   - 根因：凸问题没有坏的局部最优。不收敛的真实原因通常是**步长超过 1/L**、
     **特征未标准化导致 κ 极大**、**标签/特征错位**、或**数值溢出（未做 log-sum-exp）**。
   - 正确做法：按 κ → 步长 → 数据对齐 → 数值稳定性的顺序排查。
     神经网络才需要讨论局部最优与初始化。

6. **用测试集反复调参，然后报告测试集分数**
   - 现象：调了 30 组超参，每组都看测试集指标，最后报告最高那组的分数，写进报告/简历。
   - 根因：这是**选择性偏差**——你实际上在测试集上做了模型选择，测试集变成了验证集，
     报告值乐观偏倚。样本越小、调参次数越多，偏倚越大。
   - 正确做法：训练 / 验证 / 测试三分；调参只看验证；测试集**只在最终评估用一次**。
     需要无偏估计时用**嵌套交叉验证**（外层评估、内层调参）。
