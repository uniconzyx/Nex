# 指标是业务成本的语言：P/R/F1、ROC/PR、AUC 与校准

> 选错指标比选错模型更危险：模型错了你可以再训，指标错了你会**系统性地
> 优化错的东西**。本章的口径只有一句话——
> **指标必须反映漏判与误判的真实代价，阈值由代价决定，不由模型决定。**

## 1. 混淆矩阵家族：六个指标与各自的盲区

**中立陈述**：二分类预测落入四种结果，其余指标全是这四个格子的函数：

```text
                 真实 1          真实 0
     预测 1      TP（命中）      FP（误报）
     预测 0      FN（漏报）      TN（正确拒绝）
```

```python
precision = TP / (TP + FP)   # 判正的里面，有多少真正
recall    = TP / (TP + FN)   # 真正的正例，抓回来多少
F1        = 2·P·R / (P + R)  # P 与 R 的调和平均
accuracy  = (TP + TN) / (TP + FP + TN + FN)
```

| 指标 | 对什么敏感 | 盲区 / 失效场景 |
|---|---|---|
| accuracy | 整体对错 | 不平衡时「全判负」也能拿高分（1% 正例 → 99%） |
| precision | 误报代价（垃圾短信、误冻结） | 不看你漏了多少 |
| recall | 漏报代价（疾病、欺诈） | 不看你误报了多少 |
| F1 | P 与 R 同等重要 | **隐含假设 P、R 等权**；代价不对称时应该用 Fβ |
| Fβ (β>1) | 漏报更贵（β=2 时 recall 权重×2） | β 是拍的，要能说出依据 |

### Fβ：把代价不对称写进指标

**Fβ 的一般形式**：`Fβ = (1+β²)·P·R / (β²·P + R)`——`β²` 就是
「recall 相对 precision 的重要程度」。把 F1 当默认值是一种懒惰：
风控场景漏判一笔欺诈的代价常常是误判的十倍，此时 `β=2` 甚至 `β=3`
比 `F1` 更贴近业务（周志华《机器学习》第 2 章给出了 F1 与 Fβ 的标准定义）。

## 2. ROC vs PR：横轴的分母决定曲线会不会说谎

**中立陈述**：ROC 曲线以 **FPR = FP/N**（分母是负例总数）为横轴；
PR 曲线以 **recall = TP/P**（分母是正例总数）为横轴。
两条曲线包含的信息等价（给定全部分数即可互推），但**可读性取决于类别比例**。

```
ROC：横轴 FPR 被 N=2000 个负例「稀释」——负例越多，曲线越稳、数值越好看
PR ：横轴 recall 直接对着 P=200 个正例——基线 = 正例率 9.1%，一眼看出增量
```

| 维度 | ROC / AUC | PR / AP |
|---|---|---|
| 横轴分母 | 负例数 N | 正例数 P |
| 随机基线 | 对角线（AUC=0.5） | 水平线 `y = P/(P+N)` |
| 正例极稀有时 | **虚高**：大量 TN 把 FPR 压得很小 | **诚实**：曲线随正例数直接缩放 |
| 适用场景 | 两类都关心、比例接近均衡 | 不平衡、只关心正例的查全 |

### 稀有正例下 ROC 为什么会虚高

- **机制**：ROC 的 FPR 分母是全部负例，正例只占 9% 时，即使模型对正例
  毫无区分力，只要对负例排序略好，FPR 就很小、TPR 却可能不低——
  AUC 0.95 与「一个欺诈都没抓到」可以同时成立。
- **PR 的基线是正例率**：随机排序的 AP ≈ `P/(P+N)`。
  所以 AP 与基线之差就是「模型比随机好多少」，不需要换算，适合直接汇报。
- 两条曲线要用对场合：**类别接近均衡**时 ROC-AUC 是简洁的汇总；
  **正例 <10%**（欺诈、罕见病、默认违约）用 PR-AUC / AP + F1 沟通
  （Davis & Goadrich, ICML 2006 给出了两曲线关系的分析）。

## 3. AUC 的概率含义：一个必须会说的解释

**中立陈述**：AUC 等于「从正例中随机抽一个、从负例中随机抽一个，
模型给正例的打分高于负例的概率」：

```python
# AUC 的两种等价计算：梯形面积 = Mann-Whitney 统计量
auc = sum(tpr[i] * (fpr[i+1] - fpr[i]) for i in ...)          # 几何口径
auc = mean(score_pos > score_neg for pos in P for neg in N)   # 概率口径
```

### 校准之后：三个直接后果
1. **AUC 只依赖分数的排序**，不依赖绝对数值——所以它**对概率校准完全无感**：
   一个把所有分数乘 2 的模型 AUC 不变，但阈值 0.5 的行为全变；
2. **AUC 是「平均一切阈值后」的表现**——实际只用一个阈值工作时，
   该阈值附近的表现可能远差于 AUC（恰好落在曲线陡坡上）；
3. **AUC 不反映业务收益**：把 AUC 从 0.90 优化到 0.93 值多少钱，
   要换算成「该模型在你的阈值下多抓多少个/多误报多少个」才能回答。

**工程口径**：模型卡片里 ROC-AUC、PR-AUC、**目标阈值下的混淆矩阵**三者一起报，
只报一个 AUC 等于没报。

## 4. 阈值是业务参数：代价矩阵决定最优阈值

**中立陈述**：模型输出 `p = P(y=1|x)`，决策规则是「`p ≥ t` 判正」。
给定代价 `c_FP`（误报）与 `c_FN`（漏报），最小期望代价的规则是判后验概率：

```
判正，当且仅当   c_FN·(1−p) > c_FP·p
即              p / (1−p) > c_FP / c_FN          （几率口径）
```

- `c_FN = 10·c_FP`（漏判贵十倍）→ 阈值降到 `p > 1/11 ≈ 0.09` 才判正；
- `c_FP = 10·c_FN`（误报贵十倍）→ 阈值升到 `p > 10/11 ≈ 0.91` 才判正；
- **代价不对称时默认 0.5 一定是错的**——这是「不平衡场景下默认阈值
  recall 接近 0」的数学原因，不是模型问题。

**选阈值的标准流程**（对应 ml-ch04 示例 ex08）：
1. 在**验证集**上扫阈值，画 P/R/F1 曲线；
2. 按业务代价直接算每个阈值的总代价，选最低点（能说出 `c_FP/c_FN` 的场合）；
3. 说不出代价的场合退而求其次：F1 最大点或 Fβ 最大点；
4. 在测试集上**只报告**该阈值的绝对数字（TP/FP/FN 各多少），
   报告绝对错误数而不是只报比例——业务方能对着成本核算。

## 5. 概率校准：分数可排序不代表概率可信

**中立陈述**：校准研究的是「`p=0.7` 的样本里，是否真有约 70% 是正例」。
它独立于排序能力（AUC）：一个模型可以 AUC=0.95 但严重欠校准
（如 SVM、提升树、未经校准的神经网络）。

```
可靠性图（reliability diagram）：横轴 = 预测概率分桶，纵轴 = 桶内经验正例率
   理想：落在对角线上
   欠校准的常见形态：S 形（分数过度集中在 0/1 两端，中间概率虚高/虚低）
```

- **为什么必须校准**：当概率要进入**后续决策**（期望收益 `Σ p·v`、
  风控额度、出价）时，不可校准的概率直接等于错误的钱；
  只做排序（取 top-k）则不需要。
- **Platt 缩放**（Platt, 1999）：在已有分数上拟合一个逻辑回归
  `p_cal = σ(a·s + b)`，用**验证集**（或交叉验证的折外预测）拟合 `a, b`——
  在测试集上拟合等于又造一次泄漏；
- **Isotonic 回归**（Zadrozny & Elkan, 2002）：非参数的分段单调拟合，
  不假设 S 形，但需要更多数据且容易过拟合小样本；
- **保序回归性质**：两种方法都是保序的——校准**不改变 AUC**，
  只改概率的绝对数值。所以「校准后 AUC 掉了」一定是实现错了。

### 校准器是模型的一部分

**一条容易漏的工程纪律**：校准器是**模型的一部分**，必须和模型一起
放进 Pipeline 训练、一起版本管理；上线时若模型重训，校准器必须跟着重估。

## 三视角解析

### 🧑‍💻 程序员视角
- 先问业务三个问题再选指标：**漏一个的代价、误一个的代价、正负比例多少**。
  三个答案直接定 `β`、定「ROC 还是 PR」、定阈值，全都不用拍脑袋。
- 汇报纪律：任何模型卡片至少包含 **PR-AUC（或验证集 F1）+ 目标阈值下的
  混淆矩阵绝对值**。只给「准确率 99%」的模型在不平衡场景下应直接打回。
- 阈值不要写死在代码里：上线后按周看一次「实际代价 vs 预期代价」，
  偏了说明业务成本结构变了（或模型漂移了），重选阈值比重训更便宜。
- 概率进决策前先画可靠性图：`sklearn` 的 `calibration_curve` 十行代码。
  直方图明显偏离对角线的（SVM/树模型常见），先 `CalibratedClassifierCV`
  再上线，别让下游把 0.8 当成「80% 会发生」。

### 🎓 博士生视角
- ROC 与 PR 的信息等价性：给定全部分数，两曲线可互相推导；
  差别在**可视化与统计显著性**——PR 曲线下面积在不平衡下对正例数更敏感，
  置信区间更窄（因为有效样本量是 P 而非 N），这是 Davis & Goadrich (2006)
  的核心观察。
- AUC 的统计解释是 Mann-Whitney U 统计量的归一化形式，
  因此可以做假设检验（如 DeLong 检验比较两个模型的 AUC 差异是否显著）——
  工程上「AUC 高 0.01」多半不显著，报告差异应带区间。
- 校准的理论尺度是 **ECE（expected calibration error）**：按预测概率分桶后
  `Σ |acc(b) − conf(b)|·|b|/n`。它度量的是「概率与频率的系统性偏离」，
  与 AUC 正交——这两个维度构成了模型概率输出的完整评价。
- 代价最优阈值的推导本质上是最小化 `E[c_FP·FP + c_FN·FN]`，
  对 `t` 求导得到 `p(t)/(1−p(t)) = c_FP/c_FN`。贝叶斯决策论的直接应用；
  这也解释了「为什么把阈值当超参去网格搜索」是范畴错误——它不是模型参数，
  是决策参数。

### 📚 考研者视角
- 必考默写：**查准率、查全率、F1 的定义与公式**，以及
  「P-R 曲线的画法」「ROC 曲线的画法（横轴 FPR、纵轴 TPR）」。
  周志华《机器学习》第 2 章是标准口径。
- 高频对比题：**「类别不平衡时应该用什么指标？」**
  标准答案：精确率/召回率/F1、PR 曲线；要点明「准确率失效的原因是
  全判负类也能获得高准确率」。
- 计算题常客：给定混淆矩阵 `[[TN, FP],[FN, TP]]` 求 P/R/F1/accuracy，
  以及「以查全率为主」时选 F2（或说明理由）。注意 **F1 是 P 与 R 的
  调和平均**，不是算术平均——调和平均惩罚不平衡。
- 易混：**AUC 是排序能力，不是概率能力**；「AUC=0.9 意味着模型输出的 0.9
  可以作为概率」是概念错误，概率是否可信要看校准（可靠性图）。
