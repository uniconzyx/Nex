# ml-ch07 易错点：推荐系统里六个「指标看着好、线上就崩」的坑

1. **用未中心化的余弦算用户相似度**
   - 现象：离线邻居看起来非常相似（sim≈0.99），推荐结果却总是那批「什么都打 5 分」的用户爱看的爆款；
     换一批苛刻用户，推荐立刻失准。
   - 根因：余弦衡量的是**向量方向**，而评分向量的方向同时被「口味」和「打分松紧」决定。
     一个宽容用户的 `[5,5,4]` 与一个苛刻用户的 `[3,3,2]` 方向几乎相同，但他们的口味未必一致；
     反过来 `[5,1,5]` 与 `[3,5,3]` 才可能是真正的反向偏好。
   - 正确做法：显式评分用**中心化余弦 / Pearson**（减用户均值），item-based 用**调整余弦**（同样减用户均值）。
     Jaccard 只用于 0-1 隐式矩阵。改完后要重新检查「相似邻居的共同评分数」，少于 3 个的加收缩。

2. **把评分矩阵的缺失项当 0 做全矩阵损失**
   - 现象：训练 loss 很低，但预测值整体偏低（大多在 1~2 分），推荐列表缺乏区分度；
     用 `np.mean((R - Rhat)**2)` 时 loss 看起来「收敛得很好」。
   - 根因：`?` 不是 0 分。全矩阵求平方损失等于告诉模型「95% 的物品用户都极度讨厌」，
     模型的最优解被大量假负例拉向 0，真实观测的信号被淹没。
     在隐式场景更严重：未点击里混着「没曝光」，把它当负样本会学到「曝光机制」而非「偏好」。
   - 正确做法：**只在观测集合 Ω 上求和**（掩码 / 稀疏 COO 遍历）。
     隐式反馈改用加权 ALS（`c_ui = 1 + α·r_ui`）或 BPR 成对损失，
     负样本从「曝光未点击」里采，并排除已交互物品。

3. **随机切分交互数据做离线评估**
   - 现象：离线 Recall@20 比 baseline 高 15 个点，上线后几乎无变化，甚至下跌。
   - 根因：推荐是**时间序列**问题。随机切分让模型在训练时看到了「未来」的交互，
     而线上只能用过去预测未来。更隐蔽的是：随机切分后，同一用户的行为同时出现在
     训练和测试里，user/item 因子已经记住了这些交互，等于**ID 泄漏**。
   - 正确做法：按**全局时间切分**（如最后 2 周做测试），并保证测试期用户/物品在训练期
     至少出现过一次（否则是冷启动，应单独报告）。同时固定**负样本采样种子**，
     保证不同模型用同一批候选，否则指标不可比。

4. **用 RMSE 优化隐式反馈，或用 AUC 汇报评分预测**
   - 现象：BPR 训练完去算 RMSE，发现比 MF 差很多，于是判定「BPR 不行」；
     或者 MF 的 RMSE 降了 0.02，就直接上线，CTR 没动。
   - 根因：**目标函数与评测口径错位**。RMSE 衡量「分数拟合得多准」，BPR 优化的是
     「正样本是否排在负样本前面」，它根本不拟合评分，RMSE 当然差；
     反过来，RMSE 对排序不敏感——把所有分数加一个常数，RMSE 变差但排序不变。
   - 正确做法：先声明任务口径。**评分预测** → 平方损失 + RMSE/MAE；
     **Top-N 推荐** → BPR/softmax 损失 + Recall@K/NDCG@K/AUC。
     汇报时同时给出「同口径 baseline」，不要跨口径比较绝对值。

5. **在召回候选集里算 Recall@K，然后宣称召回提升**
   - 现象：召回层离线 Recall@500 从 0.62 涨到 0.71，上线后 CTR 不变，查日志发现
     候选集本身变大了 3 倍。
   - 根因：Recall 的分母是「相关物品总数」，分子是「Top-K 命中的相关物品数」。
     如果候选集从 1000 扩到 3000，K 也放到 500，命中数自然变多，
     但**排序层的负担**和**线上延迟**同时变差，且新增候选可能全是低质物品。
   - 正确做法：召回评测固定「全库 + 固定 K」，并同时报告**候选集规模**与**下游 NDCG**。
     召回的收益必须能传导到排序：如果 Recall 涨但 NDCG@10 不涨，说明新增的是「相关但不靠前」的物品，
     对首屏无价值。用「召回-排序联合指标」做决策。

6. **只用 Recall@K 评估，结果推荐列表全是热门**
   - 现象：模型离线指标很好，但线上用户反馈「推荐的东西我都见过了」；
     列表覆盖度只有 2%，平均流行度是物品库均值的 50 倍。
   - 根因：热门物品交互多、因子估计准、相似度高，天然在 Recall@K 上占优。
     一个「只推 Top 100 热门」的基线，Recall@20 常常能打赢不少复杂模型——
     因为测试集本身就被热门支配。指标没有惩罚「同质化」。
   - 正确做法：同时监控**覆盖度（catalog coverage）、平均流行度、基尼系数、类目熵**；
     训练时对热门降权（`w_i ∝ 1/pop^τ`）或做**分层评估**（按物品流行度分桶看 Recall）。
     重排阶段加多样性约束（MMR/DPP），并用 A/B 验证长期留存，而不是只看单日 CTR。
