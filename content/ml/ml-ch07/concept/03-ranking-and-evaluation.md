# 召回、排序与评测：把「模型分数」翻译成「业务收益」

> 一个推荐系统不是「一个模型」，而是一条**漏斗**：从百万级物品里召回几百个，
> 再排序出几十个，最后重排出十来个。每一层的目标、指标和数据分布都不同。
> 更麻烦的是：**离线指标涨了，线上不一定涨**。这一讲把链路、指标口径、
> 离线-线上鸿沟、流行度偏差与冷启动混合策略一次讲清。

## 1. 召回-排序链路：每层解决不同的问题

```text
        ┌─────────────────────────────────────────────────────────┐
        │ 物品库 10⁵ ~ 10⁷                                        │
        └───────────────────────┬─────────────────────────────────┘
                                │  多路召回（每路几十~几百）
        ┌───────────────────────▼─────────────────────────────────┐
        │ 召回：itemCF / 双塔 / 热门 / 内容 / 社交 / 地理          │
        │ 目标：高 recall，允许低 precision；延迟 < 10ms           │
        └───────────────────────┬─────────────────────────────────┘
                                │  候选集 500~2000
        ┌───────────────────────▼─────────────────────────────────┐
        │ 粗排：轻量模型（双塔/GBDT），候选压到 100~300            │
        └───────────────────────┬─────────────────────────────────┘
                                │
        ┌───────────────────────▼─────────────────────────────────┐
        │ 精排：重模型（DNN/GBDT+特征交叉），输出 pCTR/pCVR        │
        │ 目标：AUC / LogLoss / 校准；延迟 < 100ms                 │
        └───────────────────────┬─────────────────────────────────┘
                                │  Top 20~50
        ┌───────────────────────▼─────────────────────────────────┐
        │ 重排：多样性、打散、业务规则、长期价值                   │
        └───────────────────────┬─────────────────────────────────┘
                                │
                            最终曝光 6~20 个
```

**关键认知：每层的「评测集」不一样**。

- 召回层看 `Recall@K`（在**全库**里，K=100~500），因为它的职责是「别漏」；
- 排序层看 `AUC / NDCG@K`（在**召回候选集**里，K=10~20），因为它的职责是「排得准」；
- 重排层看业务指标（多样性、时长、GMV）与约束满足率。

**用排序指标评召回、或用全库召回率评排序，都是口径错位**。
这是面试里最能区分「真做过」和「背过」的问题之一。

## 2. 离线指标的口径：先把分母说清楚

### 2.1 二分类/点击预测

```
AUC = P(正样本分数 > 负样本分数)          ← 全局排序能力，对类别不平衡不敏感
LogLoss = −(1/N) Σ [y log p + (1−y) log(1−p)]   ← 校准 + 排序
GAUC = Σ_u w_u · AUC_u / Σ_u w_u          ← 按用户分组的 AUC（推荐更常用）
```

推荐场景里 **GAUC 比 AUC 更贴近线上**：AUC 会被「高活跃用户」主导，
而线上每个用户看到的是自己的列表。`w_u` 通常取该用户的曝光数或点击数。

### 2.2 Top-K 排序指标

设用户 `u` 的相关物品集合为 `Rel_u`（二值），模型给出排序列表 `L_u`。

**Precision@K / Recall@K**：

```
P@K = |L_u[:K] ∩ Rel_u| / K
R@K = |L_u[:K] ∩ Rel_u| / |Rel_u|
```

**AP / MAP**（考虑相关物品出现的位置）：

```
AP_u = (1/|Rel_u|) Σ_{k=1}^{K} P@k · 1[L_u[k] ∈ Rel_u]
MAP  = (1/|U|) Σ_u AP_u
```

**DCG / NDCG@K**（考虑多级相关性 + 位置折扣）：

```
DCG@K = Σ_{k=1}^{K} (2^{rel_k} − 1) / log₂(k + 1)
IDCG@K = 把该用户的相关物品按 rel 降序排好后的 DCG@K
NDCG@K = DCG@K / IDCG@K
```

`IDCG` 是**归一化分母**，作用是把不同用户、不同相关物品数的 NDCG 压到 `[0,1]`。
**没有 IDCG 的 DCG 不能跨用户平均**——这是最常见的实现错误。

### 2.3 手算一个例子

相关集合 `Rel = {A, C}`（|Rel|=2），模型排序：

```
排名:   1    2    3    4    5
物品:   A    B    C    D    E
rel:    1    0    1    0    0

P@1 = 1/1 = 1.00      R@1 = 1/2 = 0.50
P@3 = 2/3 ≈ 0.67      R@3 = 2/2 = 1.00
AP  = (1/2)(1/1 + 2/3) = 0.833

DCG@5 = (2¹−1)/log₂2 + 0 + (2¹−1)/log₂4 = 1 + 0.5 = 1.500
IDCG@5（理想排序 A,C,...）= 1/log₂2 + 1/log₂3 = 1 + 0.631 = 1.631
NDCG@5 = 1.500 / 1.631 ≈ 0.920
```

**读法**：Recall@3=1 说明「全都召回了」，但 NDCG=0.92 说明「C 排得偏后」。
两个指标看的是不同问题：**召回看有没有，NDCG 看排得好不好**。

### 2.4 口径陷阱清单

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 在**召回候选集**里算 Recall@K | 数值虚高（分母变小） | 召回在全库算，排序在候选集算 |
| 用**训练集**里的交互当相关集 | 泄漏，指标虚高 | 按时间切分，只用未来交互 |
| 对每个用户**等权平均** | 活跃用户被稀释 | 按曝光/点击加权，或分活跃度分层报告 |
| `K` 与线上展示位不一致 | 离线 K=50，线上只展示 6 个 | 离线 K 对齐线上首屏坑位 |
| 负样本**随机采**但线上是**曝光样本** | 分布不一致 | 负样本从曝光未点击里采 |
| NDCG 未做 IDCG 归一化 | 跨用户不可比 | 必须除以 IDCG |

## 3. 离线评估与线上 A/B 的差距

**离线指标是线上收益的有偏代理**，不是它的无偏估计。五类系统性偏差：

1. **代理指标错位**：离线优化 `P(click)`，线上要的是「停留时长 / 转化 / 复访」。
   点击率高但内容劣质，长期会掉留存（**短期指标与长期价值冲突**）。
2. **曝光偏差（exposure bias）**：离线数据只包含「被旧策略曝光过」的样本。
   新模型想推的物品没有历史交互，离线评不到；旧模型推过的物品被高估。
3. **位置偏差（position bias）**：排在第 1 位的点击率天然高，模型学到「位置」而不是「相关性」。
   训练时要加位置特征或 IPS 加权，评测时要用**无偏排序**（如 swap 实验）。
4. **反馈延迟**：下单/复购的标签要等几天甚至几周，离线只能用「已观测到的转化」，
   会系统性低估长周期物品。
5. **辛普森悖论 / 流量结构变化**：A 模型在「新用户」上更好、B 在「老用户」上更好，
   但两组的流量占比在离线与线上不同，总体结论可能反转。**必须分群报告**。

**工程做法**：

```
离线（筛模型） → 小流量回放（replay，验证打分） → 1% A/B（验证无 bug）
              → 5%~10% A/B（验证收益） → 全量（监控长期指标）
```

**离线只用来排序候选模型，不用来承诺涨幅**。一个常见的团队规范：
离线 NDCG 提升 < 1% 的模型不进 A/B（噪声大于信号）；进 A/B 的模型必须同时看
「核心指标 + 护栏指标（时长、多样性、投诉率）」。

## 4. 流行度偏差与去偏

### 4.1 偏差从哪来

```
真实偏好 ──曝光策略──► 观测交互 ──训练──► 新模型 ──► 更多曝光给热门
    ▲                                                      │
    └──────────────── 反馈闭环 ◄───────────────────────────┘
```

热门物品的交互多 → 相似度高 / 因子估计准 → 被推荐更多。三步正反馈之后，
推荐列表的**类目熵**下降，长尾供给方退出，生态恶化。

**度量**：

```
流行度偏差 = 推荐列表的平均流行度 / 物品库的平均流行度
基尼系数   = 推荐曝光分布在物品上的不均等程度
覆盖度     = 被推荐过的物品数 / 物品总数（catalog coverage）
```

### 4.2 IPS 去偏

设旧策略（记录策略）对物品 `i` 给用户 `u` 的曝光概率为 `π_0(i|u)`，
新策略为 `π_1(i|u)`。用重要性采样估计新策略的期望收益：

```
V̂(π_1) = (1/N) Σ_{(u,i) 被观测} [ π_1(i|u) / π_0(i|u) ] · reward_ui
```

**自归一化版本（SNIPS）**更稳：

```
V̂_SNIPS = Σ w_ui · reward_ui / Σ w_ui,    w_ui = π_1(i|u) / π_0(i|u)
```

**代价**：方差随权重爆炸。工程上做**权重截断** `w ← min(w, c)`（c 常取 5~20），
用少量偏差换可控方差。另一个前提是 `π_0 > 0`（** positivity / overlap **）：
旧策略从没曝光过的物品，权重无法估计——这就是「新物品无法离线评估」的根本原因。

### 4.3 其他去偏手段

- **校准（calibration）**：让每个流行度分桶的预测点击率与真实点击率一致，
  而不是整体一致。常用**分层校准 / 等频分桶 + 保序回归**。
- **多样性重排**：MMR、DPP、类目打散。目标函数里显式加「与已选列表的最大相似度」惩罚。
- **热门降权**：`score' = score / pop^τ`（τ 常取 0.1~0.3）。简单有效，但会伤短期 CTR，
  需要 A/B 验证长期留存。

## 5. 冷启动的混合策略

### 5.1 按置信度加权，而不是硬切换

```
score(u,i) = w_u · score_CF(u,i) + (1 − w_u) · score_content(u,i)
w_u = n_u / (n_u + α)          # n_u：用户交互数，α：先验强度（如 5~20）
```

物品侧同理：`w_i = n_i / (n_i + β)`。
**好处**：没有阈值跳变；交互增加时平滑过渡；α 可解释为「需要多少次交互才能信任 CF」。

### 5.2 分阶段策略

| 阶段 | 用户信号 | 物品信号 | 策略 |
|---|---|---|---|
| 完全冷启动 | 无 | 无 | 地域热门 + 业务规则 + 随机探索 |
| 用户冷、物品热 | 无 | 充分 | item-based / 热门，先收集 3~5 个兴趣点 |
| 用户热、物品冷 | 充分 | 无 | 内容向量召回、类目映射、作者/品牌关联 |
| 两者都热 | 充分 | 充分 | MF/BPR + 实时行为序列 |

### 5.3 内容特征与协同特征的融合

三种融合层次：

```
① 特征拼接（early fusion）
   x = [onehot(user), onehot(item), content_vec(item), stat_feats]
   → GBDT / DNN 学交叉
   优点：简单；缺点：冷启动时协同 one-hot 全 0，模型仍偏向热门

② 模型融合（late fusion）
   score = α·score_CF + β·score_content + γ·score_pop
   优点：可解释、可分别调权；缺点：权重需按场景调，且无法学高阶交叉

③ 表示融合（deep fusion）
   item_vec = concat(id_embedding, content_embedding) → MLP
   冷启动时 id_embedding 退化为先验，content 主导
   这是工业界双塔/wide&deep 的常见做法
```

**冷启动场景的经验判据**：如果内容特征质量高（标题/类目/图像 embedding 可信），
内容召回的贡献在冷物品上能到 50% 以上；如果内容特征很弱（只有 ID 和类目），
不如把预算花在**探索流量**上——用 bandit 直接买数据，比硬猜内容更划算。

## 6. 一张表收束：指标 → 决策

| 你关心的问题 | 该看的指标 | 不该看的指标 |
|---|---|---|
| 召回有没有漏 | Recall@K（全库） | NDCG@10 |
| 首屏排得准不准 | NDCG@K / MAP@K（候选集，K=展示位） | AUC（对 Top-K 不敏感） |
| 点击率预估准不准 | LogLoss / 校准曲线 / GAUC | RMSE |
| 是不是只推热门 | 覆盖度、平均流行度、基尼系数 | Recall@K（会被热门刷高） |
| 新策略能不能上 | IPS 估计 + 小流量 A/B | 离线 NDCG 单指标 |
| 长期生态健康 | 留存、复访、供给多样性 | 单日 CTR |

## 三视角解析

### 🧑‍💻 程序员视角

- **指标实现要先写单测**。NDCG 的 `IDCG` 分母、`log₂(k+1)` 的起始下标（k 从 1 开始还是 0）、
  多级相关性的 gain 用 `2^rel−1` 还是 `rel`，三处任一处理错，离线分数就能差 5 个点。
  用一个小例子（3 个相关物品、5 个位置）手算对拍。
- 召回评测要**固定候选集**。线上召回是多路合并后截断，离线必须复现同一套合并逻辑；
  否则「离线 Recall 涨了」可能只是候选池变大了。
- A/B 实验的最小样本量要提前算：`n ≈ 16σ²/Δ²`。很多团队在 CTR 提升 0.5% 时就下结论，
  实际置信区间跨 0，最后全量后回滚。
- 护栏指标必须和核心指标同时看：CTR +3% 但平均时长 −8%，通常是标题党/低质内容，
  长期一定亏。**短期指标可以被优化，长期指标很难骗**。
- 日志要留**曝光位次**和**策略版本**。没有位次就无法做位置去偏，没有策略版本就无法做 IPS。
  这两列是推荐系统日志的最小可用集。

### 🎓 博士生视角

- 离线评估的本质是**反事实估计（counterfactual estimation）**：你想知道新策略 `π_1` 的收益，
  但只有旧策略 `π_0` 的数据。IPS 是无偏的，但方差随 `π_1/π_0` 的尾部爆炸；
  它的有效样本量 `ESS = (Σw)²/Σw²` 常低到几百，此时置信区间极宽。
- **Doubly Robust（DR）** 估计把 IPS 与奖励模型结合：
  `V̂_DR = Σ [m̂(x) + (r − m̂(x))·w]`，只要奖励模型或倾向模型之一正确就无偏，
  方差比纯 IPS 小。这是工业界离线评估的主流方法（相关内容在因果推断，不在本章展开）。
- NDCG 的折扣函数 `1/log₂(k+1)` 是**启发式**的，不是从用户行为模型推出来的。
  更原则化的做法是用**点击模型**（position-based model / cascade model）估计
  「位置 k 被 examination 的概率」，再用它做加权——这时指标才与「用户实际看到」对齐。
- 流行度偏差的因果图是 `popularity → exposure → interaction ← preference`，
  其中 `exposure` 是 confounder。不做干预建模，学到的 `P(click|item)` 混合了
  「物品好」与「物品被曝光多」两个通道，无法分离。这是推荐系统里最典型的**混杂偏差**。
- 「离线涨、线上不涨」在统计上有一个简洁解释：离线指标与线上收益的相关性
  **只在同一策略族内成立**。跨策略族（比如从 MF 换到双塔），
  离线指标的排序能力会失效——这就是**代理指标的非不变性**。

### 📚 考研者视角

- 自命题 AI 常考：**Precision/Recall/F1、ROC-AUC、NDCG 的定义与计算**。
  NDCG 的公式要能默写：`DCG = Σ(2^{rel_i}−1)/log₂(i+1)`，`NDCG = DCG/IDCG`。
- 计算题注意**分母口径**：Recall 的分母是「相关物品总数」，不是「返回的物品数」；
  Precision 的分母是「返回数 K」，不是「相关总数」。两者不对称，别写反。
- 概念题常问「**为什么用 NDCG 而不是 Precision@K**」：因为 NDCG 同时考虑
  「相关性等级」与「位置折扣」，而 P@K 把所有位置同等对待、且只支持二值相关。
- 易混：**AUC 是全局排序指标，对 Top-K 不敏感**。把最相关的物品从第 1 名挪到第 100 名，
  AUC 几乎不变，但 NDCG@10 会崩。答题时用这句话说明「为什么推荐不用 AUC 做唯一指标」。
- 冷启动的标准答题框架：**用户侧 / 物品侧 / 系统侧**，每侧给「利用内容、利用热门、
  利用探索、利用迁移」四类手段，并补一句「冷启动的本质是信息不足，任何方法都只是先验」。
