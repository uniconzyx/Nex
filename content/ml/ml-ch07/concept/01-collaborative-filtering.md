# 协同过滤：用「谁和谁像」填补评分矩阵

> 推荐系统的原始数据永远是一张**稀疏到离谱**的矩阵：几万用户 × 几万物品，
> 观测密度常常只有 0.1%~5%。协同过滤（Collaborative Filtering, CF）的全部技巧，
> 就是在这张矩阵上回答一个问题：
> **「这个用户没看过的物品，他会打几分 / 会不会点？」**
> 它不借助任何物品内容，只借助「群体的行为模式」——这也是它既强大又脆弱的原因。

## 1. 问题形式化：评分矩阵与稀疏性

把用户集合记为 `U`（|U| = m），物品集合记为 `I`（|I| = n），交互矩阵 `R ∈ ℝ^{m×n}`：

```
                 i₁     i₂     i₃     i₄     i₅     i₆
          ┌──────────────────────────────────────────────┐
    u₁    │  5      ?      4      ?      ?      1        │  爱打高分
    u₂    │  ?      2      ?      ?      5      ?        │  口味独特
    u₃    │  4      ?      5      ?      ?      ?        │
    u₄    │  ?      ?      ?      3      ?      2        │  只评低分
    u₅    │  1      ?      ?      ?      4      ?        │
          └──────────────────────────────────────────────┘
          ? = 未观测（missing），不是 0
```

**第一件必须记住的事：缺失不是零。** 评分矩阵里 `?` 有三种完全不同的含义：

| 缺失类型 | 真实含义 | 处理方式 |
|---|---|---|
| 随机缺失（MCAR） | 用户恰好没评，与偏好无关 | 可作为负样本，但需纠偏 |
| 缺失非随机（MNAR） | 用户**只评自己看过的**，而看什么受曝光影响 | 必须建模曝光机制，否则有偏 |
| 隐式未点击 | 没曝光 / 曝光没注意 / 看了不喜欢 | 不能当负样本，需负采样 |

把 `?` 当 0 做回归，是推荐系统最常见、也最致命的错误之一——它会让模型学会「预测 0 分」，
而不是「预测偏好」。这也是 2.4 节隐式反馈要换损失函数的原因。

**稀疏性的直接后果**：两个用户共同评过的物品可能只有 1~2 个，
此时相似度的方差极大，「相似」很可能只是噪声。协同过滤的很多工程技巧
（收缩相似度、基于物品的邻域、矩阵分解）本质上都在**给稀疏的相似度估计加先验**。

## 2. user-based CF：找「和你品味相近的人」

### 2.1 相似度的四种口径

两个用户 `u`、`v` 的共同评分集合记为 `I_uv = {i : r_ui ≠ ? 且 r_vi ≠ ?}`。

**余弦相似度**（把评分看成向量）：

```
sim(u,v) = Σ_{i∈I_uv} r_ui · r_vi / (‖r_u‖₂ · ‖r_v‖₂)
```

**中心化余弦 / Pearson 相关**（先减用户均值）：

```
sim(u,v) = Σ (r_ui − μ_u)(r_vi − μ_v) / sqrt( Σ(r_ui − μ_u)² · Σ(r_vi − μ_v)² )
```

**Jaccard**（只看「评没评」，不看分数，适合隐式反馈）：

```
sim(u,v) = |I_u ∩ I_v| / |I_u ∪ I_v|
```

**调整余弦（Adjusted Cosine）**：以**用户均值**为中心（Sarwar et al., 2001），常用于 item-based：

```
sim(i,j) = Σ_u (r_ui − μ_u)(r_uj − μ_u) / sqrt( Σ_u(r_ui − μ_u)² · Σ_u(r_uj − μ_u)² )
```

注意这里减的是 `μ_u`（该用户所有评分的均值），不是物品均值。原因和上一节一样：
要先剥离「打分松紧」，剩下的才是「相对偏好」。有些实现会减物品均值，
那是另一种中心化，语义不同，不能混用。

```
评分尺度差异对余弦的影响（两用户口味相同，但一个爱打 5 分、一个爱打 3 分）

  原始评分向量            余弦相似度        中心化后
  u = [5, 5, 4]  ──┐
                   ├──►  sim ≈ 0.998  ← 看起来极像，其实只是「都爱打高分」
  v = [3, 3, 2]  ──┘                     中心化后 sim = 1.0（真正的口味一致）

  另一对：u=[5,1,5], v=[5,1,5] 与 w=[3,5,3]
  未中心化时 w 与 u 的余弦也很高（都为正），中心化后符号翻转 → 相似度变负
```

**结论**：只要用户有「打分松紧」差异，未中心化的余弦就会把「都爱打高分」误判成「口味相似」。
Pearson / 中心化余弦是显式评分的默认选择；Jaccard 只用于隐式 0-1 矩阵。

### 2.2 预测公式

选好邻居集合 `N_k(u)`（与 u 最相似的 k 个用户），预测 `u` 对 `i` 的评分：

```
r̂_ui = μ_u + Σ_{v∈N_k(u)} sim(u,v) · (r_vi − μ_v) / Σ_{v∈N_k(u)} |sim(u,v)|
```

两个细节决定成败：

1. **减去 `μ_v` 再加 `μ_u`**：这是「用别人的偏差修正自己的基线」，不是可选项。
   若直接加权平均原始评分，一个习惯打 5 分的邻居会把所有人都拉高。
2. **分母用 `|sim|` 而不是 `sim`**：负相似邻居也应参与，但权重必须为正，
   否则「负相关用户的高分」会被算成低分贡献（符号会乱）。

**邻居选择**：k 太小 → 方差大；k 太大 → 偏差大（把不相似的人拉进来）。
工程上常取 20~50，并加**相似度收缩**：

```
sim'(u,v) = sim(u,v) · |I_uv| / (|I_uv| + λ_shrink)
```

只有 1 个共同物品的「完美相似」会被压到 0.5 以下，避免小样本巧合。

## 3. item-based CF：找「和你买过的东西相似的东西」

item-based 把相似度的对象从「用户」换成「物品」：先算物品-物品相似度，
再用用户评过的物品去预测目标物品。

```
r̂_ui = Σ_{j∈N_k(i)∩I_u} sim(i,j) · r_uj / Σ |sim(i,j)|
```

**为什么工业界更常用 item-based**：

| 维度 | user-based | item-based |
|---|---|---|
| 相似度规模 | m²，用户增长快、兴趣漂移快 | n²，物品相对稳定，可离线预计算 |
| 相似度稳定性 | 用户兴趣随季节/事件变化 | 物品属性稳定，相似度可复用数天 |
| 可解释性 | 「和你相似的人买了…」隐私敏感 | 「因为你看过…」更自然 |
| 稀疏性 | 用户共同评分少时不可靠 | 物品被大量用户评过，共现更充分 |
| 新用户 | 无历史 → 完全失效 | 有一个行为就能触发 |
| 新物品 | 有用户评就能被推荐 | 无人评 → 相似度算不出（冷启动更严重） |

**核心不对称**：item-based 对**新用户**友好（只要有一个行为），对**新物品**更差；
user-based 相反。这个不对称直接决定了冷启动策略该选哪一边。

**ItemCF 的隐式反馈版本**：把评分换成行为（点击/购买），相似度用
`sim(i,j) = |U_i ∩ U_j| / sqrt(|U_i|·|U_j|)`（余弦形式的共现），
再按「用户对 i 的行为强度」加权。这也是「看了又看」「买了又买」类召回的基础。

## 4. 均值归一化：为什么它是必需品而不是优化项

### 4.1 三种偏置

真实评分可以拆成：

```
r_ui = μ + b_u + b_i + (用户-物品交互项)
```

- `μ`：全局均值（比如 3.6）；
- `b_u`：用户偏置（苛刻用户 −0.8，宽容用户 +0.7）；
- `b_i`：物品偏置（神作 +0.9，烂片 −1.2）。

**不做归一化时，模型只能靠隐因子同时解释这三项**，而偏置的方差远大于交互项——
模型会把大量容量浪费在「这个人爱打高分」上，交互信号被淹没。

### 4.2 对相似度的影响（数值例子）

```
用户 u: [5, 5, 4, 5]   μ_u = 4.75
用户 v: [3, 3, 2, 3]   μ_v = 2.75
用户 w: [5, 1, 5, 1]   μ_w = 3.00

未中心化余弦：sim(u,v) ≈ 0.999   ← 误判为「极相似」
             sim(u,w) ≈ 0.800

中心化后：u−μ_u = [0.25, 0.25, −0.75, 0.25]
          v−μ_v = [0.25, 0.25, −0.75, 0.25]  → sim = 1.000（确实同款口味）
          w−μ_w = [2, −2, 2, −2]             → sim = −0.333（口味相反）
```

**不做中心化，u 会去参考 v（其实只是都爱打高分），而不是 w（真正口味相反）**。
这就是「均值归一化为什么必要」的完整答案：它把「评分尺度」从「偏好形状」里剥离出来。

### 4.3 对矩阵分解的影响

带偏置的 MF 目标：

```
min Σ_{(u,i)∈Ω} (r_ui − μ − b_u − b_i − p_uᵀq_i)² + λ(‖p_u‖² + ‖q_i‖² + b_u² + b_i²)
```

`b_u`、`b_i` 用**交替最小二乘的闭式解**更新（固定其他项时是单变量二次函数）：

```
b_u = Σ_{i∈I_u} (r_ui − μ − b_i) / (|I_u| + λ)
b_i = Σ_{u∈U_i} (r_ui − μ − b_u) / (|U_i| + λ)
```

这就是「baseline predictor」。很多团队发现：**先把 baseline 做扎实，MF 的增益才稳定**；
baseline 没做，隐因子的提升很可能只是在拟合偏置。

## 5. 冷启动：协同过滤的结构性盲区

协同过滤的输入是交互，没有交互就没有信号。三类冷启动：

| 类型 | 表现 | 可用信号 | 典型方案 |
|---|---|---|---|
| 新用户 | 无评分，邻居为空 | 注册信息、首次行为、上下文 | 热门兜底 → 引导选择兴趣 → 内容/人口统计 |
| 新物品 | 无评分，无法算相似度 | 标题/类目/图片/文本 | 内容向量召回、类目映射到老物品 |
| 新系统 | 两者都没有 | 无 | 人工规则 + 探索（bandit）、迁移学习 |

**混合策略的工程口径**（按置信度加权，而不是硬切换）：

```
score = (n / (n + α)) · score_CF + (α / (n + α)) · score_content
```

`n` 是该用户/物品的交互数，`α` 是先验强度。交互少时内容占主导，交互多时协同占主导。
这比「新用户走规则、老用户走 CF」的硬切换平滑，也避免了阈值附近的行为跳变。

**探索是冷启动的另一半**：只靠内容特征，新物品永远拿不到协同信号，形成**富者愈富**。
生产系统通常留 5%~10% 的流量做 ε-greedy / Thompson Sampling 探索，
用短期指标损失换长期供给健康。

## 6. 协同过滤的偏差：热门、灰羊与同质化

1. **流行度偏差（popularity bias）**：热门物品被曝光多 → 交互多 → 相似度高 → 被推荐更多。
   结果是「马太效应」：长尾物品永无出头之日，推荐结果趋同。
   离线评测也会被热门支配——一个「只推最热 100 个」的基线，Recall@K 常常不低。
2. **灰羊效应（gray sheep）**：口味与任何群体都不相似的用户，CF 找不到可靠邻居，
   预测退化为全局均值。这类用户占比不高，但流失率高。
3. **同质化 / 信息茧房**：只优化相关性会让推荐越来越窄。工程上用**多样性重排**
   （MMR：`score = λ·rel − (1−λ)·max_sim`）和**类目打散**来对冲。
4. **反馈闭环（feedback loop）**：模型推荐什么，就只观测到什么，训练数据被模型自己污染。
   这是推荐系统与经典监督学习最本质的区别之一，必须靠**随机曝光**或**IPS 加权**打破。

> 一句话收束：**协同过滤不是「理解用户」，而是「利用群体行为的统计相关性」。
> 它的所有偏差都来自「行为数据不是随机采样的」这一事实。**

## 三视角解析

### 🧑‍💻 程序员视角

- 上线顺序别搞反：**热门/规则兜底 → item-based CF → MF/BPR → 双塔**。
  每一步都要有离线指标和线上 A/B，否则你无法判断涨点来自模型还是来自「终于有推荐了」。
- 相似度矩阵是 `n²` 内存。10 万物品的 float32 稠密矩阵就是 40GB——必须用**倒排 + TopN 截断**
  （每个物品只存 100~500 个近邻），并且离线批量更新、增量校正。
- 线上服务只做「查表 + 内积」：user 向量 × item 向量。**训练-服务一致性**是事故高发区：
  训练时用了实时特征，服务时取不到；训练时 ID 哈希方式与服务端不一致，都会导致「离线 AUC 0.8，线上 0.5」。
- 别用全量数据算相似度再评估。正确做法是**按时间切分**：用 t 之前的行为训练，
  预测 t 之后的交互；随机切分会把未来信息泄漏进相似度，指标虚高 10 个点很常见。
- 冷启动不要写「if 新用户: 返回热门」就完事。热门兜底要**分地域/年龄段**，
  否则新用户第一屏全是不相关爆款，直接劝退。

### 🎓 博士生视角

- user-based / item-based 都是**记忆型（memory-based）**方法：不做参数化，预测时直接查邻域。
  它们的偏差-方差行为由邻居数 k 控制，和 kNN 完全同构；相似度收缩就是**经验贝叶斯**的
  后验均值近似（把「小样本相似度」往 0 拉）。
- 矩阵分解把 CF 变成**低秩矩阵补全**：`min rank(X) s.t. X_Ω = R_Ω`。核范数松弛
  （nuclear norm）是其凸替代，理论上可在满足**不相干条件（incoherence）**时精确恢复——
  这是 Candès & Recht 的矩阵补全理论。工程上的 MF 用显式秩 k + L2，是它的非凸参数化版本。
- 显式反馈的 MF 是**双线性模型**，固定一侧对另一侧是凸二次，因此是**双凸（biconvex）**而非凸。
  ALS 单调下降且每步全局最优（对单侧），但可能停在鞍点；SGD 逃鞍点能力更强但方差大。
- 隐式反馈的正确概率模型是**一对比较**：`P(i ≻_u j) = σ(x̂_ui − x̂_uj)`，
  这导出 BPR（Rendle et al., 2009）。它不是「另一种 loss」，而是**对排序似然的极大化**；
  若把未交互当负样本又不对曝光纠偏，估计的是 `P(交互 | 曝光)` 而非 `P(偏好)`。
- 流行度偏差的因果语言：曝光是**干预（treatment）**，交互是**结果（outcome）**，
  观测数据只包含「被干预过」的样本。IPS 用 `1/P(曝光)` 加权可恢复无偏估计，
  但方差极大，实际用**截断 IPS / 自归一化 IPS** 换偏差-方差平衡。

### 📚 考研者视角

- 自命题 AI 专业课常考：**协同过滤的分类与预测公式**。要能写清
  「基于用户 / 基于物品 / 基于模型」三类的区别，以及 user-based 的预测式
  `r̂_ui = μ_u + 加权平均(r_vi − μ_v)`。
- 相似度计算是标准计算题：给出小矩阵，要求算余弦、Pearson、Jaccard，
  并说明** Pearson 本质是中心化后的余弦**。注意 Pearson 的分母是**共同评分项**上的离差，
  不是全部评分——这是最常见的扣分点。
- 冷启动的标准答法要分「用户冷启动 / 物品冷启动 / 系统冷启动」，
  并各给 2 个方案（热门、内容、社交、迁移、bandit），只答「用内容特征」拿不到满分。
- 易混口径：**RMSE 小 ≠ 推荐好**。评分预测衡量「打分准不准」，
   Top-N 推荐衡量「排序对不对」；一个模型可以在 RMSE 上赢、在 Recall@K 上输。
  答题时要先声明任务口径（评分预测 vs Top-N 推荐）。
