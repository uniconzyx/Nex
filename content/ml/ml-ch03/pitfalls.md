# ml-ch03 易错点：神经网络训练里的六个真实坑

1. **忘记清零梯度，第二次迭代开始梯度越滚越大**
   - 现象：第一个 step loss 正常，之后 loss 忽大忽小甚至爆炸；打印梯度范数发现它随 step 线性增长。
   - 根因：框架的 `.grad` 默认**累加**而不是覆盖。PyTorch 里忘了 `optimizer.zero_grad()`，上一批的梯度会一直加进来；手写 NumPy 时把 `dW` 写成 `+=` 又没有每轮置零，同理。
   - 正确做法：每个训练 step 固定顺序 `zero_grad → forward → loss → backward → step`；手写时每轮重新创建梯度数组，或显式 `dW.fill(0)`。用梯度累积模拟大 batch 时，累加是故意的，但要在 `step` 后清零。

2. **softmax / sigmoid 直接算 exp，遇到大 logits 输出 nan**
   - 现象：小批量训练正常，某些样本的 logits 到几百后 loss 突然变成 `nan`，之后所有参数都变 `nan`。
   - 根因：`exp(1000)` 在 float64 下溢出为 `inf`，`inf/inf` 得到 `nan`；`log(0)` 同理。交叉熵里直接 `-log(p)` 也会在 `p=0` 时炸掉。
   - 正确做法：softmax 先减最大值 `z - z.max()`；交叉熵用 log-sum-exp 形式，或把概率 clip 到 `[1e−12, 1−1e−12]`；混合精度训练时把 softmax/CE 放在 float32。不要用 `1/(1+exp(-z))` 裸写 sigmoid，用 `np.expit` 或先 clip。

3. **输出层与损失错配：回归套 sigmoid、分类用 MSE**
   - 现象：房价/销量回归的预测值永远落在 (0,1)；分类任务训练慢、概率校准差，饱和样本几乎不更新。
   - 根因：sigmoid 的值域是 (0,1)，套在回归输出层等于给预测加了硬截断；MSE 假设高斯噪声，对 0/1 标签是错误模型，且梯度含 `p(1−p)` 饱和因子。
   - 正确做法：按任务配对——回归 linear + MSE/MAE，二分类 sigmoid + BCE，多分类 softmax + CE，多标签每维 sigmoid + BCE。改输出层时同步改损失和标签形状，三者是一组，不能只改一个。

4. **训练时开 Dropout，推理时忘了关**
   - 现象：训练 loss 正常下降，验证/上线指标明显变差且每次推理结果都不一样；同一输入连续两次预测不同。
   - 根因：Dropout 只在训练时随机丢弃并按 `1/(1−p)` 缩放；推理时必须用完整网络、不做缩放。框架里忘记 `model.eval()`（或手写代码没传 `training=False`）就会继续随机丢弃。
   - 正确做法：把「训练/推理模式」做成显式参数并在验证前切换；为模型加一个单元测试：eval 模式下同一输入两次前向必须逐位相同。BatchNorm 的 running stats 同理，冻结层时也要冻结它的统计量。

5. **学习率过大导致发散，却去改模型结构**
   - 现象：训练几十步后 loss 从 0.7 跳到 50、再跳到 `inf`；第一反应是「层数不够/数据有问题」，于是加层、换激活，问题依旧。
   - 根因：步长超过损失曲面的局部曲率上界（约 `2/L`），参数在谷底两侧反复弹跳，最终溢出。深层网络/无归一化时曲率更大，容忍的学习率更小。
   - 正确做法：先用小学习率（如 `1e−3`）确认模型能过拟合一个 batch，再按 3 倍或 10 倍扫描；出现发散先降 10 倍并加梯度裁剪（按范数裁剪），而不是改结构。记录每次实验的 lr，别靠记忆。

6. **用 accuracy 或训练 loss 判断模型好坏**
   - 现象：1% 正例的欺诈检测 accuracy 99%，上线后一个欺诈都没抓到；或者训练 loss 降到 0.001，验证集一塌糊涂，仍认为「模型学得很好」。
   - 根因：不平衡时全判负就能拿到高 accuracy，它对少数类完全不敏感；训练 loss 只反映对训练集的拟合，不携带泛化信息，越低越可能是记住了噪声。
   - 正确做法：不平衡任务看 PR 曲线、P/R/F1 与混淆矩阵的绝对错误数，并按业务成本选阈值；模型选择只看独立验证集（或交叉验证）的指标，训练 loss 只用于排查优化是否正常。测试集只在最后用一次。
