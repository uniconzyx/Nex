# ml-ch05 易错点：决策树与集成学习的六个认知陷阱

1. **直接用信息增益切分连续特征或 ID 列，模型「精准」得可疑**
   - 现象：某列几乎是唯一 ID，单独用它切一刀训练集就纯净了，信息增益遥遥领先，模型在训练集上完美、在测试集上随机。
   - 根因：信息增益 `Gain = H(D) − H(D|A)` 对「把样本切得更碎」有系统性偏好——取值数 K 越大，条件熵 `H(D|A)` 越容易趋小（ex01 实测：outlook 的 IV=1.5774 最大，增益率把它从 Gain 0.2467 压到 0.1564，与 humidity 的 0.1518 几乎打平）。
   - 正确做法：类别/ID 列不进分裂特征；连续特征先分箱或改用增益率/基尼；上线前打印每个特征的 IV，把 IV 接近 `log n` 的列挑出来单独审。

2. **树不设深度、不做后剪枝，拿训练集全纯净当「模型很好」**
   - 现象：`max_depth=None` 一路长到叶子纯净，训练 MSE≈0，验证误差却随深度指数上升。
   - 根因：CART 默认目标就是「把训练集分纯」，不剪枝的树把噪声当规律逐层编码；ex04 实测后剪枝能把测试 MSE 明显压回来，代价是树小一个量级。
   - 正确做法：至少做一层后剪枝（如代价复杂度剪枝，扫 `ccp_alpha` 画验证曲线）；深度/叶最小样本数是预剪枝的廉价替代，但省掉的检查迟早在测试集上还回来。

3. **把 OOB 当测试集反复看——选完超参再用它报指标**
   - 现象：先用 OOB 挑 `mtry`/树数，再把同一个 OOB 准确率写进报告，数字漂亮得不像话。
   - 根因：OOB（out-of-bag）是袋外样本估计，约 36.8% 的样本天然不作任何一棵树的训练集，但它是**被用来做过超参搜索**的验证集，不再是独立的测试集估计——选择偏差会让报告值乐观。
   - 正确做法：OOB 只用于调参和早停；最终报数必须留一层从头到尾没参与任何决策的测试集（或嵌套 CV），两者差多少就是选择偏差的大小。

4. **GBDT 加大学习率却不减树数，或者加大树数却不降学习率**
   - 现象：`n_estimators=1000` 直接开跑，训练 loss 还在降但验证 loss 早开始反弹，调参全靠运气。
   - 根因：加法模型 `F_m = F_{m−1} + η·h_m` 里，学习率 `η` 是每棵树的步长；`η` 不变、树数翻倍等于步长总和翻倍，必然过冲。ex08 实测同一目标下 `η=0.3` 的收敛速度约为 `η=0.1` 的 3 倍，但验证误差的最低点也更差。
   - 正确做法：`η` 与树数**反向联动**（`η`↓则树数↑），用验证集早停定树数；先固定 `η=0.1` 量级找早停点，再考虑动 `η`。

5. **随机森林的 `mtry` 照搬 `√d` 不调，还指望「树多力量大」**
   - 现象：特征高度相关时把 `mtry` 从 10 降到 2，树间相关系数只从 0.776 动到 0.747，集成 MSE 反而从 0.867 涨到 0.927。
   - 根因：方差公式 `Var = ρσ² + (1−ρ)σ²/B` 只说明「降 ρ 有用」，没保证「降 mtry 一定降测试误差」——当多个特征是同一个潜在因子的副本时，换特征测的还是同一件事，ρ 小降幅抵不过单树偏差上升（ex06 实测）。
   - 正确做法：`mtry` 当 U 形旋钮用 OOB 扫，不照搬文献默认值；特征间存在真实竞争时子采样才大幅降 ρ，先看特征相关性再调参。

6. **用不纯度重要性直接删特征，噪声特征被「保送」**
   - 现象：随机森林的重要性榜单上前几名有个业务上完全说不通的特征，删了模型指标就掉。
   - 根因：不纯度重要性对**取值多/基数高/连续**的特征有系统性虚高——分裂机会多、偷看标签的机会就多；ex07 实测纯噪声特征在纯随机数据上也能排进前列，高基数特征的偏差尤其明显。
   - 正确做法：换**置换重要性**（打乱该列看 OOB/验证指标掉多少）或按分组做重要性；删特征必须看在留出集上的指标变化，不能看不纯度榜单。
