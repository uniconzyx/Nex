# 索引体系：基本切片、布尔掩码与花式索引

## 1. 三种索引，三种语义

| 类型 | 写法 | 结果 | 是否 view |
|---|---|---|---|
| 基本切片 | `a[1:5]`、`a[::2]`、`a[..., 2]` | 规则子集 | **view** |
| 布尔掩码 | `a[a > 0]`、`a[mask]` | 满足条件的元素（一维） | **copy** |
| 花式索引 | `a[[0, 3, 7]]`、`a[rows, cols]` | 按指定下标挑元素 | **copy** |

**为什么布尔/花式一定是 copy**：结果的元素个数与排列方式都无法用「起点 + 步长」描述，
NumPy 只好新开内存把挑出来的值拷进去。这也意味着：

```python
a[a > 0] = 99     # 这不是「赋值到视图」，而是 a.__setitem__(mask, 99)，能正常改到 a
b = a[a > 0]
b[:] = 99         # b 是 copy，改 b 不会影响 a
```

第一行能生效是因为它走的是 `__setitem__` 而非「先取 view 再赋值」——**这两者语义不同**，
是初学者最常混淆的地方。

## 2. 花式索引的配对规则（容易记反）

```python
a.shape == (3, 4)
a[[0, 2], [1, 3]]    # 结果是 [a[0,1], a[2,3]] 两个标量 —— 按下标「配对」取点
a[[0, 2]][:, [1, 3]] # 或 a[np.ix_([0,2],[1,3])] —— 取子矩阵 shape (2,2)
```

**规则**：多个花式索引**写在同一对方括号内**时是「配对取点」；
想要「取行列交叉的子矩阵」必须用 `np.ix_` 或分两次索引。

## 3. 布尔索引的组合与陷阱

```python
mask = (a > 0) & (a < 10)      # ✓ 用 & 且必须加括号（& 优先级高于比较？不，是低于）
# 错误写法：(a > 0) and (a < 10)  → ValueError: 真值不明确
```

**必须用 `&` `|` `~`（按位运算符），不能用 `and` `or` `not`** —— 因为后者会试图把整个数组
转成单个 bool，而数组的真值是未定义的。而且因为 `&` 的**优先级低于比较运算符**… 实际是
`&` 优先级**高于**比较？——总之**一律加括号**，这是唯一安全的做法。

## 4. 用布尔索引做数据清洗（数据科学日常）

```python
data = data[~np.isnan(data)]                 # 去 NaN
data = data[(data > lo) & (data < hi)]       # 截尾去异常值
labels = labels[np.isin(labels, valid_set)]  # 按白名单过滤
```

**`np.isnan` / `np.isfinite` / `np.isin` / `np.unique(return_counts=True)`** 是清洗四件套。

## 5. np.where 的两种用法

```python
np.where(cond)           # 返回满足条件的下标元组，等价于 np.nonzero(cond)
np.where(cond, x, y)     # 三元选择：cond 为真取 x，否则取 y（支持广播）
```

第一个用法在做「找出异常值位置」时很有用：

```python
rows, cols = np.where(a > threshold)
```

## 6. 视图 vs 拷贝的性能含义

- 切片（view）几乎零成本 → 可以放心地在大数组上取窗口；
- 花式索引（copy）会分配新内存 → 在循环里反复花式索引是性能杀手；
  优化手段是**一次性算好索引数组**，或用 `np.take(a, idx, axis=0)`（语义相同但有时更快）。

## 7. 一句话总结

> **基本切片给 view（省内存但会污染源），布尔/花式索引给 copy（安全但费内存）；
> 多个花式索引同框是「配对取点」，要取子矩阵请用 `np.ix_`。**

## 三视角解析

### 🧑‍💻 程序员视角
- 数据清洗日常：布尔掩码筛选、`np.where` 做条件替换、`np.isnan` 配合掩码处理缺失值。
- 性能提醒：花式索引会**物化结果**，在百万级数据上频繁使用会造成额外内存拷贝；必要时改用布尔就地赋值（`a[mask] = 0`）。
- 调试习惯：先看 `.shape` 再看值，避免形状错位导致的静默错误。

### 🎓 博士生视角
- 三种索引的语义分野：**基本索引 → 视图**（可用 strides 描述）、**花式索引 → 拷贝**（结果索引不连续）、**布尔索引**等价于 `compress` + 花式索引。
- 布尔索引的实现是「先算掩码的累计和与位置映射，再 gather」，因此需要两次遍历——这是它比基本切片慢的原因。
- 从类型论看，「索引」是一种**形状变换函数**，NumPy 用「能否用元数据描述」来决定是共享还是复制，这与惰性求值/共享结构的设计一脉相承。

### 📚 考研者视角
- 与 408 关联：数组的**顺序存储**与**随机访问**、查找算法中的「筛选/过滤」思想。
- 若专业课含数据结构实验/机试，注意「就地修改 vs 返回新数组」会在题目要求中明确写出，别默认。
- 记忆锚点：**基本切片是视图，花式索引是拷贝**；**布尔索引 = 掩码 + 花式索引，代价更高**。
