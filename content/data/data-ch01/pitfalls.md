# data-ch01 · NumPy —— 高频陷阱

1. **以为切片是拷贝，改了切片污染源数据** —— `b = a[::2]` 是 view，`b[:] = 0` 会改到 `a`。判断用 `b.base is a` 或 `np.shares_memory(a, b)`；要独立副本请显式 `.copy()`。

2. **用 `and` / `or` 组合布尔掩码** —— 数组真值未定义，会抛 `ValueError: 真值不明确`。必须用按位运算符 `&` `|` `~`，且每个子表达式都要加括号。

3. **`a[idx] += 1` 在 idx 有重复时结果偏小** —— 它展开为「取值 → 加 → 赋值」，重复索引的多次加法都基于同一个旧值，最后只写回一次。正确写法是 `np.add.at(a, idx, 1)`。

4. **聚合后忘记升维导致广播失败** —— `a.mean(axis=1)` 得到 shape `(n,)`，直接与 `a`（shape `(n,m)`）相减会报错。要用 `a - m[:, None]`，或聚合时直接 `keepdims=True`。

5. **以为 `(3,)` 能和 `(3,4)` 广播** —— 广播从**尾维**对齐，`(3,)` 的尾维 3 与 `(3,4)` 的尾维 4 不匹配，必然报错。要在尾部插维：`v[:, None]`。

6. **`a[[0,2],[1,3]]` 想要子矩阵却拿到两个标量** —— 多个花式索引在同一对方括号内是「按下标配对取点」。取子矩阵应用 `a[np.ix_([0,2],[1,3])]` 或分两次索引。

7. **链式运算产生大量临时数组撑爆内存** —— `a*b + c/d - e*f` 会产生多个与操作数等大的临时数组。大数组应分块处理，或用 `out=` 参数复用缓冲区。

8. **以为 `a.T` 会搬数据** —— 转置只是交换 strides，是 O(1) 的 view。但它会让数组失去 C 连续性，后续逐元素运算可能变慢；需要连续布局时再 `.copy()`。

9. **`np.where` 的两个分支都会被求值** —— 它不像 Python 的三元表达式那样惰性，若某分支会除零仍会触发警告。安全写法是 `np.divide(x, y, out=..., where=y!=0)`。

10. **用 float32 做大规模累加却不检查误差** —— float32 只有约 7 位有效数字，累加 10^8 个数误差可达 1e-2 量级。NumPy 的 `np.sum` 用成对求和（误差 O(log n)）好于朴素循环，但关键场景仍应升到 float64。

11. **`a.astype(np.float64)` 默认产生拷贝** —— 可用 `copy=False` 让它尽量返回 view。反之若你就是要独立副本，别依赖默认行为，显式写 `.copy()` 更清晰。

12. **误以为向量化永远更快** —— 元素数少于约 1000 时，NumPy 的固定调用开销（约 1 微秒）占比过大，纯 Python 循环可能反而更快。
