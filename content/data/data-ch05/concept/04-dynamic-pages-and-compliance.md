# 动态页面、工程化与合规红线

前面三节解决"怎么拿到且解析对"。这一节解决两件更上层的事：**动态内容怎么拿**，以及**拿到什么程度就该停**。

## 一、动态渲染：应对顺序不能颠倒

### 🧑‍💻 程序员视角

页面看起来"有数据但抓不到"，按下面的顺序排查，**不要一上来就上浏览器内核**：

1. **先看 Network 面板**：数据是 XHR/Fetch 返回的 JSON 吗？是 → 直接请求接口，**问题结束**。这是绝大多数情况。
2. **再看是不是服务端渲染（SSR）**：`view-source` 里能看到数据 → 数据在 HTML 里，只是你的选择器写错了。
3. **再看有没有初始数据注入**：`<script>window.__DATA__ = {...}</script>` → 用正则从 `<script>` 里抠出 JSON 即可，仍无需浏览器。
4. **只有前三条都不成立**（数据由 JS 运行时计算/加密后渲染），才考虑**渲染引擎**（如 Playwright/Selenium，或直接用其底层内核）。

成本对照很悬殊：接口请求是毫秒级、可控、可并发；浏览器内核是**百毫秒到秒级**、内存占用高、还要处理页面加载时序。

### 🎓 博士生视角

这一顺序的合理性来自**"计算发生在哪一侧"**这一基本判断：
SSR 把数据注入 HTML，属于服务端计算；CSR（客户端渲染）把数据获取与 DOM 构造放在浏览器运行时。
采集器若用渲染内核，本质是**在本地复现客户端运行时环境**——这带来三个不可避免的代价：环境差异（版本/字体/时区）、**不确定性**（异步加载完成时刻不固定）、资源成本（每页一个浏览器上下文）。

因此从**可复现性**角度，接口路径不仅更快，而且**输出确定性更高**——这对数据管道是决定性优势。

### 📚 考研者视角

配套考点：**B/S 架构与前后端分离**。问"为什么现代网页抓不到数据"，标准答法是"数据由前端 JS 异步请求接口后渲染，HTML 只是空壳"。
进一步追问"怎么解决"，答案要体现**优先级**："优先分析 XHR 接口直接请求；不得已才引入无头浏览器"——只答"用 Selenium"会显得缺乏工程判断。

## 二、工程化四件事：去重、限速、增量、可恢复

### 🧑‍💻 程序员视角

1. **去重**：用**规范化后的 URL** 或内容摘要作键。
   - URL 规范化要处理：大小写（host 不敏感、path 敏感）、去掉 `#fragment`、**查询参数排序**、去掉无意义的跟踪参数（`utm_*`）、解析相对链接。
   - 大站点用布隆过滤器省内存，代价是**有误判**（可能漏抓），要能接受。
2. **限速**：按域名独立限速，遵守该站 `robots.txt` 的 `Crawl-delay`。并发不等于可以打快——**并发数 × 单域名**要一起管。
3. **增量**：存 `ETag`/`Last-Modified`，下次带条件请求，304 就跳过。
4. **可恢复**：请求结果落盘（原始 `content` + 元数据），抓取队列可持久化，支持断点续抓。**先存原始响应再解析**，这样解析规则改了不用重抓。

### 🎓 博士生视角

把采集器看成一个**分布式（多站点）爬取调度问题**，它的三个约束互相牵制：
- **礼貌性约束**（每站点速率上限）：来自 `robots.txt` 与公地悲剧；
- **新鲜度约束**（页面变化频率）：决定重访周期；
- **覆盖率约束**（别漏重要页面）：决定优先级排序（常见做法是按**入链数**近似 PageRank 排序）。

经典结论是：在单一站点上，**重访间隔的最优值与页面变化率相关**，且"变化快的页面"往往也"被引用最多"，因此按入链数优先 + 自适应重访（变化多则缩短间隔）是常见折中。

### 📚 考研者视角

配套考点：**布隆过滤器的原理、误判率与空间权衡**——k 个哈希函数、m 位数组、n 个元素，误判率约 $(1-e^{-kn/m})^k$。
易错口径：**布隆过滤器只说"可能存在"或"一定不存在"**，**没有假阴性、只有假阳性**。反过来用（比如"一定不存在"当判据）才是安全的。

## 三、合规红线：这一节和技术同等重要

### 🧑‍💻 程序员视角

采集前必须过的四道关，按顺序：

1. **`robots.txt`**：先取 `https://站点/robots.txt`，用最长匹配规则判断目标路径是否被 `Disallow`；遵守其中的 `Crawl-delay`。
   ```python
   from urllib import robotparser
   rp = robotparser.RobotFileParser()
   rp.set_url("https://example.com/robots.txt")   # 实际取回后 rp.parse(lines)
   if not rp.can_fetch(USER_AGENT, url):
       return None      # 不允许就不抓，没有"但是"
   ```
   ⚠️ **`robots.txt` 是"可否抓取"的约定，不是授权书**——它说 `Allow` 不代表你可以随意使用内容。
2. **频率控制**：设 `Crawl-delay` 或更保守；并发分域名隔离；夜间抓取。
3. **版权与数据库权利**：文章正文、图片、数据库内容通常受保护。**只取你需要的字段**（元数据、统计量），不整体复制内容。
4. **个人信息**：涉及姓名/手机号/身份证/住址/位置轨迹等**个人信息**时，须有合法性基础与最小必要原则。

**绝对红线：不绕过技术措施。** 包括但不限于：破解登录/验证码、绕过访问控制、伪造身份规避封禁、破解接口签名与加密参数。这不是"技术难度问题"，而是"能不能做的问题"。

### 🎓 博士生视角

合规的底层逻辑是**"可抓取"≠"可使用"**：`robots.txt`（RFC 9309）只处理**抓取许可**，而内容的使用受**版权法**约束，个人数据受**个人信息保护法**约束。
三者是**独立**的约束层，通过一层不豁免另一层——这是最常被误读的地方。

工程上的推论是：**"最小必要"应当落实为代码约束**——采集器应当只声明实际需要的字段，对敏感字段做**白名单**而非黑名单过滤（黑名单总会漏）。

### 📚 考研者视角

答题口径（合规类问题通常出现在算法岗/数据岗的开放题）：
1. 先答**法律/规范依据**（`robots.txt` 协议、版权、个人信息保护）；
2. 再答**工程落实**（限速、UA 标识、条件请求、字段最小化、原始数据留存与删除策略）；
3. 最后答**边界判断**（公开数据 ≠ 可任意使用；技术可行 ≠ 合规）。

关键句式：**"技术能力不构成合规理由"**——这是这类题的标准落脚点。

## 四、把合规检查做成代码

### 🧑‍💻 程序员视角

把"人应该记得的事"变成"程序会拦住的事"：

```python
FORBIDDEN_FIELDS = {"id_card", "phone", "address", "real_name"}   # 个人信息白名单外字段

def guard(record: dict, cfg: dict) -> dict:
    out = {k: v for k, v in record.items() if k in cfg["allowed_fields"]}   # 白名单
    leaked = FORBIDDEN_FIELDS & set(out)
    if leaked:
        raise ValueError("命中个人信息字段，拒绝落盘: %s" % sorted(leaked))
    if not cfg.get("robots_ok", False):
        raise RuntimeError("未通过 robots 检查，禁止采集")
    return out
```

三条纪律：**白名单**优于黑名单、`robots_ok` 是**前置开关**（不是可选项）、敏感字段**拒绝落盘**而不是"提醒一下"。

### 🎓 博士生视角

把合规约束**代码化**是"合规前置"（compliance by design）的最小实现：把检查从"人工复核环节"前移到"运行时断言"。
这在工程上有明确收益——人工复核会疲劳、会遗漏，而断言是**确定性**的。

进一层的做法是**可审计**：记录每次请求的 `robots` 判定结果、限速参数、字段裁剪日志。合规事件发生时，"能证明当时是守规矩的"和"事实上守规矩"同样重要。

### 📚 考研者视角

关联考点：**软件工程中的"防御性编程"与"失败即停止"（fail-fast）**。
把合规检查类比**参数校验**：越早失败越好，代价越小。答题时给出"检查前移"的收益（避免脏数据流入下游）会很加分。

## 三视角解析

### 🧑‍💻 程序员视角
采集器的成熟度看三件事：**失败可恢复**（原始响应落盘 + 队列持久化）、**速率可配置**（每域名独立）、**合规可验证**（`robots` 判定留痕）。加功能之前先把这三件补齐。

### 🎓 博士生视角
把"动态渲染 → 接口"的降级顺序，和"合规检查 → 代码约束"的前移放到一起看，会发现它们是同一个原则：**优先选择确定性更高、代价更低的方案**，把不确定性留给真正无法避免的地方。

### 📚 考研者视角
本章开放题的得分结构：**技术方案（分优先级）+ 工程保障（去重/限速/增量）+ 合规边界（依据 + 落实 + 边界判断）**。三段都答到，才是完整答案。
