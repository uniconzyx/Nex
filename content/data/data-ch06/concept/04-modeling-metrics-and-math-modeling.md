# 建模流程、评价指标与数学建模方法论

前四章把数据变成了可用的特征表。这一章回答最后三个问题：**怎么建、怎么评、怎么写成一份站得住的答案**。

## 一、建模流程：八步不可跳

### 🧑‍💻 程序员视角

```
① 明确目标与评价口径  → ② 划分数据（时间序务必按时间切）
   → ③ 建立基线（先跑最笨的模型） → ④ 迭代特征与模型
   → ⑤ 交叉验证调参 → ⑥ 在留出集上评估 → ⑦ 误差分析
   → ⑧ 结论 + 局限 + 灵敏度
```

两个最容易被跳掉、却最重要的步骤：
- **③ 基线**：不建基线就无法回答"模型有没有用"。回归基线是"用均值预测"，分类基线是"用多数类预测"。
- **⑦ 误差分析**：看哪些样本错得最厉害、错在哪个子群。**这一步的收益通常大于换模型**。

### 🎓 博士生视角

"先建基线"有明确的方法论依据：它把问题转化为**相对改进**的度量，从而消除"任务本身的可预测性上限"对绝对指标的干扰。
一个 $R^2=0.3$ 的模型在噪声极大的任务上可能是**很好的**，在高可预测任务上是**失败的**——只有基线能区分这两种情形。

误差分析则对应**偏差-方差分解**的实证：若训练误差低而验证误差高 → 方差主导（过拟合，需要正则或更多数据）；
若两者都高 → 偏差主导（欠拟合，需要更强模型或更好特征）。这个分解把"调什么"从试错变成推理。

### 📚 考研者视角

配套考点：**过拟合与欠拟合的判别与解决**。标准答法：
- 过拟合（训练好、测试差）→ 增数据、正则化（L1/L2）、降复杂度、早停、集成；
- 欠拟合（两者都差）→ 增特征、升复杂度、减正则。

易错口径：**"模型越复杂越好"是错的**；**"训练集准确率"不能作为评价指标**。

## 二、回归评价指标：五个数各自的脾气

### 🧑‍💻 程序员视角

| 指标 | 公式 | 单位 | 对异常值 | 直觉 |
|---|---|---|---|---|
| **MAE** | $\frac1n\sum\lvert y_i-\hat y_i\rvert$ | 同 $y$ | 稳健 | "平均偏差多少" |
| **MSE** | $\frac1n\sum(y_i-\hat y_i)^2$ | $y^2$ | **敏感**（平方放大大误差） | 优化目标常用 |
| **RMSE** | $\sqrt{MSE}$ | 同 $y$ | 敏感 | 可解释的大误差惩罚 |
| **R²** | $1-\frac{SS_{res}}{SS_{tot}}$ | 无量纲 | 视情况 | "比用均值好多少" |
| **调整 R²** | 对特征数惩罚的 R² | 无量纲 | — | 比较不同特征数的模型 |

三条纪律：
1. **RMSE ≥ MAE 恒成立**（由方差非负），两者差得越多说明**误差分布越不均匀**（存在少数大误差）；
2. **R² 可以为负**——比"直接用均值预测"还差时就是负的，这不是 bug；
3. **报告口径必须写明**：RMSE 是在哪个数据划分上算的、$y$ 的单位是什么。

### 🎓 博士生视角

MAE 与 RMSE 的差别在于**隐含的损失函数**：MAE 对应**中位数**回归（最小化绝对偏差得到条件中位数），
RMSE 对应**均值**回归（最小化平方偏差得到条件均值）。因此在**右偏的目标变量**上，用 MAE 优化会偏向低估（更接近中位数），
这与"用户看到的是平均数"的业务口径可能不一致——指标选择本身就在选择**你要预测哪个统计量**。

R² 的定义 $\frac{SS_{res}}{SS_{tot}}$ 中 $SS_{tot}$ 用的是**测试集自身的均值**，因此 R² 依赖测试集分布；
这也解释了它为何可以为负（当模型偏差比"测试集均值"这个常数预测器还大时）。

### 📚 考研者视角

配套考点：**最小二乘法的原理与残差平方和**、**决定系数 R² 的含义**（回归平方和占总变差的比例）。
标准问法："R²=0.8 说明什么？"→ 答"因变量变差的 80% 可由回归模型解释"。

易错口径：**R² 高不代表模型正确**（可能存在自相关、异方差、遗漏变量）；**加入无关变量 R² 只会不降**，所以比较模型要看**调整 R²**。

## 三、分类评价指标：准确率的陷阱

### 🧑‍💻 程序员视角

先有**混淆矩阵**（以正类为关注对象）：

|  | 预测正 | 预测负 |
|---|---|---|
| **实际正** | TP | FN |
| **实际负** | FP | TN |

由此定义：精确率 $P=TP/(TP+FP)$、召回率 $R=TP/(TP+FN)$、$F1=2PR/(P+R)$、准确率 $=(TP+TN)/n$。

**准确率的陷阱**：若正类只占 1%（欺诈检测），把所有样本判为负类就有 **99% 准确率**，但召回率为 0。
所以不平衡场景要看 **F1 / 召回率 / AUC**，而不是准确率。

两两权衡：
- **精确率优先**：误报代价高（垃圾邮件误杀正常邮件）；
- **召回率优先**：漏报代价高（疾病筛查、欺诈初筛）；
- **F1**：两者调和平均，综合但**隐含"两者同等重要"**的假设。

**AUC** 的含义要背准：随机取一个正样本和一个负样本，**正样本得分高于负样本的概率**。
所以 AUC=0.5 等于随机猜，AUC=1 是完美排序。它衡量的是**排序能力**，与阈值无关——这是它相对 F1 的最大优势（F1 依赖阈值选择）。

### 🎓 博士生视角

精确率与召回率的**不可兼得**是同一个分布上不同阈值处的取值，二者随阈值单调反向移动；因此"提升召回"必然以"降低精度"为代价（在模型固定时）。
F1 作为调和平均，对**较小值更敏感**（若 $P=0.1,R=0.9$，$F1\approx0.18$ 而非 0.5），这使它天然惩罚"偏科"。

AUC 等价于 **Mann-Whitney U 统计量**归一化后的值，这是它"排序概率"解释的严格来源。
一个重要局限：**AUC 对类别极为不平衡且关注少数类时可能过于乐观**——它把大量易分的负样本也算进排序对里，
因此不平衡场景常改用 **PR-AUC（平均精度 AP）**，因为 PR 曲线只关注正类。

### 📚 考研者视角

配套考点：**混淆矩阵与各指标计算**，常以"给一组 TP/FP/FN/TN 求各指标"的形式出现。
答题要点：**先写公式再代数**，并说明"精确率看预测、召回率看真实"这一记忆锚点。

易错口径：**精确率与召回率的分母不同**——$P$ 的分母是"预测为正的总数"，$R$ 的分母是"实际为正的总数"。互换分母是最常见的算错原因。

## 四、数学建模：把开放题答成规范报告

### 🧑‍💻 程序员视角

数学建模题的评分结构几乎是固定的五段，缺一段就明显掉档：

1. **问题重述与抽象**：把文字题变成"已知 / 求 / 约束"三件事；
2. **假设与符号说明**：每条假设都要说明"为什么可以这样假设"，符号列表必须齐全（后文出现的每个符号都在表里）；
3. **模型建立**：写出数学形式（目标函数 + 约束），说明每一项的物理/业务含义；
4. **模型求解**：算法与步骤（迭代式/解析解/数值方法），并给出**结果数值**；
5. **检验与灵敏度分析**：结果是否合理（量纲、数量级、边界情形），**关键参数扰动后结论是否稳定**。

第 5 段是区分档次的段落——它回答的是"你的结论有多可靠"，而不是"你算出了什么"。

### 🎓 博士生视角

灵敏度分析（sensitivity analysis）在方法论上是**对模型输出关于参数的不确定性传播**：
局部方法（单参数偏导、一次一因子 OFAT）计算便宜但**无法捕捉参数间交互**；
全局方法（如 Sobol 指数）能分解各参数及其交互对输出方差的贡献，代价是计算量大。

工程上常用的判据是**弹性（elasticity）** $\frac{\partial y}{\partial x}\cdot\frac{x}{y}$，即"参数的相对变化引起输出的相对变化"，因为它**无量纲、可跨参数比较**。
若某参数的弹性远大于其他参数，说明模型结论对该参数高度敏感，必须给出该参数的取值依据与置信范围。

### 📚 考研者视角

配套考点（数模竞赛与部分院校复试）：**优化模型的建立（线性规划/非线性规划/整数规划）**、**最小二乘拟合**、**差分与微分方程建模**。
标准答法结构：**假设 → 符号 → 模型 → 求解 → 检验**，即所谓"三段式加两道关"。

加分点：**明确写出模型适用边界**（假设立场），并指出"若放宽某假设，模型应如何修改"——这体现的是建模素养而非套公式能力。

## 三视角解析

### 🧑‍💻 程序员视角
建模的验收闭环是：**基线 → 指标（写明口径与划分）→ 误差分析 → 灵敏度**。任何一处缺失，结论就只能当"参考值"而非"依据"。

### 🎓 博士生视角
指标选择即损失函数选择，而损失函数决定模型逼近**哪个条件统计量**（均值/中位数/分位数）。所以"用什么指标"从来不是展示问题，而是**目标函数定义**问题。

### 📚 考研者视角
本章笔面高价值点：**过拟合/欠拟合、R²、混淆矩阵四指标、精确率与召回率的权衡、AUC 的含义**；
数模方向还要加**模型假设与灵敏度分析**。共同要求：说得出公式来源与适用边界。
