# 内存布局（C/F order）与 dtype 精度溢出

## 一、C order 与 F order：连续性与遍历缓存友好性

- **C order（行优先，NumPy 默认）**：最后一个轴在内存中最连续；按行遍历最快。
- **F order（列优先，Fortran/MATLAB/R 风格）**：第一个轴在内存中最连续；按列遍历最快。
- `a.T` 交换 strides，**不搬数据**，但会破坏 C 连续性（变成 F 连续）。

```
a = np.arange(12).reshape(3,4)
a.flags['C_CONTIGUOUS']       # True
a.T.flags['F_CONTIGUOUS']     # True（转置后是 F 连续）
a.T.flags['C_CONTIGUOUS']     # False
```

### 🧑‍💻 程序员视角
- **遍历顺序要匹配布局**：对 C 数组用 `for row in A`（按行）快，用 `for col`（按列跳跃）慢——因为它违反内存顺序、cache 命中率低。实测连续行遍历可比跳跃列遍历快 1.5~3 倍（见 examples/ex14）。
- **对外接口的布局约定**：C 扩展 / BLAS / Cython 通常要 C 连续，跨语言（调用 Fortran 库、MATLAB 数据）要注意 F 连续；不确定就用 `np.ascontiguousarray` 规整，避免底层被迫拷贝。
- **工程惯例**：做「逐列聚合」（每列求均值）且数组是 C 顺序时，考虑转成 F order 或一次性 `mean(axis=0)`（ufunc 内部已针对布局优化），别手写按列循环。

### 🎓 博士生视角
- 连续性决定 **cache line 利用率**：连续遍历时 CPU 预取器可提前加载后续 cache line，每次访问命中；跳跃访问（步长 = 一整行字节）几乎每次都触发 cache miss（一次 miss ~100 时钟周期），吞吐骤降。
- transpose 的 O(1) 是因为只交换 strides；代价是结果失去 C 连续性，后续需要连续输入的算子（如 BLAS gemm）会先做一次「拷贝 + 重排」，这是隐藏成本。
- 现代内存层级（L1/L2/L3）对「空间局部性」高度敏感，这正是 row-major vs column-major 性能差异的硬件根源，也是为什么 Numpy/Pandas 对列式操作优化得特别好。

### 📚 考研者视角
- 数据分析岗笔面常借「**内存布局 / cache 局部性**」考计算机基础（与 408 计组交叉）：标准问法「行优先、列优先存储下，给定首地址、下标、元素大小，求某元素地址；哪种遍历 cache 命中率高？」
- **标准答法**：行优先地址 `base + (i*cols + j)*size`；连续访问（行优先数组按行、列优先数组按列）cache 命中率高，跳跃访问命中率低。
- **易错口径**：把「`a.T` 是拷贝」答成 True——**错**，转置是 O(1) 视图、不搬数据，只是换了连续性；这点与 data-ch01 的视图/拷贝考点直接衔接。

## 二、dtype 精度与溢出：float32 误差、整数回绕、浮点 inf

- `float32` 仅约 **7 位十进制有效数字**，大规模累加会累积舍入误差。
- 有符号整数溢出**回绕**（int8 的 127+1 = -128），无符号同理（uint8 的 255+1 = 0）。
- `float64` 上溢变为 `inf`，下溢变为 `0.0`。

```
a = np.array([127], dtype=np.int8) + 1      # -128（回绕）
u = np.array([255], dtype=np.uint8) + 1     # 0（回绕）
big = np.float64(1.7e308) * 10              # inf
```

### 🧑‍💻 程序员视角
- **累加要用 float64**：对 10^7 个 float32 求和，误差可达 1 量级（见 examples/ex11）；钱、计数、统计量累加一律 float64，直到确认性能瓶颈再考虑 float32。
- **索引/计数别用 int8**：样本量稍大就溢出回绕成负数，引发诡异越界；默认 int64 最安全，省内存才降位。
- **溢出不是异常**：NumPy 整数溢出**静默回绕**（不像 Python int 自动升任意精度），这是「C 语义」带来的隐蔽 bug；关键计数路径要提前 `astype(np.int64)` 并加边界断言。

### 🎓 博士生视角
- 浮点遵循 IEEE-754：float32 尾数 23 位 + 隐含位 ≈ 24 位二进制 ≈ 7 位十进制；大数加小数时小数被右规格化移位丢失低位，是**舍入误差的几何来源**。NumPy 的 `np.sum` 用**成对求和（pairwise）**把误差从 O(N) 降到 O(log N)，优于朴素累加。
- 整数回绕是**模 2^bits 的环形算术**（two's complement 下等价于模运算），属于「无未定义行为」的确定性错误，比浮点上溢更隐蔽因为没有 inf 这种显眼信号。
- dtype 是「**数值范围 × 精度 × 内存**」的三元权衡：降位省内存/带宽但牺牲精度与范围，需按数据真实分布选择。

### 📚 考研者视角
- 笔面常考「**浮点数表示与误差 / 整数溢出**」：标准问法「float32 和 float64 有效数字几位？整数 127+1 在 int8 下是多少？为什么？」
- **标准答法**：float32 ≈ 7 位、float64 ≈ 15~16 位十进制有效数字；int8 范围 [-128,127]，127+1 因补码回绕成 -128；uint8 的 255+1 回绕成 0。
- **易错口径**：以为「NumPy 整数溢出会报错」——**不会**，它静默回绕（继承了 C 语义）；这与 Python 原生 int 自动扩位不同，是面试高频挖坑点。关联 408 计组的「补码运算与溢出」考点。
