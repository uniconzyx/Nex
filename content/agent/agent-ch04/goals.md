# agent-ch04 · 需求洞察：用户故事与 AI 产品画布

> 对应图片 DAY 7（《AI 产品经理实战手册》）· 先修：agent-ch01（行业认知）· 面试权重：★★★★☆
> 说明：这一章看起来「不写代码」，但面试里它决定你能不能把技术方案讲到业务价值上；
> 而且每个结论都要能被脚本算出来，不能只是 PPT。

## 本章目标

学完你应该能：

1. **写出可验收的用户故事**：三段式（角色/目标/价值）+ 至少 2 条 Given-When-Then 验收条件，
   并能用规则检查「有没有角色、有没有阈值、有没有测量方法」。
2. **判断一个需求该落在四档中的哪一档**：确定性规则 / 分类 / 生成 / Agent，
   说清每档的成本带、稳定性与典型失败模式，避免「什么都上 Agent」。
3. **画出一页纸产品画布**：用户-场景-输入输出-失败兜底-成本-指标-不做什么-人工接管，
   并做完整性与一致性校验（例如成本 > 预算、指标没有测试口径）。
4. **做失败模式设计**：对「置信度低 / 超时 / 超范围 / 工具失败」给出用户可见的降级路径，
   并定义人工接管的触发条件与接管率上限。
5. **算清单位经济**：用 `token × 单价 × 日活 + 人工兜底` 算出单次成本、毛利率、保本用量，
   给出「这个需求经济上成不成立」的结论与 Go/No-Go 判据。

## 关键认知（本章最值钱的三句）

- **AI 项目最常见的死法不是模型不行，是需求不成立**：用户没有这个任务、任务无法判定对错、
  错了的代价高于收益——三者任一不成立，模型再强也救不回来。
- **「AI 适用性」是一条阶梯，不是开关**：能用规则就别用分类，能用分类就别用生成，
  只有「多步 + 工具 + 状态」才上 Agent；每往上一档，成本与不稳定性都上一个数量级。
- **画布的价值在「互相矛盾」暴露得早**：单次成本 0.08 元、预算 0.05 元，这种矛盾在文档里
  一眼可见；等到上线后才发现，已经是商业模型不成立。

## 技术交付物（来自 manifest.tech_load）

**需求 → 技术可行性评估表**，附一个**成本估算脚本**（token × 单价 × 日活），
算出「这个需求经济上成不成立」。

验收口径（对应 project.json 的任务）：

- 一页纸画布 9 个区块齐全，且通过一致性校验（成本 ≤ 预算、指标有口径、失败有兜底）；
- 用户故事 3 条以上，每条有 ≥2 条可测验收条件，模糊词检测得分 ≥ 80；
- 可行性评估表覆盖数据可得性、任务可判定性、错误代价三维，给出四档判定与理由；
- 成本脚本输入日活/输入输出 token/单价/接管率，输出单次成本、日/月成本、毛利率与保本用量；
- 给出 3 条「不做什么」与对应的范围变更预算（例如不超过基线 20%）。
## 与 ai 学科的分界

`ai` 学科讲「怎么把模型做出来/训出来」，本章讲「**要不要做、做到什么程度、错了怎么办、赚不赚钱**」。
同一个需求，`ai` 关心 loss 与架构，本章关心四档判定、可判定性、错误代价与单位经济。
本章不写模型代码；需要理解能力上限时，回 `ai` 学科看对应模型的能力边界。
