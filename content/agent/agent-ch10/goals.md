# agent-ch10 · AI 产品设计与评估方法论：把「感觉不错」变成分数

> 对应图片 DAY 30（Google《AI 设计原则》）· 先修：agent-ch04（提示工程与结构化输出）、agent-ch05（RAG 检索增强）· 面试权重：★★★★☆
> 说明：面试官不问你「什么是评估」，而问「50 条黄金集怎么分层才不偏、LLM 当裁判有哪些偏差、
> 离线忠实度涨了 3 分线上满意度为什么没动、A/B 要多少样本才看得见 2% 的提升」。
> 本章把两条主线（设计 + 评估）落成**可运行的指标与流程**。

## 本章目标

学完你应该能：

1. **构建一份 50 条黄金集**：按「意图 × 难度 × 知识依赖」三维分层抽样，难例挖掘有明确来源
   （线上兜底样本、人工投诉、badcase 聚类），每样本带判定口径与标注版本号，可一键重放。
2. **设计三层指标体系**：离线（准确率 / 忠实度 / 引用命中 / 拒答率）→ 线上（解决率 /
   转人工率 / 满意度）→ 护栏（延迟 / 成本 / 拒答率异常 / 安全投诉），并说清离线指标到
   线上指标的映射假设与失效条件。
3. **用 LLM-as-judge 做大规模预筛**：量化位置偏差与长度偏差，成对比较与打分口径的选择，
   用 Cohen's kappa / Spearman 相关与人工标注校准，知道 judge 自身也要被评估。
4. **把指标接进 CI 回归**：给出两比例检验的样本量与检验力计算，设定门禁阈值使误报率
   可控（如每次回归误报 ≤5%），发布前自动跑黄金集 + judge + 门禁，失败即阻断。
5. **产出一份《评估方案》文档**：含 50 条黄金样本清单、3 个核心指标（含口径与计算公式）、
   1 套回归流程（触发条件 → 跑法 → 门禁 → 告警 → 回滚），以及 Responsible AI 落地检查表
   （隐私、偏见、幻觉免责、审计日志）。

## 关键认知（本章最值钱的三句）

- **「感觉不错」是方差最大的评测指标**：demo 成功率高估 20~40 个百分点是常态
  （经验判断），因为 demo 数据分布集中、评测人自带正确答案的先验。黄金集的全部意义是
  **把评测从「演示」变成「抽样」**——分层、难例、口径、版本四件套缺一不可。
- **LLM 当裁判省的是人力，不是责任**：judge 有位置偏差（偏爱先出现的答案）、长度偏差
  （偏爱长答案）、自我偏好（偏爱自家模型输出）等系统性偏差，直接信 judge 分数等于
  把偏差写进验收标准。judge 必须先用 50~100 条人工标注样本校准（kappa ≥0.6 才敢用），
  且 judge 的 prompt、模型版本、温度要和被测系统一起版本化。
- **离线指标是代理，线上指标才是目的**：离线忠实度 +3 分而线上解决率不动，通常说明
  黄金集与线上流量分布脱节，或你优化的维度用户根本不感知。上线前先验证「离线→线上」
  的映射关系（历史回归拟合），再决定哪个指标进 CI 门禁；护栏指标永远一票否决。

## 技术交付物（来自 manifest.tech_load）

**交付物：评估框架 —— 50 条黄金集 + LLM-as-judge 校准 + 回归脚本；指标能接进 CI。**

验收口径（对应 project.json 的任务，逐条可核对）：

- `goldenset.py`：程序化生成 50 条黄金样本（固定种子可复现），按意图 × 难度 × 知识依赖
  分层，输出分层覆盖度表（每格样本数、无空格才算合格）与难例清单；
- 指标体系：至少 3 个指标带**计算公式与口径**（如忠实度 = 有引用支撑的声明数 / 总声明数；
  引用命中 = 引用文档确实包含答案的比例；拒答率 = 触发「无法回答」的样本占比），
  区分离线/线上/护栏三层；
- `judge_calibration.py`：用 LLM-as-judge（本地规则模拟，禁真实 API）对同一批评测，
  报告与人工标注的 Cohen's kappa / Spearman 相关，k < 0.6 时输出「不可用于门禁」结论；
  量化位置偏差（交换 A/B 顺序后结论翻转率）与长度偏差（分数 vs 答案长度的相关）；
- `regression.py`：可接 CI 的回归脚本——输入基线指标与新版本指标，输出两比例检验的
  p 值、效应量与门禁判定（通过/阻断），并模拟「模型未变时重复跑 200 次」统计误报率 ≤5%；
- 《评估方案.md》：50 条黄金样本清单、3 个指标、1 套回归流程、Responsible AI 检查表
  （隐私脱敏、偏见抽测、幻觉免责声明、审计日志字段）。
## 与 ai 学科的分界

`ai` 学科负责指标背后的数学与模型机理：假设检验的推导、p 值与检验力的严格定义、
LLM-as-judge 偏差的理论分析、RAG 四指标的形式化定义与语义分解算法。

本章**只要求工程口径与可运行产物**：黄金集怎么分层、指标公式怎么写进代码、
judge 怎么用人工样本校准、门禁阈值怎么定到误报率 5%、回归脚本怎么接 CI。
遇到「为什么两比例检验用这个统计量、faithfulness 的声明分解从何而来」的深层问题，
回 `ai` 学科追推导；本章停在「够用即止的原理 + 工程判据 + 可运行产物」。
