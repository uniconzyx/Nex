# agent-ch10 易错点：评估与设计流程的六个真实故障

1. **拿 demo 集通过率 92% 当验收口径，灰度后线上解决率只有 65%**
   - 现象：内部演示十问十答，评审会上一致通过；灰度 5% 流量后，转人工率
     飙升，抽查发现演示集里全是「知识库里有标准答案」的简单查询，
     真实流量里大量是多轮追问、需要拒答的越界问题。
   - 根因：demo 集是**方便采样**而非**分层抽样**（concept/01 §1）：
     分布集中、无难例、无拒答层，且评测人知道正确答案、对模糊回答更宽容。
     92% 与 65% 的差不是模型退化，是两批数据本来就不是一个分布。
   - 正确做法：按「意图 × 难度 × 知识依赖」分层建 50 条黄金集，难例占比 ≥30%，
     难例从线上兜底样本与投诉回流挖掘；上线前用黄金集出报告，
     覆盖率表里任何一层为空即不发布。口径与版本写进样本文件，报告可一键重放。

2. **LLM judge 偏爱先出现的答案，回归流程把「位置赢」当成「质量赢」**
   - 现象：两版本成对比较，judge 判新版本胜率 78%，团队发布后人工抽检
     发现真实胜率约五五开；把 A/B 顺序整体交换后重跑，judge 的结论大面积翻转。
   - 根因：judge 存在系统性**位置偏差**（concept/02 §1）：先出现的答案在
     prompt 前部，获得更多注意力与「先入为主」的分布先验。MT-Bench 类评测中
     该偏差的翻转率可达三成量级，未量化的 judge 等于带刻度的尺子。
   - 正确做法：每个样本交换位置评两次、不一致时判平局或第三方仲裁；
     翻转率 >10% 的 judge 不允许进门禁；在准入报告中固定输出
     「位置翻转率 / 长度相关 / kappa」三项（ex04/ex05 的模拟口径）。

3. **judge 模型静默升级，全场分数平移 0.6 分，历史门禁基线全部失效**
   - 现象：某次升级评测服务用的模型版本后，同一份黄金集上所有候选版本的
     judge 分数齐涨 0.5~0.7 分（5 分制），门禁基线「不低于 4.2」突然全线通过；
     三周后有人发现是尺子变了，不是系统变好了，期间两个退化版本被误放行。
   - 根因：judge 的 prompt、模型版本、温度未与被测系统一起版本化
     （concept/02 §2），而 judge 绝对打分跨版本不可比——分数整体平移时，
     相对排序或许还在，**绝对门禁阈值已经失真**。
   - 正确做法：judge 三要素（模型版本 + prompt hash + 温度）进日志与报告页眉；
     换任一要素必须重跑 50~100 条校准集，输出新旧 judge 分差报告，
     分差超过 0.5 分时迁移门禁基线并公告「此前的跨版本对比作废」。
     更稳的长期方案是门禁主要用成对比较口径，它对分数平移免疫。

4. **A/B 实验每天偷看指标，第三天「显著提升」上线后毫无差异**
   - 现象：新推荐策略上线 A/B，运营每天早会看一次解决率；第三天 p=0.04
     「显著」，全员庆祝并全量；两周后复盘，真实差异为零，
     同期另两个按同样流程「显著」的实验也都复现失败。
   - 根因：**optional stopping**——没到预设样本量就反复检验，
     第一类错误率随偷看次数快速膨胀（concept/03 §3）：每次偷看都给它
     一次「碰巧显著」的机会，名义 5% 的实际假阳性率可以逼近三成以上。
     根因不在分析代码，在实验纪律。
   - 正确做法：先算样本量再开实验（两比例公式，MDE=2% 通常要数千/组，
     ex03 给出精确值与功效曲线）；达到样本量前实验平台对指标不可见；
     确需提前决策时用序贯检验（group sequential / mSPRT）而非反复偷看。
     报告必须写「是否发生偷看」——这一项决定结论的有效性。

5. **离线忠实度从 0.71 涨到 0.74，线上解决率与投诉率纹丝不动**
   - 现象：团队按 RAGAS 口径优化引用与生成约束，离线忠实度连涨三个月，
     周报一片向好；同期线上「答案不对」的投诉量、转人工率没有任何变化，
     产品侧质疑评测团队「自说自话」。
   - 根因：**离线→线上映射从未被验证**（concept/01 §2）：离线指标是代理，
     其效度依赖「黄金集代表线上流量」这一假设。该假设失效的三种典型情形：
     黄金集偏简单题（优化空间全在简单题上，而投诉集中在长尾）、
     优化的维度用户不感知（引用格式变规范但答案没变对）、
     指标口径与用户判断错位（忠实度只查声明有据，不查「引对了但答非所问」）。
   - 正确做法：用历史上线数据拟合「离线变化 → 线上变化」的映射，
     斜率不显著为正的离线指标降级为「参考指标」，不进发布门禁；
     每次评估报告同时给三层指标（离线/线上/护栏），并周期性用线上新难例
     重建黄金集，让映射假设保持有效（ex09 的告警模拟即按此思路监控）。

6. **回归门禁阈值拍脑袋定 2%，每次发布都误报，真故障来时告警已被无视**
   - 现象：CI 接了两比例检验门禁，阈值「准确率下降超过 2% 即阻断」。
     结果 30% 的无改动回归被误报阻断，开发习惯性地点「忽略并重跑」；
     某次真实退化 3% 的版本，告警照常响起，也照常被忽略，坏版本上线 6 小时
     才由用户投诉发现。
   - 根因：门禁的**误报率从未被量化**。50 条黄金集上准确率的抽样波动
     本身就有 ±5~7 个百分点（95% 区间，p̂=0.8），2% 的阈值远小于噪声，
     等于把「掷骰子」设成阻断条件——误报率 30% 的系统会训练用户忽略告警
     （告警疲劳），而告警疲劳的门禁比没有门禁更危险。
   - 正确做法：阈值按**可控误报率**反解，而不是按「看起来严重」拍：
     模拟「模型未变时重复跑 200 次回归」，统计误报率，
     把阈值定在误报率 ≤5% 的分位点上（ex07 的完整流程）；
     同时报告效应量与置信区间，不报裸点值；门禁阈值与黄金集规模联动——
     样本量翻倍前，任何 3% 以下的「退化」都不该单独阻断发布。
