# 黄金集与指标设计：从「抽样」到「门禁」的工程学

> 评估的第一性问题不是「用什么指标」，而是「评测数据从哪来、代表谁」。
> demo 集里 90% 的通过率，和线上流量里 65% 的真实解决率，可以同时为真——
> 差别全在**抽样**上。本章把黄金集构建、指标分层与离线到线上的映射落成可计算的东西。

```text
黄金集 → 指标门禁 全链路
┌─────────────┐   分层抽样    ┌─────────────┐   口径版本化   ┌─────────────┐
│ 全量流量日志 │ ───────────▶ │  黄金集(分层抽样 │ ───────────▶ │  v1/v2/v3   │
└─────────────┘   难例挖掘    │ +难例挖掘)    │   标签冻结    └─────────────┘
                            └─────────────┘
        │                                  │
  离线指标(精确率/召回/分数)          线上指标(真实解决率/补救率)
        │                                  │
        └──────────▶ 据口径映射 ◀──────────┘
                    门禁: 离线≥阈值 且 线上漂移≤Δ
```

## 1. 黄金集构建：分层抽样、难例挖掘与口径版本化

中立陈述：黄金集（golden set）是**固定、带真值、可复放**的评测样本集合。
它的质量由四个维度决定：**分层结构**（样本在「意图 × 难度 × 知识依赖」上的覆盖度，
覆盖不均会让指标向高频类倾斜）、**难例来源**（线上兜底样本、人工投诉、badcase 聚类——
纯人工编题会系统性漏掉真实失败模式）、**判定口径**（什么算对：字符串全等、数值容差、
引用支撑，口径不统一则同一份预测能算出两个分数）、**版本管理**（样本增删与口径变更
都要版本号，否则「上个月 82% 这个月 79%」无法归因）。

```python
import numpy as np

rng = np.random.default_rng(7)
# 三维分层：意图 x 难度 x 知识依赖。每层配额按「线上流量占比 + 难例加权」
STRATA = {  # (意图, 难度): 配额
    ("查询", "易"): 8, ("查询", "难"): 4,          # 知识依赖单独一维，见下
    ("计算", "易"): 6, ("计算", "难"): 6,
    ("创作", "易"): 5, ("创作", "难"): 5,
    ("拒答", "易"): 4, ("拒答", "难"): 4,
    ("多轮", "易"): 4, ("多轮", "难"): 4,
}
total = sum(STRATA.values())
print(f"黄金集总配额 = {total} 条")
for (intent, diff), n in STRATA.items():
    print(f"  {intent}x{diff}: {n} 条 ({n / total:.0%})")
```

覆盖度统计是验收动作：任一层样本数为 0 即为「盲区」——例如没有「拒答」层，
系统「不懂也硬答」的毛病在指标上永远看不见。50 条是本章的标准规模：
够大到给出 ±13 个百分点以内的二项置信区间（95% Wilson 区间，见 ex02），
又小到一人一天能标完。难例占比建议不低于 30%（经验判断），
因为黄金集的使命不是「证明系统好」，而是「抓出系统坏」。

## 2. 指标分层：离线、线上与护栏，以及离线→线上的映射

中立陈述：指标体系分三层，回答三个不同的问题。**离线指标**（在黄金集上算）
回答「能力对不对」：准确率、忠实度、引用命中率、拒答率；**线上指标**（在生产流量上算）
回答「用户好不好」：解决率、转人工率、满意度；**护栏指标**回答「有没有变坏」：
P99 延迟、单请求成本、拒答率异常波动、安全投诉率。三层的错误用法是混为一谈——
拿离线准确率当 SLA（忽略分布漂移），或拿满意度当唯一门禁（满意度方差大、
滞后且受产品情绪影响）。

| 层 | 指标 | 计算公式（口径） | 回答的问题 | 典型误用 |
|---|---|---|---|---|
| 离线 | 忠实度 | 有引用支撑的声明数 / 总声明数 | 生成是否凭空编造 | 用字符串匹配近似声明分解 |
| 离线 | 引用命中 | 引用文档包含答案的样本数 / 总样本数 | 检索是否给了对的证据 | 不查「引用了但答错了」 |
| 离线 | 拒答率 | 触发「无法回答」的样本数 / 总样本数 | 该拒的是否拒了 | 只看低拒答，纵容硬答 |
| 线上 | 转人工率 | 转人工会话数 / 总会话数 | 自动化是否真的省人 | 与离线指标直接相除 |
| 护栏 | P99 延迟 / 成本 | 分位数 / 单请求均值 | 是否劣化到不可用 | 只监控均值不看长尾 |

离线到线上的映射必须**用历史数据验证，不能假设**：取过去 N 次上线，
用「离线指标变化量 → 线上指标变化量」做最小二乘拟合，斜率接近 0 或符号为负，
就说明该离线指标在此场景不是有效代理（ex09 的告警模拟用同一思路）。
经验判据（经验判断）：RAG 问答场景下，忠实度与「幻觉投诉率」通常同向，
而「引用命中率」与「解决率」的相关强弱取决于用户是否真的会点开引用。

```python
def guardrail_check(cur, base, tol=0.2):
    """护栏指标：相对基线恶化超过 tol 即一票否决（示例口径）"""
    return {k: (cur[k] > base[k] * (1 + tol)) for k, v in cur.items()}
```

## 3. 三视角解析

### 🧑‍💻 程序员视角

- 黄金集落地为代码仓库里的一个文件（`goldenset.jsonl`）+ 一条 CI 命令：
  每条样本含 `id / 输入 / 真值 / 判定口径 / 分层标签 / 版本号`。判定逻辑（归一化规则、
  容差、引用解析）和样本分开存，改口径不改数据，报告里必须打印口径版本。
- 难例挖掘要自动化：线上「点踩 / 转人工 / 空结果」的样本按周回流，经过去重与
  人工确认后进黄金集，并在样本上打 `source=online` 标签——这样你能回答
  「新版本在线上难例上通过率变化」而不只是一个总均分。
- 指标计算先写单元测试再上线：口径函数（如数值归一化 `1,234.50 == 1234.50`）
  是纯函数，用 10 组边界样本（空串、单位差异、百分号）锁死行为，防止
  「修了口径忘了同步报告」这类静默劣化。
- 门禁实现为一个纯函数 `gate(baseline_metrics, new_metrics) -> (pass, reasons)`，
  无副作用、可单测、CI 里只依赖黄金集文件与指标 JSON，不连任何服务。

### 🎓 博士生视角

- 分层抽样本质是降低估计量的方差：按比例分配（proportional allocation）在层内
  同质时最优；难例 oversampling 后必须在报告时按层权重回加权，
  `μ = Σ wₖμₖ`，否则报出的「总体准确率」是有偏的——这是调查抽样理论的直接应用。
- 二项比例 50 条样本的 95% Wilson 区间半宽约 ±13 个百分点（p̂=0.8），
  这意味着单次黄金集只能分辨「巨大」的变化；要检出 2~3 个百分点的提升，
  要么加样本（n 按 1/ε² 增长），要么改用方差更小的成对检验（McNemar）——
  统计功效的约束是「为什么小改进测不出来」的根本原因。
- 离线→线上映射的经验验证是「代理效度」（criterion validity）问题：
  离线指标是构念（construct），线上解决率是效标（criterion），
  二者相关强弱受「流量分布是否被黄金集代表」调制——分布漂移下效度自己会衰减，
  所以映射系数要周期性重估，不是一劳永逸。

### 📚 考研者视角

- 必会计算：Wilson 区间 `p̂ ± z√(p̂(1-p̂)/n)` 的近似形式与样本量反解
  `n ≈ z²p̂(1-p̂)/ε²`；p̂=0.8、ε=0.1、95% 置信 → n ≈ 62，能解释「为什么 50 条
  只能看粗粒度变化」。
- 常考对比：**准确率 vs 精确率/召回率/F1** 的适用场景（类别均衡 vs 不均衡），
  以及**宏平均 vs 微平均**在类别频率悬殊时为何结论相反（ex08 有完整算例）。
- 易混概念：**分层抽样（按层分别抽）≠ 系统抽样（按固定间隔抽）≠ 整群抽样**；
  「难例加权」后若忘记回加权，报出的指标是**有偏估计**，这不是四舍五入问题。
- 面试口径题：「50 条样本准确率 82%，95% 置信区间给不出，你怎么办？」
  标准答案是：用 Wilson 或 Clopper-Pearson 区间报区间不报点值，并说明
  该规模下 2 个百分点的差异不具统计显著性。
