# LLM-as-judge：让模型当裁判，先证明裁判合格

> 用 LLM 评 LLM 是规模化的唯一出路：人工标注一条样本几分钟，judge 只要几秒。
> 但 judge 是**带系统性偏差的测量仪器**——直接信它的分数，等于把偏差写进验收标准。
> 本章讲 judge 的偏差清单、两种口径、以及「用人工标注校准 judge」的完整流程。

## 1. judge 的偏差谱系：位置、长度、自我偏好与格式

中立陈述：LLM-as-judge 指用一个（通常更强的）模型对被测系统的输出打分或做成对比较。
实测与文献（Zheng et al., 2023, "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena"）
一致报告的偏差至少有四类：**位置偏差**（pairwise 比较时偏爱先出现的答案，
交换顺序后相当比例的结论会翻转）、**长度偏差**（偏爱更长的答案，即使内容更空）、
**自我偏好**（GPT-4 给 GPT-4 的输出打更高分）、**格式/表面偏好**（Markdown 结构、
语气自信程度影响分数）。这些偏差的方向都可预测、幅度可量化——
这正是 ex04/ex05 用本地模拟复现的东西。

```python
# judge 偏差的本地模拟：分数 = 内容质量 + 位置加成 + 长度加成 + 噪声
def judge_score(quality, position, length, w_pos=0.5, w_len=0.02):
    """position=0 表示先出现；length 为答案字符数"""
    return quality + w_pos * (1 - position) + w_len * max(0, length - 200)
# 交换 A/B 位置后 score_A - score_B 的变化量 = ±2*w_pos，与内容无关
```

**位置偏差的量化方法**是交换实验：同一对答案，先 A 后 B 评一次、先 B 后 A 再评一次，
两次结论不一致的比例就是「翻转率」；MT-Bench 论文报告的翻转率在 30% 量级。
**长度偏差**的量化是相关分析：把 judge 分数与答案长度做 Spearman 相关，
显著正相关且内容质量不变时即可判定存在长度偏差。缓解手段（按有效性排序）·
交换位置取平均（对 pairwise）、要求 judge 先输出理由再打分（chain-of-thought、
增加推理占用，经验判断有效但非根本解）、在 prompt 中显式声明「长度不代表质量」、
以及对同一评测用两个不同 judge 交叉验证。

## 2. 两种口径与校准流程：成对比较 vs 绝对打分，kappa 与相关

中立陈述：judge 有两种用法。**绝对打分**（1-10 分或 1-5 分）直接给出质量分，
可与历史版本比较，但分数跨 prompt 跨版本不可比——换一次 judge prompt，
全场分数平移 1 分是常态；**成对比较**（A vs B 哪个好）只依赖相对顺序，
对分数漂移免疫，是回归测试更稳的口径，代价是要评的对数随候选数平方增长。
校准流程固定为四步：① 取 50~100 条样本做**人工标注**（双人标注 + 第三人仲裁）；
② 同一批样本跑 judge，计算**一致性**：连续分数用 Spearman 相关，类别判定用
Cohen's kappa；③ 设定准入线（经验判断：kappa ≥ 0.6 且相关 ≥ 0.7 才允许进 CI 门禁，
0.4~0.6 只用于粗筛，< 0.4 退回人工）；④ 把 judge 的**模型版本、prompt、温度**
与被测系统一起版本化——judge 升级导致分数平移，会让所有历史对比失效。

| 校准指标 | 口径 | 准入线（经验判断） | 低于准入线的处置 |
|---|---|---|---|
| Cohen's kappa | 类别判定（好/坏） | ≥0.6 | 只做粗筛，不进门禁 |
| Spearman ρ | 连续分数 | ≥0.7 | 改用成对比较口径 |
| 位置翻转率 | 交换 A/B 后翻转比例 | ≤10% | 交换取平均后再评 |
| 长度相关 | 分数 vs 长度 ρ | \|ρ\|<0.3 | prompt 显式去偏 + 长度归一 |

```python
def cohens_kappa(a, b):
    """两份 0/1 类别标注的一致性（a、b 为等长序列），扣除随机一致后的净一致"""
    n = len(a)
    po = sum(x == y for x, y in zip(a, b)) / n
    pa1, pa0 = sum(a) / n, 1 - sum(a) / n
    pb1, pb0 = sum(b) / n, 1 - sum(b) / n
    pe = pa1 * pb1 + pa0 * pb0
    return (po - pe) / (1 - pe)
# 同为「90% 判好」的两份标注：raw agreement 高，但 kappa 会暴露随机一致的贡献
```

judge 自身也要被评估的工程含义是：**每次换 judge（模型版本或 prompt）都等于换了一把尺子**，
必须重跑校准集并记录新旧 judge 在同一批样本上的分差——分差 > 0.5 分（5 分制）时，
历史门禁基线要同步迁移，否则「尺子缩了 1 厘米」会被误判成「系统进步了」。

## 3. 三视角解析

### 🧑‍💻 程序员视角

- judge 接入必须是**可替换的一个函数签名**：`judge(sample, output) -> Judgment`，
  Judgment 里带 `score / rationale / judge_version / prompt_hash / latency / cost`。
  所有字段落日志——尺子的每一次使用都要留证据，否则分数争议无法复盘。
- 先用规则 judge 打底再上模型 judge：能写死规则的判定（格式是否合法 JSON、
  引用是否存在于给定文档、数字是否等于真值）用代码判，**代码判据零成本零偏差**，
  模型 judge 只留给语义类判定。混合口径的可靠性远高于纯模型 judge（经验判断）。
- 成对比较的样本量要算：n 个候选两两比较是 `n(n-1)/2` 对，5 个候选 = 10 对/样本，
  50 条样本 500 次 judge 调用——批量异步 + 断点续跑，别在 CI 里同步等。
- 温度设 0 且固定 seed：judge 是测量仪器，不是创意生成器；judge 输出必须可复现，
  否则同一版本两次回归的分数差里混进了 judge 自己的噪声（ex06 量化这部分噪声）。

### 🎓 博士生视角

- kappa 校正了「随机一致」：`κ = (p_o − p_e)/(1 − p_e)`，两个标注员对 90:10 的
  极端分布即使随口标也能有很高的 observed agreement，`p_e` 正是扣除这部分；
  因此**类别越不均衡，raw agreement 越虚高**，必须看 kappa。
- Spearman 相关是秩相关，对 judge 分数的重尾分布（大量 7 分、少量 1 分）比
  Pearson 稳健；但它对「系统性平移」不敏感——新旧 judge 分差恒为 +1 时
  ρ ≈ 1，所以版本迁移还要看绝对分差，两个指标互补。
- 位置偏差的成因有争议的解释路径：自回归模型的局部注意力对 prompt 前部更敏感
  （"lost in the middle" 现象的评委版），以及 RLHF 训练数据中「先出现的答案
  更常被标为好」的分布痕迹。理解成因有助于设计去偏 prompt，但工程上
  交换取平均是模型无关的稳健解。
- judge 与考生的「能力同源」问题是理论隐患：用同一家族模型做 judge，
  系统性错误（同类幻觉、同类格式偏好）会被判为「对」——自我偏好只是最表面的一层。

### 📚 考研者视角

- 必会计算：Cohen's kappa 的 `p_o` 与 `p_e` 计算（`p_e` = 双方边际分布乘积之和），
  以及一个经典结论：observed agreement 0.9 在边际极偏时 kappa 可能只有 0.4。
- 常考对比：**Kappa vs Spearman vs Pearson** 的适用场景（类别一致 / 单调关系 /
  线性关系）；**judge 的绝对打分 vs 成对比较**各解决什么问题、各自的失效模式。
- 概念辨析：**judge 的一致性 ≠ judge 的正确性**——judge 和人工标注高度一致，
  也可能一起错（共同偏差）；校准集必须独立于被测系统的训练数据。
- 面试高频：「你怎么证明你的 LLM judge 可信？」答题链条：人工双标 → κ/ρ → 准入线 →
  偏差量化（位置/长度）→ 版本化与周期性重校，缺一环就是「拍脑袋」。
