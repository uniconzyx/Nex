# 设计侧方法论：不确定性外露、可恢复性与渐进式授权

> 评估决定「系统好不好」，设计决定「系统**敢不敢**上线」。
> 同一个 80% 准确的系统，把错误包装成「猜错但不吭声」是事故，
> 包装成「不确定并给用户退路」是产品。本章讲设计侧的五件事：
> 不确定性表达、错误可恢复、渐进式授权与人机接管、A/B 的实验纪律、审计与合规。

```text
设计侧五件事 → 上线可敢性
 不确定性表达 ─┐
 错误可恢复  ─┤
 渐进式授权  ─┼─▶ 把失败设计进产品(给退路) 而非祈祷不发生
 人机接管   ─┤
 A/B 实验纪律─┘
   ┌────────────┐   显著性+护栏   ┌────────────┐
   │ 新策略(实验)│ ─────────────▶ │ 全量/回滚  │
   └────────────┘   超阈值即停     └────────────┘
```

## 1. 不确定性表达与错误可恢复：把失败设计进产品，而不是祈祷它不发生

中立陈述：概率输出的系统必然犯错，产品设计要回答两个问题：
**错了的时候用户知不知道**（不确定性表达），以及**错了之后能不能回头**（可恢复性）。
不确定性表达的工程形态是置信度分层外露：模型自报置信度（logprobs 或 verbalized）、
系统自算置信度（检索分数一致性、多答案投票率）、或按任务难度先验分层。
外露阈值按错误成本标定：高风险任务（医疗、金融建议）阈值抬高，宁可多说
「我不确定」；低风险任务（创意草稿）阈值放低，避免「什么都不敢答」的可用性灾难。
可恢复性有三件套：**撤销/回滚**（生成内容可一键撤回，写入类操作有 undo 或
二次确认）、**重试/编辑**（局部重新生成而不是全文重来）、**兜底路径**
（转人工、降级到确定性规则、明确告知无法处理并提供替代入口）。
一个常被违反的原则：**不要用不确定性表达替代兜底**——告诉用户「我不太确定」
之后必须有下一步动作，否则只是把系统的焦虑转嫁给用户。

```python
def route(confidence, risk, thresholds):
    """按置信度与风险等级路由：低风险直接答，高风险要确认或转人工"""
    t = thresholds[risk]                 # 高风险阈值更高
    if confidence >= t["auto"]:
        return "auto"
    if confidence >= t["confirm"]:
        return "confirm"                 # 先说明不确定，再给选项
    return "handoff"                     # 转人工 / 明确拒答
```

## 2. 渐进式授权与人机接管：权限随信任增长，接管永远可达

中立陈述：Agent 的授权不是二值的「全开 / 全关」，而是随历史表现逐级放大的阶梯。
渐进式授权（progressive autonomy）的工程实现是一个权限状态机：
每一级权限绑定一组动作白名单与一组护栏指标，升级条件是「当前级别下
连续 N 次无护栏告警且人工抽检通过率 ≥ p」，降级条件是「任一护栏越界或
一次严重事故」。人机接管的硬约束是**接管永远可达**：任何自动化流程都要有
「人在环上」（human-on-the-loop）的急停开关、当前状态快照（Agent 停在哪一步、
准备执行什么）、以及接管后的无痕续作。反面模式是「影子自治」——
权限悄悄扩大但没有人复核边界，出事时才发现 Agent 半年前就开始执行
没人审过的动作类型。

| 级别 | 允许动作 | 升级条件 | 降级条件 |
|---|---|---|---|
| L0 只读 | 检索、计算、建议 | 50 次无告警 + 抽检 ≥90% | 一次越权尝试 |
| L1 低风险写 | 草稿、标签、内部备注 | 连续 2 周无告警 | 一次误写外部系统 |
| L2 高风险写 | 发消息、改配置、下单 | 事故复盘通过 + 双人审批 | 任一护栏指标越界 |
| L3 自主 | 批量操作、跨系统编排 | 逐案审批 | 立即回 L1 |

## 3. A/B 实验纪律与审计合规：样本量先算后跑，日志先设计后上线

中立陈述：A/B 是设计决策的最终裁判，但它的结论强度完全由**样本量与显著性**决定。
两比例检验（新旧版本解决率 p₁ vs p₂）所需样本量由三个量决定：
基线率、最小可检测效应（MDE）、以及可接受的第一类错误率 α 与功效 1−β。
经验上最常见的翻车不是「分析错」而是「没到样本量就 peeking 偷看」——
每偷看一次，实际假阳性率就逼近名义值的数倍（ex07 给出量化）。
审计日志是合规的地基：Responsible AI 的落地检查（隐私：PII 脱敏与最小化收集；
偏见：按人群切片抽测指标；幻觉：免责声明与引用外露；审计：决策可追溯）里，
只有审计是**纯工程项**——日志字段要在设计阶段就定好，至少包含
`trace_id / 输入hash / 模型版本 / prompt版本 / 输出 / judge分数 / 护栏状态 / 操作者`。
没有审计日志的「合规」只是文档合规。

```python
from math import sqrt
def two_proportion_sample_size(p1, mde, alpha=0.05, power=0.8):
    """两比例检验每组样本量（正态近似，双侧）"""
    z_a = 1.96 if abs(alpha - 0.05) < 1e-9 else 1.64
    z_b = 0.84 if abs(power - 0.8) < 1e-9 else 1.28
    p2 = p1 + mde
    p_bar = (p1 + p2) / 2
    return int(2 * p_bar * (1 - p_bar) * (z_a + z_b) ** 2 / mde**2) + 1
```

## 4. 三视角解析

### 🧑‍💻 程序员视角

- 置信度外露要先做**校准曲线**：把模型自报置信度分桶，对桶内统计人工标注的
  实际正确率，报告 ECE（expected calibration error）。自报 0.9 的样本实际只有
  60% 对，那 0.9 就是装饰，阈值路由会系统性误判（经验判断：verbalized
  confidence 普遍偏乐观，logprob 派生指标在长答案上被稀释）。
- 可恢复性的最小实现：所有写操作走「草稿 → 确认 → 生效」三段；Agent 的每一步
  工具调用记录 `undo_action`（可空），支持按步回滚；用户界面常驻「停止 / 回退」。
  这两件事不做，渐进授权就是空话——没有退路的授权没人敢批。
- A/B 的偷看要用序贯检验或固定样本量纪律管理：实验平台在达到样本量前
  **不允许**看指标；偷看不可避免时用 group sequential 设计（α spending）。
- 审计日志落盘前先定**字段与保留期**：输入 hash 而非原文（隐私），但保留
  可反查的映射表（合规）；日志本身要防篡改（append-only 或 WORM 存储）。

### 🎓 博士生视角

- 不确定性外露是「系统 1 / 系统 2」的工程对应：快思考路径直接给答案，
  慢思考路径（不确定时）触发额外计算或人类介入；形式化地，这是对
  「动作价值」期望的序贯决策，阈值即是最优停止问题的边界。
- A/B 的偷看问题在统计上是 optional stopping：重复检验使第一类错误率
  从 α 膨胀到接近 1（上界约 1−e^{−α·k}，k 为偷看次数量级的直观刻画）；
  group sequential 与 always-valid p-value（如 mSPRT）是理论正解。
- 渐进式授权与强化学习的 safe exploration 同构：权限状态机即约束 MDP 的
  动作掩码，升级/降级条件是策略约束的在线更新——区别在于工程上
  「降级」还必须考虑人的信任修复成本，这不在任何损失函数里。
- 审计与因果责任：日志的可追溯性使「事后归因」成为可能，这是 AI 系统
  责任分配（accountability）讨论的技术前提；缺日志时，责任只能落到
  最近的人类操作者身上——这恰是组织抵制自动化的根因。

### 📚 考研者视角

- 必会计算：两比例样本量公式 `n = 2p̄(1−p̄)(z_{α/2}+z_β)²/δ²`，
  以及「MDE 减半 → 样本量约变 4 倍」的平方关系；给定 p₁=0.7、MDE=0.05、
  α=0.05、power=0.8 能口算出每组约 1400（ex03 的精确值与误差分析）。
- 常考对比：**第一类错误（假阳性）vs 第二类错误（假阴性）**在门禁场景的
  非对称代价——回归门禁宁可误报（阻断一次发布）不可漏报（坏版本上线），
  所以 CI 门禁的 α 常设得比学术 0.05 更小或配更高的功效。
- 易混概念：**置信度（calibrated probability）≠ 置信区间**；**ECE 小
  ≠ 判别力强**（一个永远输出 0.8 的分类器在基率 0.8 时 ECE 为 0 但毫无用处）。
- 面试口径题：「产品经理要把置信度显示给用户，你第一句话问什么？」
  高分回答：先问「这个置信度校准过吗」——未校准的置信度外露是负债不是功能。

## 5. 小结

设计侧与评估侧共用同一条主线：**把不确定性显式化、把失败路径工程化**。
评估给不确定性定量（指标与区间），设计给不确定性去处（路由、兜底、接管）。
Responsible AI 的检查表不是文档负担：隐私字段决定日志结构，偏见抽测决定
黄金集分层，幻觉免责依赖引用外露的工程质量，审计日志决定以上全部可否证伪。
