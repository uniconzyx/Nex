# agent-ch09 · 多模态应用开发：图像、文档与语音的工程接口

> 对应图片 DAY 24（Stable Diffusion Colab）· 先修：agent-ch08（Transformer 核心机理）· 面试权重：★★★★☆
> 说明：面试官不问你「什么是多模态」，而问「一张 1024×1024 的发票截图会花多少 token、
> 字符准确率 98% 的 OCR 为什么字段级只有 80%、CLIP 为什么能图文互搜、文生图的 CFG 调高一定更好吗」。
> 本章把三条线（理解 / 生成 / 检索）落到**工程接口与数字**上。

## 本章目标

学完你应该能：

1. **算清视觉 token 账本**：给定图像分辨率、长宽比、patch 大小与切图策略，算出 patch 数、
   视觉 token 数与多图请求的计费口径，并给出降本手段（降采样 / 限张数 / 分块预算）。
2. **搭出 OCR → 版面 → 结构化的抽取流水线**：把一张发票截图变成字段级 JSON，
   包含版面区域划分（标题 / 表格 / 页眉页脚）、表格单元格还原、schema 校验与低置信度路由。
3. **用字段级准确率与混淆矩阵做评估**：在 50 条样本上报告逐字段准确率、Top 混淆对与
   失败样本集，能按错误类型排序给出下一步优化项，而不是只报一个「平均准确率」。
4. **说清 CLIP 跨模态检索与扩散生成的可控性**：解释双塔对齐与余弦检索为什么成立；
   说清采样步数 / CFG / 种子对多样性与稳定性的影响，以及 ControlNet / Inpainting 的工程接口。
5. **交付「发票/报表识别 + 结构化抽取」小应用**：含异步任务队列与进度反馈、
   上传/生成内容的安全过滤，和一份带数字的评估报告。

## 关键认知（本章最值钱的三句）

- **多模态的账单按 token 算，而 token 数随分辨率平方增长**：patch 数 ≈ `(H/p)·(W/p)`，
  分辨率翻倍，视觉 token 变 4 倍，注意力矩阵显存变 16 倍。所有「高清原图直传」的产品设计，
  都是在给推理成本挖坑——先算账，再定分辨率上限。
- **字符级 OCR 准确率 ≠ 字段级准确率**：后者是「检测 → 识别 → 版面归类 → 字段对齐 → 后处理」
  的乘法链条，任何一环掉到 95%，整条链只剩 77%。报指标必须报字段级，
  且必须配混淆矩阵与失败样本集，否则你根本不知道先修哪一环。
- **理解、生成、检索三条线，共用同一套「对齐空间」思想**：CLIP 用对比学习把图文嵌到同一
  空间做检索；扩散模型用条件嵌入接受文本/深度图/姿态控制生成；VLM 把视觉 token 投影进
  LLM 的语义空间。工程上先分清自己在哪条线，再选工具——混用是选型翻车的第一原因。

## 技术交付物（来自 manifest.tech_load）

**交付物：文档/发票抽取应用 —— OCR → 版面 → VLM 结构化输出；50 条样本的字段级准确率。**

验收口径（对应 project.json 的任务，逐条可核对）：

- 输入一张发票/报表截图，输出带 schema 校验的结构化 JSON（金额、税号、日期、商品行等字段），
  非法结构被拦截并能重试一次；
- 流水线三段可见：OCR 文本与坐标 → 版面区域（标题/表格/页眉页脚）→ 字段映射，每段可单独查看；
- 表格能还原成单元格网格，合并单元格有明确处理策略（跨列/跨行如何表示）并说明代价；
- 50 条样本上给出**逐字段准确率**、Top 混淆对、失败样本集（≥10 条，每条含归因标签）；
- 低置信度字段走人工兜底队列，「兜底率 vs 自动错误率」随阈值变化的曲线可查；
- 异步任务队列带进度反馈；单次请求成本按「文本 token + 视觉 token」两段记账。
- 说明：本学科的示例环境禁网、无密钥，所有「模型」均为本地模拟（规则 OCR、模拟嵌入、
  虚拟队列），真实接入方式在文中指向对应 GitHub 仓库与 ch03 的客户端封装。
## 与 ai 学科的分界

`ai` 学科负责多模态模型的内部机理：ViT 的完整推导、CLIP 对比损失的数学形式、
扩散模型的 score matching 与 DDPM/DDIM 采样理论、ControlNet 条件机制的推导。

本章**只要求工程接口与数字**：视觉 token 怎么算、字段级准确率怎么评、生成参数怎么调、
单次请求成本怎么记账。遇到「为什么这样对齐、为什么这样采样」的深层机理问题，
回 `ai` 学科追推导；本章停在「够用即止的原理 + 工程判据 + 可运行产物」。
