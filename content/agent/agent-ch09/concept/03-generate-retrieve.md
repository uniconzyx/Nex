# 生成与检索的可控性：扩散采样参数与 CLIP 双塔对齐

## 1. CLIP 双塔与跨模态检索：对齐空间里检索为什么成立

中立陈述：CLIP 用两个独立编码器（图像塔 + 文本塔）把图文映射到**同一个向量空间**，
训练目标是「配对样本的余弦相似度高、非配对低」（InfoNCE 对比损失）。
推理时图文互搜就是一次矩阵乘 + top-k：图像库编码成 `(M, d)` 矩阵，查询文本编码成
`(d,)`，归一化后点积即余弦相似度，取 top-k 返回。**检索质量不来自某个精巧的排序算法，
而来自训练时对齐得好不好**——工程侧能做的只有：归一化、温度系数、候选库质量、top-k 重排。

```
图像塔                    文本塔
 I₁ ──▶ f(I₁) ─┐        T₁ ──▶ g(T₁) ─┐
 I₂ ──▶ f(I₂) ─┤                      ├─▶ 同一空间，单位向量
 ...            ▼        ...          ▼
 Iₘ ──▶ f(Iₘ) ─┴─▶ (M,d)  g(Tq) ──▶ (d,)
                        sim = f(I)·g(Tq)/√d  ──▶ top-k 检索
```

```python
import numpy as np

def topk_retrieval(img_feats, query_feat, k=3):
    """归一化 + 点积 = 余弦相似度，返回相似度最高的 k 个索引"""
    q = query_feat / np.linalg.norm(query_feat)
    I = img_feats / np.linalg.norm(img_feats, axis=1, keepdims=True)
    sims = I @ q                                  # (M,) 余弦相似度 ∈ [-1, 1]
    return np.argsort(-sims)[:k], np.sort(sims)[::-1][:k]

rng = np.random.default_rng(0)
img_feats = rng.normal(size=(6, 8))
query = img_feats[2] + rng.normal(scale=0.1, size=8)   # 与图 2 同源的查询
idx, sims = topk_retrieval(img_feats, query)
print(f"top-3 索引 {idx.tolist()}，相似度 {np.round(sims, 3).tolist()}")
# top-3 索引 [2, 4, 1]，相似度 [0.998, 0.113, 0.106]
```

注意上面这行的第二个数字：top-1 是 0.998，top-2 只有 0.113——**好的检索分数是断层式领先**。
如果 top-1 与 top-2 只差 0.02，说明查询与库都不够 discriminative，此时做 RAG 重排或
提示用户澄清，比强行取 top-1 更稳。温度系数 τ（训练时学习、推理时可调）整体缩放相似度，
只影响「分布的尖锐程度」，不改变排序——除非你把它和 top-k 截断一起用。

## 2. 扩散生成的可控性：步数、CFG、种子与两个工程接口

中立陈述：扩散模型从纯噪声出发，用「预测噪声 / 预测 x₀」的方式分数十步去噪，
每步都在缩小「当前样本与目标分布」的距离。三个旋钮决定输出的**品质与形态**：
采样步数决定逼近目标分布的精细度（步数不足 → 欠去噪、细节糊）；CFG
（Classifier-Free Guidance）用 `ε̂ = ε_uncond + w·(ε_cond − ε_uncond)` 把采样往
「更像提示词」的方向推，`w` 越大越贴合 prompt 但多样性崩塌、过饱和；种子决定
初始噪声，同种子 + 同参数 = 同张图，这是「可复现」的唯一来源。

```python
def cfg_guided(eps_uncond, eps_cond, w):
    """CFG 引导：把无条件预测往条件方向外推，w=1 时退化为普通条件采样"""
    return eps_uncond + w * (eps_cond - eps_uncond)

import numpy as np
eps_u = np.zeros(4); eps_c = np.array([1.0, -1.0, 0.5, 0.0])
for w in (1.0, 7.5, 15.0):
    print(f"CFG w={w:4.1f} → 引导后噪声预测 {cfg_guided(eps_u, eps_c, w)}")
# CFG w=1.0  → 引导后噪声预测 [ 1.  -1.   0.5  0. ]
# CFG w=7.5  → 引导后噪声预测 [ 6.5 -6.5  3.25 0.  ]
# CFG w=15.0 → 引导后噪声预测 [14. -14.  7.  0. ]
```

两个必须知道的工程接口：**ControlNet**（在去噪过程中注入额外条件信号——
边缘图、深度图、姿态，控制构图而不改变语义内容）与 **Inpainting**
（只对掩码区域去噪，保留区域像素不动，用于局部替换与消除）。两者都不是「换个模型」，
而是在采样循环里加/减一部分计算——这也是为什么它们对算力的影响可以精确预估。
生成侧的工程红线是**内容安全与版权**：提示词过滤、输出审核、训练数据与生成物的
许可证审查，缺一项都可能让产品停摆。

| 旋钮 | 调大的效果 | 调小的效果 | 工程经验值 |
|---|---|---|---|
| 采样步数 | 细节更稳、延迟线性上升 | 欠去噪、糊 | 20–30 步后收益锐减 |
| CFG w | 贴 prompt、多样性降 | 跑题、但更自然 | 7–12 是常用区间 |
| 温度（若可调） | 分布更平、惊喜多 | 更保守、重复 | 一般固定不调 |
| 种子 | 只换初始噪声 | —— | 固定种子才能 A/B |

## 三视角解析

### 🧑‍💻 程序员视角

- 相似度先归一化再点积，别手写 `cos = a·b/(|a||b|)` 后又忘了单位化查询向量；
  大批量检索时 `img_feats @ q` 一次矩阵乘就是全部排序，不要循环。
- 生成任务务必**记录完整参数三元组**（模型版本 + 种子 + CFG + 步数 + 提示词原文），
  缺一项就无法复现用户投诉的那张图；参数日志就是你的「可观测性」。
- 扩散推理的显存大头是「每步激活」，batch 与分辨率比步数更吃显存；
  要给用户做「预估显存/时间」的提示，超预算直接拒，别等 OOM。
- CLIP 类模型做检索时，库向量要离线批量编码 + 缓存（附内容哈希），
  新图入库走异步队列；不要每次请求都现算全库。

### 🎓 博士生视角

- InfoNCE 的温度系数是隐式的「对齐锐度」：τ 越小，softmax 越尖，模型越强调细粒度区分，
  但可能压垮跨模态的「一对多」关系（一张图配多句描述）——这是 CLIP 系模型
  零样本分类与检索差距的来源之一。
- CFG 的动力学解释：引导后的分数函数等价于 `∇log p(x) + w·∇log p(c|x)/p(c)`，
  w 过大时分布被推向流形外的低概率区，表现为过饱和/伪影；w→1 时失去条件控制。
- 扩散与对比学习共享「对齐」母题：前者在「时间步/噪声水平」维度对齐样本与分布，
  后者在「模态」维度对齐配对样本——理解这一点，三条多模态线就打通了。

### 📚 考研者视角

- 必会公式：`ε̂ = ε_u + w(ε_c − ε_u)`（CFG）、`cos(a,b) = a·b/(|a||b|)`（余弦相似度）、
  InfoNCE 的 `L = −log[ exp(s⁺/τ) / Σexp(s/τ) ]`。
- 常考对比：**生成式（扩散/自回归）vs 判别式（对比学习）多模态**的目标函数差异，
  以及「双塔 vs 单塔」结构对检索与推理成本的影响。
- 概念辨析：**种子控制的是初始噪声，不是输出内容**——同种子不同模型/不同参数
  输出完全不同；「换 seed 得到不同图」≠「模型有随机性魔法」，而是初值敏感性。
- 应用题：给定 `ε_u=0, ε_c=[1,2]`、`w=7.5`，能手算 CFG 结果并解释
  w=1 时为什么退化为普通条件采样。
