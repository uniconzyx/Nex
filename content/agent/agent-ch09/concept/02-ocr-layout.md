# OCR、版面还原与结构化抽取：从截图到字段级 JSON

> tech_load 的场景：把一张发票/报表截图变成机器可校验的 JSON。这条流水线
> （检测 → OCR → 版面还原 → 字段映射 → 低置信度路由）里，每一环都会吃掉一部分准确率，
> 而最终验收口径是**字段级准确率**，不是字符级准确率。本章把每一环的接口、
> 指标与失败模式讲清。

## 1. OCR 的两条路线与版面还原：字符对不等于字段对

中立陈述：OCR 解决「图里有哪些字与坐标」，版面分析解决「这些字属于哪个区域
（标题/正文/表格/页眉页脚）」，字段抽取解决「哪个区域对应 schema 里的哪个字段」。
三级串联：`P(字段对) = P(字对) × P(区域对) × P(映射对)`——即使字符准确率 98%，
一条 20 个字段的链路也可能因为区域误判、表格串行、映射错位把字段级准确率拖到 80%。

```
发票截图 ──▶ 文本检测(TextBox) ──▶ 文本识别(CRNN/VLM) ──▶ 版面分析(LayoutLM) ──▶ 字段映射
            每个框: 多边形坐标      每框: 字符串 + 置信度      区域: 标题/表格/页脚      schema: 键值对
                  │                      │                        │                     │
                  ▼                      ▼                        ▼                     ▼
              漏检=整行丢失        低置信度字符/形似字        表格串列串行             单位/币种错位
```

表格是版面还原里最硬的骨头：真实票据表格常有无线表（靠空格对齐）、合并单元格、
跨页续表。无线表靠「列坐标聚类」还原列边界，有线的靠投影/线检测。工程上
普遍先做单元格还原，再做「行→记录」的映射，让下游按结构化行消费，
而不是把整张表当成一大段文本丢给模型——后者会让 3 行 5 列的表格吐出格式随机的文本，
字段级错误率飙升。

```python
def layout_iou(a, b):
    """两个水平矩形区域 [x1, y1, x2, y2] 的 IoU：版面检测的常用指标"""
    ix1, iy1 = max(a[0], b[0]), max(a[1], b[1])
    ix2, iy2 = min(a[2], b[2]), min(a[3], b[3])
    inter = max(0, ix2 - ix1) * max(0, iy2 - iy1)
    union = (a[2]-a[0])*(a[3]-a[1]) + (b[2]-b[0])*(b[3]-b[1]) - inter
    return inter / union if union else 0.0

gt  = [10, 10, 110, 60]        # 真值：标题区域
pred = [12, 14, 108, 58]       # 预测：略有偏移
print(f"标题区域 IoU = {layout_iou(gt, pred):.3f}")
# 标题区域 IoU = 0.955
```

## 2. 字段级准确率与混淆矩阵：评估要用下游口径

中立陈述：字段级准确率 = 抽取结果中与真值**完全一致**的字段数 / 总字段数。
「金额 1234.50 抽成 1,234.50」算错（字符串不等），「税率 13% 抽成 0.13」也算错——
口径要先在验收标准里定义清楚（是否做数值归一化、是否忽略大小写）。
混淆矩阵把错误归类成可行动的项：哪对字段经常互串（销方/购方名称）、哪类字符常错
（0/O、1/l、5/S）、哪类区域常漏（页脚备注）。**按错误类型的频次排序，就是下一步的
优化清单**——比一个笼统的「平均准确率 85%」有用得多。

| 指标 | 计算口径 | 回答的问题 |
|---|---|---|
| 字符准确率 | 逐字符编辑距离 | OCR 引擎本身好不好 |
| 文本框 IoU | 预测框 vs 真值框 | 检测定位准不准 |
| 字段级准确率 | 字段值全等比例 | **业务能不能用** |
| 混淆对 Top-K | 被错判成的字段频次 | 下一步优化哪一对 |
| 兜底率 | 低置信度进人工的比例 | 端到端成本多少 |

低置信度路由是准确率与成本的平衡阀：把「置信度低于阈值」或「schema 校验失败」
（金额 ≠ 数量 × 单价、税率越界、日期非当月）的样本路由到人工或更强的模型，
其余自动通过。路由阈值不是拍脑袋——它由「自动处理的错误成本」与「人工复核成本」
的比值决定，可以用 50 条样本上的混淆矩阵与置信度分布算出来。

```python
def field_accuracy(preds, gts):
    """字段级准确率：preds/gts 为 {字段名: 值} 的列表，逐字段全等判定"""
    total = hit = 0
    for p, g in zip(preds, gts):
        for k in g:
            total += 1
            hit += (p.get(k) == g[k])       # 完全相等才算命中
    return hit / total

gts     = [{"发票号": "INV-001", "金额": "1234.50"}, {"发票号": "INV-002", "金额": "98.00"}]
preds   = [{"发票号": "INV-001", "金额": "1,234.50"}, {"发票号": "INV-002", "金额": "98.00"}]
print(f"字段级准确率 = {field_accuracy(preds, gts):.2%}（3/4：千分位符号导致 1 个字段判错）")
# 字段级准确率 = 75.00%（3/4：千分位符号导致 1 个字段判错）
```

## 三视角解析

### 🧑‍💻 程序员视角

- 流水线要**逐级落盘中间结果**（检测框、识别文本、区域划分、字段映射），
  每一级都能单独回放与评估；端到端一个黑盒函数，出错了你只能从头猜。
- schema 校验是最便宜的准确率守卫：`金额 ≈ 数量 × 单价`、`开票日期 ∈ 当月`、
  `税号长度合法`——纯代码规则，不需要模型，却能拦下大量下游事故。
- 表格还原先画「列坐标直方图」：把所有文本框的 x1/x2 投到一维，聚类出列边界，
  再按行边界切单元格；无线表这一招比通用版面模型更稳。
- 低置信度路由要有**默认动作**：宁可把拿不准的送人工，也不要静默填一个错值进数据库；
  路由日志要能按字段聚合，月底就能算出「每个字段的人工成本」。

### 🎓 博士生视角

- 文档理解的范式迁移：从「检测+识别+后处理规则」的级联流水线，
  转向端到端 VLM 直接输出结构化 JSON（docVQA/VLM 指令微调）。级联的可解释性与
  可调试性仍是工程优势，端到端的上限更高——两者是准确率/可维护性的权衡，
  不是谁取代谁。
- 序列标注视角：字段抽取可以看成 token 级的 BIO 序列标注（LayoutLM 的预训练目标
  MLM + 区域对齐），这解释了为什么版面模型常与语言模型共享骨架。
- 混淆矩阵的信息论视角：Top 混淆对往往是「语义先验太强」的字段
  （销方/购方都是「XX 科技有限公司」），错误来自模型偷懒走先验而非读图——
  解法是数据增强（交换两栏位置）或强制模型输出坐标证据。

### 📚 考研者视角

- 必会概念链：**文本框检测 → 文本识别 → 版面分析 → 字段抽取**，每一级的输入输出
  与典型模型类别（CRAFT/CRNN、LayoutLM、VLM）要能对上号。
- 指标计算要熟练：IoU 的定义（交/并）与阈值判定（IoU ≥ 0.5 记为命中）；
  字段级准确率 = 全等字段占比；精确率/召回率在「漏检」与「误检」场景的取舍。
- 常考辨析：**字符准确率与字段级准确率为什么不等价**——链路放大效应
  （98%^20 ≈ 66.8%）是标准例题，能解释「引擎评测很好但业务不好用」。
- 易错点：把「版面区域划分」与「语义分割」混为一谈；前者输出的是矩形区域类别，
  后者是像素级掩码，两者指标（IoU vs mIoU）与用途都不同。
