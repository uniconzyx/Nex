# 参数与推理经济：FFN 记忆、参数量账本、KV Cache 与采样

> 这一节把「模型为什么这么贵、显存花在哪、输出怎么控」三件事落到数字上。前两层讲
> **训练侧成本**（参数、显存），最后一层讲 **推理侧行为**（采样）。它们共同回答一个工程问题：
> 「同一个 7B 模型，为什么上下文一长，显存和账单都爆炸？」

```text
参数与推理经济（贵在哪、花在哪）:
  FFN = 两层线性间塞了一本「键值记忆」
  训练侧: 参数账本 / 显存
  推理侧: KV Cache / 采样温度
  上下文长度↑ → 显存↑↑、账单↑↑
```


## 1. FFN 是键值记忆：两层线性之间塞了一本「词典」

中立陈述：Transformer 每块里的 FFN 通常是 `Linear(d_model → d_ff) → 激活 → Linear(d_ff → d_model)`，
其中 `d_ff ≈ 4·d_model`。一个被较多引用的解释（经验判断，非唯一结论）是：FFN 第一层把 Token
表示「查」成 `d_ff` 个键值对（key=哪个神经元激活，value=激活强度），第二层把这些值「读出」
并投影回 `d_model`。也就是说，**参数密度最高的部分不在注意力，而在 FFN 这本「可训练词典」里**。

```
FFN(x) = W2 · σ( W1 · x + b1 ) + b2
         └─ d_ff×d_model ─┘   └─ d_model×d_ff ─┘
```

联想检索实验（示例 ex06）的判据：给 FFN 塞入 `K` 对「key→value」模式后，输入一个
被噪声扰动过的 key，FFN 应当能召回对应 value；随着 `K` 增大或 `d_ff` 减小，召回准确率下降
（容量与串扰）——这从侧面支持「FFN 容量有限、像一本有限页数的记忆本」。

## 2. 参数量账本：把每一类参数拆开算

中立陈述：一个标准 Decoder-only Transformer（如 GPT-2 风格）的参数大致分四块。设
`V`=词表, `d`=模型维度, `L`=层数, `h`=头数, `d_ff≈4d`。

| 组件 | 参数量（近似） | 占比直觉 |
|---|---|---|
| Token + 位置嵌入 | `V·d` | 词表大时才显著 |
| 注意力（每层的 Q/K/V/O 投影） | `4·L·d²` | 与层数、维度平方成正比 |
| FFN（每层两个线性） | `8·L·d²`（因 `d_ff=4d`） | **最大头**，是注意力的 2 倍 |
| LayerNorm（每层 2 个，各 `2d`） | 可忽略 | 相对极小 |

```python
def param_count(V, d, L, h, d_ff=None):
    d_ff = d_ff or 4 * d
    embed = V * d                      # 词表嵌入
    attn  = L * (4 * d * d)            # Q,K,V,O 四个 d×d 投影
    ffn   = L * (2 * d * d_ff)         # 两个线性层
    ln    = L * 2 * 2 * d              # 每个子层前后各一个 LN
    total = embed + attn + ffn + ln
    print(f"总参 {total/1e6:.1f}M  嵌入 {embed/total:.1%}  "
          f"注意力 {attn/total:.1%}  FFN {ffn/total:.1%}")
    return total

param_count(V=50257, d=768, L=12, h=12)   # GPT-2 small：FFN 约占一半以上
```

结论（示例 ex05）：在常见配置下，**FFN 是参数最大头**，注意力是其次；这就是为什么「瘦身」
往往先动 `d_ff` 或层数，而不是砍注意力头。

## 3. KV Cache 显存账本：长上下文贵在哪

中立陈述：自回归推理时，为避免每生成一个 Token 都重算历史，把每一层、每个头的 K/V 缓存下来。
显存随**序列长度 × 批量 × 层数 × 头数 × 每头维度 × 精度字节**线性增长。为缓解，出现了三种
KV 结构：

| 结构 | 每 Token 缓存的 KV 头数 | 显存（相对 MHA） | 说明 |
|---|---|---|---|
| MHA（多头注意力） | `h`（每头独立 K/V） | 1×（基准） | 原始设计，显存最贵 |
| GQA（分组查询） | `h_g < h`（多 Q 头共享一组 KV） | `h_g/h`× | Llama 2/3 采用，性价比高 |
| MQA（多查询） | 1（所有 Q 头共享） | `1/h`× | 推理最快，质量略降 |

```
MHA:  Q[h] ─┐
            ├─ KV[h]   → 缓存 h 套 K/V
MHA:  Q[h] ─┘

GQA:  Q[h] ── 每 g 个 Q 头 → 1 套 KV   （缓存 h_g = h/g 套）
MQA:  Q[h] ───────────────→ 1 套 KV    （缓存 1 套）
```

```python
def kv_bytes(seq, batch, L, h_kv, d, dtype=2):
    # dtype=2 字节(fp16)，每 token 每套 KV 含 K 和 V 两个矩阵，各 seq? 实为按层缓存：
    per_tok = L * h_kv * d * 2 * dtype      # K 和 V 各一套
    return per_tok * seq * batch

for name, h_kv in [("MHA", 32), ("GQA", 8), ("MQA", 1)]:
    b = kv_bytes(seq=32768, batch=1, L=32, h_kv=h_kv, d=128)
    print(f"{name}: {b/1024**3:.2f} GB / 32k 上下文（单条）")
# MHA 约十几 GB，MQA 仅其 1/32 —— 差距来自 h_kv，不是序列本身
```

经验判断：很多人以为「上下文翻倍显存翻倍」，其实在 MHA 下，32k 相对 2k 是 16 倍序列 ×
（本就昂贵的每 token 成本），叠加上「长上下文通常 bat\ch 也更大」，显存常涨一个数量级以上
（示例 ex08 的账本可对具体配置算）。

## 4. 采样参数：temperature 调熵，top-p 截尾

中立陈述：训练时输出是 `softmax(logits)` 上的交叉熵；推理时你可以**改写这个分布**来控制生成。
- `temperature T`：用 `logits/T` 再做 softmax。`T>1` 拉平分布、更随机；`T<1` 尖锐化、更确定；
  它与注意力缩放是同一数学操作（回到 concept/01 的伏笔）。
- `top-p`（核采样）：只保留累计概率达 `p` 的最小词集合，其余置零。它按**概率质量**动态截断，
  比固定 `top-k` 更适应分布胖瘦。

```
原始分布:  [.5, .2, .15, .1, .05]
T=2 之后:  更平滑，小概率词被抬起来
top-p=.8:  取前缀 [.5,.2,.15,.1] 恰好 ≥.8，把 .05 那个词砍掉
```

```python
def sample(logits, T=1.0, top_p=1.0, rng=np.random):
    z = (logits - logits.max()) / T
    p = np.exp(z); p /= p.sum()
    if top_p < 1.0:                         # 核采样：按概率降序累加截到 p
        order = np.argsort(-p)
        cum = np.cumsum(p[order])
        keep = order[cum <= top_p]
        mask = np.zeros_like(p); mask[keep] = 1
        p *= mask; p /= p.sum()
    return rng.choice(len(p), p=p)           # 示例 ex09：固定种子可复现
```

经验判断：`T` 和 `top-p` 通常二选一调，一起拉满会非常发散；生产默认常取 `T≈0.7~1.0`、
`top_p≈0.9~0.95`，代码/SQL 等要求确定性的场景降到 `T≈0` 或 `top_p≈0.1`。

## 三视角解析

### 🧑‍💻 程序员视角

- 显存账本先于写代码：上线前用上面 `kv_bytes` 这类计算器估一下「最大上下文 × 并发」的 KV 占用，
  再选 MHA/GQA/MQA 与卡型，否则长请求一上来就 OOM。GQA 是大多数新开源模型的默认选择。
- 精度直接砍半账本：`fp16`(2B) 换 `fp8`(1B) 等于 KV Cache 砍一半；但注意不是所有卡都支持
  `fp8` 推理，老卡只能用 `fp16`。量化权重（如 4bit）省的是**权重**显存，不省 KV Cache。
- 采样要固定种子做回归：示例 ex09 用固定 `rng` 保证可复现；线上排查「为什么这次答案不一样」
  时，先看 `temperature/top-p` 有没有被改，再看 prompt 有没有变，最后才怀疑模型。
- 一个静默坑：长上下文 + 大 batch 时，KV Cache 往往比**模型权重**还占显存。别只盯着
  `模型大小 ÷ 显存`，要把 `L·h_kv·d·2·seq·batch` 一起算进去。

### 🎓 博士生视角

- FFN 键值记忆假说与「稀疏专家」相关：MoE 把 FFN 做成多份专家 + 路由，本质是把这本
  「记忆本」拆成可激活的子集，用激活参数换总参数，推理仍只走少数专家。
- 参数量里 `d_ff=4d` 是经验约定；从信息瓶颈看，`d_ff` 决定了 FFN 能「记住」多少独立模式，
  示例 ex06 的容量-串扰曲线正是这一容量的实验刻画。
- RoPE 与 KV Cache 的耦合：因为旋转只依赖绝对位置，缓存 K/V 时存旋转后结果即可，相对位置
  在注意力点积里自然出现——这正是 RoPE 适合长上下文推理的原因，与 §2 的位置章形成闭环。
- top-p 的理论本质是「在保持高概率质量的前提下丢弃尾部」，等价于按分布自适应地选 `top-k`；
  当分布很尖时 top-p 接近 top-1，分布很平时接近全词表。

### 📚 考研者视角

- 标准公式要能默写：单层参数量 `注意力 4d² + FFN 2·d·d_ff`，总参 ≈ `L·(4d²+2d·d_ff) + V·d`
  （忽略 LN）；能指出 FFN 项是最大头。
- 常考计算：给定 `d=512, L=12, d_ff=2048, V=30000`，算出 FFN 与注意力各自占比，结论是
  FFN（约 `12×2×512×2048`）远超过注意力（`12×4×512²`）——数字能背也要会推。
- 易混概念：**MHA / GQA / MQA**。记忆口诀：MHA「每头各存一套」最贵最准；GQA「一组 Q 共享
  一套 KV」折中；MQA「全部 Q 共享一套」最快最省但略损质量。三者只改 K/V 的复用方式，不改注意力公式。
- 另一个易错点：**temperature 在训练时不用**。它是推理期对 softmax 输入的缩放；
  训练始终用原始 logits 算交叉熵。把「调温度」说成训练技巧是常见口误。
