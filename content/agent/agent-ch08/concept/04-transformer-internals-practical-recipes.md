# Transformer 核心机理实战手记：凯喵在白板上被追问的十二层

> 这一章讲注意力、位置编码与归一化、参数量与推理。面试官常说"能白板推一遍才算懂"——不是让你背公式，而是看你能不能在追问下不崩。这篇手记把我被追问的十二个层次按顺序铺开，每层都是上一层的自然延伸。

## 开场：为什么"能推一遍"比"知道有这个东西"值钱

Transformer 的组件就那么几个：注意力、FFN、残差、归一化、位置编码。名词谁都会说，但面试官会一层层往下钻：为什么除以 `√d`？为什么多头而不是单头大维度？Pre-LN 和 Post-LN 差在哪？QK 转置相乘后再 softmax 的复杂度是多少？KV Cache 为什么能省计算但不能省显存？

每钻一层，就会筛掉一批人。因为**表层是记忆，深层是理解**。下面十二层就是筛子的孔。

### 第一层：注意力在算什么

一句话：**在"给定一个 query 的情况下，从一组 key-value 里按相关性加权取信息"**。

```python
import numpy as np

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / np.sqrt(d_k)     # [.., Tq, Tk]
    if mask is not None:
        scores = np.where(mask, scores, -1e9)            # 屏蔽的置极小
    weights = softmax(scores, axis=-1)                   # 每行和为 1
    return weights @ V, weights                          # [.., Tq, d_v]
```

三个角色：`Q` 是"我在找什么"，`K` 是"我能提供什么"，`V` 是"我实际给出的内容"。`scores` 是相关性打分，softmax 归一化成权重，最后对 `V` 加权求和。

这就是"检索"的数学形式——和向量数据库的相似度检索是同一个思想，只是注意力是在序列内部做、且权重是软的。

### 第二层：为什么除以 √d_k

面试高频第一问。答案是**控制方差**。

假设 `q` 和 `k` 的各维独立、均值 0、方差 1，则点积 `q·k = Σ qᵢkᵢ` 的方差是 `d_k`（d 个独立项相加，方差相加）。标准差是 `√d_k`。

维度一高（比如 64、128），点积的数值范围就很大，softmax 会进入**饱和区**——最大项接近 1、其余接近 0，梯度趋近于 0，训练不动。

```python
import numpy as np

def score_scale_demo(d_k, n=10000, rng=None):
    rng = rng or np.random.default_rng(0)
    q = rng.standard_normal(d_k)
    ks = rng.standard_normal((n, d_k))
    raw = ks @ q
    scaled = raw / np.sqrt(d_k)
    return raw.std(), scaled.std()

for d in [8, 64, 256]:
    r, s = score_scale_demo(d)
    print(f"d_k={d:3d}  原始点积 std={r:6.2f}  缩放后 std={s:.3f}")
# 缩放后稳定在 1 附近，与维度无关
```

所以 `√d_k` 不是拍脑袋的常数，而是**让 softmax 的输入方差与维度无关**，从而在任何维度下都工作在梯度良好的区间。

### 第三层：为什么用多头，而不是一个更大的单头

如果单头维度是 `d_model`，多头是 `h` 个头各 `d_model/h` 维，那么**总参数量和总计算量基本相同**。所以多头不是"更贵"，而是"同样的预算下换一种组织方式"。

它换来的是**表征的子空间化**：不同的头可以学到不同的关系模式——有的头关注相邻词、有的关注句法依赖、有的关注指代。多个头并行做不同投影，等价于在多个子空间里分别做注意力，最后拼接。

```python
def multi_head_attention(X, Wq, Wk, Wv, Wo, h):
    B, T, D = X.shape
    d = D // h
    # 一次线性变换后 reshape 成多头（比循环更高效）
    q = (X @ Wq).reshape(B, T, h, d).transpose(0, 2, 1, 3)   # [B,h,T,d]
    k = (X @ Wk).reshape(B, T, h, d).transpose(0, 2, 1, 3)
    v = (X @ Wv).reshape(B, T, h, d).transpose(0, 2, 1, 3)
    out, _ = scaled_dot_product_attention(q, k, v)
    out = out.transpose(0, 2, 1, 3).reshape(B, T, D)          # 拼回
    return out @ Wo
```

一个必须记住的坑：`reshape` 的顺序决定"哪些维度归到同一个头"。`reshape(B,T,h,d)` 与 `reshape(B,T,d,h)` 得到的分组完全不同，写错了模型照样能训、只是效果变差且不报错。验证方法是用 `arange` 做输入，单步检查"拆分再拼回是否还原"。

### 第四层：因果掩码为什么是 `diagonal=1`

自回归生成时，位置 `t` 只能看到 `≤ t` 的内容。实现上用一个上三角掩码：

```python
import numpy as np

def causal_mask(T):
    # True 表示「允许关注」
    return np.tril(np.ones((T, T), dtype=bool), k=0)

# 常见错误：用 triu 屏蔽时用了 diagonal=0
# np.triu(ones, 0) 会把对角线也置 1（即屏蔽自己），位置 t 看不到自己 → 训练崩
# 正确：np.triu(ones, 1) 只屏蔽严格上三角
print(causal_mask(4).astype(int))
```

这条错得非常隐蔽：掩码写错后 loss 可能依然下降，但模型学不到"当前位置的 token"，生成质量明显异常。凯喵的检查方法是造一个"只允许看自己"的极端掩码，看输出是否退化成 `V` 本身。

### 第五层：位置编码加在哪、加什么

两种主流方案：

```text
绝对位置编码（正弦/可学习）
  - 加到 token embedding 上，在进第一层注意力之前
  - 只编码「第几个位置」，外推能力弱

RoPE（旋转位置编码）
  - 不「加」到 embedding，而是对 Q、K 做旋转
  - 编码的是「相对位置」，外推性更好，现代模型主流
```

高频错误是**加错对象**：把位置编码加到 Q/K/V 之后（而不是 embedding 上），或者在 RoPE 里只转 Q 不转 K。前者丢失顺序信息，后者破坏 `q·k` 的相对位置性质。

RoPE 的核心直觉：把 `d` 维向量两两配对，按位置 `m` 旋转角度 `m·θᵢ`。两个位置的内积只依赖 `(m−n)`，天然编码相对距离：

```python
def rope_theta(dim, base=10000.0):
    """每对维度对应的旋转频率"""
    return [base ** (-2 * i / dim) for i in range(dim // 2)]
```

### 第六层：FFN 为什么占大头参数量

Transformer 每层的参数量分两块：

```text
注意力：4 × d_model²        （Wq/Wk/Wv/Wo，每个 d×d）
FFN：   2 × d_model × d_ff  （上行 + 下行），d_ff 常为 4×d_model
      = 8 × d_model²
```

所以 **FFN 的参数量是注意力的 2 倍**。7B 模型里 FFN 占大头，这也是为什么"剪枝 FFN 中间维度"是常见的压缩手段。

顺带一个面试延伸：MoE（混合专家）正是把 FFN 拆成多个专家、每次只激活少数几个——**增加总参数量但不增加每 token 的计算量**。注意力的参数不变，变的只是 FFN 部分。

### 第七层：Pre-LN 与 Post-LN 的差别不只是顺序

原始论文是 Post-LN：`x = LN(x + Sublayer(x))`。后来主流改成 Pre-LN：`x = x + Sublayer(LN(x))`。

差别在**梯度路径**：

```text
Post-LN：残差路径要穿过 LN，深层时梯度容易被 LN 的缩放影响 → 需要 warmup，否则易崩
Pre-LN：残差是一条「干净的高速公路」，梯度可以直接回传 → 训练稳定，可以用更大学习率
```

代价是 Pre-LN 的表达能力略弱（需要在最后加一个额外的 LN 收尾），但在大模型上"能训起来"比"理论表达力"重要得多，所以现代模型几乎都用 Pre-LN 或 RMSNorm 的变体。

顺带：RMSNorm 相对 LayerNorm 去掉了减均值那一步，只做除以均方根，计算更省、效果相当，成为 LLaMA 系的默认选择。

### 第八层：残差为什么必须有

两个角度的解释：

**优化角度**：残差让每层只需学"增量"，恒等映射是默认行为。深层网络如果某层学不到有用东西，可以直接输出 0 增量，不影响整体——这让"加深"不会变差。

**梯度角度**：`∂(x + f(x))/∂x = I + ∂f/∂x`，那个 `I` 保证梯度至少能原样回传，不会因为连乘而消失。

这也是"为什么没有残差的深层网络训不动"的答案：没有 `I` 这一项，梯度只能靠雅可比矩阵连乘，几十层后必然消失或爆炸。

### 第九层：注意力的复杂度为什么是 O(T²·d)

```text
Q @ Kᵀ       : [T,d] × [d,T] → [T,T]，代价 T²·d
softmax      : [T,T]，代价 T²
weights @ V  : [T,T] × [T,d] → [T,d]，代价 T²·d
```

所以总复杂度 `O(T²·d)`，**对序列长度是平方的**。这是长上下文贵的根本原因，也是 FlashAttention、稀疏注意力、线性注意力这一整族工作的动机。

FlashAttention 的关键洞察是：**它不改变复杂度，只是改变了访存模式**——通过分块（tiling）+ 在线 softmax，把 `T×T` 的中间矩阵从显存搬到 SRAM，避免反复读写 HBM。所以它带来的是常数级的巨大加速和显存节省，而不是渐进复杂度改善。

### 第十层：KV Cache 省了什么、没省什么

自回归生成时，第 `t` 步的注意力只需要新 token 的 `q`，但需要**所有历史 token 的 `k` 和 `v`**。KV Cache 就是把历史 `k`、`v` 存下来复用。

```text
省掉的：历史 token 的 K/V 投影计算（每步都重算的话是 O(T) 次投影）
没省的：与历史 K、V 做注意力的计算（仍是 O(T) 每步），以及 KV 本身的显存
```

所以推理的总计算量从 `O(T³)`（每步重算全部）降到 `O(T²)`，但显存增加 `O(T·d·L)`。

这也解释了 MQA/GQA 的动机：**KV Cache 的显存是瓶颈**，把 KV 头数从 `h` 减到 1（MQA）或 `h/4`（GQA），显存直接降 4~32 倍，性能损失很小。这是"用一点质量换大量显存"的典型权衡。

### 第十一层：为什么训练不用 KV Cache、推理却要用

训练时是**并行**计算整个序列的注意力：一次矩阵乘法得到 `[T,T]` 的分数矩阵，所有位置的 K/V 同时算出来，没有"增量"的概念，也就没有可复用的历史。

推理时是**串行**生成：一次只能出一个 token，第 `t` 步必然要用到前 `t−1` 步的 K/V。如果不缓存，每步都要把前 `t−1` 个 token 再投影一遍，代价是 `O(T)` 次重复计算——缓存把这份重复消掉了。

一句话：**训练是"一次看全"，推理是"逐步往前"，KV Cache 是串行化的必然产物**。

### 第十二层：参数量怎么手算

面试常给配置让你算。以 LLaMA-3-8B 风格为例：

```python
def transformer_params(vocab, d_model, n_layers, d_ff, n_heads=None):
    embed = vocab * d_model                       # 词嵌入（通常与输出层共享）
    per_layer = (
        4 * d_model ** 2                          # 注意力：Wq/Wk/Wv/Wo
        + 2 * d_model * d_ff                      # FFN：上行 + 下行
        + 2 * d_model                             # 两个 RMSNorm（各一个缩放向量）
    )
    return embed + n_layers * per_layer

p = transformer_params(vocab=128256, d_model=4096, n_layers=32, d_ff=14336)
print(f"{p/1e9:.2f} B")     # 约 8.0B
```

两处易错：**词嵌入要不要算**（要，且大词表下占比不小，128K 词表 × 4096 = 5.2 亿）；**偏置项是否计入**（现代模型多用无 bias 的线性层，若题目给了 bias 要加上 `n_layers × (…)`）。

显存换算：`参数量 × 位宽 / 8`。8B fp16 ≈ 16GB，int4 ≈ 4GB。

## 三视角解析
### 🧑‍💻 程序员视角
被追问「注意力在算什么」时，能答出「用 query 与 key 的相似度给 value 加权」只是第一层；再问「为什么要除以 √d_k」，要答「点积方差随维度线性增长，不缩放会让 softmax 饱和、梯度消失」。因果掩码的 `diagonal=1` 是关键细节：`triu(ones, 0)` 会把对角线也屏蔽，导致位置 t 看不到自己，训练直接崩。多头的参数量与单头相同（每头维度 d/h），它换的是「多个子空间」而非「更多参数」。

### 🎓 博士生视角
Transformer 的可解释性研究把注意力权重当作「解释」，但后续工作指出「注意力权重不等于重要性」——残差流与 MLP 层承载了大量信息。残差连接使梯度可以「跳过」任意层直达底层，这是深层可训练的关键；LayerNorm 的位置（Pre-LN vs Post-LN）直接影响训练稳定性，Pre-LN 不需要 warmup 也能训。FFN 的中间维度通常是 4d，它承担了「逐位置的特征变换」，参数量占全模型约 2/3。

### 📚 考研者视角
AI 岗面试高频：
1. **自注意力**：公式、维度变化、复杂度 O(n²d)。
2. **缩放点积**：为什么除以 √d_k，不缩放会怎样。
3. **多头**：作用、参数量、与单头的等价性条件。
4. **残差与归一化**：Pre-LN 与 Post-LN 的差异、为什么深层网络需要残差。

## 收尾：凯喵的白板十二问

被要求"推一遍 Transformer"时，按这个顺序讲，每一层都留好延伸点：

**注意力在检索**——Q/K/V 的角色，softmax 权重归一。

**除 √d 控方差**——点积方差是 d，缩放让 softmax 不饱和。

**多头是子空间化**——同预算下换组织方式，不是更贵。

**掩码 diag=1**——写 0 会屏蔽自己，静默变差。

**位置看加在哪**——绝对编码加 embedding，RoPE 转 Q/K。

**FFN 占 2/3 参数**——MoE 就是拆 FFN。

**Pre-LN 靠残差高速公路**——稳定训练，代价是收尾 LN。

**残差给梯度一条 I**——没有它深层必崩。

**复杂度 O(T²d)**——FlashAttention 改访存不改复杂度。

**KV Cache 省投影不省注意力**——GQA 压的是显存。

**训练并行、推理串行**——缓存是串行的必然产物。

**参数手算别忘了 embedding**——大词表下占比可观。

最后说一句方法上的话。Transformer 之所以是面试的"照妖镜"，不是因为组件多，而是因为它**每一层都能往下追问三层**：知道有注意力 → 知道怎么算 → 知道为什么除 √d → 知道方差怎么推。停在哪一层，就暴露了理解到哪一层。

凯喵的建议是：**拿一张白纸，从 `X` 进、到 logits 出，把每一步的张量形状写清楚**。写不出来的地方就是没懂的地方。这个动作比读十篇解析都有用，因为形状是骗不了人的——`[B, T, D]` 变成 `[B, h, T, d]` 的那一步，你必须真的知道 `reshape` 和 `transpose` 各做了什么，才能写对。
