# 决策：先问「该不该微调」，再问「怎么微调」

> 微调和 RAG 不是二选一的信仰，而是一张可以按维度打分的决策表。
> 这一章先回答「什么时候**不该**微调」，因为它比「怎么跑通」更能决定项目成败：
> 很多团队在「数据只有 300 条、知识每周变、还要求可溯源」的场景硬上微调，
> 最后钱花了、效果没赢过 RAG、还要背一个维护负担。

## 1. 什么时候不该微调：四个反信号

先看四个最常见的「不该微调」信号，命中任何一个就要先退一步想 RAG 或纯 Prompt。

| 反信号 | 说明 | 更优解 |
|---|---|---|
| 数据量极小（< 200 条且无法扩充） | 模型容易背答案，留出集上虚高、线上泛化差 | 强 Prompt + few-shot + RAG |
| 知识高频变化（天/周级） | 微调追不上，重训成本吞掉全部节省 | RAG（重新索引分钟级） |
| 必须可溯源 / 可审计 | 微调把知识「揉进权重」，无法指向出处 | RAG（检索片段可回溯） |
| 只是「想让它更聪明」 | 推理能力微调性价比最低，容易过拟合到训练分布 | 换更大基座 / 更好 Prompt / 推理时策略 |

经验判断：多数内部工具（月请求 < 10 万、知识相对稳定）先用 RAG + 好 Prompt 验证价值，
等确认「RAG 答得对但风格/格式/工具协议总错」时，再针对**行为层**做一小次微调。
不要一上来就为「可能性」买单。

### 一个量化的成本账：演示口径

一个量化的成本账（演示口径，价格按当期替换；详见示例 ex10）：

```text
假设：RAG prompt 3000 token（检索片段），微调后 prompt 300 token，输出均 300 token
微调一次性：训练 $80 + 数据清洗标注 $2400，每月维护 $60
RAG 月费：向量库/检索服务 $70

月请求   RAG 月成本   FT 月成本   FT 摊销(12月)   更便宜
  10,000       $71        $120         $290        RAG
  50,000      $355        $600       $770         RAG
 200,000    $1,420      $2,400     $3,090         RAG
1,000,000   $7,100     $12,000    $15,290        RAG
```

注意：即便 token 成本上微调更省，**一次性数据 + 训练 + 维护摊销**在低频场景根本摊不回来。
示例 ex10 的静态盈亏平衡点约「每月 10 万次请求」——很多内部工具到不了这条线。

## 2. 微调 vs RAG 判定树：四个维度，顺序很重要

### 四个决策维度与固定提问顺序

把决策拆成四个维度，**按固定顺序问**，不要同时权衡：

```
Q1. 知识是否高频变化（天/周级）？ ── 是 ─▶ RAG（重新索引分钟级，微调追不上）
   │ 否
Q2. 是否需要引用出处 / 可审计？ ── 是 ─▶ RAG（检索片段可回溯，微调不能）
   │ 否
Q3. 要改的是「知识」还是「行为」？
   ├─ 知识（长尾事实、实体多）────────▶ RAG（微调记不牢，易幻觉）
   └─ 行为（格式/语气/工具调用协议/固定话术）──▶ 微调（这是行为，不是知识）
Q4. 成本：月请求是否高到能摊回数据+训练？ ── 否 ─▶ 先用 RAG
                                 ── 是 ─▶ 微调（6~12 个月内回本）
```

### 判定树的典型结论

判定树落地的几个典型结论（来自示例 ex10 的决策表）：

| 场景 | 选 | 为什么 |
|---|---|---|
| 知识每天变 | RAG | 重新索引分钟级；微调追不上 |
| 知识季度级稳定 + 固定话术 | 微调 | 短 prompt 省钱，风格稳定 |
| 需要引用出处/可审计 | RAG | 检索片段可回溯，微调不能 |
| 输出格式/语气/工具调用协议 | 微调 | 这是行为，不是知识 |
| 长尾事实问答、实体多 | RAG | 微调记不牢，且容易幻觉 |
| 低延迟、无检索服务 | 微调 | 省掉一次检索往返 |

关键认知：**两者不互斥**。最稳的组合是「微调学行为，RAG 供知识」——
让适配器负责语气、格式、工具协议，让检索负责最新事实。很多生产系统的答案就是这条。

```python
# 决策函数的骨架：先问知识频率与溯源，再问改的是知识还是行为
def route(knowledge_freq: str, need_citation: bool,
          change: str, monthly_q: int) -> str:
    if knowledge_freq in ("daily", "weekly") or need_citation:
        return "RAG"
    if change == "behavior":                     # 格式/语气/工具协议
        return "FT" if monthly_q >= 100_000 else "RAG+Prompt"  # 低频先别硬上
    # 剩下是「知识但稳定」的情况
    return "RAG" if monthly_q < 100_000 else "FT"  # 高频稳定才摊得回成本
```

> 经验判断：面试官真正想听的不是「我选 RAG 还是微调」，而是「我先问了哪三个问题、
> 为什么这个场景里知识频率比成本低、以及我知不知道摊销成本」。把判据说清楚，
> 比背结论值钱。

## 3. 推理能力微调：性价比最低的「想当然」

### 一个常见误区：想用微调提升推理

一个常见误区：模型「答得不够聪明」，于是想用微调提升推理能力。
现实是：推理能力来自基座规模与预训练数据，小数据微调几乎无法迁移到分布外推理，
反而会把模型「训窄」到训练集的套路。

### 判据：能写成固定流程就别指望微调

判据：如果任务能被写成「固定流程 + 规则 + 检索」，就不要指望微调解决；
如果任务需要真正的多步推理，微调 500 条样本的效果远不如换更大基座或加推理时策略
（CoT、工具调用、自我校验）。微调擅长的是**风格与格式的可复现**，不是**能力的凭空增长**。

## 三视角解析

### 🧑‍💻 程序员视角

- 先写「评估基线」再写「训练脚本」。没有 RAG 基线和留出集，你根本不知道微调有没有赢；
  很多项目训完发现「不如直接 RAG」，但数据成本已经花出去了。
- 把「该不该微调」做成上线前的一个检查项（checklist）：数据量、知识频率、溯源要求、
  月请求量四项全过才进入训练。把它写进 PR 模板，而不是留在脑子里。
- 就算决定微调，也先跑通「Prompt + RAG」版本拿到业务指标，把它当对照组；
  最终汇报要写「微调相对 RAG 基线 +X 个点（带区间）」，而不是「微调后 87%」。
- 成本要算**全口径**：数据清洗标注的人天、训练算力、回归评测流水线、重训频率。
  只算 token 差会严重低估微调的真实代价（示例 ex10 的一次性数据是每月维护的 40 倍）。

### 🎓 博士生视角

- 微调 vs RAG 本质是**参数化记忆 vs 上下文记忆**的权衡：微调把知识压进参数（推理时不占上下文、可泛化到同分布），
  RAG 把知识留在上下文（每次推理都要检索、可更新、可溯源）。二者的误差来源不同——
  微调有「遗忘旧知识」与「分布偏移」风险，RAG 有「检索召回/排序」瓶颈。
- 从信息论看，微调适合「高频重复、低熵、可分发的模式」（格式、语气、稳定话术）；
  RAG 适合「高熵、长尾、需时效的事实」。用「熵」来分维度比用「直觉」更稳。
- 摊销成本的盈亏平衡可以建模为：`N* = (训练+数据) / (云端单位成本 − 本地/微调单位变动成本)`，
  但真实世界的 `N` 不是常数——知识频率决定了你必须把「重训成本」也摊进分母，
  这会把很多看似回本的场景重新推到 RAG 一侧。
- 组合方案（微调行为 + RAG 知识）在理论上对应「把可学习的低熵部分参数化、把高熵部分上下文化」，
  是帕累托意义上的常见最优解，而非折中。

### 📚 考研者视角

- 常考概念：**参数高效微调（Parameter-Efficient Fine-Tuning, PEFT） vs 全参微调 vs RAG** 的取舍。
  标准表述要能写出：全参微调算力/显存最高但易过拟合小数据；PEFT（如 LoRA）只训少量参数、可插拔；
  RAG 不改模型、靠检索。答题时不要只说「微调效果好」，要分维度。
- 易混点：**微调（fine-tuning）≠ 私有化部署（deployment）**。微调是在某处训练定制权重，
  数据仍可能出域；私有化是部署位置，二者正交。ch06 讲部署，本章讲训练，别混。
- 计算口径：成本对比题通常给「月请求量、prompt 长度差、训练一次性、月维护」，
  要会算摊销（除以 12 个月）再比较。注意单位（美元/百万 token → 美元/token 除 1e6）。
- 另一考点：**什么时候该用 RAG 而不是微调**。标准答法从三维展开——知识时效、可溯源要求、
  数据规模与成本；并点出「推理能力提升不靠微调、行为/格式才靠微调」这一反直觉结论。
