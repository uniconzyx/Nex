# 数据工程：配比去重、对话模板与 loss mask、过拟合与失败归因

> 微调 80% 的工作量在数据，不在训练循环。这一章讲三件最容易「看起来做了、其实没做对」的事：
> 配比（拍来源比例 ≠ 落到目标类别）、去重（MinHash 只找候选、阈值要人工校准）、
> loss mask（prompt 段的 loss 再低也是在背输入）。最后给出「留出集前后对比 + 失败归因」的闭环。

## 1. 数据配比与去重：可行域搜索 + MinHash+LSH

**配比不是按来源比例拍**。不同来源池的类别分布不同，「A:B:C = 5:4:1」听起来合理，
但落地的类别分布可能和目标差一个数量级。示例 ex05 在目标「退款/物流/发票/闲聊 = 30/30/30/10」上对比：

| 配比 | 退款 | 物流 | 发票 | 闲聊 | L1 距离 | 唯一率 |
|---|---:|---:|---:|---:|---:|---:|
| A 单池 | 5.0% | 5.0% | 5.0% | 85.0% | 1.500 | 100% |
| A+B 7:3 | 14.0% | 12.5% | 11.0% | 62.5% | 1.050 | 100% |
| A+B 5:5 | 20.0% | 17.5% | 15.0% | 47.5% | 0.750 | 100% |
| A+B+C 5:4:1 | 17.0% | 15.0% | 21.5% | 46.5% | 0.730 | 98% |
| **穷举最优** | 32% | 28% | 32% | 9% | **0.070** | 98% |

拍脑袋的 `A+B+C 5:4:1` 的 L1 是 0.73，穷举最优是 0.07——**差一个数量级**。
原因：通用池 A 85% 是闲聊，对目标几乎只有噪声贡献，最优解里 A 被压到 0%；
而小类池 C 只有 80 条不同样本，硬拉到 10% 必然重复（唯一率掉到 98%）。
经验做法：报表同时给「来源比例 / 类别比例 / 唯一率」三项，只盯来源比例会掩盖小类缺口。

```python
# 配比本质是在「来源 × 类别」的可行域里搜，而不是凭手感分配来源比例
def realized(mix, pools, cats):
    dist = np.zeros(len(cats))
    unique = 0.0
    for pool, ratio in mix.items():
        size, pool_dist = pools[pool]
        k = int(round(N * ratio))
        dist += ratio * pool_dist
        unique += ratio * min(1.0, size / max(k, 1))   # 池子不够大就会重复
    return dist, unique

# 网格搜索使 L1(落地分布, 目标) 最小，且满足唯一率约束
```

**去重要分两步**：先用 MinHash + LSH 把 O(n²) 的两两比较降到候选对，再用精确 Jaccard 复核。
Jaccard 定义：

```text
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
```

示例 ex04 用 8 条中文客服数据：两两共 28 对，LSH 只吐出 5 个候选对，**减少 82% 的比较量**。
但 MinHash 只是「找出可能重复」，最终是否合并取决于阈值——而且**阈值没有通用值**：

| 阈值 | 删除条数 | 说明 |
|---:|---:|---|
| 0.45 | 3 | 过松：可能误删同主题不同意图 |
| 0.55 | 2 | 较稳：对话去重常用 |
| 0.65 | 1 | 过严：漏删改写型重复 |
| 0.75 | 1 | 过严：漏删改写型重复 |

注意 (3,4) 是同一退货政策的改写，Jaccard 仅 0.517——阈值 0.55 会漏掉它，0.45 才能合并，
但 0.45 又可能误删同主题不同意图的样本。所以**必须抽 30 对人工校准阈值**；
且字符级 MinHash 抓不到「换同义词、换语序」的语义重复，要再叠一层 embedding 聚类。

## 2. 对话模板与 loss mask：只让 assistant 段产生梯度

监督微调的标签是「下一个 token」，且**只有 assistant 说的话才应该计入 loss**。
system/user 段是输入，模型本就该「照抄」——它们的 loss 再低也只是在背输入，不代表学会了回答。

```python
# 标准做法：输入 x[0..T-2]，标签 y = x[1..T-1]（移位一位）；非 assistant 位置置 -100
labels = np.full(T - 1, -100, dtype=int)
for t in range(T - 1):
    if seg_of[t + 1] == "assistant":      # mask 作用在「标签侧」（t+1），即整体右移一位
        labels[t] = ids[t + 1]
```

示例 ex06 用一段「system/user/assistant」对话验证：shift 后，prompt 与 pad 位置全部 `-100`，
只保留 assistant 段的预测位。若把损失算在所有 token 上，模型「训练 loss 很低」
其实是把 prompt 也一起背下来了——这是最常见的虚高来源。

| 位置 | 当前段 | 预测下一 token | 是否计 loss | 后果 |
|---|---|---|---|---|
| t（system/user） | prompt | 多为照抄 | 否（-100） | 不背输入 |
| t+1（assistant） | 回答 | 真正要学 | 是 | 真实梯度 |
| t（pad） | 填充 | — | 否（-100） | 不污染 |

两个高频 bug（ex06 都复现了）：

1. **忘了 shift**：直接拿 `labels = ids` 且 mask 覆盖 assistant 本身，模型学到的是「复制输入」；
2. **mask 起点错**：从 assistant 第一个 token 开始 mask，会漏掉它的首个预测位——正确做法是 mask
   作用在**标签侧**（t+1），即 assistant 段整体右移一位。

> 经验判断：loss mask 错了，训练曲线可能「看起来正常」，但线上一测发现模型在学 prompt。
> 上训练前先打印前 3 条样本的 `input_ids / labels`，肉眼确认非 assistant 段全是 -100。

## 3. 过拟合识别与失败案例归因

**过拟合**：训练 loss 一直降、验证 loss 先降后升，是铁律。早停依据只能是验证曲线。
示例 ex07 的合成曲线：验证最低在 epoch 41（val=0.9429，train=0.7824）；patience=8 应在 epoch 49 停。
若硬训到 89：train=0.4009（还在降）、val=2.7744（比最优点高 194%）、间距比 val/train 从 1.21 涨到 6.92。
三个可写进训练脚本的判据：

```text
1. 绝对判据：val 连续 N 轮不降（N=3~8，按数据量定）→ 回滚到最佳 checkpoint；
2. 相对判据：val/train > 1.5 且持续 5 轮 → 过拟合，降 rank / 加 dropout / 减 epoch；
3. 数据判据：val 曲线抖动方差突然变大 → 验证集太小，先扩验证集再谈调参。
```

经验数字：小数据（500~2000 条）微调常见 **2~4 个 epoch** 就到最优点，10 epoch 基本都在背答案。

**灾难遗忘**：在已训模型上继续训新任务，新任务涨分时旧任务会掉分（参数更新方向冲突）。
示例 ex08 模拟：旧任务初始准确率 0.88，纯训新任务 800 步后旧能力明显下滑；混入 20% 旧数据（replay），
旧能力被拉回、代价只是新任务少了几分。LoRA 只更新低秩增量，本身能减轻遗忘，但**不能替代 replay**——两者叠加最稳。

**失败案例归因闭环**（对应 tech_load 的「失败案例归因」）：拿到「微调前/后」留出集对比后，先分类再修：

| 失败类型 | 证据 | 修复动作 |
|---|---|---|
| 过拟合 | val/train 间距比持续 > 1.5 | 降 rank / 减 epoch / 加 dropout / 扩验证集 |
| 灾难遗忘 | 旧任务留出集掉分 | 5%~20% replay 旧数据；或降学习率 |
| 数据泄漏/重复 | 训练集与验证集有重叠、去重不彻底 | 重做去重 + 严格留出；用 ex04 的精确 Jaccard 复查 |
| 配比失衡 | 小类在验证集全错 | 回到 ex05 的可行域搜索，补小类数据 |
| loss mask 错 | 训练 loss 低但线上学 prompt | 打印前 3 条 labels 确认 -100 位置 |

> 经验判断：很多「微调失败」最后定位到的是数据问题，不是训练超参。
> 所以归因的第一步永远是**复核数据流（去重、留出、mask）**，再动学习率。

## 三视角解析

### 🧑‍💻 程序员视角

- 数据流水线要有「可复现 + 可审计」两个属性：每次混数据都记录 seed、来源比例、去重阈值、留出切分方式，
  否则两个月后你无法解释「这次为什么比上次好」。
- 去重别只跑 MinHash。先 LSH 找候选（省 80%+ 比较），再对候选跑**精确 Jaccard + 人工抽 30 对校准阈值**，
  最后叠一层 embedding 聚类抓语义重复。只做第一步会漏掉大量改写型重复。
- loss mask 上训练前，先写个单测：构造一条含 system/user/assistant 的样本，断言非 assistant 位置全是 -100、
  pad 位置全是 -100、assistant 首预测位被覆盖。这个测试能拦住大部分「学 prompt」事故。
- 留出集和评估脚本要一起交付，且评估必须带**置信区间**（见 ex09）。只报一个 87% 的点估计，
  你无法判断这次微调到底赢没赢——这正是失败归因能成立的前提。

### 🎓 博士生视角

- 数据配比是带约束的分布匹配：目标类别分布 `p*` 是约束，各来源池是「基向量」，混合比例 `w` 是系数，
  求解 `min_w L1(Σ w_i p_i, p*)` 且满足唯一率/量约束。这是一个**有限混合 + 可行域投影**问题，
  不是加权求和的直觉——所以穷举最优（L1=0.07）远优于拍脑袋（L1=0.73）。
- MinHash 的理论保证：对 Jaccard 相似度 `s` 的两文档，分带 LSH 的命中概率约 `1-(1-s^b)^r`
  （b 带数、r 每带行数）。调 b/r 就是调「召回 vs 精度」的偏置；ex04 用 32 带 × 2 行，阈值偏召回。
  但 MinHash 衡的是**集合重叠**，对语义改写天然失效——这是它必须叠 embedding 聚类的根本原因。
- loss mask 本质是「在损失函数上施加结构化零权重」：`L = Σ_{t∈assistant} CE(logit_t, y_t)`，
  等价于只在 assistant 位置的反向图上有梯度流。shift 是为了让 `y_t = x_{t+1}`（自回归），
  错位则把监督信号放到了「当前 token 自身」，模型退化为复制。
- 灾难遗忘可建模为「新任务梯度在旧任务损失上的内积为负」：replay 通过混入旧数据，
  把旧任务的梯度方向重新引入优化，代价是新任务可用的容量/步数被分走一部分——这正是 ex08 权衡曲线的来源。

### 📚 考研者视角

- 常考概念：**数据质量 vs 数据数量**。标准答法：小数据微调更依赖「配比合理 + 去重干净 + 模板正确」，
  而非盲目堆量；重复样本会虚高训练指标、泄漏会虚高验证指标。
- 计算口径：Jaccard 相似度 `|A∩B|/|A∪B|` 要会手算；给定两个集合能直接写比值。
  去重的收益常用「比较次数」衡量：两两比较 O(n²)，LSH 候选对近似 O(n)——考研常考这个复杂度对比。
- 易混：**验证 loss 上升 ≠ 模型坏了**。它是过拟合信号，提示早停/正则；答题时要区分
  「训练 loss 降、验证 loss 升 = 过拟合」与「两者都升 = 学习率过大/数据有问题」。
- 另一考点：**为什么 loss mask 重要**。标准表述：SFT 是next-token prediction，
  只有模型应输出部分（assistant）该计 loss，prompt 部分计 loss 会让模型学「复述输入」，
  且稀释了真正要学的梯度（ex06 显示 assistant token 的梯度权重会被大量 prompt token 稀释）。
