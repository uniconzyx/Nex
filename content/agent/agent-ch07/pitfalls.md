# agent-ch07 易错点：LoRA/QLoRA 微调的六个真实故障

1. **训练 loss 很低但线上一测就露馅，模型在「背输入」而不是学回答**
   - 现象：训练集 loss 降到 0.4，团队以为成了；上线发现模型把 system prompt 原样复述出来，
     或 user 问题重复出现，真正该生成的回答却乱写。
   - 根因：loss mask 没做对——system/user 段甚至 pad 也计入了损失（示例 ex06 复现了这种错位：
     mask 不 shift 时模型学到的是「复制输入」）。prompt 段的 loss 再低也只是照抄，不产生有效梯度。
   - 正确做法：标签整体右移一位，非 assistant 位置全部置 -100（含 pad）；上训练前打印前 3 条样本的
     `labels`，肉眼确认 prompt 段全是 -100。只把 assistant 段的预测位放进损失。

2. **留出集准确率 92%，上线却不如 RAG 基线，指标是「虚高」的**
   - 现象：验证集上比微调前高 10 个点，欢天喜地合并部署；A/B 一开，真实业务指标没动甚至下降。
   - 根因：训练集和验证集没去重，存在重叠样本（同一条客服话术改写多遍），模型在验证集上「见过原题」。
     示例 ex04 显示改写型重复（如同一退货政策的两种说法 Jaccard 仅 0.517）MinHash 默认阈值会漏掉，
     最终训练/验证双高但泛化差。
   - 正确做法：先 MinHash+LSH 找候选，再用**精确 Jaccard + 人工抽 30 对校准阈值**去重；
     留出集必须与训练集严格分离（按会话/按来源切，而不是随机行切）；评估前先复查有无泄漏。

3. **按来源 5:4:1 配比，训练完发现「发票」类几乎全错**
   - 现象：三个来源池按 5:4:1 混合，训练顺利；验证集上主流类还行，但小类（发票/退款）准确率极低。
   - 根因：把「来源比例」当成了「类别比例」。通用池 85% 是闲聊，业务池类别分布又不均，
     最终落地分布和目标差一个数量级。示例 ex05 中拍脑袋的 `A+B+C 5:4:1` 的 L1 距离 0.73，
     而穷举最优仅 0.07——差 10 倍。
   - 正确做法：在「来源 × 类别」的可行域里搜索混合比例，不是凭手感拍来源权重；
     报表同时给「来源比例 / 类别比例 / 唯一率」，小类池样本不足时先补数据，而不是硬拉比例（会重复）。

4. **24GB 单卡一开训就 OOM，第一反应是降 rank，结果表达力砍没了**
   - 现象：QLoRA 训练 7B 报 CUDA out of memory；把 rank 从 16 降到 4 还是偶尔爆，于是再降 batch、
     降 seq，最后模型学不动。
   - 根因：账本算错了——最先爆的通常不是权重，而是**激活**。示例 ex03 的账本：7B 权重经 4bit 双重量化
     只剩 3.24GB，而激活在 batch=4/seq=1024 不开梯度检查点时高达 8GB；降 rank 对激活几乎没影响。
   - 正确做法：救 OOM 的顺序是「先开梯度检查点（8GB→1GB）→ 降 seq/降 batch → 最后才降 rank」；
     再不行用 paged optimizer 把 Adam 状态分页到 CPU。用 ex03 的显存账本公式先定位是哪一块爆，再动手。

5. **汇报「微调后 87%」就对外宣称赢了，其实 82%→87% 只是噪声**
   - 现象：留出集 200 条，模型 A 82%、模型 B（微调后）87%，负责人发邮件「微调提升 5 个点」。
   - 根因：只报点估计，没给置信区间。示例 ex09 显示 200 条样本的 95% 区间约 ±5pp，
     2.5pp 的提升完全落在噪声里；且同批样本上比两个模型要用**配对** Bootstrap / McNemar，
     独立区间会低估显著性。
   - 正确做法：报告必须写「准确率 + 95% 置信区间 + n」；同一留出集对比用配对 bootstrap 或 McNemar
     判显著（ex09 中 A错B对 14、A对B错 10，需看 p 是否 < 0.05）；要把区间压到 ±3pp，留出集至少 700~1000 条——
     这比换模型便宜得多。

6. **训完新任务，旧能力悄悄掉了，直到客诉才发现**
   - 现象：为新增「开发票」技能微调后，新技能可用了；但老用户发现「查物流」「退改签」等旧能力回答质量下滑，
     且没有任何评估报警。
   - 根因：灾难遗忘——参数更新方向与旧任务最优方向冲突，而旧任务根本没放进留出集，
     掉分了也无从知晓（示例 ex08 模拟：纯训新任务 800 步，旧任务准确率明显下滑）。
   - 正确做法：先把「旧任务」定义清楚并放进留出集，作为回归基线；混入 5%~20% 旧数据做 replay
     （ex08 显示 20% replay 能把旧能力拉回，代价只是新任务少几分）；LoRA 低秩本身能减轻遗忘，
     但不能替代 replay，两者叠加最稳。
