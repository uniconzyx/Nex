# agent-ch12 · 商业化与行业解决方案：从 demo 到能签单

> 对应图片 DAY 40（AI 产品变现指南）+ DAY 43（《实战手册》第四章）· 先修：agent-ch04（需求洞察）、agent-ch10（评估方法论）· 面试权重：★★★★☆
> 说明：面试官不问你「AI 怎么商业化」，而问「按席位还是按调用计费、毛利差在哪、
> 单次任务成本怎么拆、POC 验收标准怎么写才不扯皮、SLA 达不到怎么退」。本章把
> 「商业模式 → 成本模型 → 行业方案 → 交付验收」落成**可算的账、可签的条款、可验收的清单**。

## 本章目标

学完你应该能：

1. **拆解三种计费模式的毛利结构与风险转移**：按席位 / 按调用 / 按效果，各自的价格锚点、
   成本结构、超用风险落在谁头上，能画出同一客户在三种模式下的收入-成本曲线并解释分叉点。
2. **建立单次任务成本模型**：把 token 费、推理卡时、向量库、人工兜底四类成本拆开记账，
   算出单位经济（unit economics）与报价下限，并能归因「这个月成本为什么超了」。
3. **给出四条行业赛道的方案骨架**：客服、知识管理、代码助手、营销内容——各自的基线方案、
   真实收益口径与常见坑，能判断一个需求「该不该用 LLM 做、做到哪一档算合格」。
4. **设计 POC → 试点 → 推广的验收口径**：写出可测的验收指标（不是「效果良好」）、
   SLA 与降级预案、数据合规检查项（等保 / 个人信息保护）、失败退出条款。
5. **产出一份《行业方案书》**：含成本测算表、竞品对比矩阵、POC 验收标准三件套，
   数字之间能自洽（报价 ≥ 成本 × 安全系数，不是三个各自拍脑袋的数）。

## 关键认知（本章最值钱的三句）

- **计费模式选的不是「怎么收钱」，是「不确定性风险由谁承担」**：按席位，客户用量暴涨
  你亏；按调用，客户觉得不可预测；按效果，效果归因扯不清。先看成本曲线与用量分布的
  形状，再选模式——顺序反了，合同就是一张卖身契。
- **没有成本模型的报价是赌博**：单次任务成本 = token + 卡时 + 向量库 + 人工兜底，
  四项里任一项漏记，POC 阶段不亏，规模化之后必亏。报价下限 = 成本 ÷ 目标毛利率，
  超支归因要能落到「哪类任务的哪个成本项」。
- **POC 的成败在验收标准签订的那一刻就决定了**：「准确率提升」不是标准，
  「Top-20 高频问题自动解决率 ≥ 60%，误答率 ≤ 5%，按 500 条标注集月度复测」才是。
  验收口径写不清，Demo 再漂亮也会在验收会上变成扯皮会。

## 技术交付物（来自 manifest.tech_load）

**交付物：成本模型脚本（token / 卡时 / 向量库 / 人工兜底）+ POC 验收清单 + 竞品对比矩阵。**
三件合起来就是一份《行业方案书》的骨架。

验收口径（对应 project.json 的任务，逐条可核对）：

- 成本模型：输入「日均任务量 / 平均 token / 兜底率 / 卡时单价」，输出单次任务成本、
  月度成本、三种计费模式下的毛利对比表；固定参数下结果可复现（固定种子）。
- 价格下限：给定目标毛利率，输出报价下限与安全边际；对「用量超预估 3 倍」的 stress
  情形给出按席位计费方的毛利崩塌点。
- 竞品对比矩阵：至少 4 个候选（含自建 / Dify / n8n / 云厂商 API 路线），
  5 个维度加权打分，权重变化时结论如何翻转要能显示出来。
- POC 验收清单：每条指标可测（有口径、有数据集、有测量方法、有判定阈值），
  能自动检查「指标是否可测」（缺数据集 / 缺阈值 / 口径主观 → 判不合格）。
- 方案书自洽检查：成本测算表、报价、竞品结论之间的数字引用一致（如同一成本数字
  在测算表与报价页出现两次必须相等），不一致给出定位。
- 说明：本学科的示例环境禁网、无密钥，所有「客户数据 / 调用流水」均为本地程序化模拟，
  真实接入方式在文中指向对应 GitHub 仓库与 ch03 的客户端封装。
## 与 ai 学科的分界

`ai` 学科负责模型与算法的内部机理：注意力推导、RAG 召回排序的损失设计、
推理加速的量化原理。

本章**只要求商业与交付侧的工程判断**：计费模式与毛利结构、单次任务成本的记账口径、
验收指标的可测性设计、合规检查项与合同条款。遇到「为什么这个模型能做到这个效果」
的机理问题，回 `ai` 学科追推导；本章停在「够用即止的原理 + 工程判据 + 可运行产物」——
一份数字自洽、条款可签的《行业方案书》。
