# 单位经济与成本模型：单次任务的四元账

> tech_load 的场景：报价会上客户问「这么贵，你们成本到底多少」。
> 答不上来，或者答上来但漏了一项，POC 阶段不亏、规模化之后必亏。
> 本章把单次任务成本拆成 **token / 卡时 / 向量库 / 人工兜底** 四项，
> 加上固定成本与规模效应，算出报价下限，并给出超支归因法。

## 1. 单次任务成本四元组与报价下限

中立陈述：单次任务成本 = 变动成本 + 分摊的固定成本。变动成本四项：

| 成本项 | 计量口径 | 典型量级（示例测算） | 主要杠杆 |
|---|---|---|---|
| token 费 | 输入 tok × 单价_in + 输出 tok × 单价_out | ¥0.002~0.05/任务 | 上下文裁剪、缓存、小模型分流 |
| 推理卡时 | 自建时：`QPS × 卡时单价`；API 时计入 token | ¥0.001~0.02/任务（摊薄后） | 连续批处理、量化、利用率 |
| 向量库 | 存储 `GB×月租` + 查询 `QPS×单价` | ¥0.0005~0.005/任务 | 索引压缩、热冷分层 |
| 人工兜底 | `兜底率 × 人工处理单价` | ¥0.1~5/任务 | 置信度路由、错误预防 |

关键结构性认知：**前三项随技术优化可压，第四项（人工兜底）往往是最大且最刚性的**。
一个自动解决率 60% 的客服 Agent，若 40% 进人工、人工 5 分钟/单、时薪 ¥60，
兜底成本就是 `0.4 × 5/60 × 60 ≈ ¥2.0/任务`——token 费在它面前是零头。
**成本模型漏记兜底，等于把最大的成本项设为 0。**

```
单任务成本瀑布（示例测算，客服场景）：

token      ▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇▇                    ¥0.030
卡时(分摊) ▇▇▇▇▇▇▇▇▇                                ¥0.012
向量库     ▇▇▇                                        ¥0.004
人工兜底   ████████████████████████████████████        ¥2.000  ← 40% 兜底率
           └───────────────────────────────────────┘
           合计 ≈ ¥2.050/任务 → 目标毛利率 70% → 报价下限 ≈ ¥6.8/任务
```

报价下限公式：`p_min = c_task / (1 − g_target)`（g_target 为目标毛利率）。
按 ¥2.05 成本、70% 目标毛利，报价下限 ≈ ¥6.83/任务；若按效果计费 ¥12/自动解决
（此为含人工兜底的重交付场景，单价与上篇轻量场景不同属正常），
则只有 60% 自动解决率使有效单任务收入 ¥7.2，**贴着下限过**——用量结构或兜底率
稍一恶化就亏损，这就是「Demo 好看、签单即亏」的算术根源。

```python
def task_cost(tok_in, tok_out, p_in, p_out, gpu_share, vec_share,
              fallback_rate, human_cost):
    """单任务四元成本 + 报价下限（示例测算参数）"""
    tok = tok_in * p_in + tok_out * p_out
    total = tok + gpu_share + vec_share + fallback_rate * human_cost
    return {"token": tok, "gpu": gpu_share, "vector": vec_share,
            "fallback": fallback_rate * human_cost, "total": total}

c = task_cost(tok_in=3000, tok_out=400, p_in=0.008/1000, p_out=0.024/1000,
              gpu_share=0.012, vec_share=0.004, fallback_rate=0.4, human_cost=5.0)
p_min = c["total"] / (1 - 0.70)
print(f"四元成本: " + "  ".join(f"{k}=¥{v:.3f}" for k, v in c.items()))
print(f"报价下限(目标毛利率70%) = ¥{p_min:.2f}/任务")
# 四元成本: token=¥0.034  gpu=¥0.012  vector=¥0.004  fallback=¥2.000  total=¥2.050
# 报价下限(目标毛利率70%) = ¥6.83/任务
```

## 2. 固定成本、规模效应与超支归因

中立陈述：总成本 = `C_fix + Q × c_var`。规模效应体现在三处：
固定成本摊薄（`C_fix / Q` 递减）、推理利用率上升（并发上来后卡时分摊下降）、
向量库查询的规模折扣。但 Agent 产品有一条**反规模效应**：上下文随业务增长变长
（知识库越大、检索片段越多），token 成本占比反而升——「用得越深，每次越贵」。

```
总成本与单任务成本 vs 用量 Q：

总成本   C ╱            C_fix=¥40,000/月
              ╱────────  斜率 = c_var
单任务   c ╲████████
              ╲━━━━━━━━━╲  ← 反规模区：token 占比上升，c_var 不降反升
                Q*        规模效应区
```

超支归因 = 把 `ΔC` 分解到 `ΔC_fix + ΔQ×c_var + Q×Δc_var`。其中
`Q×Δc_var` 最阴险：用量没变、单价没变，但单任务成本涨了——通常是
上下文膨胀（知识库变大）、重试率上升（模型或工具不稳）、兜底率恶化
（新场景错误率更高）。工程判据：**成本看板必须同时显示「用量 / 单任务成本 /
四元占比」三个序列**，只看总账单的团队永远在事后才发现亏损。

```python
def attribute(q0, c0, q1, c1, cfix):
    """成本超支归因：ΔC 拆成 固定成本 / 用量 / 单成本 三份"""
    d_fix = 0.0  # 假定固定成本不变
    d_vol = (q1 - q0) * c0
    d_unit = q1 * (c1 - c0)
    return d_fix, d_vol, d_unit, (q1 - q0) * c0 + q1 * (c1 - c0)

# 示例测算：某月任务量 3万→4.5万，单任务成本 ¥2.05→¥2.30
d_fix, d_vol, d_unit, d_tot = attribute(30000, 2.05, 45000, 2.30, 40000)
print(f"ΔC=¥{d_tot:,.0f} = 固定Δ¥{d_fix:,.0f} + 用量Δ¥{d_vol:,.0f} + 单成本Δ¥{d_unit:,.0f}")
print(f"其中单成本上涨贡献 {d_unit/d_tot:.0%} —— 查知识库膨胀与重试率")
# ΔC=¥41,250 = 固定Δ¥0 + 用量Δ¥30,750 + 单成本Δ¥11,250
# 其中单成本上涨贡献 27% —— 查知识库膨胀与重试率
```

## 三视角解析

### 🧑‍💻 程序员视角

- 账本要按**任务类型**分桶记（售前咨询 / 售后工单 / 知识问答），不要只记总账：
  混合业务里亏损的往往是一类任务，总账会把问题稀释掉。字段至少含
  `{task_type, tok_in, tok_out, retries, fallback, cost, ts}`，落库即可回溯。
- 兜底率是最大的成本杠杆也是最好的告警项：它同时反映模型质量（错了才兜底）
  和流量质量（新场景错误率）。兜底率周环比 +5pp 就要拉警报，比 token 单价波动
  重要得多——单价大家都知道，兜底率只有你知道。
- 上下文裁剪是 token 优化的第一杠杆：RAG 的 top-k、历史对话的滑动窗口、
  系统提示的瘦身，三项做下来输入 token 常见可降 40%~60%（经验判断）。
- 私有化项目要建「卡时账本」：GPU 型号、利用率、并发、排队时长一起记，
  否则月底分摊卡成本全靠拍脑袋；利用率低于 30% 的卡（经验判断）就是在烧钱，
  要么上并发要么缩规格。

### 🎓 博士生视角

- 单位经济是 SaaS 分析框架在 AI 产品的移植：LTV/CAC、边际贡献、回收期
  的数学结构不变，但 Agent 产品的边际成本**非恒定**（任务复杂度异质），
  静态边际成本模型会系统性错估——这是「cost heterogeneity」带来的新问题。
- 规模效应在推理侧的表现与经典制造业相反：制造业是学习曲线（单位成本随
  累计产量幂律下降），推理侧是利用率曲线（`成本/任务 ∝ 1/吞吐` 直到饱和），
  两者叠加才构成总成本曲线；超过饱和点后，扩容是线性甚至超线性（排队、
  批处理窗口拉长）。
- 兜底率与错误率的关系是**选择效应**问题：被兜底的不是随机样本，是「模型
  不确定的样本」，其成本期望高于平均任务；用平均成本估算兜底成本会低估，
  需要按 `E[cost | fallback]` 条件期望算。
- Goodhart 视角：当「降低成本」成为被考核的指标，团队会优先砍可观测性
  （日志、评估集）这类「看不见的成本」——成本模型的输入数据本身就是
  需要被维护的资产。

### 📚 考研者视角

- 必会公式：单任务成本 `c = c_token + c_gpu + c_vec + r_fb×c_human`；
  报价下限 `p = c/(1−g)`；盈亏平衡用量 `Q* = C_fix/(p−c_var)`；
  LTV/CAC 与回收期 `CAC / 月毛利`。
- 常考计算：给定 token 单价与任务 token 分布，算单任务 token 成本；
  给定兜底率与人工单价，算兜底成本并比较「提准确率」与「降人工单价」
  哪条路对总成本影响大（通常是前者，见本篇 ASCII 瀑布的量级对比）。
- 概念链：固定成本 / 变动成本 / 边际成本 / 沉没成本 → 规模经济 / 范围经济 →
  单位经济 → 定价策略；辨析「平均成本」与「边际成本」在定价决策中的不同角色。
- 易错点：报价用「平均成本 + 加成」而不用「边际成本 + 固定回收」——
  多产品线共享固定成本时，分摊方法（按用量 / 按收入 / 按卡时）不同，
  单产品「成本」就不同，合同里要写清分摊口径，否则对账必吵。
