# 入职层：前 30 天生存、转正答辩与证据链

> 入职层的产出是「入职 30 天计划」与转正答辩叙事。试用期的隐性规则：
> 前两周评价你的**学习速度**，第一个月评价你的**判断质量**，转正时评价你的**证据链**。
> 先记住一句话：**试用期不是展示期，是取证期——每周都要留下可核对的产出。**

```text
试用期=取证期(非展示期)
 前2周 评 学习速度
 第1月 评 判断质量
 转正  评 证据链
 动作: 每周留可核对产出(读代码/小切口/建信任)
```

## 1. 前 30 天：读代码、小切口与信任的三个动作

中立陈述：前 30 天的标准切片是四周，每周有一个主任务与一个可验证产出。
**W1 读代码**：跑通本地环境、画出核心链路架构图（不追求全对，追求暴露不懂的地方）、
列「看不懂清单」找 mentor 一次问完。**W2 小切口**：挑一个低风险高可见的小改动
（文档、单测、小 bug）提交第一个 PR——目的是走通「提 PR → 评审 → 合并 → 上线」
的完整链路，不是证明技术。**W3 建信任**：值一次班（on-call 或发布值守）、
做一次跨组同步，让别人知道「有事能找到你、找到你靠谱」。
**W4 攒证据**：把你负责模块的指标基线拉出来（延迟/错误率/成本），
这是后续一切优化的对比基准——没有基线的优化在答辩里不算成果。

```
前 30 天时间线（每周一个可验证产出）
W1 读代码 ──▶ W2 小切口 ──▶ W3 建信任 ──▶ W4 攒证据
 │              │              │              │
 ▼              ▼              ▼              ▼
架构图+      第一个 PR      值班记录+      指标基线+
不懂清单     （走通评审链路）  一次跨组同步   优化候选清单
评价维度:    评价维度:       评价维度:       评价维度:
学习速度      工程习惯        协作可靠性      判断质量
常见死法:    常见死法:       常见死法:       常见死法:
憋两周不问   上来就重构     自己埋头苦干    只优化不记录基线
```

| 周 | 主任务 | 可验证产出 | 常见死法 |
|---|---|---|---|
| W1 | 跑通环境 + 读核心链路 | 架构图 1 张 + 不懂清单 ≤10 条 | 憋两周不提问，截止日交白卷 |
| W2 | 低风险第一个 PR | 合并记录 + 评审意见处理 | 上手就重构「烂代码」，踩雷 |
| W3 | 值班 / 跨组同步 | 值班记录 + 同步纪要 | 只跟 mentor 单线联系 |
| W4 | 拉指标基线 | 基线报告 + 优化候选清单 | 优化了但没记基线，答辩没数字 |

```python
# 30 天计划自检：每周必须有「可被别人核对」的产出，否则这一周在答辩里不存在
PLAN = {
    "W1": ["架构图", "不懂清单"],
    "W2": ["第一个PR", "评审处理记录"],
    "W3": ["值班记录", "跨组同步纪要"],
    "W4": ["指标基线", "优化候选清单"],
}

def check_plan(done):
    missing = {w: [a for a in acts if a not in done] for w, acts in PLAN.items()}
    return {w: m for w, m in missing.items() if m} or "计划完整，每周均可验证"

print(check_plan({"架构图", "第一个PR", "值班记录", "指标基线"}))
# {'W1': ['不懂清单'], 'W2': ['评审处理记录'], 'W3': ['跨组同步纪要'], 'W4': ['优化候选清单']}
print(check_plan(set().union(*PLAN.values())))
# 计划完整，每周均可验证
```

## 2. 转正答辩与证据链：把试用期讲成留任理由

### 转正答辩的四段式骨架

中立陈述：转正答辩的叙事骨架是四段式：**问题**（你发现了什么真问题，有基线数字）、
**动作**（你做了什么决策，为什么这么做）、**数字**（前后对比，带口径）、
**复盘**（失效边界与下一步）。四段缺一段，听众就无法把成果归因到你。
与简历四要素同源：基线=问题、归因=动作、对比=数字、口径=复盘——
转正答辩就是把 STAR-R 的 bullet 展开成 10 分钟演讲。

### 证据链：每个论断挂一个可查产物

「证据链」指每个论断都挂着一个**可查的产物**：PR 链接、A/B 报告、监控面板、
值班记录。口头说「我优化了检索」是观点；「PR #1234 + 前后 P99 对比面板」
是证据。链上最弱的一环决定整条链的可信度——所以宁可少说一件事，
也不要把没有证据的事写进 PPT（经验判断）。

| 证据类型 | 强度 | 能证明什么 | 常见缺口 |
|---|---|---|---|
| 合并的 PR + 评审记录 | 强 | 代码能力 + 协作习惯 | 只有小 PR，没有完整闭环 |
| A/B 或前后对比数据 | 强 | 判断质量 | 没有基线，数字无来源 |
| 值班/故障处理记录 | 中强 | 可靠性 | 没值过班，答辩讲不出线上 |
| 跨组同步纪要 | 中 | 沟通与影响力 | 只跟 mentor 单线 |
| 架构图/文档 | 中 | 学习速度 | 没人用过你的文档 |

```python
# 证据链完整性：每个答辩论断必须挂至少一个可查产物
CLAIMS = {
    "优化了召回质量": {"pr": "PR#1234", "ab": "A/B-0917"},
    "降低了生成成本":  {"pr": "PR#1280"},          # 缺对比数据
    "建立了值班机制":  set(),                       # 空主张：不可归因
}

def evidence_audit(claims):
    weak = [c for c, ev in claims.items() if len(ev) < 2]
    return weak or "全部论断有 ≥2 类证据支撑"

print(evidence_audit(CLAIMS))
# ['降低了生成成本', '建立了值班机制']
```

### 实习变跳板的判据：可迁移证据

实习变跳板的判据是**可迁移证据**：你留下的东西（指标提升、文档、工具、
别人还在用的脚本）在简历上就是 bullet，在面试里就是追问素材。
试用期最后一周做一次「证据盘点」：把 30 天的产物按四段式写成三条 bullet，
和入职时的简历对照——新增的这三条，就是这份实习的真实增量。

## 三视角解析

### 🧑‍💻 程序员视角

- 第一个 PR 故意选小的：文档错别字、补单测、修一个带复现步骤的小 bug。
  目的是用最小代价走完「分支 → PR → 评审 → CI → 合并 → 上线」全链路，
  第二周就能独立提 PR 的人，试错空间比第三周还在问流程的人大得多。
- W1 的架构图必须给别人看：自己觉得懂了和能讲清楚是两回事，
  找 mentor 或同组同事讲一遍，他们指出的「这里不对」就是你最值钱的不懂清单。
- 指标基线要在动手前拉：转正答辩最痛的场景是「我优化了，但说不清从多少到多少」——
  监控面板的历史数据多数只存 30~90 天，第四周才想起来拉可能已经晚了。
- 值班记录是可靠性的硬证据：一次「半夜告警 → 定位 → 止血 → 复盘」的完整记录，
  在答辩里比三个小 PR 更有分量——它证明你在没有监督时也能做对决策。

### 🎓 博士生视角

- 「读代码 → 小切口 → 建信任」的切片符合技能习得的「认知学徒制」：
  先观察专家实践（读代码），再在低风险任务上试错（小 PR），
  最后进入真实责任区（值班）。导师制（mentor）的设计目的就是压缩这个周期。
- 证据链思维与科研的「可复现性」同构：论文要求代码/数据/参数可查，
  答辩要求 PR/数据/面板可查——本质都是「把主张与证据分离，让第三方可验证」。
  学术写作里这对应 results 与 methods 的分离，简历里对应 R 与 A 的分离。
- 前 30 天的「小切口」策略有博弈论解释：新人信息不对称最严重，
  小改动是廉价的信息获取与信号释放（signal）——用可观测的可靠性换后续的信任预算。

### 📚 考研者视角

- 复试「读研规划」题可以直接复用 30 天切片结构：第一阶段文献与工具链熟悉、
  第二阶段小课题复现、第三阶段进入组会交流、第四阶段确立选题基线——
  每周一个可验证产出，比「努力科研」这类表态得分高得多。
- 常考追问「如果导师给的课题你不感兴趣怎么办」：答「先完成最低交付建立信任，
  再用数据争取调整方向」——与「小切口换信任预算」是同一策略。
- 易混点：**实习与科研的时间结构差异**——实习按月切片（周报驱动），
  科研按学期切片（里程碑驱动），复试答题别把「周报式计划」套进三年规划里。
- 答辩/汇报的通用骨架要练：问题 - 动作 - 数字 - 复盘四段，
  缺「复盘」段在学术组会里同样会被认为「没有思考深度」。
