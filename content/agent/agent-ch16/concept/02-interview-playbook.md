# 面试层：八股答题框架、系统设计与三道手写题

> 面试层的产出是「3 次模拟面试录像 + 复盘表」。面试官的问题分四类：
> **八股**（考你知道什么）、**系统设计**（考你怎么决策）、**手写题**（考你能不能把原理落成代码）、
> **行为面**（考你真实怎么做事）。先记住一句话：
> **所有题都按「结论 → 机制 → 数字/对比 → 边界」四段答，不知道边界的回答一律按半懂处理。**

```text
四类题 × 四段答题框架
 八股(知什么) 系统设计(怎么决策) 手写(落成码) 行为(真怎么干)
 四段: 结论 → 机制 → 数字/对比 → 边界
 不知边界 = 按半懂处理
```

## 1. 八股高频题与答题框架：从「背定义」到「给判断」

### LLM 岗位八股的四类

中立陈述：LLM 岗位八股集中在四类：Transformer 基础（位置编码、注意力复杂度、
归一化位置）、RAG（切分、混合检索、重排、评估）、Agent（工具调用、记忆、规划、防护）、
部署推理（批处理、KV cache、量化、显存估算）。面试官区分「背过」与「懂」的方式只有一个：
**追问边界与取舍**。因此标准答题动作是四段式：先一句结论，再讲机制（必要时给公式），
然后必须落到**数字或对比**（「O(N²) 是序列长度的平方」「FlashAttention 省显存不改 token 数」），
最后主动交代适用边界（「这在文档长度 <2k 时不明显，长文档才是主要收益」）。

| 类别 | 高频题 | 一句话锚点（结论） | 必配的数字/对比 |
|---|---|---|---|
| Transformer | 为什么 RoPE 能外推？ | 旋转把位置编进注意力点积，相对位置自然出现 | 复杂度仍是 O(N²) |
| RAG | 召回率 90% 答案还错？ | 错不在召回在「没用上」：切分/重排/生成三层查 | top-k 从 5 到 20 的变化 |
| Agent | 死循环怎么防？ | 无进展检测是主力，步数/预算上限是保险丝 | K=3，K=2 误杀合法重试 |
| 部署 | 显存怎么估？ | 权重 + KV cache + 激活三块账 | 7B fp16 ≈ 14GB 权重 |

```python
# 四段式自检：每条八股答案过一遍这四个问题，缺一段就是「半懂」
def answer_check(answer):
    stages = {
        "结论先行": len(answer.split("。")[0]) <= 40,      # 第一句必须能单独站住
        "有机制": any(k in answer for k in ("因为", "机制", "公式", "流程")),
        "有数字/对比": any(c in answer for c in "0123456789%×倍") or "vs" in answer,
        "有边界": any(k in answer for k in ("但是", "边界", "不适用", "前提", "代价")),
    }
    missing = [k for k, ok in stages.items() if not ok]
    return "完整" if not missing else f"缺: {missing}"

print(answer_check("RoPE 把位置编进 Q/K 的点积里，所以相对位置天然出现，长文本外推比绝对位置好。"))
# 缺: ['有数字/对比', '有边界']
print(answer_check("RoPE 把位置编进 Q/K 点积，相对位置天然出现；复杂度仍是 O(N²)，长序列下注意力仍是瓶颈。"))
# 完整
```

## 2. 系统设计：企业知识库 Agent 的容量账本与分层架构

中立陈述：系统设计题的推演顺序固定为**需求澄清 → 容量估算 → 接口设计 → 架构分层 →
扩展与瓶颈 → 降级与兜底**。容量估算用「回字诀」：从 DAU/QPS 出发，
按读写比例、单条大小、副本系数推存储，按请求大小推带宽，按单卡吞吐推卡数，
每个假设都报出来让面试官纠正——**能自洽比猜得准重要**（误差 2 倍内可接受）。
知识库 Agent 的架构分层：入口（限流/鉴权）→ 预处理（切分/向量化，离线）→
检索服务（BM25 + 向量混合，在线）→ 重排 → 生成（LLM，最贵）→ 后处理（引用、审核）。

```
用户请求
   │
   ▼
┌─────────┐   ┌──────────────┐   ┌────────────┐   ┌──────────┐   ┌────────┐
│ 入口网关  │──▶│ 检索服务      │──▶│ 重排(rerank) │──▶│ 生成(LLM) │──▶│ 后处理  │
│ 限流/鉴权 │   │ BM25+向量混合 │   │ top50→top5 │   │ 最贵的一跳 │   │ 引用/审核│
└─────────┘   └──────────────┘   └────────────┘   └──────────┘   └────────┘
     │               ▲                                    │
     │        离线：切分/向量化                              ▼
     │        （文档更新走增量队列）                    降级路径：
     ▼                                               检索挂→缓存热问；生成挂→返回摘要片段
 超限直接 429（令牌桶，速率按下游生成容量定）
```

### 容量账算例

以「10 万文档、2000 员工、峰值 50 QPS、平均文档 20KB」为例的容量账：

| 资源 | 估算过程 | 结果 | 面试官常追问 |
|---|---|---|---|
| 存储（原文） | 10 万 × 20KB × 3 副本 | 600 GB | 文档更新频率？ |
| 存储（向量） | 10 万 × 50 块 × 1024 维 × 4B × 1.5 索引系数 | ≈ 3 GB | 为什么乘副本系数 |
| 带宽（出） | 50 QPS × 3KB 上下文 + 0.5KB 答案 | ≈ 180 KB/s | 峰值按均值几倍估 |
| GPU（生成） | 单卡 7B fp16 约 20 QPS（经验值） | 3 张起，留 1 张冗余 | 批量能提多少吞吐 |
| 缓存 | 20% 热点问题吃掉 80% 流量 | 命中后生成量降 70%+ | 缓存多久失效 |

```python
def capacity(docs, doc_kb, qps, dim=1024, bytes_per=4, replicas=3):
    """知识库 Agent 容量账本：返回存储/带宽/卡数三类估算（经验系数见注释）。"""
    raw = docs * doc_kb * 1024 * replicas                    # 原文存储（3 副本）
    chunks = docs * 5                                        # 20KB 文档按 4KB 切块 ≈ 5 块
    vec = chunks * dim * bytes_per * 1.5                     # 向量 + HNSW 索引系数 1.5
    out_bw = qps * (3 * 1024 + 512)                          # 上下文 3KB + 答案 0.5KB
    gpus = max(1, -(-qps // 20))                             # 单卡约 20 QPS（fp16 7B，经验值）
    return raw, vec, out_bw, gpus

raw, vec, bw, gpus = capacity(100_000, 20, 50)
print(f"原文存储 {raw/1e9:.1f} GB | 向量+索引 {vec/1e9:.2f} GB | 出口带宽 {bw/1e3:.0f} KB/s | 生成卡数 {gpus}")
# 原文存储 6.1 GB | 向量+索引 3.07 GB | 出口带宽 179 KB/s | 生成卡数 3
```

注意上表的单位口径：原文 10 万 × 20KB = 2GB，乘 3 副本才是 6GB——面试时把
「乘没乘副本」说出来，比结果本身更能体现工程意识。

## 3. 三道手写题与行为面：白板考点、终止条件与反例

中立陈述：三道手写题（BM25 / ReAct / 令牌桶）的共性的是**核心逻辑 ≤ 20 行**，
考的是「能不能把原理压成代码 + 说清每行的决策」。

**BM25**：打分 `IDF(qi)·(f·(k1+1))/(f+k1·(1−b+b·dl/avgdl))`，
`IDF=ln((N−n+0.5)/(n+0.5)+1)`。k1 控制词频饱和（k1=0 退化为布尔匹配），
b 控制文档长度归一（b=1 全归一，b=0 不归一）。白板考点：公式、top-k 排序、
查询词缺失的确定性行为。

```python
import math

def bm25_score(query, doc, idf, avgdl, k1=1.5, b=0.75):
    """BM25 单文档打分：idf 为 {词: idf值}，avgdl 为平均文档长度。"""
    f = {}
    for w in doc:
        f[w] = f.get(w, 0) + 1
    dl = len(doc)
    s = 0.0
    for q in set(query):
        fi = f.get(q, 0)
        if fi == 0:
            continue                      # 查询词缺失：贡献 0，不抛错
        s += idf.get(q, 0.0) * (fi * (k1 + 1)) / (fi + k1 * (1 - b + b * dl / avgdl))
    return s
```

**ReAct**：白板上画四态循环（THINK→ACT→OBSERVE→THINK）加三个终态
（FINISH/ABORT/max_steps 触顶）。考点：状态机显式化、trace 四元组、终止条件。
只写循环不写终止条件 = 0 分——「跑多久停」是 ReAct 工程化的第一问题。

**令牌桶**：容量 C、速率 r 的桶，请求到达取 1 令牌，有则过、无则拒。
公式上等价于「累积上界」：`tokens(t) = min(C, tokens(t−Δ) + r·Δ)`。
考点：突发容量怎么算（空桶等 T 秒最多攒 `min(C, r·T)` 个）、为什么限流阈值要按
下游容量而不是入口带宽定。

```python
class TokenBucket:
    def __init__(self, capacity, rate):
        self.cap, self.rate = capacity, rate
        self.tokens, self.last = capacity, 0.0     # 初始满桶：允许启动突发

    def allow(self, now):
        self.tokens = min(self.cap, self.tokens + self.rate * (now - self.last))
        self.last = now
        if self.tokens >= 1:
            self.tokens -= 1
            return True
        return False
```

**行为面**问的是冲突/失败/优先级，标准结构是「情境→我当时的行为→结果→复盘」，
反例是「我会和同事好好沟通」（态度题）和「是队友的问题」（甩锅题）。
行为面的雷区：把团队成果说成个人、把失败说成「我太追求完美」的伪失败、
优先级题只答排序不答取舍依据。一次好的失败叙事：
「我判断错在把重排延迟优化放在召回质量之前，用 A/B 数据发现 top-3 命中率没动，
两周后换了顺序」——有判断、有数据、有修正。

## 三视角解析

### 🧑‍💻 程序员视角

- 八股答案准备「数字卡片」：注意力 O(N²)、7B fp16 权重 14GB、单卡 7B 约 20 QPS、
  k1=1.2/b=0.75 常用、令牌桶按下游容量定速率——这些数字在嘴里，面试官对你的
  可信度判定直接上一个档。
- 系统设计先问口径再画图：「QPS 是均值还是峰值？读写比？文档会更新吗？」
  三个问题问完，容量账的假设就定了；不问题直接画架构 = 蒙。
- 手写题先写终止条件和边界再写主逻辑：ReAct 没有 max_steps 就是死循环，
  BM25 查询词全缺失要返回 0 分而不是 KeyError，令牌桶时间戳乱序（机器间时钟漂移）
  要按单调时钟或 max(now, last) 处理。
- 模拟面试必须录像：只复盘不录像，第二次会以同样方式犯同样的错（口头禅、
  抢话、答非所问都只有录像能抓到）。

### 🎓 博士生视角

- BM25 的概率视角：它是 BM11/BM15 系列的概率检索模型近似，k1 与 b 没有理论最优值，
  只有与评测集匹配的经验值（Robertson & Zaragoza, 2009 的《The Probabilistic
  Relevance Framework》是标准文献）——所以「怎么调 k1/b」的正确答案是「用标注查询集扫参」，
  不是背默认值。
- ReAct 的地位在「推理与行动交织」：Yao et al.(2022, ICLR 2023) 之前，工具使用
  多为单轮「思考完再调用」，ReAct 把 observation 显式接回下一步的决策上下文，
  这是它与 function calling 流水线的本质差异——面试里能说清这点就是懂。
- 令牌桶属于「泄漏积分器」家族，与漏桶、GCRA（Generic Cell Rate Algorithm，
  ATM 网络遗产）同族；漏桶强制匀速输出（平滑但禁突发），令牌桶允许受控突发——
  面试追问「API 网关为什么多用令牌桶」，答案在下游是否需要吸收营销突发流量。
- 行为面的学术对应是结构化访谈中的「行为样本」：用过去的行为预测未来表现，
  效度高于意图提问（「你会怎么做」）——这也是追问细节（当时几点、数据多少）的原因。

### 📚 考研者视角

- 必背公式三个：BM25 打分（含 IDF）、令牌桶 replenish `min(C, tokens+r·Δt)`、
  注意力计算量 `O(N²·d)`。三个都要能默写并说清每个参数方向。
- 常考简答：「BM25 相比 TF-IDF 改进了什么」——答 TF 饱和（k1）与文档长度归一（b）
  两点，各配一个失效场景（长文档堆砌关键词、短文档被误杀）。
- 系统设计估算题的口径要练：QPS→存储→带宽→卡数四类换算，
  注意二进制/十进制单位（1KB=1024B）、副本系数、峰值=均值×(2~5) 三处最易错。
- 行为面应答模板（复试通用）：冲突题答「目标分歧而非人际分歧」，
  失败题答「可定位的错误 + 修正动作 + 数据结果」，优先级题答「取舍依据 + 如何同步」。
- 易混辨析：**漏桶 vs 令牌桶**（输出平滑性 vs 突发容忍）、
  **限流 vs 熔断**（入口配额 vs 下游保护）、**降级 vs 兜底**（功能裁剪 vs 人工接管）。
