# 简历层：一页纸、STAR-R 与量化指标四要素

> 简历的读者有两类：HR 用 15 秒决定「过不过初筛」，技术面试官把它当成**追问提纲**——
> 你写的每个 bullet 都是面试题的种子。本章 tech_load 是「简历终稿」，
> 先记住一句话：**简历不是履历表，是证据清单；每条 bullet 都要扛得住三层追问。**

```text
简历=证据清单(非履历表)
 一页纸: HR 15秒过筛 / 面试官当追问提纲
 每条bullet = 面试题种子, 扛三层追问
 STAR-R: 把"参与了"改写成"我交付+量化"
```

## 1. 一页纸结构与 STAR-R：把「参与了」改写成证据

中立陈述：一页纸的硬约束来自筛选现场：HR 平均 15~30 秒扫一份简历，
技术面试官平均 2 分钟。能被留下的信息必须**可扫读、可追问、可证伪**。
工程上的做法是「倒金字塔 + 证据密度」：顶部 1/3 放最硬的 2~3 个项目，
每个项目 3~4 条 bullet，每条 40~60 字，一条 bullet 只讲一件事；
技术栈不单独占段落，融进 bullet 的动作里（「用 numpy 重写打分函数」比「熟悉 numpy」信息量大得多）。

STAR-R 把一条项目描述拆成五段：**S**ituation（背景与约束：多大的库、多少 QPS、什么团队）、
**T**ask（你负责的那一件事，边界要小到能独立验证）、**A**ction（你做的关键决策与实现，
写「为什么这么做」不写「用了什么」）、**R**esult（带四要素的量化结果）、
**R**eflection（复盘：如果重来会改什么、这个方案的失效边界在哪）。
最后一段 R 是给面试官追问留的锚——面试官问「这个方案有什么问题」时，
主动说出边界的人比被问出来的人可信度高一个量级（经验判断）。

```
STAR-R 五段式与追问链（每条 bullet 被追问的层级）
┌──────────┬──────────────────────────┬──────────────────────────────┐
│ 段落      │ 回答什么                  │ 面试官顺着它追问什么            │
├──────────┼──────────────────────────┼──────────────────────────────┤
│ S 背景    │ 问题有多大、约束有多硬      │ 「为什么值得做？谁定的优先级？」   │
│ T 任务    │ 你负责的边界               │ 「团队里谁做别的部分？怎么协作？」 │
│ A 动作    │ 关键决策与实现             │ 「为什么用 X 不用 Y？代价是什么？」│
│ R 结果    │ 带四要素的数字             │ 「数字怎么算的？归因给你公平吗？」│
│ R 反思    │ 失效边界与重来会改什么      │ 「更大 10 倍还成立吗？」         │
└──────────┴──────────────────────────┴──────────────────────────────┘
反面：一条没有 R 的 bullet，追问到第三层就塌，整条项目的可信度归零。
```

空话是简历的第一杀手，工程上可以**规则化检测**：动词空话（负责/参与/协助/跟随）、
形容词空话（深入/熟练/很好地/极大地）、不可证伪的成果（效果显著/大幅提升）。
下面是可直接跑的空话扫描器：

```python
import re

EMPTY_PATTERNS = [
    r"负责[^，。]{0,12}$",          # 「负责了 XX 系统」——没写你改变了什么
    r"参与[^，。]{0,12}$",          # 「参与了知识库项目」——边界不可证
    r"(深入|熟练|扎实)掌握",         # 程度形容词，无证据
    r"(显著|大幅|很好|极大)地?(提升|改善|优化)",  # 不可证伪的成果
    r"等等|等工作",                  # 清单没写完
]

def scan_empty(bullets):
    """返回 [(bullet, 命中的空话模式)]，供人工重写。"""
    hits = []
    for b in bullets:
        for pat in EMPTY_PATTERNS:
            if re.search(pat, b):
                hits.append((b, pat))
    return hits

bad = ["负责公司知识库问答系统的开发与维护",
       "参与 RAG 相关模块，熟悉 LangChain",
       "系统性能得到显著提升"]
for b, pat in scan_empty(bad):
    print(f"[空话] {b}  <- 命中 {pat}")
# [空话] 负责公司知识库问答系统的开发与维护  <- 负责[^，。]{0,12}$
# [空话] 参与 RAG 相关模块，熟悉 LangChain  <- 参与[^，。]{0,12}$
# [空话] 系统性能得到显著提升  <- (显著|大幅|很好|极大)地?(提升|改善|优化)
```

改写示范：「负责知识库问答系统（S），独立负责召回层重写（T）：用 BM25 替换原有
关键词匹配，按 300 条标注查询标定 k1=1.2/b=0.75（A）：召回率从 71% 提到 89%，
top-3 命中率从 62% 提到 84%（R，口径见 §2）；复盘发现 b=0.75 对短文档过惩罚，
后续应引入文档长度分桶（R）。」——五个段落全齐，且每一段都可追问。

## 2. 量化指标四要素：没有基线/口径/归因/对比的数字只是装饰

中立陈述：一个数字要成为**证据**，必须同时说清四件事：
**基线**（做之前是多少，同类系统参照是多少）、**口径**（怎么统计的：多少样本、
什么判定规则、是否含边界 case）、**归因**（提升里哪部分是你的动作带来的，
有没有排除流量/季节性等混杂因素）、**对比**（和上一版/竞品/目标的差距）。
缺一个，面试官就有理由认为数字不可信——而面试官的默认假设就是「数字有水分」（经验判断）。

| 要素 | 回答的问题 | 缺失时的面试官判读 | 写法示例 |
|---|---|---|---|
| 基线 | 从多少到多少 | 「0 到 92% 和 90% 到 92% 是两回事」 | 「召回率 71% → 89%」 |
| 口径 | 怎么测的 | 「92% 在 10 条还是 1000 条上算的？」 | 「300 条人工标注查询，全等判定」 |
| 归因 | 凭什么是你的 | 「换成流量变低也说得通」 | 「A/B 同流量两周，其余模块未动」 |
| 对比 | 好在哪一档 | 「别人家是多少？」 | 「高于开源默认配置 6 个点」 |

把四要素做成可执行的自检函数，写完 bullet 先过一遍：

```python
def metric_score(bullet):
    """量化指标四要素自检：返回 (得分, 缺失项)。四要素齐了才是证据。"""
    checks = {
        "基线": ("%" in bullet or "→" in bullet or "从" in bullet),
        "口径": any(k in bullet for k in ("条", "样本", "查询", "天", "周", "判定")),
        "归因": any(k in bullet for k in ("独立", "负责", "改写", "重写", "引入", "替代")),
        "对比": ("→" in bullet or "到" in bullet or "高于" in bullet),
    }
    missing = [k for k, ok in checks.items() if not ok]
    return len(checks) - len(missing), missing

b_good = "独立重写召回层：300 条标注查询上召回率 71%→89%，高于开源默认配置 6 个点"
print(metric_score(b_good))
# (4, [])
b_bad = "系统效果得到大幅提升，准确率很高"
print(metric_score(b_bad))
# (0, ['基线', '口径', '归因', '对比'])
```

常见反例与修法：「准确率提升 20%」→ 补基线与口径（「从 72% 到 92%，1000 条样本」）；
「QPS 提升 3 倍」→ 补归因（「瓶颈在同步 OCR，改异步队列后；同期流量未变」）；
「延迟降低到 200ms」→ 补对比与口径（「P99 口径，压测 50 并发，原方案 850ms」）。

## 三视角解析

### 🧑‍💻 程序员视角

- 简历按「技术面试官的追问成本」倒着写：每个 bullet 自问三层（数字怎么算的 / 为什么用 X 不用 Y /
  大 10 倍还成立吗），答不上来的 bullet 删掉或补写——现场答不上来比不写更伤。
- 技术栈要融进动作句：「用 numpy 向量化 BM25 打分，索引构建从 4s 降到 300ms」；
  单列「熟悉 Python/PyTorch」等于把最贵的版面浪费在最便宜的信号上。
- 项目排序按「与目标 JD 的相关度」而不是按时间倒序：转 Agent 岗时，
  RAG/Agent 项目压实习的运维项目，即使运维更新。
- 空话扫描器（§1）应该成为交简历前的固定动作；JD 关键词对齐用同一套规则反查：
  把 JD 里的技术名词建成词表，逐个确认在简历里有对应证据，没有就删掉 JD 那条要求不匹配的岗位
  （或补一个能对齐的项目）。

### 🎓 博士生视角

- STAR-R 的信息论视角：一条 bullet 的信息量 = 降低的不确定性。空话（「显著提升」）不降低任何
  不确定性，所以无论字数多少信息量都趋零；四要素数字把结果空间从「很好/一般」压到一个可检验的点。
- 「归因」本质是因果推断的最小可识别版本：A/B、同流量对照、DiD 的思想在工程汇报里都够用——
  简历上写「A/B 两周」就是在用最朴素却最可信的识别策略，比任何复杂叙事都硬。
- 追问链结构接近结构化访谈（structured interview）的「情境→行为→结果」范式：
  行为面用「你当时做了什么」而不是「你会怎么做」，正是因为后者测的是想象、
  前者测的是可复现的行为模式——简历的 A（Action）写行为而不是计划，是同一原理。

### 📚 考研者视角

- 复试简历的标准结构要能默写：个人信息 → 教育背景 → 项目/科研经历（倒金字塔）→ 竞赛/论文 →
  技能清单。一页纸是硬约束，超一页在复试现场是减分项。
- 常考追问的应答口径：「你在这个项目里具体做了什么」——用 T 段的小边界回答，
  忌把团队成果说成个人功劳（面试官一句「那队友做了什么」就拆穿了）；
  「遇到的最大困难」——用 R（Reflection）段的结构答：问题→尝试→失败→换路→结果。
- 量化表达训练：把「提升了系统性能」扩写成四要素句式（从 X 到 Y，口径 Z，归因 W，对比 V），
  这是复试英语面试与综合面试都能直接用上的模板句。
- 易混点：**熟悉/了解/精通三档的真实含义**——面试按「精通」档追问是常规操作，
  写「精通 PyTorch」就要准备好被问自动微分与显存优化，保守写「熟悉」反而留出余地。
