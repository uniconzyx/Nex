# agent-ch16 · 简历、模拟面试与入职答辩：把项目讲成录用理由

> 对应图片 DAY 70-90（DAY 70 模拟面试简历辅导 + DAY 90 面试入职）· 先修：agent-ch14（部署与运维）、agent-ch15（性能与成本）· 面试权重：★★★★★
> 说明：这是收尾章，考的不是新知识，而是**把前 15 章的项目讲成录用理由**。面试官不问你「什么是 BM25」，
> 而问「让你给一个 200 人企业知识库写检索，k1 和 b 你怎么调、知识库半年不更新你怎么发现失效」；
> 不问你「什么是 ReAct」，而问「Agent 转了 25 步还没完，你先看哪三个指标」。
> 本章把简历层、面试层、入职层三层各落到**可验证的交付物**上。

## 本章目标

学完你应该能：

1. **把简历压成一页证据清单**：用 STAR-R（Situation/Task/Action/Result/Reflection）重写全部项目描述，
   每条量化指标写全「基线 / 口径 / 归因 / 对比」四要素；用空话检测规则扫出「参与了」「负责了」式描述，
   使一页简历里每个 bullet 都能扛住三层追问。
2. **白板手写三道高频题**：BM25 检索打分（含 k1/b 参数作用与调参方向）、ReAct 循环（状态机 + trace +
   终止条件）、令牌桶限流器（突发容量与拒绝策略）——每道在 20 分钟内写出可运行核心逻辑，
   并说清复杂度、失效边界与真实工程里要在哪里加护栏。
3. **完成 3 次模拟面试录像并复盘出失分点清单**：八股线（Transformer / RAG / Agent / 部署）、
   系统设计线（企业知识库 Agent，容量估算误差 2 倍内自洽）、行为面（冲突 / 失败 / 优先级）各至少一次；
   每次录像产出「失分点 → 改写稿」对照表，下次录像同题不重复失分。
4. **设计企业知识库 Agent 并算清它的账**：从 QPS 出发估存储 / 带宽 / GPU 卡数，
   讲清检索-生成分层、缓存与限流、降级路径，能回答「召回率 90% 但答案错你先改哪一层」。
5. **写出入职前 30 天计划与转正答辩叙事**：按「读代码 → 找小切口 → 建立信任 → 攒证据链」排优先级，
   转正答辩用「问题 - 动作 - 数字 - 复盘」结构把试用期工作讲成留任理由。

## 关键认知（本章最值钱的三句）

- **简历不是履历表，是证据清单**：每条项目描述都要能被面试官追问三层而不塌（「数字怎么算的？
  换个大 10 倍的库还行吗？你自己踩过什么坑」）。STAR-R 里最后的 R（Reflection）就是专门给追问留的锚——
  没有反思段的项目，面试官第一层就挖到底了。
- **面试考的不是「用过什么」，是「判断过什么」**：三道手写题的核心逻辑都不超过 20 行，
  但每一行背后都挂着一串工程决策——BM25 的 k1/b 是词频饱和与文档长度归一的权衡，
  ReAct 的 max_steps 是「宁可漏答不可烧钱」的保险丝，令牌桶的突发容量是「峰值体验 vs 下游保护」的阀门。
  只背定义不答判断，手写题写得再对也过不了。
- **录用理由 = 你让团队的哪个指标变好了多少**：量化指标的四要素（基线 / 口径 / 归因 / 对比）缺一个，
  数字就只是数字。「准确率 92%」没有基线就不是成果，「P99 从 3s 降到 800ms」没有归因就说不清是你的优化
  还是流量变低。写不出四要素的 bullet，宁可删掉。

## 技术交付物（来自 manifest.tech_load）

**三道手写题（BM25 检索打分 / ReAct 循环 / 令牌桶限流）+ 3 次模拟面试录像 + 入职 30 天计划。**

验收口径（对应 project.json 的任务，逐条可核对）：

- **手写题一 BM25**：输入文档集与查询，输出按 BM25 打分排序的 top-k；能在白板上写出
  `IDF·(f·(k1+1))/(f+k1·(1−b+b·dl/avgdl))` 并解释 k1 大/小、b 大/小各自意味着什么；
  对「查询词全库缺失」给出确定性行为（不抛错、不静默返回空）。
- **手写题二 ReAct**：把「想一步-做一步-看一步」落成显式状态机，产出可回放 trace
  （每步 thought/action/args/observation）；必须带终止条件（FINISH / ABORT / max_steps 三选一先到先停），
  并能说出为什么只配 max_steps 不够。
- **手写题三令牌桶**：实现固定容量 + 恒定速率 + 支持突发的限流器，给定请求时间序列输出
  每个请求的准入/拒绝与剩余令牌；能说清「令牌桶 vs 漏桶」的取舍与速率/容量怎么定。
- **3 次模拟面试录像**：每次含完整录像 + 复盘表（失分点 / 原因 / 改写稿），三轮累计覆盖
  八股 ≥ 20 题、系统设计 1 题、行为面 3 题；第三轮录像与第一轮同题复测，同类失分点清零。
- **入职 30 天计划**：按周切片（读代码 / 小切口 / 建信任 / 攒证据），每周有可验证产出
  （架构图、第一个 PR、一次跨组同步、一份试用期指标基线）；转正答辩叙事用四段式：
  问题 - 动作 - 数字 - 复盘。
## 与 ai 学科的分界

`ai` 学科讲模型与算法机理：BM25 与向量检索的数学形式、ReAct 的论文脉络与推理理论、
注意力复杂度的完整推导、推理引擎（vLLM/TensorRT-LLM）的调度算法。

本章**只讲表达与决策**：三道手写题是「把前几章的原理压成 20 行可白板的核心逻辑」，
系统设计是「用容量账本做技术选型」，简历与面试是「把项目讲成证据」。
遇到「BM25 为什么这样设计、ReAct 为什么有效」的机理追问，本章只给够用的解释与判据，
完整推导回 `ai` 学科。
