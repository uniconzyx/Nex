# agent-ch05 易错点：RAG 工程的六个真实故障

1. **切块用字符数估 token，中文块被切大 3 倍，索引变慢、上下文溢出**
   - 现象：配置里写「每块 512 token、重叠 64」，上线后单块实际长达 1500+ token，
     检索返回的几块就把 8k 窗口塞爆，模型开始截尾；向量库查询延迟也随块数异常上升。
   - 根因：`len(text)//size` 是英文经验（1 词≈1 token）。中文在多数 BPE 词表下接近 1 字 1 token，
     用字符数当 token 数，会把块大小低估约 3 倍。块数没变，但每块的实际 token 翻了几倍。
   - 正确做法：中文按「1 字 ≈ 1 token」估算并留 10%~20% 余量；或在切之前真的调用一次 tokenizer
     拿到精确 token 数再切。监控「平均块 token 数」而非「平均块字符数」，避免配置名与实物脱节。

2. **纯向量检索上线，错误码、编号类问题全答错，召回率却显示很高**
   - 现象：评测集上 Recall@5 标着 92%，但用户问「E1234 错误怎么处理」「max_connections 配多少」，
     答案经常是泛泛而谈或编造；抽查发现这些精确术语根本没被向量召回命中。
   - 根因：向量检索（bi-encoder）对稀有、专业、字面精确的术语表征弱，倾向于「语义相近」而非「字面命中」；
     而这类术语恰恰要精确匹配。只用向量一路，等于主动放弃了 BM25 最擅长的词面召回。
   - 正确做法：上**混合检索**（BM25 + 向量），用 RRF 融合而非分值加权；专业术语密集的语料，
     中文 BM25 用二元组分词比通用分词器更稳。先把「精确词面」这半边补齐，再谈语义召回。

3. **重排忘了截断 Top-N，cross-encoder 对全库打分，P95 从 200ms 飙到 8s**
   - 现象：加了一层「重排」想提精度，结果检索延迟暴涨、超时率上升，回滚后恢复。
   - 根因：cross-encoder 需要 query 与 doc 同框编码，无法预计算 doc 向量，复杂度是「候选数 × 单次编码」；
     对它跑全库（几十万候选）等于把延迟放大几十倍。它本该只精排少量候选。
   - 正确做法：融合后**硬截断 Top-20（至多 50）**再进重排；把重排延迟单独打点，
     确认它只作用在 N 个候选上。记住分工：双塔召回（可预计算、快）、cross-encoder 精排（慢、只管 Top-N）。

4. **权限过滤写在「召回之后」，用户 A 查到自己工单却召回一堆用户 B 的，删完 Top-K 空了**
   - 现象：多租户系统里，某租户查询返回的结果又少又偏；更糟的是日志里出现过其他租户的片段，
     合规审计亮红灯。
   - 根因：实现成「先召回 Top-20，再按权限删掉不属于当前用户的」。后置过滤有两个毛病：
     一是删完可能不足 K 条、质量雪崩；二是越权片段在删除前已经被检索链路读取、进过缓存与日志。
   - 正确做法：**前置过滤（pre-filter）**——索引里每块带 `tenant/role/expired` 标签，
     检索第一步就按标签过滤，保证召回的每一步都受过权；缓存键也要带租户与权限版本，杜绝串租户。

5. **只报块级 Recall@K，以为 RAG 没问题，其实黄金证据只命中 1/3**
   - 现象：块级 Recall@5 标 100%，但答案经常答不全；人工一看，黄金证据被切成 3 块、只捞到 1 块，
     模型自然只答出三分之一。
   - 根因：块级命中只看「有没有块在 Top-K 里」，不关心「命中的块是否携带完整可用证据」。
     片段被切块劈开时，块级指标满分、问答级却不及格，这种「命中但不可用」比完全没命中更隐蔽。
   - 正确做法：同时报**块级 Recall@K** 与**问答级答案完整率**；用父子块（检索用子、生成用父）
     让「检索粒度」与「上下文完整」解耦，而不是靠加大 overlap 掩盖。评估永远要两层一起看。

6. **拒答阈值压到极低，无证据也硬答，凭空编出赔偿上限酿成客诉**
   - 现象：为了「看起来什么都能答」，把置信度阈值调得很低；用户问「你们赔偿上限多少」，
     系统没有对应证据却编了个数字，引发投诉与信任危机。
   - 根因：把「高回答率」当成目标，忽略了「误答的代价远大于拒答」。无高置信证据时硬答，
     幻觉外推的概率陡增，而一次错误答案的业务代价（决策失误、合规风险）远高于一次人工介入。
   - 正确做法：用「误答成本 × 误答率」对「拒答成本 × 拒答率」做权衡，反推保守的拒答阈值；
     无证据时返回「依据现有资料无法确认，建议联系人工」，并把误答率、拒答率同时上监控，
     而非拍脑袋压低阈值。
