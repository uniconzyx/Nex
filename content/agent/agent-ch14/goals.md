# agent-ch14 · 职业发展框架：把能力翻译成岗位语言

> 对应图片 DAY 47（《实战手册》第七章）· 先修：agent-ch01（Agent 交付链路全景）· 面试权重：★★★★☆
> 说明：面试官不问你「什么是职业规划」，而是问「你工程维自评 4 级，请出示产物并接受追问」
> 「这个 Agent 上线后帮我省了多少人天」「你的计划和 JD 的差距在哪、12 个月怎么补」。
> 本章把三件事（能力矩阵 / 路径选择 / 作品集）落到**可打分、可追问、可执行**的锚点表与自检工具上。

## 本章目标

学完你应该能：

1. **建立四维五级的能力矩阵并完成一次有证据的自评**：按工程 / 模型 / 产品 / 业务四维，
   每维对照 5 级行为锚点逐级取证（每个等级必须能出示至少一个产物：commit、报告、上线记录、
   用户反馈），产出带偏差校准（自评 vs 他评）的个人能力矩阵。
2. **用 JD 关键词反推岗位能力要求并量化差距**：把任意一份 Agent 相关 JD 拆成
   「关键词 → 四维能力项 → 权重」的匹配表，算出覆盖率、证据率与 Top-3 差距项，
   并说明实习 / 校招 / 社招三种入口的考核差异。
3. **按 STAR-R 结构搭建 5 个项目的作品集目录**：每个项目写全 Situation-Task-Action-Result-Reflection，
   Result 必须带基线、口径、归因三要素；5 个项目中至少 1 个有真实用户（用户数 / 反馈可查）。
4. **排出带关键路径的 12 个月成长计划**：把目标拆成有依赖关系的任务 DAG，
   用 CPM 找出关键路径，用 PERT + 蒙特卡洛算出「按当前时间预算按时完成」的概率，
   并给出砍任务的决策规则。
5. **说清职场基本盘的三件套**：周报（进展-数据-风险-下一步）、技术评审（含技术指标到
   业务指标的换算链）、跨团队指标对齐（北极星 + 护栏），各给出一份模板与一个反例。

## 关键认知（本章最值钱的三句）

- **能力不是「我会什么」，而是「我能出示什么」**：自评的每一级都必须挂可出示产物
  （跑通的 demo ≠ 上线服务，教程跟练 ≠ 独立交付）。面试官的追问全部沿着「产物 → 指标 → 取舍 →
  复盘」向下挖，没有产物的自评在第一个追问就会塌。
- **路径选择决定技能栈的配比，而不是努力的程度**：应用开发 / Agent 工程 / 解决方案 / AI 产品
  四条路径对同一张能力矩阵的权重不同（工程维在 Agent 工程岗占 40%+，产品维在 AI 产品岗占 40%+）。
  选错路径的典型症状是「每个维度都 3 级，但没有一个维度到 4 级」——先定路径，再配资源。
- **计划失效几乎从不是因为不努力，而是因为没有关键路径概念**：把 20 个目标平铺进 12 个月，
  等于把资源均匀撒在关键路径之外。用 CPM 找出决定总工期的那条链，用概率（而非乐观值）
  管理承诺——「预计 10 周」要说成「P50 = 10 周，P80 = 13 周」。

## 技术交付物（来自 manifest.tech_load）

**交付物：个人能力矩阵自评（行为锚点）+ 12 个月成长计划 + 作品集目录。非代码，但要可被面试官逐条追问。**

验收口径（对应 project.json 的任务，逐条可核对）：

- 能力矩阵覆盖工程 / 模型 / 产品 / 业务四维，每维 5 级，每级锚点描述含「可出示产物」要求；
  自评表中每个 ≥3 级的条目必须挂具体产物（仓库 / 报告 / 上线记录 / 用户反馈），不允许空项；
- 自评经他评（mentor / 同学 / 同事）校准，偏差 ≥2 级的维度必须降级或补证，输出偏差表；
- 12 个月计划为任务 DAG（含依赖与工期），输出拓扑序、关键路径、总工期，
  以及按当前周学习时长计算的「按时完成概率」（P50 / P80 两个分位）；
- JD 匹配表：给定 1 份真实 Agent 岗位 JD，输出「关键词 → 四维 → 权重」的覆盖表、
  证据率与 Top-3 差距项，差距项与 12 个月计划的任务能对应上；
- 作品集目录含 5 个项目，每个项目 STAR-R 五段齐全、Result 段含 ≥2 个量化指标
  （有基线、有口径、有归因）；其中 ≥1 个项目标注真实用户（数量与反馈渠道可查）；
- 附一页纸简历信息密度自检（每行可追问点数、空话行清单）与周报模板一份。
- 说明：本学科示例环境禁网、无密钥，本章所有「自评 / 打分 / 规划」工具均为本地确定性程序
  （规则判定 + 固定数据），不调用任何外部服务；面试问答本身不可自动化，工具只生产
  「可被追问的材料」。
## 与 ai 学科的分界

`ai` 学科负责模型与算法的机理纵深：Transformer 完整推导、LoRA 数学、RAG 内部实现、
评估指标的统计性质。本章不重复这些内容，只要求**把已有能力翻译成岗位语言**：
能力矩阵怎么锚定、路径怎么选、作品集怎么结构化、计划怎么排。

遇到「这个指标为什么这样定义、这个误差项从哪来」的机理问题，回 `ai` 学科追推导；
本章停在「够用即止的原理 + 工程判据 + 可运行产物」——所有自评与规划工具都不依赖
任何模型调用，纯本地规则与数值计算，产出物必须经得起面试官逐条追问。
