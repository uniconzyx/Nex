# 能力矩阵：四维五级行为锚点与自评的证据要求

> tech_load 的第一件交付物。职业规划类内容最大的风险是写成鸡汤——本章的全部内容都落在
> 一个可操作的判据上：**每一个自评等级都必须挂一个可出示产物**。跑通教程是 L1，
> 能改参数是 L2，独立交付含评估的产物是 L3，设计系统与兜底是 L4，定义标准与带人是 L5。
> 面试官的追问路径永远是「产物 → 指标 → 取舍 → 复盘」，没有产物的自评在第一个追问就会塌。

```text
四维五级 BARS(行为锚定)
 维度: 工程/算法/系统/业务
 等级: L1跑通 → L2改参 → L3独立交付含评估
        → L4设计系统+兜底 → L5定义标准+带人
 红线: 每级必须挂可出示产物, 无产物自评在首追问即塌
```

## 1. 能力矩阵与行为锚定等级（BARS）：把「我会什么」变成「我能出示什么」

中立陈述：能力矩阵（competency matrix）把职业能力拆成若干维度（本章用工程 / 模型 / 产品 /
业务四维），每维定义 5 个等级，且**每个等级用「行为锚点」描述——即「处在该等级的人
典型地会做出什么行为、交付什么产物」**，而不是「了解 / 熟悉 / 精通」这类不可观测的形容词。
这种方法在人事测评里称为行为锚定等级评定法（BARS, Behaviorally Anchored Rating Scales），
核心思想与面试里的行为面（behavioral interview）一致：**用过去的行为预测未来的行为，
而行为必须留下可出示的痕迹**。

下表是「工程」维的 5 级锚点（其余三维同构，权重与产物类型不同，见 §2 与 concept/02）：

| 等级 | 行为锚点（该等级的人典型行为） | 可出示产物（缺一即降级） |
|---|---|---|
| L1 入门 | 能按教程跑通已有项目，会改配置文件里的显式参数 | 跟练仓库的 commit 记录 |
| L2 使用 | 能在别人搭好的框架里改逻辑，读得懂报错栈并定位到模块 | 带 issue/PR 编号的修改记录 |
| L3 交付 | 能独立把一个需求做成含评估的产物：有指标、有失败样本集 | 上线记录 / 评测报告 / 用户反馈 |
| L4 设计 | 能设计模块边界与兜底策略，能写清取舍与代价 | 设计文档（含备选方案对比） |
| L5 定标 | 能定义团队的工程规范与评估口径，带人复核他人产物 | 被他人引用的规范 / 评审记录 |

自评的判据因此是**产物枚举**而不是自我感觉：声称 L3，就要当场出示「含评估的产物」——
一个只有 demo 没有指标的「智能客服」，按锚点只能算 L2。这正是「熟悉度 ≠ 熟练度」的
工程含义：熟悉度是「我见过多少次」，熟练度是「我独立做成过几次、每次的指标是多少」。

```
自评声明                          →  锚点判定
「熟悉 RAG，看过 20 个教程」       →  L1（只有跟随记录，无独立修改）
「给课程项目加了重排模块」        →  L2（框架内改逻辑，无端到端评估）
「独立上线 RAG 问答，50 条样本    →  L3（含评估的交付物）
 字段级准确率 87%，有失败样本集」
「设计多路召回 + 降级策略，       →  L4（有边界设计与取舍记录）
 写清为什么不用精排模型」
```

```python
def anchor_level(artifacts):
    """行为锚点判定：artifacts 为可出示产物列表，返回最高可达等级。

    产物分级（经验判断，可按团队口径调整）：
      0 无产物        → L0
      1 跟随/教程记录  → L1
      2 框架内修改     → L2（需含定位问题的记录）
      3 含评估的交付   → L3（必须有指标 + 失败样本集）
      4 设计文档       → L4（必须含备选方案与取舍）
      5 规范/带人记录  → L5
    """
    return min(len(artifacts), 5)


cases = {
    "看过 20 个教程":        ["tutorial_notes"],
    "改过课程项目重排模块":   ["tutorial_notes", "pr_fix_rerank"],
    "独立上线 RAG 问答":      ["tutorial_notes", "pr_fix_rerank",
                              "online_record", "eval_report"],
    "设计多路召回并写文档":   ["online_record", "eval_report",
                              "design_doc", "review_notes"],
}
for claim, arts in cases.items():
    print(f"{claim:<12} → 最高可主张 L{anchor_level(arts)}")
# 看过 20 个教程         → 最高可主张 L1
# 改过课程项目重排模块   → 最高可主张 L2
# 独立上线 RAG 问答      → 最高可主张 L3
# 设计多路召回并写文档   → 最高可主张 L4
```

注意上面这个判定器的设计意图：它**只数产物类型，不数数量**。「看过 20 个教程」和
「看过 1 个教程」在产物维度上同级——数量堆叠不能跨级，这是对抗「把熟悉度当熟练度」的
第一道闸门。真正的 L3 判据是产物里有没有「评估」：指标、样本集、失败归因。

## 2. 自评的证据要求与常见偏差：为什么人人自评都偏高

中立陈述：自评（self-assessment）的系统性偏差在组织行为学里有长期记录，最常见的两个是
**宽大误差**（leniency，给自己打的分整体偏高）与**中心化偏差**（avoiding extremes，
不敢打极值导致所有人挤在中等）。心理学里的邓宁-克鲁格效应（Dunning-Kruger effect）
常被用来说明「能力低的人高估自己」，但它是**特定任务上的统计现象而非普遍定律**
（经验判断：它被大众媒体严重简化和滥用，不能拿来给具体个人贴标签）。工程上更可靠的做法
不是引用心理学名词，而是**用证据规则把偏差挤出去**：

1. **产物准入**：每维每级必须挂产物，无产物不得声称该级（§1 的判定器）；
2. **他评校准**：同一张矩阵由 mentor / 同学 / 同事独立评一遍，计算逐维偏差
   `Δ = 自评 − 他评`，`|Δ| ≥ 2` 的维度强制降级或补证（示例 ex03 的量化口径）；
3. **追问预演**：对每个 ≥L3 的条目写 3 个面试官可能追问的问题与答案，
   答不上来的条目降一级——「可被追问」本身就是熟练度的一部分。

```python
def evidence_score(level_claimed, n_artifacts, n_peer_confirmed):
    """证据折减后的有效等级：产物数与他评确认数共同决定最终可主张等级。"""
    by_artifact = min(n_artifacts, 5)                 # 产物准入上限
    by_peer = min(n_peer_confirmed + 1, 5)            # 0 个他评确认最多到 L1
    return min(level_claimed, by_artifact, by_peer)


rows = [("RAG 检索", 4, 2, 1), ("Prompt 工程", 3, 1, 3),
        ("服务部署", 2, 3, 2), ("指标拆解", 3, 1, 0)]
print(f"{'条目':<10}{'声称':>4}{'产物':>4}{'他评确认':>6}{'有效等级':>6}")
for name, claim, arts, peer in rows:
    eff = evidence_score(claim, arts, peer)
    flag = "  ← 降级" if eff < claim else ""
    print(f"{name:<10}{claim:>4}{arts:>4}{peer:>6}{eff:>6}{flag}")
# 条目          声称  产物  他评确认  有效等级
# RAG 检索        4     2        1       2  ← 降级
# Prompt 工程     3     1        3       1  ← 降级
# 服务部署        2     3        2       2
# 指标拆解        3     1        0       1  ← 降级
```

这张表揭示了一个反直觉的事实：**声称等级几乎总是高于有效等级**（表中 4 条里 3 条降级），
而这正是自评不做校准时的常态。面试官不需要懂心理学，他只要沿「产物 → 指标 → 取舍」追问
三轮，没做校准的自评就会自动现形。所以矩阵的正确用法不是「填完很开心」，
而是「填完生成一份补证清单」——降级的条目就是未来 12 个月计划的任务来源（见 concept/02 §2
与示例 ex07/ex08 的排序方法）。

## 三视角解析

### 🧑‍💻 程序员视角

- 把矩阵当**接口**用：每条自评是 `（维度, 声称等级, 产物列表, 他评确认, 有效等级）` 五元组，
  没有产物字段的条目不允许提交——这和写单测一样，不可验证的断言等于没写。
- 降级条目直接转任务：`有效等级 < 声称等级` 的每条都写进 12 个月计划的 backlog，
  附上「补什么产物能升级」的具体判据（如「上线一个带 50 条样本评估的服务」），
  不要写「好好学习 RAG」这种不可验收项。
- 四维权重按目标岗位分配（见 concept/02）：投 Agent 工程岗时工程维权重拉到 40%+，
  投 AI 产品岗时产品维拉到 40%+——**同一张矩阵换一组权重就是一份定制投递策略**。
- 警惕「工具熟悉度通胀」：会调 5 个框架的 API 不等于工程维 L3；判定只看有没有
  「含评估的独立交付」，与用过多少工具无关。

### 🎓 博士生视角

- BARS 与心理学里的「绩效评级」研究同源：评级误差（宽大、中心化、光环效应）是评级者
  的系统性偏差，不是随机噪声——这意味着校准（他评 + 证据规则）比「更认真地自评」更有效，
  因为后者无法消除系统性分量。
- 从测量学角度看，行为锚点是在构造一个**有序分类量表**（ordinal scale）：等级之间的距离
  不假定相等，所以「从 L2 到 L3」和「从 L3 到 L4」的难度差异是经验判断，
  跨级比较（如「我工程维比模型维高两级」）只在同维时间距可比。
- 邓宁-克鲁格效应是 1999 年报告的特定任务实验（幽默/逻辑/语法测试）上的元认知偏差现象，
  后续大规模复现主要支持「能力低者高估的幅度在部分任务上存在」，并非普适定律——
  引用它解释个体自评偏差属于过度外推（经验判断）。
- 与相邻概念的关系：能力矩阵是「胜任力模型」（competency model）在个人职业场景的裁剪版；
  企业用它做招聘与晋升标准，个人用它做差距分析——同一套锚点，两个方向的使用。

### 📚 考研者视角

- 必会概念链：**能力矩阵 → 行为锚点（BARS）→ 自评/他评 → 偏差校准**，
  每个环节的输入输出要能对上：矩阵的输入是维度定义，输出是等级主张 + 证据。
- 常考辨析：**熟悉度与熟练度**（是否留下可出示产物）、**自评偏差的类型**
  （宽大误差 / 中心化偏差 / 光环效应各自的表现）、**量表类型**（名义/顺序/等距/比例——
  能力等级是顺序量表，不能说「L4 比 L2 强一倍」）。
- 计算口径：有效等级 = min(声称, 产物上限, 他评上限)；逐维偏差 Δ = 自评 − 他评，
  `|Δ|≥2` 触发降级或补证——这两个公式是本章应用题的基础，务必能手算。
- 易混概念：**能力矩阵与技能清单**。技能清单是集合（会 Python、会 SQL），
  矩阵是带等级与证据的结构化主张；面试追问的是后者，简历上写的也应该是后者。
