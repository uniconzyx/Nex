# 路径选择：四条岗位路径的技能栈与 JD 关键词反推

> tech_load 的第二件交付物。能力矩阵回答「我在哪」，路径选择回答「我要去哪」。
> 同一张四维矩阵，在四条路径下的权重完全不同；不先定路径就补能力，
> 典型症状是「每个维度都 3 级，但没有一个维度到 4 级」。本章给出四条路径的
> 技能栈与考核差异表，以及一套「JD 关键词 → 四维能力项 → 权重」的反推方法。

## 1. 四条路径的技能栈与考核差异：先定终点，再配资源

中立陈述：AI 相关岗位按日常产出的不同，大致可归为四条路径：
**应用开发**（把模型能力包装成功能，交付面向用户的应用）、
**Agent 工程**（交付能自主规划、调用工具、有评估闭环的 Agent 系统）、
**解决方案**（面向客户场景做技术选型、POC 与交付，重沟通与落地）、
**AI 产品**（定义「做什么」，对指标与用户体验负责，重决策与数据）。
四条路径共享同一张能力矩阵的底层（工程/模型/产品/业务），但**权重与考核入口不同**：

| 路径 | 工程维权重 | 模型维权重 | 产品维权重 | 业务维权重 | 典型日常产出 |
|---|---|---|---|---|---|
| 应用开发 | 45% | 20% | 20% | 15% | 功能模块、接口、前端联调 |
| Agent 工程 | 40% | 30% | 15% | 15% | 工具链、评估集、编排系统 |
| 解决方案 | 30% | 20% | 25% | 25% | POC、选型报告、交付文档 |
| AI 产品 | 15% | 25% | 40% | 20% | 指标看板、需求文档、实验设计 |

（权重为经验判断的教学用默认值，实际应按目标 JD 的关键词频次重新标定——§2 给了方法。）

考核入口的差异比技能栈差异更能决定准备策略：

| 入口 | 主要考核点 | 深度 | 常见挂点 |
|---|---|---|---|
| 实习 | 基础扎实度 + 学习速度 | 1-2 轮技术 + 1 轮主管 | 八股不牢、项目讲不清、编码生疏 |
| 校招 | 项目深度 + 系统设计 | 2-3 轮技术 + 1 轮 HR | 项目没有指标、系统设计没有权衡 |
| 社招 | 交付记录 + 所有权 | 项目深挖 + 场景设计 | 只有「参与」没有「负责」、指标说不出口 |

三者的共同点是**都沿「产物 → 指标 → 取舍 → 复盘」追问**，差异在起手第一问：
实习常问「这个 Bug 你怎么定位的」（学习速度），校招常问「这个系统瓶颈在哪、怎么扩」
（系统设计），社招常问「这个项目你负责什么、上线后指标多少、回滚过一次吗」（交付记录）。

```python
PATHS = {
    "应用开发":  {"工程": .45, "模型": .20, "产品": .20, "业务": .15},
    "Agent 工程": {"工程": .40, "模型": .30, "产品": .15, "业务": .15},
    "解决方案":  {"工程": .30, "模型": .20, "产品": .25, "业务": .25},
    "AI 产品":   {"工程": .15, "模型": .25, "产品": .40, "业务": .20},
}

def path_fit(matrix, path):
    """matrix: {维度: 等级}；按路径权重算加权匹配度（0-100）。"""
    w = PATHS[path]
    return sum(matrix[d] * w[d] for d in w) / 5 * 100

matrix = {"工程": 3, "模型": 2, "产品": 3, "业务": 2}
for p in PATHS:
    print(f"{p}: 加权匹配度 {path_fit(matrix, p):5.1f}/100")
# 应用开发: 加权匹配度  54.0/100
# Agent 工程: 加权匹配度  55.0/100
# 解决方案: 加权匹配度  55.0/100
# AI 产品: 加权匹配度  58.0/100
```

同一张矩阵（工程3/模型2/产品3/业务2）在四条路径下得分接近——这说明「没有短板的通才」
在任何路径都不突出。路径选择的价值不是提高总分，而是**把资源集中到权重最高的 1-2 个维度**：
投 Agent 工程岗就把工程维从 3 顶到 4（权重 40%），比把四个维各提 0.5 级的边际收益高得多。

## 2. JD 关键词反推能力要求：把招聘语言翻译成矩阵语言

中立陈述：JD（Job Description）是高频关键词与隐性要求的混合体。反推分三步：
① **抽取关键词**并按主题归族（框架 / 模型 / 工程 / 评估 / 软技能）；
② **映射到四维**（如「LangChain」→ 工程+模型，「评测集建设」→ 工程+产品，
「跨团队协作」→ 业务+产品）；
③ **标定权重**（关键词出现频次 × 位置权重：职责段 > 要求段 > 福利段），
最后与个人矩阵算覆盖率（要求的能力项有多少被覆盖）与证据率（覆盖项里有产物的比例）。
**覆盖率低是努力问题，证据率低是表达问题**——前者补 12 个月，后者补一个周末。

| JD 关键词族 | 示例词 | 主映射维度 | 次映射维度 | 实习/校招出现频率 |
|---|---|---|---|---|
| 编排框架 | LangChain / LlamaIndex / 自研编排 | 工程 | 模型 | 高 |
| 模型与推理 | RAG / 微调 / 量化 / vLLM | 模型 | 工程 | 高 |
| 评估与数据 | 评测集 / Badcase / A/B | 工程 | 产品 | 中 |
| 系统与工程化 | 高并发 / 分布式 / CI/CD | 工程 | 业务 | 中（校招高） |
| 产品与指标 | 用户增长 / 转化率 / 留存 | 产品 | 业务 | 中 |
| 协作与沟通 | 跨团队 / Owner / 推动落地 | 业务 | 产品 | 低但一票否决 |

```python
KEYMAP = {
    "LangChain": ("工程", "模型"), "RAG": ("模型", "工程"),
    "评测集": ("工程", "产品"), "微调": ("模型", "工程"),
    "高并发": ("工程", "业务"), "A/B": ("产品", "工程"),
    "跨团队": ("业务", "产品"), "vLLM": ("模型", "工程"),
}

def jd_profile(jd_words):
    """JD 关键词 → 四维权重（主映射计 1.0，次映射计 0.5，按词频归一）。"""
    w = {"工程": 0.0, "模型": 0.0, "产品": 0.0, "业务": 0.0}
    for word, n in jd_words.items():
        p, s = KEYMAP[word]
        w[p] += 1.0 * n
        w[s] += 0.5 * n
    tot = sum(w.values())
    return {k: v / tot for k, v in w.items()}

jd = jd_profile({"LangChain": 3, "RAG": 4, "评测集": 2, "微调": 1,
                 "高并发": 1, "A/B": 1, "跨团队": 1, "vLLM": 1})
mine = {"工程": .40, "模型": .35, "产品": .10, "业务": .15}
for d in jd:
    print(f"{d}: JD 要求 {jd[d]:.0%}  我的证据 {mine[d]:.0%}  差 {jd[d]-mine[d]:+.0%}")
# 工程: JD 要求 45%  我的证据 40%  差 +5%
# 模型: JD 要求 36%  我的证据 35%  差 +1%
# 产品: JD 要求 12%  我的证据 10%  差 +2%
# 业务: JD 要求 7%  我的证据 15%  差 -8%
```

上表读法：差值为负的是**补齐优先级**（本例仅业务维 −8%，即 JD 只要求 7% 而我拿出 15% 的
证据反而说明配比错位——业务类项目讲得太多，挤占了工程/模型的讲述时间）；其余三维为正，
说明证据覆盖充分、继续加码边际收益低。反推的常见结论是「只差一维或半维」，
把 12 个月的资源集中砸在负差维度上，比四维平均补课更可能产生可出示的差距。
反推的产出必须落回 concept/01 的矩阵：每条负差维度对应一个「补什么产物」的任务，
进入 12 个月计划的 backlog（ex07 负责排序，ex08 负责算时间预算是否放得下）。

## 三视角解析

### 🧑‍💻 程序员视角

- 换路径先换权重再换努力：把 `PATHS[目标路径]` 的权重表贴在矩阵旁边，每周复盘只看
  权重 Top-2 维度的等级与产物变化，其余维度维持不退步即可——**资源集中比全面发展
  更快产生可出示的差距**。
- JD 反推要读「职责段」而不是「要求段」：职责段描述你每天干什么（权重最高），
  要求段是筛选门槛（满足即可，超额不加分）；福利段的「热爱 AI」类词汇直接忽略。
- 证据率是周末工程：覆盖率靠时间，证据率靠整理——把已有项目按 STAR-R 补齐指标与
  取舍（concept/03），一周能把「覆盖但无证据」的条目洗掉一半。
- 实习准备抓「学习速度信号」：面试官问定位过程时，要讲清「怎么复现 → 怎么二分 →
  怎么验证假设」的完整回路，而不是直接报答案；回路清晰比答案正确更能过实习面。

### 🎓 博士生视角

- 路径差异的本质是**产出函数不同**：应用开发优化「功能交付速率」，Agent 工程优化
  「系统可靠性 × 任务完成率」，解决方案优化「客户场景匹配度」，AI 产品优化
  「业务指标的边际变化」。四条路径的能力权重是产出函数的系数，不是文化偏好。
- 关键词反推在信息检索视角下是一个**词项加权**问题：JD 是查询，个人矩阵是文档，
  相关性 = Σ(词项权重 × 匹配度)。职责段/要求段的位置权重类似 BM25 的字段加权——
  工程上与简历关键词匹配（ATS 筛选）是同一机制的两个方向。
- 考核差异的演化：实习看「学习速度」源于培养成本视角（实习生按未来产出折现），
  社招看「交付记录」源于即战力视角——两套定价逻辑不同，准备策略自然分化。
- 与相邻概念的关系：路径选择是「职业决策」在工程场景的裁剪版；决策理论里的
  期望效用最大化（权重 × 等级）正是 §1 加权匹配度的形式化，区别在于权重本身
  需要按 JD 实测标定（§2），而不是先验给定。

### 📚 考研者视角

- 必会表格：四条路径 × 四维权重（记住相对大小即可：应用开发重工程、Agent 工程
  工程+模型双高、解决方案业务+产品双高、AI 产品重产品），以及实习/校招/社招的
  考核差异表（起手第一问分别是什么）。
- 常考计算：加权匹配度 = Σ(等级 × 权重)/5 × 100；JD 四维权重 = 主映射 1.0 + 次映射 0.5
  后归一；差距 = JD 权重 − 我的证据权重，负差绝对值排序即补齐优先级。
- 概念辨析：**覆盖率与证据率**——覆盖率回答「要求的能力我有没有」，
  证据率回答「我有的能力能不能出示」；前者低是规划问题，后者低是表达问题，
  两者的补救动作与时间尺度完全不同。
- 易混概念：**JD 关键词匹配与能力具备**。关键词命中只说明简历/自评的语言对上了，
  面试官的追问检验的是能力本身——「关键词密度高 + 证据率低」是简历高危组合，
  宁可关键词少而每条有证据。
