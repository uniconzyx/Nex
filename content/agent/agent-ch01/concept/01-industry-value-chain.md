# AI 产业链四层：钱从哪来，毛利被谁拿走

> 这一章不讲「AI 很火」，讲一件更硬的事：**同样的 100 元收入，落在产业链不同层，
> 成本结构、现金流形态、倒闭原因完全不同**。看懂这件事，你才知道自己投的岗位
> 是在「卖水」还是在「淘金」，以及面试时该用什么语言描述自己的价值。

```text
产业链四层（价值自上而下流动）:
  算力层 ──▶ 模型层 ──▶ 推理服务层 ──▶ 应用与工具层
  卖产能      训+授权     按token/卡时    卖结果(订阅/席位)
  利润靠利用率  固定成本亿级  薄利靠调度     最薄靠留存/获客
关键: 越靠下像「卖产能」，越靠上像「卖结果」
```


## 1. 四层结构：算力 → 模型 → 推理服务 → 应用与工具

```
        ┌──────────────────────────────────────────────────────────┐
        │  应用与工具层  Dify / Coze / Cursor / 垂直 SaaS / 内部系统  │
        │  收入：订阅、席位、按次、项目制      客户：企业/开发者/消费者 │
        └───────────────▲──────────────────────────┬───────────────┘
                        │ API 调用费/分成            │ 需求、场景、数据
        ┌───────────────┴──────────────────────────▼───────────────┐
        │  推理服务层  云厂商 MaaS / 私有化部署 / 网关 / 可观测性     │
        │  收入：按 token、按卡时、按 QPS        客户：应用层/企业     │
        └───────────────▲──────────────────────────┬───────────────┘
                        │ 模型权重/授权              │ 推理算力
        ┌───────────────┴──────────────────────────▼───────────────┐
        │  模型层  闭源 API（OpenAI/Anthropic/DeepSeek）与开源权重     │
        │  收入：API、授权、定制训练              客户：推理层/大客户   │
        └───────────────▲──────────────────────────┬───────────────┘
                        │ 训练/推理算力              │ 框架与调度
        ┌───────────────┴──────────────────────────▼───────────────┐
        │  算力层  GPU/加速卡、云主机、机房、网络、存储               │
        │  收入：卡时、包年包月、带宽            客户：模型层/推理层   │
        └──────────────────────────────────────────────────────────┘
```

四层的**收入模式**与**成本主项**可以用一张表锁死：

| 层 | 收入模式 | 最大成本项 | 毛利形态 | 规模效应 | 典型死法 |
|---|---|---|---|---|---|
| 算力 | 卡时/包年包月/带宽 | 折旧、电费、机房 | 中等，随利用率剧烈波动 | 强（重资产） | 利用率不足，折旧压死 |
| 模型 | API token、授权、定制 | 训练摊销、推理算力、人才 | 分化极大：头部高、长尾负 | 中（研发可复用） | 训完没人用，摊销无处落 |
| 推理服务 | 按 token/卡时/QPS | 上游 token、工程运维 | 薄，靠调度与缓存 | 中（软件摊薄） | 被上游降价挤压 |
| 应用与工具 | 订阅/席位/按次/项目 | 模型调用、交付人力、获客 | 最薄，且被获客吃掉 | 弱（人力线性） | 留存差、定制化拖垮 |

**第一性原理**：越靠下，越像「卖产能」，利润由**利用率**决定；越靠上，越像「卖结果」，
利润由**留存与获客成本**决定。中间两层是典型的「夹心」：上游涨价它扛，下游压价它让。

## 2. 毛利结构：毛利率不是净利率，单位经济才是

以「每 100 元收入」为单位做教学模拟（数字是量级假设，不是任何公司的财报）：

```
算力层    收入 100 = 电费18 + 带宽4 + 运维8 + 折旧42 + 毛利28
模型层    收入 100 = 推理16 + 数据5 + 训练摊销26 + 人力14 + 毛利39
推理服务  收入 100 = 上游token52 + 重试4 + 工程14 + 合规4 + 毛利26
应用层    收入 100 = 模型26 + 交付18 + 获客24 + 研发14 + 毛利18
```

三个必须记住的推论：

1. **毛利率高不等于赚钱**。算力层毛利 28%，但如果产能利用率从 70% 掉到 35%，
   折旧按交付量摊薄后翻倍，净利立刻转负：
   `净利率 = 1 − 可变成本率 − 固定成本/(收入×u/u0)`。
2. **应用层毛利最薄，但现金流可以最好**。订阅制预收，回款快；代价是获客成本前置，
   一旦月流失率超过毛利率/CAC 能承受的阈值，增长就是加速失血。
3. **模型层的毛利最不稳定**。训练是一次性重投入，摊销取决于「有多少调用量来分摊」；
   调用量不足时，模型层比应用层更危险，因为它的固定成本是**亿级**的。

应用层的生存线可以写成一个不等式：

```
LTV = ARPU × 毛利率 / 月流失率
健康线：LTV / CAC ≥ 3   且   回收期 = CAC / (ARPU × 毛利率) ≤ 12 个月
```

代入 ARPU=100、毛利率 18%、CAC=260：

| 月流失率 | LTV | LTV/CAC | 回收期 | 判定 |
|---|---|---|---|---|
| 2.0% | 900 | 3.46 | 14.4 月 | 毛利够，但回收慢 |
| 3.5% | 514 | 1.98 | 14.4 月 | 危险 |
| 6.0% | 300 | 1.15 | 14.4 月 | 每单都在亏 |
| 9.0% | 200 | 0.77 | 14.4 月 | 增长=加速死亡 |

注意回收期只由毛利率与 CAC 决定，与流失率无关；**流失率决定的是「你有没有命等到回本」**。
这就是应用层「岗位最多、存活率最低」的数学形式。

## 3. 为什么 2026 年应用层岗位最多，却存活率最低

三个结构性原因（经验判断，可用自己所在城市/行业的招聘数据复核）：

**① 进入门槛最低，供给与竞争同时爆炸。**
调用 API + 前端 + 一个知识库就能做出 demo，导致「能演示」的产品极多，
但「能通过企业验收」的极少。岗位需求因此集中在应用层，竞争也集中在这里。

**② 价值被上游与客户双向挤压。**
应用层不掌握模型定价权，也不掌握客户预算权。上游降价时，客户会问「为什么你还收这么多」；
上游涨价时，应用层只能自己吞。唯一能站住的是**掌握了工作流与数据**的产品。

**③ 交付是人力密集的，规模不经济。**
To B 项目每多一个客户就多一份实施、培训、对接。毛利 18% 意味着：
一个 10 人交付团队，年收入 1000 万，毛利只有 180 万，扣掉销售与管理费用后所剩无几。
这就是为什么「项目制 AI 公司」很难长大，而「标准化 SaaS」才能。

反过来，**存活下来的应用层公司有三个共同点**：
- 卖的是**可量化的结果**（节省多少工时、降低多少差错），不是「用了大模型」；
- 产品里有**越用越多的私有数据**（工作流、标注、历史决策），形成迁移成本；
- 交付**尽量产品化**（模板、连接器、自助配置），把人力从交付里抽出来。

## 4. 一次请求的钱怎么在四层之间分

以一个 RAG 问答为例，单次请求的账单（假设值）：

```
用户付费（应用层）                     0.050 元
 ├─ 应用层自留（毛利+交付）            0.014
 ├─ 推理服务/云 MaaS                   0.022
 │   ├─ 上游模型 token                 0.014
 │   └─ 推理工程/带宽/缓存             0.008
 └─ 算力（含在模型/推理成本里）        ≈0.006
```

这张图解释了两件事：
- **应用层的定价空间被上游成本锁住**：模型降价 50%，应用层才有机会把毛利从 18% 提到 30%；
- **推理服务层最容易被绕过**：大客户会直接找模型厂或自建 vLLM，所以它必须提供
  网关、限流、审计、缓存这些「自己搭很麻烦」的能力。

## 5. 用代码验证，而不是背结论

`examples/ex01-value_chain_margin.py` 把上面四层做成可运行的单位经济表，
并做了两个敏感性实验：算力利用率、应用层流失率。运行后你会看到：

- 四层毛利率都在 18%~39%，差距没有想象中大；
- 但把利用率从 70% 打到 35%，算力层净利从 +28 变 −32；
- 把流失率从 2% 抬到 6%，应用层 LTV/CAC 从 3.46 掉到 1.15。

**这就是「行业认知」的正确形态**：不是记住几个名词，而是能用一个模型算出
「什么条件下这层生意会崩」。

## 三视角解析

### 🧑‍💻 程序员视角

- 你所在的岗位决定了你的**技术栈被谁定价**。在应用层，你的核心价值是
  「把不确定的模型能力包成稳定接口」：重试、超时、降级、评测、成本面板。
  只会调 API 的人可替代性极高，因为上游 SDK 每年都在变简单。
- 选公司时看三个数：**毛利率、留存率、单客交付人力**。毛利率 < 20% 且靠项目制交付的公司，
  你会在 12 个月内被迫同时做售前、实施和售后，技术成长停滞。
- 做成本估算时，永远按「每解决一单」而不是「每千 token」算：
  `单均成本 = (输入 token×单价 + 输出 token×单价) / 任务成功率`。
  成功率从 80% 掉到 60%，成本立刻涨 33%，比换更便宜的模型影响更大。
- 如果你在推理服务层，护城河是**调度与缓存**：前缀缓存、连续批处理、按租户限流。
  这些东西不性感，但直接决定毛利。

### 🎓 博士生视角

- 产业链分层可以用**价值链理论**（Porter, 1985）与**微笑曲线**解释，但 AI 产业链的特殊性在于：
  模型层的边际成本不为零（每次推理都要算力），所以它不像传统软件那样「复制免费」。
  这导致「赢家通吃」被削弱——再强的模型也要为每次调用付电费。
- 规模效应的来源不同：算力层是**资本密集 + 高固定成本**，靠利用率摊薄；
  应用层是**网络效应/数据飞轮**，靠留存摊薄获客。两者的成本函数形状不同，
  不能用一个「规模越大越赚钱」的叙事概括。
- 模型层的成本可以写成 `C(q) = F + c·q`，其中 `F` 是训练投入、`c` 是单 token 推理成本。
  平均成本 `AC = F/q + c` 随 q 下降，但**永远高于 c**；这解释了为什么 API 价格战
  只能打到推理边际成本附近，打不到零。
- 研究「AI 是否提升生产率」时，产业链视角很重要：企业买的是应用层的**结果**，
  而不是模型层的**能力**。生产率收益能否兑现，取决于流程改造与数据质量，
  这也是大量 RCT 研究结论分歧的来源之一（经验判断，具体文献需按主题检索）。

### 📚 考研者视角

- 若报考人工智能/电子信息专硕，本章对应考点是**产业结构与商业模式**类论述题，
  标准答法：先分层（算力/模型/推理/应用），再逐层写「收入模式—成本结构—壁垒」，
  最后落到「为什么应用层竞争最激烈」。
- 常考计算口径：**毛利率 =（收入−营业成本）/收入**，注意营业成本不含销售与管理费用；
  **LTV = ARPU×毛利率/流失率**，**CAC 回收期 = CAC/(ARPU×毛利率)**。
  答题时先写公式再代数，避免把「毛利」和「净利」混用。
- 易混概念：**规模经济 vs 范围经济**。算力层是规模经济（同一产品产量越大越便宜），
  应用层跨行业复制是范围经济（同一能力复用到不同场景）。写反了会丢分。
- 论述题加分点：指出「模型层边际成本不为零」打破了传统软件的零边际成本假设，
  因此 AI 行业的集中度会低于互联网平台，但算力层会更高。
