# agent-ch15 · 项目实操：端到端交付一个可演示的 Agent 产品

> 对应图片 DAY 55（专属项目实战）· 先修：agent-ch05（RAG 检索）/ agent-ch10 / agent-ch11 · 面试权重：★★★★☆
> 说明：这是「交付与求职」链路的开门章，也是整条学习路线的验收章。面试官不问你「什么是 Agent」，
> 而是把本章的产出直接拍在桌上：「demo 链接发一下」「3 周怎么排的」「上线后错了你怎么发现」
> 「单次成本多少、预算超了谁负责」。本章回答一个问题：
> **怎么把一个 Agent 想法变成能公开访问、能回放、能报价、能讲 15 分钟的完整交付物。**

## 本章目标

学完你应该能：

1. **用评分卡做选题决策**：对候选 idea 按「真实用户痛感 / 3 周可行性 / 差异化」三维打分，
   写出「不做什么」清单，把需求与范围冻结成一份双方签字的范围说明书，并能评估任一变更请求
   对工期与风险的影响后再决定是否接纳。
2. **搭出基线并按错误分析迭代**：先用「最简单方案」（规则 / 提示词 / 检索裸调）把链路跑通，
   建立黄金测试集与回归口径；每轮迭代前做错误分类与帕累托排序，先修「损失占比最高的一类」，
   并用回归对比证明「没有修一个坏三个」。
3. **交付可公开访问的 demo**：容器化（一键启动、健康检查、环境变量注入密钥）、
   部署到一台公网可达的主机或平台，配监控面板（请求量 / P95 延迟 / 错误率 / 单次成本）
   与成本看板（按天 burn rate、预算阈值告警），并能说清每个阈值的取值依据。
4. **写齐四件套文档**：README（一键复现步骤 + 架构图 + 已知限制）、架构图（数据流与故障点）、
   3~5 分钟演示视频（脚本先行，失败兜底话术）、复盘文档（目标 vs 实际、数据、下一步）。
5. **完成一次 15 分钟答辩**：把「选题 → 范围 → 基线 → 迭代数据 → 上线指标 → 成本 → 复盘」
   装进时间盒，每个部分有可核对的数字，被追问时能落到具体错误样本与设计权衡。

## 关键认知（本章最值钱的三句）

- **选题决定交付质量的上限，评分卡决定你不浪费时间**：有真实用户（痛点高频、替代方案贵）、
  有明确验收（什么算「成了」）、3 周能做完（依赖可排序、关键路径 ≤ 3 周）——
  三条缺一条，中后期必然烂尾。「先做个聊天框再说」是本项目章最贵的死法。
- **先跑通基线，再谈优化；迭代按错误分析排序，不按感觉**：基线是「最简单方案」的
  端到端可运行版本，它同时是你的对照组与回归安全带；没有黄金集回归的迭代是拆盲盒——
  每轮「优化」都可能在你看不见的样本上退化，而你要到答辩前一天才知道。
- **交付三件套（容器 / 监控 / 成本）不是运维加分项，是产品定义的组成部分**：
  没有健康检查与回滚的 demo 是「演示时祈祷」；没有成本面板的 Agent 是「月底账单惊吓」；
  demo 的观众（面试官 / 用户）第一眼看的是 README 与演示视频，不是你的 prompt。

## 技术交付物（来自 manifest.tech_load）

**交付物：端到端产品 —— 可访问 demo + 容器部署 + 监控面板 + 成本看板 + 15 分钟答辩材料。**

验收口径（对应 project.json 的任务，逐条可核对）：

- **可访问 demo**：公网可达 URL（或本地一键启动 + 录屏兜底），核心用户任务
  （如「上传一份文档 → 得到带引用的答案」）端到端可完成；页面/接口明确说明
  「模型为本地模拟还是真实调用」，不拿假数据当真指标。
- **选题与范围文档**：评分卡（三维打分有依据）、范围说明书（含「不做什么」清单）、
  3 周计划（任务依赖图 + 关键路径 ≤ 21 天），任一变更请求有影响评估记录。
- **基线与评测**：最简单方案的基线可运行；黄金测试集 ≥ 50 条、每条含输入与
  可判定期望；每轮迭代前后跑同一黄金集，输出「通过数 / 失败样本 / 新增失败」
  三列对比；回归验收口径 = 无新增失败样本（或新增失败有明确归因与豁免记录）。
- **容器部署**：Dockerfile 一键构建启动；健康检查（存活/就绪两探针）生效；
  密钥走环境变量不入库；提供本地复现步骤（clone → 一条命令 → demo 可用）。
- **监控面板与成本看板**：四个指标（请求量 / P95 延迟 / 错误率 / 单次成本）有按天曲线；
  成本看板能算出 burn rate 与「预算耗尽日」预测，超阈值触发告警（阈值有依据）。
- **文档与答辩**：README / 架构图 / 演示视频（3~5 分钟）/ 复盘文档四件齐全；
  15 分钟答辩有时间分配表，讲完后观众能复述「你解决了谁的什么问题、数据是多少」。
- 说明：本学科示例环境禁网、无密钥，所有「模型」「部署」「流量」均为本地模拟
  （规则打分、模拟请求流、文本看板），真实接入方式在文中指向对应 GitHub 仓库与 ch03 客户端封装。

## 与 ai 学科的分界

`ai` 学科负责模型与框架内部：检索器的向量实现、Agent 框架源码、推理成本的技术细节。

本章**只负责把能力变成交付物**：选题怎么打分、范围怎么冻结、错误怎么排序、
指标怎么上墙、文档怎么组织、答辩怎么讲。遇到「为什么这个方案效果差」的机理问题，
本章只给定位方法（哪类错误、哪一层），深挖回 `ai` 学科；
本章停在「够用即止的原理 + 工程判据 + 可运行产物」。
