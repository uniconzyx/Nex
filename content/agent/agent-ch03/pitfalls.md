# agent-ch03 易错点：模型接入的六个真实故障

1. **流式响应按网络包解析 JSON，解析成功率掉到 70%**
   - 现象：本地用短提示测试一切正常；上线后长回答偶发丢字、`json.loads` 报 `Unterminated string`，
     前端看到半句话后卡住。
   - 根因：TCP 是字节流，不保证消息边界。一个 `data: {...}` 事件可能被切成 3 个包，
     也可能 5 个事件挤在一个包里；按 chunk 直接 `json.loads` 必然在字符串/对象中间截断。
   - 正确做法：维护**行缓冲**（`buf += chunk`，按 `\n` 切行），再维护**事件缓冲**
     （多行 `data:` 用 `\n` 拼接），空行才 dispatch。为跨包场景写单测：
     把同一段流按 1/3/7/13 字符切分，断言解析结果一致。

2. **所有错误统一重试 3 次，401 把 300ms 的失败拖成 3 秒**
   - 现象：密钥过期后，每个请求都重试 3 次才报错；错误率没降，P99 反而涨了 10 倍，
     日志里同一 `request_id` 出现 3 条 401。
   - 根因：把「可恢复错误」与「配置错误」混为一谈。401/403/400/404 重试一万次也不会变对；
     重试只会放大延迟、配额消耗与日志噪音。
   - 正确做法：先分类再重试——鉴权/入参/策略错误**快速失败并告警**；
     429 看 `Retry-After`；5xx/超时有限次退避；非幂等写操作必须带幂等键才允许重试。

3. **系统提示里塞了时间戳，前缀缓存命中率归零，账单涨 40%**
   - 现象：为了「让模型知道现在几点」，在系统提示第一行写 `当前时间：2026-10-21 10:00:03`；
     上线后 token 单价没变，但日均成本明显上升，缓存命中率监控为 0%。
   - 根因：前缀缓存要求**从第一个 token 起逐字节一致**。时间每秒变化，前缀永远不命中，
     整段系统提示都按未命中计费。
   - 正确做法：稳定前缀（角色、规则、工具定义、few-shot）放在最前且不含任何动态字段；
     时间、用户名、会话 ID 放到**用户消息**或末尾。缓存命中率要打点，按 `cached_tokens / prompt_tokens` 监控。

4. **用「字符数 ÷ 4」估算中文 token，请求超窗或截断丢关键信息**
   - 现象：本地测试 3000 字的文档能进 8k 窗口，线上同一篇报 `context_length_exceeded`；
     或者为了「保险」强行截断，把合同金额截掉了。
   - 根因：`chars/4` 是英文经验值。中文在多数 BPE 词表下接近 1 字 1 token，
     用 1/4 估算会把长度低估约 4 倍。
   - 正确做法：中文按「1 字 ≈ 1 token」估并留 15%~20% 余量；请求后用厂商返回的 `usage` 校准；
     截断时系统提示与安全规则固定保留、不参与截断。

5. **只设了总超时，首字 30 秒才到，用户以为系统卡死**
   - 现象：接口最终返回 200，但用户在前 30 秒看到空白页，大量重复点击导致并发翻倍；
     监控上「成功率 100%」，投诉却很多。
   - 根因：总超时约束的是资源占用，不约束「用户感知」。模型排队/冷启动时，
     连接一直占着但没有任何 token。
   - 正确做法：**首字超时（TTFT）与总超时分开设**：TTFT 2~5 秒，超时立即降级到备用厂商或模板；
     总超时按 `TTFT + max_tokens/速度` 估。流式接口还要支持客户端取消，及时释放连接。

6. **以为「OpenAI 兼容」就是换 `base_url`，tool call 与 reasoning 全崩**
   - 现象：切厂商后，带工具的请求开始 400；或者把 `reasoning_content` 当答案直接展示，
     用户看到一段「让我想想……」；或者 JSON 模式偶发返回带 markdown 代码块的文本。
   - 根因：兼容层只统一了请求形状，没有统一语义：tool call 的 id 长度/回传要求不同，
     JSON 模式的强制程度不同，reasoning 字段是否返回不同，usage 字段名也不同。
   - 正确做法：接入层做**能力探测 + 适配器**（工具 id 截断/映射、JSON 解析失败重试、
     reasoning 与 content 分离、usage 字段归一），并为每个厂商跑一套契约测试，
     而不是假设「同名参数 = 同行为」。
