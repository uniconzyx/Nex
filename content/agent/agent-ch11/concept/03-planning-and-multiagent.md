# 规划与多智能体：ReAct、终止条件、handoff 与成本爆炸

> 规划回答「 Agent 怎么决定下一步」，多智能体回答「什么时候值得拆成多个」。
> 这两个问题的工程答案都比直觉保守：**ReAct 的循环必须有终止条件兜底，
> 多智能体的每一跳 handoff 都是全额计费的调用**。
> 先记住一句话：**单 Agent + 好工具能解决就不要上多智能体；
> 上多智能体的合法理由只有「角色上下文互相污染」和「并行刚需」。**

```text
规划循环 vs 多智能体成本
 单 Agent + 好工具  ──优先──▶ 解决问题(不拆)
        │ 角色上下文互相污染 / 需并行
        ▼
 多智能体: A ─handoff▶ B ─handoff▶ C   (每跳=全额计费调用)
 ReAct 循环: Thought→Action→Obs ──必须有终止条件兜底
 判据: 单Agent能解就别上多智能体
```

## 1. ReAct 与 Plan-and-Execute：两种规划循环的适用面

中立陈述：ReAct（Reason + Act）把「想一步、做一步、看一步」显式化成循环：
每步由模型产出 thought → action → observation，直到 FINISH。
它的优势是**错误恢复**（observation 直接修正下一步，不需要整体重来）和
**可观测**（每步四元组落盘即 trace）；劣势是**短视**（局部最优、可能绕路）和
**步数不可预算**。Plan-and-Execute 先产出完整计划再逐步执行，
优势是**全局结构清晰、可并行**；劣势是**计划失真时纠偏成本高**
（环境变化让前三步全部作废）。反思与重试（对失败步自我批评后重做）的收益有边界：
对「参数错、格式错」这类可定位错误收益显著；对「知识缺失、目标歧义」
基本无效——重试十次不会让模型知道它不知道的东西。

```
ReAct:            ┌─▶ thought ─▶ action ─▶ observation ─┐
                  └────────────── 循环直到 FINISH ◀──────┘
Plan-and-Execute: plan（一次）─▶ [step1, step2, ...] ─▶ 逐步执行 + 计划修订（replan）
```

| 维度 | ReAct | Plan-and-Execute |
|---|---|---|
| 计划粒度 | 每步局部决策 | 全局一次规划 |
| 纠偏成本 | 低（observation 直接改下一步） | 高（触发 replan） |
| 可并行性 | 差（天然串行） | 好（无依赖步骤可并行） |
| 步数可控性 | 差（必须配死循环防护） | 好（步数 ≈ 计划长度） |
| 适用任务 | 探索型、环境反馈密集 | 结构型、子任务独立 |

混合架构（先 plan 出骨架、每步内部 react 微调）是当前主流工程解——
LangGraph 的图结构本质上就是「把 plan 编码成图、节点内部 react」。

## 2. 终止条件与死循环防护：三个检测器的分工

中立陈述：Agent 失控有三种形态——**原地重复**（同参数反复调同一工具）、
**空转烧钱**（动作在轮换但 observation 永远一样）、**只规划不动手**
（持续思考不出 action，烧上下文不烧工具）。三个检测器分工不同：
**步数上限**（`max_steps`）和**预算上限**（累计 token/金额）是兜底保险丝——
结构简单必配，但意味着「已经烧够了才停」；**无进展检测**是提前拉闸的主力：
最近 K 个 observation 两两高度相似（Jaccard ≥ 0.9）或连续 K 步无 action 即熔断。
阈值 K 是误杀/漏杀的权衡：K=2 会把「换参数重试一次」当死循环（误杀合法重试），
K=5 放过更多真循环；工程上取 3 并要求「换参数即重置计数」（经验判断）。

```
失控形态            检测器响应
原地重复      ──▶ 无进展检测：observation 相同，第 K 步拉闸
空转烧钱      ──▶ 无进展检测：observation 高相似，第 K 步拉闸
只规划不动手  ──▶ 无进展检测：连续无 action，第 K 步拉闸
（以上漏网）  ──▶ 步数上限 / 预算上限：兜底，但已烧满预算
```

触发后的动作要分级：先**提醒换策略**（把「你在重复」注入上下文），
再**熔断转人工**，不要直接杀任务——直接杀等于把「快成功的第 31 步」也杀掉。

## 3. 多智能体：角色分工、handoff、共享黑板与成本爆炸

中立陈述：多智能体把一个 Agent 拆成多个角色（如分诊/执行/审核），
角色间通过 handoff（控制权移交，携带上下文）或共享黑板（公共状态区）协作。
收益来自**专业化**（每个角色的 prompt 更短更聚焦、工具权限更小）与
**并行**（无依赖子任务同时跑）；代价是**交接成本**：每次 handoff 是一次
全额计费的模型调用，且默认传递全量上下文——同一份背景被 N 个角色
各传一遍，这是多智能体成本爆炸的主因。共享黑板（结构化公共状态，
角色只读写自己关心的字段）是对冲手段。成本账必须按角色分开记：
主力执行角色通常是成本大头（单价高、上下文长），分诊/审核应该用便宜模型——
「用贵模型干轻活」的角色错配是纯浪费（实测成本 +7% 而成功率不变，ex08）。

```
单 Agent:   [规划+工具+写作+审核 全在一个上下文里] ─▶ 1 份上下文 × N 步
多智能体:   triage ─handoff─▶ worker ─handoff─▶ reviewer
              │                │                  │
              └─ 若不共享黑板：同一背景被传 3 遍，成本 ≈ 3 份上下文 × 各自步数
```

| 协作机制 | 上下文传递 | 适用 | 主要风险 |
|---|---|---|---|
| handoff | 全量移交 | 控制权明确转移 | 重复传上下文烧钱 |
| 共享黑板 | 各读写相关字段 | 多角色长协作 | 状态竞争/覆盖 |
| 流水线（无交互） | 只传产物 | 子任务独立 | 错误不互知 |

选型判据（缺一不可）：角色上下文**互相污染**（一个 prompt 装不下两种职责）、
子任务**真正独立**（值得并行）、以及**有人买单**（成本账算得过来）。
为了「看起来高级」上多智能体，是 ch11 最常见也最贵的翻车方式。

## 三视角解析

### 🧑‍💻 程序员视角

- 每一跳 handoff 前问自己：这次移交能不能只传 diff 而不是全量上下文？
  共享黑板 + 结构化状态能把三方调用的上下文从 3 份压到 1 份，这是多智能体
  最值钱的工程优化，比换模型有效得多。
- 死循环防护的检测器要分级处置：无进展触发先注入「你在重复相同操作」的提醒，
  同一任务第二次触发才熔断——直接杀任务会误杀「第 31 步就成功」的长任务。
- trace 落盘是底线工程：每步记 thought/action/args/observation + token + 双时延，
  缺一项，线上出事时你连「死在哪一步、烧了多少钱」都答不出来。
- 多智能体先算账再动手：按角色记调用次数/token/成本/成功率，
  返工轮次的边际增益（第 N 轮多买几个百分点）要能说出来，否则上限就是拍脑袋。
- 人工介入的挂起要设计成「状态机暂停 + 外部事件唤醒」：暂停期间不能丢已完成
  的副作用，恢复后从断点继续——这和检查点（concept/02）是同一套机制。

### 🎓 博士生视角

- ReAct 的提出（Yao et al., 2022，ICLR 2023）把「推理轨迹与工具交互」交织成
  单一生成过程；Plan-and-Execute 类工作（如 LangChain 的 plan-and-execute、
  HuggingGPT 式的任务分解）代表「先全局后局部」的另一极——
  两者差异的根源是「决策粒度 vs 纠偏成本」的权衡，不是优劣。
- 反思（reflection/self-critique）的收益边界可以用「错误可定位性」解释：
  可定位错误（语法、格式、参数类型）重试有效；不可定位错误（知识缺口）
  重试只会反复采样同一错误模式——这与 RL 中「优势信号稀疏时策略梯度
  近乎随机游走」是同一现象的不同表述。
- 多智能体的理论基础接近经典 MAS（multi-agent system）的角色与协作研究：
  handoff 是「控制权转移」，黑板模型（blackboard architecture）源自
  HEARSAY-II 式的知识共享架构——LLM 时代只是把「知识源」换成了「角色 prompt」。
- 成本爆炸可以从信息论角度近似：N 个角色各持全量上下文时，总 token 量
  ≈ N × 单角色上下文 × 步数；共享黑板把共享部分从 N 份降到 1 份，
  这正是「通信复杂度」在 Agent 工程里的投影。

### 📚 考研者视角

- 必会对比：**ReAct vs Plan-and-Execute**（决策粒度、纠偏成本、可并行性、
  步数可控性四维度）；**handoff vs 共享黑板**（上下文传递方式与风险）。
- 常考简答：「Agent 死循环怎么防」——三层答案：步数上限、预算上限、
  无进展检测（observation 相似度 / 连续无 action），并说明为什么
  无进展检测是主力、阈值 K 为什么不能取 2（误杀合法重试）。
- 概念辨析：**重试与反思的区别**——重试是同样输入再采样，反思是带上
  自我批评再采样；对可定位错误有效、对知识缺口无效，这是高频陷阱题。
- 计算口径：多智能体总 token ≈ 各角色上下文之和（含重复传递部分），
  能算出「N 角色全量 handoff」与「共享黑板」两种方案的成本差。
- 论述题骨架：「什么任务值得上多智能体」——答：角色上下文互相污染、
  子任务真正独立、成本账算得过来，三条缺一不可；
  反对「为了架构好看而上多智能体」的论述要给出手账对比。
