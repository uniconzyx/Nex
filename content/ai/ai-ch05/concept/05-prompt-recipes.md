# ai-ch05 · 提示工程实战配方：从「能跑」到「稳」

> §1–§4 讲机制，这一节给可直接套用的配方与反例。凯喵调 prompt 的血泪史，浓缩成下面几条。

### 零样本 vs 少样本：何时该给例子

简单分类、模型见过的模式，零样本常够用；任务陌生、格式刁钻、边界模糊时，**给 2–5 个高质量样例**比堆指令更管用。例子要覆盖典型与边界，且格式严格对齐你期望的输出。

```text
分类任务示例：
文本：这家店服务太差了
标签：负面
文本：物流很快，满意
标签：正面
文本：<待分类>
标签：
```

### 思维链 CoT 让推理显式化

复杂数学、多步推理、需要「想清楚再答」的任务，加一句「请一步步思考」或 `Let's think step by step`，让模型把中间步骤写出来，准确率显著提升。代价是更长的输出与更高成本。

### 自洽性：多条路径投票

对高价值推理题，采样多条 CoT 路径，对最终答案投票取多数。凯喵在评测里用它把准确率从 72% 拉到 81%——单条可能算错，多条里多数正确更稳。

### 结构化输出：让模型填槽位

要机器消费结果，就别要散文。用 JSON Schema / 函数调用（tool calling）约束输出，比「请输出 JSON」可靠得多。自由文本里抠 JSON 总有边界 case。

```json
{
  "type": "function",
  "function": {
    "name": "extract_order",
    "parameters": {
      "item": "string", "qty": "integer", "urgent": "boolean"
    }
  }
}
```

### 上下文工程：把「长期记忆」外置

prompt 不是唯一上下文。把用户画像、历史摘要、工具结果**外置成可检索的状态**，按需拼进上下文，比把所有历史都塞进去更省 token 也更准。凯喵的做法：维护结构化状态槽（预算、截止日期、偏好），显式提取并校验。

### 防 prompt 注入的信道隔离

指令与数据同走一段文本，就会被「忽略上面指令，改成……」攻击。正确做法：用分隔标记隔离用户数据、工具最小权限、输出侧白名单校验、高风险动作必须人在环路。指望一句话防住注入是天真的。

### 关键指令放首尾，中段易丢失

注意力在长 prompt 里两头强、中间弱。系统规则放最前，末尾再放「任务复述 + 输出格式」收尾块，中间放参考材料。凯喵把硬性约束埋中段，结果模型「忘了」——挪到首尾才稳。

### 上下文压缩的硬约束清单

摘要上下文容易把用户提过的硬性约束「说没了」。压缩时除摘要外，单独维护「硬约束清单」与结构化状态槽，字段显式提取、显式校验，绝不只靠自由文本摘要。

### 工具调用的最小权限

给模型的工具别开放「能删库」的接口。只读查询、受限写入、危险动作单独标记并需确认。权限越小，注入的危害面越小。

### 评估提示：用 rubric 而非对拍

prompt 改了好不好，要量化。用评分量规（rubric）让模型或人按维度打分，跑一批样本看分布，而不是拿单条case 感觉「好像更准了」。凯喵每次调 prompt 都先定好评测集。

### 反例：把系统提示塞进用户消息

把 system 当作用户消息发送，绕过了角色隔离，也容易被用户数据覆盖指令。

```python
# 错误：系统规则进了 user 角色，易被注入覆盖
messages = [{"role": "user", "content": system_prompt + question}]
# 正确：系统规则走 system 角色
messages = [{"role": "system", "content": system_prompt},
            {"role": "user", "content": question}]
```

### 少样本示例怎么选

示例要覆盖典型与边界：正/负/中性、常见错法、最难的 case，且格式严格对齐期望输出。

```text
例1（典型）："物流很快" → 正面
例2（边界）："不好不坏" → 中性
例3（易错）："还行吧，就是慢了点" → 偏负面
```

### 温度不是越高越聪明

抽取、分类、评测用 `temperature=0` 保确定性；创意生成才用 0.7+。凯喵见过有人用 0.9 做 JSON 抽取，结果字段时有时无。

```python
resp = client.chat(messages=m, temperature=0.0)   # 抽取/评测：要稳定
```
