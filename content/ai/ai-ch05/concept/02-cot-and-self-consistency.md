# 思维链与推理增强：CoT、自洽性与工具循环

## 一、CoT 为什么有效

**核心机制**：CoT（Chain-of-Thought）让模型先生成中间推理步骤。它的作用不是「让模型变聪明」，而是：

1. **把计算摊到多个 token 上**。Transformer 每一层的前向计算量固定，一个 token 位只能做有限深度的组合。输出中间步骤等于**用序列长度换取计算深度**。
2. **把中间结果写回上下文**。后续 token 的注意力可以直接「读取」前面写下的中间结论，不必在隐状态里同时维持所有中间量。

这两点共同解释了为什么 CoT 对**多步算术、逻辑链、符号操作**有效，而对**单步检索型问题**（例如「法国首都是哪里」）几乎无收益——后者的答案不需要多步组合。

**涌现特性（emergent ability）**：CoT 的收益随模型规模非线性放大——小模型用 CoT 往往还不如直接回答（甚至会因为生成了错误中间步骤而更差）。这是「能力阈值」现象的典型例子，也提醒我们：**提示技巧不是普适的，它和模型能力耦合**。

## 二、CoT 家族的主要变体

| 变体 | 做法 | 适用 | 代价 |
|---|---|---|---|
| Zero-shot CoT | 加一句「Let's think step by step」 | 快速试水 | 步骤质量不可控 |
| Few-shot CoT | 给出带推理步骤的示例 | 需要固定推理范式 | 上下文开销大 |
| **Self-Consistency** | 采样多条推理路径，对**最终答案**做多数表决 | 有确定答案的推理题 | 成本是 n 倍 |
| Least-to-Most | 先拆解子问题，再逐个求解 | 复杂组合题 | 需要两次往返 |
| ReAct | 在推理中交替调用外部工具（搜索/计算） | 需要外部事实或精确计算 | 工程复杂度高 |

**Self-Consistency 的关键点**：它投票的是**答案**，不是推理路径。多条路径可以完全不同，只要最终答案一致，就提高了置信度。它把「一次生成」变成了「一次采样 + 一次聚合」，因此**成本是 n 倍、延迟也是 n 倍**——这是它没成为默认选项的原因。

## 三、CoT 什么时候反而有害

- **单步任务**：徒增 token 成本，还会引入「无中生有」的中间步骤。
- **强格式约束任务**：要求严格 JSON 输出时插入推理文本会破坏可解析性（正确做法是把推理放在 `reasoning` 字段，答案放在独立字段）。
- **能力不足的模型**：见上文涌现特性，小模型上 CoT 可能负收益。
- **需要「不推理」的高一致性任务**：例如固定模板的字段抽取，让模型自由推理反而降低稳定性。

## 三视角解析

### 🧑‍💻 程序员视角

**工程上，CoT 是一个要用 A/B 测出来的开关，而不是默认打开的优化。** 判断流程：① 任务是否真的需要多步组合（用「人类不看中间步骤能否一次答对」做代理判据）；② 打开 CoT 后在固定测试集上量准确率与 token 成本，算「每提升 1 个点准确率多花多少钱」；③ 若采用 Self-Consistency，把采样数 n 当超参扫（n=1/3/5/9），通常 n>5 后准确率进入平台而成本线性上升。

**踩坑提醒**：把 CoT 和结构化输出混在一个字段里输出，是最常见的可解析性事故来源——推理文本里的花括号会直接破坏 JSON 解析。

### 🎓 博士生视角

**CoT 的机制可以从「计算深度 vs 序列长度」的权衡来形式化**：常数层数的 Transformer 对序列位置的组合能力，等价于允许在 n 步内完成一个深度为 n 的计算图。没有中间 token 时，模型必须在固定层数内完成全部组合，这构成一个**计算复杂度上的硬约束**。

**涌现性的一个解释方向**是与「任务可分解性」耦合：当模型具备足够的中间步骤生成质量（每步正确率 p）时，多步链的整体成功率约为 p^k，因此存在一个 p 的临界值——低于它，链越长越差；高于它，链越长越好。这解释了为何同一提示在不同规模模型上表现出「阈值式」差异。

**Self-Consistency 的信息论视角**：它是对模型输出分布做**边缘化近似**——对多条路径的答案做多数表决，近似于在「答案空间」上取众数，降低了对单条路径采样噪声的方差。其收益上界取决于路径间的**错误相关性**：若多条路径犯同一个系统性错误（例如同一个前提理解错），投票无法纠正；这决定了它的收益是「降方差」而非「纠偏」。

### 📚 考研者视角

**面试常考口径**：

1. **CoT 为什么有效**：答「把多步计算展开到序列上，用 token 换计算深度，并把中间结果写回上下文供后续注意力读取」。**不要**答成「让模型更聪明 / 激活了更多参数」。
2. **Self-Consistency 投的是什么票**：投**最终答案**，不是推理路径。追问点通常是「为什么不做路径投票」——因为路径本就允许多样，答案才是要收敛的量。
3. **ReAct 的两个循环**：Reason（思考）+ Act（调用工具），观察结果再回到 Reason。它是「推理 + 工具」的交替循环，不是单纯的多步 prompt。
4. **易错口径**：以为 CoT 万能（不提负收益场景）；把 Self-Consistency 说成「多次运行取平均」（它是投票，不是数值平均）。
