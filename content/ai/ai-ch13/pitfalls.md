# ai-ch13 · 推理引擎与量化部署：KV Cache 分页、continuous batching、GPTQ/AWQ/GGUF · 常见错误

1. **部署预算只算模型权重，漏掉 KV Cache** —— 错在：预估显存时只按 `参数量×2字节` 算 14 GB，认为 24 GB 卡能轻松跑 7B。

   *为什么*：7B 模型 fp16 权重约 14 GB，但 batch=32、seq=2048 的 KV Cache 还要 32 GB。权重是固定成本，KV Cache 随并发与长度线性膨胀，两者叠加远超显存，直接 OOM。

   *怎么改*：显存账要算两项：权重（固定）+ KV Cache（层数×头×维度×2×长度×batch×字节，变动）。按目标并发与上下文长度反推所需显存。

2. **用连续分配 KV，长上下文直接 OOM** —— 错在：给每条序列按 max_seq_len 预分配连续 KV 块，以为「简单可靠」。

   *为什么*：内部碎片（多数序列用不满）+ 外部碎片（长短不一留空洞）+ 共享 prefix 重复存，三件事让显存利用率极低，长上下文高并发时迅速 OOM。

   *怎么改*：用 PagedAttention 切块+块表+物理块池，按需分配并支持前缀复用，碎片与重复存储问题一并解决。

3. **静态批处理拖垮尾延迟** —— 错在：把请求凑满一个固定 batch 再统一前向，认为「batch 越大越快」。

   *为什么*：batch 内步调必须一致，慢请求没生成完，快请求干等，GPU 空转；实时到达的请求还要排队等下一批，尾延迟和首延迟都爆炸。

   *怎么改*：改用 continuous batching：以 decode 步为调度单位，出 EOS 即释放、空位补新请求，把利用率从批级提到步级。

4. **把 continuous batching 当「免费午餐」** —— 错在：以为开了连续批处理就自动万能，不做显存/KV 管理。

   *为什么*：连续批处理每步要维护活跃集合、重排张量、管理变长 KV，调度与内存管理复杂度高。没有 PagedAttention 这类机制，动态进出的变长 batch 在显存上根本落不了地。

   *怎么改*：连续批处理必须与 PagedAttention 配套：块表管理让请求动态进出、长度不一时显存高效复用，否则调度收益被内存管理拖垮。

5. **盲目追求 int4，精度崩了还不知道** —— 错在：看到 int4 体积只有 fp16 的 1/4，直接全量化上线。

   *为什么*：位宽越低可表示级别越少，量化误差越大，没有补偿算法的裸量化会让模型输出明显变傻，而压缩比好看掩盖了精度损失。

   *怎么改*：用 GPTQ/AWQ 等带补偿的量化；量化后用下游评测验证精度，在显存/带宽与任务精度间取平衡，别只看压缩比。

6. **误以为 GGUF 是一种量化算法** —— 错在：听说 GGUF 能跑大模型，认为「用 GGUF 就等于做了量化」。

   *为什么*：GGUF 是 llama.cpp 的模型文件格式（统一头+magic+量化类型+超参），它封装的是 GPTQ/AWQ 或 llama.cpp 自家的量化结果，本身不发明量化算法。混淆会选错技术路线。

   *怎么改*：明确分工：量化算法选 GPTQ/AWQ/llama.cpp 量化；GGUF 是这些结果的打包与加载容器，面向本地/CPU 离线推理。

7. **GPTQ 拿错/没有校准集** —— 错在：随便抓几条文本当校准集，或直接不校准就量化。

   *为什么*：GPTQ 的层内补偿依赖校准集估计激活分布，校准集与真实分布偏差大，补偿方向就错，量化后精度掉得比裸舍入还狠。

   *怎么改*：用与目标任务分布一致的、有代表性的小批量数据做校准（通常几百条），且量化后做下游验证。

8. **AWQ 没保护显著通道，误差被放大** —— 错在：以为 AWQ 就是普通 per-channel 缩放，没按激活显著性区分通道。

   *为什么*：AWQ 的核心是按激活幅度保护重要通道——激活大的通道量化误差会被放大。若不做显著性缩放，权重均匀量化，显著通道的相对误差变大，精度劣于预期。

   *怎么改*：按 activation^alpha 归一化对权重通道做缩放，让显著通道的相对误差更小，再量化；这正是 AWQ 比朴素 per-channel 强的地方。

9. **前缀复用没开，共享 prompt 重复算 KV** —— 错在：多请求带同一段长 system prompt，却没启用 prefix caching。

   *为什么*：每条请求各自存、各自重算那段共享 KV，显存翻倍、TTFT 变长。在「百条请求共用一段 512 token 系统提示」场景，省下的 87.5% KV 白白浪费。

   *怎么改*：启用 prefix caching：共享 prompt 的 KV 只算一次、块表共享，既降显存又降首 token 延迟。
