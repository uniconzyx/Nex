# KV Cache 与分页注意力：显存账、碎片与复用

自回归生成的本质是「一个 token 一个 token 往外蹦」。第 t 步计算 attention 时，理论上需要
第 1..t-1 步所有 token 的 Key/Value。朴素做法是每步都把历史重算一遍——复杂度 O(n²)，根本
不可用。于是有了 **KV Cache**：把每一层、每一个历史 token 算出来的 K、V 张量缓存下来，第 t 步
只需算当前 token 的 Q，再和缓存的 K、V 做注意力。这样每步复杂度从 O(n²) 降到 O(n)，代价是
显存里要常驻一份随序列增长的 KV 缓存。

## 显存账：KV Cache 到底吃多少

```text
   请求A: [block0][block1][block2]     物理块池 (PagedAttention)
   请求B: [block0][block3]             block1/2/3 可跨请求复用，不再连续占满
   传统: 每请求预分配最大长度 → 碎片多；分页: 按需取块 → 碎片≈0
```


一层的 KV Cache 大小 = `batch × seq_len × 2(K+V) × n_heads × head_dim × dtype_bytes`。
叠满 `n_layers` 层再乘层数。举例：7B 级模型常见配置 `n_layers=32, n_heads=32, head_dim=128`，
fp16（2 字节）下，**单条 4096 长度序列**就需要约 2 GB；batch=32、seq_len=2048 时直接冲到 32 GB。
这就是为什么长上下文 + 高并发时，显存往往不是被「模型权重」占满，而是被「KV Cache」占满。
做部署预算时，权重是固定成本，KV Cache 是随并发与长度线性膨胀的变动成本，二者都要算。

## 碎片问题：连续分配撑不住多请求

传统实现给每条序列预分配「连续」的 KV 显存块，长度按最大可能 seq_len 预留。问题随之而来：
① **内部碎片**——多数序列用不到预留长度，空着也是浪费；② **外部碎片**——序列长短不一，
连续大块申请/释放后留不连续的空洞，新请求申请不下；③ **无法复用**——多个请求共享同一段系统
提示词（prefix），却各自存一份相同的 KV，白白翻倍。这正是 vLLM 提出 PagedAttention 的动机。

## PagedAttention：像操作系统分页一样管 KV

PagedAttention 借用了虚拟内存的「分页」思想：把 KV Cache 切成固定大小的**块（block）**，每块
存若干 token（如 4 个）的 K/V。序列的逻辑块号通过一张**块表（block table）**映射到物理块，
物理块可以是不连续的。好处：① 按需分配——序列长到哪、块申请到哪，消灭内部碎片；② 物理块
池化——碎片被统一调度，外部碎片几乎消失；③ **前缀复用（prefix caching）**——多条请求共享
的系统提示词只存一份物理块，块表指向同一块，省下大量重复 KV。这就把「每条序列独占一整段
连续显存」变成了「所有序列从同一块池里按需取页」。

## 复用是显存与延迟的双赢

前缀复用的收益不止省显存：共享 prompt 的请求不必各自重算那一段 KV，首 token 延迟（TTFT）
显著下降。在「100 个请求都带同一段 512 token 系统提示」的场景里，不复用要算 100 份共 4096
token 的 KV，复用后只算 1 份 512 token——节省比例可达 87.5%。这也是为什么很多推理服务把
system prompt 的 KV 显式缓存起来。

## 三视角解析

### 🧑‍💻 程序员视角
- 做部署预算时权重是固定成本，KV Cache 是随并发和长度线性膨胀的变动成本，两者都要算，别只盯着模型大小。
- 传统连续分配有内部碎片（预留过长）和外部碎片（长短不一留空洞），还会对共享 prefix 重复存——这三点正是要解决的。
- PagedAttention 把 KV 切块、用块表映射、物理块池化，前缀复用让共享 system prompt 的请求只算一份 KV，TTFT 直接降下来。
- 调block size 是工程权衡：太小块表大、调度开销高；太大会有零星内部碎片。常用 16 或 32，按业务测。

### 🎓 博士生视角
- KV Cache 是自回归模型的「记忆机制」在显存上的投影：它把 O(n²) 的注意力重计算降为 O(n) 的查表，代价是用空间换时间。这本质是注意力计算的无损缓存——缓存的是已算出的线性投影结果，而非近似。
- PagedAttention 与操作系统的页表是同一抽象：逻辑块号→物理块号的映射、按需分页、共享页（copy-on-write 式的前缀复用）。区别在于缺页由「序列增长」触发而非「内存不足」，且不存在写时复制的复杂性，因为 KV 块是只读共享的。
- 显存账揭示了一个架构事实：长上下文推理的瓶颈正从「算力」转向「显存带宽与容量」。FlashAttention 等优化也是在减少 KV 的读写次数，与 PagedAttention 的显存管理互补而非冲突。

### 📚 考研者视角
- 记忆锚点：**KV Cache 用空间换时间，O(n²)→O(n)；显存账=层数×头×维度×2×长度×字节；PagedAttention 切块+块表+前缀复用**。
- 与 408 的「虚拟内存/分页」对照：块表≈页表，物理块池≈页框池，前缀复用≈共享内存页。操作系统那套思想直接搬到了显存管理。
- 面试常问「为什么长上下文显存爆炸」「PagedAttention 解决了什么」：答 KV 随长度线性涨 + 连续分配碎片 + prefix 重复存，三点一锅端。
