# 量化取舍：GPTQ / AWQ / GGUF 权重量化

模型权重默认以 fp16 存储：7B 模型约 14 GB，70B 约 140 GB，单卡根本装不下。量化（quantization）
把权重从高精度（fp16/bf16）压到低精度（int8/int4），**文件体积与显存占用近似按比特数等比下降**
（fp16→int4 约 4x），同时减少显存带宽压力——解码时每个 token 要从显存搬权重，带宽省了延迟也降。
代价是精度损失：权重的离散化会引入误差，处理不好模型就「变傻」。

```text
位宽账（7B 模型，仅权重）：
    fp16 / 16 bit   7e9 × 2 B ≈ 14 GB
    int8 /  8 bit             ≈  7 GB
    int4 /  4 bit             ≈ 3.5 GB
    每降一半位宽体积减半，代价是精度损失，且各层敏感度不同

三条路线：
    GPTQ  逐层、按通道做最优舍入（用 Hessian 近似补偿误差）
          -> GPU 推理常用，需校准集，精度损失小
    AWQ   激活感知：先找「对输出影响大的显著通道」，这些通道保留更高精度
          -> 抗激活离群值，适合小模型与强指令场景
    GGUF  不是量化算法而是「格式」：权重+超参+tokenizer 打单文件，
          配 llama.cpp 在 CPU / 混合推理上 mmap 加载
          -> 本地部署首选，Q4_K_M 是常见的混合位宽折中

怎么选：GPU 批量服务 -> GPTQ/AWQ；笔记本/CPU 单机 -> GGUF Q4_K_M
```

## 量化位宽对体积的影响（先算账）

参数量固定时，体积 ≈ `参数量 × 比特数 / 8`。7B 模型：fp32≈26 GB、fp16≈13 GB、int8≈6.5 GB、
int4≈3.3 GB。int4 相对 fp16 压缩约 4 倍——这就是消费级显卡能跑 7B/13B 模型的根本原因。但位宽
越低，可表示的权重级别越少，量化误差越大，通常要配合「补偿」算法。

## GPTQ：按层、按通道的最优舍入

GPTQ 是「后训练量化（PTQ）」的代表。它在量化每一层时，不只看单个权重的四舍五入，而是考虑
「整层输出误差最小」——通过求解一个近似最优的量化+补偿问题，把舍入误差在通道间分摊。直观
模拟：把 fp16 权重按 per-channel 最大绝对值缩放到 int4 范围、round 后反量化，得到一小段 MSE。
GPTQ 的精髓是「补偿（compensation）」：它利用未量化权重的信息，让量化层的输出尽量贴近原输出，
所以 int4 下仍能保持很高精度，但需要校准集（calibration data）且量化过程较慢。

## AWQ：激活感知的权重量化

AWQ 的洞见是：**不是所有权重通道都同等重要，重要性由对应激活的大小决定**。激活值大的通道，
量化误差会被放大更多，所以要「保护」它们。AWQ 按比例（如 activation^0.5 归一化）对权重通道
做缩放，让显著通道的相对误差更小，再量化。它不需要像 GPTQ 那样复杂的层内优化，量化快、对
校准集不如 GPTQ 敏感，部署侧很受欢迎。

## GGUF：为本地/CPU 推理而生的格式

GGUF（llama.cpp 的格式）关注的是「怎么把量化后的模型高效地落盘与加载」，尤其是消费级 CPU/GPU
和 Apple Silicon 上的本地推理。它用统一头（magic `GGUF` + version + 张量数 + 元数据键值对）
描述模型结构、量化类型、超参，并把权重以多种量化粒度（如 Q4_K、Q5_K）打包。GGUF 本身不发明
量化算法，而是**封装** GPTQ/AWQ 类结果（或 llama.cpp 自家的量化），让一个文件能在不同后端
无缝加载。选 GGUF 往往是「我要本地、离线、低资源跑」的信号。

## 怎么选

- 要**服务端高吞吐、显存紧**：GPTQ / AWQ 的 int4，配合 vLLM 等引擎，精度与速度的甜点区。
- 要**本地/CPU/跨设备离线跑**：GGUF，生态成熟、加载简单。
- 精度敏感、不容有失：int8 甚至 fp16，用更多显存换稳妥。
记住：**量化不是越低越好**，要在「显存/带宽/延迟」与「任务精度」之间取平衡点，并用下游
评测验证，而不是只看压缩比。

## 三视角解析

### 🧑‍💻 程序员视角
- 先算账：体积≈参数量×比特/8，fp16→int4 约 4x，这是消费卡能跑大模型的根本；但位宽越低量化误差越大，要配补偿算法。
- GPTQ 按层按通道做最优舍入+补偿，int4 仍保高精度，但要校准集、量化慢；AWQ 按激活显著性保护重要通道，量化快、对校准不敏感。
- GGUF 是本地/CPU 推理的封装格式（统一头+magic+量化类型），不发明算法，而是打包 GPTQ/AWQ 类结果，离线低资源跑首选。
- 量化不是越低越好：用下游评测验证精度，在显存/带宽/延迟与任务精度间取平衡，别只看压缩比。

### 🎓 博士生视角
- 量化本质是「用可控的离散化误差换存储与带宽」。PTQ（GPTQ/AWQ）假设不重训，因此必须把误差在层/通道维度做最优分配；这与 QAT（量化感知训练，把量化注入训练）是两条路线，后者精度更高但成本大。
- GPTQ 的优化目标近似为「最小化量化层输出相对于全精度输出的误差」，属于单层最小二乘补偿；AWQ 则从「激活幅度决定权重敏感度」出发做 per-channel 缩放，二者都利用了权重-激活的耦合结构，但优化视角不同。
- GGUF 的格式设计体现了「模型即数据」的工程哲学：把结构、量化方案、超参都自描述地封装进文件，使加载端与训练/量化端解耦。这与 ONNX/Safetensors 的「可移植权重容器」思路一致，只是更面向端侧。

### 📚 考研者视角
- 记忆锚点：**体积≈参数量×比特/8；GPTQ=层内补偿最优舍入、AWQ=激活保护重要通道、GGUF=本地量化封装格式**。
- 与 408 的「定点数/浮点表示」对照：量化是把浮点权重映射到低位宽整数+缩放因子，本质是数值表示精度的取舍，和计算机组成里的定点化同理。
- 面试常问「int4 量化怎么做到的」「GPTQ 和 AWQ 区别」：答按通道缩放+补偿，GPTQ 求层输出误差最小、AWQ 按激活显著性保护通道。
