# ai-ch04 常见陷阱

1. **把优化器状态算成 8Φ** —— 只算了 Adam 的两个动量，漏掉 fp32 主权重副本。正确口径是 **12Φ**（一阶 4Φ + 二阶 4Φ + 主权重 4Φ），加上权重 2Φ 与梯度 2Φ，全参训练总共约 **16Φ 字节**。

2. **认为混合精度训练能把显存减半** —— 16Φ 里权重、梯度、优化器状态一份都不省（仍是 fp16/fp32 各就各位），真正被压缩的是**激活与带宽**。算单卡能不能训时按 16Φ 估，不要乐观打折。

3. **LoRA 的 A 和 B 都做随机初始化** —— 必须 **A 高斯随机、B 全零**，这样训练起点 ΔW = B@A = 0，模型从预训练权重无损出发。B 若随机初始化，训练初期会引入一个巨大的噪声扰动，容易把模型打坏。

4. **调大 r 却忘了同步 alpha** —— 有效缩放是 `alpha/r`。把 r 从 8 提到 64 而 alpha 保持 8，等于把有效学习率压到 1/8，表现为「LoRA 完全学不动」。惯例是 `alpha = 2r` 左右。

5. **以为 LoRA 会省推理显存** —— 不合并时反而略增（多两个分支的访存与计算）。LoRA 的收益在**训练端**（不需为冻结权重存优化器状态）。要省推理显存请走推理量化（GPTQ/AWQ）。

6. **用 LoRA 注入知识** —— 低秩假设假设 ΔW 秩 ≤ r，而注入新知识所需的权重扰动秩远大于 r，大部分信息会被投影掉。**知识用 RAG，行为才用微调。**

7. **SFT 时对整条序列算损失** —— 不掩码会导致模型花容量去学「复述用户问题」，loss 曲线照降但推理时表现异常（先复述一遍）。正确做法是把指令段的 label 置为 `-100`，**包括 pad 位置**。

8. **忘了设 pad_token_id** —— 很多基座模型默认没有 pad token，训练时会用 eos 顶替并参与 loss。必须显式设置 `pad_token_id` 并把 pad 位置的 label 也置 -100。

9. **认为奖励模型在判断「客观正确性」** —— 奖励模型学的是**人类偏好**（Bradley-Terry 成对比较），它会继承标注者的偏好偏差（偏爱长回答、偏爱顺从、偏爱加免责声明）。用它的分数当正确率用是根本性的误用。

10. **PPO 训练时只看奖励曲线** —— 奖励上升但评测不涨，就是奖励黑客。必须同时监控：KL 曲线（是否飙升/始终贴 0）、**奖励与长度的相关性**（强正相关说明代理被钻空子）。

11. **把 KL 惩罚系数 β 设得过小** —— β→0 时策略会迅速跑到 argmax r_φ，而奖励模型在训练分布之外毫无约束，结果是一堆「高分但荒谬」的输出。β 需要按模型规模与数据量调，不能照抄论文。

12. **DPO 的 π_ref logprob 与训练时的模板不一致** —— 常见错误是复用 SFT 阶段缓存的 logprob，而 prompt 模板已改。差分信号（chosen 与 rejected 的相对提升）会完全失真，训练看起来正常但学不到偏好。

13. **DPO 用跨 prompt 配对的数据** —— DPO 的推导依赖同一 prompt 下 chosen/rejected 共享配分函数 Z(x)，跨 prompt 配对会破坏这一性质。必须保证每条样本是「同问的两个回答」。

14. **认为 DPO 全面优于 PPO 所以不需要 PPO 了** —— DPO 是**离线**方法，只能拟合数据覆盖的偏好分布，无法主动探索；对偏好噪声也更敏感。有充足在线采样预算时，PPO/GRPO 的上限通常更高。

15. **把 QLoRA 与推理量化混为一谈** —— QLoRA 的 NF4 是为「可训练」服务的（前向时临时反量化）；部署推理应用 GPTQ/AWQ。另外 QLoRA 训练比 bf16 LoRA 慢 20%~40%，精度也略差，它的收益是**降显存**而非提效。

16. **合并 LoRA 权重后还想继续训练** —— `merge_and_unload` 之后 LoRA 分支就没了。多适配器/多租户场景必须保留未合并形态，按请求动态切换 adapter；只有追求推理速度时才合并。
