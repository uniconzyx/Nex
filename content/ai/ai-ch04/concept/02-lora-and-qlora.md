# LoRA 与 QLoRA：低秩适配与量化训练

## 主题一：LoRA 的低秩假设、初始化与 target_modules

LoRA（Low-Rank Adaptation）的核心假设是：**微调时的权重改变量 ΔW 是低秩的**。于是不去学整个 ΔW ∈ R^(d×k)，而是把它分解成两个小矩阵的乘积：

```
ΔW = B @ A,    A ∈ R^(r×k),  B ∈ R^(d×r),  r << min(d, k)
前向：h = Wx + (alpha / r) · B(Ax)
```

参数量对比（以 d=k=4096、r=8 为例）：

| 方案 | 参数量 | 占比 |
|---|---|---|
| 全参（一层） | 4096 × 4096 = 16,777,216 | 100% |
| LoRA r=8 | 8×4096 + 4096×8 = 65,536 | **0.39%** |
| LoRA r=16 | 131,072 | 0.78% |
| LoRA r=64 | 524,288 | 3.1% |

**初始化的讲究**：A 用高斯随机初始化、**B 全零初始化**。目的是让训练开始时 `ΔW = B@A = 0`——模型从原始预训练权重出发，而不是从一个被随机扰动的权重出发。如果 B 也随机初始化，训练初期会有一个纯粹由噪声引入的巨大扰动，容易把模型「打坏」。

**`alpha` 的作用**：缩放因子 `alpha/r`。当 r 增大时，`B@A` 的数值尺度会随 r 变化，用 `alpha/r` 归一化可以让「改 r 而不改有效学习率」成为可能。实践口径是：调 r 时同步把 alpha 设为 r 的 1~2 倍。

**`target_modules` 选谁**：原始论文只加在 `q_proj` 和 `v_proj` 上；后续实践证明加到**全部线性层**（q/k/v/o + gate/up/down）效果更好，代价是参数量约 3~4 倍。经验规律：**任务越难/越偏离预训练分布，需要覆盖的模块越多**。

### 🧑‍💻 程序员视角

工程决策树：

1. **先问「这是行为对齐还是知识注入」**。行为对齐（语气、格式、领域黑话）→ LoRA r=8~16 挂在 q/v 上通常够；知识注入 → 别用 LoRA，去用 RAG。
2. **显存紧就降 r、升 target_modules 覆盖度的顺序反转**：先保证覆盖关键投影层，再调 r。因为「挂到哪里」比「rank 多大」对效果的影响更显著。
3. **别动 alpha/r 的直觉**：常见做法是 `alpha = 2r`。有人调 `alpha=1`、`r=64` 导致有效学习率被压到 1/64，然后抱怨「LoRA 学不动」。
4. **上线时要记得 merge**：推理时把 `W + ΔW` 合并回原权重，可省掉 LoRA 分支的额外计算；但合并后就无法再切换适配器——多租户场景要保留未合并形态，按请求动态选 adapter。

### 🎓 博士生视角

低秩假设的理论依据是「内在维度（intrinsic dimension）」：Aghajanyan 等人的实验表明，预训练语言模型的**任务适配所需的有效自由度远小于参数量**——把优化限制在一个 d=几百到几千的随机子空间里，效果与全参微调几乎相当。LoRA 用的是「结构化」而非「随机」的低秩子空间，因此更高效。

从线性代数看，`ΔW = B@A` 的秩至多为 r，因此 LoRA 只能表达 **rank ≤ r 的权重扰动**。这解释了两件事：

- **为什么行为对齐能奏效**：语气/格式的调整通常对应权重空间中一个非常低维的方向（类似「风格向量」）。
- **为什么知识注入失败**：新知识需要在大量参数上形成新的关联结构，其 ΔW 的秩远大于 r，低秩投影会把大部分信息丢掉。

还有一点：LoRA 的梯度只流经 A 和 B，权重 W 冻结（`requires_grad=False`）。因此**不需要为 W 存优化器状态**——这才是 LoRA 省显存的真正来源。

### 📚 考研者视角

笔面高频口径：

- **问**：LoRA 的参数量怎么算？**答**：每个挂载的线性层增加 `r × (d_in + d_out)` 个参数。例如 d_in=d_out=4096、r=8，则为 8×4096×2 = 65,536。
- **问**：LoRA 为什么初始化时 B 置零？**答**：保证训练起点 `ΔW = 0`，模型从预训练权重无损出发。
- **问**：LoRA 与全参微调的区别？**答**：LoRA 冻结原权重、只训练低秩增量，参数量降至 1% 以下，可插拔、易部署，但表达上限受 rank 限制。
- **易错点**：说「LoRA 会减少推理显存」。**不合并时反而略增**（多两个小矩阵的访存）；它的收益在**训练**阶段。
- **易错点**：认为 `alpha` 和 `r` 是一回事。r 决定容量，alpha 决定尺度。

## 主题二：QLoRA 的四位量化与分页优化器

QLoRA = **冻结的 4-bit 量化基座 + LoRA 适配器 + 分页优化器**。三个组件各解决一个问题：

| 组件 | 解决什么 | 关键技术 |
|---|---|---|
| 4-bit 量化基座 | 权重显存 2Φ → 0.5Φ | **NF4**（正态浮点 4-bit）+ 双重量化 |
| LoRA 适配器 | 保证可训练 | 反量化后与 LoRA 增量相加做前向 |
| 分页优化器 | 显存峰值尖刺 | `paged_adamw_32bit`：显存不足时把优化器状态换出到 CPU |

**NF4 为什么比 INT4 好？** 因为预训练权重近似服从零均值正态分布。INT4 是等距量化（每个桶宽度相同），而 NF4 的桶边界按标准正态的分位数设置——**概率密度高的区域桶更密**，因此量化误差（MSE）更小。这是典型的「用先验分布换精度」。

**双重量化（double quantization）**：量化本身也需要存缩放因子。以 block=64 为例，每个 block 一个 fp32 缩放因子，开销是 32/64 = 0.5 bit/参数。对这些缩放因子再做一次 8-bit 量化，可把它压到约 0.127 bit/参数，**总共省约 0.37 bit/参数**——对 65B 模型是 3GB 级别的节省。

**一个必须说清的代价**：QLoRA 的前向计算需要**边用边反量化**，因此比 bf16 LoRA 慢（典型 20%~40%），且量化误差会让某些精细任务（如代码生成中的长标识符）质量略降。

### 🧑‍💻 程序员视角

决策表（单卡 24GB 训练 7B 模型）：

| 方案 | 权重占用 | 可训练参数 | 典型可行性 |
|---|---|---|---|
| 全参 bf16 | 14GB + 梯度/优化器 → 远超 24GB | 100% | **不可行** |
| LoRA bf16 | 14GB | <1% | 紧，seq_len 受限 |
| QLoRA 4-bit | 约 3.5GB | <1% | **宽松，seq_len 可到 4K** |

工程踩坑清单：

1. **不要把量化后的基座再 `merge_and_unload` 后继续训**——合并会失去量化收益。
2. **`bnb_4bit_compute_dtype` 建议设 bf16**（不是 fp16）。反量化后的计算精度直接影响收敛稳定性。
3. **分页优化器在 Windows 上支持不佳**，本地复现论文设置时要注意平台差异。
4. **推理部署要另做量化**：训练时的 NF4 是为「可训练」服务的，部署时通常改用 GPTQ/AWQ 以获得更好的吞吐。

### 🎓 博士生视角

QLoRA 的理论价值在于打破了「量化只用于推理」的成见。关键洞察是：**反向传播需要的是权重的高精度近似，而不是高精度存储**。由于 W 被冻结，它的更新根本不需要——只需要前向时把 4-bit 权重临时反量化成 bf16 参与计算，梯度只流向 LoRA 的 A/B。

误差分析上，NF4 的设计目标是**最小化以权重分布为测度的量化 MSE**：

```
min Σ_i w_i · (q_i - w_i)²   其中 w_i 是权重的经验分布密度
```

在正态假设下，最优量化点是分布的等概率分位点——这正是 NF4 桶边界的构造方式。相比之下 INT4 的等距边界在正态分布下把大量桶浪费在尾部稀疏区。

双重量化的意义则是一个**元层级的优化**：量化器本身的开销（缩放因子）也需要被量化。这类「对量化器再量化」的思路在极端压缩场景（<2 bit/参数）中是必需的。

### 📚 考研者视角

笔面高频口径：

- **问**：QLoRA 由哪三部分组成？**答**：4-bit NF4 量化基座 + LoRA 适配器 + 分页优化器。
- **问**：NF4 与 INT4 的区别？**答**：NF4 按正态分布分位数非均匀量化，信息论上对近似正态的权重更优；INT4 是均匀量化。
- **问**：QLoRA 相比 LoRA 的代价？**答**：训练速度下降（需实时反量化），精度略有损失，但显存需求大幅降低。
- **易错点**：认为 QLoRA 会「提升」效果。它降显存、降速度，**精度上通常略差于 bf16 LoRA**。
- **易错点**：把 QLoRA 与推理量化（GPTQ/AWQ）混为一谈。前者目标是可训练，后者目标是高吞吐推理。
