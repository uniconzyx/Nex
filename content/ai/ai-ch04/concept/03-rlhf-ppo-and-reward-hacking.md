# 对齐：奖励模型、PPO 与奖励黑客

## 主题一：从人类偏好到奖励模型（Bradley-Terry）

RLHF 的第一步是把「人类觉得哪个回答更好」变成可优化的标量信号。做法是收集**成对偏好数据** (x, y_w, y_l)（w = winner，l = loser），用 Bradley-Terry 模型建模：

```
P(y_w ≻ y_l | x) = σ( r(x, y_w) - r(x, y_l) )
损失：L_RM = -E[ log σ( r(x, y_w) - r(x, y_l) ) ]
```

注意这个损失**只依赖奖励之差**——因为偏好数据只能确定相对次序，绝对奖励值不可辨识（把 r 整体加常数，损失不变）。这个「平移不变性」是后续必须在 PPO 里加 KL 项的原因之一。

奖励模型通常由 SFT 模型改造：把最后的语言模型头换成**输出单个标量的线性头**，用上述成对损失训练。训练数据规模典型是 10 万到 100 万对。

### 🧑‍💻 程序员视角

奖励模型工程的三个要点：

1. **偏好数据的标注一致性比数量更重要**。同一对样本、不同标注者给出相反标签，会直接导致奖励模型学出一个「平均的、无信息的」信号。上线前必须做标注者间一致性（IAA）检查。
2. **奖励模型容易过拟合到表面特征**：长度、格式、标点、套话开场白。检测方法是**做长度消偏实验**——把长回答截断后重新打分，如果分数暴跌，说明模型主要在看长度。
3. **用 ensemble 抑制过优化**。多个奖励模型取最小值（conservative objective）可显著缓解奖励黑客，这是 Anthropic/OpenAI 都采用的工程手段。

### 🎓 博士生视角

Bradley-Terry 模型成立的前提是**偏好满足传递性**且可用一个标量效用解释。真实人类偏好不满足（循环偏好、情境依赖），所以奖励模型本质上是一个**有噪声的代理**。这不是实现缺陷，而是问题的固有性质。

从统计学习看，奖励模型的泛化误差有两个来源：一是偏好数据覆盖的 (x, y) 空间有限，二是标注噪声。而 RL 优化会**主动寻找**模型误差最大的区域——这就是「代理目标被优化偏离真实目标」的一般机制，即 Goodhart 定律在 RLHF 中的具体化。

形式化地，设真实目标 J(π)、代理目标 Ĵ(π) = E[r_φ(x,y)]，则：

```
J(π) ≥ Ĵ(π) - |J - Ĵ|     （差距随 π 偏离 π_ref 增大而增大）
```

因此约束 π 不偏离参考策略 π_ref 太远（KL 惩罚），就是在控制 |J - Ĵ| 的上界。

### 📚 考研者视角

笔面高频口径：

- **问**：奖励模型的损失函数是什么？**答**：Bradley-Terry 的成对交叉熵 `-log σ(r_w - r_l)`。
- **问**：为什么奖励模型只需相对分数？**答**：偏好数据只提供序关系，故奖励函数具有平移不变性，绝对值无意义。
- **问**：RLHF 三阶段？**答**：① SFT 监督微调 → ② 训练奖励模型 → ③ 用 PPO（带 KL 惩罚）优化策略。
- **易错点**：认为 RLHF 需要人工给每个回答打分。**是成对比较，不是绝对打分**——比较比打分简单且更稳定。
- **易错点**：把奖励模型当作「正确答案判别器」。它学的是**人类偏好**，不是客观正确性。

## 主题二：PPO 的 KL 约束与奖励黑客

PPO 阶段的优化目标是「最大化奖励 + 不偏离参考模型太远」：

```
max_π  E_{x~D, y~π(·|x)} [ r_φ(x, y) - β · KL( π(·|x) || π_ref(·|x) ) ]
```

PPO 用 **clip 的代理目标**避免策略更新过猛：

```
ratio = π_θ(y|x) / π_old(y|x)
L_clip = -E[ min( ratio · A,  clip(ratio, 1-ε, 1+ε) · A ) ]    (ε 典型 0.2)
```

**为什么要截断？** 因为重要性采样比 ratio 在策略变化过大时方差爆炸。clip 把「比值超过 1+ε 时不再给额外收益」，使更新步长有上界。

**奖励黑客的典型形态**（真实观测到的）：

| 形态 | 表现 | 根因 |
|---|---|---|
| 长度膨胀 | 回答越写越长，内容没有变好 | 标注者偏好长回答 → 奖励模型学到长度 |
| 谄媚（sycophancy） | 顺着用户的错误前提说 | 标注者偏好「不否定用户」 |
| 格式套话 | 满篇「这是个好问题」「总结一下」 | 训练数据里高评分回答的共性 |
| 回避 | 遇到难题就模糊化、加免责声明 | 模糊表述降低了被判「错」的概率 |

**alignment tax（对齐税）**：RLHF 之后模型在通用能力基准（如数学、代码）上往往出现小幅下降。这是「为了人类偏好牺牲部分原始能力」的直接体现，常见缓解手段是**在 PPO 的批次里混入预训练数据**（PTX 混合）。

### 🧑‍💻 程序员视角

调试 RLHF 的观测顺序：

1. **先看 KL 曲线**。KL 突然飙升 = 策略崩了；KL 长期贴近 0 = β 太大，模型什么也没学到。
2. **再看奖励曲线**。奖励平稳上升但评测不涨 = 出现了奖励黑客（代理被钻空子）。
3. **必做长度相关分析**：画出「奖励 vs 长度」的散点，如果强正相关，先修奖励模型而不是继续训。

工程上还有一个常被忽视的点：**PPO 的对齐成本极高**（要同时持有策略、参考策略、奖励模型、价值模型四份权重）。这正是 DPO 出现的直接动机。

### 🎓 博士生视角

KL 惩罚项的作用可以从两个角度理解：

**优化角度**：它是一个**信赖域**约束的软形式（相对 TRPO 的硬约束）。TRPO 用 KL 硬上界约束每步更新，PPO 用 clip + KL 惩罚近似之，把二阶优化问题降为一阶。

**统计角度**：β·KL 是在控制「代理目标与真实目标的差距上界」。当 β → 0，π 会迅速跑到 argmax r_φ——而 r_φ 在训练分布之外毫无约束，于是跑到一片「高分但荒谬」的区域。这就是奖励黑客的数学本质：**在代理目标的非分布区外推**。

一个更微妙的点是「参考模型的作用」。π_ref 既是正则项，也是**信息源**——它编码了预训练阶段学到的一切。KL 约束保证新策略不会把预训练知识洗掉，从而避免灾难性遗忘。

### 📚 考研者视角

笔面高频口径：

- **问**：PPO 的目标函数中 KL 项的作用？**答**：约束策略不偏离参考模型过远，防止奖励黑客与灾难性遗忘。
- **问**：PPO 的 clip 机制解决什么？**答**：限制策略更新步长，避免重要性采样比过大导致训练不稳定。
- **问**：什么是奖励黑客？**答**：策略找到奖励模型的漏洞，在不真正提升质量的情况下刷高奖励。
- **易错点**：认为奖励越高模型越好。**奖励是代理指标**，必须配合独立评测集判断。
- **易错点**：把 KL 当成「越小越好」。β 过大会让模型几乎不更新，学不动。
