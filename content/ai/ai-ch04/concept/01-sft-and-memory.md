# SFT 与显存账：全量微调为什么这么贵

## 主题一：显存四件套——权重、梯度、优化器状态、激活

一次训练要占多少显存，可以拆成四块：

| 组成 | 大小（以参数量 Φ 为单位） | 说明 |
|---|---|---|
| 权重（params） | 2Φ 字节（fp16/bf16） | 模型本身的参数 |
| 梯度（grads） | 2Φ | 每个参数一份梯度，与权重同 dtype |
| 优化器状态（optim states） | **12Φ** | Adam 要存一阶动量 m + 二阶动量 v（各 fp32=4Φ）+ fp32 主权重副本 4Φ |
| 激活（activations） | 与 batch、序列长度、层数正相关 | 前向过程中为反向传播保留的中间张量 |

把前三项加起来：**2Φ + 2Φ + 12Φ = 16Φ 字节**。也就是说一个 7B 模型，光「权重 + 梯度 + Adam 状态」就要 7e9 × 16 ≈ **112 GB**，还没算激活——这就是为什么单张 80GB 的 A100 训不动全参 7B。

**混合精度训练为什么是 16Φ 而不是更少？** 因为 Adam 的更新量级极小（约 1e-4 到 1e-8），在 fp16 下会被舍入误差直接抹掉（fp16 的最小规格化数约 6e-5）。所以主权重必须以 fp32 保存并参与更新，更新完再 cast 回 fp16 做前向。这三份表示（fp16 权重 / fp32 主权重 / 两个动量）就是 16Φ 的来源。

### 🧑‍💻 程序员视角

先算总账再动手。工程上的决策顺序永远是：**① 算显存 → ② 选并行策略 → ③ 才写训练脚本**。显存不够时的优先级是：

1. **先降 batch / 梯度累积**（激活是唯一能被 batch 直接线性压下去的部分）；
2. 再上 **gradient checkpointing**（时间换空间，激活从 O(L) 降到 O(√L)，代价是重算一次前向，约 +30% 时间）；
3. 再考虑 **ZeRO 分片**（把「梯度 + 优化器状态」切到多卡，Stage-2 省 14Φ/卡，Stage-3 连权重也切）；
4. 最后才是量化训练（QLoRA）。

一个高频踩坑：**「我 batch 设成 1 为什么还 OOM」**——因为激活不只跟 batch 有关，还跟 `max_seq_len` 成正比。seq_len 从 512 拉到 4096，激活直接 ×8。

### 🎓 博士生视角

16Φ 这个系数的严格性来自「优化器选择的确定论」：SGD 只要 4Φ（权重+梯度各 2Φ，无状态），AdaGrad 需要累积平方梯度，Adam 需要两个一阶/二阶矩。所以**优化器状态占主导（75%）**这件事，本质上是「用内存换条件数改善」的交易——Adam 的自适应步长让它在稀疏梯度和非平稳目标上比 SGD 稳健得多，代价就是 3 倍于权重的状态开销。

从信息论角度还有一个更本质的约束：**训练一个参数至少需要与它同量级的存储来表达其状态**。想要 O(1) 内存训练，只能走「无状态优化器 + 分片 + 重算」这三条路，而这恰好对应 ZeRO / checkpointing / LoRA 三套工程方案。

### 📚 考研者视角

笔面高频口径：

- **问**：训练一个 N 参数的模型（fp16 + Adam），显存大约需要多少？**答**：约 **16N 字节**（权重 2 + 梯度 2 + Adam 状态 12），不含激活。这是标准口径，务必记牢数字。
- **问**：推理为什么只要约 2N 字节？**答**：推理不存梯度和优化器状态，只需要权重（fp16）加 KV Cache。
- **易错点**：把「优化器状态」算成 8Φ（只算两个动量）而漏掉 fp32 主权重副本——**必须含主权重，才是 12Φ**。
- **易错点**：说「混合精度省一半显存」。省的是**激活与带宽**，权重侧的 16Φ 一分不少。

## 主题二：SFT 的数据构造与损失掩码

监督微调（SFT）看似简单，真正决定成败的是**数据**，其中最容易做错的是**损失掩码（loss mask）**。

一条 SFT 样本通常是「指令 + 输入 → 回答」。如果直接对整条序列算交叉熵，模型会花大量容量去学「复述用户的问题」，这是纯粹的浪费，而且会诱导模型在推理时也「先复述一遍」。正确做法是：

```
loss 只对 回答（assistant 段） 的位置算交叉熵；
指令/输入（system + user 段） 的 label 全部置为 -100（PyTorch 的 ignore_index）。
```

除了掩码，还有三个真实工程约束：

1. **样本多样性 > 样本数量**。500 条覆盖 50 种任务形态，胜于 5000 条同质样本——后者会把模型过拟合到某种句式。
2. **长度分布要贴近推理时的实际需求**。训练时 `max_len=512`，推理时要 4K 长文总结，长上下文能力必然崩。
3. **拒绝采样（rejection sampling）**：同一条指令生成多条回答，用规则或奖励模型筛掉差的，只留优质的——这是「自蒸馏」的低成本形态。

### 🧑‍💻 程序员视角

SFT 的调试顺序应当是：**① 打印 3 条真实样本的 token 化结果与 label 掩码 → ② 检查 loss 只落在回答段 → ③ 再跑训练**。跳过第 ① 步是新手最常见的浪费：掩码写错时 loss 曲线依然漂亮地下降（它在认真学复述问题），你要等推理时才发现模型不听话。

另一个经常被忽略的点：**pad token 的 label 也必须是 -100**，否则模型会认真地学习「生成 padding」。同时要确认 `pad_token_id` 与 `eos_token_id` 的关系（很多基座模型默认没有 pad token，需要手动设成 eos）。

### 🎓 博士生视角

从目标函数看，SFT 是对条件分布 p(y|x) 的极大似然估计，其中 x 是「指令+输入」拼接后的前缀，y 是回答。掩码等价于**限定求和范围**：

```
L_SFT = -Σ_{t ∈ answer positions} log p(y_t | y_<t, x)
```

这是一个**部分观测序列**的 MLE——把不需要建模的位置从似然里剔除，而非置零权重。区别在于：置零权重仍会让梯度尺度随长度变化（分母不同），剔除则是干净的目标函数。

它还有两个理论性质值得一提：一是 SFT **只做行为克隆**，不引入任何新的偏好信号，所以它无法让模型「变得更有帮助」——只能让它更像训练数据；二是 SFT 的分布外泛化很弱，训练数据里没出现过的指令形态，模型往往退化成「复读指令」。

### 📚 考研者视角

笔面高频口径：

- **问**：SFT 的损失为什么要做 mask？**答**：只对回答段计算损失，避免模型学习复述输入，同时保证梯度只更新「生成能力」相关参数。
- **问**：SFT 和「预训练」的目标函数是否一样？**答**：**形式相同**（都是 next-token 交叉熵），差别在**数据与掩码策略**——预训练是全位置、无监督语料；SFT 是掩码后、指令-回答对。
- **易错点**：把 SFT 说成「有监督所以和预训练不同」——形式上是同一种自回归 MLE，别把「有监督」理解成分类任务的监督。
- **易错点**：认为 SFT 能注入知识。**SFT 主要教格式与风格，知识注入效率极低**，这正是「知识用 RAG」的由来。
