# DPO 与选型：跳过奖励模型的直接偏好优化

## 主题一：DPO 的闭式推导与工程优势

DPO（Direct Preference Optimization）的核心是：**把 PPO 的最优解代入，消掉奖励函数，得到一个只依赖策略本身的损失**。

出发点仍是那个带 KL 约束的目标：

```
max_π  E[ r(x, y) ] - β · KL( π || π_ref )
```

这个问题的**闭式最优解**（对每个 prompt x 分别求解）是：

```
π*(y|x) = (1/Z(x)) · π_ref(y|x) · exp( r(x, y) / β )
```

反解出奖励：

```
r(x, y) = β · log( π*(y|x) / π_ref(y|x) ) + β · log Z(x)
```

把这个 r 代回 Bradley-Terry 的成对损失，log Z(x) 因为**只依赖 x 而在差值里消掉**，于是得到：

```
L_DPO = -E[ log σ( β · log( π_θ(y_w|x) / π_ref(y_w|x) )
                  - β · log( π_θ(y_l|x) / π_ref(y_l|x) ) ) ]
```

**读法**：让「被选中的回答相对参考模型的概率提升量」大于「被拒绝的回答的提升量」。β 控制「允许偏离参考模型多远」。

工程优势很直接：

| 维度 | RLHF (PPO) | DPO |
|---|---|---|
| 需要训练的模型数 | 4（策略/参考/奖励/价值） | **1**（策略，参考模型冻结） |
| 是否需要在线采样 | 是（每步 rollout） | **否**（离线偏好对） |
| 训练稳定性 | 敏感（多个超参） | **接近常规 SFT** |
| 显存占用 | 高 | 约等同 SFT |
| 上限 | 通常更高（在线探索） | 受离线数据分布限制 |

### 🧑‍💻 程序员视角

选型建议：

- **预算有限、数据是离线偏好对** → **DPO**。它把「对齐」降维成「在偏好对上做一次带 β 的 SFT」，工程复杂度低一个数量级。
- **有在线采样与充足算力、追求上限** → PPO。
- **数据是「正确答案」而非「偏好对」** → 都别用，去做 SFT 或 RFT（拒绝采样微调）。

实现上的两个坑：

1. **`π_ref` 的 logprob 必须用同一套 tokenizer 与完全一致的 prompt 模板重算**。常见错误是把 SFT 时缓存的 logprob 拿来用，而模板已经改过——差分信号完全失真。
2. **β 太大**（如 1.0）会让策略几乎不更新，看起来「很稳」但学不到东西；**β 太小**（如 0.01）会过拟合偏好数据里的表面特征。常用 0.1 起步。

### 🎓 博士生视角

DPO 之美的关键在于它**把一个 RL 问题转化成分类问题**。推导中最容易被忽略的一步是 Z(x) 的消去——它依赖「同一个 prompt 下的 chosen/rejected 共享同一个配分函数」，这也是 DPO **必须使用成对数据**的深层原因（跨 prompt 配对会破坏这一性质）。

理论上的已知局限有三：

1. **离线限制**：DPO 只能拟合数据覆盖的偏好分布，无法主动探索。这与「SFT 只是行为克隆」是同一类限制。
2. **对偏好噪声敏感**：PPO 通过在线采样对噪声有一定鲁棒性，DPO 会直接学到一个含噪的目标。
3. **可能降低输出多样性**：把概率质量集中到 chosen 上，会导致熵下降（生成多样性变差）。实践中常加一个熵正则项来缓解。

后续的 **IPO / KTO / ORPO** 可以看成对这个框架的修补：IPO 解决「DPO 在偏好完全可分时损失会收敛到常数、梯度消失」的问题；KTO 只用「好/坏」标签而不需成对；ORPO 把 SFT 与偏好对齐合并成一步。

### 📚 考研者视角

笔面高频口径：

- **问**：DPO 相比 RLHF 的优势？**答**：无需训练奖励模型、无需在线采样，只需偏好数据做一次监督式优化，工程复杂度与显存占用大幅降低。
- **问**：DPO 的损失里 β 起什么作用？**答**：控制策略允许偏离参考模型的幅度——相当于隐式的 KL 约束强度。
- **问**：DPO 为什么可以不要奖励模型？**答**：因为带 KL 约束的最优策略存在闭式解，可反解出奖励与策略的解析关系，代入 Bradley-Terry 损失后奖励被消掉。
- **易错点**：说「DPO 不需要偏好数据」。**恰恰相反，DPO 只吃偏好数据**，不需要的是奖励模型。
- **易错点**：认为 DPO 全面优于 PPO。**DPO 是离线方法，上限受数据限制**；有充足在线采样预算时 PPO/GRPO 仍可能更优。

## 主题二：选型原则——注知识用 RAG，改行为用微调

这是本章最该带走的判断准则。两种手段的作用面完全不同：

| 需求 | RAG | 微调（SFT/LoRA） |
|---|---|---|
| 让模型知道公司内部文档 | **强**（可即时更新、可溯源） | 弱（成本高、易幻觉、更新要重训） |
| 让模型稳定输出某种语气/格式 | 弱（靠 prompt 勉强） | **强** |
| 让模型遵守特定决策偏好 | 弱 | **强** |
| 知识频繁变更 | **强** | 弱（每次变更要重训） |
| 需要引用出处 | **强** | 无 |
| 冷启动无标注数据 | **强**（文档即数据） | 弱 |

判断口诀：**「说什么」用 RAG，「怎么说」用微调**。两者并不互斥——生产系统常见做法是「RAG 提供事实 + 微调塑造风格与拒答边界」。

另外还有两个常被混淆的替代方案：

- **提示工程 / 上下文工程**（见 ai-ch05）：零训练成本，适合快速验证与形态探索。
- **偏好对齐的替代路线**：RLAIF（用 AI 代替人类标注）、GRPO（去掉价值模型、按组内相对得分算优势）、Constitutional AI（用一套原则让模型自我批判与修订）。它们共同的目标都是**降低对齐对人工标注的依赖**。

### 🧑‍💻 程序员视角

实际项目里的决策流程：

1. **先写 prompt 试**（成本最低）。如果加几个 few-shot 示例就能达到 80% 效果，可能根本不需要微调。
2. **需要外部事实 → 上 RAG**。重点投入在 chunk 策略与召回评估上，而不是模型。
3. **prompt + RAG 都试过仍不达标，且瓶颈在「输出不稳定 / 不遵守格式 / 不守边界」→ 才上微调**。
4. **微调后仍想提高事实性** → 微调 + RAG 组合，别指望微调解决幻觉。

避免一个代价高昂的误区：**用微调去「教」模型一份会变的价目表**。价目表一变你就得重训，而 RAG 只要更新文档。

### 🎓 博士生视角

从信息存储的位置看，两种手段改的是模型的不同部分：

- **RAG 改的是「上下文」**：知识存在于推理时的输入里，因此**可审计、可更新、可溯源**，且不改变参数。它的上限受限于检索质量与上下文窗口。
- **微调改的是「参数」**：知识被压缩进权重，因此**不可溯源、更新成本高**，但收益是「零额外推理开销」且能塑造难以用自然语言描述的行为倾向。

这也解释了一个经验现象：**微调很难可靠地注入事实**。因为交叉熵目标下，模型只需要在训练样本上学到「输出正确 token」，并不会被激励去建立一个可泛化的知识结构——尤其在样本量小、重复次数少时，模型会记住「这就是这个 prompt 的答案」而不是「这是关于世界的事实」。这类**表面记忆**在分布外立刻失效。

### 📚 考研者视角

笔面高频口径：

- **问**：RAG 与微调的区别？**答**：RAG 在推理时注入外部知识，不改模型参数，可实时更新与溯源；微调改变模型参数，成本高、更新慢，适合塑造行为与风格。
- **问**：什么时候优先选微调？**答**：需要改变输出风格/格式/决策偏好、且 prompt 与 RAG 无法达成时。
- **问**：微调能解决幻觉吗？**答**：通常不能，甚至会加剧。幻觉需靠 RAG 提供事实依据 + 训练模型「无依据时拒答」。
- **易错点**：认为「微调是更高级的 RAG」。二者正交，生产系统常用组合方案。
- **易错点**：把 LoRA 当作知识注入手段。**低秩假设在知识注入上不成立**，这是本章要建立的直觉。
