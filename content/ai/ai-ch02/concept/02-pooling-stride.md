# 池化、padding 与 stride 尺寸公式
> 下采样解决「不变性」与「计算量」，但代价是空间信息损失。尺寸公式必须精确，因为张量对不齐是 CNN 工程里最常见的形状 bug。

## 1. 池化与下采样

池化（最大/平均）在局部窗口上取聚合值，窗口不重叠滑动（stride = kernel）。它带来三点效果：① 降低空间分辨率、减少计算；② 提供一定程度的平移不变性；③ 扩大后续层的感受野。

### 🧑‍💻 程序员视角
- 最大池化保留纹理/边缘响应，平均池化平滑、抑制噪声；全局平均池化（GAP）可直接替代全连接做分类头，大幅减参。
- 尺寸公式与卷积同形：out = (n − k)//s + 1（pooling 通常 p=0）。多组参数手算时务必逐层记录 H/W，避免最后展平维度对不上。
- 工程默认：用 2×2 stride=2 的 maxpool 做 2 倍下采样；现代网络（ResNet）倾向用 stride=2 的卷积代替池化下采样。

### 🎓 博士生视角
- 平移不变性的来源：max/avg 在窗口内是对称聚合，叠加多层后输出对小位移不再敏感，等价于引入「局部统计量不变」归纳偏置。
- 代价是**不可逆信息损失**：池化丢弃了窗口内位置细节，对需要精确定位的任务（检测、分割）不利，因此现代架构更谨慎使用池化。
- 反池化（unpooling）在分割解码器里有用，但只是近似还原，不能真正恢复被丢弃的信息。

### 📚 考研者视角
- 尺寸公式：out = floor((n − k)/s) + 1（池化一般无 padding）。给 28×28 经 2×2/stride2 池化得 14×14 这类要会心算。
- 概念题：「池化带来平移不变的原理」「为什么 GAP 能替代全连接」「池化丢失了什么」是高频问法。
- 易错：把池化也算上 padding，导致尺寸比实际大。
## 2. padding='same' / 'valid' 与 stride 尺寸公式

padding 控制输入边界是否补零。'valid' 不补零（输出变小）；'same' 补零使输出尺寸 = ceil(n/s)（输入被 s 整除时等于 n）。关键公式：valid 输出 = floor((n − k)/s) + 1；same 输出 = ceil(n/s)。

### 🧑‍💻 程序员视角
- 选 same 还是 valid：需要保持特征图分辨率（如编码器的 skip connection 要对齐）用 same；要压缩信息、忽略边界用 valid。
- 当 n 不能被 s 整除，same 的输出是 ceil(n/s)，**不等于** n；构建 U-Net 这类对称结构时，编码下采样与解码上采样的尺寸必须配对计算，否则 concat 形状不匹配。
- 实现细节：框架的 'same' 会把 padding 尽量均分到左右上下，奇数补零时左右差 1，复现公式时要和具体框架对齐。

### 🎓 博士生视角
- 'same' 的本质是把卷积视为在**周期延拓/零延拓**域上的运算，使输出采样网格与输入同构（仅步长缩放），数学上等价于把输入用零填充到使尺寸整除的大小。
- 当 n mod s ≠ 0，ceil(n/s) 会向上取整，意味着输出比输入「略小但比例对齐」，这是 same 与 valid 在整除情形才等价的根源。
- 反卷积/转置卷积的尺寸推导是卷积公式的逆，但输出尺寸存在歧义（多种 padding 满足），实践上以框架实现为准。

### 📚 考研者视角
- 公式题：已知 n=224, k=3, s=2, p=1，求 valid 与 same 输出。valid = (224−3)//2+1 = 111；same = ceil(224/2)=112。
- 易错：'same' 当成了「输出恒等于 n」，忽略 s>1 时向上取整且可能小于 n。
- 经典问法：「same 卷积真的总是保持尺寸吗？」「转置卷积输出尺寸怎么算」。
