# ai-ch14 · 多模态落地：图文对齐、OCR→VLM 流水线、多模态 RAG、成本与延迟 · 常见错误

1. **跨模态检索直接拿原始向量比，没过投影层** —— 错在：图像和文本编码器输出维度不同，直接算余弦相似度做检索。

   *为什么*：未对齐的向量住在两个不同空间，相似度数值毫无意义——猫图和「猫」可能比猫图和「汽车」还远。必须先各自过编码器+投影层，落到同一 hidden_dim 空间再比。

   *怎么改*：统一接投影层把图/文映射到同一空间；检索时都过「编码器+投影」，用同一度量（归一化后的余弦/点积）比较。

2. **检索没归一化，模长干扰排序** —— 错在：直接用点积做跨模态相似度排序，没对向量做 L2 归一化。

   *为什么*：图像向量和文本向量的模长分布不同，点积会被模长主导，语义相近但模长短的候选被排到后面，Top-K 召回质量崩。

   *怎么改*：检索前对两侧向量都做 L2 归一化，使点积等价于余弦，排序只由方向（语义）决定，不受模长干扰。

3. **文档理解直接端到端 VLM，跳过 OCR 不可控** —— 错在：拿到文档图直接丢给 VLM 让它答，认为「端到端更高级」。

   *为什么*：端到端在复杂版式/表格/手写上常幻觉且不可追溯，错了无法定位是「看错了」还是「想错了」；也无法单点替换优化，整体难落地。

   *怎么改*：优先 OCR→VLM 分段链路：版面检测→文本识别→问答，可解释、可单点优化、可降级，必要时再叠端到端。

4. **OCR 结果不校验直接当真值喂 VLM** —— 错在：OCR 输出不管置信度，直接拼进 prompt 让 VLM 回答。

   *为什么*：模糊/遮挡/手写处 OCR 会出 `##########` 或 `✱✱✱✱✱` 乱码，VLM 把这些当真值推理，答案必然错且难排查。

   *怎么改*：做置信度过滤：conf<0.5 或含乱码字符的样本标记人工复核，不进 VLM；对低置信召回降权。

5. **表格走普通 OCR，行列全乱** —— 错在：把表格区域当普通段落送 OCR，认为「字认出来就行」。

   *为什么*：普通 OCR 把表格读成连续文本，单元格的行列关系丢失，问答「第三行合计」这类问题必错。

   *怎么改*：表格块单独走表格结构识别，或裁剪后送专用表格模型；版面检测要能区分表格块与普通段落块。

6. **多模态 RAG 成本只算模型，漏算预处理** —— 错在：估算账单时只算 VLM 的 token 费用，认为「模型调用就是全部成本」。

   *为什么*：图像预处理（resize/OCR/视觉编码抽 embedding）在批量文档下是实打实开销（如100页×$0.002=$0.20，叠加 embedding 再翻倍），漏算会让预算严重偏低。

   *怎么改*：成本模型要含视觉 token 单价×图数 + 预处理/embedding 成本；用缓存同图 embedding、降分辨率、批处理编码压成本。

7. **延迟预算只看总时长，不拆段** —— 错在：测一次多模态问答的总耗时，说「440ms 还行」就上线。

   *为什么*：不拆段就不知道瓶颈在哪：其实文本生成占 55%、视觉编码 27%，超预算时盲目堆 GPU 没用，该砍的是生成 token 数或换小视觉编码器。

   *怎么改*：把延迟拆成预处理/视觉编码/文本生成/网络几段做预算，按关键路径优化能并行的并行、能砍的砍。

8. **多模态 RAG 无脑召回所有图** —— 错在：每次查询都把全部候选图编码送 VLM，认为「图越多越准」。

   *为什么*：每张图都编码+送 VLM，预处理与视觉 token 成本线性膨胀，延迟也涨，而很多查询其实靠文本检索粗筛就能定位是否需要图，盲目召回纯属浪费。

   *怎么改*：先文本检索粗筛，确认需要视觉再取 Top-K 图编码；对低召回置信度降权，避免无条件编码每张图。

9. **用 time.perf_counter() 做结构性容量评估** —— 错在：在性能评估里用 time.perf_counter() 测每次调用耗时，据此定容量。

   *为什么*：实测计时受机器负载、并发波动影响，不可复现，且测单次看不出「哪段是结构性瓶颈」（检测/识别/后处理各占多少），规划出的容量不可靠。

   *怎么改*：用固定预算值（如检测120ms/识别300ms/后处理80ms）做结构性容量规划，计时只作辅助验证而非规划依据。
