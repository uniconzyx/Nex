# 凯喵实战手记 · 多模态：图文对齐、OCR 流水线与成本地狱

> 凯喵说：多模态听着很酷，做起来很贵。一张图进 VLM，token 是文本的几十上百倍；一次 RAG 召回十张图，延迟和账单一起爆。真正拉开水平的不是「能不能跑通」，而是「跑得起、跑得稳」。这一章我们把多模态的现场一个个拉出来。

### 现场 1：图文对齐不是「图配一句话」这么简单

对比学习让图像和文本在同一个向量空间里靠近，但「靠近」不等于「理解」。凯喵：对齐质量取决于训练数据里图文的真实对应关系，弱标注（alt 文本、周边文字）会引入噪声。评估对齐效果一定要看下游任务，而不是只看相似度数值。

```python
# 图文相似度只是对齐的代理指标
sim = image_emb @ text_emb.T
```

### 现场 2：图像分辨率决定 token 成本

VLM 通常把图像切成 patch，每块变成 token。分辨率翻倍，patch 数量可能翻四倍。凯喵：上传前先降采样到任务真正需要的分辨率，别把 4K 原图直接喂进去——模型看不完，账单看得见。

```python
img = img.resize((768, 768))   # 按任务需要定，不是越大越好
```

### 现场 3：OCR 与 VLM 是互补而非替代

OCR 擅长精确提取文字，VLM 擅长理解版面与语义。凯喵：文档问答里常见做法是 OCR 拿文字、VLM 拿结构，再融合；纯靠 VLM 读小字容易漏，纯靠 OCR 又理解不了表格关系。

```python
text = ocr(image)              # 精确文字
desc = vlm(image, "描述版面结构")  # 结构理解
```

### 现场 4：流水线要设超时与降级

OCR 慢、VLM 更慢，任何一环卡住都会拖垮整个请求。凯喵：每一环都设超时，失败时降级（比如 OCR 失败就只返回 VLM 的描述），别让一个慢环节阻塞整条链路。

### 现场 5：多模态 RAG 不要无脑召回所有图

每次查询把全部候选图编码送 VLM，既慢又贵。凯喵：先用向量召回筛出最相关的少量图，再送 VLM 精读；召回阶段用便宜的嵌入模型，精读阶段才用贵的大模型，分层控制成本。

```python
candidates = vector_search(query, top_k=20)   # 便宜
top = rerank(query, candidates, top_k=3)      # 中等
answer = vlm_read(top)                        # 昂贵，只喂少量
```

### 现场 6：图像描述要缓存

同一张图被反复描述是纯浪费。凯喵：按图像内容的哈希缓存 VLM 输出，命中就直接返回；图片不变、描述就不变，缓存命中率往往很高。

```python
key = hashlib.sha256(img_bytes).hexdigest()
if key in cache: return cache[key]
```

### 现场 7：用固定预算做容量规划，别用计时器

`time.perf_counter()` 测单次耗时，受机器负载影响极大，据此定容量必然失真。凯喵：用「检测 120ms、识别 300ms、后处理 80ms」这类结构性预算做规划，计时只作辅助验证，不作为容量依据。

### 现场 8：批处理能显著降本

把多张图打包成一个请求送给支持批处理的接口，能摊薄固定开销。凯喵：离线任务优先批处理，在线请求再考虑单张低延迟；两者用不同的调用路径，别一套参数打天下。

```python
resp = client.batch(images, max_batch=16)
```

### 现场 9：图像预处理要统一

尺寸、色彩空间、EXIF 方向不一致，会让模型表现飘忽。凯喵：统一转成 RGB、按 EXIF 摆正、缩放到固定范围，再进模型。预处理不统一，等于给模型喂了「随机变换」的数据。

```python
from PIL import Image, ImageOps
img = ImageOps.exif_transpose(Image.open(path).convert("RGB"))
```

### 现场 10：多图输入的 token 会叠加

一次传十张图，token 是单张的十倍，可能直接超上下文。凯喵：先算总 token 预算，超了就减少图片数量或降分辨率，别等接口报「超出上下文」才回头改。

### 现场 11：图文检索要分别建索引

文本和图像的嵌入空间未必同维，混在一个索引里检索会失真。凯喵：要么用同一个多模态模型把两者映射到同空间，要么分别建索引再做融合排序。选型前先确认嵌入维度与语义空间是否一致。

### 现场 12：评估要多模态指标

只看文本相似度会漏掉「图看错了」的问题。凯喵：评估要同时看文字准确率、版面结构、以及人工抽检的图文一致性；自动指标只能筛掉明显错误，最终还要人看。

### 现场 13：隐私与合规不能忘

上传的图片可能含人脸、证件、定位信息。凯喵：脱敏、最小化上传、明确保留策略，是上线前的必答题；别为了效果把原始图无限期存着。

### 现场 14：延迟要分层优化

网络传输、预处理、模型推理、后处理，每一段都要单独度量。凯喵：先找到最慢的一段再优化，别一上来就换更大的模型——很多时候瓶颈在图片下载和预处理，而不是推理。

> 凯喵总结：多模态的坑九成在「分辨率与 token 成本」「无脑召回」「没有缓存」「计时当容量」「预处理不统一」。把这 14 个现场刻进手感，你的多模态系统才能既有效又跑得起。

> 一句话收尾：多模态的竞争力不在「能不能识别」，而在「用多少成本、多快速度识别」——工程上的每一分节省，都会体现在账单和体验上。

### 凯喵叮嘱：先算账，再上模型

最后叮嘱一句：做多模态功能前，先在纸上算一笔账——每张图多少 token、每天多少请求、单价多少，乘出来的月度成本能不能接受。凯喵见过太多「demo 很惊艳、上线就下架」的多模态功能，根子都是成本没算清。

另外，分层设计是控制成本的核心：便宜的召回、中等的重排、昂贵的精读，每一层只做自己该做的事。把所有图都送最贵的模型，是最常见也最昂贵的错误。工程能力，往往就体现在「用最少的算力拿到够用的效果」这件事上。

再多说一句：多模态应用的护城河，很少是「用了最贵的模型」，更多是「把每一环的成本都压到合理」。凯喵见过效果相近的两个产品，一个每天烧掉十倍预算，差别不在模型，而在有没有缓存、有没有分层、有没有把分辨率降到刚好够用。这些看起来琐碎的工程决策，累积起来就是能不能规模化、能不能盈利的分水岭。

还有，多模态的评估比纯文本更难，因为它多了一个「看没看对」的维度。文字抽对了但图看错了，自动指标可能仍然很高。凯喵的建议是建立一套人工抽检流程，定期把模型输出和原图放在一起核对，尤其关注表格、手写、小字这些容易出错的场景。自动指标负责筛明显错误，人负责把关语义一致性，两者缺一不可。把成本和评估这两件事同时做好，多模态功能才算真正落地。

最后一句话送给准备上多模态的人：先做一个只处理十张图的小原型，把整条链路的耗时和花费都量出来，再决定要不要做大。凯喵见过太多项目一上来就接全量数据，结果成本失控、效果还没验证，最后仓促下架。小步验证、逐步放量，在任何涉及真金白银的 AI 功能上都适用。多模态很酷，但酷不过一张能算得过来的账单。

再补一句关于评估的提醒。多模态的效果很难用单一数字概括，因为「看得准」和「答得好」是两件事。识别层错了，后面无论语言模型多强都救不回来；识别层对了但描述跑偏，用户体验同样糟糕。所以评估要分层做：先单独衡量感知环节的准确率与召回，再衡量语言环节的事实一致性，最后才看端到端的用户满意度。把三层拆开，你才能一眼看出瓶颈在哪一层，而不是对着一个模糊的总分反复调参。凯喵见过太多团队在语言侧死磕，结果真正的瓶颈其实是输入图片分辨率被压缩得太狠，感知层从一开始就丢掉了关键信息。分层评估，是让优化力气用对地方的前提。

## 三视角解析
### 🧑‍💻 程序员视角
图文对齐不是「图配一句话」这么简单：一张图可能对应多个对象、多种关系，标注粒度决定了模型能学到什么。图像分辨率直接决定 token 成本：224×224 切成 16×16 的 patch 是 196 个 token，1024×1024 就是 4096 个，成本差 20 倍。OCR 与 VLM 是互补而非替代：OCR 精确但只给文本，VLM 理解版面但可能读错字，票据场景应「OCR 抽字段 + VLM 做校验」。流水线必须设超时与降级，否则一个坏图卡住整批。

### 🎓 博士生视角
多模态的核心难题是「对齐」：视觉与语言处于不同模态空间，需要对比学习（CLIP）把二者映射到同一语义空间。CLIP 的 InfoNCE 损失让匹配的图文对相似度高、不匹配的低，但它的「相似」是全局语义而非细粒度对应（不知道「狗在左边」）。视觉 token 化的两种路线——patch embedding（ViT）与离散 token（VQ-VAE）——决定了模型能否与语言模型无缝拼接。分辨率与 token 数的平方关系是多模态成本的根本约束。

### 📚 考研者视角
AI 岗面试高频：
1. **CLIP 原理**：双塔结构、对比学习、零样本分类的实现方式与局限。
2. **ViT**：patch 切分、位置编码、与 CNN 的归纳偏置差异。
3. **多模态融合**：早期融合、晚期融合、交叉注意力的适用场景。
4. **成本控制**：分辨率与 token 数的关系、动态分辨率、图像压缩策略。
