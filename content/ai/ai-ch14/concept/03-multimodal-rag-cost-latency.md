# 多模态 RAG 与成本/延迟：视觉检索增强、预处理成本、延迟预算

RAG（检索增强生成）把「模型参数里的知识」换成「检索来的外部证据」，多模态 RAG 则是把**图像**也
纳入检索与增强。它让模型回答「基于你给的这堆图/文档」而不是「凭记忆编」。但多模态一进来，成本
和延迟立刻比纯文本 RAG 重一个量级——这一节专门算这笔账。

## 多模态 RAG 长什么样

用户问图文问题 → ① 把候选图像/文档做**预处理**（resize、编码、视觉编码器抽取 embedding）；
② 用查询（文本或图）在向量库做**跨模态检索**，召回 Top-K 相关图像/页面；③ 把召回的视觉证据与
问题一起送进 VLM 生成答案。和文本 RAG 的区别仅在于：检索对象和增强内容里多了「视觉」，而视觉
的预处理与编码远比文本贵。

## 图像预处理成本：被低估的开销

一张文档图进流水线，要 resize、可能做 OCR、过视觉编码器抽 embedding。批量文档（如 100 页）的
预处理是实打实的成本：按单张 0.002 美元估算，100 页就是 0.20 美元；若每页还要多模态 embedding，
成本再翻倍。部署时这笔账必须算进「每次入库/每次查询」的总价，否则看起来模型免费、其实预处理
烧钱。优化手段：缓存 embedding（同图不重算）、降分辨率到「够用就好」、批处理编码。

## 延迟预算：把一次问答拆成段

一次多模态问答的端到端延迟要拆段看：图像预处理 ~50ms、视觉编码 ~120ms、文本生成（8 token）~
240ms、网络/调度 ~30ms，合计约 440ms，目标 ≤500ms。可见**文本生成是大头（55%）**，视觉编码
其次。延迟预算的意义不是「总时长」，而是「哪段能砍」：若超预算，优先压缩生成 token 数或换更小
视觉编码器，而不是盲目堆 GPU。

## 成本模型：把调用拆成可计价的项

单次多模态调用成本 = 视觉 token 单价×图数 + 文本 token 单价×词数。例如 5 张图 × $0.01 + 2000
文本 token × $0.0005/1k = $0.051。做预算时把它乘上「日均调用量」，才是真正的账单。多模态 RAG
相比纯文本 RAG 多出的，正是「视觉 token 与预处理」这两块。折中策略：只在必要时召回图（先用文本
检索粗筛，确认需要视觉再取图），避免每张图都无条件编码。

## 失败模式与兜底

多模态 RAG 还会遇到：召回的图像其实不相关（检索质量差）、图像预处理把关键区域裁掉、VLM 无视
证据直接编。兜底和文本 RAG 一样——给证据做引用、对低置信召回降权、对生成做事实校验。

## 三视角解析

### 🧑‍💻 程序员视角
- 多模态 RAG = 图像预处理→跨模态检索 Top-K→视觉证据+问题送 VLM。和文本 RAG 只差「视觉」两字，但成本/延迟重一个量级。
- 预处理成本是隐藏开销：批量文档要按张算钱（如100页×$0.002=$0.20），用 embedding 缓存、降分辨率、批处理编码来压。
- 延迟预算要拆段看：文本生成常是大头(55%)，超预算先砍生成 token 数或换小视觉编码器，别盲目堆 GPU。
- 成本模型=视觉token单价×图数+文本token单价×词数；只在必要时召回图（先文本粗筛），避免每张图都无条件编码。

### 🎓 博士生视角
- 多模态 RAG 把「参数化记忆」替换为「检索到的多模态上下文」，其有效性依赖检索召回率与证据质量。和文本 RAG 一样，它用「检索即索引」规避了模型知识的时效与私有性限制，代价是引入了检索器与预处理器的误差项。
- 延迟预算的分解本质是对推理链做**关键路径分析（critical path analysis）**：各段串行/并行的拓扑决定了端到端下界。视觉编码与文本生成若可并行（如边编码边生成首 token），延迟会显著低于简单相加，工程上值得专门优化。
- 从系统视角，多模态 RAG 的瓶颈从「模型算力」转移到「数据面的 I/O 与编码」：图像预处理的吞吐、向量库的检索延迟、embedding 缓存命中率，往往比模型本身更决定成本和体验。这是 MLOps 里典型的「模型小、管道贵」。

### 📚 考研者视角
- 记忆锚点：**多模态RAG=预处理→跨模态检索→视觉增强生成；隐藏成本在预处理与视觉token；延迟大头是文本生成**。
- 与 408 的「关键路径/吞吐」对照：延迟预算分解就是关键路径分析，预处理/编码/生成哪些能并行决定端到端下界。
- 面试常问「多模态 RAG 比文本 RAG 多了什么成本」：答视觉预处理、视觉 token 单价、embedding 缓存与召回质量风险。
