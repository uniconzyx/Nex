# 记忆系统：三层结构与写入-检索-遗忘

## 主题一：记忆三层——工作记忆 / 短期记忆 / 长期记忆

把「上下文窗口」当成唯一记忆是 Agent 最常见的架构缺陷。工程上按**生命周期**分三层：

| 层 | 载体 | 生命周期 | 内容 | 容量约束 |
|---|---|---|---|---|
| 工作记忆（Working） | 当前任务的状态草稿 | 单次任务 | 当前目标、已完成步骤、待办、中间变量 | 严格有界，任务结束即销毁 |
| 短期记忆（Short-term） | 会话消息列表 | 单次会话 | 最近 N 轮对话、最近工具观察 | 滑动窗口 + 摘要压缩 |
| 长期记忆（Long-term） | 外部存储（向量库/关系库/文件） | 跨会话 | 用户偏好、稳定事实、经验教训 | 理论上无限，靠检索与遗忘管理 |

```
   用户输入
      |
      v
 [短期记忆: 最近若干轮]  <--- 摘要压缩 <--- 溢出部分
      |
      v
 [工作记忆: 本步状态]  -- 提级(importance>=阈值) --> [长期记忆: 跨会话事实]
      ^                                                   |
      |                                                   v
      +----------------- 检索(相关度+新近度+重要性) ---------+
```

### 🧑‍💻 程序员视角
工程决策：

- **工作记忆要用结构化字段，不要用自由文本。** 例如
  `{"goal": ..., "done": [...], "todo": [...], "vars": {...}}`，每步可程序化更新与断言，
  避免「模型忘了自己做到哪一步」。
- **短期记忆的核心是「压缩策略」而非「窗口大小」。** 窗口开太大 → 成本线性上涨且注意力被稀释；
  正确做法是「保留最近 K 轮原文 + 更早内容压成滚动摘要」。
- **长期记忆不能全量加载。** 必须走「检索 Top-K + 重排」，与 RAG 完全同构（可复用 ai-ch06 的链路）。
- **事故模式**：把工具返回的原始日志写进长期记忆 → 检索时噪声压过有效事实。
  正确做法是在**写入侧**就做清洗与摘要，而不是在检索侧救火。

### 🎓 博士生视角
第一性原理与结构：

- 三层划分对应**存储层级（memory hierarchy）**思想：越靠近「当前计算」的记忆越快、越小、越易失；
  越远的记忆越大、越慢、越持久。用「生命周期 × 访问频率」决定放置层级，是缓存的经典逻辑。
- 工作记忆 ≈ 寄存器/栈：`O(1)` 访问、容量极小、随任务销毁；
  短期记忆 ≈ 缓存：滑动窗口 + 淘汰策略；
  长期记忆 ≈ 外存：`O(log n)` 检索、容量近乎无限、需要索引。
- 因此「上下文窗口不够用」不是模型缺陷，而是**层级设计的常规问题**——
  解法是分层 + 淘汰 + 提升（promotion），而不是无限扩容。

### 📚 考研者视角
面试笔试考点：

- **三层定义与载体**：工作记忆（当前任务草稿，任务级）、短期记忆（会话消息窗口，会话级）、
  长期记忆（外部存储，跨会话）。
- **与操作系统类比的考点（高频）**：寄存器/缓存/外存三层存储体系，
  容量、速度、易失性三者权衡；LRU 是缓存淘汰的经典算法。
- **易错点**：把「上下文窗口」等同于「记忆」；把「长期记忆」做成「把历史全部拼接」。
- **追问口径**：长期记忆与 RAG 的区别？答：机制同构（检索增强），区别在数据来源——
  RAG 检索外部知识库，长期记忆检索 Agent 自身沉淀的交互事实与偏好。

## 主题二：写入-检索-遗忘策略

只有「写入 / 检索 / 遗忘」三个策略都设计好，记忆才是资产而不是负债。

**写入（Write）**——决定什么值得记：

- **触发式写入**：任务结束时写「结论」；用户显式纠正时写「偏好」；工具报错时写「教训」。
- **重要性打分**：`importance = w1 * 用户显式程度 + w2 * 重复次数 + w3 * 影响范围`；
  低于阈值只留在短期记忆，达到阈值才提级到长期。
- **去重**：写入前用指纹（`zlib.crc32` 等确定性哈希）比对，避免同一事实反复入库。

**检索（Retrieve）**——决定记起哪条：

- **三因子排序**：`score = α·相关度 + β·新近度 + γ·重要性`，比纯向量相似度更贴近人类记忆；
- **混合召回**：向量（语义）+ 关键词（实体/ID）+ 时间过滤（最近/N 天），再重排。

**遗忘（Forget）**——决定丢掉什么：

- **容量淘汰**：LRU（最近最少使用）/ LFU（最不常使用）/ 重要性加权淘汰；
- **时间过期**：TTL（存活期）到期自动失效，适合「有时效性的事实」；
- **摘要压缩**：把多条同类记忆合并成一条摘要，内存降数量级而保留语义（见 ex04/ex05）。

### 🧑‍💻 程序员视角
工程落地与成本账：

- **写入必须异步且可失败**：记忆写失败不应阻塞主流程；用队列 + 重试，并记录写入延迟指标。
- **检索要设预算**：长期记忆检索本身也要消耗 token 与延迟，必须设 Top-K 与字符上限。
- **LRU 用有序字典实现**：容量 `N` 内命中即「移到最新」，未命中即淘汰最旧（Python 可用 `OrderedDict`）；
  注意线程安全与持久化两个额外问题。
- **TTL 用逻辑时钟而非墙钟**：示例里用整数 `tick` 递增模拟时间，保证输出确定性、可回放（见 ex05）。
- **遗忘要有审计**：删掉的是「过期事实」还是「用户关键偏好」，需要可回溯，否则合规审计过不了。

### 🎓 博士生视角
策略的形式化：

- LRU 的淘汰判据是「最久未被访问」，其假设是**时间局部性**；LFU 假设**频率局部性**；
  两者都可用「访问序列」这一随机过程刻画。对本例的确定性测试，只需计数即可判定行为正确性。
- TTL 引入**有效期语义**：条目 `(k, v, ttl)` 的有效条件为 `now - written_at <= ttl`，
  等价于给每条记忆一个「置信度随时间衰减」的单调函数。
- 重要性加权淘汰可写成最大化保留期望效用的目标：
  `max Σ retained importance_i s.t. Σ size_i <= C`，是背包问题的一个特例（贪心按 `importance/size` 排序近似最优）。
- 摘要压缩是有损编码：信息量下降、但**信噪比上升**，其收益来自「任务相关信息的密度提升」。

### 📚 考研者视角
面试笔试考点：

- **写入触发条件**：结论达成、用户纠正、错误教训、重复出现达到阈值。
- **检索打分公式**：`score = α·相关度 + β·新近度 + γ·重要性`（能说清三因子的动机即可）。
- **遗忘三机制**：容量淘汰（LRU/LFU）、TTL 过期、摘要压缩。
- **与 408 的接口**：LRU 与 TTL 是操作系统的**页面置换 / 缓存失效**经典考点；
  「局部性原理」是 LRU 合理性的理论基础。
- **易错点**：只做「写入」不做「遗忘」，导致长期记忆无限膨胀、检索精度与成本同时恶化。

## 三视角小结

| 视角 | 一句话抓法 |
|---|---|
| 程序员 | 工作记忆结构化、短期记忆压缩、长期记忆检索；写入异步、检索有预算、遗忘有审计 |
| 博士生 | 记忆 = 存储层级；LRU 依赖时间局部性；重要性淘汰是背包问题的特例 |
| 考研者 | 三层定义、三因子检索、LRU/TTL 与操作系统置换算法对接 |
