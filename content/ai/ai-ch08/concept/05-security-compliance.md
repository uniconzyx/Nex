# LLM 安全与数据合规

## 主题一：OWASP LLM Top 10 与提示注入的纵深防御

**OWASP LLM Top 10（2025）** 给出 LLM 应用的高频风险清单，与本行最相关的是：
**LLM01 提示注入**、**LLM02 不安全输出处理**、**LLM05 供应链**、**LLM06 过度代理（excessive agency）**、**LLM07 系统提示泄露**、**LLM10 无界消耗**。
提示注入分两种形态：
**直接注入**——用户在输入里写「忽略以上指令」；
**间接注入**——恶意指令藏在**被检索的文档/网页/工具返回值**里（RAG 与 Agent 场景的主要威胁），用户本身无辜，模型却照做了。
防御原则是**纵深（defense in depth）**：输入净化（规则/白名单，见 ex08）→ 特权隔离（系统指令与不可信内容分通道、不可信内容永远当数据不当指令）→ 最小权限（工具只给必要权限、危险操作人工确认）→ 输出校验（结构/内容白名单、防泄露系统提示）→ 监控（异常指令模式告警）。

```text
不可信输入 ──► 净化(规则/白名单) ──► 通道隔离(数据≠指令) ──► 模型
                                          │
                       最小权限工具 ◄─────┴────► 输出校验 ──► 用户
```

### 🧑‍💻 程序员视角
- **没有单一灵药**：任何「过滤关键词」都能被绕过，净化只是第一层，必须叠加权限与输出校验。
- **间接注入要重点防**：RAG 文档与网页抓取内容（firecrawl 类工具）是攻击面，入库前做净化并在提示中明确标注「以下为不可信资料」。
- **过度代理是常见事故**：给 Agent 一个能删库/发邮件/转账的工具，注入成功后后果不可逆——危险操作必须人工确认 + 幂等 + 可回滚。
- **无界消耗**：限制 max_tokens、max_steps、单租户配额，防止被恶意 prompt 拖成天价账单。

### 🎓 博士生视角
- 提示注入的根因是 **LLM 没有指令/数据分离的架构保证**：Transformer 把所有输入揉进同一序列，系统提示与用户数据共享同一注意力通道，因此「指令优先级」只是训练出来的倾向而非硬约束。
- 因此理论上的彻底解法是**架构级隔离**（如让不可信内容只能通过受限通道影响控制流，或引入形式化的策略引擎做执行前校验），而非纯提示层防护。
- 与经典安全对照：提示注入类似**注入类漏洞**（SQLi/命令注入），同样的原则适用——输入验证 + 参数化（通道隔离）+ 最小权限 + 输出编码。

### 📚 考研者视角
- **笔面考点**：OWASP LLM Top 10 的高频条目；直接注入 vs 间接注入的区分与典型载体；纵深防御的层次。
- **标准口径**：提示注入＝通过输入操纵模型行为使其偏离预设指令；间接注入＝恶意指令经外部内容（文档/网页/工具返回）进入模型上下文。
- **易错点**：认为「过滤了关键词就安全了」；只在前端过滤而忽略服务端与检索侧；把系统提示泄露当成低危（可能泄露内部策略与密钥线索）。

## 主题二：数据合规：最小化、脱敏与可删除

AI 应用的合规底线是三条：**最小化**（只收集/上传完成任务所必需的数据）、**脱敏**（PII 在进入模型与日志前就替换，见 ex11）、**可删除**（用户要求删除时，主库、缓存、向量库、日志、备份全部可定位并删除）。
PII 脱敏用正则覆盖手机号、邮箱、身份证、银行卡等（正例必须命中，反例如订单号/版本号/圆周率不得误伤），并把脱敏放在**前置阶段**，让模型与日志都只见到脱敏后的文本。

### 🧑‍💻 程序员视角
- **脱敏位置决定成败**：在接入层就脱敏，才能保证下游（模型、日志、缓存、向量库）都不落地原文；事后脱敏必然有遗漏。
- **正则要有反例测试**：见 ex11 用「订单号/版本号/坐标区间」当反例，防止「宁可错杀」把业务数据打码导致功能异常。
- **可删除是工程问题**：给每条数据打上主体 ID（tenant/user），缓存与向量条目同样带该 ID，删除时按 ID 级联，并预留备份删除流程。
- **向量库里的原文**：存 embedding 时若同时存了原文，删除向量条目时必须一并删除原文。

### 🎓 博士生视角
- 合规的技术对应物是**数据流图上的可追溯与可剪枝**：最小化 = 减少进入处理链的数据字段；脱敏 = 在链上插入不可逆变换；可删除 = 保证每个副本都可按主体 ID 定位（即「数据血缘」与「副本清单」）。
- 「不可逆」的强度分级：掩码（部分保留）< 哈希（需盐且防彩虹表）< 差分隐私（可量化的隐私预算 ε）；选择取决于下游用途（需要回填就不能不可逆）。
- 删除的难点在**派生数据**：向量、微调语料、日志摘要、缓存都可能重新暴露被删数据，因此删除必须覆盖派生副本，而不仅是主表。

### 📚 考研者视角
- **笔面口径**：数据最小化、目的限制、可删除权（被遗忘权）三项原则；AI 场景额外关注训练数据来源合规与推断性隐私（模型可能记住训练数据）。
- **常考手段**：正则/词典脱敏（掩码、哈希、泛化）、差分隐私（ε 越小隐私越强、效用越低）、联邦学习（数据不出域）。
- **易错点**：认为「删了主库就删干净了」（遗漏缓存/日志/向量/备份）；把「脱敏」等同于「加密」（前者是变换后仍可用，后者是保护存储）；以为关掉训练开关就等于不用于训练。
