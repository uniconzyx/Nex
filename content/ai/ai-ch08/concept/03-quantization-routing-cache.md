# 量化、模型路由与语义缓存

## 主题一：量化方案与精度取舍

**量化**用更低位宽表示权重/激活，直接降低显存与带宽，是压 TPOT 与成本的主力。主流方案：

| 方案 | 位宽 | 特点 | 适用 |
|---|---|---|---|
| FP16/BF16 | 16 | 基线，无损参考 | 训练与高精度推理 |
| INT8 | 8 | per-tensor CT2 误差可控；激活需 per-channel | 通用推理 |
| GPTQ | 4(权重) | 训练后逐层误差补偿，静态 | GPU 低延迟部署 |
| AWQ | 4(权重) | 保护重要通道（激活大的权重），质量更稳 | GPU 生产首选 |
| GGUF | 2~8 可变 | llama.cpp 生态，CPU/混合推理 | 本地/边缘 |
| NF4 | 4 | 信息论最优的 16 电平正态分位表 | QLoRA 微调 |

关键认知：**低位宽不是免费的**。实测（见 ex02）在标准正态权重上，fp16 最大相对误差约 0.0005，int8 约 0.18，而 NF4 在 |w|≥0.1 的权重上最大相对误差可达 **1.0**——因为小权重会被就近量化到 0，相对误差 100%。这说明「看平均误差很美好，看长尾相对误差会翻车」，评估量化必须同时看 PPL/任务指标与相对误差分布。

### 🧑‍💻 程序员视角
- **选型口诀**：GPU 上要质量用 AWQ、要极致吞吐用 GPTQ；CPU/本地用 GGUF；微调用 NF4(QLoRA)。别用 INT8 per-tensor 直接量化激活（离群值会毁掉精度）。
- **必做回归**：量化后跑一遍评测集，比对准确率/格式合规率下降是否可接受；只盯显存下降不看质量是事故源头。
- **KV 量化更敏感**：长上下文任务上 KV 量化的质量损失通常大于权重，谨慎开启。
- **混合精度**：第一层/最后一层与注意力输出常保留高精度，是常见的「保质量」技巧。

### 🎓 博士生视角
- NF4 的动机：正态分布下，量化电平取**等概率分位点**可最小化量化误差的期望，比均匀电平更优；但最优性以「权重服从正态」为前提，重尾激活会破坏假设。
- GPTQ 用**二阶信息（Hessian 近似）**逐列补偿量化误差，把误差分摊到未量化权重上，逼近 OBS/OBC 框架；AWQ 则基于「激活尺度大的权重更重要」的观察做通道级缩放，属**激活感知**方法。
- 误差分解：量化误差 = 表示误差（位宽）+ 舍入误差（分位点位置）+ 累积误差（逐层传播放大）；前者靠位宽，中者靠分位点/分组，后者靠校准集与逐层补偿。

### 📚 考研者视角
- **笔面定义**：PTQ（训练后量化）vs QAT（量化感知训练）；对称量化 scale = max|x|/(2^{b-1}−1)，非对称再引入零点 zp。
- **常考计算**：给定 absmax 与位宽求量化步长与最大绝对误差（= scale/2）；求某权重的相对误差。
- **易混点**：混淆「量化误差的均值小」与「最大相对误差小」；把 GGUF 当成量化算法（它是**文件格式**，内部可含多种量化类型）。

## 主题二：模型路由、语义缓存与优化顺序

**模型路由**：按请求难度/长度/任务类型把流量分给不同模型（小模型处理简单意图，大模型兜底难例），用少量质量损失换大幅成本下降。
**语义缓存**：对 query 做 embedding，命中相似历史问答就直接返回（或复用），省掉整次推理；难点是**阈值—命中率—误命中率**三角（见 ex06 实测：阈值 0.5 时命中率 0.68 但误命中 0.15，阈值升到 0.9 误命中归零、命中率也掉到 0.10）。
**正确的优化顺序**（本章最重要的一条工程纪律）：

```
① 度量（Trace 找到瓶颈） → ② 砍上下文（精简 prompt/去重/压缩）
→ ③ 分模型（路由 + 小模型兜底） → ④ 加缓存（前缀缓存 + 语义缓存）
→ ⑤ 最后才是推理加速（量化/投机/换框架）
```
前四步通常是数倍收益且低风险，第五步往往是个位数百分比且高风险。

### 🧑‍💻 程序员视角
- **先度量**：没有 Trace 就优化等于蒙眼开车；用 Trace 看 token 分布，常发现「80% 的请求在重复问同一件事」——这时加缓存比换框架有效十倍。
- **语义缓存红线**：必须配**阈值 + TTL + 结果版本**三项，且对时效性/个性化内容禁用；误命中一个错误答案的代价可能远高于省钱。
- **路由的兜底**：小模型先答并给出置信度，低置信或高价值请求升级到大模型；路由决策本身要可观测（打标路由路径）。
- **成本核算**：按输入/输出分别计价，输出通常贵 3~4 倍（见 ex09），所以「让模型少说废话」是最便宜的优化。

### 🎓 博士生视角
- 路由本质是**代价敏感的分类/学习问题**：目标是最小化 E[cost + λ·loss]，需要在「用哪个模型」上做最优决策，可与级联分类器（cascade）理论类比——难度低时早退出。
- 语义缓存的命中判定是**近似最近邻 + 阈值**，其错误由两部分构成：embedding 的语义保真度（表达误差）与阈值判定（决策误差）；两者都随领域漂移，所以在开放域上误命中率难以压到零。
- 优化顺序的合理性来自**收益/风险比**：上下文与缓存属于确定性的确定性收益（可精确核算），而推理加速涉及数值近似（质量风险）与框架迁移（工程风险），应放在最后。

### 📚 考研者视角
- **笔面考点**：成本-延迟优化的正确顺序（先度量→砍上下文→分模型→加缓存→推理加速），以及每一步的典型手段与收益量级。
- **常考口径**：单请求成本 = 输入 token×输入单价 + 输出 token×输出单价（可含缓存折扣）；月度成本 = 单请求成本 × QPS × 时间。
- **易错点**：跳过度量直接上推理框架；语义缓存不设 TTL 导致返回过期答案；把「路由」与「A/B 实验分流」混为一谈（前者是稳态策略，后者是实验手段）。
