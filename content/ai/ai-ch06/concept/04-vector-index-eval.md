# 向量索引与 RAG 评估

## 主题一：向量索引——HNSW / IVF / PQ 的召回-延迟-内存三角

ANN（近似最近邻）索引在「召回率、延迟、内存」三角里取舍：
- HNSW：分层可导航小世界图，查询快、召回高，但内存占用大（存图结构）。
- IVF：倒排聚类，先定位最近簇再局部搜索，内存省，但召回依赖聚类质量与 nprobe。
- PQ：乘积量化把高维向量压成短码，内存骤降、可加速距离计算，但引入量化误差（见 ex08）。
实际常把 IVF 与 PQ 组合（IVF-PQ）在亿级数据上压内存。

### 🧑‍💻 程序员视角
工程选型：
- 百万级文档：HNSW 首选，延迟低、召回好，内存可接受。
- 亿级文档：IVF+PQ，用 PQ 压缩把内存从 O(N·D) 降到 O(N·M)。
- 评估索引要同时看 Recall@k（召回）、QPS（延迟）、内存占用，不可只看其一。
- HNSW 的 efSearch 越大召回越高但越慢，是线上最常调的旋钮（见 ex07 的分层下降）。

### 🎓 博士生视角
复杂度与近似保证：
- 暴力检索 O(N·D)，精确但随 N 线性变慢。
- HNSW 查询复杂度约 O(log N · M)，M 为每层近邻数；分层下降使访问节点远少于 N（见 ex07 的访问节点数 vs 暴力）。
- IVF 召回由 nprobe 与聚类紧致度决定，理论上以「簇间边界样本」的漏召回换速度。
- PQ 的误差来自子空间量化，距离计算在码本上查表加速，误差与子向量方差正相关。

### 📚 考研者视角
笔面口径：
- **HNSW/IVF/PQ 各自特点**：HNSW 快且准但费内存；IVF 省内存靠聚类；PQ 用量化极致压缩。
- **召回-延迟-内存三角**：三者不可兼得，按数据规模与预算取舍。
- **易错点**：认为 ANN 是精确检索——它牺牲少量召回换速度，需评估 Recall@k。

## 主题二：RAG 的分层评估

RAG 评估分三层：检索层（Recall@k、MRR、NDCG@k 看「找得对不对」）、
生成层（Faithfulness 忠实度、引用准确率看「用没用上」）、端到端（答案准确率、人工抽检）。
单看召回率不够，检索对了模型也可能没用上；要证明 RAG 有用，必须做「换掉检索器」的对照实验（有无检索的指标差）。

### 🧑‍💻 程序员视角
工程实践：
- 先用 Recall@k / NDCG@k 调检索器与 top-k，再用 Faithfulness/引用准确率调拼接与提示。
- 离线做「无检索 vs 有检索」「换 embedding 模型」的 A/B 或回放对照，量化 RAG 增益。
- 指标要随 k 多组对照（见 ex06），避免只报单一 k 掩盖曲线差异。
- LLM-as-Judge 做生成层评估时需校准，防止 judge 本身有偏好偏差。

### 🎓 博士生视角
指标定义：
- Recall@k = |retrieved∩relevant| / |relevant|；Precision@k = |retrieved∩relevant| / k。
- MRR = 1/rank_first_relevant（首个相关项的倒数排名）。
- NDCG@k 用分级相关性 + 位置折扣（log2(i+1)），对「排得靠前的相关项」给更高分，理想序做归一化。
这些指标评估「排序质量」，与 RAG 最终答案质量通过 Faithfulness 桥接。

### 📚 考研者视角
笔面口径：
- **召回率/精确率/MRR/NDCG**：Recall@k 看覆盖、Precision@k 看纯度、MRR 看首个相关位置、NDCG 看分级排序质量。
- **易错点**：Recall@k 高 ≠ 答案好——还需 Faithfulness 验证模型真正用上了检索证据。
- **评估闭环**：检索层指标 + 生成层忠实度 + 换检索器对照实验，三者缺一不可。
