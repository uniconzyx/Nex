# 混合检索、RRF 与重排

## 主题一：混合检索（向量 + BM25）与 RRF 融合

稠密检索擅长语义、稀疏检索（BM25）擅长关键词/专有名词。混合检索把两者结果用 RRF（Reciprocal Rank Fusion）融合：
score(d) = Σ_{r∈检索器} 1/(k + rank_r(d))，k 通常取 60。RRF 不依赖分数量纲、只用排名，
因此对「向量分数」与「BM25 分数」尺度不一致天然鲁棒（见 ex05）。

### 🧑‍💻 程序员视角
工程要点：
- 混合检索权重不必手调：RRF 直接吃排名，省去分数归一化的烦恼。
- BM25 的 IDF 符号别写反：idf = log((N-n+0.5)/(n+0.5))，n 是含词文档数，越稀有权重越高。
- 多路召回（向量/BM25/SQL 过滤）统一走 RRF，比加权求和稳。
- 查询改写（Multi-Query/HyDE）可先展开多路再融合，提升召回（见 ex12）。

### 🎓 博士生视角
RRF 的依据：两个独立弱检索器对真相关文档的排名都「靠前」的概率高于随机；
取排名的倒数之和等价于对「各检索器独立给出该文档为相关」做近似对数似然融合，
因此比单检索器更稳，且对分数分布无假设（免归一化）。BM25 的概率检索模型：
p(t|d) 经 Robertson-Spärck 式推导得 RSJ 权重，配合 TF 饱和 (k1) 与长度归一化 (b) 即为标准 BM25。

### 📚 考研者视角
笔面口径：
- **为什么混合检索**：稠密检索补语义、稀疏检索补关键词/ID，互补提升召回。
- **RRF 是什么**：按 1/(k+排名) 求和融合多路排名，k 一般 60，只用名次不用分数。
- **易错点**：把 BM25 的 IDF 写成 log((n+0.5)/(N-n+0.5))，符号反了会惩罚稀有词。

## 主题二：两阶段「召回 + 重排」

双塔（bi-encoder）embedding 是「粗排」：query 与 doc 各自编码、靠内积快速近邻检索，但缺少细粒度交互。
交叉编码器（cross-encoder）把 query+doc 拼一起过模型，能做细粒度相关性判断，但太慢无法对所有文档跑。
因此标准做法是：双塔召回 top-50~100 → 交叉编码器重排 → 取 top-5~10 喂 LLM。

### 🧑‍💻 程序员视角
工程取舍：
- 召回阶段追求「高召回、低延迟」，用 ANN 索引（HNSW/IVF）换精度换速度。
- 重排阶段追求「高精度」，用 cross-encoder，只跑几十到几百条，成本可控。
- 跳过重排直接用双塔 top-k 喂 LLM，常漏掉细粒度相关（尤其长文档里的精确证据）。
- 重排器也可用更轻的 ColBERT 式 late interaction 折中。

### 🎓 博士生视角
理论动机：双塔把 query/doc 映射到低维再做内积，等价于用「固定度量」近似真实相关性，
信息瓶颈导致细粒度信号丢失；cross-encoder 让 query 与 doc token 充分交互（attention），
表达能力更强但失去「doc 端离线预计算」的可扩展性——于是产生了「召回-重排」的两阶段分工。

### 📚 考研者视角
笔面口径：
- **召回与重排的区别**：召回用双塔快速粗筛（高召回低精度），重排用交叉编码器精细排序（高精度低吞吐）。
- **为什么两阶段**：兼得「可扩展的召回」与「高质量的排序」，单阶段无法同时做到。
- **易错点**：以为双塔 top-k 直接用即可，忽略 cross-encoder 带来的精度增益。
