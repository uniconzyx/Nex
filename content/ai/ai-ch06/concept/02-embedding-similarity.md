# Embedding 与相似度度量

## 主题一：Embedding 模型与语义空间假设

稠密检索（dense retrieval）假设语义相近的文本在 embedding 空间里距离更近。
embedding 模型把文本映射到低维向量；「语义空间假设」是 RAG 有效性的根基：query 与命中文档在向量空间可被近邻检索到。
选型看三点：多语言覆盖、向量维度（成本）、是否支持指令前缀（instruction prefix）与 Matryoshka 表示（可截断）。

### 🧑‍💻 程序员视角
工程要点：
- 维度选择直接决定存储/检索成本，优先 Matryoshka 模型（如 1024 维可截断到 256 维仍可用）。
- 检索域与训练域不一致时，加指令前缀（「为检索表示这段文本」）能显著提升召回。
- 跨语言检索要用原生多语言模型，不要靠翻译链路拼接。
- 上线前评估 Recall@k 再定维度与 top-k，避免拍脑袋。

### 🎓 博士生视角
第一性原理：稠密检索依赖「对比学习」把相关对拉近、无关对推远，损失通常为 InfoNEC：
L = -log  exp(s(q,d+)/τ) / Σ exp(s(q,d)/τ)。其隐式假设是存在平滑的语义流形，使得「近邻即相关」。
当查询涉及精确符号/ID（如「订单号 12345」）时，该假设失效——这正是稀疏检索（BM25）的补位价值。

### 📚 考研者视角
笔面口径：
- **embedding 与向量相似度**：embedding 是文本的低维稠密向量；相似度常用余弦，值越接近 1 越相关。
- **语义空间假设**：语义相近的文本在向量空间中距离更近，是「近邻即相关」的前提。
- **易错点**：以为 embedding 能编码一切——对精确字符串/数值/ID，稠密向量常常失效，需混合稀疏检索。

## 主题二：余弦 / 内积 / L2 的等价条件

三者衡量「相似」但数值尺度不同。设向量已 L2 归一化（模长=1）：
余弦 = q·d / (|q||d|)，内积 = q·d，L2 距离² = |q|² + |d|² - 2 q·d。
当两向量都归一化后，|q|=|d|=1，于是 余弦 = 内积，且 L2² = 2 - 2·余弦，
故「余弦降序」与「内积降序」排名一致、「L2 升序」与之等价（见 ex01/ex02）。

### 🧑‍💻 程序员视角
工程惯例：检索前先把 embedding L2 归一化，然后只用内积（点积）检索——
内积可用矩阵乘法 + FAISS/GPU 批量加速，比反复算余弦快得多，且排名等价。
未归一化时三者排名可能反转，直接拿原始内积当相似度是常见 bug。

### 🎓 博士生视角
等价条件的严格表述：
1. 余弦 ≡ 内积 ⇔ 所有向量模长相等（通常取归一化到 1）；
2. L2 距离 ≡ 余弦 ⇔ 向量模长恒定，因为此时 L2² 与 -余弦 只差常数 2。
若模长不齐，内积受「向量长度」污染（长向量的内积天然偏大），排名会失真。

### 📚 考研者视角
笔面口径：
- **余弦 vs 内积 vs L2**：归一化后三者排名等价；未归一化时内积受模长影响、L2 是距离（越小越近）。
- **易错点**：用原始内积当相似度却不归一化，长文档/长 query 会系统性占优。
- **手算**：cos = 点积 / (|q|·|d|)，务必先算模长再除。
