# 合成数据过滤与去重/污染：规则、语义、留验隔离

当数据规模到百万级、且大量来自模型合成（distillation / self-instruct）时，质量问题会指数级
放大：重复样本让模型死记硬背、污染样本让评测分数虚高、低质样本稀释梯度。这一节给一套
「先规则、再语义、最后隔离」的三段式 pipeline。

## 一、前两段：规则过滤与语义去重

### 第一段：规则过滤（cheap，先挡掉明显垃圾）

```text
   原始语料 → 规则过滤 → 语义去重 → 训练集污染检测 → 留验隔离 → SFT 训练
                │           │            │              │
              去脏/短/重    SimHash    与评测集      train / valid
                          near-dup     重叠率         / test 分开
```

规则过滤成本低、可并行，应当放在最前面。常用规则：① 长度门限——过短（`< 4` 字）往往无意义，
过长（如 `> 60` 字且无结构）可能是噪声拼接；② 重复率——按空格分词后 `1 - 唯一词数/总词数`，
超过阈值（如 `0.5`）说明在车轱辘话；③ 格式合法性——要求 JSON 输出的样本必须能 `json.loads`；
④ 语言/语种一致性与敏感词。规则过滤是「粗筛」，目标是用接近零的成本砍掉 10%–30% 的明显垃圾。

### 第二段：语义去重（dedup，避免记忆而非泛化）

即便规则过关，合成数据常有「换汤不换药」的近重复：同一道题改个数字、同一段话换种说法。
朴素做全文哈希去重没用，因为文本表面不同。做法是**把样本映射成指纹再比较**：
- n-gram 指纹：取 3-gram 集合，用 Jaccard 相似度，`>= 0.5` 判为重复；
- SimHash：对字符/词做加权哈希得 64 位指纹，Hamming 距离 `<= 3` 判为近重复。
SimHash 适合海量数据（可用桶+LSH 加速），n-gram 适合中小规模精确控制。去重让模型被迫见过
更多「不一样」的样本，泛化更好，也省显存与训练时间。

## 二、污染检测与留验隔离

```python
def char_ngrams(s: str, n: int = 5) -> set:
    return {s[i:i + n] for i in range(len(s) - n + 1)}

def jaccard(a: str, b: str, n: int = 5) -> float:
    A, B = char_ngrams(a, n), char_ngrams(b, n)
    return len(A & B) / len(A | B) if (A | B) else 1.0

# 阈值 0.8 是经验起点：中文长文本 5-gram 上，正常改写通常落在 0.5~0.7，
# 只改数字/换语序的「近重复」会到 0.85 以上。
def is_near_dup(a: str, b: str, thr: float = 0.8) -> bool:
    return jaccard(a, b) >= thr

# 全量两两比较是 O(N²)；万级以上改用 MinHash/LSH 先分桶再精算
```

### 第三段：训练集污染检测（contamination）

「污染」指评测/测试样本或其近似版本混进了训练集，导致 benchmark 虚高。检测用 token 级
重叠率：把测试 prompt 分词，与训练语料逐条算 Jaccard，`>= 0.5` 即标记污染。更严格的可做
n-gram 子串包含（看测试题的连续片段是否出现在训练里）。检测到污染必须**剔除**，否则你以为
涨的点全是记忆。

### 留验隔离（hold-out / contamination-free split）

最重要的一条纪律：**评测集在合成与清洗的任何一步都不能参与**。常见错误是「先合成 100 万条，
再随机抽 1 万条当测试」——这 1 万条早被合成模板的近重复污染了。正确做法：先冻结评测集，
合成/去重/过滤只在「训练候选池」上做，任何与评测集重叠率超阈值的候选直接丢弃。评测集要像
疫苗一样「绝对干净」，否则指标失去意义。

## 三、工程判据

### 一条工程判据

过滤不是「越狠越好」。过度过滤会砍掉长尾难样本，让模型变「乖」但变笨。用「保留率 + 下游
小模型验证」双指标监控：保留率太低要查规则是否过严；下游验证精度不涨则要去重是否过度。
数据工程是拿指标说话的迭代，不是一次性脚本。

## 三视角解析

### 🧑‍💻 程序员视角
- pipeline 顺序固定：规则 → 语义去重 → 污染检测 → 留验隔离。规则最便宜放最前，别一上来就跑 SimHash。
- 去重用 SimHash（64位指纹，Hamming<=3）做海量近重复，中小规模用 3-gram Jaccard>=0.5 更直观可控。
- 评测集在合成/清洗任何一步都不能碰：先冻结测试集，候选池里与它重叠率超阈值的直接丢，杜绝污染。
- 过滤不是越狠越好，盯住「保留率 + 小模型验证精度」两个指标，防止把长尾难样本误杀。

### 🎓 博士生视角
- 去重与泛化的关系可建模为：经验风险最小化里，重复样本等价于对该样本权重放大，使经验分布偏离真实分布；去重是让经验分布更均匀，等价于某种重要性采样的反向操作。
- 污染检测本质是「成员推断」的弱版本：判断测试样本是否出现在训练分布的支持集内。严格的 contamination study 还会做 n-gram 子串包含与困惑度异常检测。
- 留验隔离对应统计学习的「独立同分布测试」假设——若测试集在训练分布支撑内，泛化误差估计是有偏的。这是 LLM 评测方法论里被反复强调却常被忽略的点。

### 📚 考研者视角
- 记忆锚点：**规则粗筛→语义去重→污染检测→留验隔离；评测集全程冻结**。
- 与 408 的「哈希去重/集合运算」对照：SimHash 的 Hamming 距离、n-gram 的 Jaccard 都是集合相似度，本质一致。
- 面试常问「怎么防止 benchmark 被刷爆」：答留验隔离 + contamination detection + 用动态/私有测试集，而不是「我们不泄露答案」。
