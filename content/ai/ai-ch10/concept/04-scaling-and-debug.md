# ai-ch10 · 核心概念（四）：Scaling Law、数据与训练诊断

> 视角覆盖：程序员（工程决策）/ 博士生（第一性原理）/ 考研者（笔面口径）。三者互补、不重复。

```text
Scaling Law（Chinchilla 口径）：
    L(N,D) ≈ a/N^α + b/D^β + c
    给定算力 C ≈ 6ND，最优是 N 与 D 同比例增长（约 20 token / 参数）

数据侧三件事：
    配比      代码/数学/多语的比例 -> 直接决定能力分布
    去重      重复样本让模型「背」而非「学」，还放大小数据集权重
    tokenizer 词表大小决定同样中文要多少 token -> 直接影响成本与有效上下文

训练诊断信号：
    loss 尖峰       数据脏样本 / lr 过大 / fp16 溢出
    loss 长期不降   容量不足 / 标签噪声 / lr 太小
    训练降验证升    过拟合（加数据或正则）
    梯度范数爆炸    梯度裁剪 + warmup
```

## 1. Scaling Law：为什么「加算力」是可预测的

2020 年 Kaplan 等人的核心发现是：语言模型的测试损失随**参数量 $N$、数据量 $D$、计算量 $C$** 分别呈**幂律**下降：

$$L(N)=\Big(\frac{N_c}{N}\Big)^{\alpha_N},\qquad L(D)=\Big(\frac{D_c}{D}\Big)^{\alpha_D},\qquad \alpha_N\approx0.076,\ \alpha_D\approx0.095$$

这两条式子的实践含义是「**可外推**」：在小模型上拟合出系数，就能预测大模型的 loss（误差在几个百分点内）。这让「预训练」从试错变成了**有预算约束的工程规划**。

2022 年的 Chinchilla 修正了一个关键错误：Kaplan 时代普遍「模型太大、数据太少」。Chinchilla 的结论是，在固定计算预算 $C\approx6ND$ 下，最优解是**参数与数据同步增长**：

$$N_{\text{opt}}\propto C^{0.5},\qquad D_{\text{opt}}\propto C^{0.5},\qquad \frac{D_{\text{opt}}}{N_{\text{opt}}}\approx20\ \text{tokens/参数}$$

于是 7B 模型的计算最优数据量约为 **140B tokens**。这条结论直接改写了过去几年的训练配方（GPT-3 175B 只训了 300B tokens，按 Chinchilla 明显「欠训练」）。

但 2023 年之后又出现反转：由于**推理成本远大于训练成本**，工业界普遍选择「**过训练**（over-train）」——用远超 20 tokens/参数的数据训小模型（如 7B 训 2T tokens），使推理更便宜。这说明 Chinchilla 给的是「训练最省」的解，而产品的目标是「总成本最省」，两者不同。

### 🧑‍💻 程序员视角

- 用 Scaling Law 做预算规划：先在小规模（如 100M/1B）跑 3-5 个点拟合出 $\alpha$ 与常数，再外推目标规模的 loss 与所需 token。**不要跳过这一步直接上大模型**。
- 数据不是越多越好：超过某个点后**重复数据**的边际收益迅速衰减（重复 4 个 epoch 后几乎无收益），所以「堆数据」必须配去重。
- 判断一个训练是否「数据受限」：把验证 loss 对 token 数作图，若曲线明显低于幂律外推，说明还有数据红利；若已贴合幂律，加数据不如加参数（或换数据质量）。
- 「过训练」的工程判据：推理 QPS × 生命周期 ≫ 训练成本时，选更小的模型 + 更多 token。7B/13B 训 2T+ tokens 已成常态。

### 🎓 博士生视角

- 幂律的来源目前没有第一性原理的解释，但有几条有说服力的假说：① 数据分布的**内在维度**导致误差按维度衰减；② 模型容量与数据流形的「覆盖速度」；③ 损失的不可约项（熵）决定了幂律的下限。这是理论开放问题，不是「已知规律」。
- Chinchilla 的推导是在 $C=6ND$ 约束下最小化 $L(N,D)=E+A/N^{\alpha}+B/D^{\beta}$，对 $N,D$ 求拉格朗日条件即得 $N\propto D$。$\alpha\approx\beta$ 是关键前提，若两者不等，最优配比会偏离 20:1。
- 「过训练仍有收益」与 Chinchilla 不矛盾：Chinchilla 优化的是**训练算力**，而过训练优化的是**推理算力**。把目标函数换成「训练 + 推理总成本」，最优解自然偏向更小的 $N$ 与更大的 $D$。
- 幂律在「能力」层面会失效：loss 平滑下降，但具体能力（算术、多跳推理）常呈**涌现**（突变）或**逆缩放**（U 形）。因此「loss 预测」不等于「能力预测」，这是当前评测研究的核心难题。

### 📚 考研者视角

- **必背**：三条幂律的形式与「$C\approx6ND$」；Chinchilla 的 20 tokens/参数；过训练的含义。
- **常考计算**：给 $C=10^{22}$ FLOPs，求最优 $N,D$（$N=\sqrt{C/120}$、$D=20N$）；给 7B 模型问 Chinchilla 最优 token 数（140B）。
- **易混**：Scaling Law 是**经验规律**不是定理；「涌现能力」是能力层面的现象，与 loss 幂律不矛盾。

## 2. 数据：配比、去重与 tokenizer

Scaling Law 只谈「量」，但真实收益更多来自「质」与「配比」：

- **配比（mixture）**：代码、数学、多语、网页的比例直接决定能力分布。代码数据能提升推理，数学数据提升符号操作，但过度会导致「偏科」。配比需要用**小规模消融**（proxy）来定，不能凭感觉。
- **去重**：重复数据既浪费算力又加剧记忆（memorization）。工程上用 MinHash/SimHash 做近重复检测，阈值影响很大。
- **质量过滤**：规则（长度、符号比、语言识别）+ 模型打分（分类器/困惑度）。过滤掉 50% 的低质数据通常等价于「数据量翻倍」。
- **tokenizer**：BPE/Unigram 的词表大小影响序列长度（进而影响算力）、多语公平性、以及「数字/代码」的切分方式。词表小 → 序列长 → 训练贵；词表大 → embedding 参数多、低频 token 训练不足。

### 🧑‍💻 程序员视角

- 配比实验的正确做法：固定总 token 预算，在小模型（如 1B）上跑 5-10 组配比，用**目标任务**（不是通用 loss）选最优，再放大。直接在大模型上试配比是烧钱。
- 数据管线要有「可追溯的版本」：哪个快照、哪版过滤规则、去重阈值。**训练不可复现，八成是数据版本不一致**。
- tokenizer 一旦定了就别改（改了等于换模型）：词表与权重绑定，迁移成本极高。
- 记忆/隐私风险：重复数据 + 大模型 = 逐字复现训练数据。上线前要跑「成员推断/前缀补全」测试。

### 🎓 博士生视角

- 配比的本质是**多分布的经验风险最小化**：把各来源视为不同分布 $p_i$，混合权重 $w_i$ 决定模型在哪个分布上更准。这可以用「混合分布的最优权重」框架分析，但深度学习下缺少闭式解，只能经验搜索。
- 去重与「有效数据量」的关系可以用**重复数据的边际损失曲线**刻画：前几个 epoch 近似线性收益，超过阈值后趋平（甚至因过拟合而变差）。这是「数据重复预算」的定量依据。
- tokenizer 影响的是**序列的熵**：同一文本在更细粒度切分下熵更高（每 token 信息少）、序列更长、注意力的 $O(n^2)$ 成本上升。这是「词表大小 vs 序列长度」的取舍本质。
- 数据质量与 Scaling Law 的交互：过滤后的高质量数据往往让幂律的**指数变大**（同样算力下 loss 更低），说明「数据质量」不是常数项而是指数项——这一点尚未被写进标准 Scaling Law 公式。

### 📚 考研者视角

- **必背**：配比、去重、质量过滤、tokenizer 四个环节的作用；BPE 的基本思想（高频子词合并）。
- **常考问法**：① 数据去重为什么重要（省算力、防记忆）；② 词表大小的影响（序列长度 vs 参数）；③ 数据配比如何确定（小模型消融）。
- **易混**：tokenizer ≠ embedding（前者切词、后者查表）；去重 ≠ 清洗（去重是近重复检测，清洗是质量过滤）。

## 3. 训练诊断：怎么读 loss 曲线

loss 曲线是训练唯一的「仪表盘」，读法要分四类信号：

| 现象 | 含义 | 处理 |
|---|---|---|
| 训练 loss 与验证 loss 同步下降 | 健康 | 继续 |
| 训练降、验证平/升 | 过拟合（小数据）或分布不一致 | 加数据/正则、查泄漏 |
| 两者都平台化（plateau） | 学习率太小、容量不足、数据无信息 | 调 lr、加容量、换数据 |
| 验证 loss 先降后升（U 形） | 经典过拟合，或双下降的峰值区 | 早停、加正则；若在插值阈值附近属正常 |

还有三类「看起来反常但正常」的现象必须认识：

- **双下降（double descent）**：测试误差在插值阈值附近出现峰值，之后继续下降。原因不是「方差又变小」，而是过参数化后 SGD 的隐式正则挑到了泛化好的解。
- **Grokking**：训练准确率早已 100%，验证准确率在很久之后突然跳升。这是「记忆 → 泛化」的相变，与权重衰减强度强相关。
- **Loss spike**：单点突变后恢复，或突变后不恢复（优化器状态被污染）。

### 🧑‍💻 程序员视角

- 诊断顺序：**先看是否数据问题**（打乱、泄漏、重复），**再看优化**（lr、warmup、梯度范数），最后才怀疑架构。80% 的「模型不行」是数据/评估的问题。
- 学习率扫描是最有效的单变量实验：在 log 尺度上取 4-5 个值跑短程（如 500 步），选 loss 下降最快且不发散的区间。
- 评估集必须**与训练集同分布但有独立来源**，否则「验证集涨了但线上没涨」是必然。常见泄漏：同一文档被切成训练/验证两段。
- 记录要包含「失败实验」：同样的坑不该踩第二次。实验管理的最小要求是 `config + git hash + 数据版本 + seed` 四元组。

### 🎓 博士生视角

- 双下降与经典偏差-方差理论的冲突，实质是**「模型复杂度」的定义问题**：用参数量定义复杂度时，过参数化区间不单调；用「有效容量」（由数据流形维度决定）定义时，曲线仍可能单调。这是理论未解决的核心争议。
- Grokking 的机制假说：权重范数在训练早期缓慢增长、某个时刻越过「泛化阈值」，表现为相变。因此它是「优化动力学」现象，不是「模型能力」现象。
- 训练 loss 的可预测性与泛化的可预测性不等价：loss 幂律很准，但下游任务表现常出现**断点**（emergence）或**逆缩放**（inverse scaling）。这解释了为什么「只报 loss」的论文越来越难说服评审。
- 过拟合的现代判据不再是「训练/验证 gap」，而是「**分布外**泛化」。大模型可以同时「训练 loss 极低 + 分布内泛化好 + 分布外崩」，gap 单一指标已经不够。

### 📚 考研者视角

- **必背**：过拟合/欠拟合的曲线特征；早停、正则、数据增广三种应对；双下降与经典 U 形曲线的区别。
- **常考问法**：① 训练 loss 下降但验证不变的原因（过拟合/分布偏移/泄漏）；② 双下降说明了什么（复杂度与泛化非单调）；③ grokking 是什么（延迟泛化）。
- **易混**：验证集 loss 上升 ≠ 一定过拟合（也可能评估集分布漂移）；loss 平台 ≠ 收敛（可能卡在鞍点/学习率过小）。

## 4. 可复现性：把「玄学」变成「工程」

深度学习实验的不可复现来源，按影响从大到小：

1. **数据版本与顺序**（最常见）：采样器 seed、shuffle 策略、数据快照。
2. **硬件与算子**：非确定性 kernel（atomicAdd）、cuDNN benchmark、多卡归约顺序（浮点不满足结合律）。
3. **超参与环境**：框架版本、默认值随版本变化、混合精度开关。
4. **随机种子**：初始化、dropout、数据增强。

工程上的最低标准：固定 seed、关掉 benchmark、开启确定性算法（`torch.use_deterministic_algorithms(True)`）、记录 config 与 git hash。**容忍「性能损失 5% 换可复现」**，在需要定位 bug 的阶段是划算的。

### 🧑‍💻 程序员视角

- 三件套：`config.yaml`（含所有超参默认值）、`git rev-parse HEAD`、`data_manifest.json`（分片 hash）。缺一件，三个月后没人能复现。
- 用「**冒烟测试**」验证管线：1 个 batch 过拟合到 loss≈0（能过拟合单 batch 说明前向/反向/损失都对）。
- 分布式下的可复现极难（归约顺序不定），通常只保证「统计等价」而非「逐位相同」。发表级实验建议单卡小规模复现关键结论。

### 🎓 博士生视角

- 浮点不满足结合律是分布式不可复现的**根本原因**：AllReduce 的树形/环形归约顺序不同，结果差 1 ulp，长训练后放大成可见差异。这不是框架 bug。
- 「可复现性危机」在方法学上等价于「缺少误差棒」：单 seed 的结果可能落在分布的尾部。严谨做法是 3-5 个 seed 报均值±标准差，尤其在「提升 0.3%」的结论上。
- 确定性算法的性能代价来自「不能用 atomicAdd 的并行归约」，必须串行化或分块，因此吞吐下降。这解释了「可复现」与「快」的取舍。

### 📚 考研者视角

- **必背**：可复现的四个来源；确定性算法的取舍；单 batch 过拟合测试的作用。
- **常考问法**：① 为什么同样的代码结果不同；② 如何验证训练管线正确（单 batch 过拟合）；③ 多 seed 的必要性。
- **易混**：可复现（同结果）≠ 可重复（同结论）；前者是工程属性，后者是科学属性。
