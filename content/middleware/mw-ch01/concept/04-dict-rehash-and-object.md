# 四、字典渐进式 rehash 与对象系统

本文件覆盖两个核心主题：**① dict 的渐进式 rehash** 与 **② 对象类型/编码系统与二进制安全**。

---

## ① dict：渐进式 rehash（不阻塞的单线程友好设计）

（中立陈述）Redis 的 `dict` 用两张哈希表 `ht[0]`/`ht[1]`，负载因子超阈值（或 rehash 中）触发扩容/缩容。它**不一次性搬迁**全部 entry，而是用 `rehashidx` 记录进度，在执行增删改查及定时任务 `serverCron` 中**每次搬一个桶**，搬完才把 `ht[1]` 替换为 `ht[0]` 并清空 `ht[1]`。期间查找要查两张表。

### 🧑‍💻 程序员视角
- **rehash 期间写入都进 ht[1]**：迁移过程中新 key 落到 `ht[1]`，所以「迁移中」是最终一致的中间态；如果你的逻辑依赖 `keys` 顺序或快照，要意识到这段时间数据分布在两张表。
- **大字典 rehash 是平滑的**：相比一次性 `rehash` 会卡顿几百毫秒，渐进式把代价摊到多次命令，单线程不会被卡死——但 `BGSAVE`/`BGREWRITEAOF` 时 rehash 会暂停（避免 COW 页放大）。
- **踩坑**：误以为 `DBSIZE` 立刻反映新表，实际迁移中两表之和才是总数（Redis 内部已处理，应用层无需关心，但排查内存时要懂）。

### 🎓 博士生视角
- **触发条件**：`used / size >= 1` 且未在做 `BGSAVE` 或 `used/size` 远超 `5`（强制）触发扩容到 `2^n`；`used/size < 0.1` 触发缩容。取 `2^n` 是为让 `hash & (size-1)` 等价于取模且分布均匀。
- **搬迁单元**：每次 rehash 一个非空桶的所有 entry，顺带在 `serverCron` 里「连搬 100 个桶 / 1ms」上限，保证后台推进又不超时。
- **查找逻辑**：先查 `ht[0]`，若 `rehashidx != -1` 且 `ht[0]` 未命中，再查 `ht[1]`；新增只写 `ht[1]`，从而保证 `ht[0]` 只减不增、最终搬空。

### 📚 考研者视角（笔面考点）
- **标准问法**：「Redis 的 dict 怎么扩容、为什么渐进式？」答双表 + `rehashidx` 逐步搬桶，避免单线程一次性 rehash 造成长尾延迟。
- **易错口径**：渐进式 rehash **期间新数据写入 ht[1]**，不是 ht[0]；「迁移中查找要查两张表」是必考点，别漏。
- **连问**：「缩容条件？」答负载因子 `<0.1`；「为什么 size 取 2 的幂？」答位运算取模均匀。

## ② redisObject 类型/编码系统与二进制安全

（中立陈述）Redis 一切键值都包成 `redisObject`：`type`（五大型）、`encoding`（底层编码）、`refcount`（引用计数共享）、`lru`（LRU/LFU 时钟）。`TYPE` 看 type，`OBJECT ENCODING` 看 encoding。二进制安全贯穿——长度由 `len` 记录，value 可含任意字节。

### 🧑‍💻 程序员视角
- **看编码再优化**：用 `OBJECT ENCODING` + `MEMORY USAGE` 定位 big key 与异常编码；某 Hash 本该 listpack 却显示 hashtable，多半是某个 value 超 64B。
- **共享对象**：小整数（0~9999）被全局共享、引用计数管理，不要依赖「每个 key 独立对象」的内存估算。
- **踩坑**：把 key 命名成含 `\n` 的串也能存（二进制安全），但客户端/监控按行解析会乱，纯属自找麻烦。

### 🎓 博士生视角
- **对象头 16 字节拆分**：`type(4b)+encoding(4b)+lru(24b)` 塞进一个字、`refcount` 一个字、`ptr` 一个字，共 16B；小整数编码把值直接放 `ptr`，省一次分配。
- **引用计数 vs GC**：Redis 用 `refcount` 即时释放而非 GC，单线程下无并发引用问题；共享仅限只读小整数，字符串等可变对象不共享，避免别名写污染。
- **二进制安全的本质**：所有字符串长度来自 `len`，命令处理按字节数而非 `\0` 截断，因此图片/序列化流可原样存取。

### 📚 考研者视角（笔面考点）
- **标准问法**：「redisObject 包含哪些字段？」答 type、encoding、refcount、lru、ptr，并解释各自作用。
- **易错口径**：`TYPE` 返回的是**顶层类型**（string/list…），`OBJECT ENCODING` 才是底层编码——面试常问「`SET k 123` 后 TYPE 与 ENCODING 分别是什么」，答 string / int。
- **连问**：「为什么小整数能共享？」答只读不可变 + 引用计数，可变对象不共享以免别名污染。
