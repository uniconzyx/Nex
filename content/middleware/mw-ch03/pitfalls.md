# 易错点 · Redis 高可用：主从、哨兵与 Cluster

> 行首编号条目（门禁按行首 `1.`/`- ` 统计）。每条：`N. **陷阱标题** —— 说明 + 正确写法`。

1. **混淆全量同步与部分同步、以为从节点重启一定走全量** —— 从节点断线重连时若断线期间写命令仍在主节点 `repl_backlog` 环形缓冲窗口内（offset 未滑出），走「部分同步」只补缺失区间，无需全量；只有首次、换主、或 backlog 被覆盖才 FULLRESYNC。正确写法：答「部分同步可行性取决于 offset 是否仍在 backlog 窗口」，并强调 backlog 是固定大小环形缓冲，写入过快/断线过久会退化全量。

2. **把哨兵的 quorum 当成 Raft 的多数派** —— quorum 只是「确认主节点 SDOWN 的哨兵数门槛」，用来达成 ODOWN，通常小于哨兵总数；真正执行故障转移的 leader 选举才需要「多数派（>N/2）」票。正确写法：明确区分「ODOWN 的 quorum」与「leader 选举的多数派」，二者独立配置、语义不同。

3. **选主规则记反优先级** —— 故障转移选新主顺序是 `replica-priority` **最小**优先 → 复制 `offset` **最大**（数据最新）优先 → `runid` **字典序最小**优先。正确写法：priority 小优先（数值越小越想当主）、offset 大优先（数据越新越优先），别把方向记反。

4. **MOVED 与 ASK 不分、以为都刷新路由表** —— MOVED 表示槽归属已永久变更，客户端应**刷新**本地槽映射；ASK 仅发生在槽迁移中间态，是「本次临时」重定向，**不刷新**映射。正确写法：答「MOVED 刷新、ASK 不刷新」，并说明 ASK 只管该 key 本次去目标节点拿。

5. **以为 Cluster 多 key 操作随便跨槽** —— 跨槽多 key（`MSET`/`MGET`/多 key Lua）默认报 CROSSSLOT 错误；必须用 hash tag `{...}` 把相关 key 约束到同一槽（如 `order:{u1}:a`、`order:{u1}:b`）。正确写法：答「默认跨槽不允许，用 hash tag 同槽」，并提醒 hash tag 设计不当会造成数据倾斜（大量 key 挤进同一槽）。

6. **以为哨兵/Cluster 能彻底杜绝脑裂** —— 哨兵投票与 Cluster 故障转移都只是「逻辑共识」，极端网络分区下仍可能双主；`min-replicas-to-write` + `min-replicas-max-lag` 是「软隔离」（宁可停写也不分叉），不是硬 fencing。正确写法：说明脑裂的不可合并性根源，并指出 min-replicas 是 CP 取舍、会降低可用性，且从节点慢/lag 大也会意外触发停写。

7. **以为 16384 槽可以随便改大提升粒度** —— 槽数固定 16384（14 位），槽分配表以 bitmap 经 gossip 传播，翻倍会使元数据与 `CLUSTER SLOTS` 体积翻倍；官方建议集群节点数 ≤1000，单槽过大在应用层再拆 key。正确写法：答「槽数固定 16384，是迁移粒度与元数据开销的折中」，不要说「可以调成更大」。
