# fs-ch14 · Agent × 全栈工程接缝：流式、长任务、幂等与成本 · 常见错误

1. **网关把流读光再返回，流式体验消失** —— 错在：在网关/中间件里写了 `const body = await response.text()` 或类似 `collect()`，再一次性转发。

   *为什么*：流式接口被中途「收齐」，用户看到的是「长时间白屏后全文瞬间出现」，首字节延迟极高；同时网关要缓存整条响应的内存，长流直接 OOM。

   *怎么改*：改为字节级透传：用 `for await (const chunk of response.body)` 收到一块立刻 `writable.write(chunk)`，绝不在中间件里把流读光。

2. **流式请求没有首字节超时，上游挂了前端一直转** —— 错在：只设了整体超时（如 60s），没设首字节（TTFB）超时。

   *为什么*：模型服务起不来或卡死时，第一条数据迟迟不到，用户面对无限转圈；整体超时太长，资源被空占。

   *怎么改*：设三级超时：连接超时（快速暴露连不上）、首字节超时（快速暴露上游没产出）、整体超时（兜底）。首字节超时通常设 5–15s。

3. **用户关页面后还在烧 token（取消没传播）** —— 错在：前端断开后，后端和模型推理没收到取消信号，继续把整段回答生成完。

   *为什么*：为「已经没人看」的请求持续付费，且占用模型并发配额，挤占真实请求；成本审计里出现大量「无人消费」的调用。

   *怎么改*：用 `AbortController` 把取消信号从网关显式传到模型调用；任何一跳断开都触发上游停止生成。

4. **长任务占着连接跑几分钟，任一超时即前功尽弃** —— 错在：把需要几分钟的任务做成「同步挂起」接口，指望网关/浏览器/LB 都不超时。

   *为什么*：任意一跳的空闲超时都会断掉连接，用户看到报错，但服务端可能还在跑，形成「双盲」；发布重启直接丢失进度。

   *怎么改*：改为「创建任务返回 id → 轮询/SSE 查状态 → 取结果」三段式；状态机落库，进度写检查点。

5. **断线重连用全量重发，造成重复与浪费** —— 错在：客户端掉线后不记游标，重连就从头订阅/重新拉取全部历史事件。

   *为什么*：用户看到重复内容、重复通知；服务端白白重算一遍，长任务场景尤其浪费。

   *怎么改*：重连带上 `last-event-id` 或进度游标，服务端只补发游标之后的事件，客户端按事件 id 去重合并。

6. **工具调用重试不做幂等，副作用被执行多次** —— 错在：网络抖动后对「发邮件 / 扣库存 / 改订单」这类调用直接重试，没带幂等键。

   *为什么*：重试十次可能真的发了十封邮件、扣了十次库存；这是资损级 bug，且往往在压测/弱网下才暴露。

   *怎么改*：每次调用分配 `callId`，执行前按 id 查重，已执行直接返回原结果；重试带同一 id 只执行一次。

7. **把审计日志当普通日志，可被悄悄篡改** —— 错在：审计信息写进和业务日志同一个、可被运维随意改写的文件/表，且没有完整性校验。

   *为什么*：出事后查不清责任，甚至日志被涂改导致无法追责；合规审计直接不通过。

   *怎么改*：审计日志独立存储，用哈希链做 tamper-evident，高敏字段脱敏；定时跑完整性校验。

8. **成本只在月底看总账单，没有单次计量** —— 错在：只在调用入口记「调了一次模型」，不记录 model / 输入输出 token / 单次花费。

   *为什么*：无法定位「哪类请求最贵」「哪个租户超支」，预算烧穿才发现；也没法给用户展示花费。

   *怎么改*：把 `(model, inputTokens, outputTokens, cost)` 作为每次调用的一等记录；流式输出先估后补。

9. **限流只做全局，一个租户挤垮所有人** —— 错在：只配了全局 QPS 限流，没区分用户/租户维度。

   *为什么*：单个租户的异常流量触发全局限流，把其他正常租户一起拦在外面，多租户 SaaS 下是严重事故。

   *怎么改*：限流分单用户/单租户/全局三层；网关入口按租户维度拦最省，后端按 token 做二次成本核算。

10. **降级策略写死在业务里，出事要改代码** —— 错在：「超预算就拒绝」「模型慢就排队」这类逻辑散落在各个 handler，没有统一开关。

   *为什么*：线上要调整降级阈值时只能发版；紧急情况下改不全、改不同步，雪崩时反应慢。

   *怎么改*：把降级与预算做成显式可配置开关（排队/截断/走缓存/拒绝），阈值可热更新，见底前预警、见底后熔断。
