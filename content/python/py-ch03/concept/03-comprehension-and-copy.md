# 推导式、生成器与深浅拷贝

## 1. 推导式（comprehension）：语法糖，但不只是糖

四种推导式（外加生成器表达式）：

```python
[x * 2 for x in range(5)]                 # list
{x: x ** 2 for x in range(5)}             # dict
{x % 3 for x in range(10)}                # set
(x * 2 for x in range(5))                 # 生成器表达式（圆括号，惰性）
```

**为什么它比 `for + append` 快**：推导式在编译期生成的是**独立的 `LIST_APPEND` 字节码**（3.x 里推导式有自己的作用域，循环变量不泄漏到外层），省掉了每次迭代的 `LOAD_METHOD` + `CALL`（方法查找与函数调用开销）。实测通常快 20%~40%。

**作用域细节（3.x）**：推导式有自己的局部作用域，循环变量**不会**泄漏；而生成器表达式更是惰性，变量在迭代时才绑定。

```python
x = 'outer'
[x for x in range(3)]
print(x)   # 'outer'（3.x 中 x 未泄漏；Python 2 的列表推导式会泄漏）
```

**嵌套与可读性**：两层以内清晰，三层就该改成显式循环或拆函数。可读性优先于"一行解决"。

```python
# 扁平化二维列表（两层，可接受）
flat = [item for row in matrix for item in row]
# 注意：外层循环在前，与写嵌套 for 的顺序一致
```

## 2. 生成器表达式 vs 列表推导式：内存与复用

| | 列表推导式 `[...]` | 生成器表达式 `(...)` |
|---|---|---|
| 求值 | **即时**（eager），一次性构建 | **惰性**（lazy），按需产出 |
| 内存 | O(n)，全部驻留 | O(1)，只保存状态 |
| 可重复遍历 | 可以 | **一次性的**，迭代完就空 |
| 适用 | 结果不大、要多次遍历/索引 | 大数据流、管道式处理、只遍历一次 |

```python
import sys
big_list = [x for x in range(10**6)]       # 约 8MB+（指针数组）
big_gen  = (x for x in range(10**6))       # 约 100 字节
print(sys.getsizeof(big_list), sys.getsizeof(big_gen))
```

**经典面试点**：`sum(x for x in range(n))` 比 `sum([x for x in range(n)])` 更省内存（后者先建完整列表）。而生成器只能消费一次：

```python
g = (x for x in range(3))
list(g)   # [0, 1, 2]
list(g)   # []  <- 已耗尽
```

## 3. 深浅拷贝：拷贝的是"引用"还是"对象图"

这是本章最容易出错、也最爱考的部分。

### 三种"浅拷贝"写法（等价）

```python
b = a[:]              # 切片
b = list(a)           # 工厂函数
b = copy.copy(a)      # copy 模块
b = a.copy()          # list 自带方法（3.3+）
```

**浅拷贝的含义**：**只复制容器本身**（新建一层"指针数组"），**不复制元素对象**。新旧容器里的槽位指向**同一批元素对象**。

```
a = [[1,2], [3,4]]
b = a[:]

a -> [ p1 | p2 ]       b -> [ p1 | p2 ]     # 槽位值相同，指向同一批子列表
          \__/                /
          [1,2]  [3,4]   <- 共享！
```

```python
a = [[1, 2], [3, 4]]
b = a[:]
b[0].append(99)
print(a)   # [[1, 2, 99], [3, 4]]   <- a 也被改了！
```

只要**替换整个槽位**（`b[0] = [9]`）就只影响 b；只要**原地修改共享的子对象**（`b[0].append(...)`）就会同时影响 a。

### 深拷贝

```python
import copy
c = copy.deepcopy(a)   # 递归复制整张对象图，新旧完全独立
```

`deepcopy` 会**递归遍历**并重建所有子对象，因此：

- **能正确处理循环引用**：内部用 `memo` 字典记录「已复制过的对象 id → 新对象」，遇到环时不无限递归。
  ```python
  a = []; a.append(a)      # 自引用
  b = copy.deepcopy(a)     # 正常，不会爆栈；b[0] is b
  ```
- **代价**：比浅拷贝慢得多（递归 + 类型分派），且对**大对象图**有明显开销；某些不可深拷贝的对象（文件句柄、线程锁、数据库连接、生成器）会抛错或需自定义 `__deepcopy__`。
- **默认不复制**：`deepcopy` 对不可变原子类型（int/str/tuple of immutables）直接返回原对象（省事且安全）。

### 决策表

| 场景 | 选择 |
|---|---|
| 元素全是不可变对象（int/str/tuple） | 浅拷贝就够（甚至不需要拷贝） |
| 元素含 list/dict/set 等可变对象，且要独立修改 | **`deepcopy`** |
| 只要替换顶层元素、不碰子对象 | 浅拷贝 |
| 大对象图、性能敏感 | 手工构造新对象（比 deepcopy 快且可控） |

## 4. 共享引用的经典陷阱：`[[0]] * 3`

```python
a = [[0]] * 3        # 错：3 个槽位指向同一个 [0]
a[0].append(1)
print(a)   # [[0, 1], [0, 1], [0, 1]]   <- 三个都变了！
```

**根因**：`*` 对序列做的是**重复引用**（把同一个对象的指针复制 n 份），**不是构造 n 个新对象**。对不可变元素无害（`[0] * 3` 没问题，因为改不了），对可变元素就是灾难。

**正解**：用推导式每次新建

```python
a = [[0] for _ in range(3)]    # 每次迭代都新建一个 [0]
a[0].append(1)
print(a)   # [[0, 1], [0], [0]]
```

同理 `dict.fromkeys` 也有类似陷阱（默认值是共享对象）。

## 5. `==` 与 `is`：值相等 vs 同一性

- `==` 调 `__eq__`，比较**值**；`is` 比较**对象标识**（`id()` 是否相同，即内存地址）。
- 小整数缓存：CPython 缓存 `-5 ~ 256`，所以 `a = 256; b = 256; a is b` 为 True，而 `257` 不一定。**不要用 `is` 比较数值**。
- 判断 `None` 一律用 `is None`（单例，且避免触发自定义 `__eq__`）。

```python
a, b = 256, 256
print(a is b)   # True（小整数缓存）
a, b = 257, 257
print(a is b)   # False（同一行赋值可能仍 True，取决于编译器常量折叠——不要用 is 比数值！）
```

## 6. 速记

- 推导式有自己的作用域、循环变量不泄漏，比 `for+append` 快（专用字节码）。
- 生成器省内存但**只能消费一次**；列表可重复遍历。
- 浅拷贝 = 复制容器、**共享子对象**；深拷贝 = 递归重建整张图（用 memo 处理循环引用）。
- `[[0]] * 3` 是**共享引用**陷阱 → 改用 `[[0] for _ in range(3)]`。
- `is` 比同一性、`==` 比值；数值比较永远别用 `is`。

## 三视角解析

### 🧑‍💻 程序员视角
- 切片、`list(x)`、`copy.copy` 都是**浅拷贝**（只复制外层容器）；要连内层一起复制用 `copy.deepcopy`。
- 嵌套结构的「改了一处结果全变」几乎都是浅拷贝导致的别名问题——先想清楚要浅还是要深。
- 生成器表达式惰性求值且**只能消费一次**；需要多次遍历就换成列表。

### 🎓 博士生视角
- 浅拷贝复制**容器结构**但共享内部对象的引用；深拷贝递归复制并维护 **`memo` 字典**，从而正确处理循环引用与共享子对象（避免无限递归与重复复制）。
- 生成器表达式返回的是迭代器（`__next__` 驱动），一旦耗尽就不可重用——这是迭代器协议的一次性语义，与可重复迭代的容器有本质区别。
- Python 3 中推导式有**独立作用域**，循环变量不会泄漏到外层（Python 2 会泄漏）——这是语言层面的语义变更，值得记住以防读旧代码时误判。

### 📚 考研者视角
- 与**值语义 vs 引用语义**、浅拷贝/深拷贝的经典概念题对应（C++ 的拷贝构造、Java 的 `clone` 都存在同一问题）。
- 循环引用与 `memo` 的处理可与图论中的「已访问集合」类比，是「用辅助结构避免重复访问」的通用模式。
- 记忆锚点：**浅拷贝共享内层、深拷贝递归复制**；**推导式在 Python 3 不泄漏变量**。
