# 02 · 索引、切片与视图

## 主题一：视图与副本——最容易踩的语义差异

NumPy 的索引分两大类，返回的东西**本质不同**：

| 索引方式 | 返回 | 是否共享内存 |
|---|---|---|
| 基本切片 `a[1:3]`、`a[::2]`、`a[:, 0]` | **视图** | 是 |
| 花式索引 `a[[0, 2]]` | **副本** | 否 |
| 布尔索引 `a[a > 0]` | **副本** | 否 |

视图之所以可能，是因为数组的「数据」与「怎么看数据」是分开的：视图只是换了一套 `shape` + `strides` + 起始偏移，指向**同一块**内存。所以改视图等于改原数组。

```python
import numpy as np
a = np.arange(10)
v = a[2:6]          # 视图
v[0] = 100
print(a[2])         # 100 —— 原数组被改了

c = a[[2, 3]]       # 花式索引 -> 副本
c[0] = -1
print(a[2])         # 仍是 100 —— 原数组没变
```

判定方法是 `np.shares_memory(x, y)`，它做的是真正的区间重叠检查（不是猜「大概共享」）：

```python
print(np.shares_memory(a, a[2:6]))   # True
print(np.shares_memory(a, a[[2,3]])) # False
```

`reshape` 也常常返回视图——只要内存布局允许「换一种切法」而不需要搬家：

```python
b = np.arange(12)
c = b.reshape(3, 4)          # 视图
print(np.shares_memory(b, c))  # True
d = b.reshape(3, 4).T          # 转置 -> 仍是视图（只是 strides 换了顺序）
print(d.strides)               # (8, 32)：行内跳 8 字节，换行跳 32 字节
```

**但 `reshape` 不总能成功返回视图**：`a.T.reshape(-1)` 因为转置后的内存不再连续，会静默复制一份。想显式控制就用 `a.reshape(...)` 后的 `arr.base is not None` 判定，或干脆用 `np.ascontiguousarray` 表明意图。

### 🧑‍💻 程序员视角

**「改不动原数组」是最常见的 bug。** 写了 `sub = df[df.x > 0]` 然后 `sub["y"] = 1`，原 `df` 纹丝不动——因为布尔索引给的是副本。修法有二：① 明确要改原数据，就写回 `df.loc[df.x > 0, "y"] = 1`；② 明确只改子集，就对副本操作，并接受「这是新对象」。

**用视图做「零拷贝切窗」是性能手段。** 处理大数组时（例如滑窗），尽量用切片视图而不是 `copy()`；只有当需要在函数返回后继续持有、且不愿拖住整块内存时，才显式 `.copy()`——否则一个 8 字节的视图会让整块 800 MB 的内存无法释放。

**`np.may_share_memory` 是宽松判定。** 它只判断「区间是否可能重叠」，会给出假阳性；要精确判定用 `np.shares_memory`（`max_work` 默认可控），代价是稍慢。

### 🎓 博士生视角

**步长（strides）是数组代数的基础设施。** `strides` 让「转置」「切片」「广播」都退化成元数据操作，从而使得这些操作是 O(1) 的。代价是**内存访问不再顺序**：转置后的数组按逻辑顺序遍历会跳着读，缓存不友好。这就是为什么「先把转置结果 `.copy()` 再算」有时反而更快——用一次拷贝换回顺序访问。

**视图是零拷贝，也是悬垂引用的来源。** 视图持有对 base 的引用（`arr.base`），只要视图活着，整块内存就不会被回收。对超大数组做细粒度切片并长期缓存，会造成「明明只用了 1% 数据却占着 100% 内存」的隐性泄漏。

**负步长（`a[::-1]`）也是视图**，只是 `strides` 为负。这解释了「为什么 `a[::-1]` 是 O(1) 的」，也解释了为什么 `a[::-1].reshape(...)` 往往需要拷贝。

### 📚 考研者视角

**标准问法：「`a[1:3]` 是视图还是副本？`a[[1,2]]` 呢？」** 必须答准：基本切片**是视图**（可改原数组），花式索引和布尔索引**是副本**。这是最常考、也最容易答错的一题。

**易错口径：「`reshape` 一定返回视图吗？」** 不一定。当内存不连续（如转置之后）时 `reshape` 会返回副本。判断方法：看 `arr.base`，或用 `np.shares_memory`。

**易错口径：「`a.T` 会复制数据吗？」** 一维以上数组的转置**不会**复制，只是交换 `shape` 与 `strides`；一维数组的 `T` 就是它自己。

## 主题二：布尔索引与高级索引

布尔索引用一个**同形状的 bool 数组**做筛选，返回一维副本：

```python
import numpy as np
a = np.array([3, -1, 4, -1, 5])
mask = a > 0
print(mask)          # [ True False  True False  True]
print(a[mask])       # [3 4 5]
print(a[a > 0].sum())  # 12
```

布尔索引可以多条件组合，注意**用 `&` `|` `~` 并加括号**，不能用 `and`/`or`：

```python
print(a[(a > 0) & (a < 5)])   # [3 4]
```

花式索引（整数数组）按给定顺序取值，并且会**按索引形状**重组输出：

```python
a = np.arange(10)
print(a[[7, 0, 2]])            # [7 0 2]
print(a[np.array([[0,1],[2,3]])])  # [[0 1] [2 3]]
```

两者组合时（二维数组按下标取值）常见写法是 `a[rows, cols]`，返回的是**逐对**取值的一维数组，而不是「按行再按列」的矩形——这个差别是很多人第一次用 `numpy` 做「取对角线」时的困惑来源。

### 🧑‍💻 程序员视角

**`np.where` 比 `if/else` 更可控。** 需要「按条件在两组值之间二选一」时，`np.where(cond, x, y)` 是一次向量化选择，不需要构造 Python 循环，也不会因为分支而破坏向量化。多条件分支用 `np.select([c1, c2], [v1, v2], default=...)`。

**布尔掩码要提前算好，别在循环里反复算。** `mask = df.x > 0` 算一次、复用多次；每次内联写 `df[df.x > 0]` 会重复遍历。

**别用链式布尔索引做赋值。** `a[a > 0][0] = 9` 改的是副本，静默失效。要改就一次写清：`a[np.argmax(a > 0)] = 9` 或用 `np.flatnonzero` 拿到位置。

### 🎓 博士生视角

**布尔索引的本质是「按掩码收集」。** 它需要先算出等长的 bool 数组（一趟遍历），再按 True 的位置把元素拷出来（第二趟），因此是两份工作而不是一份。若只需要计数或求和，用 `np.count_nonzero(mask)` / `a[mask].sum()` 里的前者能省掉第二趟。

**花式索引的形状语义。** 广播后的整数索引数组决定输出形状；`a[rows[:, None], cols[None, :]]` 得到的才是矩形外积式的取法。理解这一点就不会对「为什么 `a[[0,1],[0,1]]` 只给两个元素」感到意外。

**`axis` 与索引的正交性。** 索引操作改变的是「取哪些元素」，`axis` 改变的是「沿哪个方向做归约」；两者常被混为一谈，但一个作用于选择、一个作用于聚合。

### 📚 考研者视角

**标准问法：「怎么按条件筛选数组？」** 答布尔索引：`a[a > 0]`，返回副本。若问「怎么在满足条件的位置赋值」，答 `a[a > 0] = 0`（这是唯一可以「看着像链式其实不是」的写法——它是单次索引赋值）。

**易错口径：「`and` 能连接两个条件吗？」** 不能。`a > 0 and a < 5` 会对数组做真值测试并抛 `ValueError`。必须用 `&`，且每个条件都要加括号（`&` 优先级高于比较运算符）。
