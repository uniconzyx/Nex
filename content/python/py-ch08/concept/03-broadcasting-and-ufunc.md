# 03 · 广播与 ufunc

## 主题一：广播规则

广播（broadcasting）是 NumPy 让**不同形状**的数组能做逐元素运算的机制。规则只有三条，从**最右边的维度**开始对齐：

1. 若两个维度**长度相等**，直接对齐；
2. 若其中一方长度为 **1**，则把它沿该维度**逻辑复制**到另一方的长度；
3. 若既不相等、也都不为 1，**报 `ValueError`**。

例子对照：

| 形状 A | 形状 B | 结果 | 说明 |
|---|---|---|---|
| `(3, 4)` | `(4,)` | `(3, 4)` | B 被「提升」为行向量逐行复用 |
| `(3, 1)` | `(1, 4)` | `(3, 4)` | 两者都沿长度为 1 的维度扩展 |
| `(3, 4)` | `(3,)` | **报错** | 从右对齐后 4 vs 3 不兼容 |

```python
import numpy as np
a = np.arange(12).reshape(3, 4)
b = np.array([10, 20, 30, 40])
print((a + b).shape)          # (3, 4)
print((a[:, :1] + b).shape)   # (3, 4) —— (3,1) 与 (4,) 广播
try:
    a + np.array([1, 2, 3])
except ValueError as e:
    print("ValueError:", str(e)[:60])
```

**广播不产生真实的内存拷贝**（只改 `strides`，把长度为 1 的维度的步长设成 0），所以「把 `(3,1)` 扩成 `(3,4)`」是零成本的。但**运算结果**是实实在在要分配的新数组，所以广播规则不会拯救内存。

一个高频写法是给向量「加一个轴」以实现按行/按列的运算：

```python
x = np.array([1, 2, 3])              # (3,)
print((x[:, None] * x[None, :]))      # (3,3) 外积
```

`None`（即 `np.newaxis`）的作用就是插入一个长度为 1 的新维度，从而让广播规则把它扩展出去。

### 🧑‍💻 程序员视角

**广播是「省内存」而非「免费午餐」。** 两个大数组广播相加，结果数组的大小等于广播后的完整形状。写 `big[:, None] + big[None, :]` 之前先算一下元素数——`(100000, 100000)` 是 10^10 个元素，直接 OOM。这种场景要分块算。

**用 `keepdims=True` 保住维度以便广播。** `a.mean(axis=1)` 得到 `(3,)`，无法直接与 `(3,4)` 广播；写成 `a.mean(axis=1, keepdims=True)` 得到 `(3,1)`，就能 `a - a.mean(axis=1, keepdims=True)`（按行去中心化）。这是最实用的一个技巧。

**广播失败时先打印形状。** 报错信息里给的形状是「对齐后」的，若自己算过一遍 `(3,4)` 与 `(3,)`，就能立刻定位是「最后一个维度不匹配」。

### 🎓 博士生视角

**广播的形式化定义。** 对两个形状 `(s1, s2, ..., sn)` 与 `(t1, ..., tm)`，先右侧对齐，对每一维 `d`：若 `s_d == t_d` 或有一方为 1，则该维输出长度为 `max(s_d, t_d)`；否则不兼容。输出的秩 = `max(n, m)`。缺失的前导维度视为 1。

**广播是「存储层的技巧 + 运算层的复制」。** 表达式层面它是零拷贝的（`strides=0` 实现），但 ufunc 求值时每个逻辑位置仍要取一次值。因此广播并不降低**算术**次数，只降低**存储**次数。

**与 `einsum` 的关系。** `np.einsum("ij,j->i", a, b)` 显式写出指标消去，等价于「按 j 做加权和」，可以完全避免创建中间的大中间数组；当中间量比输入大很多时，`einsum` 是更省内存的写法。

### 📚 考研者视角

**标准问法：「广播规则是什么？」** 答三条：右对齐；相等或为 1 才兼容；不兼容就报错。再举一例 `(3,1)+(4,)→(3,4)` 说明「为 1 的维度会被扩展」。

**易错口径：「`(3,4)` 和 `(3,)` 能相加吗？」** **不能**。右对齐后 4 与 3 冲突，报 `ValueError`。若想按行相加，需要把后者改成 `(3,1)`（`b[:, None]`）。

**易错口径：「广播会复制数据吗？」** 广播本身不复制（靠 `strides=0` 实现零拷贝），但**运算结果**会分配新数组，其大小是广播后的形状。

## 主题二：axis 语义与聚合

`axis` 是「沿哪个方向压下去」，不是「在第几个维度上操作」。对二维数组：

- `axis=0`：把行压掉，得到每**列**的统计（结果长度 = 列数）；
- `axis=1`：把列压掉，得到每**行**的统计（结果长度 = 行数）；
- 不传 `axis`：对整个数组压成一个标量。

```python
import numpy as np
a = np.arange(12).reshape(3, 4)
print(a.sum(axis=0))   # [12 15 18 21] —— 4 个元素（按列）
print(a.sum(axis=1))   # [6 22 38]      —— 3 个元素（按行）
print(a.sum())         # 66
```

记法：**`axis=k` 表示结果中不再有第 k 维**。看结果形状最直接——`a.sum(axis=0)` 的 `shape` 是 `(4,)`，正好是「去掉第 0 维」。

常用的聚合与 NaN 口径：

| 函数 | 作用 | 遇 NaN |
|---|---|---|
| `sum` / `mean` / `std` | 求和 / 均值 / 标准差 | **传播**（结果为 NaN），除非用 `np.nansum` 等 |
| `np.nanmean` / `np.nansum` | 跳过 NaN 的版本 | 忽略 NaN |
| `argmax` / `argmin` | 极值**位置** | 不可靠（NaN 比较恒为 False） |
| `np.ptp` | 极差 `max - min` | 传播 |

```python
x = np.array([1.0, np.nan, 3.0])
print(x.mean(), np.nanmean(x))   # nan 2.0
```

注意 `np.ptp(a)` 是**函数**形式；NumPy 2.0 起已移除 `ndarray.ptp()` **方法**，老代码需要改。

### 🧑‍💻 程序员视角

**宁可显式写 `axis`。** 不传 `axis` 的聚合会把二维数组拍平，遇到「想要每行均值却写成整体均值」时不会报错，只会静默给你一个错数。团队里统一约定：聚合一律写 `axis`。

**区分「传播 NaN」与「跳过 NaN」。** `df.mean()`（pandas）**默认跳过** NaN，而 `np.mean(arr)` **默认传播**——同一个词在两个库里的默认行为相反，是跨库协作时的高频事故点。

**`argmax` 与 NaN 一起用是陷阱。** `np.argmax([1, np.nan, 3])` 可能返回 2（也可能返回 1，取决于具体实现在遇到 NaN 时的比较路径），它**没有**可靠的语义。要拿 NaN 安全的位置，先 `np.nanargmax`。

### 🎓 博士生视角

**归约的代数结构。** `sum` 满足结合律与交换律，因此允许任意顺序累加（浮点下会因顺序不同产生微小差异）。`mean` 由 `sum` 与 `count` 复合得到，所以「跳过 NaN 的均值」= 「忽略 NaN 的 sum」/「非 NaN 的个数」，`np.nanmean` 正是按这两个量算的，而不是先删 NaN 再算（后者会多一次拷贝）。

**浮点归约的误差累积。** 朴素顺序累加 n 个数的误差是 O(n·ε)；NumPy 对 `sum` 使用了**部分成对求和**（pairwise summation），把误差降到 O(log n·ε)。这解释了「为什么 `np.sum` 比手写循环累加更准」——不只是快。

**`axis` 与步长的关系。** 沿 `axis=0` 归约（跨行、列内连续）和沿 `axis=1` 归约（行内连续）的缓存行为完全不同：后者是顺序访问，前者是跨步访问。大数组上两者的性能差异可达数倍，这是「同一个聚合换个 axis 就慢一倍」的真实原因。

### 📚 考研者视角

**标准问法：「`axis=0` 和 `axis=1` 分别是什么？」** 标准口径：`axis=0` 沿行方向压（跨行），得到每列的结果；`axis=1` 沿列方向压（跨列），得到每行的结果。**最稳的记法**：结果里少掉 `axis` 指定的那一维。

**易错口径：「`arr.mean()` 遇到 NaN 怎么办？」** NumPy 默认**传播**（返回 NaN）；要跳过需显式 `np.nanmean`。而 pandas 的 `mean()` 默认**跳过**——两者相反，务必分清。

**易错口径：「`len(arr.sum(axis=1))` 等于什么？」** 等于行数（第 0 维长度），因为 `axis=1` 把第 1 维压掉了。
