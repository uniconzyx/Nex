# py-ch08 · pitfalls：numpy/pandas 高频陷阱

1. **把切片当副本改** —— `sub = a[1:3]; sub[0] = 9` 会改到原数组 `a`，因为基本切片是**视图**。要独立改就 `sub = a[1:3].copy()`。

2. **把花式索引当视图改** —— `a[[1, 2]][0] = 9` 改的是**副本**，原数组不变，且不报错。赋值必须落回原数组：`a[1] = 9`。

3. **用 `and` / `or` 连接布尔条件** —— `a > 0 and a < 5` 会对数组做真值测试并抛 `ValueError`。正确写法 `(a > 0) & (a < 5)`，两个条件都要加括号。

4. **忘记 `keepdims` 导致广播失败** —— `a - a.mean(axis=1)` 形状是 `(3,4)` 与 `(3,)`，直接报错。改成 `a - a.mean(axis=1, keepdims=True)`。

5. **广播前不估内存** —— `x[:, None] * x[None, :]` 在 `len(x)=100000` 时要 10^10 个元素，直接 OOM。大形状先算元素数，必要时分块。

6. **`reshape` 一定返回视图的误判** —— 转置后内存不连续，`a.T.reshape(-1)` 会**静默拷贝**。用 `np.shares_memory` 或看 `arr.base` 实证。

7. **`np.ptp(a)` 与 `a.ptp()` 混用** —— NumPy 2.0 起已移除 `ndarray.ptp()` **方法**，只能写函数形式 `np.ptp(a)`，老代码必须改。

8. **NaN 的传播与跳过混为一谈** —— `np.mean([1, nan, 3])` 返回 `nan`（传播）；pandas 的 `df.mean()` **默认跳过** NaN。跨库换用时结果不同，务必显式 `np.nanmean`。

9. **`argmax` 在含 NaN 数组上取值** —— `np.argmax` 遇到 NaN 的行为不可靠（NaN 比较恒为 False）。要拿位置用 `np.nanargmax`。

10. **链式赋值静默失效** —— `df[df.a > 0]["b"] = 1` 改的是中间副本，原表不变。正确写法 `df.loc[df.a > 0, "b"] = 1`（单次 `loc`）。

11. **pandas 相加是「按标签对齐」而非「按位置」** —— 两个索引不同的 Series 相加会取索引**并集**并补 `NaN`，结果比预期长。要按位置需 `.to_numpy()`。

12. **`loc` 切片端点是闭区间** —— `df.loc["b":"d"]` **含** `d`，而 `df.iloc[1:3]` **不含**位置 3。两套切片规则混用是高频 bug。

13. **CSV 的 dtype 推断毁掉前导零** —— `read_csv` 把 `"007"` 读成整数 `7`。编号、电话、身份证号必须显式 `dtype=str`。

14. **`groupby` 默认丢弃 NaN 分组键** —— 含 NaN 键的行会被静默丢掉。要保留必须 `dropna=False`。

15. **pandas `std` 与 numpy `std` 分母不同** —— pandas 默认样本标准差（`ddof=1`），numpy 默认总体标准差（`ddof=0`），小样本下数字对不上。

16. **`inplace=True` 的误解** —— 它并不省内存，且新版 pandas 已逐步弃用。统一用重新赋值 `df = df.dropna()`。

17. **`np.vectorize` 被当成性能手段** —— 它只是语法糖，底层仍逐元素调用 Python 函数，速度与显式循环同级。要性能请真正向量化。

18. **在循环里反复创建大数组** —— `acc = acc + x[i]` 每次迭代都新分配内存，峰值内存是数据量的数倍。用 `acc += x[i]`（原地）或直接 `x.sum()`。
