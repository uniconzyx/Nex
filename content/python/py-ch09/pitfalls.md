# py-ch09 · 面向对象：类、继承与魔术方法 · 常见错误

1. **可变默认参数 / 可变类属性** —— 错在：`class Foo: items = []` 或 `def f(x, acc=[])`，然后往里 append。

   *为什么*：类属性与函数默认值都在**定义时只求值一次**，所有实例/所有调用共享同一个对象。表现出来就是「第二次调用时里面还有上次的数据」，而这在单元测试里常常因为用例顺序不同而时好时坏。

   *怎么改*：类里改成在 `__init__` 中 `self.items = []`；函数里用 `def f(x, acc=None)` 再 `if acc is None: acc = []`。

2. **`super()` 用错对象** —— 错在：多继承链里写成 `Base.__init__(self)` 直接调父类，或者子类 `__init__` 忘了调 `super()`。

   *为什么*：直接点名父类会绕过 MRO，导致链上其他 mixin 的初始化被跳过；忘了调用则父类状态根本没初始化，属性访问时 AttributeError。在多继承里这两种错都不会在定义时报，只在运行时某个路径上炸。

   *怎么改*：一律写 `super().__init__(*args, **kwargs)`，让 Python 按实际 MRO 走；每个参与协作的类都要接受并透传 `**kwargs`。

3. **`__eq__` 返回 False 而不是 NotImplemented** —— 错在：`def __eq__(self, other): return self.x == other.x`，没有先判断类型。

   *为什么*：传入不同类型时 `other.x` 可能不存在（AttributeError），或者返回 False 阻断了对方更精确的比较。表现为 `a == b` 与 `b == a` 结果不一致，或者排序/去重出现莫名其妙的错误。

   *怎么改*：先 `if not isinstance(other, type(self)): return NotImplemented`，再比较字段。需要跨类型比较时显式写出对方的处理分支。

4. **重写 `__eq__` 后忘了 `__hash__`** —— 错在：定义了 `__eq__`，然后把对象放进 `set` 或当 dict 键，发现「明明放进去了却取不到」。

   *为什么*：定义 `__eq__` 时 Python 自动把 `__hash__` 设为 `None`，对象变成不可 hash，`set` 会直接抛 `TypeError: unhashable type`。更隐蔽的情况是手动实现了一个错误的 `__hash__`（比如 hash 了可变字段），导致对象改了之后再也找不到。

   *怎么改*：要可 hash 就显式实现 `__hash__`，且只 hash 不可变字段；或者直接用 `@dataclass(frozen=True)` 让它自动生成正确的 `__eq__` 与 `__hash__`。

5. **以为重写 `__new__` 返回什么就得到什么** —— 错在：`def __new__(cls): return 42`，期望 `Obj()` 得到 42，但后续 `obj.attr` 全部失败。

   *为什么*：`__new__` 返回非本类实例时，`__init__` 不会被调用；而且返回的对象类型就是 `int`，没有你定义的任何属性。「单例」写法里如果缓存对象写错，会出现「第二次拿到的是个半初始化对象」。这条规则的边界是：只有当 `__new__` 返回 `cls` 或其子类的实例时，才会继续执行 `__init__`。

   *怎么改*：需要工厂语义时用 `@classmethod` 返回实例，不要重写 `__new__`；确实要重写（单例、不可变子类）时，保证返回类型与 `cls` 一致。

6. **往实例上挂魔术方法，期望生效** —— 错在：`obj.__len__ = lambda: 5`，然后 `len(obj)` 还是旧值。

   *为什么*：解释器对特殊方法走 `type(obj).__len__(obj)`，在**类型层面**查找，显式跳过实例字典。普通方法能被实例属性遮蔽，魔术方法不能。这条规则导致「同一个 mock 技巧有的生效有的不生效」——普通方法打实例有效，魔术方法必须打类。

   *怎么改*：改行为就改类：`Sneaky.__len__ = lambda self: 99`，或用 `mock.patch.object(cls, "__len__")`。别指望往实例上塞。

7. **`isinstance` 判父类时用 `type() ==`** —— 错在：`if type(x) == Animal:` 来判断「是不是动物」。

   *为什么*：`type()` 返回精确类型，子类实例一律不通过，于是 `Dog(Animal)` 被判定为「不是动物」。反过来，用 `type(x) == Animal` 做分发时，任何子类都会走到「都不匹配」的分支，表现为「新增子类后功能静默失效」——不报错，只是没生效。

   *怎么改*：用 `isinstance(x, Animal)`，它会沿 MRO 检查。需要「精确类型」时才用 `type(x) is Animal`，并且要写清为什么排除子类（比如序列化时的严格类型校验）。

8. **`@property` 上写 `@staticmethod` 或顺序写反** —— 错在：`@staticmethod` 套在 `@property` 外面，或者 `@property` 与 `@x.setter` 名字不一致。

   *为什么*：装饰器顺序决定最终对象类型——`@property` 必须是最外层（最靠近函数的是 `@staticmethod` 就先变成静态方法，再包成 property 行为不对）。`setter` 名字不一致（`@y.setter def x(self)`）不会报错，只会让 setter 静默失效，赋值时直接覆盖了 property 对象。

   *怎么改*：顺序固定为 `@property` 在最外层；`@<同名>.setter` 的函数名必须和 property 名一致。写完用 `c.area = 1` 实测一次，别只读不写。

9. **在 `__init__` 里做重活或抛异常** —— 错在：`__init__` 里读文件、连数据库、校验失败就 `raise`，然后对象构造一半被丢弃。

   *为什么*：构造器里做 I/O 让单测必须准备真实环境；抛异常时对象已经分配（`__new__` 成功），只是引用被丢掉，若有副作用（已开的文件句柄、已注册的回调）就泄漏。更难查的是：如果子类 `__init__` 抛异常，父类已经完成的初始化不会回滚。

   *怎么改*：`__init__` 只做「把参数挂到 self 上」这类无副作用的事；校验与 I/O 放到 `classmethod` 工厂（`from_file`）或显式的 `load()` 方法里。这样构造失败是明确的、可测的。

10. **多继承里把「有状态的类」当 mixin** —— 错在：写了 `class CacheMixin: self._cache = {}` 这种带状态的 mixin，然后多重继承。

    *为什么*：带状态的 mixin 会与其他类争抢 `__init__` 的调用顺序与同名属性。C3 保证 MRO 唯一，但保证不了「谁先设 `self._cache`」这件事符合你的预期——尤其当另一个父类也有 `_cache` 时，静默覆盖。

    *怎么改*：mixin 只提供行为、不持有状态（不定义 `__init__`）；需要状态时用组合：`self.cache = Cache()`。判据是「这个能力能不能在没有实例状态的情况下实现」，能才做成 mixin。


11. **定义了 `__eq__` 却忘了 `__hash__`** —— 错在：自定义相等比较后，对象放进 `set` 或当 `dict` 键时报 `TypeError: unhashable type`。

   *为什么*：Python 一旦发现类定义了 `__eq__` 且没定义 `__hash__`，会把 `__hash__` 置为 `None`。因为「相等对象必须有相同哈希」这个不变量无法自动保证，干脆禁止哈希。

   *怎么改*：同时定义 `__hash__`，且必须基于**与 `__eq__` 相同的字段**：`def __hash__(self): return hash((self.x, self.y))`。两者字段不一致会让 `set` 出现重复元素。

12. **把可变对象当类属性** —— 错在：`class A: items = []`，然后 `self.items.append(x)`，所有实例共享同一个列表。

   *为什么*：类属性在类定义时创建一次，实例通过属性查找拿到的是同一个对象。任何实例的修改都会影响其他实例。

   *怎么改*：类属性只放不可变值（常量、方法）；一切可变对象都在 `__init__` 里创建为实例属性。

13. **`super()` 当成「调用父类」** —— 错在：多继承里以为 `super()` 一定调到父类，实际调到的是 MRO 里的下一个类，可能是兄弟类。

   *为什么*：`super()` 返回的是沿 MRO 从当前类之后开始的代理，不是「父类指针」。`class Child(Left, Right)` 时 `Left` 里的 `super()` 会调到 `Right`。

   *怎么改*：把 `super()` 理解为「协作链的下一环」，所有参与类都用协作式写法（调 `super().__init__()`）；排查时先打印 `cls.__mro__`。

14. **`__getattr__` 里访问 `self.xxx` 导致无限递归** —— 错在：在 `__getattr__` 中读另一个可能不存在的属性，触发再次进入 `__getattr__`。

   *为什么*：`__getattr__` 只在常规查找失败后调用，如果它内部又访问一个不存在的属性，就再次失败、再次调用，直到递归溢出。

   *怎么改*：内部改用 `object.__getattribute__(self, name)` 或 `super().__setattr__` 绕过钩子；并确保未命中时抛 `AttributeError` 而不是返回 `None`。

15. **给需要动态属性的类加 `__slots__`** —— 错在：为了省内存给类加了 `__slots__`，之后插件往实例上挂字段（或某些库做缓存标记）时报 `AttributeError`。

   *为什么*：`__slots__` 移除了实例的 `__dict__`，属性只能存在固定的槽位里，任何动态添加都被禁止。

   *怎么改*：只在「实例数量极大且字段完全固定」的场景用（如百万级数据点）；普通业务类不加，灵活性更重要。需要两者兼得时，`__slots__` 里加 `"__dict__"` 保留动态能力。
