# 凯喵实战手记：Python 基础里那些「看起来会、一写就翻车」的现场

> 这一章我们不讲语法表，而是跟着凯喵钻进几个真实踩坑现场。你会发现 Python 的「动态」「鸭子」「一切皆对象」三句话，落到代码里全是坑。把这 12 个现场刻进手感，比背一百行语法都管用。

### 1. 动态类型不是「不用声明」，是「运行到才认类型」

凯喵刚学 Python 时写过这样一个函数，以为和 Java 一样安全：

```python
def add(a, b):
    return a + b

add(1, 2)        # 3
add("a", "b")    # "ab"
add(1, "b")      # TypeError
```

`+` 的含义由**运行时的实际对象类型**决定，不是由你写的变量名决定。`a` 这个变量名本身不带任何类型信息。所以「类型错误」不会在写代码时拦你，只会在调用那一刻炸。修法：关键接口用 `typing` 注解 + `mypy` 静态检查，把「运行时才发现的错」提前到「提交前」。

### 2. 可变默认参数的「共享幽灵」

这是 Python 面试和线上事故第一名。凯喵曾在一次批量任务里，所有用户共享了同一份配置列表：

```python
def load_user(name, tags=[]):
    tags.append(name)
    return tags

load_user("alice")   # ['alice']
load_user("bob")     # ['alice', 'bob']  ← 不是你想要的！
```

默认参数对象在**函数定义时**就创建好了，之后每次调用都复用同一个 `[]`。修法：默认参数永远用 `None`，函数体内新建：`tags = tags or []`。

### 3. 闭包捕获的是变量，不是那一刻的值

凯喵写循环注册回调时，九次得到同一个结果：

```python
callbacks = []
for i in range(3):
    callbacks.append(lambda: i)
[cb() for cb in callbacks]   # [2, 2, 2]，不是 [0, 1, 2]
```

`lambda` 里引用的 `i` 是外层循环变量，循环结束时 `i=2`，三个闭包都看到同一个最终值。修法：用默认参数把「当时的值」钉住：`lambda i=i: i`。

### 4. `==` 和 `is` 的边界：小整数池与驻留

凯喵第一次看到下面这段，以为 Python 有 bug：

```python
a = 256; b = 256
a is b        # True
x = 257; y = 257
x is y        # False（CPython 实现相关，别依赖）
```

CPython 把 `-5..256` 的小整数和短的字符串做了**驻留（intern）**，所以 `is` 返回 True 只是实现巧合。语义上永远用 `==` 比较值，`is` 只用于和单例（`None`、`True`、`False`）比较。

### 5. 深浅拷贝：你改的到底是「同一份」还是「副本」

凯喵做配置合并时，改了副本却影响了原配置：

```python
import copy
a = {"cfg": [1, 2, 3]}
b = a.copy()            # 浅拷贝：顶层是新的，但嵌套列表还是同一份
b["cfg"].append(4)
a["cfg"]                # [1, 2, 3, 4] ← 被改到了
c = copy.deepcopy(a)    # 深拷贝：连嵌套也新建
```

浅拷贝只复制一层引用。嵌套结构要 `copy.deepcopy`。

### 6. 可变对象不能当字典键

凯喵用列表当缓存键，直接报错：

```python
cache = {}
cache[[1, 2]] = "x"    # TypeError: unhashable type: 'list'
```

字典键要求**可哈希**，即可变对象（list、dict、set）都不行。用元组 `tuple([1, 2])` 或冻结集合。配合第 15 条的 `__eq__/__hash__` 规则一起看。

### 7. `for...else` 不是「如果没进循环」而是「循环没 break」

凯喵找元素时写过反逻辑：

```python
for item in items:
    if item.ok:
        break
else:
    print("没找到")   # 只有「一次都没 break」才执行
```

`else` 子句在循环**正常结束（未被 break）**时执行，是「找遍了没找到」的优雅写法，不是「循环体为空」的意思。

### 8. 生成器一次遍历即耗尽

凯喵把生成器当列表反复用，第二次全空：

```python
g = (x*x for x in range(3))
list(g)   # [0, 1, 4]
list(g)   # []  ← 已经消费完了
```

生成器是「惰性、一次性」的。需要多次遍历就 `list(g)` 落盘，或每次重新构造。

### 9. 解包与 `*`：多余元素去哪了

凯喵解析日志行时靠解包省了不少代码：

```python
first, *middle, last = [1, 2, 3, 4, 5]
# first=1, middle=[2,3,4], last=5
```

`*var` 收集「其余所有」，必须是可迭代的。「解包目标元素数不匹配」会直接 `ValueError`，所以解包前先确认长度，或用 `*_` 吃掉不要的部分。

### 10. 字符串是不可变的，拼接要算代价

凯喵早年用 `+=` 在循环里拼十万行日志，慢到怀疑人生：

```python
s = ""
for line in big:
    s += line        # 每次都新建字符串对象，O(n²)
# 正确：parts = []; parts.append(line); "".join(parts)
```

字符串不可变，`+=` 在循环里反复分配新对象。大量拼接用列表 `append` 再 `"".join()`，或直接用 `io.StringIO`。

### 11. `del` 只是解绑，不保证立刻回收

凯喵以为 `del obj` 会马上释放内存：

```python
del big_list
# 只是把名字 big_list 从命名空间移除；若还有别的引用，对象不会回收
```

`del` 删的是**名字到对象的绑定**，引用计数归零后才会回收。循环引用要靠 GC 兜底。真正控制生命周期的是「让引用消失」，而不是 `del` 这个动作。

### 12. 异常不是流程控制，但别裸 `except:`

凯喵见过最危险的代码是：

```python
try:
    do()
except:          # 吃掉一切，包括 KeyboardInterrupt、SystemExit
    pass
```

裸 `except:` 会捕获包括 `KeyboardInterrupt` 在内的所有异常，导致你 `Ctrl+C` 都停不下来程序。至少写 `except Exception:`，并按异常类型分别处理；预期之外的异常让它冒泡出来。

> 凯喵总结：Python 基础的坑九成在「动态类型的运行时才炸」「可变默认参数」「闭包捕获变量」「浅拷贝」「可变对象当键」。把这 12 个现场刻进肌肉记忆，入门阶段能少踩无数坑，比任何高级特性都值得先练熟。

> 现场之外：写 Python 最稳的习惯是「小函数、显式类型注解、不可变优先」。能用元组就不用列表当数据载体，能 `deepcopy` 就别赌浅拷贝，能 `==` 就别手滑敲成 `is`。把基础当规律而不是约定，你会比很多写了几年的人都稳。

> 一句话收尾：Python 给你自由，也把「正确性」的责任还给了你——好用的前提是真懂它每一步在运行时做了什么。

### 凯喵复盘：把 12 个现场连成一条直觉

这 12 个坑表面零散，其实有一条主线：**Python 把「类型安全」和「生命周期」的责任从编译器手里交还给了你**。动态类型意味着类型错误推迟到运行时；可变默认参数和闭包捕获变量，是因为「对象身份」比「名字」更根本；浅拷贝、`+=`、生成器耗尽，本质都是「同一份数据被几处共享」的问题。所以写 Python 最稳的心法不是记清单，而是**默认一切皆对象、一切皆引用、能不可变就不可变**。把这条主线刻进手感，上面 12 个现场会自然归位，而不是变成需要死背的孤立陷阱。最后送一句口诀：**对象身份优先于名字，不可变优先于可变**——这两句话能替你拦掉上面大半的坑，也比任何速查表都经用。
