# 03 · 内建容器与推导式

四种常用容器：

- `list` 有序可变：`[1, 2, 3]`，支持切片、append、推导式
- `tuple` 有序不可变：`(1, 2)`，适合异构固定结构
- `dict` 键值映射：`{"a": 1}`，键须可哈希
- `set` 无序去重：`{1, 2}`，集合运算

选容器的判据不是"哪个用得熟"，而是**访问模式**：按下标随机访问选 `list`，按键查找选 `dict`，只要去重与集合运算选 `set`，需要不可变/可哈希选 `tuple`。

## 一、复杂度速查

| 操作 | `list` | `dict` | `set` | `tuple` |
|---|---|---|---|---|
| 按下标访问 | O(1) | — | — | O(1) |
| 按值/键查找 | O(n) | O(1) 均摊 | O(1) 均摊 | O(n) |
| 尾部追加 | O(1) 均摊 | O(1) 均摊 | O(1) 均摊 | — |
| 头部插入/删除 | O(n) | — | — | — |
| 删除指定元素 | O(n) | O(1) | O(1) | — |
| 是否有序 | 是 | 是（3.7+） | 否 | 是 |
| 可哈希（能当 dict 键） | 否 | 否 | `frozenset` 可以 | 元素都可哈希时 |

这张表解释了最常见的性能问题：**`if x in list` 写在循环里**就是 O(n²)。判断"在不在"用 `set`。

## 二、`list`：动态指针数组

`list` 底层是**一维的 `PyObject*` 数组**（不是链表），因此：

- `a[i]` 是 O(1)（指针数组索引）。
- `append` 均摊 O(1)：容量不足时按约 **1.125 倍**（`n + n>>3`）扩容，而不是 2 倍。
- `insert(0, x)` 与 `pop(0)` 是 O(n)：要搬移整个数组。
- 元素存的是**引用**，不是值本身——所以一个列表可以混合类型，也所以浅拷贝共享内层对象。

```text
list 的内存结构（ob_item 数组）

  list ─► [ size=3 | allocated=4 ]
              │
              ▼
         ┌────┬────┬────┬────┐
         │ *  │ *  │ *  │ 空 │   元素是指针，指向真正的对象
         └─┼──┴─┼──┴─┼──┴────┘
           ▼    ▼    ▼
          1    "a"  [2]       各自的 Python 对象
```

### 切片语义：左闭右开、支持负索引、返回新对象

```python
xs = [0, 1, 2, 3, 4]
xs[1:3]      # [1, 2]
xs[-2:]      # [3, 4]
xs[::-1]     # [4, 3, 2, 1, 0]  反转（返回新列表）
xs[::2]      # [0, 2, 4]
xs[1:3] = [9]  # 切片赋值可以改变长度：[0, 9, 3, 4]
```

切片**永远是浅拷贝**：`xs[:]` 复制了外层指针数组，内层对象仍共享。

## 三、`tuple`：不只是"不可变的列表"

`tuple` 的两个额外能力来自不可变性：

1. **可哈希**（当元素都可哈希时），因此能当 `dict` 的键、`set` 的元素。`list` 不行。
2. **可作为"记录"使用**：位置即字段，适合异构数据 `("Alice", 30, "Beijing")`。

```python
point = (3, 4)
cache = {point: "origin-ish"}     # tuple 当键
x, y = point                      # 解包
```

注意**"不可变"是浅的**：`t = ([1], 2); t[0].append(3)` 合法，因为改的是元组里那个列表对象，不是元组本身。这也意味着含可变元素的 tuple **不可哈希**。

需要"带字段名的 tuple"时用 `collections.namedtuple` 或 `typing.NamedTuple`；需要可变版本用 `dataclasses.dataclass`。

## 四、`dict`：哈希表，且保证插入顺序

```python
d = {"a": 1, "b": 2}
d["c"] = 3            # 插入
d.get("z")            # None，不抛异常
d.get("z", 0)         # 默认值
d.setdefault("a", 99) # 键存在则返回原值，不存在则插入
"a" in d              # O(1) 判断键
d.keys() / d.values() / d.items()
```

三条机制性事实：

- **键必须可哈希**：`int`/`str`/`tuple`/`frozenset` 可以，`list`/`dict`/`set` 不行。自定义类默认按 `id` 哈希，要按值相等必须同时实现 `__hash__` 与 `__eq__`。
- **3.7 起保序是语言保证**（3.6 是实现细节）。这是个"优化结果被提升为规范"的案例。
- **紧凑表示**：3.6 起用"稀疏索引表 + 密集 entries 数组"，内存比旧实现省 20~25%，也正是保序的来源（entries 按插入顺序追加）。

高频配套工具（都在 `collections` 里）：

- `defaultdict(list)`：免去 `if k not in d: d[k] = []`。
- `Counter(seq)`：计数，支持 `most_common(n)`。
- `OrderedDict`：现在主要为了 `move_to_end` 与"顺序敏感相等"语义。

## 五、`set`：哈希集合与集合运算

```python
a = {1, 2, 3}
b = {3, 4}
a | b     # 并集 {1,2,3,4}
a & b     # 交集 {3}
a - b     # 差集 {1,2}
a ^ b     # 对称差 {1,2,4}
a <= b    # 子集判断
```

`set` 无序、元素必须可哈希、支持 O(1) 成员判断。要去重又保序，用 `dict.fromkeys(seq)`（3.7+ 保序）：

```python
list(dict.fromkeys([3, 1, 3, 2]))   # [3, 1, 2]
```

## 六、推导式：快，但要克制

```python
sq = [x * x for x in range(1, 4)]           # 列表推导
evens = {x for x in range(10) if x % 2 == 0} # 集合推导
pairs = {k: v for k, v in zip("ab", [1, 2])} # 字典推导
gen = (x * x for x in range(10**6))          # 生成器表达式，惰性
```

### 为什么列表推导比 `for + append` 快

不是"语法糖"层面的优化，而是字节码层面的：推导式被编译成**独立代码对象**，在循环内直接用 `LIST_APPEND` 指令追加，省掉了每次迭代的 `LOAD_METHOD`/`CALL`（属性查找 + 函数调用）。实测通常快 20~40%。

生成器表达式则连列表都不建，逐个 `yield`，适合"只需消费一次"的大数据流，但**不能重复遍历**。

### 可读性边界

两层嵌套是上限：

```python
flat = [x for row in matrix for x in row]         # 可读
weird = [x for row in matrix for x in row if x if x > 0]   # 别这么写
```

超过两层就写普通循环，或者拆成两步。推导式的目的是**让"从序列构造序列"这件事一眼可见**，不是压缩行数。

## 七、边界与陷阱

- **`if x in list` 在循环里**：O(n²)，改用 `set`。
- **切片是浅拷贝**：嵌套结构仍共享。
- **`list.copy()` 不等于深拷贝**：需要 `copy.deepcopy`。
- **`dict` 键必须可哈希**：`d[[1]] = 1` 抛 `TypeError`。
- **遍历 `dict` 时改它**：抛 `RuntimeError`。要改先 `list(d.items())`。
- **`set` 无序**：`{3,1,2}` 打印顺序不保证，别写依赖顺序的测试。
- **自定义类当 `dict` 键**：默认按 `id` 哈希，两个"值相同"的实例会是不同键；必须实现 `__hash__` + `__eq__`（或直接用 `dataclass(frozen=True)`）。
- **`sort()` vs `sorted()`**：前者原地返回 `None`，`y = xs.sort()` 会让 `y` 变成 `None`。
- **可变对象不能当默认参数**：`def f(x={})` 会在所有调用间共享。

## 八、可运行示例：哈希、保序与复杂度差异

```python
from collections import Counter, defaultdict

xs = [3, 1, 3, 2]
print("uniq_ordered:", list(dict.fromkeys(xs)))     # [3, 1, 2] 去重且保序
print("set:", sorted(set(xs)))                      # [1, 2, 3]

d = {"b": 2, "a": 1}
d["c"] = 3
print("insert_order:", list(d))                     # ['b', 'a', 'c'] 插入顺序

dd = defaultdict(list)
for k, v in [("x", 1), ("x", 2), ("y", 3)]:
    dd[k].append(v)
print("defaultdict:", dict(dd))                     # {'x': [1, 2], 'y': [3]}

print("counter:", Counter("aabbbc").most_common(2)) # [('b', 3), ('a', 2)]

square = {x: x * x for x in range(3)}
print("dict_comp:", square)

gen = (x * x for x in range(3))
print("gen_once:", list(gen), list(gen))            # [0,1,4] [] 生成器一次性

t = ([1], 2)
t[0].append(3)
print("tuple_shallow:", t)                          # ([1, 3], 2)
```

最后一行是"元组不可变是浅的"实证：元组本身没变（还是那两个引用），但它指向的列表被改了。

## 三视角解析

### 🧑‍💻 程序员视角
- 推导式比显式 `for + append` 更快（少了属性查找与函数调用开销），可读性也更好；但**嵌套超过两层就该退回循环**，否则可读性崩坏。
- 大数据集用**生成器表达式**（`(... for ...)`）而非列表推导式，能省下整份内存。
- `dict` 在 3.7+ **保序是语言保证**（此前只是 CPython 实现巧合）；`set` 无序且不能按下标取。
- 判据化选容器：查成员用 `set`、查键值用 `dict`、按下标用 `list`、要当键用 `tuple`。

### 🎓 博士生视角
- 列表推导式会被编译成**独立的代码对象**（有自己的作用域与局部变量表），并走专用字节码（`LIST_APPEND`），避免了每次迭代的函数调用与属性查找——这是它快的根本原因，而非「语法糖」。
- `list` 是**动态指针数组**：元素是 `PyObject*` 引用而非值本身，扩容采用约 `n + n>>3` 的过度分配策略（**不是 2 倍**），从而让 `append` 均摊 O(1)。
- `dict` 自 3.6 起采用**紧凑表示**（稀疏的 `indices` 表 + 密集的 `entries` 数组），既省内存又让插入顺序天然可迭代——「保序」是实现优化的副产品被提升为语言保证。
- 哈希表的最坏情况是 O(n)（所有键冲突到同一桶），Python 用扰动函数（`hash` 与自身高位异或）缓解，但仍不抗哈希碰撞攻击；`dict` 会随机化字符串哈希（`PYTHONHASHSEED`）来防 DoS。
- 可哈希的充要条件是**不可变且相等对象哈希相等**（`a == b` 推出 `hash(a) == hash(b)`）。自定义类若重写了 `__eq__` 而不重写 `__hash__`，Python 会把 `__hash__` 置为 `None`，使其不可哈希——这是刻意的防线。

### 📚 考研者视角
- 与 408 的**顺序存储、哈希表**直接对应：`list` ↔ 顺序表（随机访问 O(1)、中间插入 O(n)）；`dict`/`set` ↔ 哈希表（关注装填因子与冲突处理）。
- 常见考法：给定哈希函数与关键字序列，手算装填因子与平均查找长度（ASL）；与 Python 对照能加深理解。
- 常考辨析：`list`（顺序表，按下标）vs `set`（哈希，按值）在成员判断上的复杂度差异；顺序表插入/删除的平均移动次数。
- 记忆锚点：**list 扩容约 1.125 倍（不是 2 倍）**；**dict 保序是 3.7+ 的语言保证**；**`in list` 是 O(n)、`in set` 是 O(1)**。
