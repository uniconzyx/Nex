# 01 · 变量与动态类型

Python 是**动态强类型**语言：变量无需声明类型（动态），但运算不会偷偷做危险隐式转换（强类型）。变量本质是一个"名字"，绑定到对象；对象本身有类型且分**可变 / 不可变**。

"变量是标签，不是盒子"这句话被引用得太滥，但它是理解 Python 全部对象语义的钥匙：赋值不复制数据，只把名字贴到另一个对象上。

## 一、名字与对象：绑定而不是装箱

```python
a = 1        # a 绑定到整数对象 1
b = a        # b 也绑定到同一个对象
a = a + 1    # 重新绑定 a 到新对象 2，b 不受影响
print(a, b)  # 2 1
```

`a = a + 1` 做了三件事：读出 `a` 指向的对象、计算 `a + 1` 得到**新对象**、把 `a` 重新绑定到新对象。原来的对象 1 仍然被 `b` 指着，所以不被回收。

对比 C：`int a = 1; int b = a; a = a + 1;` 里 `a` 和 `b` 是两个独立的内存单元，从创建起就互不相干。Python 里"独立"是**通过重新绑定**得到的，不是通过分配单元。

```text
名字 → 对象（CPython 的对象头）

  a ──┐
      ├──► [ ob_refcnt=2 | ob_type=int | 值=1 ]   ← 同一个对象
  b ──┘

  a = a + 1 之后
  a ──────► [ refcnt=1 | int | 值=2 ]   ← 新对象
  b ──────► [ refcnt=1 | int | 值=1 ]   ← 老对象仍被 b 引用
```

### 对象头里的两个关键字段

CPython 中每个对象都以 `PyObject` 开头：**引用计数 `ob_refcnt`** 与 **类型指针 `ob_type`**。

- **类型属于对象，不属于名字**——这是"动态类型"的形式化表述。同一个名字先后可以指向 `int`、`str`、`list`，因为类型信息挂在对象上。
- **引用计数是即时回收**：`refcnt` 归零立即释放。`sys.getrefcount(x)` 能读到它，但调用本身会 +1，所以返回值总是比"实际引用数"多 1。

## 二、可变与不可变：唯一需要背的分类

| 类型 | 可变性 |
|---|---|
| `int`、`float`、`bool`、`complex` | 不可变 |
| `str`、`bytes`、`tuple`、`frozenset` | 不可变 |
| `list`、`dict`、`set`、`bytearray` | 可变 |

不可变对象的所有"修改"操作，实际都是**创建新对象 + 重新绑定**：

```python
s = "abc"
s2 = s
s += "d"        # 创建新字符串 "abcd"，s 重新绑定
print(s2)       # "abc" —— 原对象没变
```

可变对象则原地修改，所有指向它的名字都会看到变化：

```python
xs = [1, 2]
ys = xs      # ys 与 xs 指向同一列表
xs.append(3) # 原地修改，ys 可见
print(ys)    # [1, 2, 3]
```

这条区别的直接后果是**默认参数陷阱**：

```python
def bad(x=[]):      # 默认值在函数定义时创建一次，被所有调用共享
    x.append(1)
    return x
bad(), bad()        # ([1, 1], [1, 1]) —— 不是 ([1], [1])

def good(x=None):
    x = [] if x is None else x
    return x
```

## 三、`is` 与 `==`：身份 vs 值

- `==` 调用 `__eq__`，比较**值**（可以自定义）。
- `is` 比较 `id()`，即**是不是同一个对象**。

```python
a = [1, 2]
b = [1, 2]
a == b      # True（值相同）
a is b      # False（不同对象）

c = a
a is c      # True（同一对象）
```

三个"看起来能用"的例外，全部不可依赖：

1. **小整数缓存**：CPython 预创建 −5~256 的整数对象，所以 `a = 256; b = 256; a is b` 为 True，但 257 就可能为 False。
2. **字符串驻留（interning）**：形如标识符的短字符串会被复用，运行期拼接出来的通常不会。
3. **`None` / `True` / `False` 是单例**：`x is None` 永远正确且是推荐写法。

工程规则：**只有 `None` 用 `is`，其余比值用 `==`**。

## 四、作用域：LEGB 与 `global` / `nonlocal`

名字查找顺序是 **Local → Enclosing → Global → Built-in**。赋值语句会让名字**默认成为局部变量**，这导致一个经典困惑：

```python
count = 0
def inc():
    count += 1     # UnboundLocalError：因为有赋值，count 被视为局部变量
```

想改外层要用 `global`（模块级）或 `nonlocal`（闭包外层函数）。这也是"为什么 `list.append` 能改全局列表却不用 `global`"的答案——`append` 是**修改对象**而不是**重新绑定名字**。

## 五、类型注解：提示，不强制

```python
def greet(name: str) -> str:
    return "Hi " + name

greet(42)      # 运行期不报错（会在拼接时因类型不符而 TypeError，但不是注解拦下的）
```

注解在运行期只是 `__annotations__` 里的字典，**解释器不校验**。要做运行时校验得用 `pydantic`、`beartype`、`typeguard` 等库；要做静态检查用 `mypy` / `pyright`。注解的价值在于工具链与可读性，而不是运行时安全。

## 六、边界与陷阱

- **可变默认参数**：见上，用 `None` 哨兵。
- **浅拷贝不是深拷贝**：`xs.copy()` / `xs[:]` 只复制外层，嵌套列表仍共享；要深拷贝用 `copy.deepcopy`。
- **`is` 判断值**：小整数与驻留字符串会让它"偶尔对"，掩盖 bug。
- **`+=` 对可变对象是原地操作**：`xs += [1]` 等价 `extend`，会改到所有别名；`xs = xs + [1]` 才创建新列表。
- **元组"不可变"是浅的**：`t = ([1], 2); t[0].append(3)` 合法，因为改的是内部列表。
- **循环引用无法靠引用计数回收**：需要 `gc` 模块的分代回收兜底；诊断泄漏用 `gc.get_objects`、`tracemalloc`。

## 七、可运行示例：别名、缓存与浅拷贝

```python
import copy
import sys

a = [1, 2]
b = a
b.append(3)
print("alias:", a, b, a is b)          # [1,2,3] [1,2,3] True

x = 256
y = 256
print("small int cached:", x is y)     # True（实现细节，别依赖）

nested = [[1], [2]]
shallow = nested.copy()
deep = copy.deepcopy(nested)
nested[0].append(99)
print("shallow:", shallow)             # [[1, 99], [2]] —— 内层共享
print("deep:", deep)                   # [[1], [2]]      —— 完全独立

print("refcnt:", sys.getrefcount(a))   # 比实际引用数多 1（参数本身占一个）
```

`shallow` 与 `deep` 的对比是本章的核心：浅拷贝只复制了"外层列表的指针数组"，内层列表还是同一批对象。

## 三视角解析

### 🧑‍💻 程序员视角
- 变量是**贴在对象上的名字**，赋值是「绑定」而不是「装箱」；因此 `a = b` 之后两者指向同一对象，改其中一个共享的可变对象会互相影响。
- 判断相等用 `==`；`is` 比较的是身份（地址）。小整数缓存（−5 到 256）和字符串驻留会让 `is` 偶尔「看起来能用」，但**永远不要依赖它**。
- 类型注解（`x: int`）只是提示，运行时不强制——想做运行时校验得靠 `pydantic` / `beartype` 之类。
- 需要"独立副本"时明确说清层级：浅拷贝（`copy()`/`[:]`）还是深拷贝（`deepcopy`），别让调用方猜。

### 🎓 博士生视角
- CPython 中每个对象都有 `ob_refcnt`（引用计数）与 `ob_type`（类型指针）头部，变量只是指向 `PyObject*` 的名字绑定。**类型属于对象，不属于名字**——这就是「动态类型」的形式化表述。
- 引用计数是**即时回收**，但无法处理循环引用，因此必须有分代 GC 兜底；`sys.getrefcount` 能观察到引用计数（注意它自身会 +1）。
- 名字与对象的分离带来「同一对象多个名字」的别名语义，这与 C 的「变量即内存地址」模型根本不同；工程上这就是「可变对象默认参数」等陷阱的根源。
- 函数默认值在**定义时**求值一次并挂在 `__defaults__` 上，与调用次数无关；这与「每次调用重新求值」的直觉相反，也是 `datetime.now()` 当默认值会拿到进程启动时刻的原因。
- 小整数缓存与字符串驻留都是**实现层的性能优化**（避免频繁分配），标准只保证 `None`/`True`/`False` 是单例，其余 `is` 结果均属实现细节。

### 📚 考研者视角
- 与计组的「变量 = 存储单元的符号化地址」形成对照：C 中变量绑定的是**地址**，Python 中名字绑定的是**对象引用**。
- 若专业课含程序设计语言原理，常考「值语义 vs 引用语义」「静态类型 vs 动态类型」的分类与优劣。
- 常考辨析：可变/不可变类型在函数传参时的行为差异（Python 全部是"传对象引用"，但因可变性不同表现不同）。
- 记忆锚点：**变量是「标签」不是「盒子」**；**`==` 比值、`is` 比身份**；**默认参数在定义时求值一次**。
