# py-ch06 常见陷阱

1. **`re.match` 被当成整串匹配** —— `re.match(r"\d+", "12abc")` 返回 `Match`，你可能以为它校验通过了。**校验格式一律用 `re.fullmatch`**（或自己加 `^...$`）。

2. **`findall` 有分组时只返回分组** —— `re.findall(r"(\d)", "a1b2")` 得到 `['1','2']`；两个分组时得到**元组列表**。想拿整串匹配就别加捕获组（用 `(?:...)`），或改用 `finditer` + `m.group(0)`。

3. **替换模板没用原始字符串** —— `re.sub(p, "\1", s)` 里的 `"\1"` 会被 Python 先当八进制转义解释。**必须写 `r"\1"`**，或统一用 `r"\g<1>"`。

4. **`\12` 的歧义** —— 想表达"组 1 后面跟字面 2"时写 `r"\12"`，实际会被解析为**组 12**，导致 `re.error: invalid group reference`。**一律用 `r"\g<1>2"`**。

5. **非捕获组不占编号** —— `((\d)(?:-)(\d))` 里只有 3 个捕获组；混用 `(?:...)` 后按"看起来的第几个括号"取组必然错位。

6. **嵌套分组编号是"外层更小"** —— `((\d)(\d))` 里组 1 是整体 `12`，组 2、3 才是内层；很多人以为是内层先编号。

7. **对 `None` 直接取组** —— `re.match(...)` 失败返回 `None`，此时 `m.group(1)` 抛 `AttributeError`。正确写法：`m.group(1) if m else None`。

8. **`^` / `$` 默认只管整串首尾** —— 多行日志里想按行匹配必须加 `re.M`；同理 `.` 默认不匹配 `\n`，跨行匹配要加 `re.S`。这两个 flag 作用**互不相干**。

9. **把非贪婪当性能优化** —— 非贪婪只改变尝试**顺序**，不缩小搜索**空间**。`(a+?)+b` 在失败串上同样指数爆炸。

10. **嵌套量词引发回溯爆炸（ReDoS）** —— `(a+)+b`、`(.*)*`、`(x|y)*` 这类"可重叠的嵌套量词"在匹配失败的输入上退化为指数时间：25 个字符即可产生 1600 万次尝试。**优先把模式化简**（`(a+)+` 等价于 `a+`），其次才用占有量词 `*+` 或原子组 `(?>...)`。

11. **占有量词 / 原子组需要 Python 3.11+** —— 在 3.10 及更早版本上写 `a*+` 或 `(?>a+)` 会直接抛 `re.error`。跨版本部署时要先确认运行时版本。

12. **变长 `lookbehind` 会报错** —— Python 要求 `lookbehind` **定宽**：`(?<=\d+)` 抛 `look-behind requires fixed-width pattern`。变长回顾要改用捕获组或调整模式结构。

13. **用正则解析结构化数据** —— 拿正则去解 JSON / CSV / HTML 是**语言类别的越界**：这些格式有嵌套与转义，正则在形式上就无法正确识别。请用 `json` / `csv` / `html.parser`，正则只用于"格式松散的提取"。

14. **`re.sub` 的 `count` 语义记反** —— `count=0` 是**全部替换**（默认），不是"替换 0 次"；只想替换一处要写 `count=1`。

15. **`re.X`（verbose）模式下空白被忽略** —— 想让模式匹配一个空格，必须写 `\ ` 或 `[ ]`，否则会静默失配。

16. **用 `.` 匹配"任意字符"却遇到换行** —— `.` 默认不匹配 `\n`。解析多行块时要显式 `(?s)` 或 `re.S`，否则 `<div>...</div>` 跨行就抓不到。

17. **模式里动态拼接用户输入未转义** —— 用户填的 `.` `*` `(` 会变成元字符，造成误匹配甚至 ReDoS。**拼接前一律 `re.escape(user_input)`**。

18. **用正则做日期合法性校验** —— `\d{4}-\d{2}-\d{2}` 会放过 `2026-13-45`。格式正确 ≠ 合法，日期请用 `datetime.strptime` 校验。
