# 04 · sub 替换、文本清洗与"正则 vs 解析库"的边界

替换是正则最常用的落地场景，但也是最容易被滥用的地方。

## 4.1 `re.sub` 的三种替换形态

| 形态 | 示例 | 说明 |
|---|---|---|
| **字符串 + 反向引用** | `re.sub(r"(\w+)@(\w+)", r"\2@\1", s)` | 模板里用 `\1` / `\g<1>` |
| **函数** | `re.sub(r"\d+", lambda m: str(int(m.group()) * 2), s)` | 可做任意逻辑（加减、查表、格式化） |
| **带 `count`** | `re.sub(p, r, s, count=1)` | 只替换前 N 个 |

```python
import re
print(re.sub(r"(\w+)\s+(\w+)", r"\2 \1", "world hello"))       # 字符串模板
print(re.sub(r"\d+", lambda m: str(int(m.group()) * 2), "a1b22"))  # 函数
print(re.sub(r"a", "X", "aaa", count=1))                        # 只替换第一个
```

**函数形态的价值**：它是"带状态/带计算"的替换入口。例如把 `"12.5kg"` 转成 `"12500g"` 就需要读数值后换算，字符串模板做不到。

## 4.2 文本清洗的典型配方

清洗任务几乎都可以拆成"三步":

1. **规范化**：统一换行（`\r\n` → `\n`）、去 BOM、`unicodedata.normalize("NFKC", s)` 统一全角/半角。
2. **剥离/替换**：去 HTML 标签、去多余空白（`re.sub(r"\s+", " ", s).strip()`）、掩码敏感信息。
3. **提取**：用命名组把结构化字段捞出来。

```python
import re, unicodedata
s = "  Ｈｅｌｌｏ，世界   "
print(repr(unicodedata.normalize("NFKC", s).strip()))  # 'Hello,世界'
```

**重要提醒**：`NFKC` 会把全角字母/数字转成半角，但**不会**把中文标点统一 —— 把 `，` 全换成 `,` 需要显式映射。

## 4.3 零宽断言（边界匹配）

| 断言 | 含义 | 消耗字符 |
|---|---|---|
| `(?=X)` | 后面是 X | 否 |
| `(?!X)` | 后面不是 X | 否 |
| `(?<=X)` | 前面是 X | 否 |
| `(?<!X)` | 前面不是 X | 否 |

**Python 的限制**：`lookbehind` **必须定宽**。`(?<=\d+)` 会抛 `re.error: look-behind requires fixed-width pattern`。变长回顾要用捕获组替代或改写模式。

```python
import re
print(re.findall(r"\d+(?=元)", "10元 20个 30元"))       # ['10', '30'] 后面是"元"
print(re.findall(r"(?<=\$)\d+", "$10 $20 30"))           # 定宽回顾
try:
    re.findall(r"(?<=\d+)\w", "12a")
except re.error as e:
    print("变量长 lookbehind 报错:", str(e)[:40])
```

## 4.4 什么时候**不该**用正则

这是本章最重要的一节。**有形式语法的东西，请用解析库**：

| 格式 | 该用什么 | 为什么不该用正则 |
|---|---|---|
| JSON | `json.loads` | 有嵌套、转义、Unicode 转义；正则无法正确解析 |
| CSV | `csv` 模块 | 引号内可含逗号/换行，正则难以正确处理 |
| HTML/XML | `html.parser` / `lxml` | 嵌套不可数；正则只能近似 |
| URL 查询串 | `urllib.parse.parse_qs` | 需处理百分号编码与重复键 |
| 日期 | `datetime.strptime` | 需校验合法性（闰年、月份天数） |

**判断法则**：**能写出"正规文法/AST"的东西，就用解析器；只有在"格式松散、只做模式提取"时才用正则。**

```python
import re, json
bad = r'\{"id":\s*(\d+)\}'   # 看起来能用，但遇嵌套/转义就崩
obj = {"id": 1, "tags": [{"id": 2}]}
print("正则漏掉嵌套:", re.findall(bad, json.dumps(obj)))   # ['1'] —— 内层 id=2 没抓到（也抓不对）
print("解析器全对:", json.loads(json.dumps(obj))["tags"][0]["id"])  # 2
```

## 4.5 可读性：`re.X` 与预编译常量

复杂模式用 `re.X`（verbose）可以换行 + 加注释：

```python
import re
DATE = re.compile(r'''
    (?P<y>\d{4}) - (?P<m>\d{2}) - (?P<d>\d{2})   # 年-月-日
''', re.X)
print(DATE.match("2026-10-08").groupdict())
```

**注意**：`re.X` 下**空白被忽略**，想匹配空格要写 `\ ` 或 `[ ]`，这是一个隐蔽的坑。

## 三视角解析

### 🧑‍💻 程序员视角

**排查顺序（"清洗结果不对"）**：

1. **先 `repr` 再看**：全角逗号 `，`、不换行空格 `\xa0`、BOM `\ufeff` 在终端里几乎不可见，`repr` 一打印就现形。
2. **确认是否做了 Unicode 规范化**：`NFKC` 能统一全角/半角的字母数字，但中文标点不会变，需要单独映射表。
3. **替换模板的组号是否正确**：`\g<1>` 优于 `\1`，尤其后面跟数字时。
4. **是否该换库**：数据是 JSON/CSV/HTML 却还在写正则 —— 立刻换解析器，这是**投入产出比最高**的修复。

**工程决策**：
- 清洗**永远幂等**：`f(f(x)) == f(x)`。用同一段文本跑两遍，结果必须一致，否则线上重跑会二次损坏数据。
- 敏感信息掩码要**同时覆盖**明文与编码形态（邮箱、手机、身份证），并写下误伤率评估。

### 🎓 博士生视角

**形式化视角**：正则语言（正则表达式可识别的语言类）**严格弱于**上下文无关语言。JSON、嵌套括号、HTML 都是上下文无关（甚至是更高级别）的语言，因此**存在**正则无法正确识别的输入 —— 这不是实现问题，是**语言类别的界限**。

**为什么"看起来能跑"**：在日常样本上，嵌套深度浅、转义少，写得足够复杂的正则会"碰巧对上"。但这属于**错误率非零**的近似，随着输入分布变化（出现嵌套、转义、CDATA）就会静默出错 —— 比直接报错更危险。

**设计动机**：解析器之所以更好，是因为它把"识别"与"构造语义"分成两层：词法层（tokens）与语法层（AST）。正则只有一个扁平的匹配层，无法承载层次结构。**结构化数据用结构化工具**，这是一条从形式语言理论直接推出的工程结论。

### 📚 考研者视角

**标准问法**：`re.sub` 的替换字符串里怎么引用分组？零宽断言是什么，Python 有什么限制？

**标准答法**：
- 替换模板用 `\1`（数字）或 `\g<name>`（命名）引用分组；**组号可能达到两位数时必须用 `\g<n>`**，否则 `\12` 会被当作组 12。
- 零宽断言（`(?=)` `(?!)` `(?<=)` `(?<!)`）**只判断、不消耗字符**，常用于边界条件；**Python 的 `lookbehind` 必须定宽**，`(?<=\d+)` 会直接报 `re.error`。

**易错口径**：
1. `re.sub` 的 `count` 默认为 `0`，表示**全部替换**，不是"替换 0 次"。
2. 替换模板里的 `\` 需要小心：普通字符串 `"\1"` 会被 Python 先解释成八进制转义，**必须写原始字符串 `r"\1"`**。
3. `re.X` 模式下**空白被忽略**，要匹配空格需 `\ ` 或 `[ ]`。
4. 断言不消耗字符，因此可以**重叠匹配**（同一个位置可被多个断言检查）。
