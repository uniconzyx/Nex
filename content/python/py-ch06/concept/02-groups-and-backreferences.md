# 02 · 分组、命名组与反向引用

分组的本质是**给匹配的子串打标记**，之后既能从 `Match` 里按序号/名字取回，也能在替换模板里引用。

## 2.1 三类括号

| 写法 | 名称 | 是否捕获 | 用途 |
|---|---|---|---|
| `(...)` | 捕获组 | 是 | 需要取出这段内容 |
| `(?:...)` | 非捕获组 | 否 | 只想分组改变优先级，不要多余捕获 |
| `(?P<name>...)` | 命名组 | 是（有名字） | 可读性；在 `sub` 模板里用 `\g<name>` |

**编号规则**：从左到右按**左括号出现顺序**编号，组 `0` 恒为整串。

```python
import re
m = re.match(r"((\d)(\d))-(\d)", "12-3")
print(m.groups())   # ('12', '1', '2', '3')
print(m.group(0))   # '12-3'  —— 整个匹配
print(m.group(1))   # '12'    —— 最外层组
```

**易错点**：嵌套时**外层编号更小** —— 上面 `((\d)(\d))` 里，整体是组 1，两个内层分别是组 2、3，最后 `-(\d)` 是组 4。很多人会误以为内层先编号。

## 2.2 命名组与 groupdict

```python
m = re.match(r"(?P<y>\d{4})-(?P<mo>\d{2})", "2026-10")
print(m.group("y"), m.group("mo"))   # 2026 10
print(m.groupdict())                 # {'y': '2026', 'mo': '10'}
```

命名组的**真实价值**在替换模板里：`\g<mo>` 比 `\2` 可读得多，也不怕插入新组导致编号漂移。

## 2.3 反向引用：`\1` 与 `\g<1>`

反向引用（backreference）表示"匹配与前面某个组**相同**的内容"。它是正则**超出正则语言能力**的典型例子。

```python
import re
# \1 表示与组 1 相同的内容
print(re.search(r"\b(\w+)\s+\1\b", "hello hello").group(0))   # 'hello hello'
# 替换模板里引用组：把 'world hello' 换成 'hello world'
print(re.sub(r"(\w+)\s+(\w+)", r"\2 \1", "world hello"))       # 'hello world'
```

**模板引用的两种写法**：

| 写法 | 适用 | 风险 |
|---|---|---|
| `r"\1"` | 组号 < 10 且后面不接数字 | `r"\12"` 会被解释成**组 12**，而非"组 1 后跟字面 2" |
| `r"\g<1>"` | 通用 | 无歧义，推荐 |

**结论**：只要组号可能遇到两位数，或后面紧跟数字，就一律用 `\g<n>` / `\g<name>`。

## 2.4 分组的回溯视角

每个捕获组都是一次"记录位置"的动作。**组越多，回溯时保存/恢复的状态越多**。这引出两条工程建议：

1. 不需要取值的地方一律用 `(?:...)`，减少状态、也避免 `findall` 返回形态意外改变。
2. 组里嵌套量词（如 `(\d+)+`）会放大回溯，是回溯爆炸的常见源头。

## 三视角解析

### 🧑‍💻 程序员视角

**排查顺序（"分组取不到值"）**：

1. **数左括号**：`m.group(2)` 取不到，先数清有几个 `(` 才编号到 2（别忘了嵌套时外层编号更小）。
2. **看是不是非捕获组**：`(?:...)` **不占编号**。混用捕获与非捕获时，编号只数捕获组。
3. **检查有没有匹配成功**：`m` 为 `None` 时 `m.group(...)` 直接抛 `AttributeError`，正确写法是 `m.group(1) if m else None`。
4. **`findall` 返回的是元组还是列表**：取决于分组个数（见 01 章），取错形态是很常见的 bug 来源。

**工程决策**：**校验类**正则优先 `(?:...)`，**提取类**正则才用捕获组。混在一起写会导致 `findall` 的返回形态难以预测，可维护性骤降。

### 🎓 博士生视角

**形式化定位**：捕获组让正则获得了**记忆能力**，本质上是把匹配从"有限状态"提升为"带存储的自动机"。反向引用 `\1` 要求引擎在匹配过程中**回看历史子串**，这已超出正则语言范畴 —— 带反向引用的"正则"实际表达能力可达 NP 完全（用于某些编码问题）。

**代价的严格来源**：之所以能"免费"获得这个能力，是因为回溯引擎把匹配当成**深度优先搜索**：每个组是一次选择点，失败就回溯重选。因此：
- 表达能力 ↑（支持反向引用、断言、条件组）；
- 最坏复杂度 ↑（从 DFA 的 `O(n)` 退化到指数级）。

**设计动机**：现实中"需要反向引用"的场景其实很少（主要是找重复词、匹配成对引号）。如果权衡后不需要，改用保证线性的引擎（RE2 系）能彻底消除被恶意输入打挂的风险 —— 这是"用表达能力换安全性"的典型工程取舍。

### 📚 考研者视角

**标准问法**：`(?:...)` 和 `(...)` 有什么区别？`\1` 和 `\g<1>` 有什么区别？

**标准答法**：
- `(...)` 是**捕获组**，会占用组号、能出现在 `groups()`/`groupdict()` 里，也会改变 `findall` 的返回形态；`(?:...)` 是**非捕获组**，只改变结合优先级，不占用编号。
- `\1` 是数字反向引用，**在替换模板里紧跟数字会有歧义**（`\12` = 组 12）；`\g<1>` 是显式形式，无歧义，推荐使用。

**易错口径**：
1. 组编号按**左括号出现顺序**，嵌套时外层编号更小 —— 反直觉。
2. `m.groups()` **不含**组 0（整串），组 0 要用 `m.group(0)`。
3. 没匹配上时 `m` 是 `None`，不会抛异常；抛异常的是**对 `None` 取组**这一步。
4. `findall` 遇到 1 个分组时返回 `list[str]`，遇到多个时返回 `list[tuple]` —— 形态不固定。
