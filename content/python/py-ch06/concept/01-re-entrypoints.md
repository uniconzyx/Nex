# 01 · re 的四个入口：match / search / fullmatch / finditer

`re` 模块的入口函数最容易混淆的地方在于 **匹配起点** 与 **返回什么**。下面这张表是本章的锚点。

## 1.1 入口对照表

| 函数 | 起点 | 是否要求整串匹配 | 返回值 | 典型用途 |
|---|---|---|---|---|
| `re.match(p, s)` | **字符串开头** | 否（前缀即可） | `Match` 或 `None` | 判断"是否以某模式开头" |
| `re.search(p, s)` | **任意位置** | 否 | `Match` 或 `None` | 判断"串里有没有" |
| `re.fullmatch(p, s)` | 开头 | **是（必须吃满）** | `Match` 或 `None` | 校验格式（手机号、日期） |
| `re.finditer(p, s)` | 任意位置 | 否 | 迭代器，逐个产出 `Match` | 需要每个匹配的位置/分组 |
| `re.findall(p, s)` | 任意位置 | 否 | `list`（见下） | 只要内容 |
| `re.sub(p, repl, s)` | 任意位置 | 否 | 新字符串 | 批量替换 |

**关键直觉**：`match` 与 `search` 都不是"整串匹配"。要校验格式，**必须用 `fullmatch`**，或者自己加 `^...$`。

```python
import re
s = "abc123"
print(bool(re.match(r"\d+", s)))      # False —— 开头不是数字
print(bool(re.search(r"\d+", s)))     # True  —— 串里有数字
print(bool(re.fullmatch(r"[a-z]+\d+", s)))  # True —— 整串正好是 字母+数字
```

## 1.2 `findall` 的分组陷阱

`findall` 的返回形态**取决于有没有分组**，这是最容易踩的坑：

| 正则 | 返回 |
|---|---|
| 无分组 `r"\d"` | `['1', '2', '3']` —— 整个匹配 |
| 一个分组 `r"(\d)"` | `['1', '2', '3']` —— **只返回分组内容** |
| 两个分组 `r"(\d)(\d)"` | `[('1','2'), ('3','4')]` —— **元组列表** |
| 一个分组 + 非捕获组 `r"(\d)(?:x)"` | 只含那一个捕获组 |

**结论**：想在 `findall` 里拿到"整个匹配"，要么不加任何捕获组（用 `(?:...)` 包裹所有分组），要么改用 `finditer` 后取 `m.group(0)`。

## 1.3 编译与复用

`re.compile(p)` 返回 `Pattern` 对象，可复用。**Python 内部有缓存**（`re._MAXCACHE`，默认 512 条），所以循环里直接写 `re.match(p, s)` 通常也不会重复编译 —— 但一旦模式数量超过缓存容量或模式是动态拼接的，显式 `compile` 更稳。

```python
NUM = re.compile(r"\d+")
print(NUM.findall("a1b22c333"))   # ['1', '22', '333']
```

## 1.4 flags：最常用的三个

| flag | 作用 | 易错点 |
|---|---|---|
| `re.I` | 忽略大小写 | 对 Unicode 也会生效（`İ` 之类需注意） |
| `re.M` | `^`/`$` 匹配**每行**行首行尾 | 不加时只管整串首尾 |
| `re.S` | `.` 匹配换行符 | 不加时 `.` 不匹配 `\n` |

```python
multi = "a\nb\nc"
print(len(re.findall(r"^.", multi)))          # 1
print(len(re.findall(r"^.", multi, re.M)))    # 3
print(re.findall(r"a.b", "a\nb"))             # []
print(re.findall(r"a.b", "a\nb", re.S))       # ['a\nb']
```

## 三视角解析

### 🧑‍💻 程序员视角

**排查顺序**：当"匹配不上"时，按这个顺序查，能省掉 90% 的时间。

1. **确认起点**：`match` 只从开头试，是不是该用 `search`？—— `abc123` 上 `re.match(r"\d+")` 返回 `None` 是最常见的新手困惑。
2. **确认是否要求整串**：只想校验格式却用了 `search`，会放过 `"abc123xyz"`。**校验一律 `fullmatch`**。
3. **打印实际字符串的 repr**：`print(repr(s))`。看不见的 `\r\n`、全角空格、BOM 都会让模式失配。
4. **逐步放宽**：先把模式简化到最小（如 `r"\d"`），确认能匹配，再逐段加回。这比盯着复杂模式猜要快。

**工程决策**：模式**动态拼接**时（如从配置读权限正则），务必用 `re.escape()` 转义字面量部分，否则用户输入的 `.` `*` 会变成元字符，轻则误匹配，重则回溯爆炸。

### 🎓 博士生视角

**形式化定位**：正则语言（regular language）是可被有限自动机（NFA/DFA）识别的语言类，其表达能力**严格弱于**上下文无关语言。这解释了两件事：

1. **为什么嵌套结构（配对的括号、HTML 标签）无法用正则正确解析**：`{ a^n b^n }` 不是正则语言（可由泵引理证明），而 `(a|b)*` 这类有穷状态无法"计数"。工程上能"碰巧工作"的嵌套正则都只是在有限深度内近似，遇到更深嵌套就会失效。
2. **为什么回溯引擎会指数爆炸**：`re` 用的是**回溯 NFA**（Perl 系风格）而非 DFA。`(a+)+b` 在 `aaaa...c` 上失败时，会尝试所有对 `a` 串的切分方式，共 `2^(n-1)` 种，于是耗时指数增长。同理，`a*` 与后面的模式若有重叠前缀，也会产生组合爆炸。

**关键权衡**：回溯引擎表达力更强（支持反向引用、断言，这些**不是**正则语言的能力），代价是最坏情况指数时间；`re2`/`Rust regex` 用 Thompson 构造 + DFA，保证线性时间，但**放弃反向引用**。选型要先问"是否真的需要反向引用"。

### 📚 考研者视角

**标准问法**：请说明 `re.match`、`re.search`、`re.fullmatch` 的区别，并给出「判断一个字符串是否是合法 IPv4」的正确写法。

**标准答法**：
- `match` 从**开头**匹配，允许后面有多余字符；`search` 从**任意位置**扫描；`fullmatch` 要求**整串**匹配。
- 校验 IPv4 应该用 `fullmatch`（或 `^...$`），因为 `match`/`search` 都会放过 `49.6.1.1 ` 这种带尾巴的串。

**易错口径**：
1. `re.match` **不是**整串匹配 —— 这是最高频的错答。
2. `findall` 有分组时**只返回分组**，不是整个匹配。
3. `^` 与 `$` 默认只管整串首尾，要多行语义必须加 `re.M`。
4. `re.error` 是**编译期**异常：模式写错时会立刻抛，而不会静默返回 `None`。
