# 05 · 可变默认参数陷阱与装饰器原理

## 一、可变默认参数陷阱（坑源）

默认参数在 `def` **执行时**求值并绑定一次，之后所有调用共享同一个默认对象。若默认值是可变对象（`list/dict/set`），`def f(x=[]): x.append(1)` 会让多次调用共享同一列表 → 累积污染。

正确惯用法：`def f(x=None): x = x or []`（或 `if x is None: x = []`），每次调用惰性新建。这是 Python 最著名的陷阱之一，也是 CPython 文档与《流畅的Python》反复强调的。

## 二、装饰器原理（基于闭包）

`@trace` 等价于 `f = trace(f)`：装饰器是接收函数、返回函数的高阶函数，利用闭包包装原函数，在不改源码的前提下加日志/计时/缓存/权限。原理依赖：① 函数是一等对象；② 闭包持有被包装函数；③ `*args/**kwargs` 透传任意签名。

```python
def trace(fn):
    def wrapper(*args, **kwargs):
        print("call", fn.__name__)
        return fn(*args, **kwargs)
    return wrapper
```

注意：`functools.wraps` 应保留原函数的 `__name__/__doc__`，否则 `wrapper` 会遮蔽元数据（工具/调试会失真）。

## 三、对比

- Java 无装饰器（用注解 + AOP/动态代理），C++ 用模板/CRTP/宏模拟，均比 Python 闭包装饰器笨重。Python 装饰器是"语法级的高阶函数应用"。
- 可叠放：`@a @b def f()` = `f = a(b(f))`，执行顺序**从下往上包裹、从上往下调用**。

## 四、工程实践

- 永远用 `None` 哨兵处理可变默认参数。
- 写装饰器务必 `from functools import wraps`。
- 装饰器有轻微调用开销（多一层函数帧），热路径用缓存/内联权衡。

## 三视角解析

### 🧑‍💻 程序员视角
- 默认参数一律用 `None` 兜底再在函数内初始化（`if acc is None: acc = []`）。
- 写装饰器**必须加 `functools.wraps`**，否则被装饰函数的 `__name__` / `__doc__` / 签名都会丢失，排查问题时非常痛苦。
- 带参装饰器是「三层嵌套」：最外层收装饰器参数，中间层收函数，最内层收调用参数。

### 🎓 博士生视角
- 可变默认参数的根因是**默认值在 `def` 执行时求值并存进 `function.__defaults__`**：所有调用共享同一个对象，这是求值时机的必然结果。
- 装饰器本质是「**函数 → 函数**」的高阶函数，`@deco` 只是 `f = deco(f)` 的语法糖——理解这一点，所有装饰器形态（带参、类装饰器、堆叠）都变成同一模板的变体。
- 闭包 + 装饰器共同构成 **AOP（面向切面编程）** 的实现基础：在不修改原函数的前提下织入日志、计时、缓存、重试等横切关注点。

### 📚 考研者视角
- 与软件工程的**装饰者模式（Decorator Pattern）**直接对应：二者都主张「不修改原对象而增强行为」，区别是 Python 用高阶函数、OOP 用包装类。
- 若考程序设计语言，常考「语法糖的展开」「高阶函数的应用」。
- 记忆锚点：**默认值在定义时求值一次**；**装饰器 = 返回新函数的高阶函数**。
