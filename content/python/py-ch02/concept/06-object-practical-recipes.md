# 凯喵实战手记 · Python 对象模型与函数式的「当场翻车」

> 凯喵说：Python 看着比 C++ 温柔，但「一切皆对象」「动态作用域」「闭包延迟绑定」这些特性，一旦你不真正理解，就会在运行时给你表演什么叫「我明明写的是对的」。这一章我们把这些现场拉出来，让你看清楚 Python 每一步在运行时到底做了什么。

### 现场 1：可变默认参数是共享的陷阱

```python
def add_item(x, lst=[]):
    lst.append(x)
    return lst

print(add_item(1))  # [1]
print(add_item(2))  # [1, 2]  —— 不是你以为的 [2]！
```

默认参数在**函数定义时**只创建一次，所有调用共享同一个列表。凯喵的修法：默认用 `None`，函数体内 `lst = lst or []`，每次调用拿到新列表。

### 现场 2：闭包延迟绑定（late binding）

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])  # [2, 2, 2]，不是 [0, 1, 2]
```

闭包捕获的是变量名 `i` 本身，循环结束后 `i` 是 2，所以全部返回 2。凯喵：要「快照」当前值就 `lambda i=i: i`，把当前值绑定成默认参数。

### 现场 3：`UnboundLocalError` 的编译期决定

```python
x = 10
def f():
    print(x)   # UnboundLocalError!
    x = 20
```

只要函数体内有 `x = 20` 这种赋值，Python 就把 `x` 当成**局部变量**，而 `print(x)` 在赋值前执行就报错。凯喵：要改全局用 `global x`；嵌套里改外层用 `nonlocal x`，别以为「能读到就是全局」。

### 现场 4：装饰器丢元信息

```python
def deco(f):
    def wrapper(*a, **k):
        return f(*a, **k)
    return wrapper

@deco
def greet(): """say hi"""
print(greet.__name__)  # 'wrapper'，不是 'greet'
```

装饰后的函数变成了 `wrapper`，名字、文档、注解全丢。凯喵：用 `functools.wraps(f)` 装饰 wrapper，元信息自动保留，调试和文档才正确。

### 现场 5：参数顺序的硬规则

调用时顺序必须是：位置 → 默认 → `*args` → 仅关键字 → `**kwargs`。写函数时签名顺序也一样。凯喵：想强制调用方用关键字传参，把参数放 `*` 之后（如 `def f(a, *, b)`），可读性更好也避免位置错传。

### 现场 6：`*args` / `**kwargs` 解包重复键

```python
def f(a, b): ...
f(**{'a':1}, **{'a':2, 'b':3})  # 后面的 'a' 覆盖前面的，实际 a=2
```

解包时后者覆盖前者，不会报错。凯喵：动态拼参数字典时警惕重复键静默覆盖，那是隐蔽 Bug 的来源。

### 现场 7：函数属性当「静态变量」却忘了全局共享

```python
def counter():
    counter.n = getattr(counter, 'n', 0) + 1
    return counter.n
```

函数对象本身是可变对象，挂属性确实能当静态变量，但它是**全局共享**的，并发/多实例下会互相污染。凯喵：需要状态优先用类或闭包变量，别滥用函数属性当存储。

### 现场 8：把函数属性当"静态变量"却忘了它是全局共享

（与上呼应）凯喵强调：函数属性本质上挂在模块级对象上，任何地方调用都改同一份。需要隔离状态时，用实例属性或闭包，别图省事挂函数上。

### 现场 9：误以为 `del`/重新赋值能改外部可变对象

```python
def f(lst):
    lst = [1, 2, 3]   # 只是把局部名 lst 指向新列表，外部没变
def g(lst):
    lst[:] = [1, 2, 3]  # 改的是原列表内容，外部变了
```

`lst = ...` 只改局部绑定，不影响调用方；要改原对象内容得用切片赋值或 `clear()+extend()`。凯喵：分清「重绑定名字」和「原地修改对象」。

### 现场 10：命名空间与作用域 LEGB

Python 查找名字顺序：Local → Enclosing → Global → Builtin。凯喵：遇到「明明定义了却报 NameError」，先想它在哪个作用域、是否被内层同名遮蔽、是否在引用前执行到。

### 现场 11：可变对象作类属性的共享灾难

```python
class Box:
    items = []   # 类属性，所有实例共享
b1 = Box(); b1.items.append(1)
b2 = Box(); print(b2.items)  # [1] —— b2 也"继承"了这个 1
```

类属性是共享的，想每个实例独立就在 `__init__` 里 `self.items = []`。凯喵：可变类属性是经典坑，初始化放实例里。

### 现场 12：深浅拷贝的边界

`copy.copy` 浅拷贝只复制一层，嵌套容器仍共享；`copy.deepcopy` 递归全拷但慢且可能递归爆栈。凯喵：需要独立副本又含嵌套时上 `deepcopy`，但注意对象有循环引用时 deepcopy 能处理（它带备忘录），自己写的递归拷贝不行。

> 凯喵总结：Python 的坑九成在「可变默认参数」「闭包延迟绑定」「作用域编译期决定」「装饰器丢元信息」「重绑定 vs 原地改」。把这 12 个现场刻进手感，运行时灵异事件少一大半。

> 一句话收尾：Python 给你自由，也把「正确性」的责任还给了你——好用的前提是真懂它每一步在运行时做了什么，而不是凭直觉猜。

### 凯喵复盘：Python 的「坑」本质是「运行时语义和你以为的不同」

这 12 个现场，没有一个是因为语法错误——它们都能跑，只是结果偏离直觉。凯喵总结它们的共同根因：Python 的很多行为是在**运行时**按对象模型动态决定的，而你脑子里想的是「静态/直觉版本」。比如默认参数是在函数定义时求值一次（不是每次调用），闭包捕获的是变量名而非当时的值，函数内的赋值会让变量变成局部——这些全都是「运行时的真相」和「你的想象」之间的错位。

第二类高频事故是**共享可变状态**。可变默认参数、类属性、函数属性、闭包变量，本质都是「同一份可变对象被多处引用」，一处改了别处跟着变。凯喵的防御性习惯是：默认参数用 `None`、可变状态放实例、需要隔离就上类或闭包。凡是看到「明明没改它怎么变了」，第一反应就是「是不是共享了同一个可变对象」。

第三类是**作用域与绑定**。LEGB 查找顺序、`global`/`nonlocal` 的必要性、切片赋值 vs 重绑定名字的区别——这些决定了「这个变量到底是谁的、改的是不是你想改的那个」。把作用域当成 Python 的「命名空间地图」，每次困惑时按 L→E→G→B 一层层找，名字相关的 Bug 基本都能定位。理解对象模型不是为了炫技，而是让「写下的代码」和「运行的代码」终于变成同一件事。

### 凯喵速记：Python 的三条防坑底线

只记三句也能避掉大部分灵异事件：第一，默认参数用 `None`、可变状态放实例，别让同一份可变对象被多处共享；第二，函数内要改外层变量就 `global`/`nonlocal`，别靠直觉猜作用域；第三，闭包要快照当前值就 `lambda i=i`，别等循环结束才求值。这三句挡掉了八成 Python 运行时 Bug，剩下细节回来翻这 12 个现场对号入座即可，不必硬背。

最后说一句心态：Python 的魔法其实都不魔法，只是运行时替你做了很多隐式决定。你越早把对象模型、作用域、绑定这些底层规则吃透，就越少被「明明应该这样」的惊讶击中。初学阶段可以靠试错往前走，但一旦要写长期维护的代码、要和别人协作、要在深夜排查只在生产环境才出现的怪问题，理解的深度就直接决定你排查的速度。把这一章的十几个现场当成一张对照表，遇到反常行为就回来逐条排除，久而久之你会形成一种可靠的直觉：看到某个写法，就能预判它在运行时会怎么走。那时候你会发现自己不再害怕那些所谓灵异现象，因为你能看见它们背后的因果。这份看见因果的能力，才是 Python 真正教会你的东西。

## 三视角解析
### 🧑‍💻 程序员视角
可变默认参数是共享陷阱，闭包延迟绑定是第二个——两者都源于「定义时求值一次」。`UnboundLocalError` 的根因是「函数内赋值让名字变成局部变量」，即使在赋值前读取也会报错，要改外部变量得声明 `global`/`nonlocal`。装饰器不加 `functools.wraps` 会丢掉原函数的 `__name__`/`__doc__`，影响调试与文档生成。这些坑的共同解法是「理解 Python 的绑定时机」。

### 🎓 博士生视角
Python 的函数是「一等对象」，装饰器本质是「接收函数、返回函数」的高阶函数，`@deco` 只是 `f = deco(f)` 的语法糖。`functools.wraps` 复制的是 `__wrapped__` 与元信息，使 `inspect.signature` 能穿透装饰器。描述符协议（`__get__`/`__set__`）是 `property`、`classmethod`、`staticmethod` 的底层机制，理解它才能解释「为什么类方法能拿到 cls」。

### 📚 考研者视角
Python 面试高频：
1. **装饰器**：原理、带参数的装饰器（三层嵌套）、`functools.wraps` 的作用。
2. **闭包**：定义、`nonlocal` 的使用、延迟绑定的坑。
3. **生成器**：`yield` 的执行流程、与迭代器的关系、`send`/`throw` 的用法。
4. **`*args`/`**kwargs`**：打包与解包、位置参数与关键字参数的顺序规则。
