# 02 · 函数定义与参数：def、解包与调用约定

## 一、理论根基：函数是一等对象、被延迟创建

`def` 在运行期**执行**：它创建函数对象（`<class 'function'>`），把编译好的字节码、默认参数值、闭包单元（`__closure__`）打包，并把名字绑定到当前命名空间。因此默认参数在 `def` 语句执行时求值一次（见第 5 讲陷阱）。函数对象是一等公民：可赋值、可作参/返回值、可存容器。

## 二、实现机制：参数如何传递与解包

CPython 调用约定：

- 位置参数按顺序压入局部变量槽。
- `*args`：把可迭代对象解包为位置参数序列，收集进元组 `args`。
- `**kwargs`：把映射解包为关键字参数，收集进字典 `kwargs`。
- 传入侧 `f(*seq)` / `f(**dict)` 是**调用期解包**：把序列/字典"展开"成位置/关键字实参（语法糖，底层为 `CALL_FUNCTION_EX` 等字节码）。
- 参数求值策略 **call by sharing（共享引用）**：形参得到实参对象的引用。对**可变对象**原地修改，调用方可见；对**不可变对象**重绑定，调用方无感——这解释了为什么传 list 进函数 `append` 会影响外面，而传 int 重赋值不会。

## 三、与 C++/Java 对比

- C++：`void f(T a)` 值拷贝；`void f(T& a)` 引用；可变参数用 `initializer_list`/可变模板，`f(args...)` 是编译期展开。
- Java：`f(T... args)` 编译为数组；无 `**kwargs` 等价物（需手写 `Map` 或 builder）。
- Python：`*args/**kwargs` 是解释器级、运行期、类型无关，最灵活但有一定运行期开销（构建 tuple/dict）。

## 四、工程实践

- 关键字参数提升可读性：`process(data, timeout=30, retries=3)`。
- 仅用 `*args/**kwargs` 做"透传/委托"（装饰器、wrapper），别在业务函数里滥用到可读性崩坏。
- 解包传入：`add(*row)`、`fn(**config)` 适合配置驱动/数据驱动代码。

## 三视角解析

### 🧑‍💻 程序员视角
- 参数顺序固定：位置参数 → 默认参数 → `*args` → 仅关键字参数 → `**kwargs`；调用时用 `*` / `**` 解包。
- **可变默认参数是经典陷阱**：`def f(x, acc=[])` 会让所有调用共享同一个列表——默认值写 `None` 再在函数内初始化。
- 想强制关键字调用，在参数列表里加一个裸 `*`（`def f(a, *, b)`）。

### 🎓 博士生视角
- **默认值在函数定义时求值一次**，结果存进 `function.__defaults__`——这是可变默认参数陷阱的根因，不是「Python 的 bug」而是「求值时机」的必然结果。
- Python 的传参模型常被误称为「引用传递」，准确说法是 **call by object reference / call by sharing**：函数收到的是对象引用，对不可变对象重绑定不影响调用方，对可变对象原地修改则会影响调用方。
- `*args` 打包为 `tuple`、`**kwargs` 打包为 `dict`；关键字参数经 `CALL_FUNCTION_EX` 拆包，比纯位置调用略慢——这是「可读性换性能」的真实代价。

### 📚 考研者视角
- 与 C 的**值传递**、C++ 的**引用传递/指针传递**构成经典对比题：「为什么 C 无法用值参交换两个变量，而 Python 传列表能改内容却仍不能换名字？」
- 若考程序设计语言，常考「参数传递方式分类（值/引用/名/值-结果）」。
- 记忆锚点：**Python 是「传对象引用」**；**默认参数在定义时求值一次**。
