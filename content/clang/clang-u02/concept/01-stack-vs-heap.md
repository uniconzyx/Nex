# 栈与堆：两种生命周期

## 一、进程内存分区（高地址 → 低地址）

```
+---------------------+  高地址
|   命令行参数/环境变量  |
+---------------------+
|        栈 (stack)     |  ↓ 向下增长：局部变量、参数、返回地址
+---------------------+
|         ↓             |
|        ...            |
|         ↑             |
+---------------------+
|        堆 (heap)      |  ↑ 向上增长：malloc/free
+---------------------+
|   BSS 段（未初始化全局） |
+---------------------+
|   数据段（已初始化全局）  |
+---------------------+
|  只读数据段（字面量）    |
+---------------------+
|   代码段 (.text)      |  低地址
+---------------------+
```

## 二、栈的特点

| 维度 | 栈 |
|---|---|
| 管理方式 | **自动**（进入/离开作用域即分配/回收） |
| 分配速度 | 极快（只移动栈指针 `rsp`，通常 1 条指令） |
| 容量 | 小（Linux 默认 8 MB，Windows 默认 1 MB） |
| 碎片 | 无 |
| 生命周期 | 作用域结束即失效 |

**关键推论**：

- **大数组必须放堆**：`int a[1000000];`（4 MB）在 Windows 默认 1 MB 栈上会**栈溢出**。
- **不能返回局部变量地址**：作用域结束栈帧即失效 → 悬垂指针。
- 栈大小可用 `ulimit -s`（Linux）/ 链接器 `/STACK`（Windows）调整。

## 三、堆的特点

| 维度 | 堆 |
|---|---|
| 管理方式 | **手动**（`malloc`/`free`） |
| 分配速度 | 较慢（要在空闲链表中查找、可能有系统调用） |
| 容量 | 受虚拟地址空间与物理内存限制，远大于栈 |
| 碎片 | **有**（外部碎片 + 每块头部开销） |
| 生命周期 | 从 malloc 到 free，跨函数、跨作用域 |

**这是堆存在的唯一理由**：「**生命周期超越作用域**」+「**大小运行时才确定**」。

## 四、`malloc` 的真实成本

`malloc` 并不每次都向内核要内存。glibc 的分配策略：

1. **小请求（< 128 KB）**：从堆顶通过 `brk` 已申请的大块里切分，走**空闲链表 / 分离存储**。
2. **大请求（≥ 128 KB）**：直接 `mmap` 一块独立区域，`free` 时 `munmap` 还给内核（阈值 `M_MMAP_THRESHOLD` 可调）。

**每块都有元数据头部**（大小、链表指针、标志位），因此：

```c
malloc(1)   /* 实际占用通常 ≥ 32 字节（头部 + 对齐到 16 字节） */
```

**为什么 free 后 RSS 不降**：小块的 `free` 只是放回空闲链表，**物理页并未归还内核**——这是**正常行为，不是泄漏**。判断泄漏要看「持续增长且不回落」，而不是「释放后不下降」。

## 五、碎片

- **外部碎片**：空闲内存总量够，但**不连续**，无法满足大请求。
- **内部碎片**：分配器为对齐/元数据多给的部分（`malloc(1)` 给的 ≥32 字节里的浪费）。

**缓解**：按尺寸分级的内存池、避免频繁分配释放大小不一的块、复用缓冲区。

## 六、与 C++ 的边界（面试常问）

| 维度 | `malloc/free`（C） | `new/delete`（C++） |
|---|---|---|
| 本质 | **库函数** | **运算符** |
| 是否调构造/析构 | 否 | 是 |
| 大小 | 需 `sizeof` 手算 | 自动推导 |
| 返回类型 | `void*`（需转型） | 具体类型指针 |
| 失败行为 | 返回 `NULL` | 抛 `std::bad_alloc` |

**绝不可混用**：`new` 分配用 `free` 释放会跳过析构；`malloc` 分配用 `delete` 释放会对未构造对象调析构——都是 UB。C 中没有构造/析构概念，所以只有 `malloc/free`。

## 三视角解析

### 🧑‍💻 程序员视角
- 栈快但小（默认几 MB），堆慢但大：大数组、长期存活的数据放堆；局部小对象放栈最省事。
- 别返回局部变量的地址；`static` 局部变量能延长生命周期，但会破坏可重入性（多线程下是隐患）。
- 栈溢出（SIGSEGV）在递归/大局部数组时最常见，看 backtrace 的重复栈帧就能判断。

### 🎓 博士生视角
- 栈分配只是**移动栈指针**（单条指令，O(1)），因此极快；堆分配必须走分配器（查找空闲块、更新元数据，必要时 `brk`/`mmap` 系统调用），因此慢一到两个数量级。
- 栈大小受 `RLIMIT_STACK` 限制且**向低地址增长**；堆向高地址增长，二者中间是未映射区（历史上共享同一空间）。
- 堆的核心问题不是速度而是**碎片**：反复分配释放不同大小的块会造成外部碎片，这正是内存池/分代分配器存在的理由。
- 生命周期语义也不同：栈对象的作用域结束即销毁（自动），堆对象必须手动 `free`（无所有权类型系统，因此易漏易重）。

### 📚 考研者视角
- **408 计组/操作系统交叉**：栈的硬件支持（栈指针、栈帧、返回地址）、虚拟地址空间的布局（代码段/数据段/堆/栈）、页表与缺页。
- 常考概念题：「栈与堆的区别」（分配方式、生长方向、效率、生命周期、碎片），要求分点作答。
- 记忆锚点：**栈自动、堆手动；栈小快、堆大慢；栈向低、堆向高**。
