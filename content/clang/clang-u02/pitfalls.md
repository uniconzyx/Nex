# clang-u02 · 易错点

1. **`malloc` 后不判空** —— 内存不足时 `malloc` 返回 `NULL`，直接解引用即崩溃。**正确写法**：分配后立即 `if (!p) { /* 处理或向上传播 */ }`。

2. **`realloc` 直接赋值给原指针** —— `p = realloc(p, n);` 一旦失败返回 `NULL`，`p` 被覆盖，原内存**永久泄漏**。**正确写法**：`void *tmp = realloc(p, n); if (!tmp) { ... } p = tmp;`。

3. **`free` 后继续使用（use-after-free）** —— `free(p)` 只归还内存，不改 `p` 的值，`*p` 或 `p[i]` 是 UB（可能崩溃，也可能静默读到已被复用的数据）。**正确写法**：`free(p); p = NULL;`。

4. **重复释放（double free）** —— 对同一块 `free` 两次会破坏分配器元数据。**正确写法**：释放后立即置 `NULL`（`free(NULL)` 是安全的），或明确所有权让释放只发生一次。

5. **对非 `malloc` 来源的指针 `free`** —— 对栈变量地址、全局数组、或 `p + 1` 这类**偏移后**的指针调用 `free` 会破坏堆。**正确写法**：只 `free` 分配函数返回的原始地址。

6. **`count * sizeof(T)` 乘法溢出** —— 用户可控的 `count` 极大时乘法回绕，分配到远小于预期的块，后续写入造成**堆溢出**（可被利用的安全漏洞）。**正确写法**：`if (count > SIZE_MAX / sizeof(T)) return NULL;` 或改用自带溢出检查的 `calloc`。

7. **大数组放栈上** —— `int a[1000000];` 一次占 4 MB，在默认 1 MB 栈上直接栈溢出。**正确写法**：改用 `malloc`，或调大栈（但不要依赖）。

8. **返回局部数组的地址** —— `char *f(void){ char buf[64]; return buf; }` 返回后栈帧失效，得到悬垂指针。**正确写法**：改用 `malloc`（调用方负责释放）、让调用方传入缓冲区、或返回 `static`（注明不可重入）。

9. **误把「释放后内存不归还系统」当泄漏** —— 小块 `free` 后内存回到分配器空闲链表，RSS 不降是**正常现象**。**判断标准**：是「持续增长且不回落」，而不是「释放后不下降」。

10. **多线程下共享分配器/共享指针** —— `malloc`/`free` 本身是线程安全的（内部有锁），但**共享数据的读写**不是。两个线程对同一指针一个 `free` 一个用，是典型的竞态 UB。**正确写法**：明确所有权归属，跨线程传递用队列而非裸指针。

11. **忽略 `calloc` 与 `malloc` 的语义差异** —— 误用 `malloc` 却期望内容是 0，会读到脏数据并引发难查的逻辑错误。**正确写法**：需要零初始化就用 `calloc`。
