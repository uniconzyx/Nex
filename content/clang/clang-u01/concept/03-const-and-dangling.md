# const 修饰指针、野指针与悬垂指针

## 一、const 修饰指针的三种形态

**读法：从右往左**（`const` 修饰它左边紧邻的部分）。

| 声明 | 名称 | 能否改 `p` | 能否改 `*p` |
|---|---|---|---|
| `const int *p` | 指向常量的指针 | ✅ 能 | ❌ 不能 |
| `int * const p` | 常量指针 | ❌ 不能 | ✅ 能 |
| `const int * const p` | 两者都锁 | ❌ 不能 | ❌ 不能 |

**记忆口诀**：`const` 在 `*` **左边** → 锁住**内容**；在 `*` **右边** → 锁住**指针本身**。

```c
int x = 1, y = 2;
const int *p1 = &x;
p1 = &y;        /* OK */
/* *p1 = 5;     /* 编译错误 */

int * const p2 = &x;
*p2 = 5;        /* OK */
/* p2 = &y;     /* 编译错误 */
```

**工程价值**：`const` 是**接口契约**。`void print(const char *s)` 告诉调用方「我不会改你的数据」，也让编译器帮你挡住误写。函数参数能加 `const` 就加。

**C 与 C++ 的重要差异（面试考点）**：

```c
const int N = 5;
int a[N];        /* C：错误（C 中 const 变量不是常量表达式，VLA 除外） */
                 /* C++：OK（C++ 中 const int 是编译期常量） */
```

C 里要真正的编译期常量，用 `#define` 或 `enum`。

## 二、野指针（wild pointer）

**定义**：声明了但**未初始化**的指针——它的值是栈上的残留垃圾。

**危害**：`if (p) { ... }` 无法挡住它（垃圾值通常非 0），解引用直接踩内存。

**对策**：**声明即初始化**。

```c
int *p = NULL;         /* 好习惯 */
```

## 三、悬垂指针（dangling pointer）

**定义**：指针指向的对象**已经失效**，但指针本身还在。

**三大来源**：

### 1. free 之后继续使用

```c
int *p = malloc(sizeof(int));
free(p);
*p = 10;        /* UB：use-after-free */
p = NULL;       /* 规范做法：置空，重复 free(NULL) 是安全的 */
```

注意：`free` **不会**修改 `p` 的值，`p` 仍指向那块已归还的内存。这也解释了为什么「重复 `free` 同一指针」是双重释放（double free）——会破坏分配器的元数据。

### 2. 返回局部变量地址

```c
int *bad(void) {
    int local = 42;
    return &local;      /* UB：函数返回后栈帧已失效 */
}
```

正确做法：返回值（拷贝）、返回 `static` 变量（但**不可重入**）、或让调用方传入缓冲区/由调用方负责释放。

### 3. 指向已离开作用域的对象

```c
int *p;
{
    int x = 5;
    p = &x;
}                       /* x 的生命周期结束 */
printf("%d\n", *p);     /* UB */
```

## 四、字符串字面量的类型陷阱

```c
char *s = "hello";      /* 危险：字面量在只读段，写它 → 段错误 */
s[0] = 'H';             /* UB / SIGSEGV */

const char *s2 = "hello";   /* 正确：类型就表达了只读 */
char buf[] = "hello";       /* 正确：buf 是栈上可写副本 */
buf[0] = 'H';               /* OK */
```

**关键区别**：`char *s = "..."` 只把指针指向只读段；`char buf[] = "..."` 会**复制**一份到可写内存。前者改不了，后者能改，且 `sizeof` 也不同（指针 8 vs 数组 6）。

## 五、越界为什么「有时不崩」

指针算术无边界检查。`a[5]` 越界读写栈上的相邻变量——可能读到别的变量、可能破坏返回地址：

- 可能静默出错（最危险）；
- 可能立刻崩溃；
- 可能被攻击者利用（栈溢出）。

**防护手段**：

1. 始终传长度，循环条件用 `i < n`。
2. 编译期加固：`-fsanitize=address,undefined -fstack-protector-all`。
3. CI 中跑 ASan：越界与 use-after-free 会被立即定位。

## 三视角解析

### 🧑‍💻 程序员视角
- 记口诀：**`const char *p` 是「指向常量的指针」（内容不可改），`char * const p` 是「常指针」（指向不可改）**——从右往左读 const 修饰谁。
- 返回**局部变量地址**是经典 UB：函数返回后栈帧失效，指针悬垂。编译器常警告，但别依赖警告。
- `free` 之后立刻把指针置 `NULL`（`p = NULL`），能挡住大部分「use-after-free」的低级事故。

### 🎓 博士生视角
- `const` 是**类型系统层面的只读约束**，不是硬件保护：除字符串字面量所在只读段外，通过强制转换丢弃 `const` 并写入是 UB（可能不崩，但优化器可据此做出违反直觉的假设）。
- 这一点很关键：**UB 不只影响那一行**。编译器若假定对象不变，可能把「改过之后又读」优化成「直接用旧值」，于是代码「看起来没生效」。
- 悬垂指针的本质是**生命周期错配**：指针比对象活得久。C 没有生命周期类型系统（对比 Rust 的借用检查器），因此只能靠规范与工具（ASan、valgrind）兜底。
- `restrict` 与 `const` 都会参与**别名分析（alias analysis）**，直接影响向量化与重排优化的激进程度。

### 📚 考研者视角
- **408 高频**：`const` 与指针结合的四种写法辨析（`const int *p` / `int const *p` / `int * const p` / `const int * const p`）——这是选择题常客。
- 常考概念题：「指针与 const 的关系」「什么是野指针、悬垂指针」「为什么不能返回局部变量的地址」。
- 记忆锚点：**`const` 离谁近就修饰谁**；**`const` 是编译期约束，不是运行时保护**。
