# 地址、指针与数组退化

## 一、指针的本质：带类型的地址

内存是一排**按字节编号**的格子，编号就是**地址**。指针是一个变量，里面存的正是这样一个编号。

```c
int x = 42;
int *p = &x;      /* p 里存的是 x 的地址 */
```

关键点：**指针有类型**，类型决定两件事——

| 类型 | 解引用读多少字节 | 指针 +1 前进多少字节 |
|---|---|---|
| `char *` | 1 | 1 |
| `short *` | 2 | 2 |
| `int *` | 4 | 4 |
| `double *` | 8 | 8 |

所以 `p + 1` **不是**「地址加 1」，而是「地址加 `sizeof(*p)`」。这是指针算术的全部秘密。

在 64 位机器上，任何指针都占 **8 字节**——`sizeof(char*) == sizeof(double*) == 8`。类型不改变表示，只改变解释方式。

## 二、数组退化（decay）

数组名在**大多数表达式**中会转换（退化）为「指向首元素的指针」：

```c
int a[5];
int *p = a;        /* 等价于 &a[0] */
```

退化有两个例外：

1. **`sizeof(a)`** 得整个数组字节数 `5 * sizeof(int) = 20`；
2. **`&a`** 得到的是**数组指针** `int (*)[5]`，而不是 `int *`。

这就是 `a`、`&a`、`&a[0]` 三者「地址值相同、类型与步长不同」的原因：

```c
int a[5];
/* 假设 a 的地址为 0x1000 */
a        /* 类型 int*,         a + 1  => 0x1004 */
&a[0]    /* 类型 int*,         + 1     => 0x1004 */
&a       /* 类型 int(*)[5],    + 1     => 0x1014（前进 20 字节） */
```

**面试标准答法**：三者的**值**（地址）相同，但**类型不同**，因此 `+1` 的步长不同——`a` 和 `&a[0]` 走一个元素，`&a` 走整个数组。

## 三、函数参数的退化陷阱

数组作函数参数时，会退化为指针，**长度信息彻底丢失**：

```c
void f(int a[5]) {          /* 编译后实际是 int *a */
    printf("%zu\n", sizeof(a));   /* 8，不是 20 */
}
```

- `int a[5]`、`int a[]`、`int *a` 作形参**完全等价**（`[5]` 只是文档性提示，编译器不检查）。
- 因此必须额外传长度：`void f(int *a, size_t n)`。
- 用 `sizeof(a) / sizeof(a[0])` 求长度的惯用法**只在数组未退化的作用域内**有效。

**判别口诀**：只要它已经不是「数组类型」了（例如成了参数、被赋给指针），`sizeof` 就再也拿不到数组长度。

## 四、指针相减与比较

- **指针相减**：仅当两个指针指向**同一数组**（或数组尾后一个位置）时才有定义，结果是 `ptrdiff_t` 类型的**元素个数**（不是字节数）：

```c
int a[5];
ptrdiff_t d = &a[4] - &a[1];   /* 3（元素个数） */
```

- **指针比较**：`<`、`>` 同样只在同一数组内才有意义；`==`、`!=` 任何情况下都可用（含与 `NULL` 比较）。
- 不同对象的指针相减/比较是 UB——即使「看起来」地址大小合理。

## 五、`NULL` 与空指针

```c
int *p = NULL;      /* 不指向任何对象 */
if (p) { ... }      /* 等价于 p != NULL */
```

- `NULL` 在 C 中通常是 `((void*)0)`（在 C++ 中是 `0`/`nullptr`）。
- 解引用 `NULL` 是 UB，几乎必然段错误。
- `free(NULL)` 是**安全的空操作**，这使「释放后立即置 NULL」成为可靠习惯。
- C23 引入 `nullptr` 常量，语义更严谨。

## 六、`void *`：通用指针

`void *` 是「无类型指针」，可以与其他对象指针**隐式互相转换**（C 中不需要强转）：

```c
void *raw = malloc(100);   /* C 中无需 (int*) 强转 */
int *arr = raw;
```

- **不能**对 `void *` 解引用，也不能做指针算术（因为 `sizeof(void)` 无定义，GCC 扩展下按 1 处理——不可移植）。
- 它是 C 的「泛型」手段：`qsort`、`memcpy`、`malloc` 都靠它。

## 三视角解析

### 🧑‍💻 程序员视角
- **数组作为函数参数会退化为指针**，长度信息当场丢失：所以必须另传长度（`void f(int *a, size_t n)`），或用结构体把数组包起来传引用。
- `sizeof(数组)` 只在**同一个作用域内**有效；在函数里 `sizeof(参数)` 得到的是指针大小（8 字节），这是最经典的误判。
- 拷贝大块内存用 `memcpy` 而非手写循环，编译器会把它优化成向量指令；`restrict` 能提示无别名，帮助优化。

### 🎓 博士生视角
- 数组名在**大多数表达式上下文**中退化为指向首元素的指针，但存在三个例外：`sizeof`、`&`、以及字符串字面量用于初始化数组。退化是**不可逆的信息丢失**（维度与长度都没了）。
- 指针算术按**所指类型的大小**缩放，因此 `p + 1` 的实际地址增量是 `sizeof(*p)`；越界指针即使不解引用也是 UB（如 `&a[6]`）。
- 通过「与函数类型不符的指针」调用函数是 UB；C 的类型系统在函数指针处最薄弱，这是许多回调崩溃的根源。
- 形式化一点看，数组类型与指针类型在类型系统中是**不同类型**，退化是编译器插入的隐式转换（array-to-pointer conversion），而不是「数组就是指针」。

### 📚 考研者视角
- **408 高频**：「数组名就是常量指针」是错误说法——数组名是数组类型，只在表达式中退化；这个概念题几乎年年出现。
- 常考计算：指针加减的地址变化（结合元素大小）、`&a` 与 `a` 的类型差别（前者是指向整个数组的指针，`+1` 跳过整个数组）。
- 与计组交叉：数组的**地址计算** `base + i × sizeof(T)`、按字编址与按字节编址的区别。
- 记忆锚点：**`sizeof(数组)` 在函数参数中退化为 `sizeof(指针)`**；**数组名不是指针，只是会退化**。
