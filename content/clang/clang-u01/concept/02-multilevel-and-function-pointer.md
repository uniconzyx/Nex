# 多级指针、数组指针与函数指针

## 一、多级指针：指针的指针

```c
int x = 42;
int *p = &x;       /* 一级：指向 int */
int **pp = &p;     /* 二级：指向「指向 int 的指针」 */
```

**读法：从右往左**，`int **pp` → `pp` 是「指针，指向 `int *`」。

**解引用次数要匹配**：

```c
*pp      /* 得 p，类型 int* */
**pp     /* 得 x，类型 int，值是 42 */
```

**为什么需要二级指针**——只有一种核心场景：**函数需要修改调用方的指针本身**。

```c
/* 错误：只改了本地副本 */
void alloc_bad(int *p) { p = malloc(sizeof(int) * 10); }   /* 调用方指针没变，且内存泄漏 */

/* 正确：传指针的地址，才能改到调用方的指针 */
void alloc_ok(int **out, size_t n) {
    *out = malloc(sizeof(int) * n);
}
int *buf = NULL;
alloc_ok(&buf, 10);
```

这与「函数要修改 `int` 就传 `int *`」是同一条规则递归一次的结果。链表头插/删头节点也依赖它。

## 二、数组指针 vs 指针数组（最经典的易混点）

```c
int *arr[5];    /* 指针数组：5 个元素的数组，每个元素是 int* */
int (*par)[5];  /* 数组指针：一个指针，指向「含 5 个 int 的数组」 */
```

**判别法**：看**括号与结合性**——

- `int *arr[5]`：`[]` 优先级高于 `*`，所以先结合成「数组」，`arr` 是数组，元素类型 `int*`。
- `int (*par)[5]`：括号强制先与 `*` 结合，`par` 是指针，指向 `int[5]`。

**用途**：数组指针是遍历**二维数组**的正确工具：

```c
int m[3][4];
int (*row)[4] = m;      /* row 指向一行（4 个 int） */
row + 1;                /* 前进 16 字节，跳到下一行 */
```

对比：`int **p = m;` 是**错的**——二维数组不是「指针的指针」，它是「数组的数组」，内存连续。

## 三、函数指针

**声明语法**：`返回类型 (*名字)(参数类型列表)`

```c
int (*fp)(int, int);       /* 指向「接受两个 int、返回 int」的函数 */
```

括号不可省：`int *fp(int, int)` 是「返回 `int*` 的函数」。

**赋值与调用**（`&` 与 `*` 都可省略）：

```c
int add(int a, int b) { return a + b; }

fp = add;        /* 等价 fp = &add; */
int r = fp(1, 2);   /* 等价 (*fp)(1, 2); */
```

**四大实际用途**：

1. **回调**：`qsort` / `bsearch` 的比较器。

```c
int cmp(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);        /* 避免相减溢出 */
}
int arr[5] = {3, 1, 4, 1, 5};
qsort(arr, 5, sizeof(int), cmp);
```

2. **虚表的手工模拟**：C 没有虚函数，用「函数指针结构体」实现多态（GTK / Linux 内核 `file_operations` 都是这个套路）。
3. **跳转表 / 状态机**：`handler_t table[] = { h1, h2, h3 };` 用数组下标分派，比 `switch` 更易扩展。
4. **插件注册**：把函数指针存入全局表。

**用 `typedef` 化简**（工程必备）：

```c
typedef int (*binop_t)(int, int);
binop_t fp = add;
binop_t ops[4] = { add, sub, mul, divi };   /* 函数指针数组，天然当跳转表 */
```

**信号量陷阱**：函数指针数组的声明 `int (*ops[4])(int,int)` 里，`[]` 先结合——`ops` 是数组，元素是函数指针。存函数**返回值**才需要数组指针。

## 四、函数指针与 `dlsym`/动态加载

运行时按名字取函数（插件系统）：

```c
void *h = dlopen("./libplug.so", RTLD_LAZY);
void (*init)(void) = dlsym(h, "plug_init");
init();
```

这解释了「函数指针 = 运行时可替换的行为」，也是 C 里实现「依赖注入」的唯一手段。

## 三视角解析

### 🧑‍💻 程序员视角
- 函数指针是 C 的**回调**机制：`qsort` / `pthread_create` / 事件表都靠它；配合 `typedef` 能让声明可读性大幅提升。
- 多级指针最常见的用途是「**修改指针本身**」（`void alloc(Node **p)`），以及动态二维数组的两种分配方式。
- 声明看不懂就用**右左法则**：从标识符出发，先向右（`[]`、`()`），再向左（`*`）。

### 🎓 博士生视角
- 函数指针 = C 的**运行时多态**雏形：把一组函数指针放进结构体（如 `struct file_operations`），就是 Linux 内核的对象模型，也是 C++ 虚函数表的手工版本。
- 数组指针与指针数组的差异源于**优先级**：`[]` 高于 `*`，故 `int *p[10]` 是指针数组、`int (*p)[10]` 是数组指针。
- 函数指针的调用约定（cdecl / stdcall / SysV AMD64）决定参数如何入栈/入寄存器与谁清理栈——这是 **ABI** 的一部分，跨编译器/跨语言 FFI 时必须一致。
- 指向函数的指针与指向数据的指针在标准上**不保证可互相转换**（虽在主流平台可行），这是嵌入式与 JIT 场景的常见坑。

### 📚 考研者视角
- **408 高频辨析题**：`int *p[10]`、`int (*p)[10]`、`int (*p)(int)`、`int (*p[10])(int)` 各是什么——这是指针部分的必考类型。
- 与计组交叉：**子程序调用的返回地址与参数传递**，函数指针只是把「目标地址」从编译期固定变成运行期可变。
- 记忆锚点：**右左法则**；**`(*p)` 有括号才是「指针」本体，否则 `[]` 先结合**。
