# clang-u04 · 易错点

1. **二进制数据用文本模式读写导致损坏** —— 在 Windows 上，文本模式会把 `\n` 与 `\r\n` 互转，`0A` 被偷偷扩成 `0D 0A`，图片/结构体/压缩包直接坏掉。**正确写法**：任何非文本字节一律用 `"b"` 模式（`rb`/`wb`），且读写两端模式一致。

2. **fopen 不判 NULL 就解引用** —— 文件不存在/无权限时 `fopen` 返回 `NULL`，紧接着 `fread(fp,...)` 是段错误。**正确写法**：每次 `fopen` 后 `if (!fp) { perror(...); return ...; }`。

3. **把 `w`/`w+` 当「存在则报错」用** —— `w` 会**直接截断**已有文件到 0 字节，重要内容瞬间消失。**正确写法**：想「不存在才创建、存在则报错」用 POSIX `open(path, O_CREAT|O_EXCL, 0600)`，或先 `fopen "r"` 探测存在性。

4. **用 `feof` 当循环条件导致多读一次** —— `feof` 只在「读操作已越过文件尾」后才置位，用它当 `while(!feof)` 前置条件必然多进一次循环、把 `EOF(-1)` 当数据使用。**正确写法**：以 `fread/fgetc/fscanf` 的返回值/EOF 为终止条件，结束后才用 `feof/ferror` 区分原因。

5. **忽略 fread/fwrite 的返回值** —— 返回的是「元素个数」而非成功标志；磁盘满或到 EOF 时返回少于请求值。把 `fwrite(..., fp)` 当无返回值调用会吞掉短写。**正确写法**：`size` 传 1、`nmemb` 传字节数，比较返回值与实际长度，区分 `feof`/`ferror`。

6. **程序退出前没 fclose/fflush 丢失数据** —— 全缓冲文件（普通文件默认）的数据停在用户态缓冲，`return 0`/`exit()` 才会替你 flush；`abort()`/`kill -9` 不会。**正确写法**：写完关键数据主动 `fflush(fp)`，必要时 `fsync(fileno(fp))`；长进程别依赖退出时才刷。

7. **读写切换的流漏掉 fseek/fflush** —— 同一 `FILE*` 上「写后读」或「读后写」之间必须插入定位或刷新，否则行为未定义（缓冲与位置不一致）。**正确写法**：每次读写角色切换前 `fseek(fp,0,SEEK_CUR)` 或 `fflush`+定位。

8. **混用 FILE 与底层 read/write 同一 fd** —— `stdio` 的用户态缓冲会截留数据，两套 API 看到的位置/内容不一致，结果是 UB。**正确写法**：要么全程用 `stdio`，要么全程用 `read/write`，需要底层访问时用 `fileno(fp)` 并在切换前后 `fflush`。
