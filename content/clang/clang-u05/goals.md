# clang-u05 · 预处理与宏 · 学习目标

> **先修**：clang-u01 指针与地址运算、clang-u02 内存与动态分配（理解翻译阶段前的 token 概念即可）。
> **衔接**：clang-u06 Makefile 与构建（预处理产物是编译流水线的第一关）、clang-u07 多文件与链接（头文件守卫与翻译单元）。
> **面试权重**：★★★★☆ —— 宏的卫生问题、`#`/`##`、条件编译、头文件守卫是 C 岗高频题；X-Macro 与 `_Static_assert` 是区分「会用」与「懂设计」的分水岭。

## 学完你能做到

1. **说清翻译阶段**：能按 C 标准复述从源文件到可执行映像的 7 个翻译阶段（phase 1–7），并解释「预处理发生在编译之前、宏只是纯文本替换」。
2. **区分对象宏与函数宏**：理解 `#define` 的两种形式，知道函数宏不是函数，并掌握**括号卫生**与**多重求值**两大陷阱。
3. **写出卫生的宏**：用 `#` 字符串化、`##` 记号拼接做元编程；多语句宏一律用 `do { … } while (0)` 包裹。
4. **驾驭条件编译**：熟练使用 `#if`/`#ifdef`/`#ifndef`/`#elif`/`#else`/`#endif` 与 `defined` 运算符做平台/特性开关。
5. **避免重复包含**：手写 `#ifndef` 守卫，也能讲清 `#pragma once` 与它的差异与取舍。
6. **掌握进阶技巧**：用 X-Macro 由一张表生成枚举/字符串表/函数表，用 C11 的 `_Generic`、`_Static_assert` 提升类型安全与可维护性。

## 博士视角（要理解到什么程度）

- **预处理是「文本变换」，不是「语义分析」**：宏展开只做 token 级别的替换与拼接，不做类型检查、不解析语法树；因此宏的报错信息往往晦涩，且展开结果可能破坏语法。
- **翻译阶段是标准定义的严格顺序**：三字符序列/行拼接（phase 2）、token 化（phase 3）、预处理（phase 4）、字符串化与拼接（phase 4 内）、字符集映射（phase 5）、拼接相邻字符串字面量（phase 6）、最后才进入语法/语义分析（phase 7）。头文件 `#include` 在 phase 4 被递归展开。
- **`#` 与 `##` 发生在宏参数被替换之后**：这就是「直接 `STR(VERSION)` 得到 `"VERSION"` 而非 `"20260919"`，必须用 `TOSTR(VERSION)` 二次展开」的根本原因（标准规定 `#`/`##` 抑制参数进一步宏展开，需间接一层才能先展开参数）。
- **守卫的本质是「翻译单元内去重」**：`#ifndef` 守卫只防止同一翻译单元内重复包含；跨翻译单元的符号冲突靠 `static`/`static inline` 或链接属性解决。

## 程序员视角（要能用出来）

- **宏能省一次函数调用开销，但牺牲类型安全与可调试性**：能用 `static inline` 函数替代的函数宏优先用 `inline`；需要泛型的场合再用宏或 C11 `_Generic`。
- **所有宏参数在使用处加括号、整个表达式加括号**：这是避免运算符优先级事故的硬规矩。
- **把宏当「代码生成」而非「计算」**：X-Macro、日志宏、`#define` 配置开关都是它的主战场；别拿宏写复杂逻辑。
- **工程里用条件编译隔离平台差异**（Windows/Linux、32/64 位、调试/发布），但开关过多会让构建矩阵爆炸——用构建系统（见 clang-u06）统一控制更稳妥。
