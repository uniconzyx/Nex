# 01 · 翻译阶段与 `#include` 的文本包含语义

## 一、理论根基：C 程序如何变成可执行文件

从一份 `.c` 源文件到可运行程序，要经过**翻译（translation）**与**链接**两大阶段。C 标准（C11 §5.1.1.2）把「翻译」细分为 7 个严格有序的阶段（phase），理解这个顺序，是理解「为什么某些写法合法、某些未定义」的钥匙。

```
源文件(.c/.h)
   │  phase 1  三字符序列/换行规范、源/执行字符集识别
   ▼
   │  phase 2  反斜杠换行 \ 拼接物理行 → 逻辑行
   ▼
   │  phase 3  分解为 注释/空白/预处理 token（标识符、数字、标点、字符串等）
   ▼
   │  phase 4  ★ 预处理：执行 #include/#define/#if 等指令
   │           - #include 把目标文件整体「文本替换」进来（可递归）
   │           - 宏在此时被展开（# 与 ## 也在此阶段完成）
   ▼
   │  phase 5  字符常量/字符串字面量中的源字符集 → 执行字符集
   ▼
   │  phase 6  相邻字符串字面量拼接（"a" "b" → "ab"）
   ▼
   │  phase 7  语法与语义分析 → 生成翻译单元（一个 .o 的目标代码）
   ▼
翻译单元 ──(链接器链接多个 .o 与库)──▶ 可执行映像
```

> **关键结论**：预处理（phase 4）发生在语法/语义分析（phase 7）**之前**。预处理器不懂 C 语法，只做 token 级别的文本变换。这就是为什么「宏展开出半个语句」不会在预处理时报错，而会在后续编译阶段报出令人费解的错误。

## 二、实现机制：`#include` 到底是什么

`#include <stdio.h>` 与 `#include "mymath.h"` 的语义是**纯文本包含**：

1. 预处理器定位文件（`<>` 走系统包含路径，`""` 先查当前文件目录再走系统路径）。
2. 把该文件的全部内容**逐字复制**到 `#include` 所在位置。
3. 被包含文件内部若还有 `#include`，则**递归**展开（受守卫保护，见 concept/04）。

因此，一个 `.c` 文件经过预处理后，会变成一份**巨大的、把所有头文件铺开**的单一翻译单元（translation unit）。可以用 `gcc -E` 亲眼看到展开结果（见 examples/ex10.json）。

```c
/* main.c */
#include "mymath.h"      /* 内容被整段贴进来 */
int main(void) { return my_add(1,2); }
```

展开后等价于把 `mymath.h` 的全文插入到 `#include` 行。多个 `.c` 各自独立预处理，因此**头文件会被每个翻译单元各展开一次**——这正是「头文件守卫」存在的根本原因（重复定义会触发 multiple definition 错误）。

## 三、工程实践：翻译单元与「一次定义规则」

- **一个 `.c` 是一个翻译单元**：它预处理后的全部内容构成编译的基本单位。
- **ODR（One Definition Rule）**：在**同一个翻译单元**内，非 `inline` 的全局函数/对象只能定义一次；跨翻译单元则通过 `extern` 声明 + 单点定义 + 链接来解决。
- **把宏/内联函数/类型定义放进头文件，把实际存储/实现放进 `.c`**：这是 C 工程的标准分层。

## 四、边界与陷阱

- 头文件里放**带存储的全局变量定义**（如 `int g = 0;`）会被每个包含它的 `.c` 各定义一份 → 链接期 `multiple definition`。应改为 `extern int g;`（头文件）+ `int g = 0;`（某一个 `.c`）。
- `#include` 本质是拷贝，因此**循环包含**（`a.h` 含 `b.h`，`b.h` 又含 `a.h`）若没有守卫会无限递归或重复定义；守卫可破。
- 预处理 token 化在 phase 3，所以 `a/* comment */b` 不会拼成 `ab`——注释在 token 化前已被替换为空格（phase 3 的注释处理）。

## 三视角解析

### 🧑‍💻 程序员视角
- **`#include` 是纯文本替换**，不是模块导入：它把整个文件内容原样插进来，所以「头文件越少编译越快」。
- 用 `gcc -E x.c | less` 直接看预处理结果，是排查宏问题的最快手段。
- 头文件只放**声明**、实现放 `.c`；`#include "x.h"` 先搜当前目录、`#include <x.h>` 只搜系统路径。

### 🎓 博士生视角
- C 的翻译过程被标准划分为**多个翻译阶段**：三字符组替换与行拼接 → 预处理（宏展开、条件编译、include）→ 转成预处理记号 → 语法/语义分析 → 生成目标代码。**宏替换发生在语法分析之前**，所以宏完全没有类型与作用域概念。
- 这解释了宏的一系列「怪癖」：宏参数若不加括号会被后续运算符改写优先级、有副作用的实参会多次求值——这些都是「在记号层面做文本替换」的必然后果。
- 从编译原理看，C 的预处理是**独立于编译的阶段**（很多语言已取消，改用模块/import），其代价是「文本包含」带来的重复解析与宏污染。

### 📚 考研者视角
- **408 与编译原理交叉**：编译的四个阶段（**词法分析 → 语法分析 → 语义分析 → 代码生成**，加上中间代码与优化），C 的预处理作为前置阶段单列。
- 常考概念题：「预处理与编译的区别」「`#include` 与 `import` 的区别」。
- 记忆锚点：**`#include` 是文本包含，宏在编译之前展开**。
