# 02 · 对象宏、函数宏与宏的「卫生」问题

## 一、理论根基：宏是「文本替换」而非「调用」

`#define` 有两类：

```c
#define PI 3.14159                 /* 对象宏：一个标识符替换成一段 token */
#define MAX(a, b) ((a) > (b) ? (a) : (b))   /* 函数宏：带形参的替换 */
```

**第一性原理**：函数宏在预处理阶段被**整体替换**进调用点，没有「调用栈」、没有「参数求值」的语义——只是把实参 token 替换到形参位置。这与函数有本质区别：

| 维度 | 函数 | 函数宏 |
|---|---|---|
| 求值时机 | 运行期，参数先求值再传入 | 预处理期，实参 token 直接替换，**不预先求值** |
| 类型 | 强类型，参数有类型 | 无类型，任何 token 都能塞进去 |
| 开销 | 有调用/返回开销（inline 可消除） | 零调用开销，但代码体积膨胀 |
| 调试 | 可单步进入 | 宏展开后消失，难调试 |

## 二、实现机制：两类典型「不卫生」陷阱

### 陷阱 1：括号缺失导致运算符优先级破坏（优先级卫生）

函数宏的**形参**和**整体结果**都必须加括号，否则替换后会被外层表达式的运算符「吃掉」。

```c
#define SQUARE(x) x * x
int r = SQUARE(2 + 1);   /* 展开为 2 + 1 * 2 + 1 = 5，而非 9 */
```

正确写法：`#define SQUARE(x) ((x) * (x))`——**参数加括号、整体加括号**。

### 陷阱 2：参数多重求值（多次展开副作用）

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int i = 0;
int m = MAX(i++, 2);     /* 展开：((i++) > (2) ? (i++) : (2)) */
```

`i++` 被求值了**两次**：一次比较、一次作为返回值。结果 `i` 从 0 变成 1，且 `m` 的值依赖于求值顺序（这是**未指定行为**）。参见 examples/ex02.json 的真实输出：`MAX(i++, 2) = 2 (i 被求值两次后 = 1)`。

> **博士视角**：多重求值是宏「文本替换」语义的必然结果——同一个形参在宏体里出现几次，实参就被替换几次。任何带副作用的实参（自增、赋值、含 `++` 的函数调用）都会触发。这是宏**无法**像函数那样「求值一次」的根本原因。

### 陷阱 3：多语句宏缺少包裹

函数宏若展开成多条语句，直接放在 `if/for/while` 的单语句位置会出 bug：

```c
#define LOG(x) printf("A:%d\n", x); printf("B:%d\n", x)
if (cond) LOG(k);        /* if 只管辖第一条语句，第二条永远执行 */
```

正确写法是用 `do { … } while (0)` 把多条语句「封」成一个单语句：

```c
#define LOG(x) do { printf("A:%d\n", x); printf("B:%d\n", x); } while (0)
```

`do-while(0)` 的优点：① 末尾的 `;` 自然闭合；② 作为单条语句可安全地放进 `if/for`；③ 永不真正循环。参见 examples/ex03.json 的对比输出。

## 三、工程实践：什么时候用宏、什么时候用 `inline`

- **优先 `static inline` 函数**：有类型检查、可调试、无多重求值问题；只有需要「泛型 token 操作」或「编译期字符串/记号变换」时才用宏。
- **宏参数必须全括号、整体全括号**：这是硬规矩，靠 code review 与 `-Wall` 仍难完全发现。
- **给宏起全大写名**：视觉上提醒读者「这是宏，可能有副作用/多重求值」。
- **多语句宏必用 `do { } while (0)`**：无例外。
- **带副作用的实参不要用宏**：`MAX(x++, y)` 这类调用应改成先算好再传值。

## 四、边界与陷阱

- 宏没有作用域（`#undef` 前一直有效），容易与第三方库同名宏冲突——可用 `#undef` 或加前缀规避。
- 宏不能递归（预处理器不保存「正在展开」的上下文，同名会无限展开，标准禁止）。
- 函数式宏返回「最大值」时用 `?:` 而不是 `if`，以保证能用在表达式上下文。

## 三视角解析

### 🧑‍💻 程序员视角
- 三条铁律：**宏参数一律加括号**、**多语句宏用 `do { ... } while (0)` 包裹**、**有副作用的表达式绝不要传宏**（会多次求值）。
- 能不用宏就别用：常量用 `const`/`enum`，小函数用 `static inline`，类型泛型用 `_Generic` 或直接写两个函数。
- 宏名尽量加前缀并 `#undef`，减少命名污染。

### 🎓 博士生视角
- 宏是**文本替换**，没有作用域、没有类型检查、没有求值一次保证。`MAX(i++, j)` 会让 `i` 自增两次——这不是「编译器 bug」，而是文本替换的必然结果。
- `do { ... } while (0)` 的作用是让多语句宏在 `if (...) MACRO; else ...` 这类语境中成为**语法上的单条语句**，从而不破坏 `if/else` 配对（用 `{}` 会因为后接分号而产生多余空语句）。
- 从语言设计看，宏是「**在编译前做代码生成的逃生舱**」，它用「丧失一切安全保证」换取「能表达语法层面的抽象」；现代语言用宏系统（Rust macro_rules）、泛型、编译期计算来提供**受约束的**替代品。

### 📚 考研者视角
- **与编译原理交叉**：预处理与宏展开是编译流程的第一步，常考「宏与函数的区别」（展开时机、类型检查、求值次数、代码体积）。
- 常考概念题：「带参宏为什么容易出错」「`do-while(0)` 的作用」。
- 记忆锚点：**参数加括号、多语句 `do-while(0)`、副作用表达式不传宏**。
