# 翻译单元、声明与定义、链接属性

## 1. 从源码到可执行：谁负责哪一段

C 的编译流程里，**每个 `.c` 文件（更准确说，每个经过预处理的 `.c`）都是一个独立的翻译单元**。
编译器一次只看到一个翻译单元，它对别的 `.c` 里有什么**一无所知**：

```
main.c ──预处理──> main.i ──编译──> main.o ─┐
                                            ├─链接器──> app.exe
util.c ──预处理──> util.i ──编译──> util.o ─┘
```

这解释了一个初学者最常见的困惑：

```c
/* main.c */
int add(int, int);          /* 声明：告诉编译器「有这么个函数，签名如此」 */
int main(void) { return add(1, 2); }
```

编译 `main.c` **完全通过** —— 编译器只需要知道 `add` 的**签名**来生成调用指令。
至于 `add` 到底在不在，是**链接器**的问题。所以：

- 编译错误说 `implicit declaration of function` → 缺**声明**（头文件没包含）。
- 链接错误说 `undefined reference to 'add'` → 缺**定义**（没把 `util.o` 或库加进来）。

**这两个错误发生在不同阶段、由不同工具报出，修法完全不同。** 面试里能把这条线讲清，就已经赢过多数人。

## 2. 声明 vs 定义

| | 声明（declaration） | 定义（definition） |
|---|---|---|
| 作用 | 引入名字及其类型 | 真正分配存储 / 给出函数体 |
| 函数 | `int f(int);` | `int f(int x){ return x; }` |
| 变量 | `extern int x;` | `int x = 0;` 或 `int x;`（试探性定义） |
| 可否重复 | 可以，多次声明无害 | 一个翻译单元内至多一次；跨翻译单元默认只允许一次（外部链接） |

函数「定义」天然也是「声明」。变量的坑更多：**`int x;` 在文件作用域既是定义（试探性定义，
tentative definition）**，而 `extern int x;` 只是声明。所以把头文件写成：

```c
/* bad.h —— 灾难 */
int count;          /* 每个包含它的 .c 都产生一个定义 → multiple definition */
```

在 C99 之前，多个试探性定义会被链接器**合并**（common 符号），所以「偶尔也能跑」；
但在现代编译器默认 `-fno-common`（GCC 10+ 起是默认行为）下，**直接报多重定义**。
这正是大量老代码在升级 GCC 后突然编译失败的原因。

**正确写法**：头文件只放声明，定义放在某个 `.c` 里。

```c
/* count.h */
extern int count;          /* 声明 */
/* count.c */
int count = 0;             /* 唯一的定义 */
```

## 3. 链接属性（linkage）：名字在哪个「作用域」里可见

C 标准定义了三种链接属性，它决定**多个翻译单元里的同名标识符是否指同一个实体**：

| 链接属性 | 触发方式 | 跨翻译单元可见 | 典型用途 |
|---|---|---|---|
| 外部链接（external） | 函数默认；文件作用域变量默认 | 是 | 提供给其他模块调用的接口 |
| 内部链接（internal） | 文件作用域加 `static` | 否 | 模块私有实现，避免污染全局命名空间 |
| 无链接（none） | 块作用域变量、函数参数 | — | 局部变量 |

```c
static int helper(void);        /* 内部链接：别的 .c 里即使声明也链不到 */
int api_function(void);         /* 外部链接：可以被别的 .c 调用 */
```

**`static` 用在本文件作用域的变量/函数上时，含义与块作用域里完全不同**：

- 块作用域 `static int n;` → 「静态存储期」（生存期贯穿整个程序），链接属性仍是「无链接」。
- 文件作用域 `static int n;` → 「内部链接」（其他翻译单元看不见）。

同一关键字两种含义，是 C 语言里最容易混淆的设计之一，也是面试爱考的对比点。

### 内部链接为什么重要
1. **避免符号冲突**：两个模块各自有个 `init()`，都加 `static` 就互不干扰。
2. **给优化器更大空间**：编译器确定符号不逃逸出本翻译单元，就能内联、删除、做常数传播。
3. **减少动态库导出符号表体积**。

## 4. 头文件里到底该放什么

| 可以放头文件 | 不能放头文件 |
|---|---|
| 函数声明、`extern` 变量声明 | 函数定义（除非 `static inline`） |
| 结构体/联合体/枚举**类型**定义 | 非 `inline` 的全局变量定义 |
| 宏、`typedef` | 需要初始化的对象定义 |
| `static inline` 函数、`extern inline` 的约定 | — |

`struct` 定义放头文件是**合法的**：类型定义不产生符号、不分配存储（除非实例化对象）。

## 5. 工程实践：一个模块的标准形态

```
math/
├── math.h        # 公开接口：声明 + 类型 + 宏
├── math_internal.h  # 内部共享（不对外）
└── math.c        # 实现；私有函数加 static
```

- 对外只暴露 `math.h`，内部细节用 `static` 封死。
- 这就是 C 里「信息隐藏」的全部手段——没有 `private`，只有 `static` 和「不放进头文件」的纪律。

## 三视角解析

### 🧑‍💻 程序员视角
- **排查顺序固定**：`implicit declaration` → 查头文件包含路径与拼写；`undefined reference` → 查
  是否把 `.o`/库加进链接命令行、`-l` 顺序、符号是否被 `static` 藏起来了。
- **默认策略**：所有只在本 `.c` 内使用的函数**一律加 `static`**。这不是可选项，是纪律——它同时买到
  了封装、优化空间和更小的符号表。
- **头文件只放声明**；需要常量用 `static const` 或 `enum`（C 里 `const` 变量在 C 中仍有外部链接，
  放头文件会多重定义，需 `static const` 或 `extern const` + 一处定义）。
- 用 `-Wall -Wextra` 打开告警，`-Wmissing-prototypes` 能强制你为每个外部函数写声明。

### 🎓 博士生视角
- **翻译单元是一个 lexical scope 之上的「编译边界」**。C 的分离编译是一种**名义化（nominal）
  模块系统的最弱形态**：跨单元一致性靠程序员手工维护声明，编译器无从验证。这直接导致了
  「声明与定义不一致时行为未定义」——例如一个 TU 里声明 `void f(int)`、另一个定义为
  `void f(double)`，是 **UB**，链接器不会报错（C 没有名称修饰）。
- **链接属性本质是「符号的绑定时机与作用域」**：内部链接 = 静态绑定到本单元；外部链接 = 延迟到
  链接期解析。这与动态库引入的**运行时绑定**构成三级层次（编译期/链接期/加载期）。
- **ODR（One Definition Rule）在 C 里不叫 ODR，但同样存在**：外部链接对象在全程序只允许一个定义，
  否则是约束违规（链接错误）。C++ 把它形式化成 ODR 并扩展到类定义、模板、inline 函数。
- **`-fno-common` 的变迁**是一段活的标准化史：C 的**试探性定义**（C99 6.9.2p2）允许同一 TU 内多个
  tentative definition 合并；跨 TU 的合并依赖 linkers 的 common 符号扩展，属于实现行为而非标准保证。
  GCC 10 默认 `-fno-common` 正是在把「实现行为」收回到「标准行为」。

### 📚 考研者视角
- **考点归属**：计算机组成原理 → 编译/汇编/链接（目标文件、符号表、重定位）；操作系统 → 链接与装入
  （静态链接、动态链接、装入时重定位）。
- **必背对照表**：

  | 概念 | 归属阶段 | 报错关键词 |
  |---|---|---|
  | 缺声明 | 编译期 | implicit declaration / undeclared |
  | 缺定义 | 链接期 | undefined reference |
  | 多重定义 | 链接期 | multiple definition |
  | 重复包含 | 预处理期 | redefinition of ... |

- **记忆锚点**：**「编译器只管签名，链接器才管地址」**。一句话记住两个阶段的职责边界。
- 选择题高频：`static` 的作用（限制作用域到本文件 + 静态存储期）、`extern` 的作用（声明而非定义）、
  头文件里放定义的后果（重复定义）。
