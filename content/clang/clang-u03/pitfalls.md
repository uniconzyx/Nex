# clang-u03 · 易错点

1. **忘记对齐导致 `sizeof` 远超字段之和** —— `struct { char c; int i; };` 在小端 LP64 下是 8 字节（char 后填 3 字节），不是 5。把 `char` 夹在两个大成员之间更糟。**正确写法**：按对齐从大到小排（大成员在前、小成员聚尾），必要时用 `_Static_assert(sizeof(S)==N, ...)` 固化布局。

2. **用位域写可移植二进制协议** —— 位域从字的哪端开始、是否跨字、无名位域对齐都是**实现定义**的；同一份代码在 GCC/Clang、大端/小端机器上比特排布可能完全不同。**正确写法**：协议字段一律用「位移 + 掩码」显式编码，如 `(raw >> 3) & 0xF`，并把字段宽/偏移写成常量。

3. **用 union 读非活跃成员当类型双关（UB）** —— 写入 `u.i` 又读 `u.f` 在严格 aliasing 下是未定义行为，编译器可能返回「不是内存里那个比特」的值。**正确写法**：用 `memcpy(&dst, &src, sizeof)` 或 `unsigned char` 逐字节观察（C11 §6.2.6.1），可移植且避开活性成员限制。

4. **结构体浅拷贝分裂指针所有权** —— `struct Buf b = a;` 让 `b.p == a.p`，两者共享同一块堆内存，`free` 两次即 double free。**正确写法**：含指针的结构体要么显式深拷贝、要么明确「谁分配谁释放」的所有权、要么禁止拷贝。

5. **返回局部结构体指针** —— `struct P* f(){ struct P p=...; return &p; }` 返回栈帧已失效的地址，得到悬垂指针。**正确写法**：返回结构体**值**（`return p;` 调用方拿到副本），需要逃逸生命周期再用 `malloc` 并约定释放责任。

6. **以为传结构体一定「慢」而滥用 malloc** —— 小/中等结构体按 ABI 常走寄存器或隐藏指针返回，编译器已做拷贝消除；强行 `malloc` 反而引入堆分配与 `free` 成本。**正确写法**：先值传递/值返回，profile 显示瓶颈后再考虑动态分配。

7. **误用柔性数组成员** —— `struct P { int len; uint8_t data[]; };` 的 `sizeof` 不含 `data`，且必须用 `malloc(sizeof *p + n)` 分配；不能用于栈/静态对象，不能 `memcpy` 整个结构体（漏掉柔性区）。**正确写法**：动态分配时一次性包含负载，复制用按长度 `memmove`。

8. **把 `#pragma pack` 当默认优化** —— 强制紧凑布局会取消对齐，在 ARM/RISC-V 等严格架构上引发 SIGBUS，且降低访问性能。**正确写法**：仅在对接外部固定二进制格式时局部使用，并尽快恢复默认对齐。
