# clang-u03 · 结构体与联合体 · 学习目标

> **先修**：clang-u01 指针与地址运算（必须会 `->`、指针算术）、clang-u02 动态分配（malloc/free）。
> **衔接**：clang-u04 文件 IO（把结构体以二进制形式落盘）、clang-u07 多文件与链接（结构体跨文件共享靠头文件）。
> **面试权重**：★★★★☆ —— 内存对齐、结构体布局、union 类型双关是系统/嵌入式/高频考点。

## 学完你能做到

1. **说清结构体在内存里到底长什么样**：能手算 `sizeof`、能画出带 padding 的 ASCII 内存布局图、能解释为什么 `sizeof` 经常大于「各字段之和」。
2. **掌握内存对齐规则**：理解 `_Alignof` / 自然对齐、`offsetof` 宏、以及「成员重排减少填充」的工程技巧。
3. **认清位域的边界**：知道位域是**实现定义**行为，跨平台/跨编译器布局不一致，能讲清它何时可用、何时是坑。
4. **区分结构体拷贝与逐成员赋值**：理解结构体赋值是逐成员拷贝（浅拷贝），嵌套指针时与 `memcpy` 的差异、与深拷贝的关系。
5. **用 union 做类型双关并能讲清 UB 边界**：知道「读非最后写入的活跃成员」是未定义行为（C11 起有例外），以及 tagged union 这种安全惯用法。
6. **理解 ABI 与结构体布局的关系**：为什么 C 的结构体布局是 FFI / 二进制协议的基石，以及何时不能随便改成员顺序。
7. **正确传参与返回结构体**：知道小结构体常被编译器「隐藏地」走寄存器/指针返回优化，避免无谓的 `malloc`。

## 博士视角（要理解到什么程度）

- **对齐是硬件契约**：CPU 按字/缓存行取数，未对齐访问在部分架构（ARM、RISC-V）直接触发总线错误，在 x86 上也有性能惩罚。对齐约束本质是「内存访问粒度」对数据布局的倒逼。
- **结构体内存布局是语言标准留白的少数「可见实现细节」**：标准只规定「成员按声明顺序递增、可能有填充」，具体填充/对齐由 ABI（如 x86-64 System V AMD64 ABI）固化，这也是为什么同平台不同编译器结果一致、跨平台却可能不同。
- **union 的活性规则（active member）是类型系统的「后门」**：C11 允许通过 `unsigned char` 数组观察任何对象的比特表示（6.2.6.1），但用 union 做类型双关在严格 aliasing 下仍属灰色地带；`_Generic` 与 `memcpy` 才是可移植的类型重解释。

## 程序员视角（要能用出来）

- 需要跨进程/落盘的二进制格式，结构体布局就是协议——成员顺序、对齐、`_Static_assert(sizeof(...))` 是「自描述契约」。
- 高频分配的小结构体，把大对齐成员往前放、小成员聚拢，能省下可观内存（一个服务上亿对象时这是真金白银）。
- 需要位级协议（网络包头、寄存器映射）时可以用位域，但**务必固定编译器和平台**，或改用显式位移掩码以保证可移植。
- 不要把柔性数组成员（flexible array member）和「定长数组当缓冲区」混为一谈——前者是 ABI 级特性，后者是普通字段。
