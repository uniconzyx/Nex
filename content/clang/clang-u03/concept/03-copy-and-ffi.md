# 03 · 拷贝语义、传参/返回优化与柔性数组

## 一、结构体赋值：逐成员浅拷贝

C 中结构体是**值类型**，赋值 `a = b;` 是**逐成员拷贝（memberwise copy）**，等价于对每个字段做 `a.x = b.x;`。这与 C++ 的拷贝构造不同——C 没有构造/析构，赋值纯粹是比特层面的逐字段复制。

**关键陷阱：浅拷贝 + 内部指针 = 双重释放风险**。
```c
struct Buf { char *p; size_t n; };
struct Buf a = make_buf(10);
struct Buf b = a;     // b.p == a.p，两对象共享同一块内存
free(a.p); free(b.p); // double free！a.p 与 b.p 指向同一处
```
这与 clang-u02 的「裸指针所有权」问题同源：只要结构体「拥有」一个指针，浅拷贝就会分裂所有权。修复手段与 u02 一致——要么禁止拷贝、要么显式深拷贝、要么改用 `malloc`/`free` 的明确所有权约定。

## 二、传参与返回：被编译器「隐藏优化」的拷贝

**博士视角 —— 结构体如何进出函数**：
- 传参 `void f(struct S s)`：标准语义是「整份拷贝传进去」，但编译器会**按 ABI 决定实际传递方式**。小结构体（能装进寄存器/参数寄存器对）通常直接走寄存器；稍大的可能**隐式改为传指针**（`f(struct S *s)` 的等价物），调用方在栈上留一份副本，被调方经指针访问——调用者完全无感，这就是「隐藏指针优化（hidden pointer / by-invisible-reference）」。
- 返回结构体 `struct S g(void)`：同样可能被改写为「调用方预留空间、传一个隐藏指针让被调方写入」（`struct S *ret`）。C11 起 `struct S x = g();` 这种「先构造再拷贝」的语义被允许（且通常被优化成）**直接构造到目标**，避免一次中间拷贝（RVO 的类比）。
- 结论：**盲目用 `malloc` 返回指针「避免拷贝」常常适得其反**——编译器对返回结构体的优化往往比一次堆分配 + 后续 `free` 更便宜。现代实践：小到中等结构体直接值返回，让 ABI/优化器决定；只有「对象生命周期必须逃逸出函数」才用动态分配。

## 三、返回局部结构体指针是 UB

```c
struct P* bad(void) { struct P p = {1,2}; return &p; }  // 悬垂指针，栈帧已失效
```
返回**值**（`return p;`，让调用方拿到一份拷贝）才正确。这点与 clang-u01 的「返回局部变量地址」陷阱一致，只是对象换成了结构体。

## 四、柔性数组成员（Flexible Array Member）

C99 允许结构体**最后一个成员**是未知长度的数组：
```c
struct Packet {
    uint32_t len;
    uint8_t  payload[];   // 柔性数组成员，不计入 sizeof
};
```
- `sizeof(struct Packet)` **只算到 `len`**，不含 `payload`。
- 必须用 `malloc` 分配「结构体 + 额外负载空间」：`struct Packet *p = malloc(sizeof *p + n);`，此时 `p->payload` 可合法访问 `n` 字节。
- 这是「单个堆块承载变长数据」的 ABI 级惯用法，比「单独 malloc 两块再指针相连」少一次分配、缓存更友好。内核、网络协议栈、序列化库大量使用。
- 边界：柔性数组成员**不能**用于栈上/静态对象、不能用于非最后成员、不能用 `memcpy` 整个结构体拷贝（会漏掉柔性区——必须按字节长度手动复制）。

## 五、可运行示例：值返回 vs 指针返回

```c
#include <stdio.h>

struct Point { int x, y; };

struct Point make(void) {        // 值返回：调用方拿到独立副本
    struct Point p = {3, 4};
    return p;                    // 不是返回地址，无悬垂问题
}

void by_value(struct Point p) {  // 传值：形参是实参的副本
    p.x = 99;
    printf("in by_value: x=%d\n", p.x);
}

int main(void) {
    struct Point a = make();
    printf("returned: x=%d y=%d\n", a.x, a.y);
    by_value(a);
    printf("after by_value: x=%d\n", a.x);   // a 未被修改
    return 0;
}
```

**输出**：
```
returned: x=3 y=4
in by_value: x=99
after by_value: x=3
```

> 关键结论：`make()` 值返回得到独立副本；`by_value(a)` 的修改只作用于形参副本，调用方 `a` 不受影响——印证结构体是值类型、「传值即拷贝」。需要跨函数改原对象时，应传 `struct Point *p`（clang-u01 的指针语义）。

## 三视角解析

### 🧑‍💻 程序员视角
- 结构体赋值/传参是**逐成员浅拷贝**：含指针成员时只复制指针，不复制指向的数据（深拷贝要自己实现）。
- 传大结构体请传**指针**（`const T *`），按值传会整块复制，代价随结构体大小线性增长。
- C99 的**柔性数组成员（FAM）**用来实现变长结构：`struct S { int n; int data[]; }`，分配时 `malloc(sizeof(struct S) + n * sizeof(int))`。

### 🎓 博士生视角
- 按值传参在 ABI 层有**隐藏指针优化**：小结构体可能被打包进寄存器（SysV AMD64 有分类规则），大结构体则通过栈复制；结构体**返回**常用「隐藏指针（sret）」写入调用方提供的空间。
- 柔性数组必须是结构体的**最后一个成员**，且结构体不能是数组成员——这是为了让它能「溢出到」额外分配的空间。
- `struct` 的布局（对齐、位域、打包）直接决定 **ABI 兼容性**：这就是为什么不同编译器/不同编译选项编译的库不能随意混用。
- 从语言设计看，C 的结构体是「无封装的记录类型 + 值语义」，与 C++ 的类（可含方法、有访问控制）在 ABI 上兼容但语义不同。

### 📚 考研者视角
- **408 计组交叉**：**参数传递（寄存器/栈）**、**栈帧结构**、返回值的传递方式——与编译原理的活动记录（activation record）直接对应。
- 常考概念题：「值传递与地址传递的区别」「为什么数组传参退化为指针而结构体传参是复制」。
- 记忆锚点：**结构体赋值是浅拷贝**；**柔性数组必须是最后一个成员**。
